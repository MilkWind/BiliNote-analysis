## 1. Immutable 数据不可变性 *Content-[00:02]

- **Immutable 概念**：Immutable 指的是数据不可变（Immutable Data）。
- **在 React 中的体现**：在 React 中，不能直接通过 `this.state` 修改当前数据，必须通过 `this.setState` 来更改，这体现了数据不可变的核心原则。
- **JS 对象的可变性问题**：
  - JS 对象默认是可变的。使用引用赋值时，新对象只是简单引用了原始对象。
  - **隐患**：当修改新对象时，会直接影响原始对象。例如，将 `object` 引用赋值给 `b`，修改 `b.a` 时，`object.a` 也会随之改变。虽然这节省了一定内存，但在复杂场景下会造成巨大的数据污染隐患。
- **传统解决方式的弊端**：
  - 一般做法是通过浅拷贝或深拷贝来避免原对象被修改。
  - 但这会导致 CPU 和内存的严重浪费，使得原本为了节省内存的引用赋值变得得不偿失。

## 2. 不可变性的核心优势 *Content-[02:13]

为了解决上述问题并简化组件状态的深度更新，引入 Immutable 数据（如使用 `Immer` 库）具有非常重要的意义，其核心优势包括：

- **浅层比较机制（性能优化）**：
  - 通过浅层比较机制（如使用 `Object.is`）判断数据的引用地址是否发生变化。
  - 如果引用地址未发生变化，组件就不会重新渲染，从而大幅提高 React 的渲染性能。这是 React 中非常关键的性能优化点。
- **数据一致性**：
  - 不可变性确保状态的每次变更都是显式的。
  - 能够有效避免副作用导致的数据污染，保证数据的一致性和可预测性。

## 3. 不可变数据的实现方式与 Immer 核心概念 *Content-[04:00]

- **常见实现方式**：
  - 手动深拷贝（繁琐且易错）。
  - 使用第三方库：如 `Immutable.js`、`Immer` 等。其中 `Immer` 提供了更简单、更优雅的 API。
- **Immer 的核心概念**：
  - `currentState`：被操作对象的最初状态（当前状态）。
  - `draft`（草稿）：根据 `currentState` 生成的草稿状态，允许开发者直接以可变的方式进行修改。
  - `nextState`：最终生成的新的不可变数据。
  - `produce`：核心函数，接收当前状态和一个修改函数作为参数。在函数中对 `draft` 进行修改后，返回最终的新状态。
  - `producer`：通过 `produce` 生成的函数，用于每次执行相同的操作来生成新的 state。
- **共享结构（Shared Structure）原理**：
  - `nextState` 在结构上与 `currentState` 共享未修改的部分。
  - Immer 内部只修改有差异的数据节点，极大地提高了内存利用率。

## 4. Immer 实战：优化 React 状态更新 *Content-[07:35]

- **业务场景**：定义一个 state，包含 `memories` 数组（元素包含 `name`, `id`, `age` 属性），需求是给 `memories` 数组中第一个元素的 `age` 加 1。
- **传统 `setState` 方式**：
  - 需要遍历数组，找到 `id` 为 1 的元素，修改其 `age`，然后返回新数组。代码逻辑繁琐。
- **传统 `reducer` 方式**：
  - 接收 `state` 和 `action`，判断 `action.type` 为 `increment_age` 时，需要手动实现深拷贝和修改逻辑，代码冗长。
- **使用 Immer 优化**：
  - 引入 `produce` 函数。
  - 在 reducer 中，使用 `produce` 接收 `currentState` 和 `draft`。
  - 直接对 `draft` 进行可变性操作（例如：`draft.memories[0].age += 1`）。
  - **优势**：代码极度简化，逻辑清晰。Immer 底层会自动处理引用变更，生成新的不可变状态并触发重新渲染。同时，得益于共享结构，未修改的数据依然保持内存共享，内存利用率极高。
