## React 的起源与简介 *Content-[00:00]
- **起源背景**：React 起源于 Facebook（现 Meta）内部的一个项目。当时团队对现有的 JS MVC 相关框架都不满意，因此决定自主开发一套全新的工具。
- **应用与开源**：该工具最初主要用于 Instagram 网站的架设。在实际应用中发现这套工具非常高效好用，随后团队决定将其开源。
- **基本定义**：React 是一个声明式的、高效且灵活的 JavaScript 库。
- **核心理念**：允许开发者使用简短、独立的代码片段（即**组件**）来构建复杂的 UI 界面。

## 声明式设计与命令式编程对比 *Content-[00:35]
- **声明式设计（Declarative）**：
  - **核心思想**：关注于“做什么”（What），而不是“怎么做”（How）。
  - **开发方式**：开发者只需描述 UI 应该呈现的最终状态（结果），而不需要手动编写整个更新和渲染的过程。
  - **优势**：当状态发生变化时，React 会自动负责更新和渲染视图。这种设计思路极大地简化了开发流程，提高了代码的可读性和整体开发效率。
- **命令式编程（Imperative）**：
  - **核心思想**：关注于“怎么做”（How）。
  - **开发方式**：需要开发者一步一步地告诉程序如何执行，包括手动操作和更新 DOM 来完成 UI 的渲染。
  - **劣势**：过程繁琐，需要处理大量底层细节，开发效率相对较低。

## 声明式与命令式代码示例：地图标记 *Content-[02:37]
以“实现一个带有标记（Marker）的地图”为例，直观对比两种编程范式的区别：
- **命令式实现步骤**：
  1. 第一步：创建地图实例。
  2. 第二步：创建对应的标记实例（例如通过 `new Marker()` 的方式）。
  3. 第三步：将创建好的标记手动添加到当前地图中。
- **声明式实现步骤**：
  - 创建一个组件，直接在组件中描述 UI 的状态结构。
  - 例如：定义最外层是一个 `Map` 组件，内部包含一个 `Marker` 组件。
  - **区别总结**：命令式需要手动控制每一步的创建和添加过程；而声明式只需关注最终渲染的结果结构，中间的渲染和更新过程交由 React 自动处理。

## 组件化开发 *Content-[04:32]
- **核心思想**：将复杂的 UI 拆分为独立、可复用的组件，每个组件负责管理自身的状态和逻辑，最后通过组合这些组件来构建复杂的应用。
- **主要特点**：
  - **可复用**：组件可以在不同的业务场景中重复使用，有效减少代码冗余。
  - **可维护**：每个组件独立性强，职责单一，便于后期的更新、维护和调试。
  - **组合性强**：组件可以通过嵌套形成清晰的树状结构，逻辑层次分明。

## 虚拟 DOM 与 Diff 算法 *Content-[05:23]
- **虚拟 DOM（Virtual DOM）**：
  - React 使用虚拟 DOM 来提升更新性能。
  - 当状态发生改变时，会生成一棵新的虚拟 DOM 树。
  - 将新树与之前的旧树进行比较，找出差异，最后只更新实际发生变化的 DOM 节点。
- **Diff 算法原理**：
  - React 的 Diff 算法与 Vue 的 Diff 原理存在较大差异。
  - React 的 Diff 过程是通过**两次遍历**的方式来实现高效的 DOM 映射和更新。
  - *注：深入理解 Diff 原理是掌握 React 性能优化的关键，面试中常作为重点考察内容。*

## React 的其他核心特性 *Content-[06:12]
除了上述核心概念，React 还具备以下重要特性：
- **单向数据流**：数据在组件间按照单一方向进行传递，使得数据流向更加清晰、可预测。
- **JSX 语法**：使用 JSX 扩展 JavaScript 语法，允许在 JS 代码中直接编写类似 HTML 的标签，提升开发体验。
- **Hooks 与函数式组件**：通过 Hooks 和函数式组件来管理组件状态和生命周期，是目前 React 开发的主流模式。
- **学习建议**：学习 React 必须深刻理解其核心特性，这样才能在后续与 Vue 等框架进行对比时，明确对比的方向和差异点。
