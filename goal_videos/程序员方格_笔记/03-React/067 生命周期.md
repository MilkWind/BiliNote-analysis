## 1. 组件生命周期概述 *Content-[00:00]
- **核心概念**：组件生命周期是指组件从创建到销毁的整个过程。
- **三大核心阶段**：主要分为挂载阶段（Mounting）、更新阶段（Updating）和卸载阶段（Unmounting）。

## 2. 挂载阶段 (Mounting) *Content-[00:10]
挂载阶段是指组件被创建并插入到 DOM 中的过程。在类组件中，该阶段包含以下生命周期方法：
- **constructor**：组件初始化时最先调用，主要用于初始化 `state` 以及进行相关方法的绑定。
- **getDerivedStateFromProps**：一个静态方法，主要在 `render` 之前调用。它的作用是根据 `props` 的变化来更新当前 `state`。每次渲染都会触发，但在实际开发中使用比较少。
- **render**：核心渲染方法，用于渲染当前的 UI 组件，返回一个 JSX 结构。
- **componentDidMount**：在组件挂载完成后执行。通常在此阶段进行以下操作：
  - 发起网络请求。
  - 初始化第三方库。
  - 订阅相关事件。

## 3. 更新阶段 (Updating) *Content-[02:22]
当组件完成首次渲染后，用户对界面进行操作导致 `props` 或 `state` 发生变化时，组件进入更新阶段。该阶段包含以下生命周期方法：
- **getDerivedStateFromProps**：与挂载阶段相同，在更新阶段也会存在并被调用。
- **shouldComponentUpdate**：用于判断组件是否需要重新渲染。可以通过对比 `nextProps` 和 `nextState` 来决定，如果发现值没有发生变化，可以返回 `false` 来阻止渲染，从而实现性能优化。
- **render**：重新渲染组件 UI。
- **getSnapshotBeforeUpdate**：在 DOM 更新前获取快照。
- **componentDidUpdate**：在组件更新完成后执行。

## 4. 卸载阶段 (Unmounting) *Content-[03:56]
卸载阶段是指将组件从 DOM 树中移除的过程。
- **componentWillUnmount**：在组件卸载前执行，主要用于清理和善后工作。常见的操作包括：
  - 清除定时器（timer）。
  - 取消相关的事件订阅。
  - 取消未完成的网络请求等。

## 5. 函数组件的生命周期替代方案 *Content-[05:20]
在函数组件中，没有传统的生命周期方法，主要通过 Hooks（如 `useState` 和 `useEffect`）来替代：
- **useState**：用于创建和管理组件内部的状态（例如定义 `count` 状态）。
- **useEffect**：用于处理副作用，替代了挂载、更新和卸载的生命周期逻辑。
  - **执行时机**：在组件挂载和更新时都会执行。
  - **依赖项控制**：通过提供依赖项数组（Dependency Array）来精确控制执行时机。例如，只有当依赖项 `count` 的值发生变化时，才会触发 `useEffect` 内部的逻辑；如果其他状态（如 `title`）发生变化但不在依赖项中，则不会触发重新执行。
  - **Clean up 函数（清除函数）**：`useEffect` 中 `return` 的函数即为清理函数。它的执行时机相当于类组件的 `componentWillUnmount`：
    - 在组件卸载前执行。
    - 在每次更新重新渲染之前，会先执行上一次的 clean up 函数，然后再执行新的 effect 逻辑。
