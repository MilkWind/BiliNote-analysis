## 1. XSS攻击及防范 *Content-[00:01]

### 1\. 什么是 XSS 攻击
*   **全称**：Cross-Site Scripting（跨站脚本攻击）。
*   **核心原理**：攻击者通过在目标网站中注入恶意脚本（如 JavaScript 代码），当其他用户浏览该网站时，脚本会在用户的浏览器中执行，从而窃取信息或进行恶意操作。
*   **注入场景**：通常发生在有用户输入并且允许提交的地方，例如：
    *   论坛评论区
    *   文章发表/留言板
*   **注入方式**：在输入框中写入 `<script>` 标签或可执行的 JS 代码。

### 2\. 如何防范 XSS 攻击
*   **字符转义**：
    *   对用户输入的敏感字符进行转义处理（如尖括号 `< >`、斜杠 `/` 等）。
    *   目的：破坏恶意代码的结构，使其不能形成完整的 `<script>` 标签或 SQL 语句，从而让脚本失效。
*   **后端核心处理**：
    *   前端的转义防范**不是绝对安全**的。
    *   因为网络请求是可以被抓包的，请求也可以被伪造。
    *   **核心结论**：必须由后台（服务端）对数据进行严格的转义和过滤处理，才能真正确保安全。

## 2. CSRF攻击及防范 *Content-[01:18]

### 1\. 什么是 CSRF 攻击
*   **全称**：Cross-Site Request Forgery（跨站请求伪造）。
*   **与 XSS 的关系**：CSRF 攻击通常需要借助 XSS 产生的漏洞。网站的安全就像“木桶理论”，只要有一块短板（如存在 XSS 漏洞），整个安全体系就会漏水。

### 2\. CSRF 攻击的典型场景
*   **场景一：同站 XSS 结合（以淘宝为例）**
    *   用户访问淘宝网站，并且**已经登录**（浏览器保存了该域名的 `cookie`）。
    *   黑客在淘宝的评论区发布了一个恶意链接（例如一个带有转账参数的 `GET` 请求接口）。
    *   用户不小心点击了该链接，由于是淘宝域下的请求，浏览器会**自动携带当前的 `cookie`**。
    *   后台接收到带有合法 `cookie` 的请求，验证通过，导致用户的钱被转走。
*   **场景二：钓鱼网站（随机钓鱼）**
    *   用户访问一个非淘宝域名的钓鱼网站。
    *   钓鱼网站内嵌了恶意图片或链接，在后台悄悄发起一个指向淘宝转账接口的 `GET` 请求（带有转账参数）。
    *   **核心逻辑**：黑客猜测用户曾在浏览器中登录过淘宝。只要用户登录过，浏览器在发起该请求时就会自动携带淘宝的 `cookie`，从而导致财产损失。这种钓鱼方式具有随机性。

### 3\. 如何防范 CSRF 攻击
*   **防范策略 1：堵住 XSS 漏洞**
    *   确保网站本身不存在 XSS 安全问题，从根源上减少 CSRF 借力的可能。
*   **防范策略 2：添加 Token 校验**
    *   在 HTTP Header 中添加与后台约定好的 `token`。
    *   **原理**：浏览器在发起请求时，只会自动携带 `cookie`，**不会自动携带** HTTP Header 中的 `token`。因此，伪造的跨站请求无法提供正确的 `token`，后台即可拦截。
*   **防范策略 3：校验 HTTP Referer**
    *   校验请求头中的 HTTP `Referer` 字段。
    *   **原理**：`Referer` 可以标识发起当前请求的来源网站域名。后台通过校验该域名，如果不是同一个合法域名，则直接拒绝访问。

## AI 总结

本次视频主要讲解了 Web 前端面试中高频的安全问题：**XSS 攻击**与 **CSRF 攻击**。
1. **XSS（跨站脚本攻击）** 的核心在于“注入恶意脚本”，防范的关键在于对敏感字符进行转义，且**必须由后端进行核心处理**，因为前端防御可被绕过。
2. **CSRF（跨站请求伪造）** 的核心在于“伪造用户请求”，它常利用 XSS 漏洞或钓鱼网站，依赖浏览器自动携带 `cookie` 的机制来执行恶意操作（如转账）。
3. **CSRF 的防范** 主要依靠三种手段：修复 XSS 漏洞、在请求头中引入无法被自动携带的 `token` 进行校验，以及通过校验 HTTP `Referer` 来拦截跨域伪造请求。两者结合理解，是应对大厂前端安全面试的关键。
