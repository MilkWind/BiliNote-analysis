## React 严格模式 (StrictMode) 的特点 *Content-[00:00]

React 的严格模式 (StrictMode) 主要用于在开发环境下帮助开发者发现潜在问题，其核心作用包括以下六点（面试时若记不全，重点记住前两点即可）：

1\. **识别不安全的生命周期（最重要）**：在 Fiber 架构下，`render` 函数执行的次数是不确定的，可能会执行多次。严格模式在开发环境下会故意让某些生命周期函数执行两次，以确保开发人员不要写出依赖执行次数的错误代码。
2\. **使用废弃 API 的警告**：对使用已废弃的 React 方法或 API 发出警告。
3\. **检查意外的副作用**：帮助检测组件中可能存在的意外副作用。
4\. **检查过时的 Context API**：对旧版 Context API 的使用进行警告。
5\. **确保可复用的状态**：帮助确保组件状态的可复用性。
6\. **使用 React 的一些其他警告**：提供其他开发环境下的最佳实践警告。

**面试建议**：如果无法背诵全部六点，重点回答“在 Fiber 架构下，`render` 执行次数不确定，严格模式会让部分生命周期执行两次以保证代码正确”以及“提供废弃方法的警告”。

## 受控组件的概念 *Content-[01:37]

受控组件 (Controlled Component) 是指将 UI 的状态完全交给 React 的 `state` 或 `props` 进行管理的组件。在受控组件中，表单元素（如 `<input>`）的 `value` 属性由 React 状态控制，不允许直接通过 DOM 去修改 `value`，任何修改都必须通过更新 React 状态来实现。

## Ref 的特点与 forwardRef *Content-[01:47]

- **Ref 的特点**：`Ref` 主要用于获取真实的 DOM 实例或 Class 组件的实例。需要注意的是，函数式组件 (Function Component) 默认是没有 `Ref` 的，直接在函数式组件上绑定 `Ref` 无法获取任何实例信息。
- **forwardRef 的作用**：用于实现 **Ref 转发**。当需要在函数式组件上获取内部真实 DOM（如 `<button>`）的实例时，可以使用 `forwardRef` 将组件包裹起来，并将接收到的 `ref` 传递给内部的 DOM 节点。这样在外部对该函数式组件绑定 `ref` 时，就能成功获取到内部 DOM 的实例。

## useMemo 与 useCallback 的区别与应用 *Content-[02:46]

这两个 Hook 的底层原理几乎相同，核心目的都是为了**缓存数据以优化性能**，最终目标是**优化渲染**。

- **区别**：
  - `useMemo`：缓存的是**计算结果**（值）。
  - `useCallback`：缓存的是**函数**（引用）。
- **渲染优化原理**：React 组件重新渲染的条件之一是 `props` 发生变化。React 会对 `props` 进行浅比较，如果引用一致则不会触发重新渲染。
- **配合使用**：为了达到优化渲染的目的，`useMemo` 和 `useCallback` 通常需要配合 `React.memo` 一起使用，以确保子组件在 `props` 引用未改变时跳过渲染。

## 高阶组件 (HOC) 及常见问题 *Content-[04:06]

高阶组件 (Higher-Order Component, HOC) 本质上是一个函数，它接收一个组件作为参数，并返回一个经过处理的新组件。随着 Hooks 的普及，HOC 的使用频率已有所降低，但在面试中仍有两个常考问题：

1\. **Ref 不一致问题**：在外层 HOC 绑定 `Ref` 时，`Ref` 到底指向原组件还是新组件？为了解决这个问题，需要在 HOC 内部使用 `forwardRef` 进行 `Ref` 转发。
2\. **静态方法丢失问题**：如果传入的是 Class 组件，原组件上的 `static` 静态方法在返回的新组件中会丢失。解决此问题通常需要借助第三方插件（如 `hoist-non-react-statics`）来拷贝静态方法。

## 错误边界组件 (Error Boundary) *Content-[05:08]

错误边界 (Error Boundary) 是 React 原生提供的一种组件，用于捕获子组件树中的 JavaScript 错误，防止整个应用崩溃。

- **实现方式**：通过生命周期方法 `getDerivedStateFromError` 捕捉错误并更新状态（如设为 `true` 以显示错误提示 UI），底层依赖 `componentDidCatch` 来捕获错误。
- **注意事项（面试重点）**：
  1\. 只能捕获**子组件**的错误，无法捕获错误边界组件自身的错误。
  2\. 无法捕获子组件中**异步方法**（如 `setTimeout`、`Promise` 等）抛出的错误。

## Compose 函数的理解与实现 *Content-[06:34]

`Compose` 函数是 Redux 中间件的核心原理，常用于函数组合。

- **实现思路**：接收一个函数数组（类似将 `arguments` 对象转为数组），然后使用 `reduce` 方法将函数从右向左（或从左向右，视具体实现而定）进行组合，使得后一个函数的执行结果作为前一个函数的参数。
- **代码细节**：需要处理边界条件。如果数组长度为 0，直接 `return`；如果长度为 1，直接返回该函数，无需 `reduce`。核心逻辑在于巧妙的一行 `reduce` 代码。
- **面试建议**：大厂（如字节跳动）笔试题常考手写 `compose`，建议熟记并能够默写核心实现代码。

## React 插槽 (Portal) 的理解 *Content-[08:07]

React 插槽 (Portal) 提供了一种将子节点渲染到存在于父组件以外的 DOM 节点（如直接挂载到 `document.body`）的方式。

- **使用场景**：常用于页面结构复杂、DOM 嵌套很深的弹窗组件。
- **核心优势**：
  1\. **弹窗层级 (`z-index`) 方便管理**：将弹窗统一挂载到 `document` 顶层，避免深层嵌套导致 `z-index` 难以控制，方便管理弹出层级。
  2\. **方便调试 (Debug)**：在开发者工具中可以直接在 `document` 下找到弹窗 DOM，避免在深层嵌套的 DOM 树中艰难寻找弹窗来源。

## 避免不必要的 Render *Content-[09:51]

在 React 中，避免不必要的重新渲染主要有以下三种方案：

1\. **Class 组件方案**：使用 `shouldComponentUpdate` 生命周期方法，或让组件继承 `PureComponent`，通过对比前后 `props` 和 `state` 的引用来决定是否渲染。
2\. **高阶组件 (HOC) 方案**：在 HOC 内部实现类似 `shouldComponentUpdate` 的逻辑，支持根据业务需求进行定制化（例如：只有当某个特定属性发生变化时才允许重新渲染）。
3\. **函数组件方案**：使用 `React.memo` 包裹组件，并配合 `useMemo` 或 `useCallback` 来保持 `props` 引用的稳定性。

## Props 单向数据流 *Content-[10:36]

React 的数据流设计初衷是**自上而下（单向）** 的。这种设计使得数据流向更加清晰，更容易进行状态管理和追踪。如果允许数据自下而上修改，会导致数据流混乱，难以维护。因此，`props` 只能从上到下传递和修改，不能反向修改。

## React Diff 算法 *Content-[10:56]

React 的 Diff 算法基于三个核心约定：
1\. 只有相同的组件类型才会生成相同类型的 DOM 树。
2\. 可以通过 `key` 属性来标识哪些子元素在不同渲染中是稳定的。
3\. 算法只进行同层级比较，不会跨层级移动节点。

- **核心考察点**：面试中重点在于理解 `for` 循环遍历元素时的**节点移动与复用过程**。例如，将 `A B C D E F G` 变为 `A B D N A B C D E F`，算法需要识别出 `G` 被删除，并正确复用其他节点。
- **底层机制**：在对比前后数组元素时，React 会使用 `Map` 数据结构存储老节点的 Fiber 对象。在遍历过程中，如果发现老节点可以复用，则从 `Map` 中将其删除；遍历结束后，`Map` 中剩余的老节点即为未使用的节点，React 会给它们打上标记，并在 `commit` 阶段将其删除。
- **面试建议**：建议先从宏观上理解基于 `Map` 和节点复用的机制，具体的逐个对比细节可根据兴趣深入研究。
