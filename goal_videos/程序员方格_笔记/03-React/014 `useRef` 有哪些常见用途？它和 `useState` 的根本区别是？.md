## 深入理解 useRef 及其与 useState 的核心区别 *Content-[01:13]

### useRef 的基本概念
- 调用 `useRef` 会返回一个可变的 `ref` 对象。
- 该对象包含一个非常重要的属性：`.current`。
- `ref` 对象在组件的整个生命周期里保持不变（持久化）。无论组件因 `props` 或 `state` 变化重新渲染多少次，`useRef` 返回的始终是同一个对象引用。
- 开发者可以自由修改 `.current` 的值（例如重新赋值）。
- **最关键的一点**：当修改 `ref.current` 的值时，React **不会**重新触发组件的渲染。

### useState 的基本概念回顾
- `useState` 用于在函数组件中引入状态（例如计数器 `count`）。
- 当调用 `set` 函数（如 `setCount`）更新值时，如果新值与当前值不同，React 会计划一次组件的重新渲染。
- 在下一次渲染时，状态的值会更新为新值。

### 核心区别总结
- **useState**：用于管理那些发生变化时，需要让 UI 自动更新的数据状态。通过 `set` 函数更新值会触发组件的重新渲染。
- **useRef**：用于存储那些发生变化时，**不希望**触发 UI 更新的可变值。修改 `.current` 属性不会触发组件重新渲染。
- **形象比喻**：可以将 `useRef` 想象成给函数组件附加了一个实例变量或一个“小背包”。你可以在背包里存放一些数据，这些数据的改变不会让整个组件重新渲染；而 `useState` 里的数据一旦改变，组件就会重新渲染。

## 面试回答指南：核心区别与主要用途 *Content-[04:10]

当面试官问到 `useRef` 和 `useState` 的区别，以及 `useRef` 的常见用途时，可以按照以下逻辑进行回答：

1\. **点明核心区别**：
最根本的区别在于**是否会触发组件的重新渲染**。`useState` 用于管理组件状态，通过 `set` 函数更新时会触发重新渲染，让界面反映最新状态；而 `useRef` 创建的是一个可变容器（包含 `.current` 属性），修改 `.current` 的值不会导致组件重新渲染，且返回的 `ref` 对象在整个生命周期内保持不变。

2\. **描述设计目的和主要用途**：
基于上述核心区别，`useRef` 主要有两大用途：
- **用途一：访问和操作 DOM 元素**。将 `ref` 对象附加到 JSX 元素的 `ref` 属性上，通过 `ref.current` 直接访问 DOM 节点，执行获取焦点、触发动画、测量尺寸等操作。
- **用途二：存储与渲染无关的可变值**。在组件多次渲染之间持久化某些数据，且这些数据的变化不应触发重新渲染。例如：定时器 ID、上一次的 `props` 或 `state` 值、事件处理函数中需要共享但不想触发渲染的数据。

## 应用场景一：访问和操作 DOM 元素 *Content-[06:27]

这是 `useRef` 最经典、最广为人知的用法。例如：在组件加载后，让一个输入框自动获取焦点。

### 代码逻辑拆解
- 首先，使用 `useRef` 创建一个 `inputRef` 对象，初始值通常设为 `null`（因为在组件首次渲染完成前，DOM 节点不存在）。
- 将 `inputRef` 传给 `<input>` 元素的 `ref` 属性。
- 当 React 将 `<input>` 渲染到真实 DOM 时，会自动将真实 DOM 节点的引用赋值给 `inputRef.current`。
- 在 `useEffect` 内部（组件挂载完成、DOM 构建好后），`inputRef.current` 就会指向真实的 input 节点，此时可以安全地调用 `inputRef.current.focus()` 方法。

### 面试追问：为什么这里适合用 useRef 而不是 useState？
- DOM 节点的引用本身并不是一个需要驱动 UI 渲染的状态，我们只需要一个稳定的引用来操作它。
- 如果使用 `useState` 来存储 DOM 节点，当节点引用发生变化时，通常会触发不必要的重新渲染。
- `useRef` 能够提供一个持久化的引用，且其变化不会导致重新渲染，这是最根本的原因。

## 应用场景二：管理定时器 ID *Content-[08:51]

例如：实现一个每秒更新的计数器，并且能够随时清除它。

### 代码逻辑拆解
- 使用 `useRef` 创建 `timerRef`。
- `timerRef.current` 用来保存 `setInterval` 返回的定时器 ID。
- 当需要清除定时器时，直接读取 `timerRef.current` 并调用 `clearInterval` 即可。

### 为什么不用 useState 来存 timer ID？
- 如果使用 `useState` 存储 timer ID，在 `useEffect` 中调用 `setTimerId` 时，会额外触发一次组件渲染。
- 这个渲染对于用户界面来说是没有必要的，因为 timer ID 本身对用户不可见，它的改变也不需要更新 UI。
- `useRef` 完美避开了这个问题，它只需要静静地保存这个 ID，不干扰正常的渲染流程。

## 应用场景三：存储上一次的 props 或 state *Content-[10:20]

有时候我们需要知道某个 `prop` 或 `state` 在上一次渲染时的值，以便用来进行比较或执行某些特定逻辑。

### 代码逻辑拆解与原理分析
- 使用 `useRef` 创建 `prevRef`，初始值设为 `undefined`。
- 首次渲染时，`prevRef.current` 为 `undefined`。
- 在 `useEffect` 内部（渲染之后执行），将当前的值赋值给 `prevRef.current`。
- 当用户输入导致值发生变化、组件重新渲染时，在**此次渲染**中，`prevRef.current` 显示的仍然是**上一次**渲染后存入的值。
- 渲染完成之后，`useEffect` 再次执行，将当前的最新值更新到 `.current` 属性中，为下一次渲染做准备。
- **总结**：`prevRef` 就像一个“延迟一拍”的记录器。它的更新不会触发新的渲染，而是为下一次渲染提供历史数据。

## 课程总结 *Content-[12:00]

- **核心逻辑**：`useRef` 返回一个可变的 `ref` 对象，修改其 `.current` 属性不会触发组件的重新渲染。这与 `useState` 更新状态会触发重新渲染形成了鲜明的对比。
- **两大用途**：访问 DOM 元素、存储与渲染无关的可变值。
- **面试技巧**：深刻理解“是否触发组件重新渲染”这一根本区别，并结合具体的应用场景（如 DOM 操作、定时器、历史状态记录）进行阐述，就可以在面试中游刃有余地应对相关问题。
