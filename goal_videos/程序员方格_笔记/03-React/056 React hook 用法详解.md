## 1. React Hooks 简介与优势 *Content-[00:00]

React Hooks 是 React 16.8 版本之后引入并推荐的新特性，它的出现极大地提升了 React 开发的效率。目前绝大部分前端开发都已采用 Hooks 的方式进行组件开发。

**为什么使用 Hooks？**
- **提升开发效率**：代码复用性和可扩展性更强，能够方便地抽取公共组件或方法。
- **状态逻辑复用**：Hooks 允许在无需修改组件结构的情况下，复用状态逻辑。
- **赋能函数组件**：在 Hooks 出现之前，函数组件被视为纯函数（无状态的 Stateless 组件），只有 Class 组件才能拥有自身状态。Hooks 让函数组件拥有了自己的状态，从而更好地进行 UI 渲染和逻辑复用。
- **契合函数式编程思想**：Hooks 允许将组件中相互关联的部分，根据业务逻辑拆分成更小的函数，体现了函数式编程的思想。
- **简化 Class 组件**：Class 组件在很多时候更多是作为语法糖存在，使用 Hooks 无需学习复杂的函数式或响应式编程相关技术，降低了心智负担。

## 2. useState 详解与使用原则 *Content-[02:49]

`useState` 是在函数组件中创建和管理状态的核心 Hook。

**基本用法**
- 返回一个数组：第一个元素是当前状态值，第二个元素是修改状态的方法（类似于 Class 组件中的 `this.setState`）。
- **初始化参数**：可以传入一个具体的值，也可以传入一个函数。强烈建议使用**函数**来进行**惰性初始化**。

**使用原则与最佳实践**
1. **扁平化状态**
   - **避免深层嵌套**：状态对象嵌套过深会导致修改起来非常麻烦。例如，将 `user` 对象嵌套 `address` 再嵌套 `city` 是不推荐的。
   - **拆分状态**：建议将状态拆分为独立的变量，如分别定义 `name` (set name)、`age` (set age)、`address` (set address)。
   - **合并关联状态**：对于具有强关联性的状态（如宽度 `width` 和高度 `height`），可以通过对象的方式集中合并管理。

2. **惰性初始化 (Lazy Initialization)**
   - **避免重复计算**：当初始状态需要进行复杂的计算（如大量数据的累加）时，如果直接传入计算结果，会导致每次组件渲染时都重新执行该计算，造成严重的性能损耗。
   - **传入函数**：通过向 `useState` 传入一个函数，可以确保该复杂的计算逻辑**仅在组件首次挂载时执行一次**。在后续的更新阶段，React 会直接复用已存储的值。
   - **底层逻辑**：React 内部会判断初始化参数是否为函数，如果是则调用该函数获取初始值，否则直接赋值，最终返回状态和 dispatcher（修改方法）。

## 3. useEffect 详解与最佳实践 *Content-[09:28]

`useEffect` 让函数组件具备了类似 Class 组件的生命周期概念，用于处理副作用（如数据请求、DOM 操作、事件监听等）。

**基本用法**
- **参数一（处理函数）**：包含具体的副作用逻辑。
- **参数二（依赖数组）**：用于限定触发条件。只有当数组中的依赖项（如 state、props 等变量）发生变化时，才会重新执行处理函数。

**执行时机**
- **组件初始化**：在 DOM render 完成后执行一次。
- **依赖更新**：当依赖数组中的值发生变化时再次执行（类似于 `componentDidUpdate`）。

**清理函数 (Clean up)**
- 处理函数可以返回一个函数，称为清理函数。
- 该函数会在**下一次重渲染时**（在执行新的副作用之前）被调用，用于清除上一次渲染产生的副作用（如清除定时器 `clearInterval`、取消事件订阅等）。

**最佳实践**
- **职责单一**：不要滥用，避免将所有逻辑都塞进一个 `useEffect` 中。
- **逻辑拆分**：根据不同的业务场景和依赖项，将逻辑拆分到多个 `useEffect` 中。例如，数据请求（依赖 `dataId`）和事件监听（仅需初始化时绑定）应分开处理。这样可以避免某个依赖变化时连带触发不相关的逻辑，提升代码可读性和执行效率。

## 4. useLayoutEffect 详解与执行时机 *Content-[14:38]

`useLayoutEffect` 的用法与 `useEffect` 类似，但核心区别在于**执行时机**。

**执行时机与特点**
- **同步触发**：在所有 DOM 变更完成后**同步**触发，先于浏览器的绘制阶段。
- **避免视觉闪烁**：如果在 `useEffect` 中修改 DOM 布局或样式，由于它是异步执行的，可能会导致用户在绘制前看到中间状态，产生视觉上的闪烁或不一致。使用 `useLayoutEffect` 可以在浏览器绘制前同步修改样式，避免这种视觉问题。

**React 渲染与 Hooks 执行顺序**
1. React 开始渲染组件，生成虚拟 DOM。
2. 计算完成后，更新真实 DOM。
3. 执行 `useEffect` 的清理函数（Clean up，如果存在）。
4. 执行 `useLayoutEffect`（同步读取布局并修改 DOM 样式）。
5. 浏览器进行页面绘制。
6. 执行 `useEffect` 的副作用函数。

## 5. useRef 详解及其他 Hooks 概览 *Content-[17:40]

**useRef 详解**
- **创建引用对象**：用于访问和操作真实的 DOM 元素。
- **保存可变值**：可以存储与渲染无关的可变数据（如定时器 ID、上一次的状态值）。
- **跨渲染周期共享**：使用 `useRef` 保存的数据在组件重新渲染时不会丢失，能够跨渲染周期共享数据。

**其他 Hooks 概览**
- 视频中提及了其他常用的内置 Hooks，如 `useMemo`（缓存计算结果）、`useCallback`（缓存函数引用）、`useContext`（跨组件传递数据）等。
