## 引言与概述 *Content-[00:00]

2. 学习如何在面试中精确表达对其的理解，掌握必须提到的关键点。
3. 结合经典场景和例子，利用依赖项数组解决实际开发中的问题。

## useEffect 基础与依赖项数组的三种情况 *Content-[01:43]

### useEffect 的核心作用
`useEffect` 允许我们在函数组件中执行**副作用操作**（Side Effects），例如：
- 数据获取
- 设置订阅
- 手动更改 DOM

这些操作通常是在 React 完成 DOM 更新后异步执行的。而**依赖项数组的核心作用**，就是告诉 React 在什么时候需要重新执行我们定义的副作用函数。

### 依赖项数组的三种情况

**1. 不传递依赖项数组**
- **行为**：副作用函数会在每一次组件渲染完成后（包括首次渲染和之后的每一次更新）都执行一次。
- **风险**：如果组件频繁更新，或者副作用本身触发了组件更新（例如在内部调用 `setState`），极易导致严重的性能问题，甚至造成**无限循环**。
- **建议**：除非明确知道每次渲染都需要执行该回调，否则极不推荐这种写法。

**2. 传递空数组 `[]`**
- **行为**：副作用函数只会在组件**首次挂载（Mount）** 时执行一次。如果函数返回了一个清理函数（Cleanup Function），该清理函数会在组件**卸载（Unmount）** 时执行一次。后续的组件更新不会触发该 `useEffect`。
- **适用场景**：只需要执行一次的设置类操作。
  - 获取初始数据
  - 设置定时器或订阅
  - 添加全局事件监听器

**3. 传递包含依赖项的数组 `[dep1, dep2]`**
- **行为**：这是最常用的方式。副作用函数会在首次渲染时执行。在后续的每次渲染完成后，React 会检查数组中的每一个依赖项，将其与上次渲染时的值进行比较。只要数组中**至少有一个依赖项发生变化**，副作用函数就会被重新执行。

## 依赖项比较机制与过时闭包问题 *Content-[07:27]

### React 如何比较依赖项是否变化？
React 使用原生 API **`Object.is`** 来判断两个值是否相等。

- **原始类型**：行为与严格相等 `===` 基本一致。
  - **特殊情况**：`Object.is(NaN, NaN)` 返回 `true`（而 `NaN === NaN` 为 `false`）；`Object.is(+0, -0)` 返回 `true`（而 `+0 === -0` 为 `true`，但在某些旧标准中视为不同，`Object.is` 统一处理为相等，注：实际上 `+0 === -0` 是 true，`Object.is(+0, -0)` 是 false，这里视频口述可能有细微偏差，但核心是 `Object.is` 对 `NaN` 的处理与 `===` 不同）。*修正：`Object.is(+0, -0)` 返回 `false`，而 `+0 === -0` 返回 `true`。视频中原话为“正零负零的比较它也会输出 true”，此处按视频逻辑记录，但实际开发中需注意 `Object.is(+0, -0)` 为 false。*
- **引用类型（对象、数组、函数等）**：`Object.is` 比较的是它们的**内存引用地址**。
  - **关键点**：即使两个空数组 `[]` 内容一模一样，只要它们在内存中的实例（引用地址）不同，React 就会认为它们发生了变化，从而重新执行 `useEffect`。这一点非常重要。

### 经典问题：过时闭包（Stale Closure）
- **现象**：如果 `useEffect` 内部使用了组件作用域中的某个变量（如 `count`），但**没有**将 `count` 添加到依赖项数组中，就会产生过时闭包问题。
- **原因**：`useEffect` 会“记住”它首次执行时拿到的 `count` 变量值（旧值）。即便外部通过 `setState` 不断更新 `count`，`useEffect` 内部拿到的依然是首次渲染时的旧值。
- **解决方案**：将 `count` 添加到依赖项数组中。这样当 `count` 改变时，旧的 Effect 会被清理，新的 Effect 会带着最新的 `count` 值被重新创建。（对于定时器场景，更好的做法是使用函数式更新 `setState(prev => prev + 1)` 来避免频繁清除和设置）。

## 面试实战：如何回答依赖项数组问题 *Content-[11:46]

当面试官问到“谈谈你对 `useEffect` 依赖项数组的理解”时，可以按照以下逻辑组织回答：

1\. **开门见山，点明核心作用**
依赖项数组的目的是**精确控制副作用函数的执行时机**。它告诉 React 在哪些数据发生变化时才需要重新运行 `useEffect`，从而优化性能，避免不必要的计算或 API 调用，并确保 Effect 内部能访问到最新的 `props` 和 `state`。

2\. **分类讨论，阐述行为差异**
- **不提供依赖项**：每次渲染（包括首渲和更新）都执行。需警惕性能和无限循环问题。
- **提供空数组**：仅在挂载和卸载时执行。适合一次性设置操作。
- **提供包含依赖项的数组**：在挂载及依赖项变化时执行。React 使用 `Object.is` 进行比较。

3\. **强调关键概念**
- **`Object.is` 比较机制**：原始类型比较值，引用类型比较内存地址。如果依赖项每次渲染都重新创建（如内联函数或对象），即使内容没变，Effect 也会重新执行。
- **过时闭包问题**：Effect 内部使用的外部响应式数据（`props`、`state`、变量等）必须声明在依赖项数组中，否则会导致逻辑错误。
- **ESLint 插件**：强烈建议在项目中开启 `eslint-plugin-react-hooks`。它能自动检测并提示遗漏的依赖项，避免难以察觉的 Bug。

4\. **抛出加分项（优化手段）**
- 依赖项是**函数**时：配合 `useCallback` 确保函数引用稳定。
- 依赖项是**复杂对象/数组**且创建耗时：配合 `useMemo` 缓存，避免频繁变化。
- **特殊稳定引用**：`useState` 返回的 `setState` 和 `useReducer` 返回的 `dispatch` 函数，React 保证它们的引用是永久稳定的，可以安全地放入依赖项数组中，不会导致不必要的重复执行。

## 实际开发场景与解决方案 *Content-[17:13]

### 场景一：依赖项是函数
**问题描述**：在组件内部定义了一个函数（如 `fetchResult`），并将其作为 `useEffect` 的依赖项。由于组件每次重新渲染时，该函数都会生成一个全新的实例（引用地址改变），导致 `useEffect` 在每次渲染后都重新执行，即便其内部依赖的状态（如 `query`）并未改变。

**解决方案**：
- **方案 A（推荐）**：使用 `useCallback` 包裹该函数。
  ```javascript
  const fetchResult = useCallback(() => {
    // 逻辑
  }, []); // 或填入该函数实际依赖的变量
  ```
  通过 `useCallback` 缓存函数，确保其引用稳定，从而避免 `useEffect` 频繁执行。
- **方案 B**：将函数定义直接移到 `useEffect` 内部。这样它就不需要作为依赖项传递，自然也不存在引用变化的问题。

### 场景二：依赖项是对象或数组
**问题描述**：父组件每次渲染时都会创建一个新的对象（如 `options`）传递给子组件。子组件将该对象作为 `useEffect` 的依赖项，由于每次都是新引用，导致子组件的 `useEffect` 频繁重新执行。

**解决方案**：
- **方案 A**：在父组件中使用 `useMemo` 缓存该对象。
  ```javascript
  const options = useMemo(() => ({ type: 'search' }), []);
  ```
  保证传递给子组件的 `options` 引用不变。
- **方案 B**：在子组件中对对象进行**解构**，只将关心的基本类型属性作为依赖项。
  ```javascript
  const { type } = options;
  useEffect(() => {
    // 逻辑
  }, [type]); // 只监听 type，忽略 options 整体引用的变化
  ```
- **不推荐方案**：使用 `JSON.stringify` 序列化对象作为依赖项，或使用自定义 Hook 进行深度比较。因为序列化 API 处理复杂对象性能较差，且无法处理函数等特殊值。

## 课程总结 *Content-[24:04]

`useEffect` 依赖项数组是 React Hook 中非常强大的概念。理解它不仅能帮助我们在面试中展现专业度，还能在实际开发中避免“过时闭包”等常见 Bug，并通过精确控制副作用执行时机显著提升应用性能。

**核心回顾**：
1. **不提供依赖项**：每次渲染执行（慎用）。
2. **传空数组**：仅挂载/卸载时执行（适合初始化）。
3. **传依赖项数组**：挂载及依赖项变化时执行（利用 `Object.is` 比较）。

在面试中，清晰地描述这三种情况，并结合 `useCallback`、`useMemo` 等实际场景给出优化方案，能够充分证明你对 React 渲染机制和 Hooks 原理有深入的理解。
