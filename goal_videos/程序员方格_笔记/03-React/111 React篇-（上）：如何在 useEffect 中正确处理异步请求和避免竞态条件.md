## 1. 引言：useEffect 异步操作的常见痛点 *Content-[00:01]
- 在编写 React 应用时，开发者经常会遇到以下与 `useEffect` 异步操作相关的痛点：
  - 组件明明已经卸载，但控制台仍然报警，提示“不能在未挂载的组件上更新 state”。
  - 当依赖项频繁变化时，`useEffect` 中发起的异步请求行为总是显得非常诡异。
- 这些问题通常都是由于在 `useEffect` 中处理异步操作的“姿势”不正确所导致的。
- 本节的核心目标：
  - 弄清楚 `useEffect` 对回调函数的核心要求。
  - 学习在 `useEffect` 中正确的异步写法。
  - 认识什么是“竞态条件”（Race Condition），为后续深入解决该问题打好基础。

## 2. 核心原理：为什么 useEffect 不能直接使用 async 函数 *Content-[01:13]
- `useEffect` 主要用于处理副作用（如数据获取、订阅、手动更改 DOM 等）。
- 其基本形态为 `useEffect(callback, dependencies)`，这里的关键在于第一个参数（即回调函数）。
- **React 对回调函数返回值的期望**：
  1. 同步执行副作用，不返回任何内容（即返回 `undefined`）。
  2. 返回一个清理函数（用于组件卸载或依赖变化时的清理操作）。
  3. 什么都不做，直接返回 `undefined`。
- **如果直接将 `async` 函数作为回调会怎样？**
  - 众所周知，`async` 函数会隐式返回一个 `Promise` 对象。
  - 如果 `useEffect` 的回调里面返回了一个 `Promise`，那么当组件卸载或者依赖项变化导致 `useEffect` 需要重新运行并尝试清理时，React 就会试图把这个 `Promise` 当作清理函数来调用。
  - 这显然不是我们想要的结果，会导致运行时错误或非预期行为。
- **结论**：`useEffect` 里面的回调函数本身**不能**是 `async` 函数。

## 3. 正确姿势：如何在 useEffect 内部执行异步操作 *Content-[03:03]
- 既然不能直接传入 `async` 函数，正确的做法非常简单：
  - 直接在 `useEffect` 的回调函数**内部**定义一个 `async` 函数。
  - 然后在该回调中立即调用这个内部定义的 `async` 函数。
- **代码结构示例**：
  ```javascript
  useEffect(() => {
    // 在内部定义 async 函数
    const fetchData = async () => {
      // 执行异步操作
    };
    
    // 立即调用
    fetchData();
  }, [dependencies]);
  ```
- **这种写法的优势**：
  - 确保了 `useEffect` 本身接收的直接回调函数是**同步**的。
  - 如果需要有返回值，可以正常设置并返回一个清理函数，而不是直接返回 `async` 函数产生的 `Promise`。

## 4. 概念解析：什么是竞态条件（Race Condition） *Content-[03:49]
- 在正确发起了异步请求之后，还有一个非常常见且重要的问题需要处理，那就是**竞态条件**。
- **典型场景描述**：
  1. 组件因为某个 prop（例如一个搜索词 `query` 变量）的变化，触发 `useEffect` 发起了**请求 A**。
  2. 在请求 A 还没有返回的时候，prop 又变了（例如用户快速输入了新的搜索词），组件再次触发 `useEffect`，发起了一个新的数据**请求 B**。
  3. 因为网络波动或其他原因，**请求 B 先返回**，组件调用 `setState` 更新状态。
  4. 过了一会，**请求 A 才返回**，组件再次调用 `setState` 更新为请求 A 的结果。
- **导致的结果**：
  - 这时候用户看到的就不是最新搜索词（请求 B）的结果，而是上一个搜索词（请求 A）的结果。
- **竞态条件定义**：
  - 多个异步操作完成的顺序与他们触发的顺序不一致，导致了最终的结果是非预期的。

## 5. 面试实战：标准回答话术总结 *Content-[05:21]
- **问题 1：`useEffect` 回调函数可以是 `async` 吗？为什么？**
  - **标准回答**：不可以。因为 `async` 函数会隐式返回一个 `Promise`，而 `useEffect` 期望它的回调函数要么不返回任何东西（`undefined`），要么返回一个清理函数。如果 `useEffect` 回调直接是 `async` 函数，那么它返回的 `Promise` 会在组件卸载或者 effect 需要清理时，被 React 错误地当作清理函数来尝试执行，这样通常会导致运行时错误或者非预期的行为。
- **问题 2：如果确实需要在 `useEffect` 中执行异步操作（比如获取数据），应该怎么做呢？**
  - **标准回答**：我们可以在 `useEffect` 的回调函数内部定义一个 `async` 函数，然后立即调用它。这样就能确保 `useEffect` 本身接收的直接回调是同步的，并且返回值是符合原本预期的。同时，我们还需要关注 `useEffect` 操作可能带来的**竞态条件**问题，并且使用适当的清理机制来避免组件卸载或者依赖变化导致的状态更新错误。
