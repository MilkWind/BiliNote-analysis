## 为什么需要生命周期 *Content-[00:29]

在深入了解具体的钩子函数之前，我们需要先理解为什么 Vue 需要提供生命周期这个概念。

一个 Vue 组件的一生，从在内存中被创建，到渲染到页面上显示，再到因为数据变化而更新，最后不再需要时被从页面上卸载。在这一条完整的生命线中，我们总希望在某些特定的时间点“插个队”，执行一些自定义的逻辑。

**常见的应用场景包括：**
- **组件刚显示在页面上时**：非常适合向服务端请求首屏需要的数据。
- **建立长连接或定时器**：例如建立 WebSocket 连接，或者设定一个每秒更新的定时器。
- **集成第三方 DOM 库**：例如图表库、动画库，必须等真实的 DOM 元素准备好之后才能进行初始化。
- **组件离开时**：必须负责任地把之前建立的连接、定时器、事件监听等清理掉，否则极易造成内存泄漏。

所有这些关键的时间点，都是 Vue 通过生命周期函数提供给我们的切入点，让我们可以精准地在组件生命的不同阶段执行想要的代码。

## Vue 生命周期的四个主要阶段 *Content-[02:03]

一个完整的 Vue 组件生命周期，主要可以分为以下四个阶段：

- **创建阶段**：组件在内存里被初始化的过程。
- **挂载阶段**：组件第一次被渲染到真实的 DOM 上的过程。
- **更新阶段**：当组件的响应式数据发生变化时，会导致它需要重新渲染，此时进入该阶段。这个阶段可能会循环发生很多次。
- **卸载阶段**：组件从 DOM 中被移除的时候。

**注意**：在挂载、更新和卸载这三个阶段中，Vue 都非常贴心地提供了 `before`（之前）和 `after`（之后，通常以具体动作命名）这两个相邻的钩子。

## 常用生命周期钩子详解 *Content-[03:20]

我们不需要死记硬背所有钩子，先对最常用的几个核心钩子建立直观的印象：

- **`onMounted`**：最常用的钩子之一。表示组件已经被挂载到页面上，此时真实的 DOM 已经准备好。特别适合用来做一些初始化的副作用，如请求数据、初始化第三方库等。
- **`onUnmounted`**：组件即将被卸载销毁时触发。它通常和 `onMounted` 成双成对出现，是我们在组件离开之前进行各种清理工作的最佳时机。
- **`onUpdated`**：当数据变化且 DOM 同步更新完成之后触发。主要用在需要基于更新后的 DOM 做一些操作的场景。例如：让一个聊天列表在收到新消息后自动滚动到底部。
- **`onBeforeUpdate`**：数据变化，DOM 同步更新完成之前触发。在这里可以访问到更新前的状态，例如旧的 DOM 结构，或者在组件卸载前做最后一次的数据确认。

## 代码示例：副作用的创建与清理 *Content-[04:45]

在实际开发中，副作用的管理至关重要。以下是一个标准的代码处理模式：

- 在 `onMounted` 钩子中，我们建立一个定时订阅、事件监听（如 `onResize`）或网络连接。
- 对应的，我们**必须**在 `onUnmounted` 钩子中调用相应的清理函数，来取消这个订阅或监听。

**核心原则**：有始有终。这是一个非常非常重要的编程习惯，也是避免资源泄漏和内存泄漏的关键。

## 父子组件生命周期执行顺序演示 *Content-[06:01]

通过一个包含父子组件的示例，我们可以清晰地观察生命周期的执行顺序和触发时机：

- **页面初次加载（挂载过程）**：
  - 执行顺序：父组件 `onBeforeMount` -> 子组件 `onBeforeMount` -> 子组件 `onMounted` -> 父组件 `onMounted`。
  - **结论**：组件的挂载过程是“先父后子”，但是完成挂载（触发 `mounted`）的过程是“先子后父”。

- **父组件数据变化（更新过程）**：
  - 点击父组件按钮改变数据，触发父组件的 `onBeforeUpdate` 和 `onUpdated`。子组件不受影响。

- **隐藏子组件（卸载过程）**：
  - 触发子组件的 `onBeforeUnmount` 和 `onUnmounted`，说明子组件被正确卸载。随后父组件发生了一次更新。

- **显示子组件（重新挂载）**：
  - 子组件的 `onBeforeMount` 和 `onMounted` 再次被触发。说明每一次的显示和隐藏，都是一个完整的挂载和卸载过程。

- **子组件数据变化（子组件更新）**：
  - 每次只有子组件的 `onBeforeUpdate` 和 `onUpdated` 被触发，父组件没有任何反应。
  - **结论**：父组件的更新是独立的，子组件的数据变化并不会影响到父组件。

## 实战建议与常见避坑指南 *Content-[08:45]

在项目的实际应用中，请务必牢记以下几点建议和避坑指南：

1\. **初始化与清理必须成双成对**：凡是在 `onMounted` 里面创建的副作用（如定时器、事件监听、网络连接等），都必须在 `onUnmounted` 里面清理掉。

2\. **慎用 `onUpdated` 等更新钩子**：尽量避免在里面放置复杂的业务逻辑，**绝对不要**在里面直接修改响应式数据。因为修改数据会再次触发更新，进而再次进入 `onUpdated`，形成无限更新循环（死循环），最终导致应用崩溃。

3\. **数据获取与 SSR（服务端渲染）注意事项**：
  - 对于纯客户端渲染（CSR）的应用，把首屏数据获取的逻辑放在 `onMounted` 钩子里是非常普遍且合理的做法。
  - 如果使用了服务端渲染（SSR），需要特别注意：`onMounted` 钩子在服务端是**不会执行**的。因此，任何依赖浏览器 API（例如 `window` 对象）的代码都不能放在这里，否则会直接报错。

- **挂载阶段**：`onBeforeMount` 和 `onMounted`
- **更新阶段**：`onBeforeUpdate` 和 `onUpdated`
- **卸载阶段**：`onBeforeUnmount` 和 `onUnmounted`
