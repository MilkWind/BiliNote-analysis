## Redux 中间件概念及常用中间件 *Content-[00:00]
- **Redux 中间件的本质**：
  - 利用 `compose` 函数实现了函数返回值的一个链条。
  - 换一个角度讲，中间件实际上是对 `store.dispatch` 方法的增强。
- **常用 Redux 中间件**：
  - 面试官询问“用过哪些 Redux 中间件”，主要是为了考察候选人项目中数据状态管理的实际落地情况。
  - 市面上出现频次较高的中间件主要有三个：`redux-thunk`、`redux-saga` 和 `redux-observable`。
  - **技术演进**：
    - `redux-saga` 及其封装库（如 `dva`）目前使用已经相对较少，主要因为对 Hooks 的支持不够友好。
    - 目前业界使用最多、最推荐的是 **Redux Toolkit (RTK)**。

## redux-thunk 原理与优缺点 *Content-[00:48]
- **核心原理**：
  - `redux-thunk` 在 `dispatch` 时增加了一层判断逻辑。
  - 如果传入的 `action` 是一个函数，则继续执行该函数，并向该函数注入 `dispatch` 和 `getState` 等参数。
  - 在函数内部，可以继续调用 `dispatch` 来触发其他 action。
- **解决的问题**：
  - 允许 `action` 创建函数返回一个函数而不是普通的对象，从而支持异步操作（如 API 请求）。
- **缺点与现状**：
  - 对于大型项目而言，`redux-thunk` 的功能过于简单。
  - 处理复杂异步逻辑时，写法繁琐且复杂，容易出现逻辑难以维护的情况。
  - **结论**：目前在新项目中已不再推荐单独使用 `redux-thunk`。

## Redux Toolkit 简介 *Content-[01:25]
- **定位**：
  - Redux Toolkit (RTK) 是官方提供的数据管理中间件综合解决方案。
- **优势**：
  - 非常适合大型项目，能够大幅简化 Redux 的样板代码。
  - 内置了 `redux-thunk`、`Immer` 等常用工具，配置更加简单高效，是目前 React 项目状态管理的首选方案。

## 不可变数据结构：Immer vs Immutable.js *Content-[01:41]
- **为什么需要不可变数据结构**：
  - React 组件在更新时，核心机制是对比 State 或 Props 的**引用地址**。
  - 使用不可变数据结构，每次修改数据都会返回一个**全新的对象（新引用）**，从而确保 React 能够正确触发组件更新。
- **主流方案对比**：
  - **Immer**（目前主流推荐）：
    - **优点**：API 非常简单，上手几乎没有难度；允许以“可变”的写法来操作数据，底层自动转换为不可变更新。
    - **底层原理**：基于 ES6 的 `Proxy` 和 `Object.defineProperty` 实现。
    - **缺点**：需要运行环境原生支持 `Proxy`（现代浏览器均已支持）。运行效率受环境因素影响较大。
  - **Immutable.js**（早期流行）：
    - **优点**：兼容性极好，支持 ES3/ES5 等老旧环境；执行效率整体比较平稳。
    - **缺点**：API 复杂，学习成本高；库文件庞大臃肿；在数据转换时需要执行 `fromJS` 和 `toJS`，存在一定的前期性能成本。
- **结论**：综合来看，`Immer` 更简单、更轻量，且现代浏览器已全面支持，因此在当前项目中**强烈推荐优先使用 `Immer`**（Redux Toolkit 内部已默认集成）。

## Context 与 Redux 的对比 *Content-[03:57]
- **Context 能代替 Redux 吗？**
  - **答案是：不可以。** 两者解决的问题维度完全不同。
- **适用场景差异**：
  - **Context**：比较适合封装复杂的组件，解决组件树中跨层级的状态传递问题（如主题、语言等相对静态的全局配置）。
  - **Redux**：适合管理整个项目的复杂数据状态，提供集中式的状态管理。
- **Context 的局限性（为什么不能替代 Redux）**：
  - **缺乏调试工具**：没有时间旅行（Time Travel）功能，状态调试非常困难。
  - **性能问题**：Context 的值发生变化时，容易导致所有消费该 Context 的组件进行额外的重新渲染，对性能不友好（缺乏细粒度的更新控制）。

## React 新增生命周期钩子详解 *Content-[04:24]
*(注：讲师提及 16.8，实际这些生命周期是在 React 16.3 引入，配合 Fiber 架构使用)*
- **`static getDerivedStateFromProps`**：
  - **特点**：这是一个**静态方法**（Static Method）。
  - **作用**：取代了旧的三个生命周期钩子：`componentWillMount`、`componentWillUpdate` 和 `componentWillReceiveProps`。
  - **调用时机**：在 `render` 方法之前调用，并且在组件初次挂载以及后续更新时都会被调用。
  - **返回值**：返回一个对象来更新 `state`；如果返回 `null` 则不更新任何内容。
- **`getSnapshotBeforeUpdate`**：
  - **调用时机**：在最近一次渲染输出被提交到 DOM（冻结点）之前调用。此时页面还未实际更新，DOM 元素尚未发生变化。
  - **作用**：允许组件在发生更改之前从 DOM 中捕获一些信息（例如滚动位置）。
  - **应用场景**：例如在滚动列表中动态添加元素时，需要保存并恢复用户的滚动位置。
  - **返回值传递**：该生命周期的任何返回值，都将作为第三个参数传递给 `componentDidUpdate` 钩子。
