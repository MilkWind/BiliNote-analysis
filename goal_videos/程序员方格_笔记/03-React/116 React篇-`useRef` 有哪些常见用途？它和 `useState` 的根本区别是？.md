## 1. 理解 useRef 与 useState 的核心区别 *Content-[01:13]

- **useRef 的基本概念**：
  - 调用 `useRef` 会返回一个可变的 `ref` 对象，该对象包含一个核心属性：`.current`。
  - `ref` 对象在组件的整个生命周期里都会保持不变。无论组件因为 `props` 或 `state` 变化重新渲染多少次，`useRef` 返回的对象始终是同一个引用。
  - 开发者可以自由修改 `.current` 属性的值（例如重新赋值）。
  - **最关键的特性**：修改 `.current` 的值时，React **不会**重新触发组件的渲染。

- **useState 的基本概念**：
  - 用于在函数组件中引入和管理状态（如计数器）。
  - 调用 `set` 函数（如 `setCount`）更新值时，如果新值与当前值不同，React 会计划一次组件的重新渲染。
  - 在下一次渲染时，状态的值会更新为新值，并驱动 UI 更新。

- **核心区别与形象比喻**：
  - `useState` 用于管理那些变化时需要让 UI 自动更新的数据状态，通过 `set` 函数更新值**会触发**组件重新渲染。
  - `useRef` 用于存储不希望因其变化而重新触发 UI 更新的可变值，修改 `.current` 属性**不会触发**组件重新渲染。
  - **形象比喻**：`useRef` 返回的 `ref` 对象在组件整个生命周期里是持久的，可以把它想象成给函数组件附加的一个“实例变量”或“小背包”。你可以在背包里存放东西，这些东西的改变不会让整个组件重新渲染；而 `useState` 里的东西一旦改变，组件就必须重新渲染。

## 2. 面试回答指南：核心区别与主要用途 *Content-[04:10]

当面试官问及 `useRef` 和 `useState` 的区别，以及 `useRef` 的常见用途时，可以按以下逻辑清晰作答：

- **要点一：点明核心区别**
  - 最根本的区别在于**是否会触发组件的重新渲染**。
  - `useState` 用于管理组件状态，通过 `set` 函数更新时会触发重新渲染，让界面反映最新状态。
  - `useRef` 创建的是一个可变的容器（带有 `.current` 属性），修改 `.current` 的值不会导致组件重新渲染。其返回的 `ref` 对象在整个生命周期内保持不变。

- **要点二：描述设计目的和主要用途**
  - 基于上述核心区别，`useRef` 主要有两大用途：
    1. **访问和操作 DOM 元素**：这是最广为人知的用途。将 `ref` 对象附加到 JSX 元素的 `ref` 属性上，通过 `ref.current` 直接访问真实 DOM 节点，进行获取焦点、触发动画、测量尺寸等操作。
    2. **存储与渲染无关的可变值**：在组件多次渲染之间持久化某些数据，且这些数据的变化不应触发重新渲染。例如：定时器 ID、上一次的 `props` 或 `state` 的值、事件函数中需要但不想触发渲染的数据。

## 3. 应用场景一：访问和操作 DOM 元素 *Content-[06:37]

- **场景描述**：在组件加载后，让一个输入框自动获取焦点。
- **代码逻辑拆解**：
  1. 使用 `useRef(null)` 创建一个名为 `inputRef` 的对象（初始值通常为 `null`，因为首次渲染完成前 DOM 节点不存在）。
  2. 将 `inputRef` 传递给 `<input>` 元素的 `ref` 属性。
  3. 当 React 渲染该 `<input>` 元素到真实 DOM 时，会自动将真实 DOM 节点的引用赋值给 `inputRef.current`。
  4. 在 `useEffect` 内部（组件挂载完成、DOM 构建好后），`inputRef.current` 指向真实的 input DOM 节点，此时可以安全调用 `inputRef.current.focus()` 方法。

- **面试官追问：为什么这里适合用 `useRef` 而不是 `useState` 来获取 DOM？**
  - DOM 节点的引用本身并不是一个需要驱动 UI 渲染的状态，我们只需要一个稳定的引用来操作它。
  - 如果用 `useState` 存储 DOM 节点，当节点引用发生变化时，通常会触发不必要的渲染。
  - `useRef` 能提供持久化的引用，且其变化不会导致重新渲染，这是最根本的原因。

## 4. 应用场景二：管理定时器 *Content-[08:51]

- **场景描述**：实现一个每秒更新的计数器，并能够清除它。需要保存 `setInterval` 返回的定时器 ID。
- **代码逻辑**：使用 `timerRef.current` 来保存定时器 ID。
- **为什么不用 `useState` 来存 timer ID？**
  - 如果用 `useState` 存储 `timerId`，在 `useEffect` 中调用 `setTimerId` 设置状态时，会额外触发一次渲染。
  - 这个渲染对于用户界面来说是没有必要的，因为 `timerId` 本身对用户不可见，其改变也不需要更新 UI。
  - `useRef` 完美避开了这个问题，只需静静保存 ID，不干扰正常的渲染流程。

## 5. 应用场景三：存储上一次的 props 或 state *Content-[10:20]

- **场景描述**：有时需要知道某个 `prop` 或 `state` 在上一次渲染时的值，以便进行比较或执行特定逻辑。
- **代码逻辑**：
  1. 初始化 `prevRef`，其 `.current` 初始值为 `undefined`。
  2. 当 `currentValue` 首次被设置时，`useEffect` 会在渲染之后执行。此时 `prevRef.current` 仍为 `undefined`。
  3. 在 `useEffect` 内部，将当前的 `currentValue` 赋值给 `prevRef.current`。
  4. 当用户输入导致 `currentValue` 变化时，组件重新渲染。在这次渲染中，`prevRef.current` 显示的仍然是上一次渲染后存储的值。
  5. 渲染完成后，`useEffect` 再次执行，更新 `.current` 属性，为下一次渲染做准备。
- **总结**：`prevRef` 就像一个“延迟一拍的记录器”，它的更新不会触发新的渲染，而是为下一次渲染提供上一次的数据。

## 6. 总结与回顾 *Content-[12:00]

- `useRef` 的核心逻辑：返回一个可变的 `ref` 对象，修改其 `.current` 属性不会触发组件重新渲染。这与 `useState` 更新状态会触发重新渲染形成鲜明对比。
- 两大主要用途：访问 DOM 元素、存储与渲染无关的可变值。
- 核心记忆点：`useRef` 和 `useState` 的核心区别在于**是否触发组件的重新渲染**。理解这一点并结合具体应用场景，即可在面试中游刃有余地应对相关问题。
