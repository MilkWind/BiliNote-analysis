## Hooks 原理及为什么不能在 Hooks 里写判断 *Content-[00:00]

- **Hooks 数据存储原理**
  - Hooks 的数据实际上保存在 Fiber 对象上。
  - 具体存储在 Fiber 对象的一个属性 `memoizedState` 中。
  - 多个 Hooks 之间通过链表结构进行连接，每个 Hook 对象包含一个 `next` 属性，指向下一个 Hook 对象。

- **Hooks 的执行阶段**
  - 分为 `mount`（挂载）和 `update`（更新）两个阶段。
  - 第一次渲染时执行 `mount`，后续所有的更新全部走 `update` 方法。

- **Hooks 的链表结构**
  - Hooks 的链表结构实际上是**环状链表**（Circular Linked List）。
  - 原因：React 内部为了方便处理数据结构，以及进行互斥时的遍历（面试时回答“内部方便处理数据结构，进行互斥时的遍历”即可，深入理解需要阅读源码）。

- **为什么不能在 Hooks 里写判断（条件语句）**
  - 因为 Hooks 是通过 `next` 指针进行连接的环状链表（例如 A -> B -> C -> A）。
  - 必须按顺序找到 A，才能通过 A 的 `next` 找到 B，再通过 B 的 `next` 找到 C。
  - 如果在 Hooks 中写了判断（条件语句），导致某个 Hook（比如 B）在当次渲染中不执行，那么后续的 Hook（比如 C）也就无法被找到和访问，从而导致整个 Hooks 链表断裂，引发严重的状态错乱问题。

## React 最新版本的渲染模式 *Content-[02:47]

- React 最新版本主要有**两种渲染模式**：
  1\. **同步模式（Legacy Mode）**：默认模式。项目初始化时如果不做额外配置，默认就是同步模式，没有开启并发更新特性。
  2\. **并发模式（Concurrent Mode）**：支持并发更新特性。

- **如何开启并发模式**
  - 需要使用 `useTransition` 和 `useDeferredValue` 这两个 Hooks 来开启并发更新特性。

## setState 是同步还是异步 *Content-[03:20]

- **核心结论**
  - `setState` 本质上是**异步**的。

- **具体分类（根据渲染模式不同）**
  1\. **同步模式（Legacy）下**：表现为**微任务异步**（Microtask）。
  2\. **并发模式（Concurrent）下**：表现为**宏任务异步**（Macrotask）。

- **宏任务的实现机制**
  - 并发模式下的宏任务是基于 `postMessage` 实现的。
  - **为什么不使用 `setTimeout`**：因为 `setTimeout` 的时间不准确，存在延迟和精度问题，无法满足 React 对时间切片的高精度要求。

## Fiber 的粒度是什么 *Content-[04:18]

- **Fiber 对象的粒度**
  - Fiber 对象对应 React 虚拟 DOM 树中的**每一个节点**（包括组件节点和原生 DOM 节点）。

- **案例分析**
  - 假设有一个 `App` 组件，内部包含 `div`、`span`、`p` 标签。
  - 在这个案例中，会创建 **4 个** Fiber 对象（分别对应 `App`、`div`、`span`、`p`）。

- **Fiber 树的关联属性**
  - Fiber 对象之间通过三个核心属性进行关联，形成树状结构：
    1\. `return`：指向**父节点**。
    2\. `child`：指向**第一个子节点**。
    3\. `sibling`：指向**下一个兄弟节点**。
  - 例如：`App` 的 `child` 指向 `div`；`div` 的 `child` 指向 `span`；`span` 的 `sibling` 指向 `p`。

- **面试考察点**
  - 面试官常通过给出具体的组件结构案例，询问会创建多少个 Fiber 对象以及它们之间的指针指向，以此考察候选人对 React 底层原理（Fiber 架构）的真实理解程度。

## AI 总结

本次视频主要讲解了 React 前端面试中的四个核心高频问题：
1. **Hooks 原理**：Hooks 状态存储在 Fiber 节点的 `memoizedState` 中，通过 `next` 指针形成环状链表。因此，Hooks 必须保持调用顺序一致，严禁在条件判断或循环中使用，以免链表断裂。
2. **渲染模式**：React 分为同步（Legacy）和并发（Concurrent）两种模式，可通过 `useTransition` 等 Hooks 开启并发特性。
3. **setState 异步机制**：`setState` 本质是异步的。在同步模式下为微任务异步，在并发模式下为基于 `postMessage` 实现的宏任务异步。
4. **Fiber 粒度**：Fiber 节点对应虚拟 DOM 树中的每一个元素或组件。通过 `return`、`child`、`sibling` 三个指针属性构建出完整的 Fiber 树结构。
