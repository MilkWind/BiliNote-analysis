## 1. 合成事件的概念与背景 *Content-[00:11]
- **事件处理机制**：在 React 中，事件处理是一个非常重要的知识点，React 采用的是**合成事件（SyntheticEvent）** 机制。
- **合成事件的定义**：合成事件是浏览器对原生事件的一种跨浏览器封装。在早期的前端开发中，开发者需要自己封装代码来兼容不同浏览器（如 IE）以及不同层级的事件差异。
- **抹平差异**：React 通过合成事件帮开发者抹平了不同浏览器之间的事件差异，并进行了跨浏览器的封装。
- **跨平台支持**：React 本身也是一种跨平台的语言。例如通过 **React Native**，可以开发原生的 App，并最终编译成 Android 或 iOS 等对应的原生应用。因此，React 在语言层面上针对浏览器和平台做了统一的底层处理。

## 2. 合成事件的核心目的与优势 *Content-[01:52]
React 采用合成事件主要有以下几个核心目的和优势：

- **跨浏览器兼容与更好的跨平台**：
  - React 采用**顶层事件代理机制**，能够保证事件冒泡的一致性。
  - 通过这种机制，React 可以跨浏览器执行，抹平不同浏览器和不同平台之间事件对象的差异，保证在不同环境下的表现完全一致。

- **避免垃圾回收（事件池机制）**：
  - 在原生 DOM 事件中，事件对象可能会被频繁地创建和回收。如果对象没有被标记为可达，就会触发垃圾回收机制被清除。
  - 为了避免频繁创建和销毁事件对象带来的性能损耗，React 引入了**事件池（Event Pool）** 机制。
  - React 会从事件池中获取或释放事件对象。当事件触发时，直接从事件池（数组）中弹出对象，从而避免频繁创建和销毁，防止事件对象被垃圾回收清除。

- **统一管理与事务机制**：
  - 合成事件的设计也方便了 React 内部对事件的统一管理，并且能够很好地配合 React 的**事务机制（Transaction）** 运行。

## 3. 合成事件与原生事件的区别 *Content-[04:11]
React 的合成事件与 DOM 原生事件在语法和使用上存在以下三点主要区别：

1\. **事件命名方式不同**：
   - 原生事件：采用纯小写命名（例如 `onclick`）。
   - React 事件：采用**驼峰命名法**（例如 `onClick`）。

2\. **事件处理函数类型不同**：
   - 原生事件：事件处理函数通常是一个字符串（例如 `onclick="handleClick()"`）。
   - React 事件：需要传入一个**函数引用**作为事件处理函数（例如 `onClick={handleClick}`）。

3\. **阻止默认行为的方式不同**：
   - 原生事件：通常通过在函数末尾 `return false` 来阻止默认行为。
   - React 事件：必须显式调用 `event.preventDefault()` 来阻止默认行为。
