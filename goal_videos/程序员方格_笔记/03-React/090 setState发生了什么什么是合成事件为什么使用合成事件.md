## 1. setState 发生了什么 *Content-[00:00]

在面试中，`setState` 的执行原理是高频考点。从源码角度剖析，`setState` 实际上调用了以下几个核心方法：

- **进入更新入口**：首先调用 `enqueueSetState` 方法，标志着状态更新流程的开始。
- **获取更新优先级**：接着调用 `requestUpdateLane` 方法，获取本次更新的优先级。
- **Fiber 树的构造**：获取到的优先级将用于 Fiber 树的构造。Fiber 树的构建是严格基于优先级的：
  - 优先级越高的任务，越先进行构造。
  - 如果任务的优先级低于当前的渲染优先级，则该更新将会被忽略。

### 更新的两种核心模式
面试官询问 `setState` 时，最核心是想了解**更新机制**。在 React 最新版本中，更新主要分为以下两种模式：

1\. **同步更新模式**
- 虽然页面的渲染本质上是一个异步过程，但在同步更新模式下，页面的更新调度是在**微任务（Microtask）** 中进行的。

2\. **并发更新模式**
- 通过 `useTransition` 或 `useDeferredValue` 等 API 开启，这是 React 最新版本的并发特性。
- 本质是**降低任务优先级**：将当前任务标记为低优先级并延后执行，从而让高优先级的任务（如用户交互）先执行。
- 在并发更新模式下，异步渲染是在**宏任务（Macrotask）** 中进行的。

> **面试建议**：务必向面试官清晰区分“同步模式在微任务中调度”与“并发模式在宏任务中调度”这一核心差异，这是拉开面试差距的关键点。

## 2. 什么是合成事件 *Content-[02:10]

合成事件（SyntheticEvent）是 React 模拟原生 DOM 事件所有属性的一种机制。我们需要分老版本和新版本来理解：

### 老版本的合成事件（了解即可）
- **事件委托目标**：事件主要委托到 `document` 上，但部分事件仍会绑定到当前元素，存在不确定性。
- **事件映射**：存在 React 事件与原生事件的映射关系。例如，React 的 `onMouseLeave` 会被映射为原生的 `mouseout` 事件。
- **事件池机制**：老版本包含事件池（Event Pool）机制以复用事件对象。

### 新版本的合成事件（面试重点）
新版本对合成事件进行了重大重构，主要具备以下四个特点：
1. **委托目标变更**：事件不再委托到 `document`，而是直接委托到 `root`（即 React 项目挂载的根 DOM 节点，如 `<div id="app">`）。
2. **捕获阶段提前**：React 捕获阶段的合成事件，被提前到原生事件的捕获阶段执行。这修复了老版本在冒泡阶段处理事件时存在的一些缺陷。
3. **移除事件池**：新版本中彻底移除了事件池机制。
4. **引入事件优先级**：事件响应具备了优先级机制，这是 React 18 并发特性的重要底层支撑。

## 3. 为什么使用合成事件 *Content-[03:29]

React 引入并维护一套合成事件系统，主要基于以下核心优势：

- **浏览器兼容性统一**：抹平不同浏览器（如 Chrome、Firefox 等）之间 DOM 事件 API 的差异。开发者无需手动处理繁琐的事件兼容性问题，调用更加统一方便。
- **多平台适配**：React 不仅应用于 Web 浏览器，还广泛应用于 React Native 等移动端平台。合成事件机制有助于实现跨平台的事件逻辑统一。
- **实现事件委托**：通过统一的事件委托机制，避免在大量 DOM 元素上直接创建和绑定事件监听器，从而显著优化内存和性能。
- **事件池机制（老版本特性）**：老版本通过事件池避免频繁创建和销毁事件对象，提升了旧版浏览器的性能。（注：面试时需说明最新版本已移除此机制）。
- **新版本的事件实例化**：在新版本中，合成事件对象会在 React 初始化时进行实例化，与 React 核心同时完成初始化。

1. 在 `setState` 原理方面，重点掌握了从 `enqueueSetState` 到 `requestUpdateLane` 的源码流程，以及 Fiber 树基于优先级的构建逻辑。最关键的区分点在于：同步更新模式依赖**微任务**调度，而通过 `useTransition` 等开启的并发更新模式则依赖**宏任务**调度。
2. 在合成事件方面，明确了新老版本的核心差异：新版本将事件委托节点从 `document` 移至 `root`，提前了捕获阶段的执行，移除了事件池，并引入了事件优先级。
3. 使用合成事件的核心目的在于抹平浏览器差异、支持多平台（如 React Native）适配、通过事件委托优化性能。掌握这些底层逻辑，能够在社招面试中展现出扎实的 React 源码基础与架构理解能力。
