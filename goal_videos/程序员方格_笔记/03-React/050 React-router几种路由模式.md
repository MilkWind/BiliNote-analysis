## HashRouter 模式 *Content-[00:00]
- **不推荐使用的原因**：
  - 路由地址不美观，且存在潜在的安全问题。
  - 不需要使用 Nginx 作为静态资源代理，也无需配置 `historyApiFallback`。
- **核心原理**：
  - 本质上是使用 URL 的锚点（`#`）。
  - 哈希（Hash）部分的内容不会向服务器发送请求，因此无需服务器端的特殊配置。
- **使用方法**：
  - API 替换：将路由创建 API 替换为 `createHashRouter`。
  - URL 格式：路径前带有 `#` 号，例如 `#/home/about`、`#/detail/1`。

## 底层原理解析：History 与 Hash 的差异 *Content-[01:12]
- **面试核心问题**：
  - 作为 React Router 的开发者，在底层逻辑中如何处理 History 和 Hash 模式？是分别写两套逻辑吗？
- **底层实现机制**：
  - **入口层抹平**：底层并不是写两套逻辑，而是仅在创建实例的入口层面，针对当前的 path 做一层抹平处理。
  - **逻辑复用**：将 Hash path 转换后，统一成对应的路由 URL。底层的路由事件监听、组件匹配、根据 path 进行打分等核心逻辑是完全复用的。
- **事件监听的统一**：
  - 过去需要区分 `hashchange` 和 `popstate` 事件。
  - 现在 `popstate` 事件也能够监听到哈希值的变化，因此在事件监听层面已经没有差异化处理。
- **结论**：History 和 Hash 在底层实现层面上，唯一的区别仅在于入口层面的 URL 区分。

## MemoryRouter 内存路由模式 *Content-[02:50]
- **核心概念**：
  - 内存型路由（Memory Router），将路由表和历史记录（堆栈内容）存储在内存中。
  - **特点**：页面刷新时，路由信息会丢失；路由切换不会引起浏览器 URL 的变化，因为它是根据内存中的历史堆栈进行管理，不与当前 URL 关联。
- **配置与使用**：
  - 使用 `createMemoryRouter` 创建。
  - 需要提供特定的配置项：
    - `initialEntries`：初始化路由的条目数组（例如 `['/about', '/home', '/user/42']`）。
    - `initialIndex`：初始化路由的索引。例如，索引 `0` 对应 `/about`，索引 `1` 对应 `/home`。
  - **示例表现**：在内存路由中，即使手动修改 URL 或切换到不存在的路由，页面也不会发生变化，完全由内存中的状态控制。

## StaticRouter 静态路由模式 *Content-[05:14]
- **核心概念**：
  - 静态路由（Static Router），主要用于静态路由场景（如服务端渲染 SSR）。
- **特点**：
  - 不操作浏览器的历史记录。
  - 因为不存在服务端的 history 相关 API，所以无法进行常规的前端路由跳转操作。
