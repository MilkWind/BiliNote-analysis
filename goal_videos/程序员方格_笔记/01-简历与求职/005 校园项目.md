## 个人信息与整体布局 *Content-[00:00]
- **保持简洁**：个人信息部分不需要冗长的描述，应做到精简。
- **重点体现核心信息**：
  - **工作年限**：让面试官快速了解你的工作经验层级。
  - **期望 Base 地**：明确你期望的工作城市（Base 地），方便 HR 进行初步筛选。

## 个人技能部分优化指南 *Content-[00:26]
- **框架技能需有所侧重**：
  - **避免混写**：不要将 Vue 和 React 写在同一行。如果两者都写，面试官会认为你“两个都不精”，且同时准备两者的面试成本极高。
  - **侧重写法**：根据项目经验决定侧重点。例如第一个项目是 React，则优先写 React。
    - *侧重描述*：掌握 React 相关技术栈及生态，并深入了解 React 框架实现原理。
    - *非侧重描述*：了解 Vue，拥有 Vue 相关开发经验。
- **前端工程化与规范拼写**：
  - 必须按照标准规范拼写技术名词，如 `Webpack`、`Vite`、`tsup`、`Vue`、`React`。拼写错误会显得极不专业。
- **慎用后端技能（如 Java）**：
  - 如果仅是大学课程级别的“了解”，没有实际上线、运维和长期维护经验，建议**不要写**。
  - 面试时若被深问后端原理或架构，容易翻车，适得其反。
- **技能部分需包含“实战基建”产出**：
  - 个人技能是简历的第一部分（Part 1），必须足够丰富以吸引面试官继续阅读。
  - 不要只罗列基础技术点，应加入实战产出与基建内容，例如：
    - 实现大前端命令行工具 / 脚手架。
    - 开发 React UI 组件库。
    - 前端稳定性 / 监控体系建设。
    - 前端搭建体系 / 低代码（Low-code）相关建设。

## 工作经历撰写技巧 *Content-[06:17]
- **拒绝废话与流水账**：
  - 不要写“负责前后端开发”、“参与内部项目开发迭代”、“与其他研发人员合作完成项目”等开发工程师的本职工作废话。
  - 不要写“撰写产品需求文档（PRD）”等偏离前端核心竞争力的内容，除非你想强调全栈但缺乏前端深度。
- **突出核心亮点**：
  - 例如：参与制定前端标准化规范，并落地相关工具，约束和引导团队按照规范编写代码。
- **分层描述（业务层面 vs 技术层面）**：
  - **业务层面**：负责的业务线/系统，维护与开发带来的数据提升或产品效果。
  - **技术层面**：挑选以下重要亮点写入简历：
    1\. **技术选型**
    2\. **前端标准化能力建设**
    3\. **研发提效**
    4\. **工程化建设**
    5\. **性能优化**
    6\. **AI 方面的探索**

## 项目描述与核心贡献规范 *Content-[09:56]
- **项目描述“三段论”**：
  - 尽量控制在三句话以内，清晰表达：
    1\. **项目是什么**（系统定位与业务背景）。
    2\. **负责什么**（核心职责）。
    3\. **达到什么效果**（业务收益或技术提升）。
- **核心贡献避免“全栈流水账”**：
  - 不要写“完成产品原型设计”、“完成前后端搭建”、“测试部署到服务器”等。这虽然体现了你做的事情多，但无法体现前端深度。
  - **正确做法**：必须在前端搭建/开发方向上延展，补充研发提效、工程化、性能优化等面试官关注的深度内容。
- **排版建议**：
  - 使用小标题并**加粗**（如：**优化方案**），提升简历的可读性和视觉层次。

## 项目优先级调整与内容合并 *Content-[12:13]
- **项目优先级原则**：
  - 按照项目含金量**从高到低**排列。把最好的项目、最亮眼的经历放在第一个位置，切忌把普通项目放前面导致面试官失去阅读兴趣。
- **零散项目合并**：
  - 对于零散的小项目（如前后端工具 JS 库、脚手架编写、文件上传组件、大屏项目等），不要单独列为一个项目，应合并到主项目中。
- **合并示例（研发提效方向）**：
  - 利用 `pnpm` 等多包管理方案（Monorepo）维护前端工程化体系。
  - 将基础服务（如 OSS 服务、编码服务、CDN 等）统一收口，进行功能抽取。
  - 供其他团队使用，减少重复开发，提升整体研发效率。

## 具体项目亮点与深度挖掘 *Content-[15:21]
- **移动端项目（Taro 多端适配）**：
  - **图片优化**：采用缩略图与图片列表分析处理，同时异步加载原图，将加载时间从 1-2 秒优化至基本秒开。
  - **多端差异化适配**：针对微信端不同定位/机型的差异，通过分端变量处理，以及接入微信 JSSDK 进行差异化处理；引入高德 SDK 并解决多端适配问题。
  - **经验体现**：充分体现 Taro “一套代码，Run anywhere” 的多端开发经验，此经验应在个人技能中重点提及。
- **B端后台管理系统（Vue 全家桶）**：
  - **PDF 渲染与处理**：实现 PDF 渲染器，优化文件上传至 OSS 的流程。
  - **大文件上传**：实现大文件上传的断点续传能力。
  - **建议**：此类项目技术亮点较多，优先级可适当提前。
