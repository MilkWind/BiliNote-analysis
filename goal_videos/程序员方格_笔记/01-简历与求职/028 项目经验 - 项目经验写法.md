## 项目经验撰写核心原则 *Content-[00:00]

在撰写前端简历的项目经验时，核心目标是体现出你在项目中真真切切做了什么、具体实现了什么，并挖掘出你比别人在某个技术上理解得更深入、应用得更彻底。对于工作经验丰富、项目众多的求职者，需遵循以下原则：

1\. **相关性优先**：优先挑选与目标岗位或技术栈高度相关的项目。
2\. **合并同类项**：不要将所有做过的项目一一罗列，挑选最能代表你技术实力的项目即可，避免项目同质化问题。
3\. **拒绝流水账**：避免写成“使用了某技术实现了某基础功能”的流水账，这种写法无法体现技术深度，写与不写没有区别。

## 简历案例逐条剖析与优化 *Content-[00:41]

以下通过 8 个常见的前端项目职责描述，详细剖析错误写法与优化方案：

1\. **路由配置 (Vue Router)** *Content-[01:04]*
- **错误写法**：使用 Vue Router 配置路由，对页面进行切换。
- **分析**：这是前端工程师的基础操作，毫无亮点。
- **优化写法**：使用 Vue Router 的全局导航守卫 `beforeEach` 实现路由鉴权。
- **亮点**：体现了对路由高级特性（导航守卫）的掌握，而非仅仅停留在基础配置。

2\. **数据请求 (Axios)** *Content-[01:52]*
- **错误写法**：Axios 请求数据，`v-for` 对数据进行遍历渲染。
- **分析**：过于基础，无法体现对 Axios 在项目中的深度应用。
- **优化写法**：对 Axios 进行二次封装，使用 `Interceptors`（拦截器）实现全局请求及响应处理。
- **亮点**：遵循实事求是、深入细致的原则。使用英文专业术语 `Interceptors`，能够在满篇中文的简历中凸显关键字，吸引 HR 和简历解析系统的注意力。

3\. **文件上传与格式限制** *Content-[03:00]*
- **错误写法**：图片视频的上传以及限制图片上传的大小格式。
- **分析**：未说明具体是通过什么手段（如后缀名对比还是其他方式）进行的限制，表述不清。
- **优化写法**：通过文件签名（Magic Number）的方式限制图片和视频上传的格式，并实现图片视频的上传预览。
- **亮点**：明确了具体的技术实现手段（文件签名），体现了严谨性。

4\. **过渡动画实现** *Content-[03:49]*
- **错误写法**：使用 transition 方法实现过渡动画的效果。
- **分析**：未指明是 Vue 的 `<transition>` 组件还是 CSS 的 `transition` 属性，表述模糊会让人质疑专业能力。
- **优化写法**：使用 `<transition>` 组件实现路由跳转时的过渡动画，根据路由对象中的 `from` 属性判断路由来源，展示不同的动画效果。
- **亮点**：描述清晰且点出关键点。注意简历排版，尽量控制在一行以内，保持简洁，避免长篇大论导致 HR 失去阅读耐心。

5\. **自定义 HTML5 播放器** *Content-[05:13]*
- **错误写法**：自定义 HTML5 播放器。
- **分析**：未说明使用了什么技术栈，稀里糊涂。
- **优化写法**：原生 JavaScript 结合 CSS3 自定义 HTML5 播放器。
- **亮点**：明确了技术实现手段。若需扩展，可简述播放器功能，但切记尽可能不要超过一行。

6\. **地图定位与距离计算** *Content-[05:45]*
- **错误写法**：使用高德地图定位用户之间的距离。
- **分析**：缺少英文关键字，不利于简历筛选。
- **优化写法**：AMap（高德地图）实现用户定位及用户之间距离的计算。
- **亮点**：采用“英文专业术语 + 中文解释”的形式。既能让系统或技术面试官捕获到 `AMap` 关键字，又能让非技术的 HR 看懂具体内容。

7\. **公共组件与模块封装** *Content-[06:49]*
- **错误写法**：负责项目常用组件及业务组件封装。
- **分析**：语句不通，缺乏具体数量，未说明是否封装了其他公共模块（如自定义指令、组合式函数）。
- **优化写法**：封装 13 个公共组件、5 个组合式函数（Composables）、6 个自定义指令。
- **亮点与技巧**：
  - **数字量化**：用具体数字（13个、5个、6个）量化工作成果。
  - **专业命名**：组件命名应参考 Element UI / Vuetify 等成熟组件库的英文命名，切忌使用在线翻译的生硬词汇。
  - **详略得当**：若封装组件数量较少（如 3 个），可直接列出具体组件名；若数量较多，则只写总数即可。

8\. **代码性能优化** *Content-[08:40]*
- **错误写法**：对代码进行优化，减少页面加载时间和消耗资源。
- **分析**：空泛描述，未列出具体优化手段，也没有结果导向的数据。
- **优化写法**：
  - **优化手段**：使用 LocalStorage 缓存个人信息、全局异步组件、Suspense 代码分割、`shallowRef`、`shallowReactive` 等。
  - **量化结果**：页面加载时间由原来的 2.7 秒降低到了 2.2 秒。
- **亮点**：详细列出应用的具体优化技术，并提供极具说服力的量化结果数据。

## 项目经验撰写四大黄金法则 *Content-[09:22]

总结上述案例分析，撰写项目经验时应严格遵循以下四个原则：

1\. **使用英文专业术语**：能用专业术语替代的，尽量换成英文（如 `Interceptors`、`AMap`）。目的是在众多的中文汉字中，让 HR 和解析系统一眼扫描到核心技术点。
2\. **描述具体且闭环**：明确写出具体做了什么、用了什么方法、实现了什么功能、达到了什么结果，拒绝模糊不清的表述。
3\. **数字量化成果**：不一定每一项工作都有可量化的成果，但如果存在（如性能提升的具体秒数、封装组件的具体数量），一定要抓住机会用数字进行量化。
4\. **善用行为动词**：使用精准、专业的行为词来描述你的职责和贡献，使简历语言更加规范、有力量。
