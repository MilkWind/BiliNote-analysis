## 1. 简历检查概述 *Content-[00:00]
- 本节既是简历的检查，也是简历策划课程的大总结。
- 在投递简历之前，必须对简历进行严格检查，确保简历内容与真实实力相匹配。
- 检查是否采用了“二级陈述”的方式进行描述，细节决定成败，切勿因细节错失面试机会。
- 在多次投递简历却未得到回复时，更应重新检查和评估简历，对比优秀简历找出不足并修改。
- 优秀的简历是反复修改出来的，没有绝对完美的简历，只有更适合应聘岗位的简历。

## 2. 全局四原则 *Content-[00:59]
- **相关性原则**：讲究人岗匹配，相关性优先级最高。必须把与应聘岗位最相关的内容放在优先级最高的位置（最前面）。
- **简洁性原则**：保证简历的版式以及所写的描述都足够简洁，同时能清晰表达核心意思。
- **客观性原则**：简历上陈述的所有事情和技术都必须是真实发生过的。可以适当美化，但绝对不允许夸大其词或造假。
- **结果导向性原则**：做任何事情能用结果说话的一定用结果说话，能用数字量化的一定不要忘记用数字去量化结果。

## 3. 个人信息模块检查 *Content-[02:07]
- **姓名与标题**：以姓名作为简历标题即可，无需单独添加“个人简历”或“简历”等画蛇添足的标题。检查姓名是否有生僻字，如有需添加拼音。
- **手机号码**：确认是否填写且号码正确。建议按 3-4-4 或靓号方式，使用连字符或空格分割（如 138-1234-5678）以提升阅读体验。确认是否可通过该手机号添加微信。
- **邮箱**：确认邮箱是否正确，建议使用大厂邮箱（降低被系统过滤的概率）。测试能否正常收发邮件，并确认是否设置了邮件签名。邮箱地址建议为姓名的直译，便于记忆。
- **照片**：虽为选填，但强烈建议放置职业照。切忌放生活照，与其放生活照不如不放。
- **意向岗位与薪资**：确认意向岗位填写正确；填写明确的薪资范围，且薪资区间跨度不超过 3000 元；意向城市只填一个，不要写多个。

## 4. 教育背景模块检查 *Content-[03:45]
- **时间精度**：上学时间需精确到月份。
- **学校备注**：如果是 985、211 或双一流院校，务必添加备注，因为并非所有 HR 都了解你的学校背景。
- **专业与排版顺序**：
  - 默认顺序：起止时间 -> 院校名称 -> 专业。
  - 若招聘明确要求计算机专业：专业 -> 院校 -> 起止时间。
  - 若招聘明确要求 985/211/双一流：院校名称 -> 专业 -> 起止时间。
  - 若同时要求院校和专业：院校 -> 专业 -> 起止时间。

## 5. 技术栈模块检查 *Content-[04:43]
- **避免拉低水平**：不要写 Git、npm 等基础工具，以免拉低整体技术水平。
- **核心基础技术**：列出 HTML5、CSS3、JavaScript、ES6/ES6+、jQuery、Sass、TypeScript 等。
- **核心生态**：列出 Vue2/Vue3、Vuex/Pinia、Vue-Router、Axios、Uni-app、小程序等。
- **高阶亮点与原理**：写出核心技术的高阶亮点或底层原理，如 CSS 的 BFC、ES6 的 Promise、Vue 的 Diff 算法、响应式原理等。
- **二级陈述**：清晰说明技术水平。格式为：“会什么技术 + 利用什么特性/原理 + 做了什么事/实现了什么功能”。例如：“会 CSS3，利用新特性实现了主题定制”。
- **避免堆砌与主观词**：不要刻意堆砌技术栈关键字；慎用或不用“精通”、“熟练掌握”、“了解”等主观性形容词，因为每个人对形容词的理解标准不同。

## 6. 工作经历模块检查 *Content-[06:18]
- **排版顺序**：默认将起止时间优先放在最左侧。
- **公司/产品知名度**：若公司知名，公司名放最左；若产品知名，产品名放最左。顺序依次为：知名公司名/知名产品名 -> 岗位名称 -> 起止时间。
- **排序与相关性**：多家工作经历默认按倒序排列；把相关性强的工作经历放在最前面的位置。
- **内容描述**：通过“四大法则”将工作内容描述清楚且饱满，体现出自己的职业规划以及个人在团队中的定位。
- **表达规范**：采用数字化表达量化成果；使用专业术语及英文专业术语，并仔细核对拼写。

## 7. 项目经验模块检查 *Content-[07:22]
- **基本信息**：是否有正确的项目名称；是否有项目介绍（用一段话让对方知道项目是做什么的）。
- **技术与职责**：是否写了技术栈和职责描述（避免透露太少让对方猜测）；是否有主要职责（明确你在项目中具体做了什么）。
- **分离与描述**：工作经历和项目经验必须分开写；按照“用什么技术 + 实现了什么具体功能”的二级陈述方式把职责描述清楚。
- **专业术语**：检查是否准确使用了中英文专业术语。

## 8. 自我评价模块检查 *Content-[08:07]
- **适用人群**：在前端领域经验丰富且有一定成绩或成果的人一定要写，反之则不要写。
- **内容要求**：是否有总结（包括技术栈总结、项目经验、行业经验）；是否有成果和个人能力的体现。
- **字数与位置**：字数尽可能控制在 200 字以内；如果写了自我评价，强烈建议放在简历的“黄金广告区”。

## 9. 语言技能、证书与爱好检查 *Content-[08:41]
- **语言技能与证书**：是否使用了二级陈述；证书是否具有含金量。
- **爱好**：有产出物或坚持很久的爱好可以写，反之不要写。

## 10. 简历命名与格式规范 *Content-[08:57]
- **文件格式**：必须为 PDF 格式。
- **命名规范**：姓名-应聘岗位-工作年限（使用连字符连接）。

## 11. 细节与排版规范检查 *Content-[09:10]
- **错别字与病句**：反复检查，尤其是技术关键字（如 ECharts 写成 Echart），连写简历都不认真，无法让人相信你会认真对待工作。
- **日期格式统一**：如使用“2019.09-2023.06”，则全文统一，不要混用“2021年6月”或“2021.6”。
- **列表与符号统一**：
  - 列表符号统一（如项目经验用 1. 2. 3.，其他模块也用 1. 2. 3.，不要混用 A. B. C.）。
  - 标点符号统一：通篇使用中文标点，不要中英文混用。
  - 避免使用句号或分号，推荐使用逗号、顿号、加号、冒号，保持简历简洁易读。
- **对齐与字体**：
  - 垂直对齐：同模块或跨模块垂直方向默认左对齐，最右侧模块选择右对齐。
  - 字体：使用常用字体，避免特殊字体在对方电脑上缺失导致排版错乱。
  - 字号与颜色：字体不超过三种字号，颜色不超过三种（避免花哨，白底黑字/深色字最稳妥）。
- **间距与留白**：行间距、段间距、内边距整齐划一。避免大片留白（如两页半、三页半），可通过调整内边距或精炼文字控制在整页（如近三页或近四页）。
- **内容同质化**：合并同类项，避免多个项目职责类似、内容重复，以免增加 HR 扫描简历的成本并降低简历质量。
- **用词规范**：禁止使用“大概”、“左右”、“可能”、“获取”等不确定性词汇；尽量使用“负责”、“主导”、“牵头”等强情名词（动词）。
- **一行原则**：调整内边距或精炼文字，尽量让描述控制在一行内，避免一行放不下折行导致效果差。
- **超链接与空格**：检查 PDF 中的超链接是否有效，无效需用 WPS 重新处理；删除排版后字与字之间的多余空格。
- **标点细节**：顿号/逗号用于描述语句，加号用于技术栈，冒号用于个人信息和项目经验。
- **一致性原则**：技术名词大小写全文一致（如 Vue，不要写成 VUE 或 vue）；连字符/加号前后通常留有空格（如 `0 - 1`），但作为专有名词一部分时不加空格（如 `vue-router` 中间不能有空格）。
- **缩进**：统一缩进格式（如统一缩进两个汉字）。
- **他人检查**：最后让他人帮忙检查简历，多读几遍，确保格式美观舒服。
