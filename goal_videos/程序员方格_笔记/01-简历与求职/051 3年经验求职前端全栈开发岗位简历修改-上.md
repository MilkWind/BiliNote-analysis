## 引言：简历的重要性与常见误区 *Content-[00:00]
- **背景**：针对拥有3年前端全栈开发经验、具备一定 Java 基础的求职者进行简历修改指导。
- **常见误区**：有经验的求职者往往容易忽视简历的编写，认为“只要有能力，简历怎么写都会被录用”。
- **核心观点**：
  - 工作年限不等于工作能力，能力必须通过简历直观体现。
  - 简历是用人单位（HR）了解求职者的第一媒介，排版和内容细节直接决定是否能获得面试机会。
  - 即使简历整体不错，如果存在细节问题，HR 在对比筛选时仍会将其淘汰，因此必须重视简历的编写，避免踩坑。

## 联系方式：注重排版与细节 *Content-[02:43]
- **原简历问题**：电话和邮箱等联系方式挤在一起，没有分隔，阅读体验不佳。
- **修改建议**：使用分隔符（如竖线 `|`）将电话和邮箱隔开。
- **修改目的**：展现求职者对简历排版的重视，提升 HR 的阅读体验，体现专业度。

## 求职意向：目标明确，避免模糊 *Content-[03:39]
- **原简历问题**：写了“也可以考虑前端相关的岗位，只要能用到我的技术就可以”。这种表述过于模糊、不聚焦，让 HR 无法明确求职者的核心目标。
- **修改建议**：
  - 明确岗位：直接写明求职“前端开发工程师”。
  - 明确方向：说明主攻“前端全栈方向”。
  - 辅助能力：说明可以配合完成基础的 Java 后端辅助工作。
- **修改目的**：表达清晰、专注，让 HR 一眼看出求职者的核心定位，其他技能仅作为辅助加分项。

## 工作年限：表达严谨，精确到月 *Content-[05:42]
- **原简历问题**：写“3年左右”或“差不多快3年了”，表达不够严谨。
- **修改建议**：直接写明“3年”，并精确到具体的起止月份，例如“2023年4月 - 2026年3月”。
- **修改目的**：体现求职者做事的严谨性，让 HR 对候选人的实际工作时长有准确的预期。

## 现居地：细化到区，考虑通勤 *Content-[06:33]
- **原简历问题**：只写了所在城市（如“北京”），缺乏具体区域信息。
- **修改建议**：将现居地细化到具体的区，例如“北京市朝阳区”。
- **修改目的**：HR 在筛选简历时会考虑候选人的通勤距离和生活状态（如在北京，通州区、朝阳区与平谷区的通勤情况完全不同），细化到区有助于 HR 评估候选人的稳定性。

## 离职原因：精简内容，呼应意向 *Content-[07:35]
- **原简历问题**：描述过于啰嗦、冗余（如“个人职业规划原因、想找更好平台、发挥全栈技术、配合后端、提升技能、实现进步”等），没有突出重点。
- **修改建议**：精简语言，并与求职意向相呼应。修改为：“个人职业规划调整，希望能寻找更专注于前端技术、全栈技术的发展平台，进一步提升核心技术能力，同时发挥 Java 基础优势，实现职业进阶。”
- **修改目的**：
  - 去除冗余，直击重点。
  - 与求职意向保持高度一致，向 HR 传递出“目标明确、专注于前端全栈领域”的积极信号。

## 个人简介：拒绝罗列，突出核心竞争力 *Content-[11:02]
- **原简历问题**：像流水账一样罗列技术栈（HTML5, CSS3, JavaScript, TypeScript, React, Vue, Webpack, Spring Boot 等）和工作流程，没有突出3年经验的核心竞争力。
- **修改建议**：
  - **技术深度**：强调深耕前端核心技术，熟练应用 HTML5, CSS3, ES6+, TypeScript，精通 React/Vue 两大主流框架及 Webpack 等工程化工具。
  - **全流程能力**：强调可独立完成从需求对接、架构设计到开发部署的全流程。
  - **后端协同**：具备 Java 后端能力，能高效配合后端团队（强调前端为主，后端为辅）。
  - **软技能与特质**：补充工作严谨、注重代码质量和用户体验、持续关注前端技术迭代、善于自学等个人特质。
- **修改目的**：从“我会什么”转变为“我的核心优势是什么”，让个人简介更具说服力和针对性。
