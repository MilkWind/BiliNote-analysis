## 1. 抬头与个人优势 *Content-[00:32]

### 抬头基本信息
- **突出核心信息**：重点突出“8年工作经验”和“期望职位”。
- **隐藏不利信息**：对于年龄等可能产生劣势的个人信息，可以选择暂时隐藏或忽略。

### 个人优势与技能描述
- **优先级排列**：按照对技能的熟练程度从上到下排列，最擅长、最了解的技能放在最前面。
- **视觉重点突出**：对核心技能或亮点进行**加粗**处理，让面试官一扫就能抓住重点。
- **基础技能“简写”原则**：
  - 简历是“开卷考试”，写什么面试官就可能问什么。
  - 对于 JS, TS, CSS 等常规基础，无需过于细致地罗列（如原型链、闭包等），避免给自己挖坑。
  - 建议汇总为一条，例如：“熟练使用 JS/TS，了解 TS 相关特性及常见类型推导”。
- **框架技术栈（Vue / React）**：
  - 明确自己的主力技术栈。如果是 Vue 体系，写“熟练使用 Vue2/Vue3，了解 Vue 生态及底层原理”即可，无需详细展开数据绑定、数组重写等具体细节。
  - 如果想同时面试 React 岗位，且 React 不如 Vue 熟练，可通过措辞调整侧重，如“了解 React”。面试时可坦诚“更擅长 Vue，但也有 React 项目经验”。
- **微前端与跨端**：
  - 提及 uni-app 及微前端（如 qiankun）方案。
  - 如果实战项目中有微前端相关经验，必须在个人优势中将“**微前端**”加粗，起到承上启下、引出下文项目的作用。
- **数据可视化**：
  - 涉及 ECharts, Three.js 等技术时，建议采用“小标题+加粗”的形式，如“**数据可视化**：熟悉 ECharts、Three.js 等数据展示方案”。
- **前端构建工具**：
  - 不要仅局限于当前使用的工具（如只用 Webpack），应体现知识广度。
  - 建议涵盖 Webpack, Vite, esbuild, Rollup 等，并特别强调具备**构建优化经验**，最好能写出优化后的最终数据指标。
- **工程化与稳定性**：
  - 具备生产环境全链路问题定位、性能调优、故障跟进能力。
  - 能够推动新技术和工程解决方案落地，保障系统稳定性与效率。可将其汇总提炼为“负责系统稳定性与工程化建设”。

## 2. 工作经历 *Content-[07:26]

### 整体评价与优化思路
- 8年3份工作，跳槽频率正常，但原简历描述过于简略，缺乏亮眼突出。
- 简历字字珠玑，写上去的内容必须对自己有帮助，避免写“负责需求评审、任务排期、项目迭代”等毫无优势的常规废话。

### 结构化描述建议
- **分条阐述**：将工作内容按“业务方向”和“技术层面”进行分类。
  - **业务方向**：明确负责的具体业务线。
  - **技术层面**：突出技术选型、内部系统重构、微前端管控平台建设等核心贡献，并将下文的实战项目关联到对应公司的经历中。
- **凸显核心技术栈**：如果不同公司使用的核心技术栈不同（例如 A 公司主打 Vue，B 公司主打 React），需要在对应公司的经历中重点凸显该技术栈。

## 3. 项目经历：微前端管控平台 *Content-[09:20]

### 项目筛选与排序
- 项目数量控制在 3-5 个即可，面试时间是有限的。
- 按照优先级排列，将最有亮点、最想和面试官深入探讨的项目放在最前面。

### 项目结构规范
- **项目背景**：简述项目是什么，解决了什么业务痛点。
- **核心技术栈**：只罗列核心技术栈，切忌将所有用到的技术全部堆砌。
- **主要职责**：明确个人角色（如项目负责人），重点凸显核心贡献。

### 细节打磨与亮点总结
- **术语命名规范**：前端标准化术语必须规范且前后统一。例如，不要前面写 React/Vue2，后面写成 v2/v3 或 VUE2/VUE3。细节见真章，不统一的命名会显得非常不专业。
- **数据与成果前置**：将关键数据（如“接入200多个子应用”）和总结性术语放在项目背景或开头，让面试官第一时间看到成果。
- **亮点总结公式**：
  - 发现的问题 -> 解决方案 -> 最终效果 -> **推广至其他团队**。
  - 强调“团队影响力”：不仅体现个人编码能力，还要体现解决方案被其他团队认可和使用的价值。
- **职责描述重构（避免分散）**：
  - 不要写成流水账，应帮面试官总结亮点。
  - **性能优化**：例如“针对几万条数据使用虚拟滚动，实现页面秒开”。
  - **研发提效**：
    1. 实现不同主题/主色适配。
    2. 子应用快速创建。
    3. 埋点综合性处理。
    - **成果**：沉淀底层能力与规范，实现子应用一键接入，业务方无需关注基础常规能力。
  - **构建优化**：基于 esbuild 优化 Vue 子应用的构建性能。

## 4. 项目经历：业务项目（电商商城等） *Content-[15:19]

### 项目描述与角色
- 避免角色名称重复（如同时写“前端开发”和“前端高级开发”），可直接统称为“项目负责人”或“核心开发”。
- 技术栈描述适当简化，突出核心。

### 核心亮点归纳（前端三大关注点：性能、稳定性、效率）
- **性能优化层面**：
  - 采用多线程加载，防止主线程阻塞。
  - 大文件分片上传技术（将大文件拆分成小块进行上传）。
- **研发提效层面**：
  - 封装动态表单组件。
  - 通过 Slot 自定义表格表单，支持高度可配置的选项。
  - 完善表单校验与提交逻辑。
- **总结建议**：同样按照“性能优化”和“研发提效”进行分类总结，将分散的功能点聚合成有体系的技术贡献，降低面试官的阅读成本。

## AI 总结

本视频针对拥有 3-8 年经验的前端开发者（涵盖校招与社招）提供了一套极具实操性的简历修改指南。核心方法论可以归纳为以下四点：

1. **扬长避短，引导面试**：简历是“开卷考试”，基础技能点到为止，避免过度细化导致被深挖盲区；通过措辞（如“熟练”与“了解”）巧妙管理面试官的预期。
2. **结构化表达，降低阅读成本**：无论是个人优势、工作经历还是项目职责，都应按照“业务/技术”、“性能/提效”等维度进行分类和加粗，让面试官一秒抓住重点。
3. **数据导向与影响力构建**：项目描述不能只写“做了什么”，必须遵循“问题-方案-效果-推广”的逻辑，用具体数据（如200个子应用、秒开）和团队影响力来证明自己的高阶能力。
4. **细节决定专业度**：前端术语（如 Vue2/React）的大小写和拼写必须全局统一规范，构建工具要体现知识广度，这些细节往往是高级开发者的试金石。
