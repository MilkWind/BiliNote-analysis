## 1. STAR 法则简介与基础示例 *Content-[00:00]

写好一段工作经历可以运用 **STAR 法则**，将每段经历归纳为四个部分来充分挖掘自身亮点：
- **S (Situation/背景)**：事情发生的背景。
- **T (Task/任务)**：需要完成的任务或目标。
- **A (Action/行动)**：为了完成任务采取的具体行动。
- **R (Result/结果)**：最终取得的结果。

**基础示例（以学习前端为例）：**
- **S (背景)**：隔壁老王家儿子从事前端开发，薪资不错，自己也想学前端。
- **T (任务)**：找靠谱的职业院校或网上买课学习，目标是找一份比老王家儿子更好的工作。
- **A (行动)**：在网上买课，同时在线下试听院校的前端课程。
- **R (结果)**：选择了一家职业院校学习了六个月，最终找到了一份月薪 18k 的工作，实现了最初的目标。

## 2. 常见前端简历描述误区与优化思路 *Content-[01:22]

### 常见误区：流水账式写法
许多前端求职者的简历描述如下：
- “使用 HTML5/CSS3 开发页面，完成 100% 还原和适配”
- “Vue Router 实现路由跳转”
- “Axios 请求数据”
- “Pinia 实现状态管理”
- “配合测试同事持续优化项目，完成 bug 修改”

**问题分析：**
这种表述方式寡淡无味，像记流水账一样，说了又好像没说，毫无营养。实际上，求职者在工作中肯定用过 Vue Router 的导航守卫、封装过 Axios 等，但简历中没有实事求是地展现出来。这种不走心的写法无法吸引 HR 眼球，会导致工作能力被低估，直接影响薪资和应聘结果。

### 优化思路：对比与升华
以服装销售为例，展示描述方式的重要性：
- **低级写法**：卖场日常顾客接待。
- **优化写法**：使用销售技巧，负责店面接待时把握客户心理，提高下单量，成交量为其他员工的两倍。

**结论：** 优化后的简历内容完全真实，也是实际的工作内容和成果，但不同的描述方式会带来完全不同的阅读感受，更能展示出个人高级的能力。

## 3. 运用 STAR 法则优化前端工作经历实战 *Content-[04:08]

按照四大法则对常见的前端工作经历进行优化，具体成果如下：

### T (任务 Task)
- 负责移动端产品的页面开发，使用原生 HTML5/CSS3 100% 还原设计图，且完美适配常见品牌及各型号机型。
- 使用 Vue 技术栈完成前端的数据交互，并且配合原生 JS 完成效果的交互。

### A (行动 Action)
为了能够实现高质量、按时交付项目，采取了以下行动：
- 提前搭建前端架构，封装公共模块组件、Hooks 函数、Directive（自定义指令）、Axios。
- 团队内部明确分工及开发规范。
- 进行难点预判，提前储备技术，处理常见兼容适配问题。
- 利用 Mock 数据，使用甘特图跟进项目的进度。
- 召开日例会复盘当天工作以及代码 Review，与产品再次确认需求以及下一步计划的实施安排。

### R (结果 Result)
- 所开发的页面完成了 100% 还原交付，且无适配和兼容的问题。
- 交互效果 100% 还原，无兼容问题。
- 提前一周通过测试，高质量交付完成。

通过这种方式，把核心的工作内容按照四大原则描述完毕，逻辑清晰地解释了“为什么能提前一周高质量交付”。剩下的与产品及测试部门的对接工作，同样可以按照此法则继续优化。

## 4. 关于 STAR 法则中 S（背景）的疑问解答 *Content-[05:56]

**疑问：** 在上述优化实例中，为什么没有写 S（背景）？

**解答：**
- **S（背景）不一定每个项目都有**：如果非要写背景，通常就是“老板要求”或者是“公司要赚钱”，这对具体的技术描述意义不大。
- **核心在于逻辑闭环**：按照 STAR 法则优化完毕后，重点在于把“在上家单位有什么任务”、“做了什么”、“采取了什么样的行动”、“取得了什么样的结果”写得清清楚楚、明明白白。只要 T、A、R 的逻辑清晰，就能充分证明个人的技术实力与项目贡献。

本视频详细讲解了前端面试中如何使用 **STAR 法则**（Situation, Task, Action, Result）来撰写高质量的工作经历。视频指出，许多求职者习惯使用“流水账”式的平庸写法（如仅罗列使用 Vue Router 跳转、Axios 请求数据），这会导致技术深度被掩盖。通过对比和实战演示，强调了在简历中必须真实、具体地展现技术细节（如组件封装、架构搭建、项目进度管理等）和量化成果。掌握 STAR 法则，能够有效提升简历的专业度与逻辑性，帮助求职者在面试中脱颖而出，实现跳槽涨薪。
