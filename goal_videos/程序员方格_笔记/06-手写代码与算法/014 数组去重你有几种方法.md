## 1. 数组去重问题的拆解维度 *Content-[00:21]
- 面试中“数组去重”看似简单，但如果仅回答使用 `Set`，往往无法拿到高分。需要从多个维度进行全面拆解：
- **基本类型去重**：处理数字、字符串、`Symbol` 等。需要特别注意面试官爱问的陷阱：`NaN` (Not a Number) 的处理，以及是否需要保持去重后数组的原始顺序。
- **对象去重**：比基本类型复杂。不能简单使用 `==` 或 `===` 比较，因为对象比较的是引用地址。通常需要根据特定字段（如 `id`）去重；进阶情况是要求对整个对象进行深度对比。
- **性能考量**：不同实现方式的时间复杂度和空间复杂度有很大区别，需要权衡并选择最优解。

## 2. 方法一：使用 ES6 的 Set *Content-[01:23]
- **实现方式**：利用 `Set` 天然不重复的数据结构特性，将数组传入 `Set`，再使用展开运算符 `...` 转回数组，一行代码即可实现。
- **处理 `NaN` 的优势**：在 `Set` 内部，`NaN` 被认为是与自身相等的，因此重复的 `NaN` 会被自动去重。这一点在面试中回答出来非常加分。
- **复杂度分析**：时间复杂度和空间复杂度均为 $O(n)$，因为需要遍历一次数组并创建一个新的 `Set`。
- **适用场景**：对于绝大多数基本类型去重场景，这是最简洁高效的最优解。

## 3. 方法二：传统方法及其优化与缺陷 *Content-[02:20]
- **双重循环 + `indexOf`**：
  - 外层循环遍历原数组，内层循环使用 `indexOf` 在新数组中查找，若不存在则 `push` 进去。
  - **缺点**：时间复杂度为 $O(n^2)$，当数组长度达到成千上万时，性能会急剧下降。
- **优化方案：使用 `Object` 键值对（哈希表）**：
  - 创建一个空对象 `Object` 作为哈希表，遍历数组将元素作为对象的键。若键不存在则存入，并将元素推入结果数组。
  - **优点**：将时间复杂度降至 $O(n)$。
  - **致命缺陷**：对象的键会被强制转换为字符串。这意味着数字 `1` 和字符串 `'1'` 在对象眼里是同一个键，导致字符串 `'1'` 被错误过滤。此方法仅适用于元素都是同一种简单类型的场景。

## 4. 方法三：对象数组去重与深度对比 *Content-[03:51]
- **根据特定字段去重（使用 `Map`）**：
  - `Map` 的键可以是任意类型，不会发生强制类型转换。
  - 遍历数组，以对象的特定字段（如 `id`）作为 `key` 在 `Map` 中查找。若不存在则存入 `Map` 并保留该对象。
  - 配合 `filter` 方法处理非常优雅，时间复杂度为 $O(n)$，是处理对象数组去重的标准答案。
- **对整个对象进行深度对比去重**：
  - **巧妙解法**：利用 `JSON.stringify` 将整个对象序列化为 JSON 字符串，然后使用 `Set` 对这些字符串进行去重。
  - **注意事项**：对象属性的顺序会影响 JSON 字符串的结果。例如 `{a: 1, b: 2}` 和 `{b: 2, a: 1}` 会被认为是不同的字符串。因此该方法只能解决特定场景，不够通用。

## 5. 方法四：filter 配合 indexOf 的陷阱与解决 *Content-[05:51]
- **一行流写法**：`arr.filter((item, index) => arr.indexOf(item) === index)`。原理是 `indexOf` 只返回元素第一次出现的索引，相等则保留。
- **`NaN` 陷阱**：
  - `indexOf` 底层使用严格相等（`===`）判断，而 `NaN` 是 JavaScript 中唯一不等于自身的值。
  - 因此 `indexOf(NaN)` 永远返回 `-1`，导致 `NaN` 无法被正确去重，会被重复保留。
- **解决方案**：将 `indexOf` 替换为 ES7 的 `includes`。`includes` 底层做了特殊处理，能够正确识别 `NaN`。这体现了对语言细节的掌握程度。

## 6. 终极版 unique 函数封装与工程化 *Content-[07:12]
- **基础版**：使用 `Set` 处理基本类型去重。
- **进阶版**：增加 `key` 参数。不传 `key` 走 `Set` 逻辑；传入 `key` 则使用 `Map` 处理对象数组，提升代码可复用性。
- **第三版（高扩展性）**：将 `key` 改为 `options` 配置对象。
  - 支持多字段联合去重：将多个 `key` 的值拼接成唯一字符串。
  - 支持自定义比较函数 `fn`：将比较逻辑交给用户，应对各种复杂的去重需求。
- 写到这个程度，能够充分体现前端工程师的工程化能力。

## 7. 面试满分答案总结 *Content-[08:01]
- **基本类型**：首选 `Set`，简洁高效且能正确处理 `NaN`。
- **对象数组**：使用 `Map` 并通过指定 `key` 实现去重。
- **避坑指南**：注意 `NaN` 陷阱，`indexOf` 无法处理 `NaN`，必要时必须使用 `includes`。
- **性能优化**：避免使用双重循环导致 $O(n^2)$ 的时间复杂度问题。
