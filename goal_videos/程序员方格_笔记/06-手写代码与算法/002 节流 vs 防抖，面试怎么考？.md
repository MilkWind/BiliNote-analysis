## 1. 高频事件与性能优化背景 *Content-[00:07]

在前端事件开发中，经常会遇到一些高频触发的事件，例如：
- 用户滚动页面（`window.scroll`）
- 调整窗口大小（`window.resize`）
- 在输入框里快速打字（`input` 事件）

**性能瓶颈的产生：**
如果这些高频事件没有得到妥善处理，很容易成为页面的性能杀手。以 `window.scroll` 为例，快速滚动页面时，该事件可能在极短时间内触发几十甚至上百次。如果每一次滚动都执行复杂的计算或 DOM 操作，会导致页面变得非常卡顿，甚至引起浏览器崩溃。

**优化方案：**
通过**节流（Throttle）**和**防抖（Debounce）**，可以有效减少回调函数的执行次数，从而降低对 CPU 和内存的消耗。对于需要发送网络请求的场景（如输入框实时搜索），还能减轻服务端压力，最终显著提升用户的操作体验，让页面更加流畅。

## 2. 节流 (Throttle) 核心概念 *Content-[01:04]

**核心目标：**
控制事件的执行频率。

**运行机制：**
设定一个固定的时间周期（例如 200ms）。在这个周期内，无论用户触发事件多少次，回调函数**最多只执行一次**。

**形象比喻：**
节流就像**水龙头**。无论你把水龙头开得多大，单位时间内流出的水量是受到限制的。

**核心特点：**
节流是一种**周期性执行**的策略，保证在设定的时间间隔内，回调函数至少（或最多）执行一次。

## 3. 防抖 (Debounce) 核心概念 *Content-[01:45]

**核心目标：**
控制事件的触发时机。

**运行机制：**
当事件触发后，不立即执行回调函数，而是等待一个固定的延迟时间（如 500ms）。如果在等待期间事件再次被触发，则会取消掉之前的等待，并**重新开始计时**。只有当事件停止触发，且等待时间完全过去，回调函数才会真正执行。

**形象比喻：**
防抖就像**按电梯按钮**。如果在等待关门的时间里，没有其他人按其他楼层的按钮，电梯门才会关上；如果有人按了新楼层，关门的时间就会重新计算。

**核心特点：**
防抖限制的是执行时机，确保函数只在事件停止触发后的“空闲期”执行一次。

## 4. 节流 (Throttle) 实现原理与代码 *Content-[03:54]

**实现思路：**
节流的经典实现思路是**基于时间戳**。

**核心逻辑：**
1\. **设定参数**：需要执行的回调函数 `fn`，以及时间间隔 `delay`。
2\. **记录时间**：使用变量 `lastTime` 记录上一次成功执行回调的时间点，初始值设为 `0`。
3\. **返回新函数**：`throttle` 函数返回一个新的函数（真正绑定到高频事件上的处理器）。在内部需要处理 `this` 指向（`context`）和参数传递（`args`）。
4\. **时间差判断**：
   - 获取当前时间戳 `now`。
   - 判断 `now - lastTime >= delay`。
   - 如果**满足**：说明距离上次执行已经过去了一个完整的周期。允许执行回调，第一时间更新 `lastTime = now`，然后调用 `fn.apply(context, args)`。
   - 如果**不满足**：说明还在同一个周期内，忽略本次触发。

**代码框架示例：**
```javascript
function throttle(fn, delay) {
    let lastTime = 0;
    
    return function(...args) {
        const context = this;
        const now = Date.now();
        
        if (now - lastTime >= delay) {
            lastTime = now;
            fn.apply(context, args);
        }
    }
}

// 使用示例：绑定到 window.scroll，每 200ms 最多执行一次
window.addEventListener('scroll', throttle(function() {
    console.log('滚动事件触发');
}, 200));
```

## 5. 防抖 (Debounce) 实现原理与代码 *Content-[07:42]

**实现思路：**
防抖的实现主要依赖于 JavaScript 的定时器机制，尤其是 `setTimeout` 和 `clearTimeout`。

**核心逻辑：**
1\. **设定参数**：回调函数 `fn`，延时时间 `delay`。
2\. **记录定时器**：使用变量 `timer` 存储定时器的 ID，初始值设为 `null`。
3\. **返回新函数**：同样处理 `this` 指向（`context`）和参数（`args`）。
4\. **清除与重设定时器**：
   - 每当事件触发进入函数时，首先判断 `timer` 是否存在。
   - 如果**存在**：说明上次设置的定时器还未执行，立即清除旧定时器 `clearTimeout(timer)`。
   - **重新设置**：无论是否清除，都重新设置一个新的 `setTimeout`，在 `delay` 毫秒后尝试执行回调。
   - 在 `setTimeout` 的回调内部，真正执行业务逻辑 `fn.apply(context, args)`，并在执行后将 `timer` 置为 `null`，表示没有活动的定时器了。

**代码框架示例：**
```javascript
function debounce(fn, delay) {
    let timer = null;
    
    return function(...args) {
        const context = this;
        
        if (timer) {
            clearTimeout(timer);
        }
        
        timer = setTimeout(() => {
            fn.apply(context, args);
            timer = null; // 执行完毕，重置 timer
        }, delay);
    }
}

// 使用示例：绑定到 input 事件，停止输入 500ms 后执行
const myInput = document.getElementById('my-input');
myInput.addEventListener('input', debounce(function() {
    console.log('输入停止，发送请求');
}, 500));
```

## 6. 核心区别与业务场景选择 *Content-[11:32]

**核心区别总结：**
- **节流 (Throttle)**：节约流量。限制执行**频率**，保证在设定时间内**至少/最多执行一次**。属于**固定周期执行**。
- **防抖 (Debounce)**：消除抖动。限制执行**时机**，保证在事件停止触发并等待一段空闲时间后，**只执行一次**。属于**空闲等待后执行**。

**业务场景选择指南：**

1\. **适用节流 (Throttle) 的场景：**
   需要持续响应的高频事件，但不能处理得太频繁。
   - **滚动加载**：在滚动过程中，每隔一段时间检查是否到达底部以触发加载。
   - **监听窗口变化**：实时调整布局，不需要每次像素变化都重新计算。
   - **游戏连续射击**：点住鼠标需要连续射击，但需要限制射速，避免瞬间打光子弹。

2\. **适用防抖 (Debounce) 的场景：**
   需要在事件停止后，执行一次最终操作的场景。
   - **搜索框输入**：用户停止输入后，再根据最终关键词请求联想或执行搜索，避免每输入一个字符就发一次请求。
   - **`window.resize`**：只关心用户停止拖动窗口后的最终尺寸，以此来重新布局，而不是在拖动过程中频繁计算。
   - **拖拽事件 (`drag`)**：配合防抖使用，确保用户在真正释放拖拽元素后，才去处理收尾的逻辑。

## AI 总结

节流（Throttle）和防抖（Debounce）是前端处理高频事件、优化页面性能的核心手段。
- **节流**通过设定固定时间周期，限制函数的执行频率，适用于需要持续响应但无需过于频繁的场景（如滚动加载、游戏射击）。
- **防抖**通过定时器机制，在事件停止触发后的空闲期执行函数，适用于只需获取最终状态的场景（如搜索框联想、窗口 resize 重新布局）。
理解两者的核心区别（周期性执行 vs 空闲后执行）并结合具体业务需求进行选择，是前端开发中构建流畅、高性能 Web 应用的关键能力。
