## 1. 什么是柯里化 (Currying) *Content-[01:08]

柯里化（Currying）是来源于函数式编程的一个重要概念。

- **核心思想**：将一个原本接收多个参数的函数，转换成一系列只接收一个（或少量）参数的函数序列。
- **执行过程**：
  - 不再需要一次性给函数提供所有的参数。
  - 调用柯里化后的新函数时，它每次只接收一个（或多个）参数，并返回一个新的函数。
  - 这个过程会持续进行，直到一步一步地提供了所有必需的参数。
  - 当所有参数都齐备之后，函数序列的最后一步才会执行原函数，并返回最终结果。

## 2. 引入柯里化的核心优势 *Content-[02:12]

引入柯里化这种看似复杂的调用方式，主要为现代 JavaScript 开发和函数式编程带来了以下重要优势：

- **延迟执行和部分应用**：
  - 通过柯里化，可以提前固定函数的一些参数，生成一个新的函数。
  - 这个新函数会“记住”之前已提供的参数，允许你在稍后的时机或不同的地方再提供剩余的参数来最终执行函数，无需立即执行。
  - 这使得开发者可以创建更具针对性的、预设了部分行为的函数。
- **显著提高函数的复用性**：
  - 通过预设参数，可以从一个通用的基础函数派生出许多更特定的函数版本。
  - **示例**：一个通用的日志函数经过柯里化后，可以轻松创建出 `logInfo`、`logWarning`、`logError` 等不同级别的日志函数，无需重复编写相似的代码逻辑，有效避免代码冗余。
- **增强函数的组合性**：
  - 柯里化函数每次只处理一个参数并返回新函数，这种结构非常契合函数组合的链式调用风格。
  - 允许开发者像搭积木一样，把小的、单一职责的柯里化函数组合成复杂的数据处理流程。

## 3. 手写柯里化函数实现 *Content-[04:59]

柯里化并非 JavaScript 原生的内置 API，而是一种函数转换技术或模式。我们可以利用 JS 的高级特性（如高阶函数、闭包、剩余参数等）来手动实现。

- **核心骨架**：
  编写一个名为 `curry` 的高阶函数，它接收一个待柯里化的原始函数 `fn`，并返回柯里化后的新函数。

```javascript
function curry(fn) {
  return function curried(...args) {
    // 判断逻辑与递归调用
  };
}
```

- **核心判断逻辑**：
  在 `curried` 函数内部，需要判断当前收集的参数是否已经足够执行原始函数 `fn`。
  - **条件**：`args.length >= fn.length`（当前收集到的参数数量 >= 原始函数期望的参数数量）。
  - **参数足够时**：直接执行原始函数 `fn`。使用 `fn.apply(this, args)`，其中 `this` 是为了确保在原始函数内部 `this` 上下文指向正确。
  - **参数不足时**：不能直接执行，而是返回一个新的函数等待剩余参数。

- **参数不足时的递归处理**：
  返回的新函数依然使用剩余参数 `...restArgs` 接收本次调用传入的参数。
  使用 `concat` 方法将之前收集的 `args` 和新接收的 `restArgs` 合并，然后再次调用 `curried` 自身，形成递归调用链，直到参数足够为止。

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    } else {
      return function (...restArgs) {
        return curried.apply(this, args.concat(restArgs));
      };
    }
  };
}
```

## 4. 柯里化函数的调用示例 *Content-[09:06]

通过一个求和函数 `sum(a, b, c)` 来演示柯里化后的灵活调用方式：

```javascript
function sum(a, b, c) {
  return a + b + c;
}
const curriedSum = curry(sum);
```

- **逐个参数传递**：
  `curriedSum(1)(2)(3)`
  每次传入一个参数，参数不足时返回新函数，直到传入 `3` 时参数齐备，执行原函数输出 `6`。
- **一次性传入多个参数**：
  `curriedSum(1, 2)(3)`
  第一次传入两个参数，内部判断 `args.length` (2) 小于 `fn.length` (3)，返回新函数并记住 `[1, 2]`。第二次传入 `3`，合并后执行。
- **混合传参**：
  `curriedSum(1)(2, 3)`
  原理同上，第一次记住 `1`，第二次传入 `2, 3` 后合并执行。
- **一次性传完所有参数**：
  `curriedSum(1, 2, 3)`
  像调用原始函数一样直接传入所有参数，直接执行并返回结果。

**结论**：柯里化后的函数提供了极大的灵活性，并不强制每次只传一个参数，允许在不同的阶段以不同的组合方式提供参数。

## 5. 实际使用中的关键注意事项 *Content-[12:02]

在基础实现之外，实际开发和复杂场景中需要注意以下关键点：

- **参数数量判断的局限性 (`fn.length`)**：
  - 基础实现依赖函数的 `length` 属性来获取期望的参数数量。
  - **注意**：`fn.length` **不会**计算带有默认值、剩余参数（rest parameters）或解构参数的个数。
  - 在处理带有这些特性的函数时，基于 `fn.length` 的判断可能不再准确，需要编写更复杂的逻辑来确定何时执行原函数。
- **`this` 上下文处理**：
  - 实现中使用了 `apply(this, args)` 来传递上下文，这是一种较健壮的做法。
  - 如果柯里化函数依赖于特定对象的方法调用，或者内部使用了箭头函数，可能需要更精细的 `this` 绑定策略。
  - 在纯粹的函数式编程中，通常会避免使用依赖 `this` 的函数。
- **成熟库的高级特性**：
  - 业界成熟的柯里化函数库（如 `lodash`、`ramda`）会考虑更复杂的场景。
  - 例如支持**占位符参数**（Placeholder），允许跳过某个参数在后续再提供。
  - 理解了基础的手写实现原理，再去学习这些成熟库的高级用法会更加容易和深入。

## 6. 柯里化与偏函数 (Partial Application) 的区别 *Content-[14:11]

在学习柯里化时，常有人将其与偏函数混淆，虽然柯里化可以实现偏函数的效果，但两者概念和实现方式不同：

- **柯里化 (Currying)**：
  - **目的**：将一个多参数函数彻底转换成一系列专注于接收单个（或少量）参数的函数。
  - **特点**：将参数的接收过程**序列化**。可以一步步传 `f(a)(b)(c)`，也可以一次传多个 `f(a, b)(c)`。
- **偏函数 (Partial Application)**：
  - **目的**：固定函数的部分参数，生成一个新的函数，该新函数接收剩余的参数并执行原始函数。
  - **特点**：**提前应用**了部分参数。
  - **示例**：`const partialF = partial(f, a, b)`，然后调用 `partialF(c)`。

## AI 总结

柯里化（Currying）是 JavaScript 函数式编程中一种优雅且实用的技术，其核心是将多参数函数转化为单参数函数序列。它通过延迟执行、参数预设和函数组合，极大地提升了代码的灵活性、复用性和可组合性。手写柯里化函数的核心在于利用高阶函数和闭包，通过判断 `args.length >= fn.length` 来决定是执行原函数还是返回接收剩余参数的新函数。在实际应用中，需特别注意 `fn.length` 对默认值和剩余参数的计算缺陷，以及 `this` 上下文的正确绑定。此外，需明确柯里化（参数接收序列化）与偏函数（提前固定部分参数）在概念上的本质区别。掌握柯里化有助于编写出更高级、更具表达力的前端代码。
