## 1. 题目介绍与解题思路 *Content-[00:00]

- **面试高频题目**：实现一个并发控制调度器，要求能够限制同时执行的异步任务数量。
- **核心解题思路（三步走策略）**：
  1. **执行池（停车场模型）**：
     - 将执行池想象成一个只有固定数量车位的停车场。例如，若最大并发数设定为 3，则代表停车场只有 3 个车位。
     - 在代码中，使用一个数组（如 `running`）来表示执行池，里面存放当前正在执行的任务。
  2. **等待队列**：
     - 当停车场车位停满后，后续新来的任务必须排队。
     - 使用一个等待队列（如 `q`），所有新到来但暂时无法执行的任务都会先被丢入该队列中等待。
  3. **自动调度机制（核心闭环）**：
     - 当停车场有一辆车开走（即有一个异步任务执行完成）时，系统必须立刻从等待队列中叫一辆新车进来，占用空出来的车位。
     - 这一机制形成了一个完美的闭环，保证了停车场的利用率达到最高，同时绝对不会超出车位（最大并发数）的限制。

## 2. 代码骨架与属性初始化 *Content-[01:27]

- **类定义**：创建一个名为 `Scheduler` 的类来封装调度器逻辑。
- **构造函数 `constructor` 初始化属性**：
  - `max`：最大并发数，即停车场的总车位数。
  - `running`：执行池，使用数组存放正在运行的任务（Promise）。
  - `q`：等待队列，存放所有处于等待状态的任务。
- **`add` 方法（任务添加入口）**：
  - 这是向调度器添加任务的入口方法，它返回一个 `Promise`。
  - **返回 `Promise` 的目的**：让外部调用时能够通过 `await` 语法来等待该任务真正执行完成。
  - **内部逻辑**：在 `add` 方法内部并不直接执行任务，而是将任务函数本身及其对应的 `resolve` 函数打包成一个对象，然后塞入等待队列 `q` 中。
  - 最后，调用 `run` 函数来尝试启动调度引擎。

## 3. 核心调度引擎 run 方法剖析 *Content-[02:32]

- **`while` 循环（调度开关）**：
  - 持续检查两个核心条件，只有同时满足时才会启动新任务：
    - 条件一：执行池 `running` 中还有空位（即 `running.length < max`）。
    - 条件二：等待队列 `q` 中还有新的任务在排队（即 `q.length > 0`）。
- **任务执行与状态管理**：
  - 当条件满足时，从等待队列 `q` 中使用 `shift()` 方法取出最前面的任务。
  - 立即执行该任务（注意：`task` 本身是一个返回 `Promise` 的函数）。
  - 使用 `.then()` 捕获任务的执行结果，并通过之前打包保存的 `resolve` 函数，将结果传递给 `add` 方法返回的那个 `Promise`。
  - 同时，将正在执行的这个任务 `Promise` 推入 `running` 执行池中，表示该“车位”已被占用。
- **核心调度逻辑（`finally` 回调）**：
  - 给任务的 `Promise` 挂上 `.finally()` 回调。使用 `finally` 是因为无论任务是成功还是失败，都算作执行完毕，必须释放占用的车位。
  - **动作一（释放车位）**：在 `finally` 内部，从 `running` 执行池中将刚才完成的 `Promise` 删除（如使用 `splice`），释放空位。
  - **动作二（递归调度）**：再次递归调用 `this.run()`。这会立即触发新一轮的条件检查，看看是否能从等待队列中再拉取一个新任务来执行。
  - 正是通过这一步递归调用，实现了自动的链式调度，让整个系统像永动机一样持续、稳定地运转。

## 4. 面试满分要点总结 *Content-[04:27]

在面试中，清晰地向面试官表达以下三个核心要点，即可拿下高分：
1. **核心设计模式**：必须讲出使用“执行池 + 等待队列”的设计模式，这是整个解题的根基。
2. **调度触发时机与方式**：强调任务完成后的调度是在 `.finally()` 中触发的（确保成功与失败都能释放资源），并通过递归调用 `run` 方法实现自动的链式调度。
3. **设计的最终目的**：点明通过这套闭环系统的设计，能够优雅且严格地保证并发数量永远不会超过设定的最大值。

## AI 总结

本题考察的是前端开发中经典的**异步并发控制**场景。解题的核心在于构建一个基于“执行池”和“等待队列”的调度模型。通过 `Scheduler` 类封装状态，利用 `Promise` 的 `.finally()` 机制确保任务无论成败都能正确释放执行池资源，并结合递归调用 `run` 方法实现任务的自动流转。掌握这一闭环设计模式，不仅能完美应对并发限制面试题，还能在实际业务（如请求限流、批量任务处理）中高效控制资源消耗。
