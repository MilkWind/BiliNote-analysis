## 题目解析与核心考察点 *Content-[00:00]
- **面试必考题**：手写 `Promise.all` 和 `Promise.allSettled`。
- **考察深度**：这道题不仅仅考察对 Promise API 的熟悉程度，更深层次考察的是对**异步并发控制**的理解。如果答不好，很容易在面试中失分。

## 典型错误写法与三大致命问题 *Content-[00:21]
- **错误思路**：创建一个 Promise，遍历输入的 Promise 数组，将每个 Promise 的结果 `push` 到结果数组中，循环结束后立即 `resolve`。
- **致命问题 1：顺序错乱**。`Promise.all` 要求返回结果的顺序必须与输入数组一致。由于 Promise 是异步的，使用 `push` 会导致先完成的任务先入数组，顺序无法保证。
- **致命问题 2：时机错误**。`forEach` 循环走完会立即执行 `resolve`，但此时内部的 Promise 可能一个都还没执行完，导致 `resolve` 出去的是一个空数组。
- **致命问题 3：异常丢失**。代码中只写了 `then` 的成功回调，若任何一个 Promise 失败，异常会被吞掉，外部完全感知不到，导致整个逻辑崩塌。

## 核心异步编程难点分析 *Content-[01:56]
- **难点 1：并发控制下的顺序性**。`Promise.all` 本质是并发执行一组异步任务，但要求结果按原始顺序排列。并发和顺序是一对矛盾，需要巧妙解决。
- **难点 2：完成时机的判断**。需要一个机制，在最后一个 Promise 执行完毕的精确时刻去 `resolve` 最终结果，不能早也不能晚。

## 解决顺序问题：索引赋值法 *Content-[02:42]
- **解决方案**：放弃使用 `push` API，利用 `forEach` 循环提供的**索引（index）**。
- **实现细节**：
  - 预先创建一个空的结果数组。
  - 在每个 Promise 完成时，根据其在原始数组中的索引，将结果放到结果数组的对应位置上（即 `result[index] = value`）。
  - 这样无论哪个 Promise 先完成，结果都会被放在正确的位置，完美保证顺序。
- **良好习惯**：使用 `Promise.resolve` 包装传入的值，以兼容非 Promise 实例的普通值。

## 解决完成时机问题：计数器控制 *Content-[03:40]
- **解决方案**：使用一个**计数器**来精确捕捉所有 Promise 都完成的时刻。
- **实现细节**：
  - 在最外层定义一个计数器，初始值为 0。
  - 在每个 Promise 成功的回调中，将结果存入结果数组后，让计数器加 1。
  - **关键判断**：当计数器等于结果数组的长度（即传入的 Promise 数组长度）时，表示所有任务已完成，此时执行 `resolve` 操作。

## 边界条件与异常处理 *Content-[04:32]
- **边界情况 1：空数组处理**。根据 Promises/A+ 规范，若传入空数组，应立即同步返回一个已完成的 Promise，值为空数组。在代码开头判断 `promises.length === 0`，直接 `resolve([])`。
- **边界情况 2：异常处理**。`Promise.all` 的规则是“快速失败”，只要有一个 Promise 失败，整体立即失败。
  - 在 `then` 方法中加入第二个参数（失败回调）。
  - 一旦任意一个 Promise 进入失败回调，直接 `reject` 失败的原因，将错误传递出去。

## 手写 Promise.allSettled 及与 Promise.all 的区别 *Content-[05:51]
- **核心区别**：
  - `Promise.all`：一个失败，整体立即失败。
  - `Promise.allSettled`：不管内部 Promise 成功还是失败，都会耐心等待所有任务执行完毕，永远不会直接失败。最终 `resolve` 的是一个包含每个 Promise 结果的对象数组。
- **结果对象格式**：
  - 成功：`{ status: 'fulfilled', value: value }`
  - 失败：`{ status: 'rejected', reason: error }`
- **实现细节**（在 `Promise.all` 基础上修改）：
  - 框架几乎一致：同样使用索引保证顺序，使用计数器控制时机。
  - **成功回调**：不直接存 `value`，而是存对象 `{ status: 'fulfilled', value: value }`。
  - **失败回调**：不直接 `reject` 整个 Promise，而是在结果数组中记录 `{ status: 'rejected', reason: error }`，同时计数器加 1。
  - 当计数器等于数组长度时，统一 `resolve` 结果数组。

## 面试满分答案核心总结 *Content-[07:46]
- **核心 1：索引赋值**。使用数组索引赋值，绝对不能用 `push`，保证结果顺序。
- **核心 2：计数控制**。使用计数器精确判断所有异步任务完成的时机。
- **核心 3：异常处理**。明确 `all`（快速失败）和 `allSettled`（全部等待完毕后返回）在面对失败时的不同策略。
