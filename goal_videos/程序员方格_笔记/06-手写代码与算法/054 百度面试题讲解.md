## 1. 题目分析与核心原理 *Content-[00:01]
- **题目需求**：实现一个功能，使得数字（原始类型）可以直接调用自定义方法（如 `add` 方法），并且支持链式调用（如连续进行加减操作）。
- **核心原理分析**：
  - 数字本身是**原始类型**（Primitive Type），在 JavaScript 中，原始类型本身是不能直接调用方法的。
  - 当尝试使用原始类型调用方法时，JavaScript 引擎会自动进行**包装转换**，将其临时转换为对应的**包装类型**（Wrapper Object）。
  - 对于数字而言，其对应的包装类型是 `Number`。也就是说，`5.add(3)` 在底层相当于 `new Number(5).add(3)`。

## 2. 实现自定义方法（加法）与链式调用 *Content-[01:07]
- **扩展原型方法**：
  - 既然数字调用方法时会自动转换为 `Number` 对象，那么只需要在 `Number.prototype` 上绑定自定义方法即可让所有数字调用。
  - 例如，定义一个加法方法：
    ```javascript
    Number.prototype.add = function(n) {
        // 获取当前数字的原始值并相加
        return this.valueOf() + n;
    }
    ```
- **链式调用的实现**：
  - 要实现链式调用（如 `5.add(3).minus(2)`），方法必须有返回值，且返回值必须能够继续调用下一个方法。
  - **返回值的选择**：
    - **手动包装**：返回 `new Number(result)`。这样返回的是一个对象，可以继续调用方法，但直接 `console.log` 打印时会显示为对象类型（如 `Number {8}`），不够纯粹。
    - **返回原始值（推荐）**：直接返回计算后的原始数字（如 `return this.valueOf() + n`）。虽然返回的是原始类型，但在进行下一次链式调用时，系统会**再次自动进行包装**，因此完全不影响后续的方法调用，且打印时显示为淳朴的原始数字类型。

## 3. 实现减法方法（minus）与代码测试 *Content-[03:35]
- **实现减法逻辑**：
  - 同理，在 `Number.prototype` 上绑定 `minus` 方法：
    ```javascript
    Number.prototype.minus = function(n) {
        return this.valueOf() - n;
    }
    ```
- **代码测试**：
  - 执行链式调用：`5.add(3).minus(2)`
  - 执行过程：
    1. `5.add(3)` -> 返回原始值 `8`
    2. `8.minus(2)` -> 系统自动将 `8` 包装为 `Number` 对象，调用 `minus` 方法，返回原始值 `6`
  - 最终计算结果为 $5 + 3 - 2 = 6$，完美实现数字直接调用方法并支持链式操作的功能。

## 4. 面试题核心考点总结 *Content-[04:22]
这道百度面试题主要考察了以下三个核心知识点：
1. **原始类型与包装类型的自动转换**：
   - 原始类型（如 Number、String、Boolean）不是对象，理论上不能调用方法。
   - 当对原始类型调用方法时，系统会自动将其转换为对应的包装类型对象，调用完成后（如果不涉及返回或赋值）再销毁该临时对象。
2. **原型与原型链操作**：
   - 要让所有数字都能调用自定义方法，必须将方法挂载到其包装类型的原型上，即 `Number.prototype`。这样所有通过自动或手动包装生成的 `Number` 对象都能通过原型链访问到该方法。
3. **链式调用的返回值设计**：
   - 链式调用的前提是方法必须有返回值。
   - 返回操作后的**原始值**即可，无需手动 `new Number()` 包装。因为在下一次链式调用时，JavaScript 引擎会自动帮你完成包装转换。这样既保证了链式调用的连续性，又维持了数据类型的纯粹性。
