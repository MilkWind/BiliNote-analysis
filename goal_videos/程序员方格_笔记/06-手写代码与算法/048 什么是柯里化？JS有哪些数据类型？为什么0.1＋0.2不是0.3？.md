## 1. 什么是柯里化 (Currying) *Content-[00:00]
- **核心原理**：柯里化是将一个接收多个参数的函数，转化为一系列只接收单个参数的函数的过程。调用一个方法后，它会返回一个新的函数。
- **执行示例**：例如执行 `add(5)`，数字 5 会被存入内存中，并返回一个新的函数。当继续调用该新函数并传入参数 3 时（即 `add(5)(3)`），最终返回结果 8。
- **标准概念**：一个接收两个参数的函数，可以被柯里化为只接收一个参数的函数，该函数返回一个新的函数来接收第二个参数并返回最终结果。
- **优缺点**：
  - **优点**：将多参数函数转换为单参数函数，使得函数更易于组合和重用。
  - **缺点**：在实际项目中，柯里化代码的可读性较差，逻辑较为绕弯，通常更多用于面试考察。

## 2. JS 有哪些数据类型 *Content-[01:32]
JavaScript 中的数据类型主要分为两大类：
- **基本数据类型（7种）**：`number`、`string`、`boolean`、`null`、`undefined`、`symbol`、`bigint`。
- **引用数据类型**：`object`。需要注意的是，函数（Function）和数组（Array）在本质上也都属于对象。

## 3. 为什么 $0.1 + 0.2 \neq 0.3$ *Content-[01:48]
- **底层原因**：计算机硬件在底层是以二进制形式存储和计算数据的。当把十进制的浮点数（如 0.1 和 0.2）转换为二进制时，会变成无限循环小数。由于计算机的精度限制，必须对这些无限循环小数进行四舍五入截断，从而导致最终的运算结果不准确。
- **解决方案**：
  1. **转为整数计算**：将小数放大转为整数进行运算，得出结果后再缩小（做除法）还原为小数。
  2. **字符串处理**：将数字转换为字符串，然后手动实现字符串的相加逻辑来保证精度。

## 4. new 操作符发生了什么 *Content-[02:30]
使用 `new` 关键字实例化对象时，底层主要执行了以下四个步骤：
1. **创建空对象**：在内存中创建一个全新的空对象。
2. **链接原型**：将新创建对象的 `__proto__` 属性指向构造函数的 `prototype` 属性。
3. **绑定 this 并执行**：执行构造函数，并将新创建的空对象作为 `this` 的上下文绑定。
4. **返回结果**：判断构造函数的返回值。如果构造函数显式返回了一个对象，则返回该对象；否则，返回最初新创建的那个对象。

## 5. typeof 和 instanceof 的区别 *Content-[02:53]
- **instanceof**：用于检测一个对象是否属于某个类或其子类（即判断原型链），返回一个布尔值（`boolean`）。
- **typeof**：用于检测变量的数据类型，返回一个表示类型的字符串。
  - **特别注意**：当使用 `typeof null` 时，返回的结果是 `"object"`，这是 JS 历史遗留的一个 Bug。

## 6. 什么是事件的冒泡和捕获 *Content-[03:20]
DOM 事件流包含两个主要阶段：
- **捕获阶段（Capture）**：事件从最外层的根节点开始，自上而下传递到目标元素。
- **冒泡阶段（Bubble）**：事件到达目标元素后，自下而上向根节点方向传递。
- **执行顺序**：先发生捕获，后发生冒泡。

## 7. 什么是事件委托 *Content-[03:34]
- **概念**：将子元素的事件监听器绑定到其父级元素上，利用事件的冒泡机制，通过 `event.target` 来获取实际触发事件的子元素。
- **优势**：如果一个父元素下包含大量子元素（例如 100 个 `li` 标签），为每个子元素单独绑定事件会消耗大量内存并影响性能。通过事件委托，只需绑定一次事件即可，大幅提升了性能并减少了内存占用。

## 8. split 和 join 的区别 *Content-[04:05]
- **split**：字符串方法。将字符串按照指定的字符进行分割，并转换成一个数组。
- **join**：数组方法。将数组中的元素按照指定的字符拼接在一起，并转换成一个字符串。

## 9. 堆和栈的区别 *Content-[04:16]
- **栈（Stack）**：用于存储基本数据类型。
- **堆（Heap）**：用于存储引用数据类型（如对象）。
- **访问机制**：对象的引用地址存储在栈中，而对象的实际数据存储在堆中。当访问一个对象时，程序会先在栈中获取该对象的引用地址，然后再根据这个地址去堆内存中找到对应的实际数据。

## 10. 怎么实现深拷贝 *Content-[04:37]
深拷贝会完全复制一个对象，开辟新的内存空间。常见的实现方式有三种：
1. **递归实现**：手写递归函数。需要处理多种复杂情况，如函数、数组、`symbol` 类型以及循环引用等。
2. **JSON 序列化**：使用 `JSON.stringify()` 将对象转为字符串，再用 `JSON.parse()` 转回对象。这种方法简单粗暴，但缺点是无法拷贝函数，且对 `symbol` 等特殊类型支持不佳。
3. **第三方库**：直接使用成熟的工具库，如 `lodash` 中的 `_.cloneDeep()` 方法。

## 11. 怎么实现浅拷贝 *Content-[05:34]
浅拷贝只复制对象的第一层属性，如果属性是引用类型，则复制其引用地址。
- **对象浅拷贝**：使用 `Object.assign()` 或 ES6 的扩展运算符（`...`）。
- **数组浅拷贝**：使用数组的 `slice()` 方法或 `concat()` 方法。

## 12. 闭包有什么作用 *Content-[05:53]
- **核心作用**：闭包最主要的功能是**延长作用域链**，使得内部函数能够访问外部函数作用域中的变量，即使外部函数已经执行完毕。

## 13. encodeURI 和 decodeURI 的作用 *Content-[06:08]
这两个方法主要用于处理浏览器 URL 中的特殊字符（尤其是中文字符）：
- **encodeURI**：对 URL 进行转码（加密）。采用 UTF-8 编码格式，将中文等特殊字符转换为浏览器可识别的格式，防止服务端接收参数时出现乱码。
- **decodeURI**：对转码后的 URL 进行解码（解密），将其还原为原始的字符。

## 14. window.onload 和 document.ready 的区别 *Content-[06:59]
- **window.onload**：原生 JS 方法。必须等待整个页面的所有资源（包括 JS、CSS、图片等）全部加载完毕后，才会执行回调函数。
- **document.ready**：浏览器原生并没有 `document.ready` 方法，这通常是 jQuery 中的 `$(document).ready()`。它只需要 DOM 树构建完成即可执行，不需要等待外部资源（如图片）加载，因此执行时机更早，效率更高。
