   - 如何优雅地收集每一次传入的参数。
   - 准确判断执行时机：什么时候继续返回函数等待下一个参数，什么时候真正执行目标函数。
   - 边界情况的处理：如 `this` 指向问题、参数为空等。

如果概念不清且代码写不出来，面试表现就会非常危险。想要拿高分，必须在概念和代码实现两个层面都做到位。

## 柯里化 (Currying) 概念解析 *Content-[01:10]

### 定义
柯里化是一个非常简洁的概念：**把一个接收多个参数的函数，转换成一系列只接收一个（或少数几个）参数的函数的过程**。

### 示例说明
假设有一个普通的 `add` 函数，接收 `a`、`b`、`c` 三个参数并返回它们的和：
```javascript
function add(a, b, c) {
  return a + b + c;
}
add(1, 2, 3); // 返回 6
```

经过柯里化包装后（例如使用 `curry` 函数），新的 `curryAdd` 函数不再需要一次性给够所有参数：
```javascript
curryAdd(1)(2)(3);    // 返回 6
curryAdd(1, 2)(3);    // 返回 6
curryAdd(1)(2, 3);    // 返回 6
```
无论怎么分批传参，只要参数齐了，都能正确返回结果。

### 核心思想
柯里化主要做了两件事：
1\. **参数复用**：每次调用时，实际上是在保存或固定一部分参数。
2\. **延迟执行**：只要参数还没给够，就不会真正执行原始函数，而是持续返回一个新函数。等到参数齐全时，再一次性计算出结果。

## 柯里化手写实现 *Content-[02:33]

手写柯里化是面试的重头戏。核心思路是：**利用闭包持续收集参数，直到参数个数达到原始函数的要求，再执行目标函数**。

### 代码实现
```javascript
function curry(fn) {
  // 1. 获取目标函数期望的形参个数
  const arity = fn.length; 
  
  // 2. 返回柯里化后的主体函数
  return function curried(...args) {
    // 3. 判断收集到的参数是否已经满足原函数的要求
    if (args.length >= arity) {
      // 参数够了，直接执行原函数并返回结果
      return fn.apply(this, args);
    } else {
      // 参数不够，返回一个新函数继续收集下一轮参数
      return function (...nextArgs) {
        // 递归调用 curried，将新旧参数拼接后传入
        return curried.apply(this, args.concat(nextArgs));
      };
    }
  };
}
```

### 关键细节解析
- **`fn.length`**：这个属性可以获取函数定义时声明的形参个数，是判断参数是否收集完毕的关键。
- **剩余参数语法 `...args`**：用于灵活接收用户每次传入的单个或多个参数。
- **递归调用**：当参数不足时，返回的匿名函数会接收 `...nextArgs`，并通过 `concat` 方法将新旧参数拼接，再次传递给 `curried` 函数，形成优雅的递归收集过程。

## 柯里化应用场景 *Content-[04:45]

面试官通常会追问柯里化的实际应用场景，其核心应用正是前面提到的**参数复用**和**延迟执行**。

### 场景一：参数复用
假设有一个发送网络请求的函数，需要 `method`、`url` 和 `data` 三个参数：
```javascript
function request(method, url, data) {
  // 发送请求逻辑
}
```
通过柯里化，我们可以固定 `method` 参数，创建专用的请求函数：
```javascript
const curryRequest = curry(request);
const post = curryRequest('POST');

// 后续调用只需关心 url 和 data，代码更加清爽
post('/api/users', { name: 'Alice' });
post('/api/orders', { id: 101 });
```

### 场景二：延迟执行
假设有一个日志记录函数，需要 `level`、`time` 和 `message`：
```javascript
function log(level, time, message) {
  // 记录日志逻辑
}
```
通过柯里化，我们可以先创建一个专门记录错误日志的函数：
```javascript
const curryLog = curry(log);
const errorLog = curryLog('ERROR'); // 此时不会立即执行

// 在程序的任何地方，等到真正需要记录错误时，再传入剩余参数
errorLog(new Date(), 'Something went wrong!');
```
这种能力在函数式编程和组合函数时特别有用，能创建出非常灵活和强大的代码逻辑。

## 反柯里化 (Uncurrying) 概念解析 *Content-[06:34]

### 定义
如果说柯里化是让函数变得更加“专一”（每次只接收少数参数），那么反柯里化就是**让一个方法变得更加通用**。
它的定义是：**让一个只能被特定对象调用的方法，变得可以接收任何对象作为第一个参数的通用函数**。

### 示例说明
假设有一个对象 `obj`，包含一个依赖 `this.name` 的 `sayHi` 方法：
```javascript
const obj = {
  name: 'John',
  sayHi() {
    console.log(`Hi, I'm ${this.name}`);
  }
};
obj.sayHi(); // 输出: Hi, I'm John
```
这个方法只能被 `obj` 或具有 `name` 属性的对象调用，适用范围很窄。

经过反柯里化（`uncurry`）处理后：
```javascript
const uncurriedSayHi = uncurry(obj.sayHi);

// 此时，this 被解放成了显式的第一个参数
uncurriedSayHi(obj);             // 输出: Hi, I'm John
uncurriedSayHi({ name: 'Jane' }); // 输出: Hi, I'm Jane
```

### 核心思想与应用
反柯里化的核心是**扩大方法的适用范围（泛型化）**，让对象的专属方法能为所有类似对象服务。
最经典的例子是**借用数组方法**：
```javascript
// 传统写法
Array.prototype.push.call(arrayLikeObj, 1, 2, 3);

// 反柯里化写法
const push = uncurry(Array.prototype.push);
push(arrayLikeObj, 1, 2, 3); // 语义更加清晰
```

## 反柯里化手写实现 *Content-[08:40]

反柯里化的实现比柯里化简单得多。核心思路是：**通过闭包把目标函数的 `this` 抽出来，变成新函数的第一个参数**。

### 代码实现
```javascript
function uncurry(fn) {
  return function (context, ...args) {
    // 将传入的 context 作为 this 绑定到原函数上，并执行
    return fn.call(context, ...args);
  };
}
```

### 使用示例
将 `Array.prototype.push` 反柯里化后，得到一个通用的 `push` 函数：
```javascript
const push = uncurry(Array.prototype.push);

// 创建一个类数组对象
const arrayLikeObj = { length: 0 };

// 直接调用，将 arrayLikeObj 作为 this (context) 传入
push(arrayLikeObj, 1, 2, 3); 

console.log(arrayLikeObj); 
// 输出: { '0': 1, '1': 2, '2': 3, length: 3 }
```
通过一行代码，巧妙地将隐式上下文变成了显式参数。

## 柯里化与反柯里化总结对比 *Content-[10:09]

将两者放在一起对比，可以更深刻地理解函数式编程的精髓：

| 特性 | 柯里化 (Currying) | 反柯里化 (Uncurrying) |
| :--- | :--- | :--- |
| **操作方向** | **收缩** | **扩张** |
| **转换过程** | 多参数函数 -> 一系列单参数函数链 | 对象专属方法 -> 接收任何对象的通用函数 |
| **核心目的** | 参数复用、延迟执行 | 扩大方法的适用范围（泛型化） |
| **`this` 处理** | 保持原有的 `this` 指向 | 将 `this` 提取为显式的第一个参数 |
| **典型示例** | `curryAdd(1)(2)(3)` | `uncurry(obj.method)(newObj)` |

### 满分回答模板
当面试官问及此题时，可以按照以下逻辑给出满分答案：
1. **阐述柯里化**：把多参数函数转变成单参数函数链式调用的过程，核心价值在于**参数复用**和**延迟执行**，可用于创建预设部分参数的具体函数（如封装 POST 请求）。
2. **阐述反柯里化**：与柯里化相反，把对象专属方法变成接收上下文作为第一个参数的通用函数，核心价值在于**扩大适用范围**，实现方法的**泛型化**，方便借用其他对象的方法（如借用 `Array.prototype.push`）。
3. **总结共性**：虽然两者操作方向不同（一收缩一扩张），但最终目标完全一致，都是为了**提高代码的复用性和灵活性**。

## AI 总结

本视频详细拆解了前端面试中的高频手写题——**柯里化（Currying）** 与**反柯里化（Uncurrying）**。
- **柯里化**是一种“收缩”操作，通过将多参数函数转化为单参数函数链，实现**参数复用**与**延迟执行**，极大提升了代码的灵活性和复用率。
- **反柯里化**则是一种“扩张”操作，通过提取 `this` 上下文作为显式参数，将特定对象的专属方法转化为通用函数，实现方法的**泛型化**，常用于优雅地借用原生方法（如数组方法）。
两者方向相反，但殊途同归，最终目的均是为了提升代码质量，是掌握函数式编程思想的重要基石。掌握其概念、手写实现及边界处理，是应对大厂前端面试的关键。
