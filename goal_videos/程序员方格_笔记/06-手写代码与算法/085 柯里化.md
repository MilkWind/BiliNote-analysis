## 1. 柯里化 (Currying) 的核心概念 *Content-[00:09]

在 JavaScript 函数式编程中，有两种操作是必不可少的：**柯里化 (Currying)** 和 **函数组合 (Function Composition)**。
- **柯里化**：可以比喻为流水线上的“加工站”。
- **函数组合**：可以理解为“流水线”本身，它由多个加工站（柯里化函数）组合而成。

**柯里化的核心定义**：
柯里化是指将一个接收多个参数的**多元函数**，转换成依次调用的**一元函数**链的过程。
用数学表达式可以表示为：$f(a, b, c) \rightarrow f(a)(b)(c)$。

**执行机制**：
- 可以一次性调用柯里化后的函数，也可以每次只传入一个参数，分多次进行调用。
- 函数接收第一个参数后，会返回一个接收第二个参数的新函数。
- 该新函数接收第二个参数后，再返回一个接收第三个参数的函数。
- 依次类推，直到最后一个函数接收完所有参数，会将之前收集到的所有参数应用到原始的普通函数中，并返回最终的计算结果。

## 2. 柯里化函数的调用示例 *Content-[02:19]

通过一个具体的加法函数 `sum` 来演示柯里化的调用过程：

1. **定义普通函数**：
   定义一个接收三个参数 `a, b, c` 的普通加法函数 `sum(a, b, c)`。

2. **转化为柯里化函数**：
   使用一个名为 `curry` 的工具函数，将普通的 `sum` 函数转化为柯里化版本。

3. **分步调用演示**：
   - 第一次调用：`const sum1 = sum(1)`。此时传入第一个参数 `1`，`sum1` 成为一个接收第二个参数的新函数。
   - 第二次调用：`const sum2 = sum1(2)`。传入第二个参数 `2`，`sum2` 成为一个接收第三个参数的新函数。
   - 第三次调用：`const result = sum2(3)`。传入最后一个参数 `3`，此时所有参数收集完毕，触发原函数执行，返回最终的加法结果。

通过这种方式，原本需要一次性传入三个参数的多元函数，被优雅地转换成了依次接收参数的一元函数链。

## 3. 柯里化函数的核心逻辑总结 *Content-[03:57]

柯里化函数的执行逻辑可以总结为以下两个核心判断条件：

- **参数数量 = 原函数形参数量**：
  当接收到的参数总数量与原函数的形参数量相同时，说明参数已收集完毕，此时直接**执行原函数**并返回结果。

- **参数数量 < 原函数形参数量**：
  当接收到的参数总数量小于原函数的形参数量时，说明参数尚未收集完毕。此时需要**返回一个新的函数**，该函数用于继续接收剩余的参数，直到参数数量满足条件为止。

## 4. 手动实现柯里化 (Curry) 工具函数 *Content-[05:14]

如果要手动实现一个 `curry` 工具函数，其核心逻辑如下：

1. **函数签名**：
   - 入参：接收一个原始函数 `fn`。
   - 返回值：返回一个新的函数。

2. **内部逻辑处理**：
   返回的新函数接收不定项参数（记为 `x`，可能是一个或多个参数）。
   - **判断参数长度**：检查当前传入参数 `x` 的长度（`x.length`）是否**大于等于**原函数形参的长度（`fn.length`）。
   - **满足条件（大于等于）**：
     说明参数已经收集完毕。此时通过 `apply` 的方式（`fn.apply(null, x)`）执行原函数，并返回执行结果。
   - **不满足条件（小于）**：
     说明参数还未收集完。此时需要返回一个新的函数，该新函数接收剩余的参数（记为 `ox`）。
     将之前收集的参数 `x` 与新传入的参数 `ox` 进行拼接合并，然后**递归调用** `curry` 函数，继续处理合并后的参数，直到参数收集完毕。

## 5. 柯里化函数的特点与应用场景 *Content-[08:31]

柯里化 (Currying) 在函数式编程中具有以下显著特点和核心应用场景：

- **参数复用**：
  可以提前传入部分参数，从而得到一个新的、已经绑定了部分参数的函数。这个新函数可以在不同的场景中方便地复用，减少重复代码。

- **延迟执行**：
  柯里化函数不会立即执行原逻辑，而是会持续返回新函数，直到所有的参数收集完毕后，才会真正执行原函数。这种特性非常适合处理需要等待多个条件或参数就绪的场景。

- **便于函数组合**：
  柯里化是函数式编程的基石之一，它使得函数能够更灵活地进行组合 (Compose) 和管道 (Pipe) 操作，极大地提升了代码的可读性和可维护性。
