## 什么是 LRU 缓存 *Content-[00:29]
- **全称与概念**：LRU 全称为 Least Recently Used（最近最少使用）。其核心思想非常符合直觉：如果缓存满了需要删除数据，应该删除最久没有被使用过的数据。基于“如果一个数据很久没有被用过，将来被用到的可能性也很小”的假设。
- **应用场景**：这种淘汰策略在计算机世界中无处不在，例如：
  - 浏览器中的图片缓存
  - 操作系统或手机的内存管理
  - Redis 的内存淘汰机制
  - 数据库的查询缓存

## 核心需求与数据结构选择 *Content-[01:25]
- **核心需求**：面试官通常要求实现 `get`（查询数据）和 `put`（插入或更新数据）两个核心操作，且它们的时间复杂度必须严格为 $O(1)$。这意味着无论缓存中有多少数据，操作都必须在常数时间内完成。
- **数据结构分析**：
  - **哈希表 (Map)**：在 JavaScript 中即 `Map`。优点是增、删、查都是 $O(1)$，完美符合快速 `get` 数据的需求。致命缺点是**无序**，无法维护使用顺序，因此无法知道应该淘汰谁。
  - **双向链表**：天生用于维护顺序。在队头添加元素或删除队尾元素的操作是 $O(1)$（因为能快速拿到队头和队尾）。缺点是**查找慢**，查找中间元素需要从头遍历，时间复杂度为 $O(n)$。
- **组合方案（强强联合）**：
  - 通过 Map 存放 `key` 和链表节点的映射关系。
  - 当需要 `get key` 时，先通过 Map 在 $O(1)$ 时间内找到对应的链表节点。
  - 使用双向链表维护所有节点的时间新鲜度。被访问过的节点通过链表操作移动到链表头部；缓存满时，删除尾部节点。
  - Map 负责快速定位，链表负责灵活排序，两者结合完美实现 $O(1)$ 复杂度。

## 核心操作流程梳理 *Content-[04:58]
- **定义**：将链表头部定义为“最近使用端”，尾部定义为“最久未使用端”。
- **访问数据流程 (`get` / `put`)**：
  - 先通过 Map 查询数据是否在缓存中。
  - **如果命中（数据存在）**：将数据从链表当前位置移动到链表头部（标记为最新鲜），然后返回数据。
  - **如果未命中（数据不存在）**：
    - 若缓存已满，需删除链表最尾部的节点（最久未访问），**同时必须从 Map 中删除对应的 `key`**。
    - 创建新节点，插入到链表头部，并在 Map 中建立 `key` 到新节点的映射。
- **操作总结**：`get` 命中的核心是“移动到头部”；`put` 新数据的核心是“插入到头部”，若容量满则“先删除尾部节点”。

## 代码结构设计 *Content-[06:42]
- **双向链表节点 (ListNode) 设计**：
  - 包含 `key`、`value`、`prev`（前驱指针）、`next`（后继指针）。
  - **关键细节**：节点中必须额外存储 `key`。因为当缓存满了删除尾部节点时，需要通过该节点的 `key` 去 Map 中 $O(1)$ 删除对应的映射，防止内存泄漏和 Map `size` 不准确。
- **LRU 缓存类 (LRUCache) 骨架**：
  - `capacity`：缓存最大容量，初始化时传入。
  - `cache`：Map 结构，存储 `key` 到 `ListNode` 的映射。
  - `head` 和 `tail`：双向链表的哨兵节点（虚拟节点）。
- **哨兵节点 (Dummy Node) 的妙用**：
  - `head` 和 `tail` 本身不存储任何有效数据。初始化时 `head.next` 指向 `tail`，`tail.prev` 指向 `head`，形成基础空链表。
  - 所有真实数据节点都插入在 `head` 和 `tail` 之间。
  - **核心作用**：消灭链表操作中的边界条件判断（如链表为空、删除头/尾节点等）。保证任何真实节点的 `prev` 和 `next` 永远不是 `null`，使后续的插入和删除代码极其简洁优雅。

## 原子操作封装 *Content-[10:39]
- **`removeNode(node)`**：从链表中删除指定节点。
  - 让前置节点跨过当前节点直接指向下一个节点，同时让下一个节点的前指针指向前置节点。
  - 得益于虚拟节点，无需做任何 `null` 判断，代码非常清爽。
- **`addToHead(node)`**：将节点插入到 `head` 和原第一个真实节点之间。
  - **注意操作顺序**：先确定新节点的左右关系（`prev` 和 `next`），再修改原第一个节点和 `head` 指向新节点的关系，防止指针丢失。
- **`moveToHead(node)`**：将节点移动到头部。
  - 逻辑：先调用 `removeNode` 删除该节点，再调用 `addToHead` 将其添加到头部。这是 `get` 方法命中的核心操作。
- **`removeTail()`**：删除尾节点（最老的数据）。
  - 找到最靠近虚拟尾节点的节点（`this.tail.prev`）。
  - 调用 `removeNode` 将其删除。
  - **关键细节**：必须将该被删除的节点 `return` 回去，以便调用方获取其 `key` 并在 Map 中联动删除。

## 实现 get 和 put 方法 *Content-[15:45]
- **`get(key)` 方法实现**：
  1\. 检查 `key` 是否存在于 Map 中（`this.cache.has(key)`）。若不存在，返回 `-1`。
  2\. 若存在，通过 Map 获取对应的链表节点 `node`。
  3\. 调用 `moveToHead(node)` 将其标记为最近使用。
  4\. 返回 `node.value`。
  - 全程每一步都是 $O(1)$ 操作，完美满足面试要求。
- **`put(key, value)` 方法实现**：
  - **情况一：`key` 已存在**。
    1\. 从 Map 获取旧节点，更新其 `value`。
    2\. 调用 `moveToHead(node)` 将其移动到头部。
  - **情况二：`key` 不存在**。
    1\. 创建新的 `ListNode`（传入 `key` 和 `value`）。
    2\. 将新节点加入 Map，并调用 `addToHead(node)` 插入链表头部。
    3\. **检查容量**：如果 Map 的 `size` 超过 `capacity`，调用 `removeTail()` 获取被删除的尾部节点。
    4\. 通过返回的尾部节点获取 `key`，从 Map 中 `delete` 对应的条目，完成联动删除。
  - 无论走到哪个分支，所有操作都是常数时间复杂度 $O(1)$。

## 面试扩展问题 *Content-[19:46]
- **LFU 缓存 (Least Frequently Used)**：
  - **区别**：LRU 淘汰最久未使用的，而 LFU 淘汰访问次数最少的（如果访问次数一样，再按 LRU 规则淘汰）。
  - **实现**：更加复杂，通常需要两个哈希表和一个双向链表来维护频率和顺序。
- **带过期时间的 LRU**：
  - **需求**：让缓存项具有生命周期（如只能活 5 分钟）。
  - **实现**：在链表节点中增加一个过期时间字段。在 `get` 的时候先检查是否过期，过期则删除。
  - **进阶**：可能还需要一个后台扫描任务，定期清理那些一直不被访问但已经过期的“僵尸数据”。

## 面试总结与要点回顾 *Content-[20:55]
- **数据结构选择**：必须讲清楚单独使用 Map 或双向链表的局限性，以及组合使用实现 $O(1)$ 的原理。
- **关键操作**：精准写出原子方法（`removeNode`, `addToHead` 等），这是 LRU 缓存的核心。
- **边界处理**：使用虚拟头尾节点简化操作是代码亮点；`put` 后检查容量并联动删除 Map 节点体现了代码的严谨性。
- **常见追问准备**：
  - **为什么不用数组/动态数组？** 数组中间插入或删除需要移动大量元素，时间复杂度为 $O(n)$。
  - **为什么不用单链表？** 单链表删除元素必须知道其前驱节点，寻找前驱节点需要重新遍历，时间复杂度为 $O(n)$。双向链表完美解决了这个问题。
