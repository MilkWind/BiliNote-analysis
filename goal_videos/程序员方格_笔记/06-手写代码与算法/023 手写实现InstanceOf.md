## 手写 InstanceOf 核心考点解析 *Content-[00:00]

- **背景**：手写 `instanceof` 是经典的前端面试题，能够有效筛选出对 JS 原型链理解不深或代码考虑不周全的候选人。
- **MDN 定义**：`instanceof` 运算符用于检测构造函数的 `prototype` 属性是否出现在某个实例对象的原型链上。
- **核心考点 1：原型链**
  - `instanceof` 的本质是沿着对象的原型链向上层层查找。
  - 要求候选人清晰理解原型链的形成过程，以及如何用代码遍历它。
- **核心考点 2：边界处理**
  - 健壮的函数必须能处理各种意外情况。
  - 需要处理左侧操作数传入数字、字符串或 `null` 时的异常。
  - 需要处理右侧操作数不是函数时的异常。

## 代码实现：参数校验 *Content-[01:34]

- **函数定义**：定义函数 `myInstanceOf(left, right)`，接收左右两个操作数。
- **左侧操作数 (`left`) 校验**：
  - 规范明确指出：如果左侧操作数不是对象，结果永远返回 `false`。
  - 这包含了所有的基本数据类型（如字符串、数字）以及 `null`。
  - 注意：尽管 `null` 在 JS 中属于对象类型，但在此处也必须返回 `false`。
- **右侧操作数 (`right`) 校验**：
  - 右侧必须是一个构造函数，即其类型必须为 `function`。
  - 如果不是函数（例如传入了对象字面量），V8 引擎会直接抛出 `TypeError`。
  - 在代码中需要模拟这一行为，判断右侧类型若非函数则主动抛出 `TypeError`。

## 代码实现：遍历原型链 *Content-[02:58]

- **获取目标原型**：首先获取右侧构造函数的原型对象 `right.prototype`，并将其存入一个变量中。
- **遍历原型链**：
  - 使用标准方法 `Object.getPrototypeOf(left)` 获取左操作数的直接原型（不推荐使用非标准的 `__proto__`）。
  - 使用 `while (true)` 循环，不断向上查找。
- **循环内的三个判断逻辑**：
  1. **终止条件 1**：如果 `left === null`，说明已到达原型链终点且未找到匹配项，直接返回 `false`。
  2. **匹配成功**：如果 `left === prototype`（即当前查找的原型等于右侧构造函数的原型），说明找到了匹配项，直接返回 `true`。
  3. **继续向上查找**：若以上两个条件均不满足，则更新 `left = Object.getPrototypeOf(left)`，将其指向上一级原型，进入下一次循环。

## 进阶探讨：跨 iframe 问题与解决方案 *Content-[04:55]

- **`instanceof` 的著名缺陷**：在处理跨窗口或跨 `iframe` 的对象时，`instanceof` 的类型判断会失效。
- **失效原因**：
  - JavaScript 中每个 `iframe` 都有自己独立的作用域。
  - 它们包含独立的 `window` 对象以及 `Array` 等原生构造函数。
  - 主页面的 `Array` 和 `iframe` 里的 `Array` 是两个完全不同的函数对象，存在于不同的内存地址。
  - 因此，当使用主页面的构造函数去判断由 `iframe` 中的构造函数创建的实例时，由于两者的原型对象根本不是同一个对象，`instanceof` 会返回 `false`。
- **标准解决方案**：
  - 使用 `Object.prototype.toString.call()` 方法。
  - 这是一个非常标准的类型检测方法，能够返回表示对象类型的内部字符串（例如判断数组会返回 `[object Array]`）。
  - 在处理可能来自不同 `iframe` 的对象时，使用该方法比 `instanceof` 更加可靠。
