## 1. 面试题目解析与常见误区 *Content-[00:00]

- **面试题目**：手写 `Promise.all` 和 `Promise.allSettled`。
- **考察核心**：不仅考察对 Promise API 的熟悉程度，更深层次考察对**异步并发控制**的理解。如果答不好，面试很容易挂掉。
- **典型错误写法及三个致命问题**：
  - 很多候选人的第一反应是创建一个 Promise，遍历输入的 Promise 数组，获取结果后 `push` 到 `result` 数组中，最后 `resolve(result)`。这种写法存在三个致命缺陷：
  - **顺序错乱**：`Promise.all` 要求返回结果的顺序必须与输入数组一致。由于 Promise 是异步的，完成时间不确定，使用 `push` 会导致“谁先完成谁先进入结果数组”，从而打乱顺序。
  - **时机错误**：使用 `forEach` 循环时，循环一走完就会立即执行 `resolve`。但此时内部的 Promise 可能一个都还没有执行完毕，导致 `resolve` 出去的是一个空数组。
  - **异常丢失**：代码中只写了 `.then` 的成功回调，如果任何一个 Promise 失败，整个逻辑就会崩塌，异常被吞掉，外部完全感知不到。

## 2. 核心难点分析 *Content-[01:56]

这道题背后考察的是两个核心的异步编程难点：
- **并发控制下的顺序性**：`Promise.all` 的本质是并发执行一组异步任务，但要求对结果有确定的掌控，即结果必须按原始顺序排列。“并发”和“顺序”是一对矛盾，需要通过代码设计来解决。
- **完成时机的判断**：必须有一个机制，能够在最后一个 Promise 执行完毕的精准时刻去 `resolve` 最终结果，不能早也不能晚。

## 3. 手写 Promise.all 的正确实现 *Content-[02:42]

理解了上述难点后，可以通过以下步骤写出正确的代码：

- **解决顺序问题（利用索引）**：
  - 放弃使用 `push`，改为在遍历时利用 `forEach` 提供的**索引 (index)**。
  - 预先创建一个空的结果数组 `result`。在每个 Promise 完成时，根据其在原始数组中的索引，将结果放到 `result` 数组的对应位置上（即 `result[index] = value`）。
  - 这样无论哪个 Promise 先完成，结果都会被放在正确的位置，完美保证顺序。
  - **编程好习惯**：使用 `Promise.resolve()` 包装传入的值（`item`），以兼容传入的不是 Promise 实例的普通值。

- **解决完成时机问题（利用计数器）**：
  - 引入一个**计数器 (count)** 进行控制。
  - 在最外层定义计数器，初始值为 0。
  - 在每个 Promise 成功的回调中，将结果放入 `result` 数组后，让计数器加 1（`count++`）。
  - **关键判断**：如果计数器等于结果数组的长度（即 `count === promises.length`），表示所有任务都已完成。只有在这个时候，才执行 `resolve(result)`。通过计数器精确捕捉所有 Promise 完成的时刻。

## 4. 边界条件与异常处理 *Content-[04:45]

一个功能完整、逻辑严谨的代码必须处理边界情况，这也是面试官一定会追问的点：

- **空数组处理**：
  - 根据 Promise A+ 规范，如果给 `Promise.all` 传入一个空数组，应该立即同步返回一个已完成的 Promise，其值为空数组。
  - **实现**：在代码开头增加判断，如果 `promises.length === 0`，直接 `resolve([])`。
- **异常处理（快速失败机制）**：
  - `Promise.all` 的规则是：只要有一个 Promise 失败，整个 `Promise.all` 就立即失败。
  - **实现**：在 `.then` 方法中加入第二个参数（失败回调）。一旦任意一个 Promise 进入该回调，直接 `reject(reason)`，将失败原因传递出去。

## 5. 手写 Promise.allSettled 的实现 *Content-[05:51]

搞定 `Promise.all` 后，面试官通常会接着问两者的区别，并要求手写 `Promise.allSettled`。

- **核心区别**：
  - `Promise.all`：一个失败，整体立即失败。
  - `Promise.allSettled`：不管内部的 Promise 是成功还是失败，都会耐心等待所有任务执行完毕，**永远不会直接失败**。
  - **返回格式**：最终 `resolve` 出去的是一个包含每个 Promise 结果的对象数组。成功时格式为 `{ status: 'fulfilled', value: value }`，失败时格式为 `{ status: 'rejected', reason: reason }`。

- **实现思路**：
  - 整体框架与 `Promise.all` 几乎一模一样，同样使用**索引**保证顺序，使用**计数器**控制时机。
  - **成功回调修改**：不直接存 `value`，而是存对象 `{ status: 'fulfilled', value: value }`。
  - **失败回调修改**：不直接 `reject` 整个 Promise，而是在结果数组中记录状态，将 `status` 改为 `'rejected'`，并记录失败原因 `{ status: 'rejected', reason: reason }`。同时计数器加 1。
  - `Promise.allSettled` 本身永远不会被 `reject`，它把成功和失败都作为一种状态收集起来，最后统一交给调用者处理。

## 6. 面试满分答案核心总结 *Content-[07:46]

想要在面试中给出满分答案，必须牢记以下三个核心点：
1. **索引赋值**：使用数组的索引进行赋值，绝对不能用 `push`，以保证结果顺序与输入一致。
2. **计数器控制**：使用计数器来精确判断所有异步任务完成的时机，确保 `resolve` 的准确性。
3. **异常处理策略**：清晰理解 `all` 和 `allSettled` 在面对失败时的不同策略。`all` 是快速失败（一个报错整体报错），而 `allSettled` 是全部等待完毕之后再返回最终的结果。

明白这三点，不仅能写出完美的代码，更能向面试官证明你对异步并发控制有非常深刻的理解。
