## 1. 发布订阅模式简介与日常使用 *Content-[00:00]

- **重要性**：发布订阅模式（Publish-Subscribe Pattern）在前端领域应用极其广泛，许多主流框架以及日常业务代码中都会频繁使用。因此，它是前端面试中非常高频且核心的考察概念。
- **日常使用方式**：
  - 在实际工作中，我们通常通过 `EventEmitter`（事件发射器）来使用该模式。
  - **订阅事件**：通过 `on` 方法监听特定事件，并绑定相应的回调函数。可以针对同一个事件订阅多个不同的回调（例如针对不同用户触发不同的响应）。
  - **发布事件**：通过 `emit` 方法触发事件，并向回调函数传递相关的参数或信息。

## 2. 核心概念：发布者、订阅者与事件通道 *Content-[00:46]

- **设计模式特点**：发布订阅模式是一种常规的软件设计模式，其核心特点是允许对象之间进行**松散的耦合通信**，从而有效减少模块或对象之间的直接依赖。
- **三大核心组成部分**：
  1. **发布者（Publisher）**：负责产生和发布消息。发布者可以有多个，且不会直接调用订阅者。
  2. **订阅者（Subscriber）**：负责接收和处理消息。订阅者通过注册监听来对特定消息做出响应。
  3. **事件通道 / 事件中心（Event Channel）**：发布者和订阅者之间不存在直接调用关系，而是通过“事件通道”进行通信。发布者将消息发布到通道，订阅者从通道监听并获取消息。

## 3. 手写实现思路与核心功能 *Content-[02:27]

- **面试技巧**：在手写代码前，建议先向面试官清晰地阐述自己的设计思路。通过层层分析，不仅能展现清晰的逻辑思维能力，还能在交流中激发灵感，完善代码实现。
- **核心功能设计**：
  1. **事件中心（Event Center）**：需要一个数据结构（如对象或 Map）来作为总控，用于存储事件名称及其对应的回调函数数组。
  2. **`on` 方法（订阅）**：用于订阅某个特定事件，并将对应的回调函数（Listener）注册到事件中心。
  3. **`emit` 方法（发布）**：用于发布某个事件，触发并调用事件中心里所有订阅了该事件的回调函数。
  4. **`off` 方法（取消订阅）**：用于解除对某个事件的订阅，将对应的回调函数从事件中心移除，避免内存泄漏或重复执行。

## 4. JavaScript 代码实现细节 *Content-[06:59]

- **定义 `EventEmitter` 对象**：
  - 在对象内部定义一个属性（如 `events` 或 `listeners`）作为事件中心，用于存储事件和回调。
- **实现 `on(event, listener)` 方法**：
  - 接收事件名 `event` 和回调函数 `listener` 作为参数。
  - 判断当前 `event` 是否已经在 `events` 中注册。
  - 如果未注册，则为其初始化一个空数组。
  - 如果已注册，则直接将当前的 `listener` `push` 到对应的数组中，实现批量存储。
- **实现 `emit(event, ...args)` 方法**：
  - 接收事件名 `event` 和需要传递的参数 `...args`。
  - 首先判断该事件在事件中心是否存在。如果不存在，则直接 `return` 忽略。
  - 如果存在，则通过 `forEach` 遍历该事件对应的回调函数数组，依次执行 `listener`，并将传入的参数 `...args` 传递给回调函数。
- **实现 `off(event, listener)` 方法**：
  - 接收事件名 `event` 和需要移除的回调函数 `listener`。
  - 判断该事件是否存在，不存在则直接 `return`。
  - 如果存在，则使用数组的 `filter` 方法，过滤掉与传入 `listener` 相同的回调函数，从而完成取消订阅的操作。下次 `emit` 时，被过滤的回调将不再被执行。

## 5. 实际使用示例与总结 *Content-[10:17]

- **使用流程演示**：
  1. 定义多个回调函数（如 `user1`, `user2`）。
  2. 实例化 `EventEmitter`，使用 `on` 方法监听特定的事件（如 `message`），并绑定上述回调。
  3. 使用 `emit` 方法触发 `message` 事件，并传入参数（如 `hello world`），此时所有订阅者都会接收到消息并执行。
  4. 使用 `off` 方法取消某个特定回调的订阅，后续再次 `emit` 时，该回调将不再被触发。
- **总结**：使用 JavaScript 实现发布订阅模式整体逻辑较为清晰简单，核心在于维护好“事件与回调”的映射关系，并妥善处理订阅、发布和取消订阅的边界条件。
