## call 与 apply 的核心作用 *Content-[00:01]

在面试中手写 `call` 和 `apply` 之前，首先需要清晰地向面试官阐述它们的核心作用，做到“先总后分，有理有据”。

**核心作用**：
`call` 和 `apply` 的本质作用是**改变函数执行时的 `this` 指向**，并在指定的 `this` 值和若干个指定的参数值前提下，调用某个函数或方法。

**案例说明**：
- 假设有对象 `foo`，其中包含属性 `name`。
- 另有函数 `bar`，其内部执行 `console.log(this.name)`。
- 如果直接调用 `bar()`，由于全局或 `bar` 内部没有 `name` 属性，会返回 `undefined`。
- 如果使用 `bar.call(foo)` 进行调用，`bar` 函数内部的 `this` 就会被强制指向 `foo` 对象，从而成功打印出 `foo.name` 的值。

**面试回答技巧**：
不要一上来就罗列代码步骤。应先总述 `call` 和 `apply` 改变 `this` 指向的作用，接着通过具体例子拆解背后的运行机制，最后再引出如何一步步手写实现。

## 手写 call 的基础思路与实现 *Content-[04:47]

在理清了底层机制后，可以将手写 `call` 的过程拆解为三个核心步骤：

**思路拆解**：
**第一步**：将目标函数变为指定 `context`（即传入的 `this` 对象）的一个属性。
**第二步**：执行该函数（此时函数内的 `this` 自然指向 `context`）。
**第三步**：执行完毕后，删除该临时添加的属性，避免污染原对象。

**伪代码示例**：
```javascript
context.fn = this;      // 1. 将函数设为 context 的属性
context.fn();           // 2. 执行函数
delete context.fn;      // 3. 删除临时属性
```

**初步代码实现 (`call2`)**：
- 在 `Function.prototype` 上扩展 `call2` 方法。
- 明确变量指向：
  - `context`：传入的第一个参数（即指定的 `this` 对象）。
  - `this`：谁调用 `call2`，`this` 就指向谁（即原函数本身，如 `bar`）。

```javascript
Function.prototype.call2 = function(context) {
    context.fn = this;
    context.fn();
    delete context.fn;
}
```

## 完善手写 call 的边界条件与细节 *Content-[09:43]

初步实现仅完成了基本功能，在面试中需要展示代码的严谨性，处理以下边界条件和细节，这也是脱颖而出的亮点所在：

**1. 支持参数传递**
- 原生 `call` 支持传入多个参数。
- **实现**：通过 `arguments` 对象获取除 `context` 外的所有参数。使用 `Array.prototype.slice.call(arguments, 1)` 截取参数，并在执行函数时传入。

**2. 处理 `context` 为 `null` 或 `undefined` 的情况**
- 原生 `call` 在不传 `this` 或传 `null`/`undefined` 时，默认指向全局对象。
- **实现**：判断 `context` 是否存在。若不存在，则进行环境兼容：浏览器环境下指向 `window`，Node 环境下指向 `global`。

**3. 支持函数返回值**
- 原生 `call` 会返回原函数的执行结果。
- **实现**：使用变量接收 `context.fn(...args)` 的执行结果，并在方法最后 `return` 该结果。

**4. 防止属性名冲突（核心亮点）**
- 如果 `context` 对象本身已有 `fn` 属性，直接赋值会覆盖原属性，导致数据丢失。
- **实现**：使用 ES6 的 `Symbol` 作为唯一的属性键名，确保不会与原有属性冲突。
- **向下兼容**：如果当前环境不支持 `Symbol`，则生成随机字符串作为键名，同样保证唯一性。

**完整实现参考**：
```javascript
Function.prototype.call2 = function(context) {
    // 1. 处理 context 为 null/undefined 的情况，兼容不同环境
    context = context || (typeof window !== 'undefined' ? window : global);
    
    // 2. 防止属性名冲突，优先使用 Symbol，不支持则使用随机字符串
    let fnKey;
    if (typeof Symbol !== 'undefined') {
        fnKey = Symbol('fn');
    } else {
        fnKey = 'fn_' + Math.random().toString(36).slice(2);
    }
    
    // 3. 将函数设为 context 的属性
    context[fnKey] = this;
    
    // 4. 获取除 context 外的其他参数并执行函数，接收返回值
    let args = [...arguments].slice(1);
    let result = context[fnKey](...args);
    
    // 5. 删除临时属性
    delete context[fnKey];
    
    // 6. 返回执行结果
    return result;
}
```

## call 与 apply 的核心区别 *Content-[20:34]

`call` 和 `apply` 在改变 `this` 指向和核心执行逻辑上是完全一致的，它们本质的区别仅在于**参数传递的格式**：

- **`call`**：参数逐个传递（枚举方式），如 `fn.call(context, arg1, arg2)`。
- **`apply`**：接收一个数组作为参数集合，如 `fn.apply(context, [arg1, arg2])`。

在面试中，只要彻底掌握了 `call` 的手写逻辑，只需在参数处理环节将“逐个传参”改为“数组展开传参”，即可轻松实现 `apply` 的手写。
