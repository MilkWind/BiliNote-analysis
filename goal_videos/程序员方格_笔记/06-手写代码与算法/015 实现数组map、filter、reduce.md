## 手写 map 方法的三大核心细节 *Content-[00:00]

手写数组的 `map`、`filter`、`reduce` 方法是前端面试中的超高频场景题。以 `map` 为例，看似只需要一个简单的 `for` 循环遍历并将结果放入新数组即可，但如果只回答基础逻辑，往往会忽略三个致命细节，导致面试失分：

- **稀疏数组（Sparse Array）的处理**：
  例如数组 `[1, , 3]` 中间存在空位，它不是 `undefined`，而是真正的空位。原生 `map` 会智能地跳过这些空位，但如果使用普通的 `for` 循环，会将其当作 `undefined` 处理，导致与原生行为不一致。
- **`this` 绑定的问题**：
  `map` 方法可以接收第二个参数 `thisArg`，用于指定回调函数执行时内部的 `this` 指向。如果仅仅是简单调用回调函数，`this` 的指向就会发生错误。
- **边界处理**：
  编写健壮的代码必须考虑边界情况。例如，调用 `map` 时传入的是 `null` 或 `undefined`，或者传入的 `callback` 不是一个函数。严格的校验能体现编码的严谨性。

## 手写 map 方法的满分实现 *Content-[01:34]

在明确上述三个坑之后，可以按照以下步骤编写满分的 `map` 实现：

- **第一步：边界检查**
  确保调用者（`this`）不是 `null` 或 `undefined`，并且传入的 `callback` 必须是一个函数，这与原生 `map` 的行为保持一致。
- **第二步：准备工作**
  使用 `Object(this)` 将调用者转换为对象，以兼容类数组对象。同时，使用无符号右移操作符（`>>> 0`）快速、安全地将 `length` 属性转换为非负整数，这是 ES 规范中的标准地道操作。
- **第三步：创建结果数组**
  `new` 一个与原数组等长的新数组。注意，`map` 从不修改原数组，而是返回一个新数组。
- **第四步：核心循环与稀疏数组处理**
  使用 `for` 循环遍历，**关键点**在于使用 `in` 操作符（`k in O`）来判断索引 `k` 是否是对象真实存在的属性。
  - 如果是空位，`in` 返回 `false`，直接跳过。
  - 如果索引存在，则使用 `call` 方法将之前存储的 `thisArg` 绑定为回调函数里的 `this`。
  - 传入三个标准参数：当前值（`value`）、当前索引（`index`）、原数组（`array`）。
  - 将回调函数的返回值赋值给新数组的对应位置。
- **第五步：返回结果**
  循环结束后，`return` 新数组。

**易错点对比**：
如果不使用 `in` 操作符，循环到空位时获取到的值是 `undefined`，会导致 `undefined` 被错误地映射到新数组中。使用 `in` 操作符判断数组项不存在并跳过，才能保持新数组的稀疏特性，与原生表现完全一致。

## 手写 reduce 方法的核心难点 *Content-[04:01]

`reduce` 的实现比 `map` 更复杂，其核心难点在于对初始值（`initialValue`）的处理。前几行的边界检查和准备工作与 `map` 相同，接下来的精髓在于确定累加器（`accumulator`）的初始值：

- **判断是否传入初始值**：
  通过 `arguments.length` 进行判断。如果参数个数 `>= 2`，说明传入了 `initialValue`；如果 `< 2`，说明未传入。
- **情况一：传入了初始值**
  直接将 `initialValue` 赋值给累加器。
- **情况二：未传入初始值**
  需要从数组中找到第一个真实存在的元素作为初始值。使用 `while` 循环配合 `in` 操作符，直到找到一个存在的索引 `k`。
  - **边界情况**：如果数组为空且未传初始值，`reduce` 必须直接抛出错误（`TypeError`）。
  - 找到元素后，将其作为初始值，并将索引 `k` 加 1，因为下一次循环要从下一个元素开始。
- **主循环**：
  从索引 `k` 开始遍历，依然使用 `in` 操作符跳过稀疏元素。通过不断调用 `callback` 来更新累加器的值，直到循环结束并返回最终结果。

**两种情况直观对比（以数组 `[1, 2, 3]` 为例）**：
- **提供初始值 `0`**：累加器初始为 `0`，从索引 `0` 开始遍历。累加过程为：$0+1=1$，$1+2=3$，$3+3=6$。
- **未提供初始值**：累加器初始为 `1`（第一个元素），从索引 `1` 开始遍历。累加过程为：$1+2=3$，$3+3=6$。
虽然最终结果相同，但起点和遍历次数完全不同，这是 `reduce` 的核心知识点。

## 手写 filter 方法的实现逻辑 *Content-[06:59]

`filter` 的逻辑本质上是 `map` 的一个变种，实现相对简单：

- **准备工作**：
  边界检查与模板化代码同 `map` 一致（转换数组、获取长度）。
- **创建结果数组**：
  将结果数组初始化为空数组 `[]`。因为不知道最后有多少个元素会被保留，不能预设长度，只能使用 `push` 方法。
- **核心循环**：
  同样使用 `in` 操作符处理稀疏数组。拿到 `value` 后，通过 `call` 方法绑定 `this` 并执行回调。
  - **关键判断**：如果 `callback` 执行结果为 `true`，则将 `value` `push` 到结果数组中；如果为 `false`，则什么都不做。
- **返回结果**：
  循环结束后，返回只包含通过测试的元素的结果数组。

掌握 `map` 中的稀疏数组处理和 `this` 绑定后，编写 `filter` 便是小菜一碟。

## 进阶优化：链式调用的性能隐患与解决方案 *Content-[08:10]

手写的 `map`、`filter`、`reduce` 都会返回新数组，因此可以像原生方法一样进行链式调用（如 `arr.map().filter().reduce()`）。但在面试中，指出其性能隐患并提供优化思路是极大的加分项：

- **性能隐患**：
  每一次调用（如 `map`）都会创建并返回一个全新的中间数组，`filter` 又会在此基础上再创建一个新数组。如果数据量非常大，中间数组的创建和内存分配开销将非常显著。
- **优化思路**：
  - **惰性求值（Lazy Evaluation）**：先不计算，将所有操作存起来，直到真正需要结果时再一次性执行。像 `RxJS` 这样的响应式编程库就是采用此思路。
  - **Transducer 模式**：函数式编程中的一种高阶组合技巧。它可以将 `map`、`filter` 等操作组合成一个单一的函数，从而实现只遍历一次数组就完成所有操作，彻底消除中间数组的开销。

## 面试核心考察点总结 *Content-[09:33]

面试官考察手写数组方法，重点并非测试你对 API 的记忆，而是考察你对 JS 语言细节的理解深度。想要拿满分，必须在代码和沟通中体现以下三个核心点：

1. **稀疏数组的处理**：熟练使用 `in` 操作符判断索引是否真实存在。
2. **`this` 的绑定**：使用 `call` 或 `apply` 正确传递 `thisArg`。
3. **严格的边界校验**：像库作者一样思考，严谨处理 `null`/`undefined`、非函数回调、空数组无初始值等异常情况。

在面试时，不仅要写出包含这些细节的代码，还要清晰地讲出“为什么这么做”，这将为你的面试表现带来巨大的加分。
