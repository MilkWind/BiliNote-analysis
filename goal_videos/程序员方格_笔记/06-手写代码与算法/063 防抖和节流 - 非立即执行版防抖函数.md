## 防抖的概念与核心原理 *Content-[00:00]

### 1. 防抖（Debounce）的基本概念
当事件被频繁触发时，防抖机制会让事件处理函数在**最后一次触发后**，延迟指定的时间（例如 500ms 或 1s）再执行。

### 2. 核心运行机制
- **延迟执行**：触发事件后，不会立即执行处理函数，而是开启一个倒计时。
- **重新计时**：如果在延迟时间内，事件再次被触发，则之前的计时作废，**从零开始重新计算**延迟时间。
- **最终执行**：直到最后一次触发后，在完整的延迟时间内没有新的事件触发，才会真正执行一次事件处理函数。

### 3. 核心总结
**多次触发，只执行最后一次，前面的触发都作废。** 只要在规定的延迟时间内屡次触发，都会不断重新计算时间，直到有一次满足了完整的延迟时间（如大于 500ms 无触发），才会执行函数。

### 4. 生活案例：电梯关门
- 按下电梯关门键后，电梯会等待 3 秒才真正关门。
- 如果在这 3 秒内有人进入电梯，电梯会**重新计时**，再等 3 秒。
- 直到 3 秒内没有人再进入，电梯才会执行关门操作。这是最经典的防抖案例。

## 防抖的两种类型及应用场景 *Content-[03:26]

防抖主要分为两种类型，适用于不同的业务场景：

### 1. 非立即执行版（延迟执行）
- **特点**：触发事件后不马上执行，而是延迟指定时间后执行。如果在延迟时间内再次触发，则重新计时。
- **应用场景：搜索框输入**。
  - **原因**：不希望用户每输入一个字符就发起一次网络请求。
  - **效果**：等待用户停止输入（如 500ms 内无新输入）后，再执行对应的搜索请求或事件处理函数，避免无效的高频请求。

### 2. 立即执行版
- **特点**：第一次触发事件时**立即执行**。后续触发则重新计时，在延迟时间内不再执行。直到延迟时间走完，再次触发才会二次执行。
- **应用场景：点击提交按钮**。
  - **原因**：用户点击提交后需要立即响应，但要防止用户在规定时间内（如 1000ms）疯狂连击导致重复提交。
  - **效果**：点一下马上执行提交逻辑，1000ms 内再次点击不会触发，直到 1000ms 倒计时结束，再次点击才会执行第二次。

## 非立即执行版防抖的核心原理 *Content-[05:57]

非立即执行版防抖是面试和实际开发中最常用的版本，其核心原理可以拆解为以下三步：

1. **利用定时器实现延迟**：使用 `setTimeout` 来设定延迟执行的时间。
2. **清除与重建**：每次触发事件时，必须先**清除上一个定时器**（`clearTimeout`），然后**重新创建一个新的定时器**。这就实现了“重新计时”的效果。
3. **最终执行**：只有最后一次触发后，定时器没有被清除，延迟时间自然结束，才会执行最终的事件处理函数。

## 非立即执行版防抖的代码实现 *Content-[07:31]

以下是非立即执行版防抖函数的完整封装与使用流程，面试中常以手写代码的形式考察。

### 1. 封装防抖函数 `debounce`
- 接收两个参数：事件处理函数 `fn` 和延时时间 `delay`。
- 定义一个变量 `timer` 用于保存定时器的 ID，初始值为 `null`。
- 返回一个新的函数，利用 ES6 的 rest 参数 `...args` 接收所有传入的参数。
- 在新函数内部，首先判断并清除上一次的定时器。
- 使用 `setTimeout` 创建新定时器，在回调函数中使用 `fn.apply(this, args)` 执行目标函数，以确保 `this` 指向正确并传递参数。

```javascript
// 封装防抖函数
function debounce(fn, delay) {
    let timer = null; // 定义定时器变量，保存定时器的 ID
    
    return function (...args) {
        // 每次触发事件时，清除上一个定时器
        if (timer) {
            clearTimeout(timer);
        }
        
        // 重新创建新的定时器，实现延迟执行
        timer = setTimeout(() => {
            // 使用 apply 改变 this 指向，并传递参数 args
            fn.apply(this, args);
        }, delay);
    };
}
```

### 2. 定义事件处理函数
创建一个模拟搜索请求的函数，在实际开发中，这里通常是发起 AJAX 请求。

```javascript
// 定义事件处理函数（模拟搜索请求）
function handleSearch(e) {
    console.log('发起了搜索的请求');
    // 获取并打印输入框的内容
    console.log('搜索内容:', e.target.value); 
}
```

### 3. 给输入框绑定防抖函数
获取 DOM 元素，并通过 `addEventListener` 监听 `input` 事件，将事件处理函数和延迟时间（如 500ms）传入防抖函数中。

```javascript
// 获取输入框元素
const input = document.querySelector('input');

// 绑定防抖函数，设置延迟时间为 500ms
input.addEventListener('input', debounce(handleSearch, 500));
```

### 4. 运行效果验证
- 在 `input` 框中快速连续输入内容时，控制台**不会**立即打印。
- 因为在 500ms 内不断输入，定时器会被不断清除并重置。
- 只有在**最后一次输入后等待 500ms**，定时器才会执行，控制台打印一次结果。
- 完美解决了高频触发导致的重复请求问题。

## AI 总结

防抖（Debounce）是前端性能优化的核心手段之一，主要用于限制高频事件的执行频率。其核心思想是“延迟执行，重新计时”，确保在频繁触发的事件中只执行最后一次。防抖分为“非立即执行”和“立即执行”两种模式，分别适用于搜索框输入和按钮防连击等场景。在代码实现上，非立即执行版防抖主要依赖 `setTimeout` 和 `clearTimeout` 的配合，并通过闭包保存定时器状态，利用 `apply` 方法确保 `this` 指向和参数的正确传递。掌握防抖的原理与手写实现，是前端面试和日常开发中的必备技能。
