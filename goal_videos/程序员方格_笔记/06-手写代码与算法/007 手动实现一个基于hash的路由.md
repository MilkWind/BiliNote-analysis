## 核心问题与路由模式 *Content-[00:00]

在实现前端路由（如 Vue Router）时，核心需要解决两个基本问题：
1. **如何改变 URL 而不引起页面刷新**：当前端路由发生变化时，页面不应重新加载。
2. **如何感知或检测路由（URL）发生了变化**：前端需要有一种机制来监听 URL 的变化，从而触发相应的组件渲染。

前端路由主要有两种模式，它们感知变化的方式有所不同：
- **Hash 模式**：主要关注 URL 中 `#` 号后面的部分。`#` 及其后面的内容作为页面内的锚点，改变这部分 URL 不会引起页面刷新。通过监听 `hashchange` 事件来感知哈希值的变化。
- **History 模式**：利用 HTML5 History API，通过监听 `popstate` 事件来感知 URL 的变化。

## 路由变化的感知与拦截机制 *Content-[01:42]

改变 URL 的方式主要有以下几种，针对不同的方式，路由需要采取不同的感知和拦截策略：

1. **浏览器前进/后退**：
   - 属于浏览器行为，页面本身不知道发生了前进或后退。
   - **感知方式**：无论是 Hash 模式还是 History 模式，底层都可以通过监听 `window.addEventListener('popstate', ...)` 事件来感知（Hash 模式也可以专门监听 `hashchange`）。

2. **A 标签跳转**：
   - A 标签的默认点击行为会触发页面刷新。
   - **拦截方式**：需要劫持（拦截）A 标签的点击事件，阻止默认行为，手动获取对应的 `path` 并进行处理。

3. **通过 `location` 改变 URL**：
   - 直接修改 `location` 会导致页面刷新，在路由中通常不直接使用这种方式，而是使用 History API。

4. **History API (`pushState` 和 `replaceState`)**：
   - 这两个方法可以改变 URL 且不刷新页面。
   - **痛点**：调用 `pushState` 和 `replaceState` **不会**触发 `popstate` 事件。
   - **拦截方式**：必须通过劫持（重写）这两个方法，在方法内部手动触发路由更新逻辑，从而知道想要改变的路径是什么。

**核心逻辑总结**：
无论通过何种方式改变 URL，最终目的都是拿到最新的 `path` 路径，然后根据 `path` 去匹配路由表，找到对应的组件并完成渲染。

## 核心类与初始化实现 *Content-[05:41]

在代码实现层面（以 Vue 3 版本思路为例），需要定义 `HashHistory`（或 `History`）类以及 `VueRouter` 类。

### 1. 构造函数 (constructor) 初始化
在 `VueRouter` 的构造函数中，接收 `options` 配置对象，并进行以下初始化操作：
- **路由模式 (mode)**：从 `options.mode` 获取，默认使用 `hash` 模式。
- **路由表转换 (createMap)**：`options.routes` 是一个数组，为了能通过 `path` 快速匹配组件，需要遍历路由数组，将其转换为一个对象 `routeMap`。其中 `key` 为 `path`，`value` 为对应的 `component`。
- **创建 History 实例**：实例化对应的 History 类（如 `HashHistory`），用于存储当前的路由对象。该对象包含 `current` 属性，永远指向最新的路由信息。

### 2. 初始化事件监听 (init)
在 History 实例的 `init` 方法中，根据不同的模式注册相应的事件监听：
- **Hash 模式**：
  - 获取当前的 hash 值，如果不存在则赋予一个默认值。
  - 监听 `hashchange` 事件和 `load` 事件。
  - 当 hash 变化或页面加载完成时，更新 `history.current` 为最新的路由状态。
- **History 模式**：
  - 获取当前的 `pathname`，如果不存在则赋予默认值。
  - 监听 `popstate` 事件。
  - 当路径变化时，更新 `history.current`。

## Vue 插件机制与 Install 方法 *Content-[11:50]

Vue Router 作为一个 Vue 插件，必须提供 `install` 方法，以便通过 `Vue.use()` 进行注册。

### 1. 混入 (Mixin) 与生命周期注入
- 在 `install` 方法中，使用 `Vue.mixin` 注入全局混入。
- 在 `beforeCreate` 生命周期钩子中执行路由实例的挂载逻辑。

### 2. 路由实例的挂载逻辑
- **根组件判断**：检查 `this.$options.router` 是否存在。如果存在，说明当前是根组件。
  - 将路由实例挂载到根组件上：`this._routerRoot = this` 和 `this._router = this.$options.router`。
- **非根组件处理**：如果当前不是根组件，则通过父组件向上查找：
  - `this._routerRoot = this.$parent._routerRoot`。
  - 这样确保了所有层级的组件都能访问到根组件上的 `_routerRoot`。

### 3. 定义 `$router` 和 `$route`
为了让所有组件都能通过 `this.$router` 和 `this.$route` 访问路由信息，使用 `Object.defineProperty` 进行拦截和定义：
- **`this.$router`**：在 `get` 拦截器中，返回 `this._routerRoot._router`（即 VueRouter 实例）。
- **`this.$route`**：在 `get` 拦截器中，返回 `this._routerRoot._router.history.current`（即当前最新的路由对象）。

## 全局组件与 RouterView 渲染 *Content-[16:47]

Vue Router 还注册了一些全局组件，如 `router-link` 和 `router-view`。

### RouterView 的渲染逻辑
`router-view` 组件负责渲染当前路由匹配的组件，其核心渲染逻辑如下：
1. **获取当前路由对象**：通过 `this._routerRoot._router.history.current` 获取最新的路由信息。
2. **匹配组件**：利用之前初始化时生成的 `routeMap`，通过当前路由的 `path` 找到对应的组件。
3. **渲染组件**：使用 Vue 的 `render` 函数，将匹配到的组件渲染到页面上。
