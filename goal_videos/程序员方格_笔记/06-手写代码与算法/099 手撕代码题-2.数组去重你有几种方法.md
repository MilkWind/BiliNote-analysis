## 问题拆解与核心考量 *Content-[00:17]
数组去重看似简单，但如果回答仅限于使用 `Set`，在面试中可能会显得不够深入。要彻底拿捏这道题，需要从以下几个维度进行拆解：

- **基本类型去重**：处理数字、字符串、`Symbol` 等。需要特别注意面试官爱问的 `NaN`（Not a Number）处理陷阱，以及是否需要保持去重后数组的原始顺序。
- **对象去重**：比基本类型复杂。不能简单使用 `==` 或 `===` 比较，因为对象比较的是引用地址。需要根据特定字段（如 `id`）去重，或者进一步考虑对整个对象进行深度对比。
- **性能考量**：不同实现方式的时间复杂度和空间复杂度有很大区别，需要综合评估。

## 方法一：ES6 Set 去重 *Content-[01:20]
这是目前最主流、最简洁的方法，适用于绝大多数场景。

- **实现原理**：`Set` 是天然不重复的数据结构。将数组传入 `Set`，再利用展开运算符 `...` 将其转回数组，一行代码即可搞定。
- **处理 `NaN` 的优势**：`Set` 内部认为 `NaN` 与自身相等，因此能自动去除重复的 `NaN`。在面试中答出这一点非常加分。
- **复杂度分析**：时间复杂度为 $O(n)$，空间复杂度为 $O(n)$（需要遍历一次数组并创建一个新的 `Set`）。

## 方法二：传统去重方案及其缺陷 *Content-[02:13]
在没有 `ES6` 的时代，通常使用以下传统方法，但都存在一定局限性。

- **双重循环 + `indexOf`**：
  - **原理**：外层循环遍历原数组，内层循环使用 `indexOf` 在新数组中查找，若不存在则 `push` 进去。
  - **缺陷**：时间复杂度高达 $O(n^2)$。当数组长度达到成千上万时，性能会急剧下降。
- **利用对象键的唯一性（哈希表）**：
  - **原理**：创建一个空对象作为哈希表，遍历数组并将元素作为对象的键。如果对象中不存在该键，则存入对象并加入结果数组。
  - **优势**：将时间复杂度降至 $O(n)$。
  - **致命缺陷**：对象的键会被强制转换为字符串。这意味着数字 `1` 和字符串 `"1"` 在对象眼中是同一个键，导致字符串 `"1"` 被错误过滤。此方法仅适用于元素均为同一种简单类型的场景。

## 方法三：对象数组去重与深度对比 *Content-[03:46]
针对对象数组的去重，`Set` 方法无法直接搞定，需要借助其他数据结构。

- **根据特定字段去重（如 `id`）**：
  - **实现**：使用 `Map`。与 `Object` 不同，`Map` 的键可以是任意类型，不会发生强制类型转换。
  - **原理**：创建 `Map`，遍历数组，以对象的 `id` 作为 `key` 查找。若 `Map` 中不存在该 `id`，则存入并保留该对象。结合 `filter` 方法处理非常优雅。
  - **复杂度**：时间复杂度为 $O(n)$，是处理此类问题的标准答案。
- **整个对象深度对比去重**：
  - **实现**：利用 `JSON.stringify` 将整个对象序列化为 JSON 字符串，再用 `Set` 对字符串进行去重。
  - **缺陷**：对象属性的顺序会影响 JSON 字符串的结果。例如 `{a: 1, b: 2}` 和 `{b: 2, a: 1}` 会被序列化为不同的字符串，从而被误判为不同对象。此解法仅适用于特定场景，不够通用。

## 方法四：filter 配合 indexOf 的陷阱与优化 *Content-[05:51]
这是一种常见的一行流写法，但隐藏着经典陷阱。

- **实现原理**：`indexOf` 只会返回元素第一次出现的索引。配合 `filter`，如果当前索引与 `indexOf` 返回的索引相等，说明是首次出现，予以保留。
- **`NaN` 陷阱**：`indexOf` 底层使用严格相等（`===`）判断，而 `NaN` 是 JavaScript 中唯一不等于自身的值。因此 `indexOf` 永远找不到 `NaN`，导致数组中的 `NaN` 被重复保留。
- **优化方案**：将 `indexOf` 替换为 `ES7` 的 `includes` 方法。`includes` 底层做了特殊处理，能够正确识别 `NaN`。这体现了对语言细节的掌握程度。

## 终极版 unique 函数封装 *Content-[07:08]
为了体现工程化能力，可以将去重逻辑封装成一个高可复用、高扩展性的工具函数。

- **基础版**：使用 `Set` 处理基本类型去重。
- **进阶版**：增加 `key` 参数。如果不传 `key`，走 `Set` 逻辑；如果传入 `key`，则使用 `Map` 处理对象数组。大幅提升代码可复用性。
- **扩展版**：将 `key` 改为 `options` 配置对象，支持更复杂的场景：
  - **多字段联合去重**：将多个 `key` 的值拼接成一个唯一的字符串进行去重。
  - **自定义比较函数**：支持传入比较函数 `fn`，将比较逻辑交给用户自定义，从而应对各种复杂的去重需求。

## 面试满分答案总结 *Content-[08:01]
在面试中回答数组去重时，可以按照以下逻辑组织答案，轻松拿捏面试官：

- **基本类型**：首选 `Set`，因为代码简洁高效，且能正确处理 `NaN`。
- **对象数组**：使用 `Map`，并通过指定特定的 `key`（如 `id`）来实现去重。
- **注意 `NaN` 陷阱**：明确指出 `indexOf` 无法处理 `NaN`，在必要场景下应使用 `includes` 替代。
- **性能考量**：强调避免使用双重循环，防止出现 $O(n^2)$ 的时间复杂度问题，优先选择 $O(n)$ 的哈希表或 `Set`/`Map` 方案。
