## 引用计数算法简介 *Content-[00:08]
- **基本概念**：引用计数（Reference Counting）是一种较早的垃圾回收（GC）策略。顾名思义，该算法通过记录对象被引用的次数来决定是否进行回收。
- **工作原理**：
  - 如果对象被其他对象引用，则说明其仍在使用中，不可被清除。
  - 如果对象的引用计数为 0（即没有任何其他对象引用它），则该对象会被视为垃圾，进而被垃圾回收器（GC）回收。
- **应用现状**：由于该算法存在较多明显的缺陷，现代 JavaScript 引擎中已经很少再单独使用这种算法。

## 引用计数算法示例解析 *Content-[00:50]
通过一个具体的代码示例，可以清晰地演示引用计数的动态变化过程：
1. **创建对象与初始引用**：
   - 创建对象 `A`：`let A = new Object()`。此时 `A` 指向该内存对象，该对象的引用计数为 **1**。
   - 创建对象 `B` 并指向 `A`：`let B = A`。此时该对象同时被 `A` 和 `B` 引用，引用计数增加为 **2**。
2. **解除引用**：
   - 将 `A` 重新赋值：`A = null`。此时 `A` 不再引用该对象，对象的引用计数减 1，变为 **1**（仅剩 `B` 引用）。
   - 将 `B` 重新赋值：`B = null`。此时 `B` 也不再引用该对象，对象的引用计数再次减 1，变为 **0**。
3. **触发回收**：
   - 当引用计数降为 0 时，说明该对象已经没有任何外部引用，GC 会立即回收该对象所占用的内存空间。

## 引用计数算法的优点 *Content-[02:25]
- **实时性与即时回收**：开发者或引擎能够清楚地知道当前对象被引用的具体次数。当对象的引用计数变为 0 的那一刻，对象会被**立即回收**，无需等待。
- **无需暂停执行线程**：相比于标记-清除算法（Mark-and-Sweep）需要每隔一段时间暂停 JavaScript 执行线程来进行 GC，引用计数算法在运行时不需要暂停主线程，对程序执行的阻塞较小。
- **无需全局遍历**：标记-清除算法需要遍历堆中的所有活动与非活动对象来进行标记和清除；而引用计数算法只需要在对象被引用或解除引用时进行简单的计数加减操作即可，日常开销相对较小。

## 引用计数算法的缺点 *Content-[03:15]
- **循环引用问题（致命缺陷）**：这是引用计数算法最严重且无法克服的问题。
  - **场景描述**：如果对象 `A` 的某个属性指向对象 `B`，同时对象 `B` 的某个属性又指向对象 `A`（即 `A.prop = B` 且 `B.prop = A`），形成闭环。
  - **导致后果**：即使外部作用域中已经销毁了对 `A` 和 `B` 的引用（例如将外部的 `A` 和 `B` 变量置为 `null`），但由于 `A` 和 `B` 之间互相引用，它们的引用计数永远无法降为 0。
  - **最终影响**：这些对象将永远无法被 GC 识别为垃圾并回收，从而导致严重的**内存泄漏**问题，最终可能引发程序崩溃。

## AI 总结
引用计数算法通过实时追踪对象的引用次数，在引用归零时立即回收内存，具有无需暂停线程和无需全局遍历的优点。然而，其致命的“循环引用”缺陷会导致互相引用的对象即使脱离外部作用域也无法被回收，从而引发内存泄漏。正是由于这一难以解决的痛点，现代前端与 JavaScript 引擎已普遍弃用该算法，转而采用标记-清除、标记-整理等更先进的垃圾回收策略。
