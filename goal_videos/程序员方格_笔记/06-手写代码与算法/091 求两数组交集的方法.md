## 面试题背景与概念解析 *Content-[00:00]

- **数组操作的重要性**：在前端开发过程中，使用数组保存和处理数据是非常实用且频率极高的操作。因此，用人单位经常通过数组操作相关的面试题来考察候选人的实际编码能力。
- **交集的概念**：交集指的是两个数组中共同拥有的元素。例如，数组 `[2, 3, 4]` 和数组 `[2, 4, 5]` 之间的交集是 `[2, 4]`。
- **考察目的**：在实际业务中，经常需要找出两组数据的共性。这类面试题并非空穴来风，而是具有实际的业务应用价值，主要考察开发者对数组的操纵能力以及解决交织数据问题的能力。
- **基本解题思路**：遍历其中一个数组，获取每一项的值，去另一个数组中进行比对。如果存在则保留（即为交集），如果不存在则过滤掉。

## 方法一：Set 结合 filter（推荐方案） *Content-[05:40]

- **核心思路**：利用 `Set` 集合去除数组中的重复元素，避免重复计算；然后使用 `filter` 方法筛选出同时存在于两个数组中的元素。
- **实现步骤**：
  - 定义一个接收两个数组参数的函数。
  - 将两个数组分别转换为 `Set` 对象，实现自动去重：`const set1 = new Set(arr1); const set2 = new Set(arr2);`。
  - 对其中一个 `Set`（或将其转换回数组）调用 `filter` 方法。
  - 在 `filter` 的回调函数中，检查当前元素是否存在于另一个 `Set` 中（使用 `set2.has(item)` 或 `set2.includes(item)`）。
  - 返回过滤后的新数组，即为最终的交集结果。
- **方法优势**：
  - **代码简洁**：逻辑清晰，非常适合在面试中手动编写。
  - **性能较优**：利用 `Set` 提前去重，避免了后续重复的比较和计算，提升了执行效率。
  - **经典推荐**：这是面试中最经典、最理想的实现方式。

## 方法二：reduce 结合 includes（扩展方案） *Content-[10:20]

- **核心思路**：使用 `reduce` 方法手动遍历数组，在遍历过程中检查元素是否存在于另一个数组中，并将符合条件的元素累积到结果数组中。
- **实现步骤**：
  - 对第一个数组调用 `reduce` 方法，并传入一个空数组 `[]` 作为初始的累加器（accumulator）。
  - 在遍历过程中，获取当前元素 `item`。
  - 检查 `item` 是否存在于第二个数组中（使用 `arr2.includes(item)`），并且检查该元素是否尚未被写入累加器中（用于防止结果数组中出现重复项）。
  - 如果条件满足，使用 `push` 方法将 `item` 追加到累加器数组中。
  - 遍历结束后，返回累加器，即为交集结果。
- **方法劣势**：
  - 代码相对冗长，逻辑不如第一种方法直观。
  - 由于结合了 `reduce` 和 `includes`，在处理大型数组时需要进行多次遍历和查找，性能较差。
  - 仅适用于数据量较小的数组场景。

## 面试策略与建议 *Content-[14:00]

- **首选方案**：在面试中遇到求数组交集的题目时，优先且强烈推荐使用**方法一（`Set` + `filter`）**。该方法代码简洁、性能较好，能体现出良好的编码习惯。
- **扩展展示**：如果在完成方法一后还有时间，或者为了向面试官展示更全面的知识储备，可以主动扩展讲解**方法二（`reduce` + `includes`）**。在讲解时，需说明其实现原理以及在处理大型数组时的性能劣势，这样能让面试回答更加完善，展现技术深度。
