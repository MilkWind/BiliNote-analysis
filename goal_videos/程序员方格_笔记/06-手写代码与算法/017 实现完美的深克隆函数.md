## 为什么需要深拷贝及 JSON 方案的缺陷 *Content-[00:56]

- **深拷贝的必要性**：
  - 在日常开发中，经常需要处理多层嵌套的对象（如用户配置信息）。
  - 如果基于原配置创建新配置并随意修改，简单的赋值（浅拷贝）只复制了引用，修改新对象会直接影响原对象。
  - 深拷贝的目的是创建一个全新、完全独立的副本，确保修改互不影响。

- **JSON 方案的缺陷**：
  - 最快捷的深拷贝方案是 `JSON.parse(JSON.stringify(obj))`，但在面试和实际生产中存在诸多致命问题：
    - 会直接忽略值为 `undefined` 和 `Symbol` 的属性。
    - 无法处理函数、正则表达式等特殊对象（通常会被转换为 `null` 或空对象）。
    - **致命缺陷**：如果对象中存在循环引用，该方法会直接报错崩溃。
  - 因此，一个能在生产环境使用且能应对面试官深入追问的深克隆函数，必须手动实现。

## 基础版本：处理普通对象和数组 *Content-[02:20]

- **目标**：正确处理普通对象和数组的嵌套拷贝。
- **代码框架与核心逻辑**：
  - **出口条件**：如果传入的 `target` 是 `null` 或不是对象（即原始类型如数字、字符串、布尔值），直接返回其本身。因为原始类型按值传递，不存在深拷贝的需求。
  - **判断类型与创建容器**：使用 `Array.isArray()` 判断 `target` 是数组还是对象，并创建对应的空容器 `cloneTarget`。
  - **遍历与递归**：
    - 使用 `for...in` 循环遍历 `target` 的所有可枚举属性。
    - **严谨性检查**：在循环内部，必须使用 `Object.prototype.hasOwnProperty` 判断属性是否为 `target` 自身的属性，确保不会拷贝从原型链上继承的属性。
    - 递归调用 `deepClone` 函数，将结果赋值给 `cloneTarget[key]`。
  - **返回结果**：返回 `cloneTarget`。
- **效果验证**：该基础版本逻辑清晰，能够处理绝大部分简单的对象和数组嵌套场景。修改克隆对象的属性，原对象完全不受影响。

## 解决循环引用问题：引入 WeakMap *Content-[04:57]

- **循环引用的问题**：
  - 当对象的某个属性指向自身（如 `target.self = target`）形成闭环时，基础版 `deepClone` 会尝试拷贝 `target.self`，发现它又是 `target`，从而陷入无限递归。
  - 最终会导致浏览器的调用栈被耗尽，抛出 `RangeError`（栈溢出错误）。

- **解决方案：引入 WeakMap**：
  - 引入外部数据结构 `WeakMap` 作为备忘录，记录已经拷贝过的对象。
  - **核心思路**：
    - 在开始拷贝一个对象前，先检查是否已经拷贝过。
    - 如果已拷贝过，直接返回之前创建好的副本，中断递归。
    - 如果未拷贝过，创建新副本，并**立即**将“原对象-新副本”的对应关系存入 `WeakMap`，然后再继续递归拷贝其属性。
  - **为什么使用 WeakMap**：`WeakMap` 是弱引用的，当原对象被垃圾回收机制回收时，`WeakMap` 中对应的键值对也会被自动移除，能有效避免内存泄漏，是非常优雅的解决方案。

- **代码改进细节**：
  - 函数参数增加 `map = new WeakMap()`。
  - 拷贝前检查 `map.has(target)`，若存在则直接返回 `map.get(target)`。
  - 若不存在，创建 `cloneTarget` 后，**立即**执行 `map.set(target, cloneTarget)`。这一步至关重要，它确保了在后续递归中再次遇到该对象时能直接命中并返回，避免死循环。
  - 在递归调用 `deepClone` 时，务必将 `map` 参数一直传递下去。
- **效果验证**：改进版成功处理了循环引用，克隆对象保持了原有的循环引用结构，且正确指向克隆后的自身，保证了数据的独立性。

## 处理复杂数据类型：Date、RegExp、Set、Map、Symbol *Content-[09:58]

- **面临的问题**：之前的逻辑只考虑了数组和普通对象，遇到 `Date`、`RegExp`、`Set`、`Map` 等会被当成普通对象处理，导致拷贝结果变成空对象。
- **精确类型判断**：
  - 放弃 `typeof`，使用 `Object.prototype.toString.call(target)` 获取精确类型。
  - 封装 `getType` 辅助函数，返回如 `obj`、`array`、`date`、`regexp`、`set`、`map` 等格式化的类型字符串，准确识别各种数据类型。

- **分类处理逻辑（使用 switch 语句）**：
  - **Object / Array**：按原逻辑创建空容器。
  - **Date**：使用 `new Date(target)` 重新创建。
  - **RegExp**：使用正则构造函数 `new RegExp(target.source, target.flags)` 重新创建。
  - **Set**：创建空 `Set`，遍历原 `Set`，对每个 `value` 进行递归深拷贝后 `add` 到新 `Set` 中。
  - **Map**：创建空 `Map`，遍历原 `Map`，对每个 `key` 和 `value` 分别进行递归深拷贝后 `set` 到新 `Map` 中。
  - **原始类型**：直接返回 `target`。
  - **注意**：创建新容器后，务必将其 `set` 到 `WeakMap` 中。

- **处理 Symbol 键**：
  - `for...in` 循环无法遍历 `Symbol` 类型的键。
  - 使用 `Object.getOwnPropertySymbols(target)` 获取所有的 `Symbol` 键。
  - 将其与 `Object.keys()` 获取的普通键合并为 `allKeys` 数组。
  - 遍历 `allKeys`，对每一个键对应的值进行递归深拷贝，确保不遗漏任何细节。

## 总结与核心技术回顾 *Content-[15:36]

- **实现过程的三个阶段**：
  1. **基础递归拷贝**：实现简单的对象和数组嵌套处理。
  2. **引入 WeakMap**：解决循环引用导致的无限递归问题。
  3. **精确类型判断与分类处理**：支持复杂数据类型，并完善 `Symbol` 键的处理，使函数达到生产级别的完备性。

- **掌握的核心技术**：
  - **WeakMap**：利用其弱引用特性解决循环引用，同时避免内存泄漏。
  - **Object.prototype.toString.call**：精确判断数据类型的“万金油”方法。
  - **Object.getOwnPropertySymbols**：获取容易被忽略的 `Symbol` 键，体现思维的严谨性。

- **学习意义**：手写 `deepClone` 不仅仅是为了应付面试题，更重要的是通过这个过程，深刻理解 JavaScript 的引用类型、堆栈内存机制以及垃圾回收等底层核心概念。
