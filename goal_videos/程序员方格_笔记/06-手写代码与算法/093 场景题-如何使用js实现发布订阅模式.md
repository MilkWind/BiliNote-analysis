## 发布订阅模式的使用方式 *Content-[00:28]
- 在实际工作中，通常通过类似 `EventEmitter` 的实例来操作和管理事件。
- **订阅事件**：
  - 通过 `on` 方法监听特定事件，并传入对应的回调函数（Listener）。
  - 可以为同一个事件注册多个不同的回调函数。
  - 当该事件被触发时，会依次执行所有订阅该事件的回调函数，实现一对多的消息分发。
- **发布事件**：
  - 通过 `emit` 方法触发对应的事件。
  - 在发布时，可以向回调函数传递相关的参数或信息，实现数据的同步传递。

## 发布订阅模式的核心特点与组成 *Content-[02:14]
- **核心特点**：
  - 属于经典的设计模式之一。
  - 允许对象之间进行松耦合（Loose Coupling）的通信。
  - 发布者与订阅者之间不存在直接调用的关系，从而大幅降低了代码的耦合度，提高了系统的可维护性和扩展性。
- **核心组成部分**：
  - **发布者（Publisher）**：负责发布消息，系统中可以有多个发布者。
  - **订阅者（Subscriber）**：负责接收并处理消息，系统中可以有多个订阅者。
  - **事件通道/事件中心（Event Channel / Event Center）**：
    - 作为发布者与订阅者之间的通信桥梁。
    - 订阅者通过注册监听事件通道上的消息来做出响应。
    - 这种模式在事件驱动编程和业务编程中应用极为广泛。

## 实现思路与核心功能 *Content-[04:20]
- **面试技巧**：在面试中如果遇到没有明确思路的手写题，可以先向面试官阐述分析思路。边说边理清逻辑，不仅能展现清晰的思维能力，还能在交流中激发灵感。
- **核心功能拆解**：
  1. **事件中心（Event Center）**：用于集中存储事件及其对应的回调函数，作为整个模式的总控中心。
  2. **`on` 方法**：用于订阅某个事件，并将对应的回调函数注册到事件中心。
  3. **`emit` 方法**：用于发布某个事件，触发并调用所有订阅该事件的回调函数。
  4. **`off` 方法**：用于解除对某个事件的订阅。在某些场景下（如只需触发一次的监听），需要避免无限制的订阅，此时可通过 `off` 移除特定的回调。

## JavaScript 代码实现细节 *Content-[06:57]
- **定义事件中心**：
  - 创建一个 `EventEmitter` 对象（或类）。
  - 在对象内部定义一个属性（如 `events`）用于存储事件和回调函数的映射关系。通常使用对象或 Map，键为事件名，值为回调函数数组。
- **实现 `on(event, listener)` 方法**：
  - 接收事件名 `event` 和回调函数 `listener` 作为参数。
  - 判断当前事件是否已在事件中心注册（即检查该事件名对应的数组是否存在）。
  - 如果未注册，则初始化一个空数组。
  - 将传入的 `listener` 通过 `push` 方法存入该事件对应的回调数组中，实现批量存储。
- **实现 `emit(event, ...args)` 方法**：
  - 接收事件名 `event` 和需要传递的剩余参数 `...args`。
  - 判断事件中心是否存在该事件，如果不存在则直接返回（忽略）。
  - 如果存在，则获取该事件对应的回调函数数组。
  - 使用 `forEach` 遍历数组，依次执行每个 `listener`，并将传入的参数 `...args` 传递给回调函数。
- **实现 `off(event, listener)` 方法**：
  - 接收事件名 `event` 和需要取消的回调函数 `listener`。
  - 判断当前事件是否存在，不存在则直接 `return`。
  - 如果存在，则在事件中心找到该事件对应的回调数组。
  - 使用 `filter` 等方法，将数组中严格等于传入 `listener` 的项过滤掉，从而精准取消该特定回调的订阅。

## 使用示例与总结 *Content-[10:17]
- **定义回调函数**：例如定义 `user1` 和 `user2` 两个处理函数作为订阅者。
- **订阅事件**：使用 `EventEmitter.on('message', user1)` 等方式监听 `message` 事件。
- **发布事件**：使用 `EventEmitter.emit('message', 'Hello World')` 触发事件，并将 `'Hello World'` 作为消息内容传递给回调函数。
- **取消订阅**：使用 `EventEmitter.off('message', user1)` 移除 `user1` 的监听，后续再次触发 `message` 事件时，将不再执行 `user1`。
