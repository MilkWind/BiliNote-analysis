## 1. 发布订阅模式的使用与核心概念 *Content-[00:00]

- **重要性**：在前端领域，许多主流框架以及日常业务代码中都会频繁使用到发布订阅模式（Publish-Subscribe Pattern）。它是前端面试中非常高频且重要的核心概念。
- **基本使用方式**：
  - 通常会使用一个事件触发器（如 `EventEmitter`）来进行事件的相关管理。
  - **订阅事件**：通过 `on` 方法监听对应的事件，并传入回调函数。可以针对同一个事件注册多个不同的回调，或者针对不同用户进行订阅。当事件触发时，会通知到所有的订阅者。
  - **发布事件**：通过 `emit` 方法触发对应的事件，并可以向回调函数传递相关的信息或参数（例如传递 message）。

## 2. 发布订阅模式的特点与架构 *Content-[02:16]

- **核心特点**：允许对象之间进行松散的耦合通信，减少对象之间的直接依赖。
- **架构组成**：
  - **发布者（Publisher）**：可以有多个发布者，发布者不会直接调用订阅者，两者之间不存在直接的调用关系。
  - **订阅者（Subscriber）**：允许通过注册监听对应通道上的消息来做出响应。
  - **事件通道/事件中心（Event Channel / Event Center）**：发布者和订阅者之间通过事件通道进行消息的发布与接收。
- **应用场景**：在事件驱动编程和业务编程中非常常用，是解耦代码的重要手段。

- **实现思路拆解**：
  - **事件中心（Event Center）**：需要一个用于存储事件及其对应回调函数的总控中心。
  - **`on` 方法**：用于订阅某个事件，并将对应的回调函数注册到事件中心。
  - **`emit` 方法**：用于发布某个事件，并调用所有订阅该事件的回调函数。
  - **`off` 方法**：用于解除订阅。在某些场景下（如只需触发一次），可以通过此方法取消事件监听，避免无限制的订阅和内存泄漏。

## 4. JS 代码实现细节 *Content-[06:10]

- **定义 `EventEmitter` 对象**：
  - 在对象内部定义一个属性（如 `events`）作为事件中心，用于存储事件名和相关的回调函数数组。
- **实现 `on(event, listener)` 方法**：
  - 接收事件名 `event` 和回调函数 `listener`。
  - 判断当前 `event` 是否已在 `events` 中注册。
  - 如果未注册，则为该事件初始化一个空数组。
  - 如果已注册，则将当前的 `listener` push 到对应的数组中进行批量存储。
- **实现 `emit(event, ...args)` 方法**：
  - 接收事件名 `event` 和需要发布的相关参数。
  - 判断事件中心里当前事件是否存在，若不存在则直接返回（忽略错误）。
  - 若存在，则遍历 `events[event]` 数组，依次执行每个 `listener`，并将参数传入。
- **实现 `off(event, listener)` 方法**：
  - 接收事件名 `event` 和需要取消的回调函数 `listener`。
  - 判断当前事件是否存在，不存在则直接 return。
  - 若存在，则在事件中心找到对应的 listener 数组，通过过滤（filter）的方式将指定的 `listener` 移除，从而取消订阅。下次发布时即可忽略该已取消的事件。

## 5. 使用示例与总结 *Content-[10:17]

- **使用流程**：
  1. 定义相关的回调函数（如 `user1`, `user2`）。
  2. 通过 `EventEmitter` 的 `on` 方法监听相关事件。
  3. 使用 `emit` 方法触发事件，并传入具体信息（如 `hello world` message）。
  4. 在需要时，通过 `off` 方法取消当前事件的订阅。
- **总结**：使用 JS 实现发布订阅模式整体逻辑较为简单，核心在于理解事件中心的数据结构（对象嵌套数组）以及 `on`、`emit`、`off` 三个核心方法对数据的操作。掌握其底层原理有助于更好地应对前端场景题面试。
