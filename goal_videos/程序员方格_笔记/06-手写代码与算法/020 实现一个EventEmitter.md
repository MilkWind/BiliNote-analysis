## 面试核心考察点 *Content-[00:00]

手写 `EventEmitter` 是前端面试中的高频常考题，主要考察候选人的 JavaScript 基础以及设计模式思想。要完美解答此题，核心需要拆解为以下两个方面：

1\. **API 设计**
面试官希望看到你了解标准 `EventEmitter` 的形态，必须设计出最核心的四个方法，缺一不可：
- `on`：用于订阅事件。
- `emit`：用于触发事件。
- `off`：用于取消订阅。
- `once`：用于实现只执行一次的特殊订阅。

2\. **边界情况处理**
这是区分普通代码与优秀代码的关键，体现了代码的严谨性和工程经验。需要深入思考以下细节：
- 如果同一个事件被监听了多次（重复订阅）该如何处理？
- `emit` 触发时，如何将参数正确无误地传递给回调函数？
- 回调函数内部的 `this` 指向应该指向谁？
- 事件监听后如果不释放，是否会造成内存泄漏？

## 核心数据结构设计 *Content-[01:43]

实现 `EventEmitter` 的第一步是设计骨架，即选择合适的核心数据结构来存储事件及其对应的回调函数。

**推荐方案：使用 `Map` 结合 `Set`**

- **`Map` 用于存储所有事件**：
  - `key`：事件名称（如 `click` 或自定义的事件名）。
  - `value`：回调函数的集合。
  - **优势**：`Map` 在根据 `key` 查找 `value` 时，时间复杂度为 $O(1)$，查找速度极快，不受注册事件数量的影响，保证了高效性。

- **`Set` 用于存储回调函数集合（作为 `Map` 的 `value`）**：
  - **优势**：`Set` 数据结构中的元素具有唯一性。这天然地解决了重复订阅的问题，同一个回调函数无论被 `on` 多少次，在 `Set` 中都只会保留一份，实现了自动去重。

通过 `Map` + `Set` 的组合，一个简单的数据结构选择就同时解决了高效查找和回调去重两个核心问题。

## 核心 API 实现：on 与 emit *Content-[02:54]

有了数据结构后，即可开始编写最核心的两个方法，它们分别代表了生产者和消费者。

- **`on(event, callback)` 方法（订阅事件）**：
  1. 接收事件名 `event` 和回调函数 `callback`。
  2. 检查 `Map` 中是否存在该事件，如果不存在，则创建一个新的 `Set` 并将其存入 `Map`。
  3. 将 `callback` 添加到对应事件的 `Set` 集合中。

- **`emit(event, ...args)` 方法（触发事件）**：
  1. 接收事件名 `event` 和任意数量的参数 `...args`。
  2. 检查该事件是否被订阅，如果没有订阅，则直接 `return`，不做任何处理。
  3. 如果已订阅，从 `Map` 中取出对应的 `Set`。
  4. 遍历该 `Set`，将里面存储的每一个回调函数取出执行，并将 `args` 原封不动地传递进去。

## 核心 API 实现：off 与 once *Content-[04:33]

完善 `EventEmitter` 的另外两个关键方法，需要处理更复杂的逻辑。

- **`off(event, callback)` 方法（取消订阅）**：
  需要根据传参情况考虑两种逻辑：
  1. **只传事件名**：意味着用户想取消该事件的所有订阅。直接调用 `Map.delete(event)` 将该事件从 `Map` 中删除即可。
  2. **同时传事件名和回调函数**：意味着用户只想取消特定的监听。此时需要从对应的 `Set` 中 `delete` 掉该特定的回调函数。

- **`once(event, callback)` 方法（只执行一次）**：
  这是面试官非常喜欢考察的技巧点。不能直接将用户的 `callback` 传入，而是需要将其包装：
  1. 创建一个新的包装函数 `wrapper`。
  2. 在 `wrapper` 内部，首先执行用户真正的 `callback`，并传入相应的参数。
  3. **关键步骤**：在执行完真正的回调后，立刻调用 `off` 方法，将 `wrapper` 这个临时监听器从订阅列表中移除。
  4. 最后，将包装好的 `wrapper` 传入 `on` 方法进行订阅。
  - **效果**：当事件第一次触发时，`wrapper` 被执行并自我移除；下一次再 `emit` 同一事件时，`wrapper` 已不存在，从而完美实现只触发一次的效果。

## 满分进阶优化策略 *Content-[06:54]

在实现基础功能后，主动进行以下额外优化，可以瞬间提升代码质量，展示高级工程素养，让面试官眼前一亮：

1\. **链式调用**
让 `on` 和 `off` 方法在执行完毕后返回 `this`。这样用户就可以写出如 `emitter.on(...).on(...).off(...)` 这样优雅的链式调用代码。

2\. **错误处理**
在 `emit` 方法遍历执行回调时，给每个 `callback` 包裹一个 `try...catch`。这样可以确保某个监听器内部报错时，不会导致整个事件系统崩溃，从而提升代码的兼容性和健壮性。

3\. **内存优化**
如果一个事件的所有监听器都被 `off` 掉了，其对应的 `Set` 会变成空集，但 `Map` 中依然保留着该事件名与空集合的映射。虽然单次占用不大，但日积月累会造成内存泄漏隐患。
- **解决方案**：在 `off` 方法执行后增加判断，如果该 `Set` 的 `size` 变为 0，则顺手将该 `event` 从 `Map` 中 `delete` 掉，及时释放内存。

## 总结与回顾 *Content-[08:22]

手写 `EventEmitter` 满分答案的核心策略如下：

1. **数据结构**：选用 `Map` + `Set`，完美兼顾 $O(1)$ 的查找效率和回调函数的自动去重。
2. **核心 API**：精准实现 `on`、`emit`、`off`、`once` 四个方法，特别要熟练掌握 `once` 中的包装函数（Wrapper）思想，建议手动练习。
3. **边界处理**：主动提出并实现链式调用、错误处理（`try...catch` 隔离错误）以及内存优化（清理空 `Set`），向面试官充分展示你的工程素养与深层思考。
