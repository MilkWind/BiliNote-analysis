## 千位分隔符的概念与面试题要求 *Content-[00:00]
- **千位分隔符概念**：
  - 是一种大额数字的国际惯用表达方式。
  - 当数字金额较大（如六位、七位数，例如 1234556）时，难以快速区分具体数额。
  - 通过在整数部分每隔三位添加一个逗号（如 1,234,556），可以直观地看出千位、万位等，符合国际显示大额数字的标准。
- **面试题要求**：
  - 使用 JavaScript 实现千位分隔符功能。
  - **核心规则**：整数部分每隔三位加一个逗号。
  - **难点与边界情况**：
    - 数字长度是动态的，无法固定具体的分割位置。
    - 需要处理**负数**（负号也占长度，不能把负号当成数字进行分隔）。
    - 需要处理**小数部分**（小数部分不需要进行千位分隔）。
  - **输入输出**：传入的是数字类型，处理时需要先转换为字符串类型，再进行格式化操作。

## 方法一：正则表达式实现 *Content-[03:30]
- **实现思路**：
  - 推荐使用正则表达式，代码最为简洁高效。
  - 前提是需要对正则表达式的逻辑有较好的理解。
- **代码逻辑**：
  - 定义一个格式化函数（如 `formatter`），接收数字参数。
  - 将数字转换为字符串，调用字符串的 `replace` 方法进行内容替换。
  - **正则匹配规则**：
    - 匹配整数部分，且排除负号的影响。
    - 匹配每三个数字为一组。
    - 使用全局匹配标志，找到所有符合条件的数字组。
  - **替换逻辑**：在匹配到的每三个数字组之间插入一个逗号。
- **特点**：
  - 能够完美处理纯整数、负数以及带小数的情况（小数部分不受影响）。
  - 代码极简，执行效率高。
  - 缺点是对正则不熟悉的人较难理解和编写。

## 方法二：循环遍历实现 *Content-[07:40]
- **实现思路**：
  - 如果不熟悉正则表达式，可以使用循环遍历的方式。
  - 这种方式逻辑更加直观，便于理解，且兼容性更好。
- **代码逻辑**：
  - 定义函数（如 `formatNumber`），将传入的数字转为字符串。
  - 使用 `.` 将字符串分割为**整数部分**和**小数部分**（如果没有小数则只获取整数部分）。
  - **处理整数部分**：
    - 采用**从后往前**遍历的方式处理整数部分。
    - 设置计数器，每累加到 3 个数字时进行判断。
    - **关键判断**：如果当前计数为 3，并且当前索引 `i !== 0`（即前面还有数字，不是最左侧的起始位置），则在当前数字前面插入一个逗号。
  - **合并结果**：
    - 将格式化后的整数部分与小数部分重新组合。
    - 如果存在小数部分，则用 `.` 连接；如果没有，则直接返回处理后的整数部分。
- **特点**：
  - 逻辑清晰，更容易控制细节。
  - 对浏览器兼容性要求低，适合老旧环境。

## 方法三：国际化 API 实现 *Content-[12:00]
- **实现思路**：
  - 使用 JavaScript 内置的国际化 API，代码量最少，且能自动适配多地区格式。
- **代码逻辑**：
  - 使用 `Intl.NumberFormat` 对象。
  - 示例代码：`new Intl.NumberFormat('en-US').format(number)`。
  - `'en-US'` 表示使用英美的数字格式化标准（即整数部分每隔三位使用逗号分隔）。
- **特点与优势**：
  - **自动适配地区**：不同地区有不同的分隔符习惯（如英美用逗号，某些欧洲国家用点），该 API 可自动处理。
  - **功能丰富**：支持货币、百分比等扩展格式。
  - **自动处理边界**：能够自动处理负数，并保留小数部分的原有位置。
- **注意事项**：
  - 需要现代浏览器支持（不兼容老旧浏览器）。
  - 传入的参数必须是**有效的数字**，在调用前需要进行数字有效性验证，避免传入空值或非法字符导致报错。

## 三种方法总结与对比 *Content-[14:44]
- **正则表达式法**：适合追求代码简洁、快捷，且对正则有一定掌握的开发者。
- **循环遍历法**：适合需要精细控制逻辑、追求高兼容性，或对正则不熟悉的开发者。
- **国际化 API 法**：适合面向国际化项目、需要适配不同国家地区格式，且运行环境为现代浏览器的场景。
