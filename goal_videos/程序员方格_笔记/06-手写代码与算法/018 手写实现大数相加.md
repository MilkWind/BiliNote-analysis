## 1. 问题背景与 JS 数字精度痛点 *Content-[01:29]

在 JavaScript 中处理大数时，经常会遇到数字精度丢失的问题。这背后涉及到 JavaScript 数字存储的底层原理。

- **安全整数范围**：JavaScript 的数字并不是无限大的，它有一个安全整数的范围。可以通过 `Number.MAX_SAFE_INTEGER` 常量查看，其值约为 9000 万亿，准确的数学表达为 $2^{53} - 1$。在这个范围内，JavaScript 能够保证整数的精度表示和计算是安全的。
- **精度丢失现象**：一旦超出安全整数范围，计算就会失效。例如，当变量 `a` 比 `Number.MAX_SAFE_INTEGER` 大 1 时，再给它加上 `b = 1`，按理说 `a + b` 应该不等于 `a`，但在控制台中 `a + b === a` 的结果却是 `true`。
- **直观案例**：两个非常大的数相加，手动计算结果的个位是 5，但控制台输出的个位却是 4，相差了 1。
- **底层原因**：JavaScript 底层采用特殊的标准（IEEE 754 双精度浮点数标准）来表示数字。存储数字的空间是有限的，当数字大到一定程度时，只能存储一个近似值，从而牺牲掉部分精度。
- **结论**：不能直接使用 `+` 运算符来处理超过安全整数范围内的大数，必须通过其他手段（如字符串模拟或原生大数类型）来实现。

## 2. 核心思路：模拟数学竖式加法 *Content-[03:56]

既然不能使用 `+` 运算符，我们需要回归最原始的数学计算方法——列竖式。

- **竖式计算演示**：以 $88 + 25$ 为例。
  1. **个位对齐**：$8 + 5 = 13$，结果的个位记为 3，并向十位进 1。
  2. **十位计算**：$8 + 2 = 10$，加上个位的进位 1，结果为 $10 + 1 = 11$。十位记为 1，并向百位进 1。
  3. **百位处理**：最高位只有进位 1，直接写下。
  4. **最终结果**：拼接得到 113。
- **编程实现策略**：
  - 将大数作为**字符串**处理，绕开 JavaScript 的精度限制。
  - 从字符串的**末尾（个位）** 开始向前遍历。
  - 每次循环获取两个字符串当前位的数字进行相加。
  - 根据求和结果，计算出新的**进位值**和**当前位的结果值**。
  - 不断重复此过程，直到两个字符串的所有位都处理完毕，且没有剩余进位。
  - 由于每次只处理一位数的加法，结果绝对在安全整数范围内。

## 3. 代码实战：从零构建大数相加函数 *Content-[05:53]

将上述思路转化为具体的 JavaScript 代码，核心步骤如下：

- **初始化变量**：
  - `result = ""`：用于存储最终拼接的结果。
  - `carry = 0`：记录进位值，默认为 0。
  - `i = a.length - 1`，`j = b.length - 1`：两个指针，分别指向两个输入字符串的最后一位（个位）。
- **核心循环条件**：
  - `i >= 0`：表示字符串 `a` 未遍历完。
  - `j >= 0`：表示字符串 `b` 未遍历完。
  - `carry > 0`：表示还有未处理的进位（例如两个一位数相加产生进位，字符串遍历完后仍需处理该进位）。
  - 综合条件为：`i >= 0 || j >= 0 || carry > 0`。
- **循环内部逻辑**：
  - **获取当前位数字**：使用三元运算符处理长度不一致的情况。若 `i >= 0`，则取 `Number(a[i])`，否则补 `0`；`j` 同理。
  - **计算当前位总和**：`sum = num1 + num2 + carry`。
  - **计算新进位**：`carry = Math.floor(sum / 10)`（对 10 向下取整）。例如 `sum = 17`，进位为 1；`sum = 9`，进位为 0。
  - **确定当前位结果**：`sum % 10`（对 10 取模）。例如 `17 % 10 = 7`。
  - **拼接结果**：由于是从右向左计算，需要将新数字拼接到 `result` 的**头部**，即 `result = (sum % 10) + result`。
  - **移动指针**：`i--`，`j--`，准备处理更高一位。
- **返回结果**：循环结束后，直接 `return result`。

## 4. 单步追踪：以 99 + 8 为例解析执行逻辑 *Content-[10:39]

通过输入 `a = "99"`，`b = "8"`，详细追踪代码的执行过程：

- **初始状态**：
  - `result = ""`，`carry = 0`。
  - 指针 `i = 1`（指向 `a` 的第二个 '9'），`j = 0`（指向 `b` 的 '8'）。
- **第一轮循环（处理个位）**：
  - 满足 `i >= 0`，进入循环。
  - `num1 = 9`，`num2 = 8`。
  - `sum = 9 + 8 + 0 = 17`。
  - 新进位 `carry = Math.floor(17 / 10) = 1`。
  - 当前位结果 `17 % 10 = 7`。
  - 拼接结果：`result = "7" + "" = "7"`。
  - 指针更新：`i = 0`，`j = -1`。
- **第二轮循环（处理十位）**：
  - 满足 `i >= 0`，进入循环。
  - `num1 = 9`（`a[0]`），`num2 = 0`（因为 `j < 0`，补 0）。
  - `sum = 9 + 0 + 1(上一轮的进位) = 10`。
  - 新进位 `carry = Math.floor(10 / 10) = 1`。
  - 当前位结果 `10 % 10 = 0`。
  - 拼接结果：`result = "0" + "7" = "07"`。
  - 指针更新：`i = -1`，`j = -2`。
- **第三轮循环（处理最终进位）**：
  - 此时 `i < 0` 且 `j < 0`，但 `carry = 1 > 0`，满足循环条件。
  - `num1 = 0`，`num2 = 0`。
  - `sum = 0 + 0 + 1 = 1`。
  - 新进位 `carry = Math.floor(1 / 10) = 0`。
  - 当前位结果 `1 % 10 = 1`。
  - 拼接结果：`result = "1" + "07" = "107"`。
  - 指针更新：`i = -2`，`j = -3`。
- **循环结束**：
  - `i < 0`，`j < 0`，`carry = 0`，所有条件均为 `false`，退出循环。
  - 返回 `result`，即 `"107"`，计算正确。

## 5. 现代解决方案：BigInt 原生类型 *Content-[14:24]

除了手动“造轮子”，现代 JavaScript 提供了原生的解决方案——`BigInt`。

- **引入背景**：`BigInt` 是 ES2020 引入的新内置类型，专门用于表示大于 `Number.MAX_SAFE_INTEGER` 的整数。
- **基本用法**：
  - 在整数字面量后加上 `n`，例如 `123n`。
  - 调用 `BigInt()` 函数进行转换。
  - 创建后，可以像普通数字一样直接使用 `+`、`-`、`*`、`/` 等运算符进行计算。
- **核心优势**：
  - **原生支持**：在主流浏览器和 Node.js 环境中均可使用，性能通常优于手动实现的字符串模拟。
  - **语法简洁**：代码可读性极高，一行代码即可完成大数运算。
  - **类型安全**：作为一种独立的数据类型，`BigInt` 不能与普通的 `Number` 类型混合运算，这在一定程度上避免了隐式转换带来的错误。
