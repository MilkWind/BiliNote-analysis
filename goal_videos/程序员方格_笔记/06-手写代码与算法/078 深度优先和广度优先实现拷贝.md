## 1. 面试题背景与核心概念 *Content-[00:00]
- **考察重点**：遍历算法（Traversal Algorithm）。
- **应用场景**：在现代前端框架（如 Vue、React 等）的底层源码中，存在大量遍历对象或数组的算法。掌握遍历算法有助于深入理解框架源码，是前端面试中的高频考点。
- **主要算法分类**：
  - **深度优先搜索**（Depth-First Search, 简称 **DFS**）。
  - **广度优先搜索**（Breadth-First Search, 简称 **BFS**，也称宽度优先）。

## 2. 深度优先（DFS）与广度优先（BFS）思想解析 *Content-[01:20]
- **面试题目**：请分别使用深度优先思想和广度优先思想，实现一个对象/数组的深拷贝函数。
- **深拷贝的复杂性**：
  - 基本数据类型（如数字、字符串）或特殊对象（如 Date、RegExp）的拷贝相对简单。
  - 复杂对象拷贝的难点在于：对象内部可能嵌套其他对象或数组，需要递归处理其所有子属性，确保完全独立的副本。
- **DFS（深度优先）思想**：
  - **核心逻辑**：追求“深度”，即沿着一个属性一直向下探查，直到最深层级（叶子节点），然后再回溯处理同级其他属性。
  - **示例**：对于对象 `A` 包含 `B`，`B` 包含 `C`，`A` 还包含并列的 `A2`（数组）。DFS 会先拷贝 `A`，接着深入拷贝 `B`，再深入拷贝 `C`，最后再处理 `A2`。
- **BFS（广度优先）思想**：
  - **核心逻辑**：追求“广度”，即按“层”进行遍历。先处理当前层级的所有属性，再进入下一层级。
  - **示例**：对于上述结构，BFS 会先拷贝第一层的 `A` 和 `A2`，然后再进入第二层拷贝 `B`，最后进入第三层拷贝 `C`。

## 3. 深度优先（DFS）深拷贝实现思路 *Content-[05:14]
- **核心思想**：针对某一个属性，将其所有层级的子集全部拷贝过来，通常采用**递归**的方式实现。
- **具体实现步骤**：
  1. **边界条件处理**：
     - 检查传入参数是否为空（`null` 或 `undefined`），若是则直接返回。
     - 检查是否为特殊对象（如 `Date`、`RegExp`），若是则直接返回对应的拷贝结果。
  2. **使用 WeakMap 解决循环引用**：
     - 创建一个 `WeakMap` 用于存储已拷贝过的对象（作为 Hash 表）。
     - **WeakMap 的优势**：
       - Key 值是唯一的，自动去重，无需手动处理重复引用。
       - Key 可以是对象或数组（引用类型），完美契合深拷贝中记录对象引用关系的需求。
       - 弱引用特性有助于垃圾回收，防止内存泄漏。
     - 在拷贝前，先检查 `WeakMap` 中是否已存在该对象，若存在则直接返回已拷贝的引用，避免死循环。
  3. **创建目标容器**：
     - 判断传入的是数组还是普通对象，并创建对应的空数组 `[]` 或空对象 `{}`。
     - 将原对象与新对象的映射关系存入 `WeakMap` 中（`map.set(obj, newObj)`）。
  4. **递归遍历与拷贝**：
     - 使用 `for...in` 或 `Object.keys()` 遍历原对象的所有属性。
     - 判断属性值是否为对象/数组：
       - 如果是基本类型，直接赋值。
       - 如果是引用类型，则递归调用深拷贝函数，并将结果赋值给新对象的对应属性。

## 4. 广度优先（BFS）深拷贝实现思路 *Content-[11:11]
- **核心思想**：按层级进行拷贝，不追求单条路径的深度，而是先处理同一层级的所有节点。通常借助**队列（Queue）** 来实现，避免使用递归。
- **具体实现步骤**：
  1. **初始化与边界处理**：
     - 同样使用 `WeakMap` 记录已拷贝的对象，防止循环引用。
     - 处理 `null`、`undefined`、`Date`、`RegExp` 等边界情况。
  2. **构建队列**：
     - 创建一个队列（数组模拟），将初始的源对象和目标对象打包（如 `{ source: obj, target: newObj }`）推入队列。
  3. **循环处理队列**：
     - 当队列不为空时，循环从队列头部取出一个节点（`shift()`）。
     - 解构获取当前节点的 `source`（原对象属性）和 `target`（新对象属性）。
  4. **逐层遍历与入队**：
     - 遍历 `source` 的所有属性。
     - 判断属性值类型：
       - 如果是基本类型，直接赋值给 `target` 的对应属性。
       - 如果是引用类型（对象/数组）：
         - 检查 `WeakMap` 是否已处理过，若已处理则直接赋值。
         - 若未处理，则创建对应的新容器（`[]` 或 `{}`），存入 `WeakMap`，并赋值给 `target`。
         - **关键步骤**：将新创建的 `{ source: 子原对象, target: 子新对象 }` 推入队列尾部，等待下一轮循环处理。

## 5. 运行效果对比与核心总结 *Content-[13:33]
- **遍历顺序对比**：
  - **DFS**：先深入拷贝子对象，处理完所有后代节点后，再处理兄弟属性。（例如：先拷贝 `B1`，再深入拷贝 `B1` 内的 `D1`，最后再处理 `B2`）。
  - **BFS**：先拷贝当前层级的所有属性，然后再逐层深入到具体的子对象。（例如：先拷贝第一层的 `C1`、`C2`，再进入第二层处理内容）。
- **核心区别与优缺点**：
  1. **代码实现**：
     - **DFS**：使用递归，代码逻辑更加简洁、直观。
     - **BFS**：使用队列迭代，避免了递归调用。
  2. **内存与性能**：
     - **DFS**：如果对象嵌套层级极深，递归调用栈会非常深，可能导致**调用栈溢出（Stack Overflow）**。
     - **BFS**：使用队列在堆内存中存储节点，避免了栈溢出问题，但可能会消耗更多的**堆内存（Heap Memory）**。
  3. **实际应用场景**：
     - 在绝大多数前端实际开发和框架源码中，**DFS（深度优先）** 的使用频率更高，因为其代码可读性更好，且一般业务数据的嵌套深度在可控范围内。

## AI 总结
本题深入探讨了前端面试中经典的“深拷贝”算法实现。核心在于理解 **DFS（深度优先）** 与 **BFS（广度优先）** 在遍历策略上的本质差异：DFS 采用递归一到底，代码简洁但存在栈溢出风险；BFS 采用队列按层迭代，避免了递归缺陷但会消耗更多堆内存。在实际开发中，借助 `WeakMap` 解决循环引用是深拷贝的标配，而由于业务数据嵌套深度通常有限，DFS 凭借其高可读性成为更主流的选择。掌握这两种思想，不仅能应对面试，更能帮助开发者深刻理解前端框架底层的数据响应式与虚拟 DOM _diff_ 算法。
