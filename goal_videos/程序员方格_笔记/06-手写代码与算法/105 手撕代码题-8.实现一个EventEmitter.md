## 面试核心考点解析 *Content-[00:00]

手写 `EventEmitter` 是前端面试中的高频常考题，主要考察候选人的 JavaScript 基础以及设计模式思想。要写出一个让面试官眼前一亮的满分答案，需要把握以下两个核心关键点：

- **API 设计**：面试官希望看到你了解一个标准的 `EventEmitter` 应该具备哪些核心方法。必须精准设计并实现以下四个缺一不可的方法：
  - `on`：用于订阅事件。
  - `emit`：用于触发事件。
  - `off`：用于取消订阅。
  - `once`：用于订阅只执行一次的特殊事件。
- **边界情况处理**：这是区分普通代码与优秀代码的关键，体现了代码的严谨性和工程经验。需要深入思考并处理以下细节：
  - 如果同一个事件被监听了多次（重复订阅）该如何处理？
  - 在 `emit` 触发时，如何确保参数正确无误地传递给回调函数？
  - 回调函数执行时，`this` 的指向应该指向谁？
  - 事件监听后如果不及时释放，是否会造成内存泄漏？

## 核心数据结构设计 *Content-[01:36]

实现 `EventEmitter` 的第一步是设计核心骨架，即选择合适的核心数据结构来存储事件及其对应的回调函数。

- **推荐方案**：使用 `Map` 结合 `Set` 的数据结构。
- **Map 的作用**：用于存储所有的事件。
  - `key`：事件名称（如 `click` 或自定义的事件名）。
  - 优势：`Map` 在根据 `key` 查找 `value` 时，时间复杂度为 O(1)，查找速度极快，不受注册事件数量的影响。
- **Set 的作用**：作为 `Map` 的 `value`，用于存储回调函数的集合。
  - 优势：`Set` 数据结构中的元素具有唯一性。这天然地解决了重复订阅的问题，同一个回调函数无论被订阅多少次，在 `Set` 中都只会存储一份。

通过 `Map` + `Set` 的简单组合，同时实现了高效查找（O(1)）和自动去重两个重要特性。

## 核心 API 实现：on 与 emit *Content-[02:54]

有了完善的数据结构后，即可开始编写最核心的“一存一取”方法：`on`（生产者）和 `emit`（消费者）。

- **on 方法（订阅事件）**：
  - 接收参数：`event`（事件名）和 `callback`（回调函数）。
  - 执行逻辑：首先检查 `Map` 中是否已存在该事件名。如果不存在，则创建一个新的 `Set` 并将其存入 `Map`。最后，将传入的 `callback` 添加到对应事件的 `Set` 集合中。
- **emit 方法（触发事件）**：
  - 接收参数：`event`（事件名）和 `...args`（使用剩余参数语法接收任意多个参数）。
  - 执行逻辑：首先检查该事件是否被订阅过，如果没有订阅则直接 `return`，不做任何处理。如果已订阅，则从 `Map` 中取出对应的 `Set`，遍历 `Set` 中的每一个回调函数并执行，同时将 `args` 原封不动地传递给这些回调函数。

## 完善 API：off 与 once 的实现 *Content-[04:33]

为了让 `EventEmitter` 功能更加完备，需要实现取消订阅和单次订阅的方法。

- **off 方法（取消订阅）**：
  需要根据传入参数的不同处理两种情况：
  - **情况一（只传事件名）**：意味着用户想取消该事件的所有订阅。直接调用 `delete` 方法，从 `Map` 中将该事件彻底删除即可。
  - **情况二（同时传入事件名和回调函数）**：意味着用户只想取消特定的监听。此时需要从对应的 `Set` 中，精准地 `delete` 掉该特定的回调函数。
- **once 方法（只执行一次）**：
  这是面试官非常喜欢考察的技巧点，核心在于**包装函数（Wrapper）思想**。
  - 不能直接将用户的 `callback` 传入 `on` 方法，而是需要创建一个 `wrapper` 包装函数。
  - 在 `wrapper` 函数内部，首先执行用户真正的 `callback`，并传入 `args` 参数。
  - **关键步骤**：在 `callback` 执行完毕后，立刻调用 `off` 方法，将 `wrapper` 这个临时监听器从订阅列表中移除。
  - 最后，将包装好的 `wrapper` 函数传入 `on` 方法进行订阅。这样当事件第一次触发时，`wrapper` 执行并自我销毁，后续再次 `emit` 同一事件时，该监听器已不存在，完美实现只触发一次的效果。

## 进阶优化：打造满分代码 *Content-[06:54]

在实现基础功能后，通过以下三个细节优化，可以瞬间提升代码质量，展现出高级开发工程师的工程素养：

- **链式调用**：
  让 `on` 和 `off` 方法在执行完毕后返回 `this`。这样用户就可以写出 `emitter.on().on().off()` 这样优雅的链式调用代码。
- **错误处理**：
  在 `emit` 方法遍历执行回调函数时，给每个 `callback` 包裹一层 `try...catch`。这样可以确保某个监听器内部报错时，不会导致整个事件系统崩溃，其他回调函数依然能够正常执行，大幅提升代码的健壮性和兼容性。
- **内存优化**：
  在 `off` 方法执行后增加一个判断逻辑：如果该事件对应的 `Set` 的 `size` 变为了 0（即所有监听器都被取消），则顺手将该事件名从 `Map` 中彻底删除。这可以避免 `Map` 中残留空集合的映射，防止日积月累造成内存泄漏隐患。

## 面试满分策略总结 *Content-[08:22]

想要在手写 `EventEmitter` 这道题中拿到满分，建议遵循以下策略：

- **数据结构**：选用 `Map` + `Set`，完美兼顾 O(1) 的查找效率和回调函数的自动去重。
- **核心 API**：精准实现 `on`、`emit`、`off`、`once` 四个方法。特别是要深刻理解并手动练习 `once` 方法中的包装函数思想。
- **边界处理**：不要等面试官提醒，要主动提出并实现链式调用、错误处理（`try...catch`）以及内存优化（清理空 Set）等关键点，全方位展示你的工程素养和深层思考。
