## Vue3 响应式系统升级 Proxy *Content-[00:00]

Vue3 采用 `Proxy` 替代了 Vue2 中的 `Object.defineProperty`，主要原因及优势如下：

- **代理范围更广**：`Proxy` 可以代理整个对象，同时支持代理数组、`Map`、`Set` 等数据结构。而 `Object.defineProperty` 只能对对象的属性进行代理，天然存在缺陷。
- **监听操作更多**：`Proxy` 能够监听属性的删除、原型链上的操作等，这些是 `defineProperty` 无法做到的，使得 Vue3 的响应式系统更加强大和灵活。
- **依赖收集机制优化（懒收集）**：
  - `defineProperty` 需要递归遍历对象的属性，且在初始化时必须全部收集完毕。
  - `Proxy` 直接代理整个对象，只有当对象的属性被读取时才会进行依赖收集。这种“懒收集”机制使得 Vue3 的性能显著优于 Vue2。

## 路由守卫的作用与分类 *Content-[01:14]

路由守卫主要用于在路由跳转前后执行特定的逻辑，分为全局守卫和单个路由守卫：

- **全局守卫**：
  - 通过 `router.beforeEach`（前置守卫）或 `router.afterEach`（后置钩子）进行注册。
  - **前置守卫**：在路由跳转前触发，每次路由变化都会执行。常用于权限校验，例如判断用户是否登录，未登录则拦截并跳转至登录页。
  - **后置钩子**：在页面跳转完成后执行。常用于记录用户访问页面的日志等非阻塞性操作。
- **单个路由守卫**：
  - 针对特定的单独路由定义跳转前和跳转后的钩子，作用范围仅限于该特定路由。

## Vue3 Composition API 与 React Hooks 的区别 *Content-[02:12]

Vue3 的 Composition API 借鉴了 React Hooks 的思想，但两者在底层机制和使用规则上有显著区别：

- **调用规则限制**：
  - React Hooks 不能在循环、条件判断或嵌套函数中调用，必须保证在 React 函数的顶部调用。
  - Vue Composition API 不需要考虑调用顺序，可以灵活地在循环、条件判断中使用。
- **依赖管理机制**：
  - React 的 `useEffect` 和 `useMemo` 需要开发者手动确定依赖关系（俗称“手动挡”）。
  - Vue 的响应式系统会自动进行依赖收集（俗称“自动挡”），无需手动维护依赖数组。
- **性能与内存回收**：
  - React 每次重新渲染都需要调用 Hook，导致 GC（垃圾回收）内存回收压力更大，性能相对 Vue 可能较差。

## 虚拟 DOM 的概念与作用 *Content-[04:00]

虚拟 DOM 是对真实 DOM 的补充和增强，在渲染过程中，Vue 会添加一些属性或标记以方便内部处理。

- **解决浏览器性能问题**：传统 DOM 操作非常慢，轻微的操作都可能导致页面重排，极度耗费性能。
- **状态跟踪与 Diff 算法**：虚拟 DOM 能够很好地跟踪 DOM 状态。它根据当前数据生成描述 DOM 结构的虚拟节点，当数据变化时，利用 Diff 算法计算新旧虚拟 DOM 之间的差异，从而避免不必要的真实 DOM 操作，提升页面性能。
- **其他核心优势**：
  - **代码抽象**：对真实 DOM 进行抽象，帮助开发者写出更优雅的代码。
  - **跨平台支持**：由于不直接依赖浏览器 DOM，虚拟 DOM 可以支持跨平台渲染（如移动端原生渲染）。

## 虚拟 DOM 性能对比与 Vue3 Diff 算法变化 *Content-[05:42]

### 虚拟 DOM 真的比真实 DOM 性能好吗？
- 虚拟 DOM 提供的是基本的性能兜底（类似自动挡与手动挡的区别）。
- 在极端的细微操作下，手动操作真实 DOM 确实更快；但整体来看，虚拟 DOM 驱动的性能完全够用。日常开发中极少需要手动编写 JS 操作 DOM，只需优化数据结构和渲染流程即可。

### Vue3 Diff 算法的优化
- **Vue2 Diff 算法**：使用双端交叉对比（头跟头、头跟尾、尾跟尾、尾跟头），时间复杂度为 $O(1)$（注：视频口误为 $O(1)$，实际理论复杂度为 $O(n)$）。
- **Vue3 Diff 算法**：保留了头跟头、尾跟尾的对比，剩余部分引入了**最长递增子序列**算法。时间复杂度为 $O(n \log n)$。
- **性能权衡**：Vue3 牺牲了部分 JS 运算性能，但大幅减少了 DOM 元素的移动。在浏览器中，DOM 移动对性能的影响远大于 JS 耗时，因此 Vue3 的 Diff 算法在多数场景下性能更优异。

## Vue 中 key 的作用及注意事项 *Content-[07:53]

- **核心作用**：`key` 主要用于数组节点的复用，帮助 Diff 算法准确识别和追踪节点身份。
- **注意事项**：强烈不建议使用 `index` 作为 `key`。当数组节点发生移动（例如将尾部元素移到头部）时，会导致所有元素的 `index` 发生变化，从而破坏节点的复用机制，引发不必要的 DOM 更新和潜在的状态错误。

## Vue 未采用 React 时间分片思想的原因 *Content-[08:09]

尤雨溪曾在英文社区分享过 Vue 没有引入 React 时间分片（Time Slicing）思想的 4 点核心原因：

1. **解决 CPU 计算问题的必要性不同**：React 的架构导致更新时存在过多的计算，即使提供了性能优化 API，开发者仍可能写出性能较差的代码。Vue 通过响应式系统避免了这种过度计算。
2. **更新粒度与编译优化**：Vue 是依赖跟踪，默认只做组件级别的更新计算；而 React 每次更新都是自顶向下遍历所有 Fiber 数据结构。此外，Vue 通过 `template` 编译，可进行静态编译优化（如静态节点提升/缓存）；React 的 JSX 是动态的，无法进行此类优化。
3. **时间分片带来的额外开销**：React 引入时间分片带来了额外的任务协调计算开销。虽然使用了最小堆等算法优化，但内部仍有大量 JS 计算。Vue 没有时间分片，无需担忧此性能损耗。
4. **人眼感知阈值**：人眼对 100ms 以下的响应时间并不敏感。Vue 的更新很少出现 100ms 以上的计算（因为是组件级别且自动收集依赖），引入时间分片的收益并不划算。

## React 无法进行静态节点标记优化的原因 *Content-[11:34]

React 无法像 Vue3 那样进行静态节点标记优化，根本原因在于语法本质的差异：

- **语法动态性**：React 使用 JSX，本质是写 JS，JS 是高度动态的；Vue 使用 `template`，是声明式语法，标记有限（如 `v-if`），非常容易进行优化分析。
- **静态分析难度**：JS 语言中开发者可以编写任意复杂的逻辑，想做静态分析极其困难。
- **Bug 风险**：`template` 中逻辑相对简单，不易产生复杂 Bug；而 JSX 中可能存在各种 JS 逻辑 Bug，导致 React 无法安全、准确地进行静态节点标记优化。
