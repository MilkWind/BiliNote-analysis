## 1. 课程背景与核心目标 *Content-[00:00]

在 Vue 开发中，副作用清理是一个常见但极易被忽略的问题。开发者在开发时经常会遇到以下两种典型场景：
- **定时器残留**：切换页面之后，之前的定时器仍在后台疯狂运行。
- **搜索结果错乱**：在输入框或搜索框中输入过快时，页面显示的是之前某个关键词的旧搜索结果，而不是最新的。

这些问题的根源往往在于**副作用（如定时器、事件监听、网络请求等）没有被正确清理**。

本节课的核心目标旨在解决以下三个关键问题：
1. 副作用应该在什么时候被清理？
2. 清理的代码具体应该怎么写？
3. 如何验证你的清理逻辑确实已经生效？

## 2. 副作用的概念与清理时机 *Content-[00:51]

### 副作用的概念
在 Vue 中，像 `watch` 或者 `watchEffect` 这样的响应式函数，我们统称为**副作用**。它们的核心特点是：当其依赖的数据发生变化时，这个副作用函数就会重新执行一次。

### 清理的两个关键时刻
副作用的清理逻辑主要发生在以下两个关键时刻：
1. **重新执行前**：副作用函数准备下一次重新执行之前。
2. **销毁时**：当组件卸载，或者副作用所在的作用域被销毁的时候。

### 完整的生命周期时间线
为了更好理解，我们可以将副作用的生命周期划分为以下步骤：
- 首先，创建一个副作用。
- 当依赖发生变化时，在准备重新创建一个新的副作用之前，Vue 会先帮我们执行清理逻辑。
- 接着，把旧的副作用清理掉。
- 最后，重建新的副作用。
这就是副作用从“创建”到“清理”再到“重建”的一个完整闭环过程。

## 3. 场景一：定时器的副作用清理 *Content-[02:00]

### 问题描述：定时器叠加导致性能问题
在修改定时器间隔的场景中，如果不断改变定时器的间隔时间，每次调整都会创建一个新的 `setInterval`。如果旧定时器没有被停掉，它们就会在后台叠加运行。
- **后果**：数据错乱显示，持续消耗 CPU 资源，久而久之会造成严重的页面卡顿。例如，期望间隔 2 秒执行，但由于多个定时器叠加，实际运行逻辑完全混乱。

### 解决方案：使用 `onInvalidate`
Vue 提供了 `onInvalidate` 方法来处理此类问题。
- **实现方式**：在 `watchEffect` 的回调函数中，会接收一个 `onInvalidate` 函数（即清理函数）。我们在这个清理函数内部执行 `clearInterval` 逻辑，将上一个创建的定时器清除掉。
- **执行机制**：注册了 `onInvalidate` 后，它会在下一次 `watchEffect` 回调执行之前被自动调用。

### 验证效果
开启清理开关后，不断调整间隔时间：
- 页面 tick 的速度趋于稳定，永远按照设置的最新时间间隔跳动。
- 观察控制台，每次间隔变化时，都会先打印出一条 `clearInterval` 的日志，证明旧定时器已被成功清除。

### 核心模式总结
- **谁创建，谁清理**：创建副作用的逻辑和清理副作用的逻辑应该放在一起。
- **清理时机**：下一次副作用即将执行之前。
- **注意事项**：千万不要跨作用域去持有定时器的引用，以避免产生悬挂的、无法被清理的副作用。

## 4. 场景二：异步请求的竞态问题与清理 *Content-[05:10]

### 问题描述：异步请求的竞态条件（结果倒挂）
在搜索框快速输入关键字时，由于网络延迟是不可预测的，连续发送的多个请求可能会出现乱序返回的情况。
- **后果**：一个较早发出但响应很慢的旧请求，可能在最后才返回结果，从而覆盖掉真正想要的最新搜索结果。这被称为“竞态问题”或“结果倒挂”。

### 解决方案 1：使用 `AbortController`
- **实现方式**：在 `watch` 回调中，每次都创建一个新的 `AbortController` 实例。
- **清理逻辑**：利用 `onInvalidate`，在其清理函数中调用 `controller.abort()`。
- **效果**：当用户输入新的关键词时，上一次还没完成的请求会被立即终止，确保只处理最新请求。

### 解决方案 2：Token 验证法
- **实现方式**：每次发起请求时携带一个唯一的标记（Token）。
- **清理逻辑**：当请求结果返回时，进行校验，只接受持有最新标记的响应，直接忽略掉过期的旧结果。
- **效果**：与 `AbortController` 类似，都能有效防止旧数据覆盖新数据。

### 验证效果
开启清理开关并快速输入内容后：
- 状态栏明确提示“已终止旧请求”。
- 展示的结果始终都是最后一次输入的最新内容，数据再也不会发生倒退。

## 5. 补充概念：其他清理方式与核心原则 *Content-[07:39]

### `watch` 的 `stop` 方法
`watch` 函数本身会返回一个 `stop` 函数。开发者可以手动调用这个 `stop` 函数，来让监听器停止执行。

### 组合式函数中的清理：`onScopeDispose`
在封装组合式函数（Composables）时，更推荐使用 `onScopeDispose` 方法来注册清理逻辑。
- **优势**：当使用这个组合式函数的组件被销毁时，该函数注册的清理函数就会被自动执行，帮助你安全地释放掉所有资源。

### 最核心的原则
无论使用上述哪一种方式，都必须牢记一个最重要的原则：
**在创建副作用的那个最近的作用域里，去注册它的清理逻辑。** 这是最安全、最稳妥的做法。

## 6. 课程总结与最佳实践 *Content-[08:30]

在视频的最后，对 Vue 副作用清理逻辑的核心要点进行快速梳理：

1. **明确清理时机**：
   - 副作用在重新执行前（重跑前），以及组件被销毁时，都要做一次清理。
   - 使用 `onInvalidate` 或 `onScopeDispose` 来接收和执行清理逻辑。

2. **坚持“谁创建谁清理”**：
   - 定时器、订阅方法等，清理代码一定要放在它创建的地方。
   - 避免跨作用域的引用一直悬挂，防止产生无法清理的代码隐患。

3. **妥善处理异步请求**：
   - 使用 `AbortController` 取消旧请求，或使用 Token 验证法过滤过期响应。
   - 核心目的是防止“结果倒挂”（即旧请求的结果比新请求晚到，覆盖了新请求的结果）。

**实践收益**：严格照着这几条原则去实践，大部分的内存泄漏、竞态覆盖、性能抖动等前端常见问题都能被有效避免。

本节课深入探讨了 Vue 开发中副作用清理的核心机制与最佳实践。主要涵盖了三大核心内容：首先，明确了副作用（如 `watch`、`watchEffect`）的清理时机，即在副作用重跑前和组件销毁时；其次，通过定时器叠加和异步搜索竞态两个经典场景，详细讲解了如何使用 `onInvalidate`、`AbortController` 以及 Token 验证法来清理旧状态和取消过期请求，防止内存泄漏和结果倒挂；最后，强调了“谁创建谁清理”以及“在最近作用域内注册清理逻辑”的核心原则，并补充了 `onScopeDispose` 在组合式函数中的应用。掌握这些技巧对于提升 Vue 应用的性能和稳定性至关重要。
