## 面试题解析与核心考点 *Content-[00:00]

- **面试题目**：聊一聊 Vue3 的双向数据绑定，Model 如何改变 View，View 又如何改变 Model 层？它们的数据是如何通讯的？
- **考察重点**：
  - 考察应聘者对双向数据绑定机制底层工作原理的深入理解。
  - 重点在于 Vue3 底层如何实现双向绑定，而不仅仅是停留在表面 API 的使用层面。
- **回答思路**：
  - 需要掌握 Model 层的数据设计，以及如何将其关联到视图层（View）。
  - 需要掌握视图层（View）组件的数据变化，如何反向影响到 Model 层。

## Model 到 View 的同步原理 *Content-[02:02]

探讨 Model 层数据修改后，如何直接同步到视图层并触发视图更新。

1\. **创建响应式数据**
- 使用 `reactive` 以及 `ref` 函数来创建响应式数据。
- 数据源必须被这两个函数包裹，才能具备响应式特性，这是实现双向绑定的前提。

2\. **底层 Proxy 代理与拦截**
- `reactive` 或 `ref` 在底层实际上使用了 `Proxy` 来包装目标对象。
- `Proxy` 的核心优势在于可以拦截对象所有的读（`get`）和写（`set`）操作。
- 拦截的含义是在执行实际的读写动作前将其“拦下”，先执行一些额外的逻辑处理，然后再进行真正的读写。

3\. **依赖收集（Track）**
- 当响应式数据被放置在视图层（模板）中时，模板编译过程会触发对数据的读取操作。
- 读取操作会精准触发 `Proxy` 中的 `get` 拦截器。
- `get` 拦截器内部会调用 `track` 函数。
- `track` 函数的作用是将当前组件的渲染副作用函数（Effect）注册到依赖图（依赖集合）中，从而完成**依赖收集**。这一步明确了“哪些视图依赖于这个数据”。

4\. **触发更新（Trigger）**
- 当响应式数据被修改（例如通过代码执行 `count++`）时，会触发 `Proxy` 中的 `set` 拦截器。
- `set` 拦截器内部会调用 `trigger` 函数。
- `trigger` 函数会根据被修改的属性名，从依赖图中找到之前收集到的对应副作用函数（渲染函数）并执行。
- 副作用函数执行后，UI 会自动更新，从而完成 Model 到 View 的单向同步。

## View 到 Model 的同步原理 *Content-[09:12]

探讨视图层（View）的数据变化如何同步到 Model 层。

1\. **原生表单元素中的 `v-model`**
- 在原生输入框（如 `<input>`）中使用 `v-model` 本质上是一个语法糖，等价于**绑定值 + 监听事件**的组合。
- 当用户在视图层输入内容时，会触发 `input` 事件。
- 事件处理函数会将输入的新值赋给响应式数据（例如 `state.count = newValue`）。
- 这一赋值操作会直接触发 `Proxy` 中的 `set` 拦截器。
- `set` 拦截器随后调用 `trigger` 重新渲染组件，将新值渲染到视图层中，完成闭环。

2\. **自定义组件中的 `v-model`**
- 在自定义组件中使用 `v-model`，本质上等价于传递 `modelValue` prop 并监听 `update:modelValue` 自定义事件。
- 当子组件内部状态变化时，会通过触发自定义事件（如 `emit('update:modelValue', newValue)`）通知父组件。
- 父组件接收到事件信号后，更新自身绑定的响应式数据。
- 父组件数据的更新同样会触发 `Proxy` 的 `set` 拦截器，进而执行对应的渲染函数，完成视图的重新渲染。

## 核心机制总结 *Content-[12:56]

- **核心枢纽**：无论是 View 更新 Model，还是 Model 更新 View，其核心都依赖于 **`Proxy` 代理机制**。
- **响应式基础**：在构建响应式数据时，使用 `ref` 或 `reactive` 函数，这意味着数据必然被 `Proxy` 代理。
- **双向流程**：
  - **读取时（View 渲染/编译）**：触发 `get` 拦截器，执行 `track` 收集依赖。
  - **修改时（Model 赋值/View 交互）**：触发 `set` 拦截器，执行 `trigger` 触发更新。
- **答题关键**：在面试中回答此题时，务必突出 `Proxy` 的代理机制，以及 `get`（收集依赖）和 `set`（触发更新）这两个核心拦截器的具体作用。

## AI 总结

Vue3 的双向数据绑定核心依赖于 `Proxy` 代理机制。通过 `reactive` 和 `ref` 创建响应式数据时，底层使用 `Proxy` 拦截数据的读写操作。当视图层读取数据时，触发 `get` 拦截器并调用 `track` 收集依赖；当数据被修改（无论是通过 Model 层直接赋值，还是通过 View 层的 `v-model` 语法糖触发事件更新数据），都会触发 `set` 拦截器并调用 `trigger` 执行对应的副作用函数，从而实现视图的自动更新。理解 `Proxy` 的拦截机制以及 `track` 和 `trigger` 的协作流程，是回答该面试题的关键。
