## 1. Vue3 项目初始化与 Vite *Content-[00:00]
- **构建工具 Vite**：Vue3 推荐使用 Vite 作为新一代构建工具，初始化非常简单。
- **创建项目**：通过命令行 `npm create vite` 快速创建 Vue3 项目。
- **核心配置文件**：
  - `vite.config.js`：项目配置文件，可通过 `defineConfig` 添加相关插件（如 `@vitejs/plugin-vue`）。
  - `package.json`：包含 `dev`（启动开发服务器）、`build`（构建生产环境包）等常规脚本。
- **项目入口**：`src` 目录下的 `main.js` 为应用入口，`App.vue` 为根组件。

## 2. Vue3 多实例与多根节点特性 *Content-[02:11]
- **多实例支持**：
  - Vue2 只能声明单个实例，而 Vue3 在声明入口处可以声明多个实例。
  - **错误隔离**：多个实例之间存在错误隔离机制，如果没有阻断性错误，一个实例的异常不会影响其他实例。
- **多根节点（Fragment）**：
  - 组件模板支持多个根节点（例如同时存在 `<app>` 和 `<root>`）。
  - 每个实例都可以挂载到不同的 DOM 节点上，提升了模板编写的灵活性。

## 3. Composition API 与 Options API 对比 *Content-[03:18]
- **Options API（选项式/配置式）痛点**：
  - 按照 `data`、`computed`、`methods`、生命周期（`created`、`mounted` 等）进行配置式划分。
  - 随着业务复杂度提升，单文件代码会变得“又长又臭”，逻辑分散在不同区域，维护困难。
- **Mixins 的局限性**：
  - Vue2 使用 Mixins 解决逻辑复用，但存在明显痛点：命名冲突、暴露的变量来源不清晰、逻辑复用性差。
- **Composition API（组合式）优势**：
  - 将零散分布的逻辑组合在一起维护，支持将特定功能逻辑单独拆分为独立模块。
  - 实现了 UI 复用与状态逻辑复用的分离。
  - 相比选项式 API，组合式 API 更加灵活，代码组织更清晰。

## 4. setup 函数详解 *Content-[07:49]
- **核心定位**：`setup` 是 Vue3 为组件提供的新属性，也是 Composition API 的统一入口函数。
- **执行时机**：在 `beforeCreate` 和 `created` 生命周期钩子之前执行（Vue3 实际上取消了这两个钩子）。
- **this 指向**：`setup` 函数中**没有 `this`**，不能使用 `this.data` 或 `this.methods` 等方式获取实例属性。
- **函数参数**：
  - `props`：接收父组件传递的属性，是响应式的且不可直接修改。
  - `context`：上下文对象，包含 `attrs`（非响应式属性）、`slots`（插槽）、`emit`（触发事件）。它是一个普通 JS 对象，可以安全地进行 ES6 解构。

## 5. 响应式数据解构与 toRef 应用 *Content-[12:48]
- **Props 解构丢失响应性**：
  - 直接对 `props` 进行 ES6 解构会导致其失去响应性（父组件更新时子组件不会更新）。
  - **解决方案**：使用 `toRef` 提取属性，例如 `const title = toRef(props, 'title')`，通过 `title.value` 访问即可保持响应性。
- **Reactive 对象解构问题**：
  - 对 `reactive` 创建的对象进行解构同样会丢失响应性。
  - 使用 `toRef` 提取出的 ref 对象，修改其 `.value` 会同步更新原 `reactive` 对象，反之亦然，两者建立了响应式连接。
- **组合式函数传参**：
  - 向 `useCounter` 等组合式函数传递响应式数据时，必须使用 `toRef` 进行包裹，否则传入的普通值会丢失响应性。

## 6. 核心响应式 API 详解 *Content-[19:03]
- **ref**：
  - 用于创建基本数据类型（如数字、字符串）的响应式数据对象。
  - 必须通过 `.value` 属性来访问和修改值。
- **isRef**：
  - 用于判断一个变量是否是由 `ref` 创建的响应式对象。
- **reactive**：
  - 用于创建对象或数组的响应式数据对象。
  - 基于 `Proxy` 实现，会递归处理嵌套属性，使其全部具备响应性。
- **toRef**：
  - 将响应式对象中的**某个特定属性**转换为 `ref` 对象。
- **toRefs**：
  - 将响应式对象中的**所有属性**转换为 `ref` 对象。
  - 常用于安全解构整个 `reactive` 对象，确保解构后的每个属性依然保持响应性。

## 7. reactive 与 shallowReactive 性能对比 *Content-[25:19]
- **reactive（深层响应式）**：
  - 递归处理所有嵌套属性（类似 Vue2 的 `Vue.observable`）。
  - 修改深层嵌套属性会触发视图更新。但如果对象嵌套过深，会消耗较多性能。
- **shallowReactive（浅层响应式）**：
  - 非递归处理，只监听对象第一层（表层）数据的变化。
  - 暴露嵌套对象的原始值，深层属性的修改不会触发响应式更新。
- **性能优化建议**：
  - 对于深层嵌套且只需频繁修改表层属性的对象，使用 `shallowReactive` 可显著提升性能。
  - 若需修改深层数据，建议采用整体替换（重建对象）的方式，而非直接修改深层属性。

## 8. computed 与 watch 的使用 *Content-[30:41]
- **computed（计算属性）**：
  - 用于缓存计算结果，只有当依赖的响应式数据发生变化时才会重新计算，是性能优化的重要手段。
  - 返回的是一个 `ref` 对象。
- **watch（侦听器）**：
  - 用于监听数据变化并执行副作用（如异步请求、DOM 操作）。
  - 可以监听一个或多个响应式值。
  - 回调函数中可获取 `newValue`（新值）和 `oldValue`（旧值）。
