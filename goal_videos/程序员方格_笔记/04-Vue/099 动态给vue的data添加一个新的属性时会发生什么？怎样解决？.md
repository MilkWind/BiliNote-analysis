## 问题引入与代码示例 *Content-[00:00]
- **问题背景**：在 Vue 开发中，如果动态给 Vue 实例的 `data` 添加一个新的属性，会发生什么？如何解决由此带来的问题？
- **代码示例场景**：
  - 在模板（`<template>`）中定义一个标签，使用 `v-for` 遍历 Vue 实例中的对象（例如 `obj`），并绑定对应的 `key` 和 `value`。
  - 添加一个 `<button>` 按钮，绑定 `@click` 事件（如 `addProperty`），用于触发动态添加新属性的操作。
- **Vue 实例构建**：
  - 实例化一个 Vue 对象，并挂载到指定的 DOM 节点。
  - 在 `data` 中定义一个包含旧属性（`oldProperty`）的对象。
  - 在 `methods` 中定义 `addProperty` 方法，通过 `this.obj.newProperty = '新属性值'` 的方式，直接为对象动态添加新属性，并在控制台打印更新后的对象。

## 现象分析：数据更新但视图未更新 *Content-[01:22]
- **实际运行现象**：
  - 点击按钮后，通过 `console.log` 打印发现，数据层面确实已经成功添加了新属性（对象中已经包含了 `newProperty`）。
  - **核心问题**：尽管数据已经更新，但页面上的视图并没有发生更新，新添加的属性没有渲染到 DOM 中，结果不及预期。
- **核心疑问**：为什么数据已经改变，但视图却没有同步更新？

## 原理解析：Vue 2 响应式原理的局限性 *Content-[03:48]
- **Vue 2 响应式原理**：
  - Vue 2 的响应式系统底层是通过 `Object.defineProperty` 来实现的。
  - 在 Vue 实例初始化时，它会遍历 `data` 中的所有属性，并使用 `Object.defineProperty` 将这些属性转换为 `getter` 和 `setter`。
  - **Getter**：相当于取值函数，用于在访问属性时收集依赖。
  - **Setter**：相当于设置函数，用于在属性值被修改时通知依赖进行视图更新。
- **动态添加新属性失效的原因**：
  - `Object.defineProperty` 只能对**对象已有的属性**进行拦截和劫持。
  - 当直接通过 `obj.newProperty = value` 为对象添加一个**全新**的属性时，Vue 无法拦截到这个新增操作。
  - 因为新属性没有经过 `Object.defineProperty` 的处理，它不具备响应式特征（没有对应的 `getter` 和 `setter`）。
  - 因此，修改或访问这个新属性时，不会触发依赖收集和更新通知，导致视图无法同步更新。
  - 除非手动重新遍历对象的所有属性，再次调用 `Object.defineProperty` 进行新一轮的响应式处理，但 Vue 内部并没有自动实现这一机制。

## 解决方案：如何正确添加响应式属性 *Content-[07:04]
- **核心原则**：Vue 不允许在已经创建的实例上，直接动态添加新的响应式属性。
- **解决方案**：为了实现数据与视图的同步更新，必须使用 Vue 提供的特定方法或 JavaScript 原生方法来使新属性具备响应式。主要有以下三种方式：
  1. **使用 `Vue.set` 或 `this.$set`**：
     - 这是 Vue 官方提供的方法，专门用于向响应式对象中添加新属性，并确保新属性同样是响应式的，且触发视图更新。
     - 语法示例：`Vue.set(this.obj, 'newProperty', 'value')` 或 `this.$set(this.obj, 'newProperty', 'value')`。
  2. **使用 `Object.assign`**：
     - 通过 `Object.assign` 创建一个新对象，将原对象和新属性合并，然后替换掉原对象。
     - 语法示例：`this.obj = Object.assign({}, this.obj, { newProperty: 'value' })`。
     - 这种方式通过替换整个对象触发了原对象引用的 `setter`，从而实现了响应式更新。
  3. **直接替换整个对象**：
     - 类似于 `Object.assign`，直接给该属性赋予一个包含新属性的全新对象，利用 Vue 对对象引用的监听来触发视图更新。
