## 1. 核心问题与结论 *Content-[00:02]
- **面试问题**：Vue 计算属性（`computed`）中的函数名和 `data` 中的属性可以同名吗？为什么？
- **核心结论**：**绝对不可以同名**。
- **直接原因**：在 Vue 中，会将 `data` 的属性和计算属性（`computed`）都挂载到 Vue 实例上。如果两者同名，就会发生命名冲突，导致实例当中的属性被覆盖，从而引发不可预知的错误。

## 2. 命名冲突的本质与原理 *Content-[01:10]
- **本质原因**：`data` 和 `computed` 最终都会作为 Vue 实例的属性存在。如果同名，Vue 无法区分到底该使用哪一个，从而产生冲突并触发 Vue 的重复定义警告。
- **Vue 实例化顺序**：在 Vue 初始化时，会按照一定的固定顺序将属性挂载到对应的 Vue 实例上。**后挂载的属性会覆盖先挂载的同名属性**。
- **具体挂载顺序**：
  1. `props`
  2. `methods`
  3. `data`
  4. `computed`
  5. `watch`
- **面试答题技巧**：在面试中回答此类问题，不能仅仅回答“不可以”，必须深入到源码和原理层面，讲清楚实例化的执行步骤和覆盖机制，这样才能凸显对 Vue 底层原理的深刻理解。

## 3. 属性优先级与数据覆盖 *Content-[02:55]
- **优先级规则**：`data` 的优先级高于计算属性（`computed`）。
- **模板渲染表现**：当 `data` 和 `computed` 中存在相同名称的属性时，在模板中使用该属性，会**优先使用 `data` 的数据**。
- **原因解析**：`data` 是直接存储数据的，而计算属性（`computed`）是基于 `data` 或者其他属性变化而计算得来的。因此，在发生冲突时，直接存储数据的 `data` 具有更高的优先级。

## 4. 避免命名冲突的最佳实践 *Content-[03:39]
为了保持代码的清晰和整洁，建议在项目实施时遵循以下最佳实践：
- **命名规范**：确保 `data` 和计算属性（`computed`）具有完全不同的命名，从源头上避免冲突。
- **模块化管理**：将各自的逻辑进行分模块管理，提高代码的可读性以及可维护性。
- **严格代码审查**：在代码审查（Code Review）阶段，重点关注并检查这些潜在的命名冲突问题，及时进行修正。
- **冲突提醒机制**：在开发运行环境中，如果存在命名冲突，Vue 通常会在浏览器控制台输出相关的告警信息（Warning），提醒开发者存在重复定义的问题，帮助开发者在开发阶段及时感知并修正。

## 5. 扩展：其他属性的命名冲突 *Content-[04:58]
- **`methods` 属性**：与计算属性类似，`methods` 中的方法也会被挂载到 Vue 实例上，因此同样应该避免与 `data` 或 `computed` 中的属性同名。
- **全局避免冲突**：不仅限于 `data` 和 `computed`，`props`、`methods`、`data`、`computed`、`watch` 等所有挂载到实例上的属性，都应尽量避免相互之间的命名冲突。
- **关于 `watch`**：虽然数据监听器（`watch`）与上述三大属性都有一定的关系，但它不直接参与对命名的冲突覆盖，不过在实际开发中仍需多加注意，保持命名的唯一性和清晰性。
