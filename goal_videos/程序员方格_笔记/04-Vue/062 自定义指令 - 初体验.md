## 1. 自定义指令的本质与官方定义 *Content-[00:00]
- **本质理解**：自定义指令的本质是开发者自己定义的、专门用来操作 DOM 的特殊指令。在实际开发或编写案例时，只要涉及到底层的 DOM 操作，就应该优先考虑使用自定义指令。
- **官方定义**：在有些情况下，我们仍然需要对普通 DOM 元素进行底层操作，这时候就会用到自定义指令。

## 2. 内置指令与自定义指令的对比 *Content-[01:34]
以手机购物 App 下单表单为例，对比两种指令的区别：
- **内置指令**：如 `v-model`、`v-if`、`v-for` 等。这些是 Vue 官方预先定义好的指令，开发者可以直接使用。它们相当于表单的默认功能（例如限制只能在 `input` 框内输入内容）。
- **自定义指令**：如 `v-focus`（自动获取焦点）、`v-only-number`（只能输入数字）。这些指令在 Vue 官方中并不存在，其名称由开发者自定义（需符合语义化）。它们相当于开发者为表单制定的“自定义购物规则”。

## 3. 实际应用场景与防抖处理 *Content-[04:03]
在实际开发中，内置指令往往无法满足所有需求，自定义指令可以处理更复杂的交互逻辑：
- **自动获取焦点**：页面加载后，光标自动在输入框内闪烁（如百度搜索框），无需用户手动点击，提升用户体验。
- **限制输入内容**：例如在购物车页面，购买数量只能输入数字，禁止输入字母或特殊字符。
- **按钮提交防抖处理**：
  - **目的**：避免用户连续、快速点击提交按钮，从而发送大量无必要的请求，减轻服务器压力。
  - **防抖原理**：设定一个时间阈值（例如 500ms）。当用户第一次点击提交按钮后，如果在 500ms 内再次点击，系统会清空上一次的计时并重新计时。只有当两次点击的间隔超过设定的时间阈值，才会真正执行提交操作。这样可以确保在高频点击下，请求只会被发送一次。

## 4. 自定义指令代码实战体验 *Content-[09:12]
通过实现一个“背景变色”的自定义指令，初步体验其用法与核心目的：
- **基础结构**：引入 Vue 2，构建基础 HTML 结构 `<div id="app"><p>hello Vue高频面试题</p></div>`。
- **定义局部自定义指令**：
  - 在 Vue 实例中使用 `directives` 选项来定义局部自定义指令。
  - `directives` 是定义局部自定义指令的关键字，不可修改。
  - 定义指令名称（如 `color`），其值为一个函数。该函数接收一个参数 `el`。
- **理解 `el` 参数**：`el` 代表绑定该指令的真实 DOM 元素。如果指令绑定在 `<p>` 标签上，`el` 就是该 `<p>` 标签的 DOM 对象。
- **使用自定义指令**：
  - 在需要操作的标签上添加指令，**必须加上 `v-` 前缀**（如 `v-color`）。这是 Vue 的硬性规定，无论指令名称是什么，前缀都不能省略。
- **执行 DOM 操作**：
  - 在指令函数内部，通过 `el` 直接操作 DOM。例如修改背景色：`el.style.backgroundColor = 'red'`。
- **核心目的**：自定义指令与函数一样，其核心目的是为了**复用**。将复杂的 DOM 操作逻辑封装在指令中，可以在多个元素上重复使用。
