## 1. v-show 案例演示与底层原理 *Content-[00:00]

- **案例背景**：以控制客厅灯的开关为例，演示 `v-show` 指令的实际效果与底层逻辑。
- **代码与交互过程**：
  - 页面结构中包含一个代表“客厅灯”的 `div` 元素，使用 `v-show="showLight"` 进行控制。
  - 初始状态下，变量 `showLight` 为 `true`，灯处于打开（显示）状态。
  - 点击“开关客厅的灯”按钮，将 `showLight` 切换为 `false`，页面上的灯在视觉上消失。
- **底层原理验证（关键步骤）**：
  - 打开浏览器开发者工具，检查 DOM 节点的变化。
  - 发现“客厅灯”的 `div` 节点**依然存在**，并没有被从 DOM 树中删除。
  - 观察其样式变化，发现该 `div` 被自动添加了 CSS 样式 `display: none`。
  - 再次点击按钮，将 `showLight` 切换为 `true`，`display` 属性恢复为 `block`，灯重新显示。
- **核心结论**：`v-show` 的本质是通过控制 CSS 的 `display` 属性（`none` 为隐藏，`block` 为显示）来实现元素的可见性切换，**DOM 元素始终存在于页面中**。这与 `v-if` 会直接删除和创建 DOM 节点有本质区别。

## 2. v-if 与 v-show 的核心区别 *Content-[05:43]

面试中必须掌握的四个核心区别点：

- **渲染机制**：
  - `v-if`：真正地删除和创建 DOM 节点（比喻：把家电直接收纳起来）。
  - `v-show`：仅隐藏 DOM 节点，元素始终保留在 DOM 树中（比喻：控制灯的开关，灯还在天花板上）。
- **切换性能**：
  - `v-if`：切换成本**高**，因为每次切换都涉及 DOM 的销毁与重新创建。
  - `v-show`：切换成本**低**，仅仅是修改 CSS 的 `display` 属性。
- **初始渲染成本**：
  - `v-if`：初始成本**低**。如果初始条件为 `false`，则完全不渲染该元素，节省初始加载资源。
  - `v-show`：初始成本**高**。无论元素是否显示，都会在初始渲染时创建并挂载到 DOM 中。
- **语法使用**：
  - `v-if`：支持条件连用，可以配合 `v-else-if` 和 `v-else` 使用。
  - `v-show`：不支持连用 `v-else-if` 或 `v-else`。

## 3. 适用场景分析 *Content-[07:55]

选择 `v-if` 还是 `v-show` 的核心判断依据是**切换频率**：

- **v-if 适用场景（切换频率低）**：
  - **特点**：条件很少改变，或者初始条件可能为 `false`，不需要立即创建 DOM。
  - **典型案例**：
    - **电商会员模块**：初始状态下不显示，也不需要创建 DOM，只有满足条件时才渲染。
    - **后台管理系统的权限菜单**：根据用户权限动态渲染，没有权限的菜单直接不创建，避免无效 DOM 节点。
- **v-show 适用场景（切换频率高）**：
  - **特点**：需要频繁切换显示/隐藏状态，且初始条件通常为 `true`（默认需要初始化渲染）。
  - **典型案例**：
    - **弹幕开关**：用户可能频繁开启或关闭弹幕，需要快速切换，避免频繁创建销毁带来的性能开销。
    - **电商筛选面板**：默认创建好 DOM 结构但不显示，用户点击筛选按钮时快速展开。

## 4. 使用注意事项 *Content-[09:31]

- **v-if 的连用规则**：
  - **连续书写与条件互斥**：`v-if`、`v-else-if`、`v-else` 可以连写，实现多条件互斥（三选一或多选一）。
  - **兜底作用**：`v-else` 作为兜底选项，当 `v-if` 和所有 `v-else-if` 的条件均不满足时，执行 `v-else` 的内容。
- **禁止混用**：
  - `v-if` 和 `v-show` **绝对不可**在同一个元素上同时使用。
  - **原因**：`v-if` 控制的是 DOM 的“存在与否”（创建与销毁），而 `v-show` 控制的是 DOM 的“显示与否”（CSS 样式）。两者的底层控制逻辑完全冲突，同时使用会导致不可预期的渲染行为。

## AI 总结

在 Vue 开发中，`v-if` 和 `v-show` 都用于控制元素的显示与隐藏，但底层机制截然不同。`v-if` 是真正的条件渲染，通过销毁和创建 DOM 节点来控制，切换成本高但初始渲染成本低，适用于切换频率低的场景（如权限菜单）；`v-show` 则是通过 CSS 的 `display` 属性控制，DOM 节点始终存在，切换成本低但初始渲染成本高，适用于频繁切换的场景（如弹幕开关）。在实际开发中，需根据业务场景的切换频率合理选择，并牢记两者不可在同一元素上混用。
