## 引言：从 Proxy 到依赖追踪 *Content-[00:01]

- **回顾 Proxy 的作用**：在上一节课中，我们了解到 `Proxy` 就像一个灵敏的哨兵，能够拦截并感知数据的变化。
- **提出核心痛点**：`Proxy` 发现数据变化后，存在一个它自身无法解决的问题——它不知道该向谁汇报。也就是说，当数据改变时，它不知道具体是页面上的 A 组件、B 模块还是某个具体的 DOM 元素使用了该变量。
- **解决方案**：为哨兵配上“通讯录”和“通知系统”，即 Vue 响应式系统的核心——**依赖追踪机制**。

## 核心概念：副作用函数与响应式桥梁 *Content-[00:32]

- **Proxy 的局限性**：当执行 `state.count++` 时，`Proxy set` 捕获器会立即触发并感知值从 0 变成 1，但对页面上具体哪些部分需要更新一无所知。仅监听数据变化无法实现自动更新。
- **建立沟通桥梁**：必须在“数据”和“使用数据的地方”之间建立一座桥梁。
- **副作用函数（Effect）的定义**：
  - 任何一段读取响应式数据，并且希望在数据变化时重新执行的代码，都称为副作用函数。
  - **典型示例**：更新界面 DOM 的那段代码，就是一个最典型的副作用函数。

## 核心机制：Track 依赖收集与 Trigger 派发更新 *Content-[01:44]

要让响应式桥梁运作起来，需要完成两个核心工作：

1\. **依赖收集（Track）**：
   - **触发条件**：副作用函数执行时，恰好读取了某个响应式数据。
   - **动作**：将该副作用函数登记到该数据的依赖集合中。
2\. **派发更新（Trigger）**：
   - **触发时机**：数据发生变化时。
   - **动作**：去该数据的依赖列表中，找出所有之前通过 `track` 登记过的副作用函数，并重新执行一遍。

- **机制优势**：一个负责登记，一个负责通知。实现精准触发，各个变量各司其职、互不干扰，将性能开销降至最低。

## 形象比喻：订阅报纸流程 *Content-[04:32]

依赖追踪机制的执行过程非常像生活中的“订阅报纸”操作：

- **首次执行（订阅）**：传入 `render` 函数时，相当于去报社订阅了名为 `state.count` 的日报。
- **Track（登记名单）**：`track` 扮演报社员工，将你订阅的变量记录在订阅者名单上。
- **Trigger（派发报纸）**：一旦 `state.count` 有了新内容（数据变化），`trigger` 作为报社职员，会按照名单重新执行你传入的 `render` 函数，把最新的报纸送到你家。
- **特点**：整个过程全自动化且极其精准。

## 代码实现：依赖仓库与全局标记 *Content-[05:33]

在代码实现层面，首先需要定义两个至关重要的变量：

- **`activeEffect`（全局状态指示灯）**：
  - 用于存放当前正在执行的副作用函数。
  - 初始值为 `null`。
- **`bucket`（依赖仓库）**：
  - 使用 `WeakMap` 实现，负责存储所有的依赖关系。
  - **三层档案柜数据结构**：
    - **第一层（`WeakMap`）**：以响应式对象 `target` 为 key（例如 `state` 对象）。
    - **第二层（`Map`）**：以属性名 `key` 为 key（例如 `count`、`name` 属性）。
    - **第三层（`Set`）**：存放依赖该属性的所有副作用函数集合（例如 `effect1`、`effect2`）。

## 代码实现：Effect 函数与 Proxy 拦截器 *Content-[07:22]

- **实现 `effect` 函数（响应式系统的发动机）**：
  - 接收函数 `fn` 作为参数。
  - 使用内部函数 `effectFn` 包裹 `fn`，以便添加额外逻辑。
  - **执行前**：将 `effectFn` 赋值给全局的 `activeEffect`，表明当前有副作用函数正在执行（点亮指示灯）。
  - **执行中**：立即执行 `fn`。在此过程中若访问响应式数据，会触发 `get` 拦截，进入 `track` 逻辑。
  - **执行后**：将 `activeEffect` 重新设置为 `null`（熄灭指示灯）。这保证了只有在 `effect` 保护下执行的代码才会收集依赖，避免无关代码干扰。

- **改造 `Proxy get` 捕获器（Track 实现）**：
  - 读取属性时自动触发。
  - 检查 `activeEffect` 是否有值。若有，说明读取操作发生在副作用函数内部。
  - 按照 `target` -> `key` -> `Set` 的结构层层深入，将 `activeEffect` 添加到对应的 `Set` 集合中。
  - **Track 核心思想**：“谁在用我，我就把谁记下来”。

- **改造 `Proxy set` 捕获器（Trigger 实现）**：
  - 数据变化时触发。
  - **第一步**：设置新值，更新数据本身。
  - **第二步**：根据 `target` 和 `key` 在 `bucket` 中找到对应的副作用函数集合。
  - **第三步**：遍历集合中的每一个副作用函数并重新执行。
  - **Trigger 核心思想**：“我变化了，就通知所有用过我的人”。

## 总结与下节预告：依赖追踪的意义与内存管理 *Content-[10:12]

- **核心总结**：
  - `track` 是建名单，`trigger` 是发通知。
  - 通过两者的完美配合，响应式数据和副作用函数之间建立起了动态的双向联系。
  - 数据变化不再是孤立事件，能够自动、精准地驱动依赖它的逻辑去更新，避免了手动操作和全局刷新的性能浪费。这是现代前端框架实现高效 UI 更新的基石。
- **思考与下节预告**：
  - **抛出问题**：在真实项目中，组件有创建和销毁，副作用函数不能无限制地永远执行。它们何时开始/停止？当组件卸载时，如何自动清理其创建的所有依赖关系以避免内存泄漏？
