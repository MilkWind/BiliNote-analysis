## 1. 为什么需要 Composition API *Content-[00:00]*

本节课主要介绍 Vue 3 中非常核心且强大的特性：**Composition API**（组合式 API）。Composition API 带来的不只是语法的变化，更是组织组件逻辑的一种全新方式，其根本目的是为了实实在在解决大型组件开发中的痛点。

### Options API 的回顾与痛点
在 Vue 2 中，大家非常熟悉 **Options API** 的写法，代码通过 `data`、`methods`、`computed` 等选项分门别类地组织。
- **优点**：简单清晰，一目了然，对于小型功能、单一组件非常友好。
- **痛点**：当组件变得复杂、功能增多时，**相关逻辑会被打散**。为了实现一个完整功能，开发者需要在 `data`、`methods`、`computed`、`watch` 甚至生命周期钩子中来回跳转。这种“逻辑打散”现象让大型组件的开发和维护变得极其困难。

### 具体案例说明
假设开发一个包含两个独立功能的组件：**获取验证码的倒计时** 和 **校验用户名的表单校验**。
- 在 **Options API** 中：
  - `data` 中需要同时定义倒计时的 `count`，以及表单的 `username` 和 `usernameError`。
  - `methods` 中需要同时包含控制倒计时的 `startCountdown` 和校验用户名的 `validateUsername`。
  - `computed` 中可能还有判断校验结果的 `isUsernameValid`。
- **问题**：倒计时逻辑和用户名校验逻辑像麻花一样拧在一起，被强行拆散并分布在不同“篮子”（选项）里。修改某一功能时，需要在文件的不同地方来回翻找，功能越复杂越是一场灾难。

## 2. Composition API 的核心优势 *Content-[03:44]*

使用 Composition API 改写上述例子后，代码结构会发生显著变化。在 `<script setup>` 中，与倒计时相关的 `count` 变量和 `increment` 方法会被写在一起；表单校验相关的逻辑也可以聚合在另一个代码块中。

Composition API 带来了以下巨大优势：
1. **逻辑集中**：相关功能的代码内聚在一起，可读性和可维护性大大提升。
2. **类型推导能力强**：由于代码是函数式编写的，其 TypeScript 类型推导能力比 `this` 指向不明确的 Options API 强得多。
3. **极致的逻辑复用**：可以非常轻松地将一整块逻辑（如倒计时逻辑）抽离成一个独立的可复用函数，即**组合式函数（Composables）**，这是逻辑复用的神器。

## 3. Options API 与 Composition API 对比 *Content-[05:10]*

通过对比可以直观看出两种 API 在逻辑组织上的本质变化：

- **Options API**：代码按**选项**组织。`data` 在一块，`methods` 在一块，逻辑是**分散**的。
  - *比喻*：就像一个传统大书架，所有的书严格按照“小说”、“历史”、“科学”等类别进行分类摆放。
- **Composition API**：代码按**功能**组织。功能 A 的所有逻辑在一块，功能 B 的所有逻辑在另外一块，逻辑是**聚合**的。
  - *比喻*：赋予了开发者更多自由组合的权利。你可以把《三体》（科幻小说）和《物理学史》放在同一个书架上，因为它们都与“物理”这个主题相关。这种组织方式显然更加灵活且强大。

## 4. 如何使用 Composition API *Content-[06:12]*

Composition API 的核心入口是全新的组件选项函数：**`setup` 函数**。

### 传统写法
在 Vue 2/3 的 `export default` 中编写 `setup` 函数。
- 可以将 `setup` 理解成一个“舞台”，所有关于响应式数据、方法、生命周期的表演都在此进行。
- 在 `setup` 内部定义数据（如 `count`），然后通过 `return` 的方式将它们暴露给模板使用。
- **核心理念**：在 `setup` 里写的是组合函数的逻辑本身，而不再是配置项。

### 语法糖写法（社区最推荐/主流）
每次写 `export default { setup() {} }` 较为繁琐，Vue 团队提供了 `<script setup>` 语法糖。
- 使用 `<script setup>` 标签后，**不再需要**写 `setup` 函数和 `return` 语句。
- 所有在该标签内定义的顶层变量和函数，都会**自动暴露**给模板使用。
- 这种写法让组件编码变得非常简洁且优雅。

## 5. 与 React Hooks 的对比 *Content-[07:48]*

Composition API 的设计思想与 **React Hooks** 有异曲同工之妙。本质上，可以将 Composition API 理解为 **Vue 版本的 Hooks**，它们的核心都是通过函数组合的方式来构建和复用组件逻辑。

核心 API 对应关系如下：
- **Vue `ref`** ≈ **React `useState`**：用于创建响应式数据。
- **Vue `computed`** ≈ **React `useMemo`**：用于创建计算属性。
- **Vue `watch`** ≈ **React `useEffect`**：用于监听数据的变化并执行副作用。

## 6. 课程总结与下节预告 *Content-[08:47]*

### 本节核心要点总结
1. **定位**：Composition API 是 Vue 3 提供的一种全新逻辑组织方式。它的出现不是为了替代 Options API，而是为了解决大型复杂组件中逻辑分散、难以复用的痛点。
2. **入口**：核心入口是 `setup` 函数或更简洁的 `<script setup>` 语法糖。在此搭配 `ref` 等响应式 API 进行逻辑组合。
3. **优势**：相比于 Options API，它具备更强的逻辑聚合性和抽象能力，让代码更加健壮、易于维护。
