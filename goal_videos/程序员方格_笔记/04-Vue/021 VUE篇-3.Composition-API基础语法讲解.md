## 课程介绍与核心目标 *Content-[00:00]

- **视频主题**：Vue 3 Composition API 基础语法讲解。
- **核心目标**：掌握 `ref`、`reactive`、`computed` 和 `watch` 这四个最核心 API 的基本用法。
- **核心概念**：响应式能力。通过响应式机制，让数据在发生变化时能够自动更新视图。在 Composition API 中，创建响应式数据主要依赖 `ref` 和 `reactive` 两个函数。

## 创建响应式数据：ref 与 reactive *Content-[00:27]

### ref 的基本用法
- **适用场景**：主要用于处理数字、字符串等**基本类型**数据。
- **导入与定义**：从 `vue` 中导入 `ref`，使用 `const` 定义响应式变量。例如：`const count = ref(0)`。
- **模板中访问**：在 `<template>` 模板中，可以直接使用变量名（如 `{{ count }}`）来展示值，无需添加 `.value`。
- **Script 中访问与修改**：在 `<script>` 标签中，必须通过 `.value` 的形式去访问和修改。例如，想让计数器每秒自动加一，需要写 `count.value++`。这是因为 `ref` 内部将基本类型包装成了一个特殊的对象。

### reactive 的基本用法
- **适用场景**：主要用于处理对象或数组等**复杂数据类型**（如包含多个状态的对象）。
- **导入与定义**：从 `vue` 中导入 `reactive`，创建一个响应式代理对象。例如：`const state = reactive({ count: 0 })`。
- **访问与修改**：不需要像 `ref` 那样使用 `.value`，可以直接像操作普通对象一样访问和修改属性。例如：`state.count++`。
- **深层响应**：`reactive` 具有深层响应特性，即对象内部嵌套的属性也都是响应式的。

### ref 与 reactive 的对比与选择
- **ref**：适用于基本类型，在 JS 中访问需依赖 `.value` 属性。
- **reactive**：适用于对象或数组，可直接访问属性，且支持深层次响应。
- **选择建议**：在实际开发中使用 `ref` 还是 `reactive` 没有绝对的对错，主要取决于个人的数据结构设计和编码偏好。

## 派生状态：computed 计算属性 *Content-[03:32]

- **适用场景**：在开发中经常需要根据已有数据派生出新的值（例如：根据商品的单价和数量计算出总价）。
- **核心特性（缓存机制）**：
  - `computed` 派生出的值（如 `doubleCount`）会依赖于原始数据（如 `count`）。
  - 只有当依赖的原始数据发生变化时，`computed` 才会进行重新计算。
  - 如果依赖数据未发生变化，无论访问多少次，都会直接返回上一次计算好的结果，不会重复执行计算函数。这在处理复杂计算时能带来极大的性能优化。
- **基本用法**：
  - 从 `vue` 导入 `computed`。
  - 调用 `computed` 并传入一个回调函数，函数内部返回计算逻辑。例如：`const doubleCount = computed(() => count.value * 2)`。
- **注意事项**：
  - `computed` 返回的对象类似于 `ref`，在 `<script>` 标签中访问时，同样需要通过 `.value` 属性（如 `doubleCount.value`）。
  - `computed` 的属性是**只读**的。如果尝试直接修改它的值（如 `doubleCount.value++`），代码会报错。

## 侦听变化：watch 侦听器 *Content-[06:19]

- **适用场景**：当希望某个数据在变化时执行一些额外的“副作用”逻辑（如打印日志、向服务器发送请求、将数据存储到 `localStorage`），而不仅仅是计算出一个新值时，使用 `watch`。
- **基本用法**：
  - 从 `vue` 导入 `watch`。
  - 传入两个主要参数：第一个是想要监听的数据源（如 `count`），第二个是回调函数。
  - 当数据变化时，回调函数会被执行，并接收两个参数：`newValue`（当前变化的最新状态）和 `oldValue`（变化之前的状态）。
- **常用配置项**：
  - `immediate`：设置为 `true` 时，可以让侦听器在初始化时立即执行一次回调函数。
  - `deep`：设置为 `true` 时，可以用来深度监听对象内部属性的变化。

## 逻辑组合与复用：Composition API 的核心优势 *Content-[08:34]

- **核心思想**：Composition API 最强大的地方在于**组合**。它允许我们将逻辑进行高度封装和复用。
- **逻辑封装（Composables）**：
  - 可以将相关的数据（如 `count`）和操作方法（如 `inc`）封装到一个独立的函数中。
  - **命名约定**：通常以 `use` 开头，例如 `useCounter`。
  - 在函数内部定义 `ref` 和增加 `count` 的方法，最后通过 `return` 将它们暴露出来。
- **在组件中使用**：
  - 导入 `useCounter` 函数并调用。
  - 通过解构赋值获取返回的变量和方法，例如：`const { count, inc } = useCounter()`。
- **优势总结**：
  - 代码组织更加集中、清晰。
  - 逻辑模块高度可复用。如果其他组件也需要计数器功能，直接复用 `useCounter` 即可，极大提升了开发效率。
