## 全局状态管理的背景与 Pinia 简介 *Content-[00:00]
- **业务场景痛点**：在前端项目开发中，经常会遇到多个组件需要共享同一份数据的场景（例如用户的登录信息）。如果让每个组件单独发起请求，或者通过 `props` 逐层向下传递，会导致代码非常繁琐且难以维护。
- **全局状态的概念**：为了解决上述问题，需要一个集中的地方来存放和管理这些共享状态，这就是所谓的“全局状态”。
- **Pinia 简介**：Pinia 是 Vue 3 官方推荐的状态管理库。它的核心特点是 API 设计非常简洁，学习曲线平缓，极易上手。

## 创建 Store 的核心步骤 *Content-[00:44]
创建一个 Store 的代码非常简洁，主要包含以下几个核心步骤：
- **导入核心函数**：首先需要从 `pinia` 包中导入 `defineStore` 函数，所有 Store 的创建都依赖于此函数。
- **调用 `defineStore` 并传参**：调用该函数时需要传递两个参数：
  - **参数一：唯一 ID**。这是一个字符串（例如 `'counter'`）。Pinia 内部依靠这个 ID 来标识和管理不同的 Store，因此它必须是独一无二的。通常建议直接使用 Store 的命名来作为 ID。
  - **参数二：配置对象**。该对象包含两个非常重要的属性：
    - **`state`**：必须是一个函数，该函数需要返回一个对象。返回的对象即为该 Store 需要管理的初始数据（例如定义 `count: 0`，表示初始状态 count 的值为 0）。
    - **`actions`**：是一个对象，用于定义专门修改 `state` 数据的方法。例如定义一个 `increment` 方法，作用是将 `count` 的值加 1。在 `actions` 内部，可以通过 `this` 关键字直接访问 `state` 中的数据（例如 `this.count`）。

## 在组件中获取与使用 Store *Content-[02:24]
定义好 Store 后，在 Vue 组件中使用它的流程如下：
- **导入 Store 函数**：在组件的 `<script setup>` 标签中，将定义好的 Store 函数（例如 `useCounterStore`）导入进来。
- **获取 Store 实例**：直接调用该函数（例如 `const store = useCounterStore()`），它会返回一个 Store 实例，使用变量将其接收。
- **操作状态与方法**：拿到实例后，可以像操作普通对象一样使用它：
  - **获取状态**：直接访问属性获取值（例如 `store.count`）。
  - **调用方法**：直接调用 `actions` 中定义的方法来修改数据（例如 `store.increment()`）。
- **响应式特性**：Pinia 中的所有操作都是完全响应式的。当调用 `store.increment()` 修改了 `count` 的值后，模板中所有使用 `store.count` 的地方都会自动触发更新。

## Pinia 的核心工作逻辑与数据共享 *Content-[03:26]
- **全局单例模式**：Pinia 的核心逻辑在于，无论你在哪个组件中调用 `useCounterStore`，Pinia 都会根据之前定义的唯一 ID（如 `'counter'`）返回**同一个** Store 实例。
- **实现全局共享**：这种机制保证了数据在所有组件之间是全局共享的。例如，在 A 组件中调用方法将 `count` 修改为 1，那么在 B 组件中获取到的 `store.count` 值也会立刻同步变为 1。

## 课程要点总结 *Content-[04:11]
本节课主要学习了 Pinia 最核心的两个用法及基本工作流：
- **核心函数一：`defineStore`**。用于定义 Store，通过 `state` 定义响应式数据，通过 `actions` 定义修改数据的方法。
- **核心函数二：`useXxxStore`（如 `useCounterStore`）**。在组件中调用此函数，即可获取全局唯一的 Store 实例，从而自由访问状态和调用方法。
- **基本工作流三步曲**：创建 Store -> 获取实例 -> 使用状态。掌握这三步即可在项目中顺利使用 Pinia 进行全局状态管理。
