## 1. 课程目标与 Composition API 简介 *Content-[00:06]

- **课程背景**：在了解 Composition API 的概念及其带来的好处后，本节课将深入学习其基础语法。
- **核心目标**：掌握 `ref`、`reactive`、`computed` 和 `watch` 这四个最核心 API 的基本用法。
- **响应式能力**：Composition API 的核心在于提供响应式能力，使得数据在发生变化时能够自动更新视图。

## 2. 响应式数据：ref 与 reactive *Content-[00:35]

在 Composition API 中，创建响应式数据主要依赖 `ref` 和 `reactive` 两个函数，它们分别适用于不同的数据类型。

### ref 的基本用法
- **适用场景**：主要用于处理数字、字符串等**基本类型**数据。
- **创建与导入**：从 `vue` 中导入 `ref`，使用 `const count = ref(0)` 定义响应式数据。
- **模板中访问**：在 `<template>` 模板中，可以直接使用变量名（如 `{{ count }}`）来展示值。
- **脚本中访问**：在 `<script>` 标签中访问或修改值时，**必须通过 `.value` 属性**（如 `count.value++`）。这是因为 `ref` 内部将基本类型包装成了一个特殊的对象。

### reactive 的基本用法
- **适用场景**：主要用于处理对象或数组等**复杂数据类型**。
- **创建与导入**：从 `vue` 中导入 `reactive`，使用 `const state = reactive({ count: 0 })` 创建。
- **响应式代理**：`reactive` 会返回一个对象的响应式代理。
- **脚本中访问**：无需使用 `.value`，可以像操作普通对象一样直接访问和修改属性（如 `state.count++`）。
- **深层响应**：`reactive` 具有深层次响应的特性，即对象内部嵌套的属性也会自动变为响应式。

### 选型建议
- 实际开发中使用 `ref` 还是 `reactive` 没有绝对的对错，主要取决于个人的数据结构设计和编码偏好。

## 3. 计算属性：computed *Content-[03:32]

当需要根据已有数据派生出新的值时（例如根据商品单价和数量计算总价），`computed` 是最佳选择。

- **核心特性（缓存机制）**：`computed` 最大的特点是**带有缓存**。派生出的值仅在其依赖的原始数据发生变化时才会重新计算。如果依赖项未变，无论访问多少次，都会直接返回上一次计算好的结果，从而在处理复杂计算时带来极大的性能优化。
- **基本用法**：
  - 从 `vue` 导入 `computed`。
  - 传入一个函数，该函数返回计算结果（例如 `return count.value * 2`）。
- **访问与只读限制**：
  - `computed` 返回的变量（如 `doubleCount`）本质上类似于一个 `ref` 对象。
  - 在 `<script>` 中访问时，同样需要通过 `.value` 来获取值。
  - **注意**：默认情况下，`computed` 的 `.value` 是**只读**的。如果尝试直接修改它（如 `doubleCount.value++`），代码将会报错。

## 4. 侦听器：watch 与副作用处理 *Content-[06:19]

当数据变化时，如果不仅需要计算新值，还需要执行一些额外的操作（即**副作用**），就需要使用 `watch`。

- **副作用场景**：打印日志、向服务器发送网络请求、将数据持久化存储到 `localStorage` 等。
- **基本用法**：
  - 从 `vue` 导入 `watch`。
  - 传入两个参数：第一个是**监听的数据源**，第二个是**回调函数**。
  - 回调函数会接收两个参数：`newValue`（变化后的当前状态）和 `oldValue`（变化前的之前状态）。
- **实用配置项**：
  - `immediate`：设置为 `true` 时，可以让回调函数在初始化时立即执行一次。
  - `deep`：用于深度监听对象内部属性的变化。

## 5. 逻辑复用：组合函数 (Composables) *Content-[08:34]

Composition API 最强大的地方在于其**组合**能力，能够将分散的逻辑封装成独立、可复用的模块。

- **封装逻辑**：将相关的数据（如 `count`）和操作方法（如 `inc`）封装到一个独立的函数中。
- **命名规范**：约定俗成，组合函数名应以 `use` 开头，例如 `useCounter`。
- **使用方式**：
  - 在函数内部定义 `ref` 和方法，并通过 `return` 将它们暴露出去。
  - 在组件中导入并调用该函数，通过**解构赋值**获取所需的状态和方法（如 `const { count, inc } = useCounter()`）。
- **核心优势**：这种模式使得代码组织更加集中和灵活。如果其他组件也需要计数器功能，直接复用 `useCounter` 即可，极大提升了代码的可维护性和复用性。
