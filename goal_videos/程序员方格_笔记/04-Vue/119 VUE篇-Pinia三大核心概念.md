## Pinia 简介与核心概念概述 *Content-[00:00]
- **Pinia 简介**：Pinia 是 Vue 官方首选推荐的状态管理库。
- **主要优点**：
  - 非常轻量级。
  - 对 TypeScript 支持特别友好，类型推导完善，编写安全。
- **三大核心概念**：
  - **State**：专门用来存储数据的地方，类似于一个数据仓库。
  - **Getters**：仓库数据的计算器，用于根据现有数据计算并派生出新的值。
  - **Actions**：负责处理各种业务逻辑（例如点击按钮后触发的具体操作）。

## State：状态存储与响应式 *Content-[00:46]
- **核心定位**：State 是 Pinia 的“心脏”，应用中所有需要全局共享的数据都应该存放在这里。
- **响应式特性**：State 中的数据是响应式的。一旦 State 中的数据发生变化，页面上所有引用该数据的地方都会被自动更新，无需手动操作 DOM。
- **定义方式**：在 Store 中定义 `state` 函数，并让其返回一个包含所需管理数据的对象。
- **访问与修改**：
  - 通过 Store 实例直接访问，例如 `store.count`。
  - 若需要一次性修改多个数据，可以使用 `$patch` 方法，执行效率更高。
- **代码示例（计数器 Store）**：
  - 使用 `defineStore` 定义 Store。
  - `state` 返回一个对象，包含 `count`（初始值为 0）和 `name`（初始值为 '方格'）。
  - 这种结构清晰简单，非常适合存放基础的、需要全局共享的数据。

## Getters：计算属性与缓存机制 *Content-[02:07]
- **核心定位**：相当于 Store 里的 `computed`（计算属性），主要作用是基于 State 中的数据进行计算，派生出新的状态。
- **适用场景**：例如从任务列表中过滤出已完成的任务，或统计特定状态的数量。
- **最大优势（缓存机制）**：
  - 只要依赖的 State 数据没有发生变化，即使访问 Getters 100 次，也只会计算一次，后续直接返回缓存结果，性能极佳。
  - 只有当依赖的 State 发生变化时，才会触发重新计算。
- **定义与使用**：
  - 定义方式与 Vue 的 `computed` 非常相似。
  - 在 Getters 内部，可以通过 `this` 访问其他的 Getters。
- **代码示例（任务管理 Store）**：
  - `doneTodos`：从 `todos` (State 数组) 中过滤出 `done` 属性为 `true` 的任务（即已完成任务）。
  - `activeTodos`：过滤出未完成的任务。
  - `doneCount`：直接统计已完成任务的数量。
  - 这些 Getters 均基于 State 中的 `todos` 数组进行计算，得益于缓存机制，性能得到了大幅优化。

## Actions：业务逻辑与异步操作 *Content-[04:00]
- **核心定位**：处理业务逻辑的地方。例如用户点击按钮、提交表单等，这些操作背后的具体逻辑都应该写在 Actions 中。
- **最大特点（支持异步）**：
  - 支持异步操作，例如请求服务器接口获取数据。
  - 可以使用 `async/await` 语法来优雅地处理异步逻辑。
- **定义方式**：
  - 定义一个 `actions` 对象，内部包含所有的 Action 方法，定义方式类似于普通对象方法。
- **状态修改**：
  - 在 Action 内部，可以通过 `this` 访问定义的状态（State）。
  - 可以直接修改 `this` 上的 State 值（例如向数组中 `push` 一个新对象）。
- **与 Getters 的核心区别**：
  - Getters 只能读取和计算数据，不能修改状态。
  - Actions 可以执行复杂的业务逻辑并直接修改状态（推荐将状态修改逻辑集中在 Actions 中管理）。

## 核心概念总结 *Content-[05:06]
- **State**：数据的核心，专门用于存储应用的状态，具备响应式特性。
- **Getters**：Store 的计算属性，负责对 State 数据进行计算和派生，自带缓存功能以优化性能。
- **Actions**：负责处理所有的业务逻辑，特别是异步操作（如调用 API），并且是修改 State 的主要场所。
- **最佳实践**：深入理解这三个概念，明确分工并合理使用，即可构建出高效、清晰且易于维护的状态管理系统。
