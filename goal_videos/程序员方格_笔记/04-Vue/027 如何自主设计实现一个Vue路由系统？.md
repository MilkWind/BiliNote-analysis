## 一、 核心设计思想 *Content-[00:31]

在面试中，考察“如何自主设计实现一个 Vue 路由系统”主要是为了深入检验开发者对 Vue 路由底层原理的全面理解。设计一个完整的路由系统，核心思想主要包含以下五个关键步骤：

1\. **监听 URL 变化**
路由系统的基础是感知 URL 的变化，从而触发组件的相应切换。无论采用何种路由模式，都必须监听浏览器地址栏的改变：
- **Hash 模式**：通过监听 `hashchange` 事件来拦截和感知 URL 的变化。
- **History 模式**：通过监听 `popstate` 事件来感知浏览器的前进、后退或地址栏手动修改。
- **主动修改**：当通过代码主动调用 `pushState` 或 `replaceState` 时，可以直接在方法中获取到最新的 URL 或 path。

2\. **路由表与路由匹配**
在获取到最新的 URL path 后，需要将其与路由配置表进行匹配：
- 在初始化 Router 实例时，需要传入一份路由配置表（config），其中每个路由对象包含对应的 `path` 和 `component`。
- 系统会遍历该路由表，根据最新的 path 找到匹配的路由规则，并提取出需要渲染的 `component`。

3\. **响应式路由状态**
为了让 URL 的变化能够自动驱动视图的更新，需要维护一个响应式的路由状态（例如 `current` 变量）。当 URL 发生变化时，更新该响应式状态，从而触发 Vue 的响应式系统。

4\. **视图渲染**
匹配到最新的组件后，需要将其渲染到页面上。这通常通过实现一个 `router-view` 组件来完成，所有匹配到的路由组件内容都会在这个 `router-view` 区域范围内进行渲染。

5\. **实现导航方法**
除了依赖浏览器的默认行为，路由系统还需要支持编程式导航。需要实现如 `push`、`replace` 等方法，以便在代码中主动控制路由的跳转。

## 二、 代码实现：初始化与状态管理 *Content-[05:25]

在理清设计思路后，可以通过代码逐步实现自定义路由系统（例如命名为 `MyRouter`）。

- **定义路由表**：
  首先定义一份路由配置表，包含根路径及对应的组件。例如配置 `home` 和 `about` 两个路由，每个路由对象包含 `path` 和 `component` 属性。

- **定义 `MyRouter` 类**：
  创建一个 `MyRouter` 类，在构造函数中接收 `options` 参数，并从中提取关键配置：
  - `routes`：获取传入的路由表。
  - `mode`：获取路由模式（Hash 或 History），若未提供则默认设置为 Hash 模式。
  - `current`：使用响应式 API（如 `reactive`）定义当前路径状态，确保其变化能驱动视图更新。

- **获取当前路径 (`getCurrentPath`)**：
  编写方法以获取最新的路径，需根据当前模式进行判断：
  - **Hash 模式**：通过 `window.location.hash` 获取哈希值，使用正则表达式匹配 `#` 后面的路径内容。如果没有匹配到内容，则提供一个兜底值 `/`。
  - **History 模式**：直接返回 `window.location.pathname`。

## 三、 代码实现：事件监听与导航方法 *Content-[08:20]

- **初始化事件监听**：
  在类初始化时，必须绑定相应的事件监听器以感知 URL 变化：
  - 如果是 **Hash 模式**，使用 `addEventListener` 监听 `hashchange` 事件。在回调函数中，获取最新的路径并赋值给响应式的 `current` 状态。
  - 如果是 **History 模式**，则监听 `popstate` 事件。同理，在回调中获取最新路径并更新 `current` 状态。

- **实现编程式导航 (`push` 方法)**：
  为了支持代码层面的路由跳转，需要在类中实现 `push` 方法，接收目标 `path` 作为参数：
  - **Hash 模式**：直接修改 `window.location.hash` 的值。
  - **History 模式**：调用 `history.pushState` 方法来修改当前路径，且不会刷新页面。
  - 无论哪种模式，在修改 URL 后，都需要同步更新响应式的 `current` 状态，以触发视图的重新渲染。

## 四、 代码实现：视图渲染 (router-view) *Content-[10:26]

最后一步是实现 `router-view` 组件，将匹配到的组件渲染到页面上。

- **模板渲染**：
  在 `router-view` 组件的 `template` 中，使用 Vue 的动态组件特性 `<component :is="currentComponent">` 来渲染当前匹配到的组件。

- **计算当前组件**：
  在组件的 `setup` 或逻辑代码中：
  1. 引入并获取当前 `MyRouter` 的实例（例如通过 `useRouter` 或依赖注入）。
  2. 使用 `computed` 计算属性来动态获取当前需要渲染的组件。
  3. 在计算逻辑中，遍历 `router.routes` 路由表，根据响应式的 `current` 路径，查找并返回对应的 `component`。

- **响应式驱动**：
  通过这种设计，每次路由发生变化时，`current` 值会自动更新，`computed` 属性会重新计算获取最新的 `component`，进而驱动动态组件完成视图的无缝切换。

## AI 总结 *Content-[13:37]

自主设计实现一个 Vue 路由系统的核心在于**状态驱动视图**。整个流程可以概括为：通过监听浏览器事件（`hashchange` / `popstate`）或拦截编程式导航（`pushState`）来感知 URL 变化；将最新路径存入响应式状态（`current`）；利用计算属性（`computed`）在路由配置表中匹配出对应的组件；最后通过动态组件（`<component :is="...">`）在 `router-view` 中完成渲染。掌握这一套“监听 -> 匹配 -> 响应式更新 -> 渲染”的闭环逻辑，就能深刻理解前端路由的底层运行机制。
