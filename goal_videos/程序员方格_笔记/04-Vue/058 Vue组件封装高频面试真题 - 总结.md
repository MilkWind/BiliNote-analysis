## 1. Vue组件封装基础与定义 *Content-[00:04]
- **高频考点**：Vue 组件封装在实际项目开发和前端面试中都是绝对的高频考点。只要参与项目开发，必然会涉及组件的封装。
- **组件的定义**：抽离可复用的结构（HTML）、样式（CSS）和逻辑（JS），将其封装成为独立的 `.vue` 文件。
- **组件的核心目的**：
  - **复用**：提高代码和功能的复用率，避免重复造轮子。
  - **统一易维护**：保证全局样式和逻辑的一致性，便于后期的统一修改与维护。
  - **便于团队协作**：按组件进行模块划分，更方便团队内部的分工与协作。

## 2. 组件封装的时机与原因 *Content-[01:09]
### 什么时候封装 / 什么时候不封装
- **建议封装的场景**：
  - 需要重复使用某些代码块或特定功能时。
  - 功能独立的模块，例如：按钮（Button）、卡片（Card）、弹窗（Dialog/Modal）等基础或业务组件。

### 为什么要封装（核心目的）
1. **提高复用性**：减少重复代码的编写，提升开发效率。
2. **保证一致性**：保证样式和交互逻辑在全局保持一致，避免多处修改导致的差异。
3. **降低维护成本**：修改一处即可全局生效，大幅降低后期的维护难度。
4. **提高可读性与协作效率**：代码结构更清晰，极大地利于团队分工协作。

## 3. 组件封装的核心原则 *Content-[02:26]
视频总结了组件封装的**八大核心原则**，在面试和实际开发中需严格遵循：

1\. **单一职责原则**：一个组件应该只负责一个特定的功能或模块，避免组件过于臃肿。
2\. **可复用性原则**：组件的设计应具备高度的通用性，能够适应不同的业务场景。
3\. **数据流向原则（单向数据流）**：数据应从父组件通过 `props` 传入子组件，不要直接在子组件内部修改或定义外部数据（除非是组件完全私有的内部状态）。
4\. **可维护性原则**：必须编写良好的注释，遵循编程规范，提升代码的可读性和可维护性。
5\. **预留插槽原则**：在组件设计时，应预留 `slot` 插槽，以增加组件内容结构的扩展性。
6\. **低耦合原则（不依赖状态管理）**：尽量不要直接依赖于 VueX 或 Pinia 等全局状态管理库，保持组件的独立性和纯粹性。
7\. **样式隔离原则**：合理使用 `scoped` 属性，避免组件样式污染全局或其他组件。
8\. **扩展性原则**：提供合理的 API 和事件接口，便于外部调用和二次扩展。

## 4. 组件通信与 Props 校验 *Content-[03:56]
### 组件通信方式回顾
- **父传子**：使用 `props` 进行数据传递。
- **子传父**：使用 `$emit` 触发自定义事件进行通信。

### Props 校验回顾
- **作用**：规范父组件传入的数据，避免数据错误导致的报错，提升程序的健壮性。
- **可校验的属性**：
  - `type`：规定传入数据的数据类型（如 String, Number, Object 等）。
  - `required`：规定该字段是否为必填项。
  - `default`：设置数据的默认值。
  - `validator`：自定义校验规则（通过函数返回 true/false 来校验传入的数据是否合法）。

## 5. 插槽 Slot 的应用 *Content-[05:09]
- **作用**：让组件的内容结构可以被自定义，极大地增强了组件的灵活性和扩展性。
- **插槽的类型**：
  1. **默认插槽**（Default Slot）：未命名插槽，用于插入默认内容。
  2. **具名插槽**（Named Slot）：通过 `name` 属性区分不同的插槽区域，用于分发不同的内容。
  3. **作用域插槽**（Scoped Slot）：允许子组件向插槽提供数据，父组件可以访问子组件的数据并决定如何渲染。
- **应用场景**：如卡片（Card）组件等。在封装任何组件时，都建议预留一个插槽，以应对未来可能出现的自定义内容需求。
