## 1. Vue Router 简介与基本配置 *Content-[00:00]
- **版本与安装**：当前主要使用 Vue Router 4 版本，推荐通过 `pnpm` 或 `npm` 进行安装。
- **使用场景与核心功能**：作为 Vue.js 官方的路由管理器，Vue Router 提供了以下核心特性：
  - 建立路由与组件之间的映射关系。
  - 实现单页面应用（SPA）的无刷新页面切换。
  - 管理浏览器的历史记录。
  - 支持路由参数传递以及相关的导航守卫。
- **基本配置思路**：
  - 使用 `createRouter` 创建路由实例。
  - 选择路由模式：通过 `createWebHistory` 创建 History 模式实例，或使用 Hash 模式。
  - 定义路由表：核心配置包括 `path`（匹配的路径）和 `component`（路径匹配后渲染的组件）。

## 2. 基础使用与代码演示 *Content-[03:35]
- **创建组件**：首先创建需要路由管理的页面组件，例如 `Home` 和 `About`。
- **配置路由实例**：
  - 引入 `createRouter` 和 `createWebHistory`。
  - 将定义好的路由表传入 `createRouter` 中，生成路由实例并导出。
- **入口文件注册**：在 `main.ts` 中引入配置好的路由实例，并通过 `app.use(router)` 的方式将路由插件注册到 Vue 应用中。
- **视图渲染**：在根组件（如 `App.vue`）中，使用 Vue Router 提供的全局组件 `<router-view>`。当路径匹配成功后，对应的路由组件将会渲染在 `<router-view>` 所在的区域。

## 3. 动态路由与参数获取 *Content-[07:35]
- **动态路由配置**：
  - 在路由表中，使用冒号 `:` 来匹配动态参数，例如 `/user/:id`。
  - 适用场景：用户信息详情页、订单列表等需要传递动态标识（如 user ID）的场景。
- **参数与实例获取**：
  - 在 Vue 3 的 Composition API 中，推荐使用 Hook 函数来获取路由信息。
  - **`useRoute()`**：返回当前路由对象（`route`），包含 `name`、`params`（如 `route.params.id`）、`query` 等属性，用于获取当前路径的参数。
  - **`useRouter()`**：返回路由实例（`router`），包含编程式导航方法（如 `push`、`replace`）、导航守卫（如 `beforeEach`、`afterEach`）以及底层 HTML5 History API 的相关属性和方法。

## 4. 动态路由组件复用与生命周期问题 *Content-[12:20]
- **组件复用机制**：
  - 当在同一个组件内进行动态参数切换时（例如从 `/user/123` 切换到 `/user/321`），Vue Router 为了提升性能，会复用已有的组件实例，而不是将其销毁后重新创建。
- **生命周期问题**：
  - 由于组件实例被复用，`mounted` 等初始化生命周期钩子不会再次触发。如果之前在 `mounted` 中发起接口请求，此时请求将不会重新执行。
- **解决方案**：
  1. **使用 `watch` 监听参数变化**：通过 `watch` 监听 `$route.params.id`，当参数发生变化时，在回调函数中获取新 ID 并重新发起接口请求。
  2. **使用组件内守卫 `beforeRouteUpdate`**：在路由组件内部使用 `beforeRouteUpdate` 钩子，在组件即将更新前拦截路由变化，在此处处理参数更新和请求逻辑。

## 5. 编程式导航与命名路由 *Content-[17:50]
- **编程式导航**：
  - 通过 `useRouter()` 或 `this.$router` 获取路由实例。
  - **`push`**：跳转到指定路径，可传入字符串或对象（包含 `path`、`name`、`params` 等）。
  - **`replace`**：替换当前历史记录，不会在浏览器历史中留下新记录。
  - **`go`**：前进或后退指定的步数。
  - **`back` / `forward`**：快捷方法，分别用于后退或前进一条历史记录。
- **命名路由**：
  - 在路由表配置中为路由添加 `name` 属性（如 `name: 'user'`）。
  - 跳转时通过传入 `{ name: 'user', params: { id: 123 } }` 对象进行导航。
  - 优势：避免硬编码 URL，降低因路径修改带来的代码维护成本。
  - 在 `<router-link>` 中，`to` 属性同样支持传入命名路由对象，如 `:to="{ name: 'about' }"`。

## 6. 路由重定向与别名 *Content-[24:50]
- **路由重定向（`redirect`）**：
  - **使用场景**：常用于权限校验，例如判断用户未登录时，将访问受保护页面的请求重定向到首页或登录页。
  - **配置方式**：在路由表中设置 `redirect` 属性，可以是一个具体的路径字符串，也可以是一个函数。函数接收 `to` 参数，可根据业务逻辑（如判断登录态、判断 ID 是否为 0）动态返回重定向的目标路径。
- **路由别名（`alias`）**：
  - 在路由表中使用 `alias` 属性为路由设置别名。
  - 当用户访问别名路径时，URL 会保持为别名，但实际渲染的是原路由对应的组件。

## 7. 路由模式与部署注意事项 *Content-[27:30]
- **路由模式对比**：
  - **History 模式**：使用 `createWebHistory` 创建，URL 更加美观，符合传统 Web 应用的 URL 规范。
  - **Hash 模式**：使用 `createWebHashHistory` 创建，URL 中带有 `#` 符号，不需要服务器进行额外配置。
- **部署注意事项**：
  - 当使用 History 模式部署上线时，必须在服务器（如 Nginx）中配置相应的重写规则，将所有未匹配到静态资源的请求都指向 `index.html`。
  - 这样可以避免用户在子路由页面刷新时，服务器因找不到对应文件而返回 404 错误。
