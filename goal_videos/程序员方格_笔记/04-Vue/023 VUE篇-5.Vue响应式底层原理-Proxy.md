## 为什么需要响应式系统 *Content-[00:18]

- **原始开发模式的痛点**
  - 在没有 Vue 等框架的原始开发模式中，数据与视图（网页）是互相独立的，彼此“不认识”。
  - 当数据发生变化时（例如用户积分增加），页面不会自动更新。开发者必须手动编写代码，通过 DOM 操作（如 `document.getElementById`）一步步找到页面上显示该数据的元素，并手动更新其内容。
  - **维护困难**：当页面变得复杂，有几十上百个地方依赖同一数据时，手动更新不仅繁琐，还极易遗漏或改错，导致数据与视图不统一。业务代码与大量 DOM 操作高度耦合。

- **响应式系统的核心理念**
  - **解放开发者**：开发者只需关心数据本身。只要修改了数据，响应式系统就会自动、精准地找到所有依赖该数据的地方，并全部更新完毕。
  - **思维转变**：开发者的思考方式从“我该怎么去操作 DOM”转变为“我只需要改数据”，极大地提高了生产力。
  - **简单示例**：页面上有一个数字 `0` 和一个按钮，点击按钮数字加 `1`。使用原生 JavaScript 需要在点击事件中获取 DOM 元素并修改 `innerText`，代码与业务逻辑耦合；而使用响应式系统，只需修改数据变量即可。

## Vue3 响应式的核心：Proxy *Content-[02:55]

- **核心机制：拦截**
  - Vue 实现数据自动更新的秘密在于“拦截”。它就像一个**哨兵**，在数据被访问或修改的必经之路上站岗。只要有人动了数据，哨兵就会立刻察觉并执行相应操作。

- **Proxy 的基本概念**
  - 在 Vue3 中，这个“哨兵”就是 `Proxy`，它是 ES6 引入的新特性。
  - **代理模式**：`Proxy` 的作用是为原始数据对象创建一个代理。之后所有对数据的操作都不再直接接触原始对象，而是通过这个代理来完成。
  - **代码实现**：使用 `new Proxy(target, handler)` 将普通对象（如 `state`）包裹起来得到代理对象。
  - **捕获器（Traps）**：重点在于第二个参数 `handler` 对象，里面可以定义多种捕获器：
    - `get`：在读取代理对象属性时触发。
    - `set`：在写入或修改代理对象属性时触发。

## Proxy 与 Object.defineProperty 的对比 *Content-[04:21]

为了深刻理解 `Proxy` 的优势，需要将其与 Vue2 使用的核心 API `Object.defineProperty` 进行对比。

- **Vue2 的 Object.defineProperty**
  - **工作原理**：不代理整个对象，而是直接在原始对象上，循环遍历为每一个已知属性定义 `get` 和 `set`。
  - **缺陷 1：无法监听对象结构变化**。必须提前知道对象有哪些属性。如果后续新增或删除属性，它是完全不知道的（这也是为什么 Vue2 中新增属性必须使用 `Vue.set`）。
  - **缺陷 2：数组处理的噩梦**。它只能拦截特定属性的读写，无法监听通过下标修改数组元素，也无法监听 `push`、`pop` 等数组变异方法。
  - **Vue2 的妥协**：为了让数组支持响应式，Vue2 不得不重写数组的原型方法（如 `push`、`slice` 等），这成为了 Vue2 在数组响应式上的历史包袱。

- **Vue3 的 Proxy**
  - **工作原理**：拦截的是对**整个对象的行为**（如读、写、删除等），更加全面。
  - **完美解决数组问题**：在 `Proxy` 中，数组和普通对象没有任何区别。
    - 通过下标修改元素（如 `arr[0] = 1`）会触发 `set`。
    - 使用 `push` 增加元素会触发 `set`。
    - 甚至修改数组的 `length` 属性也能被精准监听。

- **核心差异总结**
  - `Proxy` 拦截对象行为，全面且强大；`Object.defineProperty` 仅拦截属性读写，对对象结构变化无能为力。
  - Vue3 经过深思熟虑，果断放弃 `Object.defineProperty`，全面拥抱 `Proxy`，从根本上解决了 Vue2 的响应式缺陷。
  - **关键认知**：无论是哪种 API，它们都只是“信息源”，负责告诉我们数据变了，但**并不知道具体要通知谁去更新**，这需要依赖追踪机制的配合。

- **原理解析**
  - 这个例子直观展示了 `Proxy` 在响应式系统中的角色：它就像一个**扳机**。数据的修改扣动了扳机，我们可以在其触发的函数（如 `set` 捕获器）中执行任何想做的操作（例如更新视图）。

## 课程总结与下节预告 *Content-[08:51]

- **本节课核心回顾**
  1. **响应式的目标**：将开发者从繁琐的手动 DOM 操作中彻底解放出来。
  2. **Proxy 的核心地位**：作为 Vue3 实现响应式的心脏，它通过代理方式全面拦截对数据对象的各种操作，能力远超 `Object.defineProperty`。
  3. **Proxy 的局限性**：`Proxy` 只负责监听到数据变化，但它本身并不知道这个变化应该去通知哪个视图更新。

- **下节课预告：依赖追踪与派发更新**
  - 当数据变化时（如 `count` 从 `0` 变 `1`），`Proxy` 成功拦截了变化，但系统如何知道要去更新页面上的特定元素而不是其他元素？
  - 下节课将拆解响应式系统中的另外一对好兄弟：**依赖追踪（track）** 和 **派发更新（trigger）**。
  - 届时将详细解析 Vue 是如何在“一个数据”和“一堆依赖它的视图”之间建立起沟通桥梁的。
