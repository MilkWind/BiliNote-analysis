## Vue3 重构背景 *Content-[00:23]
- **时间节点**：Vue 新版本的理念始于 2018 年末，当时 Vue2 的代码库已经有两岁半的“年龄”。
- **行业变化**：虽然从通用软件生命周期来看时间不算长，但前端世界在这段时间内发生了天翻地覆的变化。
- **重构考量因素**：
  1\. **TypeScript (TS) 的支持**：Vue2 基本没有使用 TS，而随着 TS 发展趋势越来越猛，如果不支持 TS 就会被很多开发者唾弃。因此，Vue3 必须使用 TS 进行重写以提供原生支持。
  2\. **新语言特性的利用**：需要利用 ES6 等相关的新语言特性。
  3\. **解决框架与架构问题**：亟待解决 Vue2 中存在的一些框架底层和架构设计问题。

## Vue3 带来的核心变化 *Content-[01:47]
Vue3 相比 Vue2 主要带来了以下五个方面的显著变化：
1\. **变化速度更快**：渲染和更新速度大幅提升。
2\. **体积减小**：打包后的文件体积更小。
3\. **更易维护**：代码组织和逻辑复用更加合理。
4\. **更接近原生**：提供了更贴近原生 JavaScript 的开发体验。
5\. **更易使用**：API 设计和开发模式更加友好。

## 性能提升：速度更快的原因 *Content-[02:28]
Vue3 在速度上的提升主要归功于底层的核心重写与优化：
- **重写虚拟 DOM**：对 Virtual DOM 进行了全面重写，提升了 Diff 算法的效率。
- **编译模板优化**：在编译阶段对模板进行了深度优化。
- **更高效的组件初始化**：优化了组件创建和初始化的流程。
- **Update 阶段性能提升**：在视图更新（update）阶段，性能提高了 **1.3 到 2 倍**。
- **SSR (Server-Side Rendering) 性能提升**：在服务端渲染阶段，速度提升了 **2 到 3 倍**。
- **迁移建议**：如果针对 Vue 系统有性能优化的需求，可以尝试将 Vue2 迁移到 Vue3，从而在框架底层获得巨大的性能改进。

## 体积优化：Tree-shaking 的应用 *Content-[03:28]
- **Webpack Tree-shaking**：Vue3 充分利用了 Webpack 等打包工具的 Tree-shaking（摇树优化）能力。
- **按需打包**：能够将项目中未使用的无用模块“摇掉”或裁剪掉，仅打包实际需要的模块。
- **最终效果**：通过这种能力，使得最终打包生成的产物体积尽可能小，提升了加载速度。

## 架构升级：更易维护与 Composition API *Content-[04:02]
- **Composition API 的引入**：Vue3 引入了 Composition API，并与现有的 Options API 并存使用。
- **逻辑复用与抽取**：
  - 编写代码更加灵活。
  - 逻辑抽取的颗粒度更加细致。
  - 逻辑代码可以进行高效的组合和复用，这也是目前 Vue3 常规的开发模式。
- **更好的 TS 支持**：得益于 Composition API 和底层重写，Vue3 提供了比 Vue2 好得多的 TypeScript 类型推导和支持。

## 扩展能力：更接近原生与自定义渲染 *Content-[04:57]
- **自定义渲染 API (Custom Renderer API)**：Vue3 提供了自定义渲染器的 API。
- **跨平台渲染**：这使得 Vue3 不仅局限于 Web 端的 DOM 操作，还可以将 Vue 的响应式系统应用到其他平台（如 Canvas、小程序、Native 等），使其更接近原生开发体验。
