## Vue2 响应式原理及痛点 *Content-[02:25]

**核心原理**
Vue2 的响应式系统是基于 `Object.defineProperty` 实现的。它通过劫持对象的 `get` 和 `set` 操作来追踪依赖和触发更新。

**初始化流程**
在组件初始化时，Vue2 会递归遍历 `data` 对象及其所有嵌套对象，为每一个已有的属性添加对应的 `getter` 和 `setter`，从而实现响应式。

**主要痛点与缺陷**
1. **只能劫持已有属性**：由于是初始化时递归遍历添加劫持，后续动态新增的对象属性无法被自动监听，不具备响应式。
2. **数组变更无法直接监听**：`Object.defineProperty` 无法高效监听数组的索引变化和长度变化。

**Vue2 的妥协与解决方案**
- **数组处理**：Vue2 通过重写数组的 7 个变更方法（`push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse`）来使数组具备响应式。
- **对象新增属性**：提供了 `Vue.set`（或 `this.$set`）和 `Vue.delete`（或 `this.$delete`）全局 API，用于手动添加或删除响应式属性。修改数组特定索引也需要使用 `Vue.set` 或 `splice`。

## Vue2 响应式实现细节与 API *Content-[06:19]

**依赖收集与触发更新机制**
- **get 拦截**：在读取属性时触发，如果存在 `Dep.target`，则进行依赖收集。
- **set 拦截**：在修改属性值时触发，值更新后会通知收集到的依赖进行视图更新。

**Vue2 响应式特点总结**
1. **初始化开销大**：需要在初始化时递归遍历对象的所有属性进行劫持。
2. **数组特殊处理**：必须重写 7 个数组方法来实现响应式。
3. **无法检测属性增删**：不能自动检测对象新增或删除的属性，必须依赖 `Vue.set` / `Vue.delete`。
4. **数组索引限制**：不能直接通过索引修改数组项，需借助 `Vue.set` 或 `splice`。

## Vue2 代码深入解析与 Vue.set 原理 *Content-[10:58]

**Object.defineProperty 代码演示**
- 遍历初始数据 `initData`，使用 `Object.defineProperty` 劫持每个 `key`。
- **get 操作**：访问属性时触发，返回 `initData` 中的真实值。
- **set 操作**：修改属性时触发，更新值并打印日志。
- **缺陷验证**：如果直接给对象新增属性（如 `data.vue2 = ...`），访问该属性时会返回 `undefined`。因为初始化时只代理了已有属性，新属性未被劫持，无法进行依赖收集。

**Vue.set (this.$set) 源码逻辑解析**
`Vue.set` 的主要作用是向响应式对象中添加属性，并确保新属性同样是响应式的。其内部处理逻辑如下：
1. **数组场景**：如果目标是数组且索引有效，直接调用重写过的 `splice` 方法进行修改，从而触发响应式更新。
2. **对象场景**：
   - 如果 `key` 已存在于对象中（`key in target`），直接修改值即可，因为它已经具备响应式。
   - 如果 `key` 不存在，首先判断目标对象是否为响应式对象（检查是否存在 `__ob__` 属性），并排除 Vue 实例等特殊情况。
   - 满足条件后，调用 `defineReactive` 方法，为新属性重新添加 `get` 和 `set` 劫持，完成响应式设置。

## Vue3 响应式原理与 Proxy 代码演示 *Content-[18:21]

**核心原理**
Vue3 的响应式系统摒弃了 `Object.defineProperty`，转而使用 ES6 的 `Proxy` 来代理整个对象，从而完美解决了 Vue2 的痛点。

**Proxy 代码演示**
- 使用 `new Proxy(target, handler)` 创建代理对象，间接访问目标对象。
- **handler 配置**：
  - `get` 拦截：接收 `target`、`key`、`receiver`，使用 `Reflect.get` 获取并返回值。
  - `set` 拦截：接收 `target`、`key`、`value`、`receiver`，使用 `Reflect.set` 设置值。
- **优势验证**：直接给代理对象新增属性（如 `proxyObj.vue2 = ...`），依然能够被 `get`/`set` 拦截并监测到变化，无需额外处理。

## Vue3 Proxy 特性总结与面试思路延伸 *Content-[23:45]

**Vue3 Proxy 的核心优势**
1. **惰性代理（按需代理）**：无需在初始化时递归遍历所有属性。只有在访问属性（触发 `get`）时才会进行深层代理，大大提升了初始化性能。
2. **全面监听**：原生支持监听对象新增、删除属性以及数组的所有变化，无需再重写数组方法。
3. **完整拦截**：`Proxy` 支持拦截对象的所有操作（增、删、改、查、遍历等），而不仅仅是 `get` 和 `set`，功能更强大。

**Vue3 的局限性**
- **兼容性问题**：`Proxy` 是 ES6 新特性，无法通过 polyfill 完美降级，因此 IE 浏览器不支持。使用 Vue3 需要放弃对 IE 的支持。

**面试思路延伸**
这种“对比法”不仅适用于响应式原理，还可以广泛应用于其他面试高频题。例如：
- **Diff 算法**：对比 Vue2 的双端 Diff 算法与 Vue3 的快速 Diff 算法，阐述 Vue3 在策略和性能上的优化。
- 通过“旧版本实现 -> 存在痛点 -> 新版本优化”的逻辑链条，能够充分展现你的技术深度和全局视野。
