## 1. 自定义属性校验测试 *Content-[00:01]

在 Vue 组件封装中，对传入的 Props 进行自定义校验（Validator）是非常重要的一环，能够有效规范组件的使用并减少错误。

- **校验 `size` 属性**：
  - 如果传入不符合要求的值（例如传入 `small1`），控制台会抛出警告（Warning）。
  - 警告信息会明确指出是哪个属性校验失败（`size`），并提示要求的合法值必须是 `large`、`medium` 或 `small`。
- **校验 `color` 属性**：
  - 同理，如果传入不存在的颜色值（例如 `danger1`），也会触发校验失败的警告。
  - 修正为合法值并保存刷新后，警告即可消除。
- **核心要点**：自定义校验（validator）在组件封装中必不可少，它能确保外部传入的数据类型和枚举值符合组件的设计规范。

## 2. 封装按钮禁用状态 *Content-[00:44]

接下来为按钮组件封装禁用（Disabled）状态，使其在特定条件下不可点击并呈现相应的视觉反馈。

- **接收 `disabled` 属性**：
  - 在组件的 `props` 中定义 `disabled` 属性。
  - **类型（Type）**：`Boolean`。
  - **默认值（Default）**：`false`（表示默认不禁用）。
- **属性绑定与注意事项**：
  - 在模板中，需要将接收到的 `disabled` 动态绑定到原生按钮上，使用 `:disabled="disabled"`。
  - **易错点**：在原生 HTML 中直接写 `disabled` 即可，但在 Vue 中如果要传递布尔值 `true`，**必须使用 `v-bind`（即冒号 `:`）**。如果不加 `:`，`disabled="true"` 会被解析为字符串 `"true"`，从而导致逻辑错误。为了代码清晰，可以直接写 `:disabled="true"` 或绑定变量。
- **禁用状态的样式处理**：
  - 当按钮处于禁用状态时，需要改变鼠标悬浮时的样式。
  - 在 CSS 中使用伪类选择器（如 `:disabled`），设置 `cursor: not-allowed;`，使鼠标指针显示为禁止点击的图标，提升用户体验。

## 3. 封装按钮点击事件（子传父） *Content-[03:13]

组件封装不仅是样式的传递，还包括事件的通信。需要实现点击子组件按钮时，能够触发父组件中定义的逻辑。

- **子组件事件绑定与处理**：
  - 在子组件的 `<button>` 标签上绑定原生点击事件：`@click="handleClick"`。
  - 在 `methods` 中定义 `handleClick` 方法。
  - **核心逻辑判断**：只有当按钮**未被禁用**时（`if (!this.disabled)`），才允许触发后续事件。这是为了防止禁用状态下依然能触发业务逻辑。
  - **子传父（$emit）**：在判断通过后，使用 `this.$emit('click')` 向父组件触发自定义的 `click` 事件。（注：虽然 `click` 是原生 DOM 事件名，但在 Vue 组件通信中，将其作为自定义事件名 `$emit` 出来也是完全可行的）。
- **父组件监听与使用**：
  - 在父组件中使用该按钮组件时，通过 `@click="handleDefaultClick"` 来监听子组件抛出的自定义事件。
  - **注意区分**：此处的 `@click` 监听的是子组件 `$emit` 出来的自定义事件，而非原生 DOM 的 `click` 事件。
  - **多类型按钮的回调处理**：
    - 由于按钮有多种颜色/类型（如 default, success, danger, warning），需要在父组件的 `methods` 中定义多个不同的回调函数（如 `handleDefaultClick`, `handleSuccessClick` 等）。
    - 为不同颜色的按钮分别绑定对应的回调函数，并在函数内部编写具体的业务逻辑（如 `console.log('默认按钮被点击了')`）。
    - 测试时，点击不同按钮会触发对应的回调，而禁用状态的按钮点击无任何反应，验证了逻辑的正确性。

## 4. 编写组件使用文档（企业级协作规范） *Content-[08:27]

在企业级开发和多人协作中，封装完组件后**必须**编写组件使用文档。这能大幅降低沟通成本，避免同事反复询问或自行阅读源码，是体现程序员专业性、严谨性和丰富工作经验的重要环节。

- **参考标准**：
  - 建议参考主流 UI 组件库（如 Element UI）的文档结构来编写，照葫芦画瓢，确保规范统一。
- **Attributes（属性）表格设计**：
  - 表格应包含 5 个核心字段：**参数**、**说明**、**类型**、**可选值**、**默认值**。
  - **`color`**：说明（按钮颜色），类型（String），可选值（primary, success, danger, warning），默认值（primary）。
  - **`size`**：说明（按钮尺寸），类型（String），可选值（large, medium, small），默认值（medium）。
  - **`disabled`**：说明（是否禁用状态），类型（Boolean），可选值（true / false），默认值（false）。
- **Events（事件）表格设计**：
  - 参考 Element UI 中 Radio 等组件的 Events 表格，包含 3 个字段：**事件名**、**说明**、**回调函数**。
  - **`click`**：说明（点击按钮时触发），回调函数（点击按钮后触发的回调函数）。
- **协作建议**：
  - 封装完成后，将文档发送给协作同事，让他们直接通过文档了解组件的 Props 和 Events，从而极大提高团队的整体开发效率。
