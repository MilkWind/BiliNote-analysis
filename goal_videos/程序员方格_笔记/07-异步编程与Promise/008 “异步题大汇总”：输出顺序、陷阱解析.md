## JavaScript 异步题与事件循环机制 *Content-[00:01]
- **异步题的定位**：异步题是前端面试中最能考察候选人 JavaScript 基本功的题目类型之一。题目通常会给出一段包含多种异步操作的代码，要求预测其执行顺序和最终输出。
- **视频核心目标**：
  - 深入解析如何准确预测 JavaScript 异步代码的输出。
  - 剖析背后的核心机制：事件循环（Event Loop）。
  - 理解宏任务（Macro Task）和微任务（Micro Task）的优先级差异。
  - 结合经典面试题，手把手拆解分析执行流程。
- **JavaScript 单线程与事件循环**：
  - JavaScript 是单线程的，意味着同一时间只能执行一件事。
  - 当遇到耗时操作（如网络请求、定时器）时，如果主线程一直等待，会导致页面卡死。
  - 为解决此问题，JavaScript 引入了事件循环机制。它是实现非阻塞行为的关键，负责协调和调度各种异步任务的执行。

## 核心概念：宏任务与微任务 *Content-[01:32]
要理解事件循环，需要认识以下几个核心要素：
- **Call Stack（主线程）**：同步代码执行的地方。当遇到异步操作时，主线程不会等待，而是将任务交给外部的事件触发器处理。当外部操作完成（如定时器时间到、网络请求返回），对应的回调函数不会立即执行，而是被放入不同的任务队列中排队。
- **任务队列分类**：主要分为宏任务队列和微任务队列。

### 宏任务（Macro Task）
- 宏任务是比较大型、相对独立的任务单元。
- 事件循环在每次迭代时，会从宏任务队列中取出并执行**一个**任务。
- **常见 API**：
  - 定时器：`setTimeout`、`setInterval`。
  - Node.js 环境：`setImmediate` 以及各类 IO 操作。
  - 浏览器环境：UI 渲染也被视为一种宏任务。

### 微任务（Micro Task）
- 微任务通常更小、执行速度更快。
- 与宏任务不同，在当前宏任务执行完毕后，事件循环会**立即检查并清空整个微任务队列**，这使得微任务拥有更高的优先级。
- **常见 API**：
  - `Promise.then`、`.catch`、`.finally` 方法的回调。
  - `async/await`：基于 Promise 的语法糖。在 `await` 等待 Promise resolve 或 reject 后，将后续代码作为微任务处理。
  - Node.js 环境：`process.nextTick` 是一种特殊的微任务。
  - 标准 API：`queueMicrotask` 也可以用来创建微任务。

## 事件循环流程与核心规则 *Content-[04:38]
- **事件循环的完整流程**：
  1. 执行当前的宏任务（如刚开始运行的主脚本代码）。
  2. 当该宏任务执行完毕后，事件循环会检查并清空所有排队的微任务。
  3. 如果有 UI 渲染或其他特定阶段的任务，可能会在此阶段执行。
  4. 紧接着，事件循环再次检查宏任务队列，取出下一个宏任务执行。
  5. 流程回到检查微任务队列的步骤，循环往复，直到所有队列清空。
- **核心规则**：
  - **微任务的优先级高于宏任务**。
  - 在一个事件循环的迭代中，只要存在微任务，它们就必须先于下一个宏任务执行。
  - 所有在当前宏任务执行过程中产生的微任务，都会在进入下一个宏任务之前被“一股脑”地清空。

## 异步代码常见陷阱解析 *Content-[06:19]
### 陷阱一：`setTimeout(..., 0)`
- **误区**：很多人以为设为 0ms 就意味着立即执行。
- **真相**：它只是将回调函数尽快地放入宏任务队列。它仍然是一个宏任务，需要等待当前正在执行的宏任务完成，以及当前周期内所有的微任务执行完毕之后，才会在下一个事件循环迭代的宏任务阶段轮到自己执行。

### 陷阱二：`async/await`
- 虽然它让异步代码看起来像同步一样，但背后仍然是事件循环在调度。
- 当 `async` 函数执行到 `await` 一个 Promise 时，它会暂停执行并等待状态变化，此时控制权交还给事件循环。
- 当 Promise resolve 或 reject 后，`await` 后续的代码会被打包成一个微任务，加入微任务队列等待执行。因此，`await` 后面的代码实际上是在**下一个微任务阶段**执行的。

### Node.js 环境差异
- **Node.js 11 及更高版本**：事件循环行为基本与浏览器统一，`process.nextTick` 和 Promise 微任务都在同一个微任务队列。
- **Node.js 10 或更早版本**：`process.nextTick` 的优先级高于 Promise 微任务，遇到此类老版本题目需额外注意。
- **`setImmediate`**：在不同的阶段执行，通常在 IO 回调后，但在定时器之前。

## 经典面试题深度拆解 *Content-[08:57]
通过一段包含 `setTimeout` 和 `Promise` 链式调用的经典代码，逐步分析其在浏览器/Node.js 11+ 环境中的执行流程：

1. **主脚本执行（第一个宏任务）**：
   - 同步输出 `start`。
   - 遇到 `setTimeout`（宏任务），将其回调交给 Web API 计时，完成后放入宏任务队列。
   - 遇到 `Promise.resolve().then(...).then(...)`（微任务），将第一个 `.then` 回调放入微任务队列。
   - 主脚本同步代码执行完毕，输出 `end`。
2. **清空微任务队列**：
   - 执行第一个微任务（第一个 `.then` 回调）：输出 `promise1`。内部遇到新的 `setTimeout`，将其回调放入宏任务队列（此时宏任务队列有 2 个任务）。
   - 执行第二个微任务（第二个 `.then` 回调）：输出 `promise2`。
   - 微任务队列清空。
3. **执行下一个宏任务**：
   - 取出宏任务队列中的第一个任务（主脚本中的 `setTimeout` 回调）。
   - 输出 `setTimeout1`。内部遇到 `Promise.resolve().then(...)`，将其回调放入微任务队列。
   - 该宏任务执行完毕。
4. **再次清空微任务队列**：
   - 执行新加入的微任务：输出 `promise in setTimeout`。
   - 微任务队列清空。
5. **执行最后一个宏任务**：
   - 取出宏任务队列中的第二个任务（在第一个 Promise `.then` 中创建的 `setTimeout` 回调）。
   - 输出 `setTimeout in promise`。
   - 所有任务执行完毕，程序结束。

**最终标准输出顺序**：
`start` -> `end` -> `promise1` -> `promise2` -> `setTimeout1` -> `promise in setTimeout` -> `setTimeout in promise`

## 核心要点总结与参考资料 *Content-[15:34]
- **预测异步代码输出的核心要点**：
  - 一切围绕事件循环：执行顺序为一个宏任务 -> 清空所有微任务 -> 执行下一个宏任务，循环往复。
  - `setTimeout` 不是立即执行，依然是宏任务，需等待前面的任务和微任务。
  - `Promise.then` 和基于它的 `async/await` 后面的代码属于高优先级的微任务。
