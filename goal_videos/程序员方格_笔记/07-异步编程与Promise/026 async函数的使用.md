## 回顾 Promise 的痛点 *Content-[00:00]
- **解决回调地狱**：`Promise` 很好地解决了传统回调函数嵌套过深、代码难以维护的问题。
- **链式调用依然繁琐**：虽然解决了嵌套问题，但 `Promise` 的 `.then()` 链式调用会导致代码变成“一嘟噜一串”，阅读和编写起来依然让人感到崩溃和繁琐。
- **工具应当追求简便**：视频中以洗葡萄、草莓等水果为例，说明虽然吃水果时洗水果的麻烦有时不可避免，但代码工具是我们开发者自己发明的，完全可以通过新的语法来优化这种繁琐的使用体验。

## async 函数的引入与基本语法 *Content-[04:00]
- **ES6 的新特性**：为了解决 `Promise` 在多个异步代码按顺序执行时写法繁琐的问题，ES6 推出了 `async` 异步函数。
- **黄金搭档**：`async` 函数必须搭配 `await` 关键字/语句一起使用，才能构成完整的异步编程解决方案。
- **基本语法格式**：
  ```javascript
  async function 函数名() {
      // 函数体内容
  }
  ```

## async 函数的返回值与 await 的使用 *Content-[05:40]
- **async 函数的返回值**：
  - `async` 函数的返回值默认是一个 `Promise` 对象。
  - 如果函数内部定义了 `return`，那么返回的结果将在 `.then()` 方法中接收。
- **避免无意义的 async**：
  - 如果 `async` 函数内部没有使用 `await`，仅仅是执行普通的同步代码，那么使用 `async` 没有任何实际意义。
  - 对于纯同步代码，直接使用普通的 `function` 即可，不要为了用而用。
- **await 的使用规则**：
  - `await` 后面必须跟一个 `Promise` 对象，或者一个返回 `Promise` 结果的表达式。
  - **代码示例**：
    ```javascript
    async function show() {
        // await 后面必须跟 Promise 对象或返回 Promise 的表达式
        let data1 = await 异步操作1(); 
        console.log('第一次计算结果:', data1);
        
        let data2 = await 异步操作2();
        console.log('第二次计算结果:', data2);
        
        return '计算完毕';
    }
    
    // 调用并获取最终 return 的结果
    show().then(result => {
        console.log(result);
    });
    ```

## async/await 的核心特点与优势 *Content-[11:00]
- **强行把异步变同步**：
  - `await` 会强行使代码等待其后面的 `Promise` 异步代码执行完毕后，才会继续往下执行后续代码。
  - **本质理解**：这里的“变同步”并不是真的把异步代码放到同步任务队列中执行（底层依然是异步机制），而是将一堆异步代码以**同步的方式（按顺序执行）** 展现出来，避免了以前异步代码无序、跳跃执行的问题。
- **代码可读性大幅提升**：
  - 对比 `Promise` 的链式调用，`async/await` 的写法更符合人类理解的顺序执行逻辑。
  - 代码结构更加清晰，看起来就像是在写同步代码一样，极大地降低了心智负担。
- **统一的结果处理**：
  - `async` 函数最后 `return` 的值，依然可以通过 `.then()` 来获取。
  - 并且 `.then()` 会耐心等待函数内部所有 `await` 执行完毕后，才会触发并拿到最终的返回值。

## AI 总结
本节课深入讲解了前端异步编程中 `async/await` 的使用。首先回顾了 `Promise` 虽然解决了回调地狱，但链式调用依然繁琐的痛点。随后引入了 ES6 的 `async` 函数，强调其必须与 `await` 搭配使用才有意义。详细解析了 `async` 函数默认返回 `Promise` 对象，以及 `await` 后必须接 `Promise` 对象的规则。最后总结了 `async/await` 的核心优势：它通过“强行把异步变同步”的机制，让异步代码能够按顺序执行，大幅提升了代码的可读性和编写体验，是目前处理复杂异步逻辑的最佳实践方案。
