## for...of 与 for...in 的特点 *Content-[00:00]

### for...of 的特点
- **ES6 新增语法**：`for...of` 是 ES6 中新增的循环语句。
- **遍历可迭代对象**：它可以遍历所有可迭代对象（Iterable），例如数组（Array）、字符串（String）、Map、Set 等。
- **无需索引**：与传统的 `for` 循环不同，`for...of` 不需要使用索引来返回元素，直接获取元素的值，使用更加便捷。

### for...in 的特点
- **遍历键名与索引**：`for...in` 经常用于遍历对象的键名（Key），或者遍历数组的索引。
- **不适合遍历数组**：强烈不建议使用 `for...in` 来遍历数组。因为它会遍历数组所有的可枚举属性，包括原型链（Prototype）上的属性，这会导致遍历出非预期的数据。
- **存在缺陷**：由于上述原型链遍历的问题，`for...in` 存在明显的缺陷，在实际开发工作中应尽量避免使用。

## ES6 装饰器 (Decorator) *Content-[01:03]

- **内置装饰器**：ES6 引入了 Decorator（装饰器）语法。
- **使用限制**：需要注意的是，ES6 的装饰器主要是用于类（Class）的装饰，**不能**用来装饰普通的函数。

## Promise 的核心特性与状态 *Content-[01:15]

### Promise.all 与 Promise.race
- **Promise.all**：接收一个 Promise 数组，**并行**执行所有的 Promise，并等待**全部完成**后才返回结果。
- **Promise.race**：同样是**并行**执行多个 Promise，但它的特性是“竞速”，只要其中有**最快执行完**的一个 Promise，就会立即返回该结果，其他未完成的 Promise 结果将被忽略（取消）。

### Promise 的三种状态
- **pending**：进行中。
- **fulfilled**：已成功。
- **rejected**：已失败。
- **状态不可逆**：当 Promise 的状态从 `pending` 变为 `fulfilled` 或 `rejected` 之后，状态就会被凝固，**不能再发生任何改变**。

## 浏览器的宏任务与微任务及事件循环 *Content-[01:51]

### 宏任务与微任务的概念
- **任务分类**：在 JS 引擎中，异步任务被分为宏任务（MacroTask）和微任务（MicroTask）。
- **宏任务**：由浏览器规定和提供的任务，例如定时器（`setInterval`、`setTimeout`）。
- **微任务**：由 ES6 规范引入的任务，例如 `Promise.then` 的回调。

### 关于 DOM 渲染时机的纠正
- **老说法的局限性**：过去常说“微任务在 DOM 渲染之前执行，宏任务在 DOM 渲染之后执行”，这种说法现在来看**稍微有些过时且不完全准确**。
- **React 中的特例**：在 React 框架中，`render` 渲染实际上是在微任务中执行的；而 `useEffect` 是在微任务的异步中执行的。因此，`useEffect` 的回调实际上是在 DOM 渲染**之后**执行的。不能绝对地说微任务一定在 DOM 渲染前。

### 事件循环 (Event Loop) 机制
- **底层实现**：在 Chrome 源码中，事件循环实际上开启了一个不会结束的 `for` 循环，每次从消息队列中取出第一个任务去执行，其他线程则在合适的时候将任务加到队列末尾。
- **现代浏览器的 Task 类型**：现在的浏览器环境非常复杂，存在多种不同类型的 Task，宏任务和微任务只是其中的两种类型，老式的简单二分法已无法满足现代需求。
- **执行优先级**：微任务队列（MicroTask Queue）的优先级**高于**宏任务队列。

### 完整的执行顺序
1. 将所有同步代码推入执行栈（Call Stack），从上到下直接执行。
2. 遇到异步代码时，将其放入对应的任务队列中。
3. 当前执行栈清空后，线程会去检查**微任务队列**，如果有任务则取出放入执行栈执行，直到微任务队列清空。
4. 接着检查**宏任务队列**，取出第一个宏任务放入执行栈执行。
5. 该宏任务执行完后，**再次检查微任务队列**并执行。
6. 不断重复“执行一个宏任务 -> 清空微任务队列”的过程。

## console.log 的同步与异步特性 *Content-[04:22]

- **本质是同步**：`console.log` 实际上是**同步**代码，与异步机制完全没有关系。
- **引用类型的延迟**：出于性能优化的考虑，当使用 `console.log` 打印**引用类型**（Reference Type）的数据时，对其内部值的读取和展示是存在延迟的（即打印时可能只保存了引用，展开查看时才会读取最新值）。

## WeakMap 的作用与特性 *Content-[04:36]

- **弱映射/弱引用**：`WeakMap` 是一种弱映射数据结构，它的键（Key）所引用的对象是**弱引用**（Weak Reference）。
- **核心作用**：主要用于**内存回收**（Garbage Collection）。当键引用的对象没有其他引用时，垃圾回收机制会自动回收该对象所占用的内存，从而有效防止内存泄漏。

## ES6 Map 数据结构详解 *Content-[04:49]

### 基本特点
- **键值对集合**：`Map` 是键值对的集合，类似于对象。
- **键的类型不限**：与 Object 的键只能是字符串不同，`Map` 的键可以是**任意数据类型**。
- **操作方法**：通过 `set()` 和 `get()` 方法来添加/修改和读取元素。

### 构造函数与参数
- `Map` 是一个构造函数，可以接收一个数组作为参数。
- 该数组的成员必须是**键值对**（即二维数组）。
- 任何具有 `Iterator` 接口的数据结构（包括 `Set` 和 `Map` 本身）都可以作为 `Map` 构造函数的参数。

### 键值覆盖与读取
- 如果对同一个键多次赋值，**后面的值将会覆盖前面的值**。
- 如果读取一个不存在的键，则返回 `undefined`。

### 键的判定规则（核心考点）
- **对象类型**：只有对**同一个对象的引用**（即内存地址完全相同），`Map` 才视为同一个键。
- **基本数据类型**：只要两个值**严格相等**（`===`），就被视为同一个键。
  - 例如：`0` 和 `0` 是同一个键。
  - 注意：布尔值 `true` 和字符串 `"true"` 是**两个不同**的键；`undefined` 和 `null` 也是**两个不同**的键。
- **特殊值 NaN**：`NaN` 在 `Map` 中被视为一个键，且**所有的 `NaN` 都互为同一个键**（即使 `NaN !== NaN`）。

## ES6 Set 数据结构详解 *Content-[06:38]

- **构造函数**：`Set` 也是一个构造函数。
- **类数组结构**：它类似于数组，但其核心特点是**成员唯一，没有重复值**。
- **主要用途**：在实际开发中，`Set` 最常被用来进行**数组去重**操作。
