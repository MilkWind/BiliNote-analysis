## 面试背景与核心痛点 *Content-[00:00]
在面试和实际工作中，给 `Promise` 增加超时功能是一道高频场景题，能够很好地考察对异步编程的理解深度。

- **常见痛点场景**：发起网络请求时，若后端服务故障或用户网络极差，会导致接口迟迟没有返回，页面如同卡死，用户体验极差。
- **核心问题**：`Promise` 在设计之初本身不带任何超时功能。一旦 `new` 了一个 `Promise` 实例，它就会执行到底，开发者无法从外部直接中断它。

## 实现超时功能的三大难点 *Content-[00:57]
要完美解决超时问题，需要先理清以下三个核心难点：

1\. **Promise 机制问题**：一旦创建就无法取消。即使我们在代码层面判定已经超时，但原始的 `fetch` 请求其实还在后台继续运行，这会导致不必要的资源浪费。
2\. **竞态条件（Race Condition）**：正常完成和超时这两个逻辑在“赛跑”。如果它们几乎同时发生，必须保证逻辑的正确性，避免出现意想不到的 Bug。
3\. **错误处理**：当代码 `catch` 到一个错误时，必须能够清晰地告诉用户或开发者，这到底是请求超时、接口本身的 500 错误，还是其他的网络问题。错误信息的清晰度至关重要。

## 及格分方案：利用 Promise.race 解决竞态与错误处理 *Content-[01:54]
解决上述难点的最优解是利用 `Promise.race` 这个 API，它本身就是为竞速场景而生的。

- **第一步：创建超时 Promise**
  封装一个 `timeoutPromise` 函数，内部使用 `setTimeout`。当指定的时间（毫秒）到达后，直接 `reject` 一个带有超时信息的错误。这个 `Promise` 只负责一件事：在规定时间后宣布超时。
- **第二步：竞速组合**
  将业务逻辑需要用到的 `Promise`（例如 `fetch` 请求）和 `timeoutPromise` 一起放入一个数组中，然后传给 `Promise.race`。
  - 如果 `timeoutPromise` 先跑完（时间到了），`race` 的结果就是 `reject`，代码会捕获到超时错误。
  - 如果业务逻辑的 `Promise` 在规定时间内成功 `resolve`，`race` 的结果就是正常的业务数据。
- **错误信息区分**
  在 `.catch` 处理中，通过判断错误信息是否包含“超时”关键字，就能准确区分出是超时错误还是其他错误，从而给用户不同的提示。

*注：通过这种简单的组合，优雅地解决了超时控制和竞态条件这两个难题，同时保证了错误信息的清晰度，这在面试中可以拿到及格分。*

## 满分方案：结合 AbortController 彻底解决资源浪费 *Content-[04:21]
想要拿满分，必须解决第一个难点：**Promise 无法取消导致的资源浪费**。此时需要配合浏览器提供的标准 API `AbortController`，它专门用来终止一个或多个 Web 请求。

- **改造 withTimeout 函数**
  1. 函数增加一个 `signal` 参数。
  2. 在 `timeoutPromise` 内部，监听 `signal` 的 `abort` 事件。
  3. 一旦外部调用了 `abort` 方法，监听到该事件后，立即执行清除定时器的操作，并 `reject` 一个“操作已取消”的错误。这一步是让超时逻辑本身也可以被取消的关键。
- **实际用法与资源释放**
  1. 实例化一个 `AbortController`：`const controller = new AbortController()`。
  2. 在 `fetch` 的配置项中，将 `signal` 字段赋值为 `controller.signal`。
  3. 同时，将 `controller.signal` 传给封装的 `withTimeout` 函数。
  4. 这样一来，`fetch` 请求和超时定时器就被同一个 `signal` 关联起来了。
  5. 当用户等不及点击页面上的“取消”按钮时，只需调用 `controller.abort()`。这个信号会同时通知 `fetch`（中断 HTTP 请求）和 `timeoutPromise`（清除 `setTimeout`），从而实现真正的请求终止和资源释放。

## 满分答案总结 *Content-[06:03]
在面试中回答此题，答出以下三点即可给出眼前一亮的满分答案：

1\. **核心竞速**：利用 `Promise.race` 实现业务逻辑和超时逻辑的竞速。
2\. **独立计时**：封装一个独立的 `timeoutPromise`，让它专门负责计时和在超时后 `reject` 错误。
3\. **彻底取消**：配合 `AbortController` 和 `signal`，实现对请求和定时器的真正取消，避免底层资源的浪费。
