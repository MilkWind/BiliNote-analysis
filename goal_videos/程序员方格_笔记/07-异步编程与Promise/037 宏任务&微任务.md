## 事件循环基础概念 *Content-[00:00]
- **任务队列与事件触发线程**：在主线程之外，存在事件触发线程来管理任务队列（Task Queue）。当异步任务有了运行结果后，会在任务队列中放入一个事件回调。
- **JS 引擎空闲与任务读取**：一旦执行栈中的所有同步任务执行完毕（即 JS 引擎空闲），系统就会读取任务队列，将可运行的异步任务（如事件回调）添加到执行栈中执行。这就是事件循环（Event Loop）的基本内容。
- **JS Engine 的职责**：JS 引擎主要负责执行当前的 JS 代码，运行主线程中的同步任务。
- **异步任务的来源**：在运行主线程时，会产生一些异步任务，例如对 DOM 的操作、Promise、setTimeout 等 Web API。这些异步任务有了结果后，会存入任务队列中等待执行。

## 宏任务（Macro Task）与 GUI 渲染 *Content-[01:01]
- **任务分类**：任务队列中的任务主要分为两类：宏任务（Macro Task）和微任务（Micro Task）。
- **宏任务的定义**：宏任务可以理解为同步任务。每次执行栈执行代码（整体代码块）都被当作一个宏任务。常见的宏任务包括：整体代码块、IO 操作、setTimeout、setInterval 等。
- **JS 引擎与 GUI 线程的交替工作**：
  - JS 引擎线程与 GUI 渲染线程是互斥的。
  - 为了保证宏任务与 DOM 渲染有序进行，浏览器会在一个宏任务执行结束之后、下一个宏任务执行之前，让 GUI 线程开始工作。
  - 工作流程呈现交替形式：JS 引擎执行宏任务 -> GUI 渲染 -> 继续执行下一个宏任务。
- **执行顺序**：先执行主线程的宏任务，遇到 setTimeout 等异步宏任务时，会将其放入队列，等待下一次宏任务执行。主线程执行完毕后，进行 GUI 渲染，然后再检查队列中是否有 setTimeout 等宏任务的回调并执行。

## 微任务（Micro Task）详解 *Content-[04:03]
- **微任务的引入**：ES6 引入 Promise 标准后，浏览器增加了微任务（Micro Task）的概念。
- **微任务的执行时机**：微任务是在当前宏任务执行完毕后、**GUI 渲染之前**立即执行的任务。
- **常见的微任务类型**：
  - `process.nextTick`（Node.js 环境）
  - `MutationObserver`（DOM 观察器，用于性能优化、防抖节流等场景）
  - `Promise.then`、`Promise.catch`、`Promise.finally`
- **执行逻辑**：
  - 当前宏任务执行完毕后，不会立即进行 GUI 渲染，而是先检查微任务队列。
  - 如果微任务队列中有回调，会立即全部执行并清空微任务队列。
  - 微任务清空后，再进行 GUI 渲染。
  - 渲染结束后，再次检查宏任务队列，执行下一个宏任务，循环往复。

## 事件循环整体执行流程 *Content-[07:00]
- **初始阶段**：进入整体任务队列，判断同步和异步。主线程优先执行同步任务。
- **先微后宏原则**：
  - 主线程同步任务执行完毕后，首先检查微任务队列。
  - 如果有微任务，立即执行并清空所有微任务。
  - 微任务清空后，进行 GUI 渲染。
  - 渲染完毕后，检查宏任务队列，进入下一轮事件循环，执行下一个宏任务。
- **循环机制**：宏任务执行完毕后，再次查看微任务队列，清空微任务，然后进行渲染，最后继续执行宏任务。这是一个不断交替的过程。

## 示例解析一：Promise 基础执行顺序 *Content-[08:40]
- **代码逻辑**：
  ```javascript
  new Promise((resolve) => {
      console.log(1);
      resolve();
  }).then(() => {
      console.log(2);
  });
  console.log(3);
  ```
- **输出结果**：`1 -> 3 -> 2`
- **详细解析**：
  1. `new Promise` 初始化及其内部的 `console.log(1)` 属于同步任务，直接执行，输出 **1**。
  2. 调用 `resolve()` 后，`.then()` 中的回调函数被放入微任务队列。
  3. 主线程继续向下执行同步代码 `console.log(3)`，输出 **3**。
  4. 此时主线程（当前宏任务）执行完毕，JS 引擎空闲，开始检查微任务队列。
  5. 发现微任务队列中有 `.then()` 的回调，取出执行，输出 **2**。

## 示例解析二：async/await 与 setTimeout 执行顺序 *Content-[10:40]
- **代码逻辑**：
  ```javascript
  setTimeout(() => {
      console.log(4);
  }, 0);

  async function test() {
      console.log(1);
      await Promise.resolve();
      console.log(3);
  }

  test();
  console.log(2);
  ```
- **输出结果**：`1 -> 2 -> 3 -> 4`
- **详细解析**：
  1. 遇到 `setTimeout`，将其回调函数放入宏任务队列。
  2. 执行 `test()` 函数，`console.log(1)` 是同步代码，直接执行，输出 **1**。
  3. 遇到 `await Promise.resolve()`，`await` 会将其后的代码（`console.log(3)`）挂起，并放入微任务队列。
  4. 函数执行暂停，主线程继续向下执行同步代码 `console.log(2)`，输出 **2**。
  5. 主线程同步代码执行完毕，检查微任务队列，执行 `await` 后的代码，输出 **3**。
  6. 微任务队列清空，进行 GUI 渲染（此处无实际渲染）。
  7. 检查宏任务队列，执行 `setTimeout` 的回调，输出 **4**。

## 浏览器 Event Loop 核心总结 *Content-[13:20]
- **执行顺序核心**：JS 主线程同步代码 -> 微任务 -> 宏任务。
- **微任务处理**：同步代码执行中遇到微任务，将其加入微任务队列。当前宏任务执行完毕后，立即执行并清空微任务队列中的所有微任务。
- **渲染介入**：微任务清空后，浏览器渲染线程接管进行 GUI 渲染。
- **循环重启**：渲染完毕后，JS 线程再次接管，开始下一轮宏任务循环。理解这一机制对于编写高性能前端代码至关重要。
