## 1. 面试题解析与 async/await 本质 *Content-[00:00]
- **面试题**：请用 `generator` 来模拟实现 `async/await`。
- **考察点**：对 JavaScript 异步编程核心原理的理解程度。
- **async/await 的本质**：
  - 它其实就是一个**语法糖**。
  - 核心原理是：**`generator` 函数 + 自动执行器**。
  - 两者的逻辑完全一样，都是“暂停 -> 等待 -> 继续”的模式。
- **为什么用 `generator` 作为底层**：其特性完美匹配 `async/await` 的要求。
  1. **暂停执行能力**：`generator` 使用 `yield` 关键字暂停，`async/await` 使用 `await` 暂停。
  2. **恢复执行能力**：当 `Promise` `resolve` 之后，代码能从暂停点继续执行。
  3. **双向通信**：`generator` 的 `yield` 不仅能向外传值，还能通过 `.next()` 方法向内传值，通过 `.throw()` 向内传错误。这正是 `async/await` 需要的核心能力。
- **`generator` 的局限性**：需要手动调用 `.next()` 才能一步一步执行，因此需要**执行器**来解决自动执行的问题。
  - 执行器的作用：自动管理 `next` 的调用顺序、处理 `Promise` 的 `resolve` 和 `reject`，最终把 `generator` 包装成返回 `Promise` 的形式。

## 2. 直接替换的卡点分析 *Content-[02:11]
不能简单地把 `async` 换成 `*`（变成 `generator` 函数），把 `await` 换成 `yield`。主要有以下三个卡点：
1. **需要自动执行**：`generator` 函数本身不会自动往下走，必须像“挤牙膏”一样手动调用 `.next()`。而 `async/await` 是完全自动的，实现“自动挡”是第一个难点。
2. **错误处理**：`async` 函数里可以使用 `try-catch` 捕获 `await` 失败的 `Promise`。但 `generator` 的 `yield` 只是一个暂停点，如果 `Promise` `reject`，需要通过 `.throw()` 将错误抛回 `generator` 函数内部的 `try-catch` 中。
3. **返回值形态不同**：`async` 函数调用后会立即返回一个 `Promise`，在函数执行完毕后 `resolve` 最终结果。而 `generator` 函数调用后返回的是一个**迭代器对象**。需要将迭代器包装成符合规范的 `Promise` 返回出去。

## 3. Generator 核心本质回顾 *Content-[03:38]
在写代码前，快速回顾 `generator` 作为状态机的双向通信能力：
- 调用 `generator` 函数不会立即执行，而是返回一个**迭代器对象**。
- 每次调用迭代器的 `.next()` 方法，代码从上次暂停的地方执行到下一个 `yield` 关键字，然后再次暂停。
- **关键特性**：`.next()` 方法可以接受一个参数 `value`，这个参数会作为**上一个 `yield` 表达式的返回值**传递回 `generator` 函数内部。
- **代码流程走查**：
  - `const it = g()`：得到迭代器对象。
  - 第一次 `it.next()`：不带参数，函数开始执行，在 `yield 1` 处暂停。返回对象 `{ value: 1, done: false }`。
  - 第二次 `it.next('hello')`：传入 `'hello'`，它作为 `yield 1` 表达式的求值结果赋值给变量 `a`（即 `a = 'hello'`）。代码继续执行到 `yield 2` 暂停。
  - 第三次 `it.next('world')`：`'world'` 赋值给变量 `b`，函数走到 `return` 语句执行完毕。返回对象 `{ value: 'world', done: true }`，表示执行结束。

## 4. 构建自动执行器核心逻辑 *Content-[05:59]
自动执行器的核心思路非常清晰：
1. 接收一个 `generator` 函数作为参数，调用它获取**迭代器对象**。
2. 定义一个内部函数（如 `step`），核心使命是调用 `.next()` 拿到结果。
3. 判断结果的 `done` 属性：如果为 `true`，说明执行完毕，直接返回最终结果；如果不为 `true`，则准备进行下一步。
4. **处理异步值与递归**：`yield` 出来的值不能直接作为下一次 `step` 的参数，因为暂停等待的可能是 `Promise`。
   - 使用 `Promise.resolve()` 包装 `yield` 出来的值（如果是 `Promise` 则直接包装返回，如果是普通值则包装成立即 `resolve` 的 `Promise`）。
   - 在 `.then()` 回调中拿到 `Promise` 成功后的结果，再**递归调用** `step` 函数。
5. 最后，不带任何参数直接调用 `step()` 启动整个流程。
- **代码结构**：`run` 函数接收 `generator` -> 获取迭代器 `it` -> 定义 `step(value)` -> `it.next(value)` -> 判断 `done` -> `Promise.resolve(value).then(step)` -> 初始调用 `step()`。完美解决了自动执行和处理异步值的问题。

## 5. 完善错误处理机制 *Content-[08:34]
如果 `yield` 等待的是一个会 `reject` 的 `Promise`，之前的代码中 `.then()` 会断掉，因为没有 `.catch()` 处理。
- **解决方案**：在 `.catch()` 方法中，使用迭代器的 `.throw()` 方法。
- **`.throw()` 的作用**：与 `.next()` 类似，但不是传值，而是往 `generator` 函数内部**扔一个错误**。这个错误会被函数内部的 `try-catch` 语句捕获，就像普通的 `throw` 一样。
- **注意事项**：
  - 在 `.catch()` 里调用 `it.throw(err)` 把 `reject` 信息扔回内部，让 `try-catch` 正常工作。
  - `.throw()` 也会消耗一次 `yield`，因此调用完之后，还需要**递归调用 `step`** 来继续执行，否则程序会中断。
  - 即使 `generator` 内部没有 `catch`，程序也会符合预期地中断，但为了保证功能完整，必须加上递归调用。

## 6. 面试满分答案总结 *Content-[10:06]
当面试官问及此题时，满分答案应包含以下逻辑：
1. **点明本质**：`async/await` 是 JS 的语法糖，底层实现原理是 **`generator` + 自动执行器**。
2. **阐述执行器的三大核心任务**：
   - **自动执行**：通过递归调用 `.next()` 方法，实现 `generator` 的自动执行，解决手动调用的问题。
   - **统一处理返回值**：通过 `Promise.resolve()` 来统一处理 `yield` 表达式的返回值。无论是普通值还是 `Promise`，都能无缝衔接，等待 `Promise` `resolve` 后再继续执行。
   - **错误注入**：通过 `Promise` 捕获 `reject`，并调用 `.throw()` 方法将错误注入回 `generator` 函数内部，让 `generator` 内部的 `try-catch` 能够正常生效。
