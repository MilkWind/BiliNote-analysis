## 1. 什么是事件循环 *Content-[01:45]

- **核心定义**：事件循环（Event Loop）是 JavaScript 执行异步操作的核心机制。
- **单线程特性**：JavaScript 本身是单线程的，意味着同一时间只能执行一件事。如果耗时任务（如网络请求、文件读写、用户点击事件）直接在主线程执行，会阻塞后续代码，导致页面卡死或程序无响应。
- **运行时环境提供**：事件循环并非 JavaScript 语言本身的特性，而是由 JavaScript 运行时环境（如浏览器或 Node.js）提供的机制。它充当“调度者”，协调处理非同步、需要等待的任务。
- **任务队列机制**：当异步任务（如 `setTimeout` 回调或 `Promise.then` 回调）准备好执行时，不会立即打断正在执行的同步代码，而是被放入特定的任务队列中等待。任务主要分为宏任务和微任务。
- **执行时机**：主线程总是优先执行当前的同步代码。只有当主线程上的同步代码全部执行完毕、调用栈（Call Stack）变为空时，事件循环才会介入，检查任务队列并将任务按规则移到调用栈中执行。
- **核心目标**：在单线程环境下实现非阻塞操作，保持应用或用户界面的响应性，使耗时的 IO 操作不再阻塞主线程。

## 2. 为什么需要事件循环 *Content-[05:06]

- **解决单线程阻塞痛点**：JavaScript 的单线程设计简化了编程模型，避免了多线程的复杂性，但带来了异步处理的挑战。若无事件循环，同步执行网络请求会导致整个页面或 Node.js 应用停止响应，无法处理用户交互、定时器或渲染 UI。
- **实现非阻塞 IO**：事件循环使得 JS 能够实现非阻塞的 IO 操作。实际耗时的网络请求或文件读写在浏览器或操作系统的其他线程中完成，完成后回调函数被放入任务队列，事件循环在合适时机将其推到主线程，避免阻塞。
- **保证 UI 响应性（浏览器环境）**：DOM 更新、用户交互（如点击、输入）的事件监听回调均通过事件循环调度。若 JS 脚本长时间霸占主线程，事件循环无法及时处理输入或重绘页面，会导致界面卡顿。事件循环确保了 CPU 密集型和 IO 密集型任务不会完全锁死 UI 线程。
- **异步编程模型的基础**：现代 JavaScript 异步编程模型（如 `Promise`、`async/await`、`setTimeout`、`fetch` 等）的底层实现均依赖于事件循环。没有事件循环，这些异步 API 将无法正常工作。

## 3. 事件循环的核心组成部分 *Content-[08:13]

- **调用栈（Call Stack）**：同步代码执行的地方。函数调用会被压栈（Push）和出栈（Pop），所有正在执行的函数都在这里。
- **堆（Heap）**：变量和对象在内存中存储的地址空间。
- **任务队列（Task Queue）**：用于存放等待执行的异步任务回调。包含宏任务队列和微任务队列。
- **事件循环（Event Loop）本身**：一个持续运行的进程，负责监控调用栈和任务队列，并在合适的时机将队列中的任务移到调用栈中执行。

## 4. 任务分类：宏任务与微任务 *Content-[09:19]

### 宏任务（Macro Task / Task）
- **特点**：通常比较独立，颗粒度较大。每一次事件循环迭代通常只处理一个宏任务。
- **常见类型**：
  - `setTimeout` 和 `setInterval` 的回调。
  - 用户产生的 DOM 事件（如点击、键盘输入）的回调。
  - 各种 IO 操作完成后的回调（如文件读取完毕、网络请求返回响应）。
  - 浏览器环境中的 UI 渲染（被视为宏任务，意味着在连续的 JS 执行之间，浏览器有机会更新页面）。
  - Node.js 环境特有的 `setImmediate` 回调。

### 微任务（Micro Task）
- **特点**：通常与当前执行的任务紧密相关，需要尽快执行。在每一次事件循环迭代的微任务阶段，会执行所有可用的微任务，直到微任务队列完全清空。
- **常见类型**：
  - `Promise.then`、`.catch` 以及 `.finally` 的回调函数（当 Promise 状态变为 fulfilled 或 rejected 时放入）。
  - ES6 引入的 `queueMicrotask` 函数。
  - `MutationObserver` 的回调函数（用于观察 DOM 树的变化）。
- **Node.js 特有高优先级队列**：`process.nextTick`。严格来说它不是标准的微任务，但行为类似且优先级更高，通常被放在微任务相关的讨论中。

## 5. 事件循环的单轮迭代流程 *Content-[12:21]

理解异步代码执行顺序的关键在于掌握单轮迭代流程：

1. **执行同步代码**：事件循环首先执行当前所有的同步代码，直到调用栈清空。在此过程中遇到的异步任务会被注册并放入相应的队列中。
2. **清空微任务队列**：同步代码执行完毕、调用栈为空后，事件循环检查微任务队列，执行所有可用的微任务直到队列清空。若在清空过程中产生新的微任务，会被立即添加到当前队列末尾并在本轮执行。
3. **执行一个宏任务**：微任务队列清空后，事件循环转向宏任务队列，取出排在最前面的**一个**宏任务来执行（注意：只执行一个，而不是全部）。
4. **循环迭代**：该宏任务执行完毕后，事件循环回到第 2 步，检查并清空新产生的微任务，然后再回到第 3 步取下一个宏任务。如此重复，直到宏任务和微任务队列都被清空。

## 6. 经典面试题解析：执行顺序分析 *Content-[14:20]

**代码示例**：
```javascript
console.log('1. start');
setTimeout(() => {
  console.log('4. setTimeout callback');
}, 0);
Promise.resolve().then(() => {
  console.log('3. Promise result callback');
});
console.log('2. end');
```

**执行过程详细分析**：
1. 遇到 `console.log('1. start')`：同步语句，立即压入调用栈执行，输出 `1. start`。
2. 遇到 `setTimeout`：异步宏任务，回调函数被注册，延迟后放入宏任务队列（即使延迟为 0，也需等待事件循环调度）。
3. 遇到 `Promise.resolve().then`：异步微任务，回调函数被放入微任务队列。
4. 遇到 `console.log('2. end')`：同步语句，立即执行，输出 `2. end`。
5. **同步代码执行完毕**，调用栈清空，事件循环介入。
6. **检查微任务队列**：发现 `Promise.then` 回调，将其压入调用栈执行，输出 `3. Promise result callback`。微任务队列清空。
7. **检查宏任务队列**：发现 `setTimeout` 回调，将其压入调用栈执行，输出 `4. setTimeout callback`。
8. **进入下一轮迭代**：微任务和宏任务队列均为空，事件循环停止或等待新事件触发。

## 7. 事件循环的关键注意事项 *Content-[19:15]

1. **同步代码优先级最高**：任何异步任务的回调，必须等待当前执行的同步脚本全部完成。
2. **微任务优先级高于宏任务**：在异步任务执行阶段，事件循环总会彻底清空微任务队列，然后才去执行下一个宏任务。这是两者最重要的区别。
3. **Node.js 环境的显著差异**：Node.js 的事件循环具有复杂的多阶段结构（包括 Timers, Pending callbacks, Poll, Check, Close callbacks 等），每个阶段处理特定的事件回调。此外，`process.nextTick` 队列的优先级极高，会在当前阶段任务及微任务执行完毕后、进入下一阶段前被处理，优先级甚至高于标准微任务。
4. **宏任务逐个执行的影响**：执行完一个宏任务后会检查并清空微任务队列，再取下一个宏任务。若有一个非常耗时的宏任务（如巨大的循环），虽然微任务和 UI 渲染可以在宏任务的间隙发生（不会完全阻止页面更新），但宏任务本身耗时会占用大量时间，导致帧率下降，造成页面卡顿感。

## 8. 总结与推荐学习资料 *Content-[22:28]

**核心重点总结**：
- 事件循环是 JavaScript 运行时环境中实现异步操作的核心机制。
- 异步任务主要分为宏任务（Macro Task）和微任务（Micro Task）两大类。
- 标准浏览器环境下，事件循环的基本执行顺序是：先执行完成当前所有的同步代码 -> 清空所有微任务 -> 执行宏任务队列中的第一个宏任务 -> 重复此过程。
- Node.js 环境具有多阶段事件循环，并且拥有优先级极高的 `process.nextTick` 队列。
