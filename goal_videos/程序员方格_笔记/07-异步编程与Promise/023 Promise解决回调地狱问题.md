## 1. Promise 的基本用法简化与链式编程 *Content-[00:00]

- **简化 `.then` 与 `.catch` 写法**
  - 在 Promise 的基本用法中，`.then` 和 `.catch` 不需要分开编写或重新接收 Promise 对象，可以直接使用**链式编程**。
  - **示例**：调用 `sum(1, 2)` 返回 Promise 对象后，可以直接链式调用 `.then(result => console.log(result))` 来接收并打印结果，大幅简化了代码写法。

- **`.then` 与 `.catch` 的链式调用**
  - `.catch` 可以直接跟在 `.then` 后面进行链式编程，无需另起一行去接收 Promise。
  - **状态与报错屏蔽**：当使用链式编程将 `.then` 和 `.catch` 连接在一起时，如果发生错误，报错信息会被屏蔽。这是因为在同一个链式编程中，它们相当于处于**同一个状态**（尽管内部原理有细微差别，但在实际开发中强烈推荐这种链式写法）。

## 2. Promise 解决回调地狱问题 *Content-[01:42]

- **回调地狱的背景**
  - 当多个异步代码需要顺序执行时，如果使用传统的回调函数方式，会导致回调函数层层嵌套。
  - 嵌套过深（如同两面镜子相对反射，越往深处越模糊）会导致代码极难维护，这就是所谓的**回调地狱**。

- **Promise 的解决机制**
  - **核心原理**：在 `.then` 的回调函数中，如果继续**返回一个新的 Promise 对象**，外层的 `.then` 方法就会继续匹配下一个 `.then` 的回调函数，从而实现链式编程。
  - **代码执行流程示例**：
    1. 调用 `sum(1, 2)`，在第一个 `.then(data => { ... })` 中接收第一次计算结果并打印。
    2. 在第一个 `.then` 内部 `return sum(data, 3)`，将第一次的结果作为参数传入，并返回新的 Promise。
    3. 外层继续链式调用 `.then(data => { ... })`，接收第二次计算结果并打印。
    4. 同理，继续 `return sum(data, 4)` 并接第三个 `.then`，以此类推。

- **链式编程的优势**
  - 代码结构从深层嵌套变为了**线性的链式结构**，从根本上解决了回调地狱问题。
  - **易于维护**：在链式结构中，哪个环节出问题就修复哪个环节，相比深层嵌套，排查和修复起来要简单、清晰得多。

## 3. Promise 链式编程中的错误处理 *Content-[07:29]

- **统一错误捕获机制**
  - 在多个 `.then` 进行链式编程的前提下，如果中间某个步骤出现错误（例如传入了错误的参数如字母，导致计算错误），**不需要**为每一个 `.then` 单独编写 `.catch`。
  - **只需一个 `.catch`**：只需要在整个链式编程的最后定义一个 `.catch` 即可。

- **错误处理示例**
  - 假设前几次计算均正常，在第四次调用时传入非法参数导致报错。
  - 此时，链式末尾的唯一 `.catch` 会直接捕获该错误，并输出详细的错误信息（如具体的代码行号）。
  - 无论链式编程中的哪一个环节出错，都能被这个唯一的 `.catch` 匹配并处理，这充分体现了 Promise 在错误处理上的强大与便捷。
