## 一、 同步任务与异步任务的概念 *Content-[00:01]

在 JavaScript (JS) 中，所有的代码执行任务被划分为**同步任务**和**异步任务**。JS 引擎本身具备**事件循环（Event Loop）** 机制。

- **同步代码**：代码逐行执行，主线程按顺序依次处理。例如连续的输出语句 `console.log(1); console.log(2); console.log(3);`，会严格按照 1、2、3 的顺序执行完毕，这是日常开发中最常见的同步执行模式。

## 二、 异步任务的产生与事件循环机制 *Content-[01:05]

JS 中存在许多**耗时任务**，如果将它们作为同步任务处理，会导致严重的问题。

- **常见的耗时任务**：
  - 网络数据下载
  - 图片等资源加载
  - 定时器操作（如 `setTimeout` 延时定时器、`setInterval` 循环定时器）

- **同步执行的阻塞问题**：
  如果将耗时任务归为同步代码，主线程（主干道）就会被完全阻塞。例如，设置一个超长时间的 `setTimeout`，页面会一直卡死等待该定时器结束，后续代码无法执行，导致用户体验极差。
  > **形象比喻**：就像在主干道上发生了交通事故，如果不把车挪走，后续所有车辆都会被堵死。因此，必须将事故处理（耗时任务）挪到“支线”去解决，不能耽误主干道（主线程）的正常通行。

- **异步环境与事件循环机制**：
  为了避免主线程阻塞，耗时任务必须放到**异步环境**中执行。
  > **形象比喻**：可以理解为 JS 主线程有一个“管家”。主线程将耗时操作交给管家去执行，自己继续处理后续的同步代码。管家在后台执行完毕后，会将产生的结果（如渲染页面的数据、打印的结果）交还给主线程进行最终的统筹和敲定。这就是 JS 的**事件循环机制**。

## 三、 宏任务与微任务的执行顺序 *Content-[05:58]

异步任务交由“管家”执行并返回结果时，需要回到主线程进行渲染或执行。此时，异步任务被细分为**宏任务（Macro Task）** 和**微任务（Micro Task）**，它们有着严格的执行优先级。

- **执行顺序规则**：
  1. 首先执行一个**宏任务**。
  2. 在执行下一个宏任务之前，必须**先清空（执行完）所有当前待执行的微任务**。
  3. 循环往复上述过程。

- **形象比喻（情侣与游戏）**：
  - **宏任务**：男生在家玩游戏（如创建账号、打第一关）。
  - **微任务**：女生提出的各种需求（如吃苹果、喝果汁、叫外卖、洗衣服）。
  - **执行逻辑**：男生想要顺利玩游戏（执行宏任务），必须先哄好女生，完成她提出的所有需求（清空微任务）。如果在打游戏的过程中，女生又提出了新需求（产生新的微任务），男生必须暂停游戏，优先把女生的所有需求处理完（执行完所有微任务），然后才能继续打游戏（执行下一个宏任务）。

## 四、 面试题解析：setTimeout、Promise 与 async/await *Content-[09:58]

回到面试题：`setTimeout`、`Promise`、`async`/`await` 的区别。核心在于它们在事件循环中所属的任务类型。

- **setTimeout**：
  属于**宏任务（Macro Task）**。

- **Promise**：
  属于**微任务（Micro Task）**。

- **async / await**：
  - `async` 函数本身会返回一个 `Promise` 对象。
  - 如果 `async` 函数内部没有使用 `await`，它相当于一个普通函数，不返回带状态的 `Promise`。
  - 一旦函数内部定义了 `await`，就会产生一个**带状态的 `Promise` 对象**。因此，从本质上讲，包含 `await` 的 `async` 函数属于**微任务**。

- **最终结论**：
  `setTimeout` 是宏任务，而 `Promise` 和 `async`/`await` 是微任务。
  如果它们的等待时间相同，且同时达到“待执行”状态，JS 引擎会**优先执行所有待执行的微任务**（`Promise` / `async` / `await`），**然后再去执行宏任务**（`setTimeout`）。
