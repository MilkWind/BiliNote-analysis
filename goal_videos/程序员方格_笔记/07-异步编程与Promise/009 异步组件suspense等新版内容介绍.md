## 异步组件与按需加载 *Content-[00:00]

- **核心目的**：实现按需加载，提升首屏加载性能。通过将非首屏相关的组件进行异步处理，有效减少首屏资源的体积大小。
- **实现方案**：通常使用 `React.lazy` 和 `Suspense` 组合的方式进行友好处理。
- **具体实现细节**：
  - **动态 import**：`React.lazy` 接收一个函数，该函数必须调用动态 `import()`。需要清楚动态 `import()` 的逻辑，它返回一个 `Promise`。
  - **Suspense 包裹**：加载异步组件时，由于网络请求可能比较耗时，必须使用 `Suspense` 组件将其包裹。
  - **Fallback 状态**：在 `Suspense` 的 `fallback` 属性中指定加载过程中的占位 UI。例如 `<div>Loading...</div>`，或者为了更美观，替换为骨架屏 (Skeleton Screen)。
  - **渲染逻辑**：在组件未加载完成前展示 loading 状态；加载完成后，自动渲染 `React.lazy` 中定义的相关组件结构。
- **最佳实践**：建议按照此思路处理异步组件，着重提升首屏相关性能。

## 错误边界 (Error Boundary) 机制 *Content-[01:29]

- **引入原因**：在 React 中，如果组件内部抛出异常 (`throw error`) 且没有被捕获，会导致整个页面崩溃白屏，这是一个非常恶劣的问题。因此必须使用 Error Boundary 来兜底。
- **实现原理**：
  - 错误边界通常通过**类组件**来实现。
  - **状态管理**：在组件的 `state` 中定义一个 `hasError` 状态，初始值为 `false`。
  - **生命周期钩子**：
    - `componentDidCatch`：用于监听和捕获组件树中发生的异常。
    - `getDerivedStateFromError`：在捕获到错误后触发，将 `state` 中的 `hasError` 更新为 `true`。
  - **渲染逻辑 (render)**：
    - 判断 `hasError` 状态。
    - 如果为 `true`，则渲染降级 UI，例如提示 "Something went wrong"。
    - 如果为 `false`，则正常渲染子组件 (`this.props.children`)。
- **使用位置与策略**：
  - 需要在应用的最外层（如 `App` 入口组件）使用 Error Boundary 包裹所有的子组件（包括异步组件和其他业务组件）。
  - 这样当任何内部组件发生异常时，都会被 Error Boundary 捕获，避免白屏，转而展示友好的错误提示。
  - **附加操作**：在捕获异常时，还可以结合错误上报逻辑，将错误日志上报到监控系统。
  - **第三方库**：在实际工程中，也可以直接引入第三方 npm 包（如 `react-error-boundary`）来快速实现该功能。

## 课程核心内容总结 *Content-[04:11]

- **高阶组件 (HOC)**：
  - 展示了属性代理 (Props Proxy) 和反向继承 (Reverse Inheritance) 两种模式及其使用场景。
  - **核心建议**：强烈推荐使用**属性代理**方式。因为反向继承对原组件的干预性过强，修改原始逻辑会带来不安全性。编写代码应尽量遵循纯函数思想，不修改原始输入逻辑。
- **Hooks**：
  - 推荐使用的函数式编程思想。
  - 需要格外注意每个 Hook 的使用方式和细节，建议多尝试开发**自定义 Hooks**。
  - 本节主要通过 Markdown 演示逻辑，后续章节（如状态管理、Router）会在实际工程中运行代码查看效果。
- **性能优化与容错**：
  - **纯组件 (Pure Component) / `React.memo`**：作为性能优化的重要手段。
  - **错误边界 (Error Boundary)**：工程中必须具备的容错能力，保障应用稳定性。
