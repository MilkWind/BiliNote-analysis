## 异步变同步的场景与意义 *Content-[00:00]
- **场景痛点**：在处理异步请求时，如果存在嵌套（即发送一次异步请求，需要拿到结果后再去请求下一次），会导致代码结构啰嗦、复杂，可读性差。
- **解决目的**：将异步嵌套直接转化为同步的形式，使得代码结构更加清晰，处理起来更加方便。

## 面试核心考点：async/await 的使用与底层探究 *Content-[00:52]
- **实现方式**：在前端开发中，通常借助 `async/await` 语法糖，以同步的方式来实现异步操作。
- **执行过程对比**：
  - **普通异步**：发送异步请求（假设需等待 3 秒），主线程不会被阻塞，代码会自动直接执行到第二步。
  - **异步变同步**：在 `async` 函数中，为异步请求加上 `await`。此时代码会暂停等待，直到 3 秒后拿到 `response` 结果，才会继续执行第二步。整体表现为同步的阻塞等待。
- **核心考点**：面试官考察的重点**不是**“如何使用”（即加上 `async/await`），**而是**“底层是如何实现异步变同步的”（即底层原理与执行过程），这具有一定的难度。

## 原函数示例：异步代码的同步化表现 *Content-[03:48]
- **原函数结构**：定义一个 `async` 函数，内部包含多个带有 `await` 的异步操作。
  - 第一步：发送异步请求，等待获取 `response`。
  - 第二步：拿到 `response` 后，调用 `.json()` 方法解析，再次 `await` 等待结果。
  - 第三步：拿到解析后的数据，执行后续逻辑。
- **表现结果**：由于 `await` 的存在，函数必须等第一步完成才能执行第二步，等第二步完成才能执行第三步。原本异步的请求数据，在代码执行流上变成了 1、2、3 步的同步形式。

## 底层结构解析：生成器函数与 yield 关键字 *Content-[05:29]
- **语法糖本质**：`async/await` 只是语法糖，其编译后的底层结构实际上是**生成器函数（Generator）**。
- **生成器函数（Generator）**：
  - 定义方式：在 `function` 关键字后加星号（如 `function*`）。
  - 核心关键字：`yield`。
- **`yield` 的功能**：
  - **暂停执行**：遇到 `yield` 时，函数会暂停执行。`await` 的底层其实就是 `yield`。
  - **恢复执行**：暂停后，必须调用该函数的 `next()` 方法，代码才会继续往下走；如果不调用，则永远停留在当前步骤。
  - **保留上下文**：`yield` 在执行时会保留函数的上下文（包括变量、传递的值以及当前的执行位置），以便于后续恢复执行。`async` 的底层就是生成器函数。

## 生成器函数的工作原理演示 *Content-[08:46]
- **基本结构**：定义一个生成器函数，内部包含多个 `yield` 步骤（如 `yield 1`、`yield 2`、`yield 3`）。
- **`next()` 方法的返回值**：每次调用 `next()`，都会返回一个包含两个属性的对象：
  - `value`：当前 `yield` 表达式的返回值。
  - `done`：布尔值，表示生成器函数是否已经执行到底。
- **执行流程演示**：
  - 第 1 次调用 `next()`：返回 `{ value: 1, done: false }`（未执行到底）。
  - 第 2 次调用 `next()`：返回 `{ value: 2, done: false }`（未执行到底）。
  - 第 3 次调用 `next()`：返回 `{ value: 3, done: false }`（未执行到底）。
  - 第 4 次调用 `next()`：返回 `{ value: undefined, done: true }`（已执行到底，无更多值）。

## 核心原理：转化函数与递归执行机制 *Content-[11:00]
- **自动执行器（转化函数）**：生成器函数本身不会自动执行，需要一个外层的“转化函数”将其包裹并驱动执行，这就是 `async/await` 能够自动按顺序执行的底层机制。
- **转化函数的执行流程**：
  1\. **初始化**：将生成器函数传入转化函数并执行，得到迭代器对象。
  2\. **定义递归回调**：定义一个回调函数，内部调用 `next()` 获取结果对象 `{ value, done }`。
  3\. **状态判断与处理**：
     - 如果 `done === true`：说明所有步骤执行完毕。直接使用 `Promise.resolve(value)` 将最终值返回，结束递归。
     - 如果 `done === false`：说明还有后续异步步骤。将当前的 `value`（通常是一个 Promise 对象）通过 `Promise.resolve()` 进行处理。
  4\. **递归调用与传值**：在 `Promise` 的 `.then()` 回调中，获取到上一步异步请求的结果 `result`，然后**递归调用** `next(result)`。
  5\. **上下文传递**：通过 `next(result)`，将上一步的结果传递给生成器函数内部的下一个 `yield`，使其能够接收到该值并延续往下执行。
- **总结**：整个异步变同步的过程，本质上是通过转化函数进行**递归操作**，不断调用 `next()` 执行步骤，并利用 `Promise` 处理异步结果，直到 `done` 为 `true` 结束。
