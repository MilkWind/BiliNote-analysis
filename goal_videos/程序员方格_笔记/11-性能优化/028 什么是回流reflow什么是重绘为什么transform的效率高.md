## 1. 什么是回流 (Reflow) *Content-[00:11]

- **专业术语**：Reflow（回流）。
- **产生原因**：修改布局树（Layout Tree）。例如改变元素的位置信息、宽度、高度等几何属性。
- **浏览器的处理机制**：
  - **早期机制**：为了避免连续的多次 DOM 操作导致布局树反复计算，浏览器会将 JS 代码完全执行完毕后，再统一进行计算（即异步完成 Reflow）。
  - **机制调整**：当 JS 获取布局属性时，由于是异步计算，可能无法获取最新的布局信息。经过反复权衡，浏览器最终决定在**获取属性时立即触发 Reflow**。
- **注意事项**：不仅是修改 DOM 的宽高会造成回流，**获取 DOM 的布局属性**同样会造成回流。
- **性能影响**：回流从 `Layout` 阶段开始，后续的 `Layer`（分层）、`Paint`（绘制）等全部需要重新执行，因此会非常严重地影响页面性能。

## 2. 什么是重绘 (Repaint) *Content-[01:46]

- **专业术语**：Repaint（重绘）。
- **产生原因**：修改元素的颜色、背景图片等不影响布局的属性。
- **处理流程**：
  - 本质是根据分层信息重新计算绘制指令。
  - 重绘从 `Layer` 阶段开始，一直到 `Paint` 阶段。
  - 相比于回流，重绘的流程少了一步（不需要经过 `Layout`），因此造成重绘的性能成本比回流低很多。
- **回流与重绘的关系**：
  - **回流一定会引起重绘**。
  - **原理解释（面试加分项）**：浏览器渲染分为八大步骤（涉及渲染主线程和合成线程），核心流程为 `Layout` -> `Layer` -> `Paint`。因为回流是从 `Layout` 开始的，必然包含了后续的 `Layer` 和 `Paint` 阶段，所以一定会引起重绘。在面试中从渲染原理角度解释，能展现对底层机制的深刻理解。

## 3. 为什么 transform 的效率高 *Content-[03:20]

- **基本概念**：`transform` 是 CSS3 中的一个属性，常用于实现元素的移动、缩放等动画效果。
- **高效的原因**：
  - **处理阶段靠后**：`transform` 的处理发生在渲染流程的最末尾阶段，因此性能保持得特别好。
  - **不阻塞主线程**：`transform` 不会影响渲染主线程（渲染主线程通常非常忙碌），从而避免了性能瓶颈。
- **面试回答技巧**：
  - **普通回答**：`transform` 触发了 GPU 加速。
  - **进阶回答**：结合浏览器渲染的八大流程，指出 `transform` 仅在渲染流程的最后阶段触发，跳过了前面的 `Layout`、`Layer` 等耗时步骤，从而在原理层面解释其高性能的原因。
