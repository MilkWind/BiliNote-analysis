## 为什么关注自定义字体 *Content-[00:50]

在前端开发中，自定义字体是提升项目设计感和品牌辨识度的重要手段，但它并非“免费”的 UI 装饰，而是需要被下载和管理的静态网络资源。

- **使用自定义字体的优势**：
  - **品牌辨识度**：独特的字体能让公司品牌更加显著，帮助用户潜意识里快速识别产品。
  - **提升设计感与专业感**：合适的字体是最简单、最直接提升产品“颜值”的手段。
  - **改善阅读体验**：清晰易读的字体可以降低用户的认知成本，同时字体的气质能传递出产品想要营造的氛围。

- **自定义字体的代价与副作用**：
  - 自定义字体与其他静态资源一样，需要占用网络资源并增加额外的网络请求。
  - 这会带来加载时机的不确定性，从而导致文本渲染时出现闪烁或空白现象，即 **FOUT** 和 **FOIT**。

## FOUT 与 FOIT 现象解析 *Content-[02:18]

FOUT 和 FOIT 不是浏览器的 Bug，而是浏览器在面对“自定义字体未下载完成但需要渲染文本”这一难题时，采取的两种不同加载策略。

### 1\. FOUT (Flash of Unstyled Text) 无样式文本闪现
- **现象表现**：打开网页后文字快速显示，但使用的是默认字体（如宋体或黑体），零点几秒后闪烁一下，变成设计稿中的自定义字体样式。
- **加载流程**：
  - 浏览器解析到需要自定义字体，发现其还在下载中。
  - 浏览器**不等待**，立即查找 CSS 中定义的后备字体（fallback font）进行渲染，保证内容始终可见。
  - 自定义字体下载完成后，浏览器进行重绘，替换当前字体。
- **本质原则**：**内容优先级高于样式**（追求内容可见，而非样式正确）。
- **优缺点**：
  - **优点**：文本优先可见，用户可第一时间阅读内容。对内容型网站（如博客、新闻资讯）非常友好。
  - **缺点**：字体闪现可能带来视觉上的不协调，短暂破坏精心设计的视觉效果，让界面看起来不够稳定。

### 2\. FOIT (Flash of Invisible Text) 不可见文本闪现
- **现象表现**：打开网页后，本该显示文本的地方先是一片空白，过了几秒后文字突然显现出来。
- **加载流程**：
  - 浏览器发现自定义字体未加载完成，选择**等待**，进入“字体阻塞期”（通常约为 3 秒）。
  - 在阻塞期内，浏览器**完全不渲染文本**。
  - 若 3 秒内字体加载成功，直接用自定义字体渲染。
  - 若超过 3 秒仍未加载完成，浏览器放弃等待，先用后备字体渲染文本。若之后自定义字体姗姗来迟，依然会发生一次替换（表现出 FOUT 行为）。
- **本质原则**：**样式优先级高于内容**（先保证样式统一，再显示内容）。
- **优缺点**：
  - **优点**：避免了 FOUT 带来的字体闪变和视觉跳动，保证视觉风格高度统一。
  - **缺点**：在弱网环境（尤其是移动端）下代价极大，用户会看到大量白屏，甚至以为页面损坏，对用户体验是毁灭性打击。

## 浏览器字体加载策略与 font-display API *Content-[08:13]

- **历史背景**：过去不同浏览器厂商对字体加载的策略不一致（例如老版 Chrome 倾向于 FOIT，而 IE 倾向于 FOUT），导致跨浏览器体验存在不确定性。
- **夺回控制权**：开发者比浏览器更了解项目需求（内容重要还是视觉重要）。为了显式控制字体的加载与渲染平衡，引入了 **`font-display`** API。
- **`font-display` 的作用**：
  - 它是 `@font-face` 规则内部的一个属性。
  - 它**不会**加快字体的加载速度，而是告诉浏览器在自定义字体处于不同加载阶段时，应该采取什么样的**渲染策略**。
  - 它决定了在字体加载完成之前，屏幕上应该发生什么。

## font-display: swap 策略详解 *Content-[10:51]

- **行为机制**：
  - 给浏览器明确指令：**不要有任何阻塞**。
  - 立即使用后备字体（fallback font）渲染文本。
  - 自定义字体下载完成后，直接 swap（交换）过来。
- **本质**：开发者主动且明确地选择了 **FOUT** 行为。认为让用户快速看到内容比等待字体更重要。
- **适用场景**：目前**最主流、最被推荐**的字体加载策略，体验最接近用户期望的文本快速渲染。

## font-display: block 策略详解 *Content-[12:05]

- **行为机制**：
  - 告诉浏览器“先等一下”，设置一个较短的阻塞期（规范建议为 **3 秒**）。
  - 在 3 秒内，任何使用该字体的文本都是不可见的（即 FOIT 状态）。
  - 若 3 秒内加载完成，文本以自定义字体渲染。
  - 若 3 秒后仍未加载，浏览器先用后备字体显示，等自定义字体到达后再做替换。
- **本质**：偏向 **FOIT** 策略。创造了初始的视觉一致性，并添加了一段容忍时间。
- **适用场景**：适合作为加载**品牌标识文本**（如 Logo 文字）的方法，以确保品牌视觉的短暂统一。

## font-display: fallback 策略详解 *Content-[13:22]

- **行为机制**：
  - 一种精妙的折中方案，具有极短的阻塞期（仅约 **100ms**）。
  - 若字体在 100ms 内准备好，浏览器直接切换，不影响任何样式。
  - **关键策略**：一旦超过 100ms 需要切到后备字体，那么在**本次页面访问中**，浏览器就**不会再加载**自定义字体去替换它。
- **本质**：实现了一种**快速失败**的逻辑。网速快则看自定义字体，网速慢则全程看备用字体，不会发生中途替换的闪烁。
- **适用场景**：对性能和视觉稳定性都非常友好，体验极其稳定，适合对布局抖动敏感的文本。

## font-display: optional 策略详解 *Content-[14:47]

- **行为机制**：
  - 行为与 `fallback` 类似，同样只有 **100ms** 的阻塞期，超时则回退到后备字体且不再替换。
  - **更进一步的控制**：赋予浏览器更大的决定权。明确告诉浏览器该字体是“可选的”。
  - 若浏览器检测到用户网络连接非常差，会直接开启省流模式，**根本不请求**自定义字体。
- **本质**：**性能优先级最高**。明确告知浏览器该字体只是锦上添花，并非刚需。
- **适用场景**：非常适合用在**纯粹的装饰字体**上（不影响主内容阅读）。
- **注意事项**：开发者必须做好心理预期，部分用户可能永远看不到该字体。在设计和开发时，必须确保即使该字体不存在，界面的功能和布局依然是完美的。

## AI 总结 *Content-[16:01]

自定义字体虽能提升品牌辨识度和设计感，但会引发 FOUT（无样式文本闪现）和 FOIT（不可见文本闪现）两种渲染问题。FOUT 优先保证内容可见但伴随视觉闪烁，FOIT 优先保证视觉统一但可能导致长时间白屏。

为了解决浏览器默认策略带来的跨端不一致问题，前端开发者应使用 `@font-face` 中的 `font-display` 属性来主动控制渲染策略：
- **`swap`**：无阻塞，立即显示后备字体，最主流推荐，适合正文内容。
- **`block`**：短阻塞（约3秒），适合品牌 Logo 等需要视觉统一的短文本。
- **`fallback`**：极短阻塞（约100ms），快速失败，超时后不再替换，适合对布局稳定性要求高的场景。
- **`optional`**：极短阻塞且允许浏览器在网络差时直接跳过加载，性能优先，适合纯装饰性字体。

合理选择 `font-display` 策略，能够在字体加载的网络延迟与用户体验之间找到最佳平衡点。
