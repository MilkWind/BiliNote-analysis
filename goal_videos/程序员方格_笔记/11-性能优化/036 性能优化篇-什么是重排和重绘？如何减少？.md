## 浏览器渲染流程回顾 *Content-[00:44]

要彻底搞懂重排和重绘，首先需要理解浏览器将代码转换为用户屏幕上画面的底层渲染机制。整个过程可简化为以下关键步骤：

- **解析构建 DOM 树**：浏览器下载 HTML、CSS、JS 后，解析 HTML 构建出 DOM 树，代表页面的结构。
- **构建 CSSOM 树**：同时解析 CSS 生成 CSS Object Model (CSSOM) 树，包含所有节点的样式信息。
- **生成 Render Tree（渲染树）**：将 DOM 树和 CSSOM 树结合生成 Render Tree。该树只包含需要显示在页面上的节点和样式（例如 `display: none` 的元素不会出现在渲染树中）。
- **Layout（布局/重排）**：计算渲染树中每一个可见节点的精确几何信息，如屏幕上的具体位置、尺寸大小等。
- **Paint（绘制/重绘）**：布局信息确定后，浏览器根据节点的样式信息（颜色、背景、边框等）将节点画成像素。
- **Composite（合成）**：如果页面存在多个图层（如通过 `transform` 创建的图层），浏览器会将这些图层按正确顺序合并，最终显示在页面上。

**核心结论**：重排和重绘就发生在上述流程的特定环节。当通过 JS 或 CSS 改变元素的布局或外观时，都可能迫使浏览器重新经历 Layout 和 Paint 阶段。

## 什么是重绘（Repaint） *Content-[03:50]

- **定义**：当元素的视觉样式发生变化，但几何布局（位置、大小）没有发生变化时，就会触发重绘。可以理解为元素位置大小固定，只是“换了一层皮肤”。
- **触发条件**：改变 `color`、`background`、`box-shadow` 等仅影响外观的属性。
- **特殊属性 `visibility`**：当 `visibility` 从 `visible` 变为 `hidden` 时，元素不可见但依然占据原有空间，布局未改变，因此只触发重绘。
- **性能特点**：
  - 性能开销属于**中等**。因为跳过了昂贵的布局计算环节，通常比重排轻量。
  - 尽管比重排轻量，但在动画或高频交互中连续不断触发重绘，依然会消耗大量计算资源，导致页面卡顿。
- **示例**：鼠标悬停（hover）时改变文字颜色和背景色，由于未改变盒子的宽高或位置，只触发一次重绘，不触发重排。

## 什么是重排（Reflow / Layout） *Content-[06:35]

重排（在某些文档中也称回流）是性能影响更大的操作，本质上就是重新执行 Layout 阶段。

- **触发条件**：任何导致元素几何信息发生变化的操作。
  - **样式改变**：改变尺寸（`width`、`height`、`padding`、`border`）或位置（`top`、`left`、`margin`）。
  - **DOM 结构改变**：通过 JS 添加/删除节点，或改变节点的 `display` 属性，导致页面结构变化。
- **性能特点**：
  - **性能开销非常高**：一个元素的几何属性变化可能会影响其周围元素、父元素甚至整个页面的布局。浏览器需要从变化节点开始，递归重新计算所有受影响节点的几何信息，计算过程极其复杂。
  - **必然导致重绘**：布局改变后，浏览器必须将新的布局结果重新绘制到屏幕上。因此，**一次重排必然会导致一次重绘**，其代价包含了布局计算和绘制两个阶段。
- **示例**：通过 JS 获取元素并改变其 `width` 和 `margin-top`，直接改变几何信息，触发一次重排并紧跟一次重绘。重排是前端性能优化中需要高度警惕的操作。

## 优化技巧一：合并样式修改 *Content-[09:29]

- **Bad Case（错误示范）**：获取元素后，连续三次修改 `style` 属性（分别设置宽度、高度、外边距）。虽然浏览器有渲染队列会尝试合并操作，但在最坏情况下（或在循环/高频事件回调中），每一次赋值都可能触发独立的 Layout 和 Paint，性能开销极大。
- **Good Case 1（样式与行为分离）**：将所有需要应用的样式变更聚合到一个 CSS 类（如 `.active`）中，JS 中只执行一次添加类名的操作。将多个样式变更指令打包成单一的 DOM 操作，浏览器一次性计算影响，通常只触发一次重排。
- **Good Case 2（使用 `style.cssText`）**：如果样式是动态计算无法提前定义在 CSS 文件中，可将所有要设置的样式拼接成一个字符串，一次性赋值给 `style.cssText` 属性，向浏览器发出单一变更指令，避免多次独立重排。核心思想是**将多次写入操作合并成一次**。

## 优化技巧二：使用 DocumentFragment 批量操作 DOM *Content-[12:25]

- **Bad Case（错误示范）**：在 `for` 循环内部，每次都调用 `parent.appendChild()` 向列表插入新节点。这意味着每次循环都在直接操作已挂载的真实 DOM 树，可能导致浏览器在每次循环时重新计算布局。循环 10 次最坏触发 10 次重排，列表多时会导致明显卡顿。
- **Good Case（使用文档片段）**：
  - 使用 `document.createDocumentFragment()` 创建一个 `DocumentFragment`。它是一个存在于内存中的轻量级 DOM 容器，不是真实 DOM 的一部分。
  - 在循环中，将新创建的节点附加到 `fragment` 上，而不是直接 `append` 到 `parent`。因为 `fragment` 不在渲染树中，对其操作不会引发任何重排或重绘。
  - 循环结束构建好所有元素后，再调用 `appendChild` 将整个 `fragment` 一次性添加到真实 DOM 中。浏览器只需进行一次重排即可完成布局。
  - **核心思路**：先在内存中批量进行 DOM 操作，然后一次性更新到页面上。

## 优化技巧三：利用 display: none 进行批量修改 *Content-[15:03]

- **操作思路**：当需要对一个元素进行多次复杂的样式修改时，先将其 `display` 设置为 `none`。此时元素会从渲染树中完全移除，不占据任何布局空间。完成所有修改后，再把 `display` 恢复为原来的值（如 `block`），浏览器会将更新好的元素重新放回渲染树。
- **适用场景与注意事项**：
  - 设置 `display: none` 和恢复 `display` 这两个操作本身会触发重排。
  - 此方法适用于需要对元素进行**大量、复杂且不频繁**的样式修改场景。
  - 如果只是修改一两个属性，直接修改比“隐藏-修改-显示”的折腾过程更高效。

## 优化技巧四：读写分离避免布局抖动 *Content-[16:41]

- **问题场景（布局抖动 / 强制同步布局）**：
  - **Bad Case**：遍历元素数组，在循环中先读取元素的 `offsetWidth`（读操作），然后设置 `style.width`（写操作）。
  - **原理**：浏览器通常会将写操作放入队列等待批量处理。但在下一轮循环开始时，代码又要读取 `offsetWidth`。为了保证返回最新、最精确的布局值，浏览器不得不清空写操作队列，强制触发一次重排。这种在循环中频繁强制浏览器同步执行布局的行为，就是典型的**布局抖动**。
- **解决方案（读写分离）**：
  - 将原来的一个循环拆分为两个独立的循环。
  - **第一个循环（只读）**：专门负责读取 `offsetWidth`，并将值缓存到一个数组中，期间不进行任何写操作。
  - **第二个循环（只写）**：专门负责遍历元素，利用缓存的宽度值设置新的 `style.width`，期间不进行任何读操作。
  - **效果**：彻底分开读写操作，给浏览器优化空间。在写循环中，浏览器可以将所有操作缓存，最后很可能只需一次重排即可完成。这是避免布局抖动、提升渲染性能的核心策略。

## 终极优化：绕开重排与重绘 *Content-[19:50]

对于动画场景，可以通过特定 CSS 属性完全绕开重排和重绘。

- **核心属性**：`transform` 和 `opacity`。
- **底层原理（合成层优化）**：
  - 现代浏览器有“合成层（Composite Layer）”优化机制。当检测到 `transform` 和 `opacity` 用于动画时，会将该元素提升到一个独立的合成层。
  - 一旦元素位于自己的合成层上，对这两个属性的修改可以直接在渲染流程的最后一个阶段（Composite 合成阶段）由 **GPU** 独立处理。
  - 因此，它**完全不触发重排和重绘**。
- **对比示例**：
  - **推荐做法**：使用 `transform: translate()` 实现水平移动动画，享受 GPU 加速，性能极佳。
  - **不推荐做法**：将 `position` 设为 `relative` 并动画修改 `left` 属性。`left` 是几何布局属性，动画每一帧改变它都会触发重排，消耗大量 CPU 资源，极易造成动画掉帧。
- **结论**：制作位移、缩放、旋转或淡入淡出动画时，优先使用 `transform` 和 `opacity`。

## AI 总结 *Content-[21:59]

本视频深入解析了前端性能优化中的核心概念：重排（Reflow）与重绘（Repaint）。重绘仅涉及外观改变，开销中等；而重排涉及几何布局计算，开销巨大且必然伴随重绘。为了提升页面性能，开发者应掌握以下关键优化策略：
1. **合并操作**：通过 CSS 类名或 `style.cssText` 合并样式修改，避免连续触发重排。
2. **批量 DOM 更新**：利用 `DocumentFragment` 在内存中构建 DOM，或使用 `display: none` 隐藏元素后再修改，最后一次性挂载。
3. **避免布局抖动**：严格遵循“读写分离”原则，避免在循环中交替读取布局属性和修改样式，防止浏览器强制同步布局。
4. **GPU 加速动画**：在实现位移动画时，摒弃修改 `left/top` 等传统布局属性，全面拥抱 `transform` 和 `opacity`，利用合成层交由 GPU 处理，彻底绕开重排与重绘。
