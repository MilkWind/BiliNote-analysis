## 题目解析与核心矛盾 *Content-[00:00]

- **题目背景**：如何在浏览器中执行 100 万个任务，并且保证页面不卡顿。
- **核心矛盾**：
  - JavaScript 是单线程的。
  - 如果使用 JS 代码无脑执行 100 万个任务（例如 `for` 循环 100 万次），会长时间占用主线程。
  - 主线程被完全占用后，浏览器将无法执行渲染、重排（Reflow）、重绘（Repaint）以及响应用户交互等操作。
- **导致结果**：页面出现卡死现象，用户操作得不到任何响应。
- **考察重点**：针对页面性能问题的处理能力，特别是如何优化长任务（Long Task）。

## 核心解决思想：任务分片 *Content-[01:50]

- **核心思想**：将庞大的任务分解为无数个小任务，即**任务分片（Time Slicing）**。
- **执行机制**：
  - 每个小任务（分片）执行结束后，主动让出当前的主线程。
  - 让出主线程后，浏览器可以继续执行渲染和用户响应操作。
  - 如果主线程没有渲染和响应任务，事件循环（Event Loop）会再次进入当前分片的下一个小任务继续执行。
- **框架案例（React）**：
  - React 15 的渲染是不可中断的。
  - React 16（Fiber 架构）之后变成了可中断的。React 设定了时间片，如果在规定时间内未执行完，则中断任务，将主线程交还给浏览器。后续再通过调度读取上一步暂存的结果继续执行。

## 方案一：使用 setTimeout 进行任务分片 *Content-[04:00]

- **关键技术**：使用传统方法让出主线程，如 `setTimeout` 或 `setInterval`（首选 `setTimeout`）。
- **实现思路**：
  1.  **准备数据**：创建一个包含 100 万个任务的数组。
  2.  **定义分片大小**：设定 `chunkSize`（例如每次处理 1000 个任务）。
  3.  **计算分片边界**：当前分片的结束索引为 $\min(\text{currentIndex} + \text{chunkSize}, \text{taskList.length})$。
  4.  **执行当前分片**：循环调用 `processTask` 执行当前窗口大小内的具体任务。
  5.  **让出主线程**：更新 `currentIndex`。如果 $\text{currentIndex} < \text{taskList.length}$，说明还有剩余任务。此时使用 `setTimeout(fn, 0)` 将后续任务推入宏任务队列。
  6.  **循环调度**：`setTimeout` 延迟为 0 意味着在当前宏任务执行完后让出主线程，进入下一次事件循环，然后再执行下一个分片。

## 方案二：Promise + setTimeout 组合 (微任务+宏任务) *Content-[09:10]

- **实现思路**：结合微任务（Microtask）和宏任务（Macrotask）进行组合处理。
- **具体步骤**：
  1.  同样对任务进行分片，使用 `slice` 拷贝当前窗口大小的任务数组。
  2.  遍历当前分片（chunk）执行任务。
  3.  使用 `Promise.resolve().then()` 创建微任务。
  4.  在微任务中，结合 `setTimeout` 来让出主线程。
- **方案优势**：
  - 微任务会一直执行直到清空，其优先级高于宏任务。
  - 通过 `Promise` 包裹 `setTimeout`，可以比单纯使用 `setTimeout` 更早地进入下一次事件循环，从而提高整体执行效率。

## 方案三：使用 requestIdleCallback (推荐方案) *Content-[12:25]

- **API 介绍**：`requestIdleCallback` 是浏览器提供的 API，专门用于在浏览器空闲时期调用回调函数。这也是 React 早期实现时间分片所采用的思路（React 后来为了兼容性自己重写了调度器）。
- **实现思路**：
  1.  定义任务处理函数 `doTrunk`，接收 `deadline` 参数。
  2.  在 `doTrunk` 中循环执行任务，但必须同时满足以下两个条件：
      - $\text{currentIndex} < \text{taskList.length}$（任务未执行完）。
      - $\text{deadline.timeRemaining()} > 0$（浏览器当前仍有空闲时间）。
  3.  在循环内调用 `processTask` 处理单个任务，并更新 `currentIndex`。
  4.  当空闲时间用完或当前分片执行完毕，如果任务未执行完，则再次调用 `requestIdleCallback(doTrunk)` 调度下一次执行。
  5.  首次执行时，也通过 `requestIdleCallback(doTrunk)` 触发。
- **方案优势**：能够最大程度保证页面的流畅度，因为任务只在浏览器真正空闲时执行，不会阻塞关键的渲染和用户交互，是解决此类场景题的最佳实践。

## AI 总结

在浏览器中执行海量任务（如 100 万个）而不引起页面卡顿的核心在于**任务分片**与**主动让出主线程**。由于 JS 的单线程特性，长任务会阻塞渲染和交互。视频详细介绍了三种解决方案：传统的 `setTimeout` 方案、结合微任务与宏任务的 `Promise + setTimeout` 方案，以及最推荐的 `requestIdleCallback` 方案。其中，`requestIdleCallback` 能够精准利用浏览器的空闲时间片执行任务，是保障页面极致流畅的最优解，这也与 React Fiber 架构的时间分片思想不谋而合。
