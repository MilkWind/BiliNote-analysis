## 题目解析与核心矛盾 *Content-[00:00]
- **题目背景**：前端面试高频场景题，要求在前端浏览器中执行 100 万个任务，同时必须保证页面不卡顿。
- **核心矛盾分析**：
  - JavaScript 是单线程语言。
  - 如果使用 JS 代码无脑通过循环（如 `for` 或 `while`）执行 100 万个任务，会形成一个长任务（Long Task），长时间霸占主线程。
  - 主线程被占用后，浏览器将无法执行 UI 渲染、重排（Reflow）、重绘（Repaint）以及响应用户的交互事件。
  - 最终表现：页面出现卡死现象，毫无反应，用户的操作得不到任何响应。
- **考察重点**：考察候选人对前端页面性能优化的理解，特别是如何处理和拆解长任务。

## 核心解决思想：任务分片 *Content-[01:46]
- **核心思想**：任务分片（Time Slicing）。将一个庞大且耗时的长任务，拆解分解为无数个小任务（分片）。
- **执行机制**：
  - 每个小任务（分片）执行结束后，主动让出当前的主线程。
  - 接着进入下一次事件循环（Event Loop），让浏览器有机会去执行渲染和响应用户交互等操作。
  - 如果浏览器发现主线程没有渲染和响应等紧急任务，事件循环会再次进入当前分片逻辑，继续执行下一个小任务。
- **框架中的实际应用**：
  - 以 React 框架为例：React 15 的渲染过程是不可中断的；而 React 16.8 之后引入了 Fiber 架构，渲染变成了可中断的。
  - React 设定了特定的时间片（Time Slice），如果在时间片范围内任务未执行结束，就会中断并暂停当前任务，将主线程交还给浏览器。
  - 后续如果没有更高优先级的任务，浏览器会再次调度，读取上一步暂存的状态和结果，继续执行分片任务。

## 方案一：使用 setTimeout 进行任务分片 *Content-[03:42]
- **关键技术**：寻找能够让出主线程的 API。
- **实现思路**：
  - 使用传统的 `setTimeout(fn, 0)` 或 `setInterval`。
  - 将任务进行分批处理，设置延迟时间为 0。执行完当前批次后，任务会被放入宏任务队列，等待下一次事件循环，从而让出当前主线程。
- **代码实现逻辑**：
  - 创建包含 100 万个任务的数组（Task List）。
  - 定义分片大小（Chunk Size），例如每次批处理 1000 个任务。
  - 计算当前分片的结尾索引：取 `currentIndex + chunkSize` 与 `taskList.length` 的最小值（`Math.min`）。
  - 循环执行当前分片内的任务，调用 `processTask` 处理单个具体任务。
  - 当前分片处理完毕后，判断 `currentIndex < taskList.length`。
  - 如果还有剩余任务，则通过 `setTimeout` 调度下一次分片执行，实现让出主线程的目的。
- **方案评价**：方法可行，能够解决卡顿问题，但并不是最优或首选方案。

## 方案二：Promise + setTimeout 组合方案 *Content-[09:11]
- **实现思路**：
  - 结合微任务（Microtask）和宏任务（Macrotask）进行组合处理。
  - 利用 `Promise.resolve().then()` 创建微任务，并结合 `setTimeout` 来让出主线程。
- **代码实现逻辑**：
  - 同样对任务进行分片，使用 `slice` 方法拷贝当前窗口大小（Chunk Size）的任务数组。
  - 遍历执行当前分片（Chunk）内的任务。
  - 执行完毕后，通过 `await` 结合 `Promise` 和 `setTimeout` 的组合来让出主线程。
- **方案优势**：
  - 相比于单纯使用 `setTimeout`，这种组合方式能够更早地进入下一次事件循环。
  - 原理：事件循环在主线程执行完后，会优先检查并清空微任务队列。使用 `Promise` 包裹 `setTimeout`，可以优化调度时机，使任务衔接更紧凑。

## 方案三：使用 requestIdleCallback (推荐方案) *Content-[12:22]
- **实现思路**：
  - 使用浏览器原生提供的 `requestIdleCallback` API。
  - 该 API 专门为此类场景设计，允许在浏览器空闲时期调用回调函数执行任务。
  - 注：React 的时间分片机制也是基于此思想，但由于兼容性问题，React 内部自己重写实现了一个 `requestIdleCallback`。
- **代码实现逻辑**：
  - 首次执行时，调用 `requestIdleCallback(doWork)`。
  - 在回调函数 `doWork` 中，需要判断两个核心条件：
    1. 任务未执行完：`currentIndex < taskList.length`。
    2. 浏览器有空闲时间：`deadline.timeRemaining() > 0`。
  - 在满足空闲时间的条件下，循环执行当前分片任务。
  - 执行完当前批次后，如果任务未执行完（`currentIndex < taskList.length`），则再次调用 `requestIdleCallback(doWork)` 继续执行下一个分片。
- **方案优势**：
  - 这是最推荐的方案。
  - 能够最大程度保证页面的流畅度。
  - 严格在浏览器的空闲时间内执行任务，即使进行了分片，也不会因为单个分片耗时过久而影响浏览器的其他核心任务（如渲染、交互）。

## AI 总结 *Content-[17:04]
- 视频详细讲解了前端面试中“如何在浏览器执行100万个任务且不卡顿”的经典场景题。
- 核心痛点在于 JS 单线程下长任务阻塞主线程导致页面卡死。
- 解决核心思想是“任务分片（Time Slicing）”，将大任务拆解为小任务，并主动让出主线程。
- 提供了三种递进的解决方案：
  1. 传统的 `setTimeout` 分片（基础方案）。
  2. `Promise` + `setTimeout` 组合（利用微任务优化调度时机）。
  3. `requestIdleCallback`（利用浏览器空闲时间执行，最推荐、最优雅的方案，也是 React Fiber 的核心思想之一）。
