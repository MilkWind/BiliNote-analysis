## 延迟加载的核心概念与定义 *Content-[00:00]

延迟加载（Lazy Loading）并非不加载页面资源，而是一种核心的前端性能优化技术。其核心思想是**优先保证主干资源的加载**，在浏览器空闲或用户真正需要时，再分层次、依次加载非主干或非关键资源。

- **核心目的**：使主干资源加载速度极快，避免非关键资源阻塞首屏渲染，从而大幅提升页面的整体加载性能和用户体验。
- **实现逻辑**：推迟非关键资源（如图片、脚本、组件等）的加载。在等待期间，可以先加载一个轻量级的预览图或占位图，直到用户滚动到可视区域或浏览器空闲时，再加载真实资源。
- **面试答题思路**：在面试中回答此问题，不能片面地只说某一种方案，而应该**根据不同类型的资源（图片、脚本、组件、固定资源）分类阐述**相应的延迟加载策略，展现全面的性能优化思维。

## 图片资源的延迟加载方案 *Content-[03:44]

对于图片资源，官方推荐使用原生 HTML5 提供的属性来实现延迟加载，这种方式简单且高效。

- **原生属性实现**：在 `<img>` 标签中添加 `loading="lazy"` 属性。在实际工程化开发中，通常会结合 `data-src` 属性来存储真实图片的 URL，而 `src` 属性用于存放占位图。
- **加载机制与原理**：
  - **初始状态**：页面初始化时，优先加载并显示 `src` 中的占位图（例如一个 loading 动画图标），避免页面出现空白，保证基础的用户体验。
  - **触发加载**：浏览器会自动监测图片的位置，当图片**进入视口（Viewport）** 时，自动触发加载 `data-src`（或替换 `src`）指定的真实高清图片。
- **优势**：实现了资源的梯次加载，用户感知平滑，且不会阻塞主线程和首屏关键资源的渲染。

## 脚本（JS）资源的延迟加载方案 *Content-[05:41]

JavaScript 脚本的延迟加载有多种实现方式，需根据脚本的具体作用和使用场景选择合适的方案。

1\. **使用 `defer` 属性**
- **机制**：脚本会延迟执行，等待整个 HTML 文档解析完成之后、`DOMContentLoaded` 事件触发之前执行。
- **特点**：多个带有 `defer` 的脚本会**严格按照它们在 HTML 中出现的顺序**加载和执行，且不会阻塞 HTML 解析和主线程。
- **适用场景**：非关键脚本，如数据统计代码、页面分析工具等。晚点执行不影响页面核心功能。

2\. **使用 `async` 属性**
- **机制**：脚本进行异步加载，一旦下载完成便会立即执行。
- **特点**：不阻塞 HTML 解析，但**执行顺序是不确定的**（取决于网络下载完成的先后顺序）。
- **适用场景**：相互独立的第三方库、广告脚本等。这些脚本不依赖主干代码，也不影响核心业务逻辑。

3\. **动态加载脚本**
- **机制**：通过 JavaScript 代码动态创建 `<script>` 标签，设置 `src` 属性后插入到 DOM 中，并可绑定 `onload` 回调函数。
- **特点**：**完全控制加载时机**。可以根据用户交互（如点击某个按钮）或定时器（如延迟 3 秒后）来精准触发脚本加载，灵活性极高。

## 组件与模块的延迟加载方案 *Content-[09:46]

在现代前端框架（如 Vue、React）中，组件和模块的体积往往较大，对其进行延迟加载（懒加载）是性能优化的必选项。

- **Vue 异步组件**：
  - 在 Vue 中可以通过定义异步组件来实现延迟加载。在组件加载期间，可以配置显示一个“加载中”的组件（如 Loading 动画）；如果加载失败，则显示“错误”组件。
  - 在 Vue 3 中，通常使用 `defineAsyncComponent` API 来定义异步组件。
  - **优势**：避免用户在等待组件加载时看到空白页面，提供友好的加载状态反馈。

- **动态导入模块（Dynamic Import）**：
  - 使用 ES6 的动态 `import()` 函数结合 `await` 关键字来按需导入模块。
  - **机制**：`const module = await import('./myModule.js')`。这种方式可以明确知道模块何时导入完成，然后再执行后续的业务逻辑。
  - **适用场景**：路由懒加载、按需引入体积较大的工具库或第三方插件。

## 固定资源的预加载与预取方案 *Content-[12:29]

除了延迟加载非关键资源，对于页面必需或未来可能用到的固定资源（如核心第三方库、字体文件等），可以通过 `<link>` 标签的 `rel` 属性进行预加载优化。

- **预加载关键资源（Preload）**：
  - **属性**：`<link rel="preload" href="...">`
  - **机制**：告诉浏览器**立即加载**该资源，具有**高优先级**。
  - **适用场景**：当前页面首屏必需的核心资源（如关键 CSS、首屏自定义字体、核心 JS 文件），确保它们尽早可用。

- **预取非关键资源（Prefetch）**：
  - **属性**：`<link rel="prefetch" href="...">`
  - **机制**：利用**浏览器的空闲时间**在后台加载资源，具有**低优先级**，不会抢占当前页面的关键资源带宽。
  - **适用场景**：非关键资源、体积较大的文件，或者用户在下一步操作中极大概率会访问的页面资源（如路由跳转的下一个页面的 JS chunk）。

## AI 总结

延迟加载（Lazy Loading）是前端性能优化中不可或缺的一环，其核心思想是“好钢用在刀刃上”，即优先保障主干资源的快速加载，将非关键资源的加载推迟到浏览器空闲或用户真正需要时。

在面试中回答“延迟加载方案”时，建议采用**分类阐述**的策略：
1. **图片资源**：首选原生 HTML5 的 `loading="lazy"` 属性，配合占位图提升体验。
2. **脚本资源**：根据依赖关系选择 `defer`（保序、DOM解析后执行）或 `async`（无序、下载完即执行），或通过 JS 动态创建 `<script>` 标签实现精准控制。
3. **组件/模块**：利用现代框架的特性，如 Vue 的 `defineAsyncComponent` 异步组件，或 ES6 的动态 `import()` 实现按需加载。
4. **固定资源**：合理使用 `<link>` 标签的 `preload`（高优先级立即加载）和 `prefetch`（低优先级空闲加载）来优化资源调度。

通过这种结构化、多维度的回答，能够向面试官充分展现你扎实的前端基础以及全面的性能优化思维。
