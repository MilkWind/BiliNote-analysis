## 引言：自定义字体加载的挑战 *Content-[00:00]
- **核心主题**：前端性能优化中的关键话题——如何优雅地处理 Web 自定义字体加载。
- **背景**：在项目中，开发者通常喜欢使用漂亮的自定义字体来提升项目的设计感和品牌辨识度。
- **副作用**：这一过程会伴随着文字闪烁或空白等副作用，即 FOUT 和 FOIT 现象。
- **学习目标**：深入理解 FOUT 和 FOIT 的本质，并掌握 `font-display` 工具以控制字体加载行为。

## 为什么要使用自定义字体及其代价 *Content-[00:50]
### 使用自定义字体的优势
- **品牌辨识度**：独特的字体能让公司品牌更加凸显，帮助用户在潜意识里快速认识产品。
- **设计感与专业感**：合适的字体是最简单、最直接提升产品颜值和界面专业感的手段。
- **用户体验**：清晰易读的字体可以降低用户的认知成本，同时字体的气质也能传递出产品想要营造的氛围。

### 自定义字体的代价
- **非免费资源**：自定义字体不是免费的 UI 装饰，它和其他静态资源一样，需要被下载、管理并占用网络资源。
- **性能影响**：作为网络资源，它会增加额外的网络请求，带来加载时机的不确定性，最终导致 FOUT 和 FOIT 现象。

## 深入理解 FOUT (无样式文本闪现) *Content-[02:18]
- **现象描述**：打开网页时，文字很快显示，但使用的是宋体或黑体等默认字体。零点几秒后，文字闪烁一下，变成设计稿中的自定义字体样式。
- **本质**：Flash of Unstyled Text（无样式文本闪现）。这里的“无样式”指字体样式不正确。这并非浏览器 Bug，而是浏览器在自定义字体未下载完成时采取的加载策略。
- **加载流程**：
  1. 浏览器解析到需要自定义字体的文本，发现字体正在下载。
  2. 浏览器不等待，立即查找 CSS 中定义的备用字体（Fallback Font）先渲染文本，保证内容始终可见。
  3. 自定义字体下载完成后，浏览器进行重绘，替换当前字体，产生闪现过程。
- **优缺点分析**：
  - **优点**：文本优先可见，用户第一时间可阅读内容。对内容型网站（如博客、新闻资讯）非常友好。
  - **缺点**：字体短暂闪现会带来视觉上的不协调，可能破坏精心设计的视觉效果，使界面看起来不够稳定。
- **核心原则**：内容优先级高于样式。

## 深入理解 FOIT (不可见文本闪现) *Content-[05:54]
- **现象描述**：打开网页时，本该显示文本的地方是一片空白，过了几秒后文字才显现出来。
- **本质**：Flash of Invisible Text（不可见文本闪现），关键词是“不可见”。同样是浏览器的加载策略。
- **加载流程**：
  1. 浏览器发现自定义字体未加载完成时，选择等待，进入“字体阻塞期”。
  2. 阻塞期内完全不渲染文本，用户看到一片空白。
  3. 阻塞期通常有限（如 3 秒左右）。若 3 秒内加载成功，直接用正确字体渲染。
  4. 若超过 3 秒未加载完成，浏览器放弃等待，先用后备字体渲染文本。若之后自定义字体到达，仍会发生一次替换（表现出 FOUT 行为）。
- **优缺点分析**：
  - **优点**：避免了 FOUT 的字体闪变和视觉跳动，保证视觉风格高度统一。一旦文字出现就是最终效果。
  - **缺点**：在弱网环境（尤其是移动端）下代价极大，用户会看到大量空白，甚至以为页面坏掉，对用户体验是毁灭性打击。
- **核心原则**：样式优先级高于内容，先保证样式统一，再显示内容。

## 夺回控制权：font-display API 简介 *Content-[08:13]
- **浏览器的困境**：字体加载是异步网络请求。当 HTML 和 CSS 准备好绘制内容时，字体可能还在网络另一端。浏览器面临选择：立即渲染（FOUT）还是等待（FOIT），以及等待多久。
- **历史问题**：过去不同浏览器厂商策略不一致（如老版 Chrome 倾向 FOIT，IE 倾向 FOUT），导致跨浏览器体验不一致。
- **解决方案**：开发者比浏览器更了解项目需求，需要通过显式方式告诉浏览器如何平衡内容与样式的一致性。
- **font-display API**：
  - 不是独立属性，写在 `@font-face` 规则内部。
  - **作用**：告诉浏览器自定义字体处于不同阶段时应采取的渲染策略。
  - **注意**：它影响的是渲染策略，而不是加载行为。它不能加快字体加载速度，但能决定在字体加载完成前屏幕该发生什么。

## font-display 的四种策略详解 *Content-[10:41]

### 1. swap 策略
- **指令**：不要有任何阻塞，立即使用备用字体渲染文本，自定义字体下载好后再交换（swap）过来。
- **特点**：几乎没有文本阻塞时间，用户立即看到内容。
- **本质**：开发者主动明确选择 FOUT 行为，认为让用户快速看到内容比等待字体更重要。
- **适用场景**：目前最主流、最被推荐的字体加载策略，适合大多数需要快速展示内容的场景。

### 2. block 策略
- **指令**：让浏览器先等一下，设置一个较短的阻塞期（规范建议 3 秒）。
- **特点**：3 秒内任何使用该字体的文本不可见（FOIT 状态）。若 3 秒内加载完成，用自定义字体渲染；若超时，先用备用字体显示，等自定义字体到达后再替换。
- **本质**：偏向 FOIT 策略，创造初始视觉一致性，并添加一段容忍时间。
- **适用场景**：适合作为加载品牌标识文本（如 Logo 文字）的方法。

### 3. fallback 策略
- **指令**：一种精妙的折中方案。有一个极短的阻塞期（约 100ms）。
- **特点**：若 100ms 内字体准备好，直接切换，不影响样式。若 100ms 后未加载完成，切换到备用字体，且**本次页面访问中浏览器不会再加载自定义字体去替换它**。
- **本质**：快速失败的逻辑。网速快则看到自定义字体，网速慢则全程看到备用字体，不会发生字体替换闪烁。
- **适用场景**：对性能和视觉稳定性都非常友好的策略，体验极其稳定。

### 4. optional 策略
- **指令**：最注重性能的策略。行为类似 fallback（100ms 阻塞期，超时则回退且不替换）。
- **特点**：比 fallback 更进一步，赋予浏览器更大决定权。告诉浏览器该字体是“可选的”。若浏览器检测到用户网络极差，会开启省流模式，直接不请求自定义字体。
- **本质**：性能优先级最高，明确告诉浏览器字体只是锦上添花，不是刚需。
- **适用场景**：适合纯粹的装饰字体，不影响主内容。
- **注意事项**：开发者必须做好心理预期，指定字体在部分用户处可能永远不加载。设计和开发时必须确保即使字体不存在，界面功能依旧完美。

## AI 总结 *Content-[16:01]
自定义字体虽能提升品牌辨识度和设计感，但会引发 FOUT（无样式文本闪现）和 FOIT（不可见文本闪现）等性能问题。FOUT 优先保证内容可见但伴随样式闪烁，FOIT 优先保证样式统一但可能导致白屏。为了夺回控制权，开发者应使用 `@font-face` 中的 `font-display` 属性来指定渲染策略：`swap` 适合大多数内容优先的场景；`block` 适合短暂阻塞以等待品牌标识；`fallback` 提供 100ms 的快速失败机制以保证视觉稳定；`optional` 则将性能置于首位，允许浏览器在弱网下直接跳过装饰性字体的加载。合理选择策略，能在视觉美感与加载性能之间取得最佳平衡。
