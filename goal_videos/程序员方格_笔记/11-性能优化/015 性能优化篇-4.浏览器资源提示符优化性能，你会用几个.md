## 什么是资源提示符 *Content-[00:00]
- **定义**：资源提示符并不是新的 HTML 标签，而是我们熟悉的 `<link>` 标签上 `rel` 属性的一组特殊值（如 `dns-prefetch`、`preconnect`、`preload` 和 `prefetch`），它们被称为“加载优化四兄弟”。
- **核心作用**：开发者通常比浏览器更清楚接下来页面会发生什么。通过资源提示符，开发者可以主动告诉浏览器预测马上会用到的域名或文件，让浏览器提前做好准备。
- **带来的好处**：
  - **提高首屏加载性能**：将建立连接、下载文件等耗时操作提前，缩短用户看到页面所需的总时间。
  - **减少网络连接延迟**：请求新域名资源时，浏览器需依次完成 DNS 查询、建立 TCP 连接以及进行 TLS 握手（此过程可能耗费几百毫秒甚至更久）。资源提示符可以让这些步骤提前发生。
  - **预加载关键资源**：根据业务逻辑预加载首屏渲染必需的字体文件，或用户可能点击的下一个页面的脚本文件。
- **本质**：资源提示符是一种让浏览器从被动响应变成主动预备的关键机制，是进行加载优化的神器。

## 如何区分和选择四个指令 *Content-[02:53]
为了避免混淆这四个指令，建议从两个维度建立心智模型：
1\. **时机维度**：
  - 思考：我想要提前准备的资源，是当前页面马上就要用到，还是为未来用户访问做准备？
  - 此维度主要用于区分 `preload`（为当前页面服务）和 `prefetch`（为将来的导航服务）。
2\. **深度维度**：
  - 思考：浏览器从零开始获取资源需要经过解析域名、建立连接、下载资源。我希望浏览器把准备工作提前到哪一步？
  - 此维度主要用于区分 `dns-prefetch`（仅解析 DNS）、`preconnect`（建立连接）和 `preload`（下载资源）。它们的准备深度是逐层递进的。

## DNS Prefetch：DNS预读取 *Content-[04:42]
- **代码示例**：`<link rel="dns-prefetch" href="//api.example.com">`
- **作用**：告诉浏览器稍后可能会请求该域名，让其先在后台发起 DNS 查询并缓存结果。后续真正通过 `fetch` 或 `image` 标签请求该域名下的资源时，可省掉 DNS 查询的时间。
- **特点**：
  - **开销极小**：仅做一次 DNS 查询，不建立任何网络连接，非常轻量。
  - **兼容性最好**：几乎所有现代浏览器都支持。
- **使用场景**：
  - **非首屏必需的第三方资源**：如各种分析脚本、广告脚本、插件等（通常托管在不同域名）。提前解析可略微提升速度，且不会占用过多网络资源。
  - **作为 `prefetch` 的降级方案**：部分老浏览器可能不支持 `prefetch` 或 `preconnect`，但支持 `dns-prefetch`。将两个指令同时写上，支持高级属性的浏览器会优先使用，不支持则回退到 `dns-prefetch`，至少能享受到 DNS 解析的优化。

## Preconnect：预连接 *Content-[07:11]
- **代码示例**：`<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>`
- **作用**：比 `dns-prefetch` 更进一步，不仅完成 DNS 查询，还会完成 TCP 三次握手和 TLS 加密协商，将连接通道完全建立好。当真正请求发出时，可直接发送数据，省去多次网络往返的延迟（在移动网络下节省的时间尤为可观）。
- **使用时机**：非常适合用在确定会请求且对首屏渲染非常重要的第三方域名上。
  - **字体库**：如 Google Fonts，字体文件通常托管在独立的 CDN 上，且渲染文本必需，使用 `preconnect` 预连接字体服务器域名效果极佳。
  - **核心 API 服务或静态资源**：如果应用首屏需要从一个 API 域名获取关键数据，或从一个 CDN 域名加载核心的 CSS/JS 文件，对这些域名进行 `preconnect` 是绝佳选择。
- **注意事项**：
  - **不能滥用**：建立 TCP 连接会消耗客户端和服务端的资源，且浏览器通常对单个域名的并发连接数有限制。
  - **通用建议**：只对最关键的几个域名使用该属性，`preconnect` 的域名数最好不要超过 6 个。

## Preload：预加载资源 *Content-[09:39]
- **代码示例**：`<link rel="preload" href="font.woff2" as="font" type="font/woff2" crossorigin>`
- **意图**：明确告诉浏览器该资源对当前页面的渲染至关重要，需要以最高优先级去下载它。
- **核心属性 `as`**：
  - 必须被指定，用于告诉浏览器正在预加载什么类型的资源（如 `font`、`script`、`style` 等）。
  - 帮助浏览器正确设置请求的优先级、请求头以及内容安全策略（CSP）。
- **其他常用属性**：`type`（指定文件类型）、`crossorigin`（处理跨域请求，在加载字体文件时通常是必须的）。
- **行为特点**：
  - 以极高的优先级下载指定的资源文件。
  - 资源下载完成后，浏览器并不会立即执行它（例如 JS 被 preload 后，代码不会立即运行），资源只是被放在内存中。
  - 将资源的下载时机从被动触发变为主动提前。
- **典型使用场景**：
  - **CSS 中定义的字体文件**：常规流程中，浏览器需先下载 CSS -> 解析 -> 发现需要字体 -> 下载字体，流程较长。使用 `preload` 可让字体文件和 CSS 并行下载，缩短字体生效时间。
  - **重要的背景图或核心 LCP 图片**：提前预加载核心图片，可以显著改善 LCP（最大内容绘制）指标。
  - **首屏需通过 JS 动态插入的脚本**：确保当 JS 执行插入操作时，脚本文件已经下载完毕，可以立即执行。
- **注意事项**：`preload` 一定要用在刀刃上。如果预加载了当前页面根本用不到的资源，纯属浪费带宽。

## Prefetch：为未来导航预获取 *Content-[12:48]
- **代码示例**：`<link rel="prefetch" href="page2.js">`
- **与 Preload 的核心区别**：
  - `preload`：高优先级，为当前页面服务。
  - `prefetch`：低优先级，为未来导航服务。
- **作用**：告诉浏览器用户接下来很可能会用到该资源。在当前页面加载完成、浏览器进入空闲状态后，以最低优先级去下载它并放入缓存。它的作用不是优化当前页面的下载，而是优化下一次即将发生的导航加载体验。当用户真正点击链接跳转时，所需资源已在缓存中，页面会立即打开。
- **使用场景**：
  - **多页应用 (MPA)**：当用户在 A 页面时，可以 `prefetch` B 页面的核心 JS 或 CSS。
  - **单页应用 (SPA)**：应用极为广泛。许多路由库（如 Vue Router、React Router）支持在用户鼠标悬停到某个链接时，自动 `prefetch` 对应路由的 JS chunk，使得用户点击时路由切换非常快。
  - **基于用户行为的预加载**：基于数据统计做预加载。例如电商网页的购物车页面，可以 `prefetch` 结算页面的资源，因为用户从购物车跳转的下一步极大概率是去结算。
- **本质**：利用当前少量的空闲带宽，去换取未来极致的加载体验。

## 核心要点总结 *Content-[15:05]
1\. **共同目标**：这四个属性都是通过“预知未来”，让资源早一步准备好，从而减少用户在关键路径上的等待时间。
2\. **心智模型（选用指南）**：在选用指令时，先问自己两个问题：
  - **时机**：这个资源是为当前页面准备的，还是为未来的页面准备的？
  - **深度**：我需要把加载工作推进到哪一步？是解析域名（`dns-prefetch`）、建立连接（`preconnect`）还是下载资源（`preload`）？
3\. **谨慎使用规则**：
  - 像 `preconnect` 和 `preload` 这样的工具必须谨慎使用。
  - 过度的预连接会消耗不必要的服务端和客户端资源。
  - 错误的预加载会与关键资源抢占带宽，反而拖慢页面速度。务必将这些属性用在刀刃上。

本节视频详细讲解了前端性能优化中的“浏览器资源提示符”（`dns-prefetch`、`preconnect`、`preload`、`prefetch`）。核心思想是通过开发者主动提示，让浏览器提前完成域名解析、连接建立或资源下载，从而减少网络延迟并提升加载速度。在实际应用中，需根据“时机（当前页面还是未来导航）”和“深度（解析、连接还是下载）”两个维度来选择合适的指令，并注意避免滥用 `preconnect` 和 `preload` 以免浪费带宽和系统资源。
