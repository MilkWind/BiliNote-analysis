## 1. 长连接与短连接的区别 *Content-[00:00]

在前端协议中，经常会接触到长连接协议和短连接协议：
- **HTTP 协议**：属于**短连接协议**。每次连接都需要发送确认信息，特点是经常断开、经常连接。
- **TCP 协议**：属于**长连接协议**。只有在第一次连接时发送确认信息，之后会一直保持连接状态，不轻易断开。

**核心差异**：
因为长连接“不轻易连，连上就不轻易断”，所以它在建立连接和断开连接时的过程会非常谨慎，需要经过严格的确认机制，这就是我们今天要讲的“三次握手”和“四次挥手”。

## 2. TCP 三次握手原理详解 *Content-[01:23]

三次握手是 TCP 建立连接的过程，可以通俗地理解为“确认双方通信路线是否通畅”以及“确认建立连接意向”。

- **第一次握手（客户端 -> 服务器）**
  - **动作**：客户端向服务器发送一个请求，包含 `SYN=1` 和 `SEQ=X`。
  - **含义**：“你好，我是客户端，我想和你建立连接，我的初始序列号是 X。”
  - **目的**：确认**客户端到服务器**的发送路线是否通畅。

- **第二次握手（服务器 -> 客户端）**
  - **动作**：服务器收到请求后，返回确认信息，同意连接，并带上自己的初始序列号，同时期待客户端下次发送 `X+1`。
  - **含义**：“我收到你的请求了，我同意连接。这是我的初始序列号，请你下次回复我 `X+1` 以确认。”
  - **目的**：首先确认客户端到服务器的路线是通畅的（因为收到了请求），其次询问并确认**服务器到客户端**的返回路线是否通畅。

- **第三次握手（客户端 -> 服务器）**
  - **动作**：客户端收到服务器的返回信息后，再次发送确认信息，期待下次发送具体数据。
  - **含义**：“我收到你的信息了，双向路线都已确认通畅，我们可以正式连接并发送数据了。”
  - **目的**：确认**双向路线**都是通畅的。

**结果**：三次握手完成后，从第四次交互开始，双方就可以正式进行数据的发送与接收了。

## 3. TCP 四次挥手原理详解 *Content-[03:51]

四次挥手是 TCP 断开连接的过程，可以通俗地理解为“和平分手”，需要双方确认数据已传输完毕后再彻底断开。

- **第一次挥手（客户端 -> 服务器）**
  - **动作**：客户端告诉服务器自己没有数据要发送了，准备断开连接。
  - **含义**：“我没有数据要发给你了，准备分手/断开连接。”

- **第二次挥手（服务器 -> 客户端）**
  - **动作**：服务器收到断开请求，回复确认信息，但表示还有数据需要发送，要求客户端先等待。
  - **含义**：“我知道你要断开，我确认了。但是我最后还有一点数据要返回给你，先别彻底断开。”

- **第三次挥手（服务器 -> 客户端）**
  - **动作**：服务器将剩余数据传输完毕后，正式告诉客户端可以关闭连接了。
  - **含义**：“我的东西都给你了，数据发送完毕，现在确认可以彻底断开连接了。”

- **第四次挥手（客户端 -> 服务器）**
  - **动作**：客户端接收到服务器的最终确认信息，回复确认，双方各自关闭连接。
  - **含义**：“好的，收到确认，我们各自关闭连接，各自安好。”

**结果**：四次挥手完成后，TCP 连接彻底断开。

## 4. 面试答题技巧与建议 *Content-[06:12]

在面试中遇到“请简述 TCP 三次握手和四次挥手的原理”时，建议采取以下策略：

- **理解重于死记硬背**：不需要去死记硬背底层具体的确认包（ACK）、数据包（Data）等复杂的英文缩写和字节细节。
