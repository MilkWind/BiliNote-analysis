## 面试题背景与考察重点 *Content-[00:00]
- **业务背景**：Token 常用于请求接口或登录用户系统。用户通过用户名和密码发送请求，服务端验证成功后会返回一个加密的 Token。
- **考察核心**：主要考察 Token 加密的原理及具体实现方式。在前后端数据传输中，安全性至关重要，因此加密机制是面试中的高频考点。
- **岗位能力要求**：现代前端或客户端开发人员需要具备一定的服务端知识（如使用 Node.js），至少需要了解并能清晰描述 Token 的加密原理和实现过程。

## Token 加密的两种常见方式 *Content-[02:34]
### 对称加密
- **原理**：加密和解密使用同一套公用密钥。
- **常见算法**：AES、HS256（常用于 JWT 签名）。
- **特点**：
  - **速度快**：无需复杂的密钥交换，密钥可直接存储在环境变量中读取使用。
  - **适用场景**：适合高并发场景。例如用户登录时，服务端需要根据用户 ID 快速生成并返回 Token，对称加密能显著提升响应效率。

### 非对称加密
- **原理**：加密和解密使用不同的密钥（公钥和私钥）。
- **常见算法**：RSA。
- **特点**：
  - **密钥对机制**：可以使用公钥加密、私钥签名，或者私钥加密、公钥解密。
  - **安全性要求**：公钥可以公开分发用于解密或验证，但**私钥必须严格保密**。一旦私钥泄露，攻击者即可伪造 Token 并持续请求服务端数据。

## Token 的生成实现（Node.js 示例） *Content-[07:13]
以 Node.js 环境下的 `login.js` 为例，演示 JWT Token 的生成过程。

### 对称加密生成 Token
- **引入依赖**：导入 `jsonwebtoken` 等第三方 JWT 库。
- **核心参数**：
  - **Payload（主体部分）**：通常包含用户 ID 和权限。**注意**：严禁存储密码等敏感身份信息。
  - **Secret（密钥）**：由于是对称加密，密钥通常存储在环境变量中直接读取。
  - **Options（配置项）**：指定算法（如 `HS256`）和过期时间（如 `1h`，即一小时后需重新登录）。
- **执行**：调用库的 `sign` 方法生成加密 Token。

### 非对称加密生成 Token
- **引入依赖**：导入相应的 JWT 库。
- **核心参数**：
  - **Payload（主体部分）**：同上，包含用户 ID 和权限等基础信息。
  - **Private Key（私钥）**：读取私钥文件内容作为加密密钥。
  - **Options（配置项）**：指定算法（如 `RS256`）。
- **执行**：调用库的方法，结合私钥和 Payload 生成 Token。

## Token 的传输与验证过程 *Content-[10:31]
### 客户端存储与传输
- **存储方式**：客户端接收到 Token 后，通常存储在 `Cookie` 或 `localStorage` 中。
- **传输方式**：
  - 在 HTTP 请求头（Header）中添加特定属性（如 `Authorization: Bearer <token>`）携带 Token。
  - 或者利用 `Cookie` 机制，在后续跨域或同源请求中自动携带。

### 服务端验证与解密
- **对称加密验证**：服务端获取传入的 Token，使用相同的密钥（Secret）调用验证方法，回调中即可解析出用户 ID 等核心信息。
- **非对称加密验证**：服务端导出**公钥**，调用验证方法。基于非对称加密的特性，使用公钥即可解密并验证由私钥签名的 Token。

## 安全注意事项与工具推荐 *Content-[12:50]
### 密钥管理
- **存储方式**：推荐使用专用的密钥管理服务（如 AWS KMS）来存储公钥和私钥，**严禁硬编码或明文存储**在代码中。
- **定期更换**：建议定期（如每 3 个月）更换一次密钥，以最大程度降低泄露风险。

### Token 内容设计
- **推荐存储**：用户 ID、角色（Role）、过期时间。
- **禁止存储**：密码、身份证号等敏感隐私信息。
- **完整性保护**：始终使用签名（Signature）来验证 Token 的完整性，防止数据在传输过程中被恶意篡改。

### 推荐工具与库
- **JWT 生成与验证**：
  - Node.js：`jsonwebtoken`
  - Python：`PyJWT`
  - Java：`JJWT` 或 `java-jwt`
- **密钥管理**：云厂商提供的 KMS 服务（如 AWS KMS、阿里云 KMS 等）。

## 核心总结 *Content-[14:29]
- **核心机制**：密钥的加解密是整个 Token 生成与验证的核心，主要分为对称加密和非对称加密两种方式。
- **全生命周期安全**：在 Token 的生成、传输、验证全生命周期中，必须具备**防篡改**、**防泄露**和**可追溯**的能力。
- **面试答题思路**：在面试中，清晰阐述加密原理（对称/非对称的区别与适用场景）、具体实现过程（代码层面的参数与流程）以及安全注意事项，即可完美解答此题。
