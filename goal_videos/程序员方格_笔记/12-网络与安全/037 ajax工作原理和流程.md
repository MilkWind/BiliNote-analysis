## AJAX 的定义与核心概念 *Content-[01:32]
- **全称与定义**：AJAX（Asynchronous JavaScript and XML）是一种通过**异步通讯**实现页面**局部数据更新**的技术。
- **异步通讯机制**：
  - 与同步通讯相对。同步是发送请求后必须等待响应才能继续执行；异步则是发送请求后不阻塞当前线程，等待服务器响应后再进行后续处理。
- **核心对象**：`XMLHttpRequest`。
  - 这是 AJAX 原理的核心，所有主流浏览器均支持该对象。
  - JavaScript 通过该对象在后台与服务器进行数据交互，包括发送数据、接收数据和传递数据。
- **局部更新优势**：
  - 获取数据后，无需像传统同步方式那样刷新整个页面并重新渲染。
  - 通过 JavaScript 获取需要更新数据的 DOM 元素（例如更新今天的股市信息或某个页面的局部状态），将新数据赋值给该元素的内容区域。
  - 这种方式使得页面交互更加优雅，仅局部数据发生变化，大幅提升了用户体验。

## AJAX 的核心工作流程 *Content-[04:51]
- **后台数据交换**：JavaScript 在后台与服务器进行异步数据交换，整个过程页面不会发生整体刷新。
- **DOM 操作与更新**：
  1. 服务器处理请求并返回响应数据。
  2. JavaScript 获取到目标 DOM 元素对象。
  3. 将获取到的新数据赋值给该 DOM 元素的内容区域。
  4. 页面仅发生局部内容替换，整体结构和其他部分保持不变，完成无刷新更新。

## 传统 AJAX 的具体工作步骤 (XMLHttpRequest) *Content-[06:40]
传统 AJAX 的实现主要依赖 `XMLHttpRequest` 对象，具体工作流程如下：

1\. **触发事件**：例如用户在页面点击某个按钮，监听到事件后启动 AJAX 请求。
2\. **创建对象**：使用 `new XMLHttpRequest()` 创建负责与服务器通讯的核心对象。
3\. **配置请求**：调用 `open()` 方法配置请求方式（如 GET、POST）和请求的 URL 接口。
4\. **设置请求头**：调用 `setRequestHeader()` 设置 HTTP 请求头，例如指定请求内容的类型为 `application/json`。
5\. **发送请求**：调用 `send()` 方法将请求发送到服务器。
6\. **监听响应状态**：
   - 绑定 `onreadystatechange` 事件来监听请求状态的变化。
   - 检查 `readyState` 属性：当值为 `4` 时，表示请求已完成，且响应数据已完全接收。
   - 检查 `status` 属性：当 HTTP 状态码为 `200` 时，表示请求成功。
7\. **处理响应数据**：
   - 通过 `responseText` 获取服务器返回的响应数据。
   - 对数据进行解析和转换（如 JSON 解析）。
   - 将处理后的数据赋值给页面指定 DOM 元素的 `innerHTML` 等属性，完成局部刷新。

**`readyState` 的 5 种状态详解**：
- `0` (UNSENT)：对象已创建，但尚未调用 `open()` 方法。
- `1` (OPENED)：已调用 `open()` 方法，但尚未调用 `send()`。
- `2` (HEADERS_RECEIVED)：已调用 `send()`，且响应头和状态码已接收。
- `3` (LOADING)：响应体正在接收中（此时 `responseText` 中可能已有部分数据）。
- `4` (DONE)：请求完成，所有响应数据已接收完毕。

## 现代 AJAX 方案：Fetch API *Content-[12:15]
- **背景**：传统 `XMLHttpRequest` 写法代码量较大，且存在回调函数嵌套（回调地狱）等冗余问题。现代开发中，逐渐采用更先进的 `Fetch API` 来替代。
- **核心特性**：基于 `Promise` 设计，语法更简洁，支持 `.then()` 链式调用或 `async/await` 语法。
- **基本用法**：
  - 请求指定 URL，获取 Response 对象。
  - 通过 `.then()` 解析返回的数据（如调用 `response.json()`）。
  - 通过 `.catch()` 捕获和处理错误。
  - 解析成功后，将数据绑定到页面 DOM 元素中完成渲染。
- **高级配置**：
  - `fetch` 支持传入第二个参数（配置对象），用于设置请求方法（`method`）、请求头（`headers`）、请求体（`body`）等，功能与传统 AJAX 的配置完全对应，使用非常简单。

## 传统 AJAX 与 Fetch API 的对比 *Content-[14:54]
- **语法与结构**：
  - `Fetch API` 语法更简单，基于 Promise，有效避免了回调函数嵌套。
  - 传统 `XMLHttpRequest` 采用回调函数嵌套，代码相对冗余，但涵盖了更广泛的底层网络知识。
- **兼容性与依赖**：
  - 传统 AJAX 兼容性极好，支持所有旧版浏览器。
  - `Fetch API` 是现代浏览器原生支持的 API，若在极旧浏览器中使用，可能需要引入第三方模块（Polyfill）进行支持。
- **实际应用现状**：
  - 目前大部分现代前端项目主要使用 `Fetch API` 或基于其封装的库（如 Axios）。
  - 传统 `XMLHttpRequest` 逐渐被淘汰出局，但理解其底层原理对于面试和深入理解网络请求依然非常重要（`Fetch` 底层依然依赖于 `XMLHttpRequest` 对象机制）。
