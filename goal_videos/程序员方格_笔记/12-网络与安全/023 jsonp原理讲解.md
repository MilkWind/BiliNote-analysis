## JSONP 简介与背景 *Content-[00:00]
- **历史地位**：JSONP 在早期曾是前端与后端进行数据交互的重要手段。
- **现状**：随着 Ajax 技术的普及，以及在 Vue 等现代框架中 Axios 的广泛应用，JSONP 的实际使用场景逐渐减少。
- **面试重要性**：尽管使用频率降低，但 JSONP 的底层原理依然是前端面试中的高频考点，必须深入理解。
- **核心概念**：JSONP 本质上是前后端通过特定方式达成的一种“配合”机制。

## 利用 script 标签发起请求 *Content-[00:22]
- **场景假设**：后端接口在被访问时返回纯文本 "hello world"，前端需要获取该数据。
- **前端发起网络请求的标签**：在抛开 Ajax 的情况下，前端 HTML 标签中能够发起网络请求的属性主要有：
  - `img` 标签的 `src` 属性（用于请求图片资源）。
  - `link` 标签的 `href` 属性（用于请求 CSS 样式文件）。
  - `script` 标签的 `src` 属性（用于请求 JavaScript 文件）。
- **实现思路**：利用 `script` 标签 `src` 属性能够请求网络的特点，将服务器的后台接口地址赋值给 `src`，从而让 `script` 标签去请求后台数据接口（而非传统的 `.js` 文件）。

## 解决返回数据格式问题 *Content-[01:45]
- **直接返回纯文本的报错**：如果后端直接返回 "hello world"，前端会报错。因为 `script` 标签的初衷是关联并解析 JS 文件，它会将请求回来的内容强制当作 JavaScript 代码进行解析，而 "hello world" 并非合法的 JS 语法。
- **后端直接返回 JS 代码的弊端**：
  - 后端可以修改返回格式，例如返回 `alert('hello world')` 这样的 JS 代码，此时前端可以正常执行。
  - **不可取的原因**：前端不能将需要运行的 JS 代码全部交由后端以字符串形式返回。后端可以配合调整数据格式，但不能代替前端编写前端业务逻辑代码，这违背了前后端分离与分工的原则。

## JSONP 核心原理：函数调用与参数传递 *Content-[03:44]
- **改进方案**：后端返回一段可执行的 JS 函数调用代码，例如 `demo('hello world')`。这种格式既是合法的 JS 代码，又包含了前端需要的数据。
- **前端配合与注意事项**：
  - 前端必须预先定义好 `demo` 函数来接收数据。
  - **关键细节**：当 `script` 标签使用 `src` 属性引入外部链接时，该标签内部的内联代码将失效。因此，必须**单独使用一个 `<script>` 标签**来定义 `demo` 函数。
- **执行过程**：后端返回 `demo('hello world')` 后，浏览器将其作为 JS 执行，触发 `demo` 函数的调用，并将 "hello world" 作为参数传入。前端在函数内部通过形参即可接收到后端返回的数据。
- **核心思想总结**：利用后端调用前端预先定义好的函数，并将前端想要的数据作为函数的参数传递回来，从而完成跨域数据交互。

## 动态回调函数名（Callback）机制 *Content-[06:20]
- **硬编码函数名的痛点**：如果后端写死函数名（如固定返回 `demo('...')`），当前端需要更改函数名（如改为 `show`）时，后端也必须同步修改代码。这会导致极高的沟通和维护成本。
- **解决方案（Callback 参数）**：
  - 前端在发起请求时，通过 URL 查询参数传递回调函数的名称，例如：`?callback=demo`。
  - 后端通过接收 `callback` 参数（如获取到值 `demo`），动态拼接返回的字符串：`"函数名" + "(" + "数据" + ")"`。
- **优势**：前端可以随意指定回调函数的名称，后端只需根据传入的参数名进行字符串拼接并返回数据。后端无需关心前端具体使用了什么函数名，实现了前后端的彻底解耦。

## JSONP 完整实现步骤 *Content-[08:00]
在实际开发中，实现 JSONP 的完整流程如下：
1\. **创建 script 标签**：动态创建 `script` 标签，并设置 `src` 属性，URL 中需携带 `callback` 参数以告知后端回调函数名。
2\. **定义回调函数**：将回调函数定义在全局作用域（通常挂载到 `window` 对象中），确保后端返回的函数调用能够被浏览器正确识别和执行。
3\. **插入页面发起请求**：将创建好的 `script` 标签插入到 DOM 页面中，触发网络请求。
- **进阶技巧**：不需要在页面加载时立即发起请求。可以通过监听点击按钮等用户交互事件，在事件触发时动态将 `script` 标签插入页面，从而实现按需发起 JSONP 请求。

## AI 总结
JSONP 是一种利用 `<script>` 标签不受同源策略限制的特点，实现跨域数据请求的古老但经典的方案。其核心原理是前后端配合：前端在全局定义一个回调函数，并将函数名通过 URL 参数（如 `callback`）传递给后端；后端接收到参数后，将数据包裹在该函数调用中（如 `callbackName(data)`）作为 JS 代码返回。浏览器加载该脚本时会自动执行函数调用，从而将数据传递给前端。虽然现代开发中已被 CORS 和 Axios 等方案取代，但理解 JSONP 有助于深入掌握浏览器的脚本加载机制与前后端数据交互的本质。
