## HTTP 0.9 版本 *Content-[00:08]

- **当前状态**：早就已经过时。
- **核心特点**：
  - 组成非常简单。
  - 只允许客户端发送 `GET` 这一种请求方式。
  - 没有请求头（Header）。
  - **无状态**：请求发送后就没有了，前后的请求之间没有任何关联和状态保持。

## HTTP 1.0 版本 *Content-[00:36]

HTTP 1.0 是协议的第二个版本，相较于 0.9 版本有了非常大的变化。其比较重要的三个更新如下：

1\. **新增请求方式**：在 `GET` 的基础上，新增了 `POST` 请求，即开始支持 `GET` 和 `POST`。
2\. **新增请求头与状态码**：新增了 Header（请求头），并且引入了 HTTP 状态码机制（例如 200、302、404 等）。
3\. **新增 Cookie 机制**：引入了 Cookie，让 HTTP 协议具备了状态保持的能力。例如在用户登录场景中，可以通过 Cookie 来保持登录态。

## HTTP 1.1 版本 *Content-[01:20]

HTTP 1.1 在 1.0 的基础上进行了进一步的优化和功能扩展：

- **新增 `keep-alive` 长连接**：支持复用 TCP 连接，减少频繁建立连接的开销。
- **新增 `pipeline` 管道机制**：允许在同一个连接上并发发送多个请求。
- **新增多种 HTTP 请求方法**：除了 `GET` 和 `POST`，还新增了 `PUT`、`DELETE`、`OPTIONS`、`PATCH` 等请求方法，使得 RESTful 风格的设计更加完善。

## HTTP 2.0 版本 *Content-[01:52]

HTTP 2.0 在性能方面进行了大幅度的优化，其比较大的更新包括：

- **支持二进制协议**：将原本的文本协议转换为二进制协议，解析更高效。
- **支持头部压缩**：对 Header 字段进行压缩，从而有效提升传输性能。
- **新增多路复用**：这是 2.0 版本中非常重要的一个特点，允许在同一个连接上并发处理多个请求和响应，极大提升了网络利用率。

## HTTP 3.0 版本 *Content-[02:18]

HTTP 3.0 属于 HTTP 协议历史性和革命性的大改版，具有跨时代的意义：

- **底层协议变更**：将底层传输协议从 `TCP` 改为了 `UDP`（基于 QUIC 协议）。
- **彻底解决队头阻塞问题**：得益于底层协议的改变，彻底解决了 TCP 层面存在的队头阻塞痛点。
- **缺点与现状**：目前的缺点在于兼容性还不行，因此还不能大规模使用。讲师将其比喻为 5G 和 WiFi 的关系，虽然技术更先进、更极端，但在当前阶段，面试时只需要记住其核心优势即可，实际落地还需时间。
