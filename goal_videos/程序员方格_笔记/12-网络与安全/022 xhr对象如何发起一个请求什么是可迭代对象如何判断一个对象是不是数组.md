## 1. XHR 对象发起请求与状态 *Content-[00:00]
- **XHR 基础**：`XMLHttpRequest` (XHR) 是浏览器中 JavaScript 发起原生 HTTP 请求的核心对象。
- **发起流程**：
  - 使用 `new XMLHttpRequest()` 创建实例。
  - 调用 `open()` 方法配置请求，指定请求方法（如 `GET` 或 `POST`）和请求地址。
  - 监听 `onreadystatechange` 回调函数，用于接收服务端返回的数据。
  - 调用 `send()` 方法发送请求（若是 `POST` 请求，需在此处传入请求体数据）。
- **readyState 的五种状态**：
  - `0`: 未初始化 (Unsent)
  - `1`: 载入/已打开 (Opened)
  - `2`: 载入完成/已发送 (Headers received)
  - `3`: 交互完成/接收中 (Loading)
  - `4`: 完成/数据接收完毕 (Done) -> **重点**，实际开发中通常只关注此状态。
- **状态判断**：当 `readyState === 4` 且 HTTP 状态码 `status === 200` 时，表示请求成功，此时可安全读取服务端返回的数据。

## 2. 可迭代对象 *Content-[01:15]
- **核心概念**：在 JavaScript 中，判断一个对象是否为可迭代对象（Iterable），核心在于检查该对象内部是否实现了 `Symbol.iterator` 属性。
- 拥有该属性的对象可以使用 `for...of` 循环进行遍历。

## 3. 判断对象是否为数组的四种方式 *Content-[01:28]
面试中常考的类型判断问题，共有四种主流方式：
1. **`instanceof` 操作符**：`arr instanceof Array`。
2. **原型链判断**：`Array.prototype.isPrototypeOf(arr)`。
3. **ES6 静态方法**：`Array.isArray(arr)`（最推荐，简单且跨 iframe 安全）。
4. **跨原型链调用 `toString`**：`Object.prototype.toString.call(arr) === '[object Array]'`。

## 4. parseInt 的参数陷阱 *Content-[02:20]
- **面试陷阱**：`parseInt` 实际上接受**两个**参数，而非一个。
- **参数说明**：
  - 第一个参数：需要转换的字符串。
  - 第二个参数：基数（进制数），如 `10` 表示十进制。
- **避坑指南**：虽然默认情况下通常按十进制解析，但如果不显式传入第二个参数，`parseInt` 会根据字符串的前缀（如 `0x`）自动推断进制，导致结果不符合预期。因此，**务必显式传入第二个参数**（如 `parseInt(str, 10)`）。

## 5. TypedArray 与二进制操作 *Content-[03:05]
- **应用场景**：在 3D 开发（如 WebGL、Three.js）中，加载模型或纹理时，数据通常以二进制形式存储和传输。
- **核心概念**：`TypedArray` 和 `ArrayBuffer` 是 JavaScript 中用于直接操作二进制数据的 API。
- 了解这些概念对于从事图形学或底层数据处理的 Web 前端工程师尤为重要。

## 6. 尾递归优化 *Content-[03:36]
- **背景**：腾讯、阿里等大厂高频面试题，用于解决递归过深导致的内存问题。
- **问题示例（阶乘计算）**：
  ```javascript
  function factorial(n) {
      if (n === 1) return 1;
      return n * factorial(n - 1);
  }
  ```
  - **缺陷**：函数执行时会“入栈”。当 $n$ 很大（如 100 万）时，调用栈中会同时存在 100 万个 `factorial` 函数，导致栈溢出（Stack Overflow），浏览器卡死或报错。
- **优化方案（尾递归）**：
  将中间结果以参数形式传入，直接返回函数本身，确保调用栈中始终只有一个函数。
  ```javascript
  function factorialTail(n, total = 1) {
      if (n === 1) return total;
      return factorialTail(n - 1, n * total);
  }
  ```

## 7. JIT (Just-In-Time) 编译与 JS 运行机制 *Content-[04:55]
- **JIT 概念**：Just-In-Time（即时编译），是 JavaScript 引擎在运行时的编译机制。
- **JS 运行的三个阶段**：
  1. **词法分析** (Tokenizing/Lexing)
  2. **语法分析** (Parsing)
  3. **生成可执行代码**（生成 CPU 能识别的机器码）
- **核心特性**：JS 作为脚本语言，其核心机制是**一边编译一边执行**。
  - 编译通常发生在代码执行前的几微秒甚至更短的时间内。
  - 引擎不会一次性完成所有编译再执行，而是在语法分析和代码生成阶段进行性能优化（如消除冗余），大部分代码生成机器码后执行，小部分可能边执行边编译。

## 8. script 标签的 defer 与 async 属性区别 *Content-[07:01]
两者均用于优化外部脚本的加载，但执行时机和对 DOM 渲染的影响不同：
- **`defer`（延迟执行）**：
  - 异步下载脚本，不阻塞 DOM 解析。
  - **等到整个页面渲染结束（DOM 加载完成）后**再执行。
- **`async`（异步执行）**：
  - 异步下载脚本。
  - **一旦下载完成立即执行**。
  - 执行时会中断渲染引擎，阻塞 DOM 解析，执行完毕后再继续渲染页面。

## 9. 模块化规范：CommonJS、AMD/CMD 与 ES6 Module *Content-[07:45]
- **历史规范**：`CommonJS` 是 Node.js 的模块化规范；`AMD` 和 `CMD` 是早期浏览器端的规范（现已过时，面试时了解即可）。
- **ES6 Module 与 CommonJS 的核心区别**：
  1. **值的传递**：CommonJS 输出的是**值的拷贝**；ES6 Module 输出的是**值的引用**。
  2. **加载时机**：CommonJS 是**运行时加载**；ES6 Module 是**静态编译**（在编译阶段就能确定依赖关系和输入输出变量）。
  3. **加载方式**：CommonJS 的 `require` 是**同步加载**；ES6 Module 的 `import` 支持**异步加载**（常用于现代前端项目的按需分包）。

## 10. async 与 await 的底层原理 *Content-[08:52]
- **核心原理**：`async/await` 本质上是 Generator 函数的语法糖，在底层会被编译为 `Promise` 和 `.then()` 的链式调用。
- **代码编译示例**：
  ```javascript
  // 原始 async/await 代码
  async function foo() {
      let result = await bar();
      return result;
  }
  
  // 底层编译后的原理代码
  function foo() {
      return new Promise((resolve, reject) => {
          bar().then(result => {
              resolve(result);
          });
      });
  }
  ```
