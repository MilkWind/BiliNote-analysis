## 课程引入与核心问题 *Content-[00:00]

在前面的课程中，我们主要解决了 CSS 规则冲突时的优先级问题（即哪一条 CSS 规则会“赢”）。但在实际面试和开发中，还有一个更加底层、致命且能加分的问题：**赢了之后，CSS 到底用的是什么值？** 

很多开发者存在一个潜意识误区：认为写了 `font-size: 1.5em` 就是 `1.5em`，没写 `color` 就会自动继承，页面看起来对了就行。但实际上，浏览器在真正渲染时，几乎从来不会直接使用我们写在 CSS 文件里的原始值，而是会将其层层计算后，拿到一个 **Computed Value（计算值）**，再拿这个结果去布局和绘制。本节课将完整拆解 CSS 的算值过程。

## CSS 值的完整计算过程 *Content-[02:37]

浏览器处理 CSS 值绝不是一步完成的，而是一个分阶段的计算过程。我们写在 CSS 里的只是起点，完整的处理链路如下：

1\. **声明值 (Declared Value)**
就是我们在 CSS 里写下来的那一行代码，例如 `font-size: 1.5em`。需要注意的是，**声明值永远不等于浏览器真正使用的值**。

2\. **指定值 (Specified Value)**
在这一步，浏览器要解决的是：这个元素的这个属性到底有没有一个明确来源的值？规则顺序如下：
- 有没有规则直接命中当前元素？
- 如果没有，该属性能不能继承？能的话，就从父元素继承。
- 如果不能继承，就使用初始值 (Initial Value)。
**指定值这一步，就是继承真正发生的地方。**

3\. **计算值 (Computed Value)**
将相对、不完整的值算成可执行的结果（详见后文计算值阶段）。

4\. **使用值 (Used Value)**
最终依赖环境计算出的绝对值，用于实际的布局和绘制。

## 深入理解 CSS 继承机制 *Content-[04:02]

在“指定值”阶段，继承机制发挥了关键作用。但必须明确一个核心结论：**并不是所有的属性都可以被子元素继承，只有可继承属性在没有指定值时才会发生继承。**

- **可继承的属性**：
  如 `color`、`font-size`、`font-family`、`line-height` 等。当子元素没有被直接指定这些属性的值时，它们会去继承父元素或祖先元素已设置的样式。

- **不可继承的属性**：
  如 `margin`、`padding`、`border`、`width`、`height` 以及 `background` 等。

**经典误区解析**：
如果给父元素设置了 `margin: 20px`，子元素并不会继承这个 `margin` 值。因为 `margin` 压根就不在 CSS 的继承机制里。无论使用什么标签，无论怎么声明，子元素永远不会继承父元素的 `margin` 属性。

**关于 `inherit` 关键字**：
`inherit` 不是一个描述默认行为的词，而是一个**显式的指令**。它的意思是：无论这个属性在默认情况下是否可以继承，我都强制要求从父元素拿值。

## 计算值阶段：相对值的转换 *Content-[06:29]

在确定了指定值后，浏览器需要把相对、不完整的值算成可执行的结果，这就是**计算值 (Computed Value)** 阶段。

1\. **`em` 单位的计算基准**
如果给子元素设置 `font-size: 1.5em`，这个 `1.5` 是以**父元素的计算值**为基准的。
- 假设父元素的 `font-size` 是 `20px`。
- 那么子元素的计算值就是 $1.5 \times 20 = 30\text{px}$。
- **重要顺序**：计算时一定是**先算父元素，再算子元素**。

2\. **百分比宽度的依赖**
如果给子元素设置 `width: 50%`，这个 `50%` 是相对于谁？
- 答案是：依赖于**包含块 (Containing Block)**。
- 它不是相对于 `viewport`，也不是相对于 `body`，更不是随便一个祖先元素。这也是为什么在布局题目或面试中，`50%` 的宽度经常会成为一个坑。

3\. **`line-height` 为什么推荐写纯数字？**
- 当设置 `line-height: 1.5` 时，它的**计算值仍然是 `1.5`**，不会立刻变成像素值。真正乘以 `font-size` 是在下一步的“使用值”阶段。
- 这就是为什么 `line-height: 1.5` 比写死 `line-height: 24px` 更加稳定，因为它能随着子元素 `font-size` 的变化而动态自适应。

## 调试技巧与课程总结 *Content-[08:46]

**CSS 调试技巧**：
在学习或 Debug CSS 时，**不要只看 CSS 文件**，因为在代码里看不到浏览器的最终计算结果，只能靠猜。正确的做法是：
1. 打开浏览器的 **DevTools**。
2. 选中目标元素。
3. 在 **Computed** 面板中查看任意一个属性的链路。
例如查看 `font-size`，你可以清晰地看到 `1.5em` 的声明，以及父元素 `20px` 的基准值，最终得出 `30px` 的标准答案。

**课程总结**：
如果面试官问“CSS 的值是怎么生效的？”，标准回答思路如下：
浏览器不会直接使用声明值，而是经过**层叠、指定、继承、计算和使用**等阶段。真正用于布局和绘制的是**计算值**和**使用值**。
