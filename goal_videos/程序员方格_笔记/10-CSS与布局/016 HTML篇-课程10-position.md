## position 的本质与包含块 *Content-[00:22]

- **核心本质**：`position` 的本质不是“如何移动元素”，而是“浏览器使用哪一套坐标系统来计算元素的位置”。
- **底层逻辑**：当我们编写 `top: 10px; left: 20px;` 时，并不是单纯地移动元素，而是解决一个更底层的问题——这 10 像素是相对谁的 10 像素。
- **核心结论**：`position` 等于坐标系统的选择。
- **包含块（Containing Block）**：在深入代码前，需要建立一个底层概念，即“包含块”。我们可以把包含块理解为浏览器给元素计算 `top`、`left` 时使用的参考坐标系。
- **坐标系分类**：浏览器里常见的坐标系统主要分为三类：普通文档流定位上下文坐标系、视口坐标系（Viewport）等。

## static 定位：普通文档流坐标系 *Content-[01:50]

- **表现现象**：给元素设置 `position: static`，并添加 `top` 和 `left` 的偏移值，刷新页面后元素位置不会发生任何改变。
- **原理解析**：`static` 元素完全服从普通文档流坐标系。在文档流坐标系中，元素的位置由 HTML 顺序以及 `display`、`margin` 等属性决定，`top`、`left`、`right`、`bottom` 不参与计算。
- **面试回答技巧**：当面试官问“为什么给元素加了 `top: 10px` 没反应”时，正确的回答并不是“因为 `static` 不能用 `top`”，而是“因为它仍然在普通文档流坐标系中，`top` 和 `left` 不参与布局的计算”。

## relative 定位：相对自身与创建参照系 *Content-[02:59]

- **偏移基准**：将 `position` 改为 `relative` 后，`top` 和 `left` 开始发挥作用。`relative` 的偏移是相对于它在文档流中**原本的位置**，而不是相对于父元素。
- **占位特性**：`relative` 元素**仍然占位**，不会脱离文档流。通过添加兄弟元素验证可以发现，兄弟元素并不会补上该元素原来的位置。
- **核心价值（创建参照系）**：
  - 当父元素设置为 `position: relative`，子元素设置为 `position: absolute` 时，子元素会贴在父元素的右上角。
  - 原理：`relative` 创建了一个非 `static` 的定位祖先，成为了 `absolute` 子元素的包含块（Containing Block）。给父元素加 `relative` 不是为了移动父元素，而是为了指定坐标系统，让子元素知道该往哪里进行布局。
- **总结**：`relative` 自己仍然在文档当中占位，同时创建了定位的参照系。

## absolute 定位：脱离文档流与定位祖先 *Content-[04:55]

- **三大核心效果**：`absolute` 生效后会产生三个主要影响：
  1. 元素不再占据原位置。
  2. 兄弟元素会当它不存在。
  3. 父元素计算高度时也看不到它。
- **面试高频题**：为什么 `absolute` 会导致父元素的高度塌陷？标准答案是因为 `absolute` 脱离了普通文档流，父元素在计算高度时不会考虑它。
- **定位规则**：`absolute` 会向上寻找最近的 `position` 不等于 `static` 的祖先元素作为包含块。如果一路找不到，就会相对于初始包含块（Initial Containing Block）进行定位（例如直接跑到页面的右上角）。
- **总结**：`absolute` 等于脱离文档流 + 相对最近的定位祖先进行定位。这是 `position` 最核心的坐标系统切换。

## fixed 定位：视口坐标系与 transform 的影响 *Content-[06:23]

- **基本表现**：给元素设置 `position: fixed`，元素会出现在文档的最上方，并固定在浏览器的顶部。如果页面可以滚动，`fixed` 元素不会随之滚动，永远停留在浏览器最顶部。
- **原理解析**：在这种情况下，`fixed` 使用了视口（Viewport）作为坐标系统。
- **高级面试点（包含块突变）**：`fixed` 是永远相对视口的吗？
  - 答案：不是。如果给外层容器添加 `transform` 属性，刷新页面后会发现 `fixed` 元素开始相对这个容器定位，而不是视口。
  - 原理：当祖先元素创建新的渲染上下文（比如使用 `transform`）时，`fixed` 的包含块可能会发生变化。
- **面试回答**：`fixed` 通常绑定视口坐标系，但当祖先元素创建新的渲染上下文（比如 `transform`）时，`fixed` 的包含块可能会发生变化。这是一个非常底层且有深度的理解。

## sticky 定位：基于滚动位置的状态机 *Content-[07:45]

- **行为表现**：给元素设置 `position: sticky`。在滚动页面时，它一开始像 `relative` 一样随页面滚动；当滚动到 `top` 为 0（达到阈值）时，它开始“黏住”，停留在浏览器的顶部。
- **原理解析**：这不是特效，而是因为 `sticky` 是一种基于滚动位置的状态机。可以理解为：未达到阈值时，它是 `relative`；达到阈值时，它在滚动容器内表现为 `fixed` 的状态。
- **生效条件（面试排查指南）**：当面试官问“`sticky` 为什么不生效”时，可按以下三条逐一排查：
  1. 必须指定 `top` 或者 `bottom`。
  2. 会受到最近滚动容器的限制（不能超出父容器的边界）。
  3. 不合理的 `overflow` 会导致 `sticky` 失效（例如父元素设置了 `overflow: hidden`）。

## 课程总结 *Content-[09:27]

- `position` 决定了元素使用哪套坐标系统来计算几何位置。
- **static**：服从普通文档流。
- **relative**：不脱离文档流，并且创建新的参照系。
- **absolute**：脱离文档流，会找到最近的定位祖先进行定位。
- **fixed**：通常会相对视口，但也有可能被 `transform` 改变包含块。
- **sticky**：`relative` 和 `fixed` 的状态切换。
- 使用这套底层逻辑来回答 `position` 的问题，能够展现出我们不是在死记硬背 API，而是在讲述浏览器的布局机制。
