## 课程引入与核心概念 *Content-[00:00]
- **前置知识回顾**：在前面的课程中，已经讲解了 CSS 的前半段核心知识，包括样式解析、样式重叠、多条规则冲突时的浏览器选择机制、优先级来源顺序以及 `!important` 的作用。这些主要解决的是“哪一条 CSS 规则会赢”的问题。
- **本节核心议题**：解决一个更底层、更致命且能在面试中大幅加分的问题——**赢了之后，CSS 到底用的是什么值**，即 CSS 的继承与计算值。
- **常见认知误区**：
  - 许多开发者潜意识认为：写了 `font-size: 1.5em`，最终值就是 1.5em；没写 `color`，就会自动继承。只要看起来写对了，页面渲染就对了。
  - **真相**：浏览器在真正渲染时，几乎从来不会直接使用开发者写在 CSS 文件里的值。它会将 CSS 层层计算后，拿到一个 **Computed Value（计算值）**，再拿这个最终结果去进行布局和绘制。

## CSS 值的计算阶段与指定值 *Content-[02:35]
- **案例引入**：
  - 结构：`body` 设置 `font-size: 16px`；`parent` 设置 `font-size: 20px` 和 `color: #333`；`child` 内部有一个 `span`，不写任何样式。
  - 结果：`span` 最终的 `font-size` 是 20px，`color` 是 #333。
  - 追问：浏览器是在哪一步决定它是 20px 的？是直接继承还是有中间状态？
- **CSS 值的完整计算过程**：浏览器处理 CSS 值不是一步完成的，而是一个分阶段的计算过程。写在 CSS 里的只是起点，完整过程为：**声明值 (Declared Value) -> 指定值 (Specified Value) -> 计算值 (Computed Value) -> 使用值 (Used Value)**。
  - **声明值 (Declared Value)**：在 CSS 里写下的那一行规则（例如给 `child` 设置 `font-size: 1.5em`）。**注意：声明值永远不等于浏览器真正使用的值。**
  - **指定值 (Specified Value)**：浏览器需要解决该元素的这个属性到底有没有一个明确来源的值。判定规则顺序如下：
    1. 有没有规则直接命中当前元素？
    2. 如果没有，该属性能不能继承？能的话，就从父元素继承。
    3. 不能继承的话，就使用初始值 (Initial Value)。
  - **核心结论**：**指定值这一步，就是继承真正发生的地方。**

## CSS 属性的继承机制 *Content-[04:02]
- **继承的核心原则**：并不是所有的属性都可以被子元素继承。**只有可继承属性在没有指定值时，才会发生继承。**
- **可继承属性**：
  - 包括 `color`、`font-size`、`font-family`、`line-height` 等。
  - 当子元素没有被指定这些属性的值时，它们会去继承父元素或祖先元素的值。
- **不可继承属性**：
  - 包括 `margin`、`padding`、`border`、`width`、`height` 以及 `background` 等。
- **经典误区解析**：
  - 场景：`parent` 设置了 `margin: 20px`，`child` 未声明该值。
  - 结果：`child` 并没有继承 `margin` 的值，且**永远不会继承**。
  - 原因：`margin` 压根就不在 CSS 的继承机制里。无论使用什么 HTML 标签，或者怎么去声明元素，它都不会去继承父元素的 `margin` 属性。在浏览器的 DevTools 中也能验证，子元素并没有从父元素继承 `margin`。
- **`inherit` 关键字**：
  - `inherit` 不是一个默认行为，而是一个**显式的指令**，不是描述行为的单词。
  - 它的含义不是“我想继承就继承”，而是：**无论这个属性本来是否可以继承，我都强制从父元素拿值**。

## 计算值阶段与相对单位解析 *Content-[06:25]
- **计算值 (Computed Value) 的核心任务**：把相对、不完整的值算成可执行的结果。
- **`em` 单位的计算基准**：
  - 场景：给 `child` 设置 `font-size: 1.5em`。
  - 基准：以**父元素的计算值**为基准。如果父元素 `font-size` 是 20px，那么计算过程为 $1.5 \times 20 = 30$。
  - 结果：这个 30px 就是所谓的计算值。计算顺序是**先算父，再算子**。在 DevTools 中可以看到 `font-size` 得到的值就是 30px。
- **百分比 `%` 的计算基准**：
  - 场景：给 `child` 设置 `width: 50%`。
  - 基准：依赖的是**包含块 (Containing Block)**，而不是 Viewport，也不是 Body，或者随便一个祖先元素。
  - 避坑指南：这也是为什么在布局题目或面试中，50% 的宽度经常会出现计算错误的原因。
- **`line-height` 的推荐写法**：
  - 推荐将 `line-height` 写成无单位的数字（如 `1.5`）。
  - 原理：在计算值阶段，`line-height: 1.5` 的计算值仍然是 `1.5`，它不会立刻变成像素。真正乘以 `font-size` 是在下一步的“使用值”阶段。
  - 优势：因此，`line-height: 1.5` 比直接写死 `line-height: 24px` 要更加稳定。
- **Debug CSS 的实用技巧**：
  - 调试 CSS 时，不要只看 CSS 文件，因为在文件里看不到浏览器的计算结果，只能靠猜。
  - 正确做法：打开 DevTools，选中元素，在 **Computed** 面板里查看任意一个属性的链路。例如查看 `font-size`，可以看到它的 30px 最终是怎么来的（一层层 1.5 的声明，再到父元素 20px 的值），这一行就是浏览器给出的标准答案。

## 课程总结与面试回答技巧 *Content-[08:46]
- **面试标准回答话术**：如果面试官问“CSS 的值是怎么生效的？”，可以按以下逻辑回答：
  1. 浏览器不会直接使用声明值 (Declared Value)。
  2. 而是经过层叠、指定、继承、计算和使用等阶段。
  3. 最终真正用于布局和渲染的是**计算值 (Computed Value)**和**使用值 (Used Value)**。

## AI 总结 *Content-[09:14]
本节课深入剖析了 CSS 渲染底层的值计算机制，打破了“写了什么就用什么”的直觉误区。核心要点如下：
1. **CSS 值的生命周期**：从声明值到最终的使用值，需经历指定、继承、计算等多个阶段，浏览器最终使用的是计算值和使用值。
2. **继承机制的边界**：只有特定属性（如 `color`, `font-size`）支持继承，而盒模型属性（如 `margin`, `padding`, `width`）绝不继承。`inherit` 关键字可用于强制继承。
3. **相对单位的计算基准**：`em` 依赖于父元素的计算值（先父后子），`%` 宽度依赖于包含块 (Containing Block)。`line-height` 推荐使用无单位数字以保证稳定性。
4. **实战调试建议**：排查 CSS 问题必须依赖 DevTools 的 Computed 面板，追踪属性的真实计算链路，而非仅凭代码主观猜测。掌握这些底层原理，能显著提升前端面试中的专业深度。
