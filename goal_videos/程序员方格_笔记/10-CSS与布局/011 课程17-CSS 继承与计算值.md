## CSS 值的计算过程概述 *Content-[02:35]

- **核心结论**：浏览器在真正渲染时，几乎从来不会直接使用开发者在 CSS 中写的值。它会将 CSS 层层计算后，拿到一个 Computed Value（计算值），再拿这个结果去布局和绘制。
- **CSS 值的完整计算过程**：浏览器处理 CSS 值不是一步完成的，而是一个分阶段的计算过程。写在 CSS 里的只是起点，完整过程如下：
  1\. **声明值 (Declared Value)**：在 CSS 里写下来的值（如 `font-size: 1.5em`）。需要注意的是，声明值永远不等于浏览器真正使用的值。
  2\. **指定值 (Specified Value)**：浏览器需要解决该元素属性到底有没有一个明确来源的值。
     - 规则判定顺序：
       - 有没有规则直接命中当前元素？
       - 如果没有，能不能继承？能的话从父元素继承。
       - 不能继承的话，就使用初始值 (Initial Value)。
     - **关键点**：指定值这一步是**继承真正发生的地方**。
  3\. **计算值 (Computed Value)**：将相对、不完整的值算成可执行的结果（后续章节详细讲解）。
  4\. **使用值 (Used Value)**：最终用于布局和绘制的值。

## CSS 继承机制详解 *Content-[04:00]

- **核心结论**：并不是所有的属性都可以被子元素继承，只有**可继承属性**在没有指定值时才会发生继承。
- **可继承的属性**：
  - 当没有被元素指定这些属性的值时，它们会去继承父元素或祖先元素的样式。
  - 常见可继承属性：`color`、`font-size`、`font-family`、`line-height` 等。
- **不可继承的属性**：
  - 常见不可继承属性：`margin`、`padding`、`border`、`width`、`height`、`background` 等。
- **经典误区示例**：
  - 给父元素 `parent` 设置 `margin: 20px`，子元素 `child` 未声明该值。
  - 结果：`child` 并不会继承 `margin` 的值，它永远不会继承，因为 `margin` 压根就不在继承机制里。无论使用什么标签或如何声明元素，都不会继承父元素的 `margin`。

## `inherit` 关键字与强制继承 *Content-[05:50]

- **`inherit` 的本质**：它不是一个默认行为，也不是描述行为的单词，而是一个**显式的指令**。
- **作用机制**：它的意思不是“我想继承就继承”，而是**无论这个属性本来是否可以继承，都强制从父元素拿值**。

## 计算值阶段与相对值转换 *Content-[06:19]

- **核心任务**：把相对、不完整的值算成可执行的结果。
- **相对单位计算 (`em`)**：
  - 示例：给 `child` 设置 `font-size: 1.5em`。
  - 基准：以**父元素的计算值**为基准。
  - 计算：如果父元素 `font-size` 是 $20\text{px}$，则 $1.5 \times 20 = 30\text{px}$。这个 $30\text{px}$ 就是计算值。
  - 顺序：**先算父，再算子**。
- **百分比计算 (`%`)**：
  - 示例：给 `child` 设置 `width: 50%`。
  - 基准：依赖的是**包含块 (Containing Block)**，而不是 Viewport、Body 或随便一个祖先元素。这也是在布局题目或面试中，`50%` 宽度经常出现坑的原因。
- **`line-height` 的特殊性**：
  - 为什么推荐 `line-height` 写成数字（如 `1.5`）而不是像素（如 `24px`）？
  - 在计算值阶段，`line-height: 1.5` 的计算值仍然是 `1.5`，它不会立刻变成像素。
  - 真正乘以 `font-size` 是在下一步的**使用阶段**。因此，`line-height: 1.5` 比 `line-height: 24px` 更加稳定。

## 调试技巧与课程总结 *Content-[08:45]

- **Debug CSS 技巧**：
  - 不要只看 CSS 文件，因为在 CSS 文件里看不到浏览器的计算结果，只能靠猜。
  - 应该打开 DevTools，选中元素，在 **Computed** 面板里查看任意一个属性的链路。
  - 例如查看 `font-size`，可以看到 $30\text{px}$ 最终是怎么来的（从 $1.5$ 的声明到父元素 $20\text{px}$ 的值），这一行就是浏览器给出的标准答案。
- **课程总结**：
  - 面试官提问：CSS 的值是怎么生效的？
  - 标准回答：浏览器不会直接使用声明值，而是经过**层叠、指定、继承、计算和使用**阶段，真正使用的是**计算值**和**使用值**。

## AI 总结

本节课深入剖析了 CSS 值的底层计算机制，打破了“写了什么就用什么”的思维误区。核心要点包括：CSS 值的生效需经历声明、指定、计算到使用的完整链路；继承仅发生在指定值阶段且仅限特定属性；相对单位（如 `em`、`%`）的计算依赖于父元素计算值或包含块；而 `line-height` 使用无单位数字能在计算阶段保持灵活性，提升布局稳定性。掌握这些底层原理并结合 DevTools 的 Computed 面板进行调试，是应对前端面试中 CSS 场景题和底层原理题的关键加分项。
