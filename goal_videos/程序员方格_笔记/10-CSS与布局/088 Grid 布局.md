## Flex 与 Grid 的设计目标差异 *Content-[00:23]
- **核心定义**：Flex 是一维布局，Grid 是二维布局。
- **思维方式的差异**：
  - 使用 **Flex** 时，我们在问浏览器：“这些元素要怎么排成一条队？”它更像是**内容驱动**的。
  - 使用 **Grid** 时，我们在问浏览器：“这个页面整体的版式长什么样？”我们需要把画布切成网格，定义多少行、多少列，以及哪些区域占几块，它更像是**设计稿驱动**的。
- **上手体验**：Flex 符合直觉，上手就能写；Grid 要求先做版式设计，提前想清楚结构，因此上手容易卡壳。
- **结论**：Grid 并不是比 Flex 更高级，两者只是解决不同问题的工具。

## 真实场景下 Flex 布局的局限性 *Content-[02:17]
- **经典布局场景**：实现一个包含 Header、Sidebar、Content 和 Footer 的常见页面结构。
- **Flex 的实现方式**：
  - 外层容器使用 Flex 让 Header、Main 和 Footer 纵向排列。
  - Main 内部再使用 Flex 让 Sidebar 和 Content 横向排队。
- **Flex 的天然特征与痛点**：
  - **依赖嵌套容器**：在描述二维结构时，必须通过嵌套来模拟（外层管纵向，内层管横向）。
  - **复杂度爆炸**：当页面变复杂（如增加右侧工具栏或内部再分区）时，嵌套层级会越来越多，导致两种痛苦：
    1. **改结构困难**：例如在移动端需要将 Sidebar 放到底部，必须修改 HTML 顺序、调整 `flex-direction` 或添加 `order` 属性。
    2. **布局意图不直观**：在 CSS 中只能看到 `display: flex` 等属性，代码“能跑”但很难一眼看出整个页面的版式结构，团队协作中维护成本极高。
- **结论**：Flex 做页面结构时，本质上是用“排队”去“模拟”版式，这种模拟会在后期带来极大的复杂度。

## Grid 布局的实现与工程优势 *Content-[04:32]
- **Grid 的实现步骤**：
  1. **声明行列**：使用 `grid-template-rows` 和 `grid-template-columns` 定义行高和列宽（例如：Header 高 60px，Main 占据剩余高度，Footer 高 40px；Sidebar 宽 220px，Content 占据剩余宽度）。
  2. **划分区域**：使用 `grid-template-areas` 分配区域。这种写法的可读性极高，不是在调对齐，而是在“画结构”，甚至可以直接把它当成一张小型的设计稿。
  3. **元素认领**：让每个子元素通过 `grid-area` 属性认领自己对应的区域。
- **Grid 的工程优势**：
  - **HTML 与视觉解耦**：HTML 的顺序不再强绑定视觉顺序。DOM 可以完全按照语义来写（Header 在前，Footer 在后），视觉排版由 `grid-template-areas` 决定，这对可访问性、SEO 以及后期结构调整非常友好。
  - **响应式调整极简**：在移动端需要将 Sidebar 移到 Content 下方时，只需在 CSS 中添加 Media Query，修改 `grid-template-areas` 的字符串排列即可（如改为 `header`、`content`、`sidebar`、`footer`）。无需修改 HTML 顺序，也无需折腾 `flex-direction` 或 `order`，仅仅是换了一张“版式图”。

## 工程实践中 Grid 不常用的原因 *Content-[07:55]
尽管 Grid 非常适合页面整体结构，但在实际工程中团队仍更爱用 Flex，主要原因有三点：
- **心智成本更高**：Flex 上手门槛低，而 Grid 需要提前理清行列和区域的关系。在业务需求没有明确版式、经常“边做边改”的情况下，团队自然倾向于试错成本更低的 Flex。
- **组件化时代的需求特征**：日常工作中 90% 的布局需求都是在写组件内部（如按钮对齐、卡片分区），这些绝大多数是**一维问题**。在这一层级，Flex 就是最优解甚至标准答案。
- **团队规范固化**：许多中后台团队已经有固定的 Layout 模板，或者沉淀了一套成熟的 Flex 写法。在这种情况下，引入 Grid 的收益不一定能覆盖学习成本和重构风险。
- **结论**：Grid 不常用不是因为它弱，而是因为它更像是一个“版式工具”，而工程里大量的需求是在做“组件细节”。Grid 用的少，绝不等于 Grid 不重要。

## 总结与面试应对策略 *Content-[09:35]
- **一句话选择规则**：
  - 如果面对的是一堆东西**怎么排**（一维排列），用 **Flex**。
  - 如果面对的是页面整体版式**怎么切**（二维结构），用 **Grid**。
- **面试高分话术**：在面试中，可以通过这句话向面试官展示你对布局层级的深刻理解：“**Grid 是写设计稿骨架的工具，而 Flex 是写组件排列的工具。**” 面试官考察 Grid 和 Flex 时，本质上就是在考察你能否分清布局层级并做出正确的工具选择。
