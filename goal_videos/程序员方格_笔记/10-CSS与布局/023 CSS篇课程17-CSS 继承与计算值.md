## 引言：CSS 值的底层逻辑 *Content-[00:00]
- 在前面的课程中，我们主要解决了 CSS 样式重叠、规则冲突、优先级来源顺序以及 `!important` 等“哪一条 CSS 规则会赢”的问题。
- 本节课将解决一个更加底层、致命且面试中非常加分的问题：**赢了之后，CSS 到底用的是什么值？** 也就是 CSS 的继承与计算值。
- **常见误区**：很多开发者潜意识里认为，写了 `font-size: 1.5em` 最终就是 `1.5em`，没写 `color` 就会自动继承，只要看起来写对了，页面渲染就对了。
- **实际情况**：浏览器在真正渲染时，几乎从来不会直接使用开发者写的值。它会把写的 CSS 层层计算后，拿到一个 **Computed Value**（计算值），再拿这个结果去布局和绘制。

## CSS 值的计算阶段 *Content-[01:35]
- **示例引入**：
  - `body` 设置 `font-size: 16px`，`parent` 设置 `font-size: 20px`。
  - `child` 中的 `span` 未设置任何样式。
  - 结果：`span` 的 `font-size` 是 `20px`，`color` 是 `#333`。
  - 追问：浏览器是在哪一步决定它是 `20px` 的？是直接继承还是有中间状态？
- **核心结论**：浏览器处理 CSS 值不是一步完成的，而是一个分阶段的计算过程。写在 CSS 里的只是起点。
- **完整计算过程**（按顺序）：
  1. **声明值 (Declared Value)**：在 CSS 里写下的规则（如 `font-size: 1.5em`）。注意：声明值永远不等于浏览器真正使用的值。
  2. **指定值 (Specified Value)**：解决该元素属性是否有明确来源的值。
     - 规则顺序：是否有规则直接命中当前元素？ -> 能否继承？（能则从父元素继承） -> 使用初始值。
     - **继承真正发生的地方就是“指定值”这一步。**
  3. **计算值 (Computed Value)**：将相对、不完整的值算成可执行的结果。
  4. **使用值 (Used Value)**：最终在页面上使用的值。

## CSS 继承机制详解 *Content-[04:02]
- **核心结论**：**并不是所有的属性都可以被子元素继承**。只有“可继承属性”在没有指定值时才会发生继承。
- **可继承的属性**：
  - 文本与字体相关：`color`, `font-size`, `font-family`, `line-height` 等。
  - 当子元素未指定这些属性时，会继承父元素或祖先元素的值。
- **不可继承的属性**：
  - 盒模型相关：`margin`, `padding`, `border`, `width`, `height`。
  - 背景相关：`background` 等。
- **经典误区验证**：
  - 给 `parent` 设置 `margin: 20px`，`child` 未声明。
  - `child` **永远不会**继承 `margin` 的值，因为 `margin` 压根就不在继承机制里。无论使用什么标签（如改成 `div`），都不会继承父元素的 `margin` 属性。

## 强制继承：inherit 关键字 *Content-[05:50]
- `inherit` 不是一个默认行为，而是一个**显式的指令**。
- 它的意思不是“我想继承就继承”，而是：无论该属性本来是否可以继承，都**强制从父元素拿值**。

## 计算值阶段：相对单位的基准与 line-height *Content-[06:25]
- 在“计算值”阶段，浏览器会把相对、不完整的值算成可执行的结果。
- **相对单位 `em` 的计算基准**：
  - 示例：`child` 设置 `font-size: 1.5em`。
  - 基准：父元素的计算值。若父元素 `font-size` 为 `20px`，则计算值为 $1.5 \times 20 = 30$（即 `30px`）。
  - 计算顺序：**先算父，再算子**。
- **百分比 `%` 的计算基准**：
  - 示例：`child` 设置 `width: 50%`。
  - 基准：依赖的是**包含块 (Containing Block)**，而不是 Viewport，也不是 `body` 或随便一个祖先元素。这也是布局题中 `50%` 宽度常踩坑的原因。
- **`line-height` 为什么推荐写成无单位数字**：
  - 在计算值阶段，`line-height: 1.5` 的计算值仍然是 `1.5`，不会立刻变成像素值。
  - 真正乘以 `font-size` 是在下一步“使用值”阶段。
  - 结论：`line-height: 1.5` 比 `line-height: 24px` 更加稳定，因为它能随子元素自身的 `font-size` 动态计算。

## 调试技巧：使用 DevTools 查看计算值 *Content-[08:08]
- 学习或 Debug CSS 时，不要只看 CSS 文件，因为无法直接看到浏览器的计算结果，只能靠猜。
- **正确做法**：打开 DevTools，选中元素，在 **Computed** 面板里查看任意属性的链路。
  - 例如查看 `font-size`，可以看到 `30px` 是如何由 `1.5em` 的声明和父元素 `20px` 的值计算得来的。这一行就是浏览器给出的标准答案。

## 课程总结 *Content-[08:46]
- **面试回答思路**：当被问到“CSS 的值是怎么生效的”时，可以这样回答：
  - 浏览器不会直接使用声明值。
  - 而是经过**层叠、指定、继承、计算和使用**阶段。
  - 真正使用的是**计算值**和**使用值**。

## AI 总结
本节课深入剖析了 CSS 样式在浏览器中的底层生效机制，打破了“写了什么就用什么”的表层认知。核心要点包括：CSS 值的生效需经历声明值、指定值、计算值和使用值四个阶段；继承机制仅对特定属性（如字体、颜色）有效，且在“指定值”阶段发生；相对单位（如 `em`、`%`）的计算依赖于父元素计算值或包含块；推荐使用无单位的 `line-height` 以保证布局稳定性。掌握这些底层逻辑，不仅能提升 CSS 调试能力，更是前端面试中展现深度的关键加分项。
