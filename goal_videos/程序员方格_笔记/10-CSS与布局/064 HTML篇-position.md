## 核心概念：Position 的本质与 Containing Block *Content-[00:22]

- **Position 的本质**：`position` 属性的本质并不是决定“怎么移动元素”，而是决定“浏览器使用哪一套坐标系统来计算这个元素”。
- **偏移量的真实含义**：当我们写 `top: 10px` 或 `left: 20px` 时，并不是单纯地往某个方向挪动，而是在解决一个更底层的问题——这 10 像素是相对谁的 10 像素。
- **Containing Block（包含块）**：在写代码前需要建立的底层概念。包含块可以理解为浏览器给元素计算 `top`、`left` 等偏移值时所使用的**参考坐标系**。
- **坐标系统分类**：浏览器中常见的坐标系统主要分为普通文档流定位上下文坐标系和视口坐标系等。

## Static 定位：普通文档流坐标系 *Content-[01:47]

- **默认行为**：当元素设置为 `position: static` 时，它完全服从普通文档流坐标系。
- **位置决定因素**：在文档流坐标系中，元素的位置由 HTML 顺序以及 `display`、`margin` 等属性决定。
- **偏移属性失效**：`top`、`left`、`right`、`bottom` 属性在 `static` 状态下不参与布局计算。
- **面试回答技巧**：当面试官问“为什么给元素加了 `top: 10px` 没反应”时，正确的回答不是“因为 `static` 不能用 `top`”，而是“因为它仍然在普通文档流坐标系中，`top` 和 `left` 不参与布局的计算”。

## Relative 定位：相对自身与创建参照系 *Content-[02:59]

- **相对自身原位置**：`relative` 的偏移是相对于该元素在文档流中**原本的位置**，而不是相对父元素。
- **不脱离文档流**：`relative` 元素仍然会在文档中占位。即使发生了偏移，其原来的位置依然被保留，兄弟元素不会补上来。
- **核心价值（创建参照系）**：`relative` 真正的作用在于为子元素创建定位参照系。
  - 当父元素设置 `position: relative`，子元素设置 `position: absolute` 时，父元素就成为了一个非 `static` 的定位祖先，从而成为子元素的包含块。
  - 给父元素加 `relative` 往往不是为了移动父元素本身，而是为了指定坐标系统，让子元素知道该往哪里进行布局。
- **总结**：`relative` 的作用有两点：第一，自己仍在文档中占位；第二，创建了定位的参照系。

## Absolute 定位：脱离文档流与定位祖先 *Content-[04:54]

- **脱离文档流的三大效果**：
  1. 元素不再占据原位置。
  2. 兄弟元素在布局时会当它不存在。
  3. 父元素在计算高度时也看不到它。
- **面试高频题（高度塌陷）**：为什么 `absolute` 会导致父元素高度塌陷？标准答案是因为 `absolute` 脱离了普通文档流，父元素在计算高度时不会考虑它。
- **包含块寻找规则**：`absolute` 元素会向上寻找最近的 `position` 不等于 `static` 的祖先元素作为包含块。如果一路向上找不到，就会相对于初始包含块（通常是视口或根元素）进行定位。
- **核心规则**：`absolute` = 脱离文档流 + 相对最近的定位祖先进行定位。这是 `position` 体系中最核心的坐标系统切换。

## Fixed 定位：视口坐标系与 Transform 影响 *Content-[06:22]

- **视口坐标系**：`fixed` 定位通常使用视口（Viewport）作为坐标系统。元素会固定在浏览器的指定位置（如顶部），在页面滚动时不会随之滚动。
- **高级面试点（包含块变化）**：`fixed` 元素永远相对视口吗？答案是否定的。
  - 如果外层祖先元素添加了 `transform` 等属性，会创建一个新的渲染上下文。
  - 此时，`fixed` 元素的包含块可能会发生变化，它将相对于这个设置了 `transform` 的容器进行定位，而不是视口。
- **面试回答话术**：`fixed` 通常绑定视口坐标系，但当祖先元素创建新的渲染上下文（例如使用了 `transform`）时，其包含块可能会发生改变。这体现了对浏览器底层渲染机制的深度理解。

## Sticky 定位：基于滚动位置的状态机 *Content-[07:45]

- **状态机机制**：`sticky` 不是单纯的特效，而是一种基于滚动位置的状态机。
  - 未达到阈值时：表现为 `relative` 状态，跟随文档流滚动。
  - 达到阈值时（如 `top: 0`）：在滚动容器内表现为 `fixed` 状态，黏在指定位置。
- **生效与排查条件**（面试中遇到 `sticky` 不生效时的排查思路）：
  1. 必须指定 `top` 或 `bottom` 等阈值属性，否则无法触发状态切换。
  2. 会受到最近滚动容器的限制，不能超出其父级滚动容器的边界。
  3. 不合理的 `overflow` 设置（如父元素设置了 `overflow: hidden`）会导致 `sticky` 失效。

## 课程总结：Position 坐标系统切换逻辑 *Content-[09:24]

- `position` 决定了元素使用哪套坐标系统来计算几何位置：
  - **static**：使用普通文档流坐标系。
  - **relative**：不脱离文档流，并创建新的定位参照系。
  - **absolute**：脱离文档流，寻找最近的定位祖先进行定位。
  - **fixed**：通常相对视口，但可能被 `transform` 等属性改变包含块。
  - **sticky**：基于滚动阈值，在 `relative` 和 `fixed` 状态之间切换。
- **面试核心策略**：用这套“坐标系统切换”的逻辑来回答 `position` 相关问题，能够向面试官展现出你不仅是在背诵 API，而是在深刻理解并讲述浏览器的底层布局机制。
