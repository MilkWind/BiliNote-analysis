## 浏览器开发工具定位错误 *Content-[00:20]
- **考察核心**：在前端开发过程中，针对页面问题如何发现并定位到具体的错误元素，主要考察发现问题和定位问题的能力。
- **控制台 (Console)**：
  - 通过浏览器控制台查看相关的 JS 错误信息。
  - 能够获取错误的具体类型、发生的位置（如行号、列号）等基础信息。
- **元素检查器 (Elements 面板)**：
  - 使用 Elements 面板查看页面的 DOM 结构，找到问题对应的元素。
  - 通过右键点击页面元素选择“检查 (Inspect)”，可以精准定位到对应的 HTML 代码。
- **事件监听器 (Event Listeners)**：
  - 在 Elements 面板中选中对应元素后，可以在 Event Listeners 或 Properties 面板中查看该元素绑定的事件处理函数。
  - 通过追踪这些处理函数，能够找出可能导致事件处理异常的相关代码逻辑。

## 错误监控与全局异常捕获 *Content-[01:41]
- **监控与上报的必要性**：
  - 仅依赖本地控制台只能看到开发者主机的异常，无法获取真实用户环境下的错误信息。
  - 因此，必须进行前端的错误监控与上报，这是面试中的重点考察方向。
- **全局错误捕获 (`window.onerror`)**：
  - 通过监听全局的 `error` 事件来捕获全局的 JS 异常。
  - 回调函数中可以获取到丰富的错误参数：
    - `message`：错误信息。
    - `source`：发生错误的脚本 URL。
    - `lineno` 和 `colno`：错误发生的行号和列号。
    - `error`：具体的 Error 对象。
  - 在回调中收集这些数据后，通过上报逻辑将错误信息发送至服务端。

## Promise 异常捕获 *Content-[03:51]
- **Promise 异常特性**：
  - 如果 Promise 的异常没有被 `.catch()` 捕获，它会一直向外层抛出，最终可能导致未处理异常。
- **捕获机制 (`unhandledrejection`)**：
  - 通过监听 `unhandledrejection` 事件来捕获未被处理的 Promise 异常。
  - 在事件回调中，可以获取到对应的 `promise` 对象及其抛出的异常信息。
  - 收集到这些异常信息后，需要补充 `type` 类型和具体的 `error` 信息进行统一上报。

## React 工程中的 Error Boundary *Content-[05:31]
- **Error Boundary 的作用**：
  - 在 React 工程中，需要在关键节点包裹 Error Boundary（错误边界）。
  - 如果不进行异常捕获，错误会层层向外抛出，最终导致整个应用白屏崩溃。
- **自定义 Error Boundary 实现**：
  - 可以自行编写或引入第三方 NPM 包。自定义实现需继承 `React.Component`。
  - **状态定义**：
    - `hasError`：布尔值，标识是否发生异常。
    - `error`：存储具体的错误对象。
  - **生命周期方法**：
    - `static getDerivedStateFromError(error)`：在渲染阶段捕获错误，用于更新 state（将 `hasError` 设为 `true`，并保存 `error`），从而渲染兜底 UI。
    - `componentDidCatch(error, errorInfo)`：在提交阶段捕获错误，用于获取详细的错误信息和组件堆栈，通常在此处进行异常的日志上报。
  - **Render 渲染逻辑**：
    - 在 `render` 方法中判断 `hasError` 状态。
    - 如果发生异常，返回兜底的 UI 节点（例如提示“出错了”）。
    - 如果正常，则返回正常的子组件节点。
