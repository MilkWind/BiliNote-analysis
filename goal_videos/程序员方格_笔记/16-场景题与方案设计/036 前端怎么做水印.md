## 一、 水印的应用场景与核心需求 *Content-[00:09]

在实际前端开发中，水印常用于保护敏感信息或版权。以下是常见的应用场景及核心需求：

### 1. 常见应用场景
- **企业内部系统**：防止员工截图泄密，水印需显示对应的员工工号和姓名。
- **文档预览**：在 PDF 或图片预览时，添加“仅供预览”等提示水印。
- **图片版权保护**：为设计师或摄影师的作品添加水印，防止被盗用。
- **考试系统**：在试卷页面添加考生个人信息水印，防止作弊或泄题。

### 2. 核心需求
- **全屏覆盖**：水印需要覆盖整个页面。
- **不影响交互**：水印不能阻止用户的正常操作，鼠标事件需要透传。
- **防删除**：即使用户通过开发者工具删除了水印 DOM，也需要能够自动恢复。
- **性能良好**：水印的实现和渲染不能影响页面的整体性能。

## 二、 方案一：CSS 背景图实现 *Content-[01:12]

这是最基础的水印实现方式，主要通过 CSS 样式来完成。

### 1. 实现原理
- 将水印绑定到 `body` 的 `::after` 伪元素上。
- 使用 `position: fixed`（固定定位）覆盖整个页面，并设置最高的 `z-index` 确保在最顶层。
- 设置 `pointer-events: none`，使鼠标事件透传，从而不影响页面的正常交互。
- 使用 `background-repeat: repeat` 将背景图铺满全屏。

### 2. 优缺点分析
- **优点**：实现非常简单，纯 CSS 即可完成；渲染性能较好。
- **缺点**：容易被删除（用户可通过开发者工具直接移除 DOM）；不能动态修改内容（因为背景图片通常是写死的）。
- **适用场景**：适用于对安全性要求不高、内容固定的简单场景。

## 三、 方案二：Canvas 生成水印 *Content-[02:35]

通过 Canvas 绘制水印并转换为图片，可以实现更灵活的水印内容。

### 1. 单行水印实现
- **创建 Canvas**：实例化 Canvas 元素并设置宽高。
- **绘制文字**：获取 2D 上下文（`context`），设置字体大小、颜色、对齐方式等基本样式。
- **旋转画布**：设置画布的旋转角度（如 20 度），旋转点通常设置在画布中点。
- **生成图片**：使用 `fillText` 绘制文字后，将 Canvas 转换为 Base64 格式的图片（`toDataURL`）。
- **渲染到页面**：创建一个 DOM 元素，将生成的 Base64 图片设置为背景图，使用 `repeat` 铺满全屏，采用 `fixed` 定位置于顶层，最后插入 `body` 中。

### 2. 多行水印实现
- **配置多行文本**：增加 `lines` 等属性来配置多行文本内容。
- **动态计算尺寸**：根据文本行数和字体大小，动态计算 Canvas 的宽高以及旋转点位置。
- **循环绘制**：循环遍历多行文本，动态计算每一行的 Y 轴起始点，并依次绘制到 Canvas 上。
- 后续的渲染和铺满全屏逻辑与单行水印保持一致。

## 四、 方案三：防删除水印（MutationObserver + Shadow DOM） *Content-[06:16]

为了解决水印容易被删除或修改的问题，可以结合 DOM 监听和 Shadow DOM 来增强防护。

### 1. 核心机制
- **MutationObserver**：用于监听 DOM 树的变化，当水印节点被删除或属性被修改时，能够立即捕获并作出反应。
- **Shadow DOM**：将水印的样式和结构封装在 Shadow Root 中，增加外部直接修改的难度。

### 2. 实现细节
- **创建与渲染**：创建水印容器 DOM，判断是否已存在。若不存在则创建，并记录该 DOM 的引用。将样式推入 Shadow Root 中。
- **监听 DOM 变化**：使用 `MutationObserver` 订阅 `body` 下的子节点、属性及所有后代节点的变化。
- **处理函数逻辑**：
  - **防删除**：遍历 `removedNodes`，如果发现移除的节点中包含当前的水印 DOM，说明水印被删除，此时立即重新执行 `render` 方法恢复水印。
  - **防修改**：检查水印 DOM 的属性是否被恶意修改，若是，则将其移除并重新 `render`。
- **销毁机制**：在离开页面或执行某些离开操作时，必须取消 `MutationObserver` 的监听并删除对应的 DOM，以防止内存泄漏。

## 五、 方案四：暗水印（不可见水印） *Content-[09:43]

暗水印在视觉上不可见，主要用于图片泄露后的溯源。

### 1. 特点与应用场景
- **不可见性**：不影响图片的视觉效果，用户无法直接察觉。
- **可溯源**：图片被截图或泄露后，可通过专门的解码工具提取出隐藏的数据信息，从而追溯泄露来源。
- **适用场景**：版权保护、机密文件防泄露溯源等。

### 2. 核心代码逻辑
- **编码（添加暗水印）**：
  1. 创建 Canvas 并绘制原图。
  2. 使用 `getImageData` 获取原图的像素数据。
  3. 将需要隐藏的文字转化为二进制数据。
  4. 通过特定的算法对二进制数据进行混淆处理。
  5. 将混淆后的数据混合到原图的像素数据中，最后返回带有暗水印的图片 URL。
- **解码**：
  - 根据编码时使用的算法进行逆向解码。
  - 从像素数据中提取出二进制信息，并将其转换回原始文字。

## 六、 四种方案总结与对比 *Content-[11:28]

| 方案 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **CSS 背景图** | 实现简单，性能好 | 易被删除，不支持动态修改内容 | 简单的静态水印需求 |
| **Canvas 生成** | 内容灵活，支持动态修改 | 依然可以被用户通过开发者工具删除 | 一般场景下的动态水印需求 |
| **防删除版本** | 难以删除和修改，安全性极高 | 持续监听 DOM，性能开销较大 | 重要信息保护、高安全需求场景 |
| **暗水印** | 不可见，不影响视觉，可溯源 | 技术复杂，需要专门的解码工具 | 版权保护、泄露溯源场景 |
