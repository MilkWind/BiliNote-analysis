## 前端静态资源加载失败降级处理概述 *Content-[00:00]

在前端开发中，前端应用上线的核心内容即为前端静态资源。如果在页面加载过程中前端资源出现异常，将会导致各种意想不到的负面结果。因此，如何感知资源加载异常，并在异常发生后对当前资源进行降级处理，是前端稳定性建设中至关重要的一环。

- **核心目的**：通过兜底策略，尽可能减小资源加载失败带来的业务损失，避免页面出现白屏或功能失效。
- **工程素养**：敬畏生产环境，全面考量线上可能遇到的各种异常场景，做好感知与降级处理措施，是前端工程师必备的基本素养。
- **考察重点**：该场景题主要考察候选人对前端系统稳定性的全面考量能力，以及在实际工作中是否真正落地过相关的容灾策略。

## 常见静态资源的降级处理策略 *Content-[01:17]

前端应用中的静态资源主要包括图片、JS 和 CSS。针对不同类型的资源，常见的降级处理方式如下：

- **图片资源降级**：
  - 通过监听图片的 `onerror` 事件来感知加载异常。
  - 当触发 `error` 事件时，将图片的 `src` 替换为默认的占位图（Placeholder），从而避免页面出现破损的图标，保证视觉体验的完整性。

- **JS 和 CSS 资源降级**：
  - 通过动态插入对应的 `<script>` 或 `<link>` 标签来加载资源。
  - 监听标签的 `onerror` 事件，一旦捕获到加载失败：
    - **加载备用资源**：尝试加载备用的相关资源（例如其他 CDN 节点上的资源）。
    - **用户提示**：如果备用资源也无法加载，则提示用户刷新页面。

## CDN 兜底与多源切换策略 *Content-[02:11]

为了进一步提升资源加载的可用性，通常会采用 CDN 兜底和多源切换的高级策略。

- **CDN 兜底机制与监控**：
  - **资源同步**：在页面正常加载时，将当前页面的资源同步保存一份到对应的 CDN 资源库中。
  - **异常兜底**：当页面加载触发 `onerror` 时，主动去拉取兜底的 CDN 资源。这样即使用户访问的源出现问题，也能通过兜底资源保证页面正常渲染，避免出现“空窗”（内容缺失/白屏）效果，提供良好的用户体验。
  - **兜底监控**：必须对兜底行为进行严格的监控。一旦感知到发生了兜底切换，说明主源出现了问题，需要及时触发告警，以便工程师快速定位、排查并修复根本问题。

- **多源兜底（Multi-CDN 策略）**：
  - 针对关键的 JS/CSS 资源，可以配置多个 CDN 源。
  - 当主源失效时，系统自动切换到备用源，通过多源冗余大幅提升核心资源的可用性。

## 全局错误监控与上报 *Content-[03:43]

除了针对特定标签的局部监听，还需要建立全局的错误监控体系，以捕获所有遗漏的资源加载错误。

- **全局错误捕获**：
  - 使用 `window.onerror` 全局错误处理函数。
  - 使用 `window.addEventListener('error', callback, true)` 在捕获阶段监听错误事件（注意：资源加载错误通常不会冒泡，必须在捕获阶段监听）。
- **统一上报**：
  - 将捕获到的资源加载错误信息，结合前端埋点系统（Tracking）进行统一上报，便于后续的数据分析与问题追踪。

## 动态加载脚本与 Error 监听代码实现思路 *Content-[04:41]

针对 JS 脚本的动态加载与降级，具体的代码实现思路如下：

1. **动态创建标签**：通过 `document.createElement('script')` 动态创建 `<script>` 标签。
2. **设置主源地址**：将 `<script>` 标签的 `src` 属性设置为正常的 JS 资源地址。
3. **监听 Error 事件**：为该 `<script>` 标签绑定 `onerror` 事件处理函数。
4. **执行 Fallback 逻辑**：
   - 在 `onerror` 回调中，判断是否存在备用源（Fallback URL）。
   - 如果存在备用源，则将当前 `<script>` 标签的 `src` 替换为备用源的地址。
5. **插入 DOM**：最后，将处理好的 `<script>` 标签插入到页面的 DOM 树中（如 `document.head.appendChild(script)`），完成脚本的加载。

通过上述思路，可以有效实现主脚本加载异常时向备用脚本的平滑切换。
