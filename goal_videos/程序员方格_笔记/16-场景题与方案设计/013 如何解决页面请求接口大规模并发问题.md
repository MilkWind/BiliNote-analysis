## 2. 前端并发控制策略 *Content-[00:55]
- **请求合并**：将同类型的请求合并成一个请求，减少网络请求次数，降低服务器压力。
- **请求队列**：实现请求排队机制，控制同时发起的请求数量，避免瞬间大量请求导致服务崩溃。
- **防抖与节流**：针对频繁触发的请求（如滚动、输入等事件）进行控制，有效降低请求频率。

## 3. 数据缓存策略 *Content-[02:05]
- **前端缓存**：利用浏览器缓存机制（如 `localStorage`、`sessionStorage` 等）缓存用户频繁访问且入参未发生变化的数据，避免重复请求，节省网络消耗。
- **结果缓存**：合理设置 HTTP 缓存头（如 Cache-Control），利用浏览器或代理服务器的缓存机制。
- **CDN 缓存**：利用 CDN 节点缓存静态资源。在 SSR（服务端渲染）场景下，可在 CDN 层进行静态节点缓存，加快 SSR 页面返回速度。

## 4. 服务端优化方案 *Content-[03:20]
- **数据库优化**：添加适当的索引，优化查询语句，提升数据库读写效率。
- **服务端缓存**：使用 Redis 等中间件进行缓存，避免频繁读取数据库，减少 I/O 操作。
- **负载均衡**：使用 Nginx 等工具分发请求，将流量分散到多个服务器，支持更高的并发量。

## 5. 代码实现：请求并发控制 *Content-[04:28]
- **核心逻辑**：通过队列管理请求，限制最大并发数。
- **初始化**：在构造函数中设置最大并发数量（如 `max = 5`），初始化当前运行数量 `running = 0` 和请求队列 `queue = []`。
- **添加请求（add 方法）**：
  - 判断当前正在进行的请求数量（`running`）是否大于等于 `max`。
  - 如果超出限制，将当前请求任务存入队列 `queue` 中。
  - 如果未超出，`running` 加 1，立即发起请求。
- **请求完成处理**：
  - 请求成功或失败后，`running` 减 1。
  - 检查队列 `queue` 中是否还有等待的任务，如果有，则取出并执行。

## 6. 代码实现：请求合并 *Content-[07:57]
- **核心逻辑**：通过唯一的 `key` 和 `Promise` 状态合并相同请求。
- **类设计**：抽取一个请求合并类，包含 `pending` 对象用于存储正在进行的请求。
- **请求方法（request）**：
  - 接收参数 `key` 和实际的请求函数 `fetch`。
  - 检查 `pending` 中是否已存在该 `key`。如果存在，直接返回对应的 `Promise`。
  - 如果不存在，调用 `fetch` 获取 `Promise`，并将其存入 `pending[key]`。
  - 在 `Promise` 完成后，删除 `pending[key]`。
  - 返回该 `Promise`，实现相同 `key` 的请求共享同一个结果。

## 7. 代码实现：前端缓存策略管理 *Content-[10:05]
- **核心逻辑**：使用 `Map` 实现带有过期时间的缓存管理。
- **数据结构**：使用 `Map` 存储数据，同时记录数据的存入时间戳和过期时间（TTL）。
- **set 方法**：
  - 接收 `key`、`value` 和过期时间。
  - 将 `value` 和当前时间戳存入 `Map`。
- **get 方法**：
  - 根据 `key` 从 `Map` 中取出数据。
  - 如果数据不存在，直接返回。
  - 如果存在，计算当前时间与存入时间的差值，判断是否大于过期时间。
  - 如果已过期，则从缓存中删除该数据并返回空；如果未过期，则返回缓存的数据。

## 8. 性能优化建议（网络与代码层） *Content-[12:35]
- **网络层优化**：
  - 使用 HTTP/2 的多路复用特性，减少连接开销。
  - 开启 Gzip 压缩，减小传输体积。
  - 使用 CDN 加速静态资源分发。
- **代码层优化**：
  - 实现请求取消机制（如使用 `AbortController`），避免无效请求。
  - 添加请求重试机制，处理偶发的网络异常。
  - 实现错误重试机制，提升系统容错率。

## 9. 服务端优化建议 *Content-[13:47]
- **多级缓存**：结合本地缓存（如 JVM 内存）和分布式缓存（如 Redis），构建多级缓存架构。
- **合理设置缓存时间**：根据数据的更新频率和业务重要性，设置合理的 TTL。
- **缓存预热**：在系统启动或大促前，提前将热点数据加载到缓存中，避免缓存冷启动导致的数据库压力。
