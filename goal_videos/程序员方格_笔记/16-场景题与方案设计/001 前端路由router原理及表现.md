## 课程大纲与 Vue Router 简介 *Content-[00:29]

Vue Router 是 Vue 全家桶中的核心路由管理工具，在中后台管理系统中，通常会使用它来实现组件之间的页面跳转。本课程重点基于 Vue Router V4 版本进行讲解。

课程主要大纲包含以下几个部分：
- **基础内容**：Vue Router 的相关简介及安装、相关配置以及基本使用。
- **核心功能**：路由模式、动态路由、嵌套路由等基本内容。
- **进阶内容**：Vue Router 的进阶用法。
- **SSR 相关**：SSR（Server-Side Rendering，服务端渲染）的相关概念、是什么以及如何实现 SSR 等内容。

## 路由概念的演变：后端路由与前端路由 *Content-[01:27]

路由的概念最早是由后端（服务端）路由演变而来的。在前后端未拆分的时代，路由主要放在服务端层。

1\. **后端路由**
- **工作原理**：通过切换不同的 URL 向服务端发送请求，服务端接收请求后，拼接好对应的 HTML 完整页面返回给浏览器。
- **优点**：
  - 减轻了前端的压力。
  - SEO（搜索引擎优化）友好。
  - 首屏加载速度快，因为服务端直接返回了已经拼接好数据的完整页面。
- **缺点**：
  - 每次导航都需要重新加载整个新页面。
  - 浏览器不会复用相关资源，整体页面重新加载导致用户体验非常差。

2\. **前端路由**
- **工作原理**：主要应用于 SPA（Single Page Application，单页面应用）。前端会将所有的路径重定向到根页面，通过前端事件劫持路径的变化。当路径发生变化时，触发对应事件，根据当前的 path 和路由表去匹配对应的页面，从而知道应该渲染哪个组件。
- **本质**：前端路由其实就是前端框架（如 Vue.js）处理下的组件之间的切换，通过动态更新页面内容来实现路由效果。

## 前端路由原理与项目选型 *Content-[03:10]

前端路由的出现主要是为了解决后端路由体验差的问题，但它也带来了新的挑战。

1\. **前端路由的优缺点**
- **优点**：
  - 用户体验非常好。
  - 页面切换流畅，因为整体只是前端组件之间的切换，不涉及整个页面的重新加载，切换时效非常短（主要取决于与服务端接口的响应时间）。
- **缺点**：
  - SEO 较差。SPA 工程的典型特征是只有一个 HTML 页面，其中包含一个空的根标签（如 `<div id="app"></div>`），页面内容完全依靠 JS 动态更新。
  - 搜索引擎爬虫在爬取页面时，只能获取到空节点，无法读取到完整的页面结构、描述（description）和关键词，因此不利于 SEO 优化。

2\. **项目技术选型建议**
在进行项目架构选型时，需要根据业务侧重点来决定：
- **侧重 SEO（如官网首页）**：不建议使用纯 SPA，应采用服务端渲染（SSR）等方案来解决 SEO 和首屏体验问题。
- **中后台管理系统**：这类系统通常与 SEO 关系不大，不要求搜索引擎收录，更侧重于用户的整体交互体验。因此，使用 SPA 架构是完全合适且主流的选择。

## 前端路由模式：Hash 模式与 History 模式 *Content-[06:45]

在实现前端路由时，主要有两种常见的路由模式：Hash 模式和 History 模式。

1\. **Hash 模式**
- **工作原理**：URL 中会包含一个 `#`（井号）符号。通过修改 `#` 后面的 path 来改变路由，前端监听 path 的变化进而修改当前的组件内容。
- **特点**：`#` 符号及其后面的内容发生变化时，浏览器不会向服务器发送请求去获取新资源。
- **优点**：兼容性比较好，配置简单，易于使用。
- **缺点**：
  - URL 不美观，带有 `#` 号，不如传统后端路由友好。
  - 依然存在 SPA 的通病，SEO 较差。

2\. **History 模式**
- **工作原理**：利用 HTML5 History API 实现。URL 中没有 `#` 号，采用传统的 path 拼接方式，看起来和后端路由的 URL 一样美观。
- **存在的问题**：
  - 当用户切换 path（例如从 `/home` 切换到 `/about`）后，如果直接刷新页面或向服务器请求该路径，由于使用的是前端路由，服务端并没有对应的物理文件路径。
  - 如果服务器没有进行相关配置，直接请求该路径会返回 404 错误。
- **解决方案**：
  - 需要服务端（如 Nginx）进行配合配置。
  - 在 Nginx 中，可以使用 `try_files` 指令，将根路径下的所有访问请求都重定向（fallback）到 `index.html` 文件。
  - 这样无论访问什么路径，服务器都会返回 `index.html`，然后由 `index.html` 中的前端 JS 逻辑去监听 URL 的变化，并交由前端路由处理组件的渲染。

本视频详细讲解了 Vue Router V4 的核心原理及路由模式。首先对比了后端路由与前端路由的演变，指出后端路由首屏快且 SEO 友好但体验差，而前端路由（SPA）体验流畅但 SEO 较弱，并据此给出了官网用 SSR、中后台用 SPA 的选型建议。接着深入剖析了前端路由的两种主要模式：Hash 模式兼容性好但 URL 不美观；History 模式 URL 美观但需要服务端（如 Nginx）配置 `try_files` 重定向到 `index.html` 以防止刷新时出现 404 错误。内容扎实，是前端面试中关于路由原理的必背知识点。
