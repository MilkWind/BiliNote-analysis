## 1. 使用 Axios 库进行拦截 *Content-[00:20]

这是前端开发中最常规、最基础的拦截方式，主要通过 Axios 提供的拦截器（interceptor）功能来实现。

1\. **请求拦截 (Request Interceptor)**
- 在每次发起请求之前，代码逻辑会先进入拦截器。
- **常见操作**：统一设置请求头（`headers`），例如在每次请求前注入 Token 等认证信息。
- **异常处理**：如果发生异常，可以抛出对应的 `Promise` 进行后续处理。

2\. **响应拦截 (Response Interceptor)**
- 在接收到后端响应后进行处理。
- **正常情况**：如果不做特殊处理，直接返回对应的 `response`；也可以在此对返回的数据结构进行统一的格式化或处理。
- **异常情况**：统一处理异常状态，例如捕获“未登录”或“未授权”等状态码，进行统一的错误提示、Token 刷新或路由跳转。

## 2. 重写全局 Fetch API 实现拦截 *Content-[04:05]

除了基础的 Axios 拦截，面试官通常期望候选人能发散思维。掌握原生 `fetch API` 的拦截是体现能力差异（如区分 P5 与 P6/P7 级别）的重要加分项。

1\. **保存原始 Fetch 方法**
- 首先存储原始的 `window.fetch` 方法（例如 `const originFetch = window.fetch`），以便在重写后仍能调用原生能力。

2\. **重写全局 Fetch**
- 重新定义 `window.fetch`，在内部实现拦截逻辑。
- **请求前处理**：获取传入的 `resource` 和 `config`，通过 `new Headers(config.headers)` 构建新的请求头配置，统一添加 `Authorization` (Token) 等信息。
- **发起请求**：使用 `try...catch` 包裹逻辑，调用之前保存的原始 `originFetch` 发起真实的网络请求。

3\. **响应与异常处理**
- 检查 `response.ok` 状态。如果不 OK，进行统一的错误处理操作。
- 如果请求成功，直接返回当前的 `response`。
- 如果发生异常，在 `catch` 块中打印相关异常信息并 `throw` 抛出，保证错误能被上层捕获。

## 3. 使用 Service Worker (SW) 拦截所有请求 *Content-[08:08]

这是最深挖的一种方式。Service Worker 可以拦截页面中所有的网络请求，包括 AJAX 和 Fetch 资源请求，常用于实现离线缓存和 PWA 应用。

1\. **监听 Fetch 事件**
- 通过 `self.addEventListener('fetch', callback)` 监听当前页面发出的所有网络请求。

2\. **缓存优先策略 (Cache First)**
- 在事件回调中，首先通过 `caches.match(event.request)` 在缓存组（Cache API）中查找是否有匹配的响应。
- 如果匹配到缓存，则直接返回缓存中的响应，无需发起网络请求。

3\. **网络请求与缓存更新**
- 如果缓存中没有匹配项，则调用 `fetch(event.request)` 发起真实的网络请求。
- **检查响应状态**：在回调中检查 `response` 是否为成功态。如果不等于成功态，直接返回该错误响应。
- **克隆响应流**：如果请求成功，**必须使用 `response.clone()` 克隆响应**。核心细节：Fetch 的响应流（Response Stream）只能被读取一次，因此需要克隆一份用于存入缓存，保留原响应用于返回给页面。
- **存入缓存**：将克隆后的响应和原始的 `request` 添加到缓存组中（`cache.put`）。
- **返回结果**：最终返回当前的 `response` 给页面渲染。
