## 具体题目与核心考点 *Content-[02:22]
- **面试题目**：如何自主设计并实现一个 Vue3 的路由系统。
- **核心考点 1：模块设计能力**。考察候选人如何从零开始构思、规划并搭建一个完整的路由模块。

- **应对策略**：此题不仅考察技术储备，还考察过往经验以及临场应变能力。候选人需要掌握核心的设计方向和提示，展现出对底层原理的探索精神。

## 设计思路：接口与数据结构定义 *Content-[04:42]
- **从使用角度反推设计**：在实际使用路由时，开发者需要配置一个“路径与组件一对一映射”的数组。基于此使用习惯，可以反推模块内部的数据结构设计。
- **定义路由记录接口（Route Record）**：
  - 需要定义一个对象类型，包含两个核心属性：
    1. **URL 路径**：例如 `/about`、`/home` 等。
    2. **对应的组件**：该路径所映射的具体 Vue 组件。
- **定义路由配置选项接口（Router Options）**：
  - 由于路由记录是一个数组，因此需要定义一个配置对象接口。
  - 该接口包含一个核心属性，即由上述“路由记录接口”组成的数组。用户在初始化时，只需将包含路由映射关系的数组传入该配置对象即可。

## 设计思路：Router 核心类实现 *Content-[07:36]
- **实现 Router 类**：在实际使用中，开发者调用的是路由类的实例化对象，因此首先需要设计并实现一个 `Router` 类。
- **类的核心属性**：
  - **路由记录数组**：用于接收并保存用户传入的路由配置数据。
  - **当前路由路径（Current Route）**：用于记录当前匹配到的路径及对应的组件状态。
- **构造函数（Constructor）**：
  - 接收用户传入的 `options` 配置对象，并从中提取路由记录数组进行保存。
- **初始化方法（init）**：
  - **首次匹配**：在初始化时，获取当前的 Hash 路径值，并调用内部的匹配方法（match）进行首次路由匹配，确保页面加载时能正确渲染根目录或当前路径的组件。
  - **监听 Hash 变化**：监听浏览器的 `hashchange` 事件。当 URL 中 `#` 后面的哈希值发生改变时，触发事件并再次调用匹配方法，从而实现组件的动态跳转。

## 设计思路：路由匹配核心逻辑 *Content-[09:41]
- **匹配方法（match）的执行流程**：
  1. **获取路径**：获取当前 URL 的 Hash 路径。
  2. **路径清洗**：去除路径开头的 `#` 符号，得到纯净的完整路由路径。
  3. **遍历比对**：遍历用户传入的路由记录数组，将数组中每个对象的路径属性与当前获取的路径进行严格比对。
  4. **匹配成功**：如果在数组中找到了完全一致的路径，则将当前路由的值更新为匹配到的对应组件，完成跳转。
  5. **匹配失败**：如果遍历结束仍未找到匹配项，则提示路径未找到，并返回 404 状态或 404 组件。

## 设计思路：实例化与挂载使用 *Content-[11:13]
- **实例化 Router 类**：
  - 在主程序中，将包含路由记录的 `options` 配置对象作为参数传入，创建 `Router` 类的实例。
- **配置路由数组**：
  - 定义各个路由组件及其对应的路径，组装成配置数组，传入实例化过程中。
- **挂载到 Vue 实例**：
  - 将创建好的 Router 实例挂载到 Vue3 的 App 实例上（例如使用 `app.use(router)`），从而完成整个自定义路由系统的集成与启用。

## 面试回答核心步骤总结 *Content-[13:05]
在面试中回答此类自主设计问题时，清晰地阐述以下核心步骤即可获得高分评价：
1\. **构建接口与参数**：构建“路径对应组件”的接口，并由该接口生成数组，作为用户传入的配置参数。
2\. **获取 Hash 值**：在运行时获取当前 URL 的 Hash 值，并去除 `#` 符号。
3\. **数组匹配**：在用户传入的路由记录数组中，遍历查找与当前 Hash 值匹配的路径对象。
4\. **组件跳转**：获取匹配到的组件并进行渲染跳转，完成路由的核心设置。
- **补充说明**：虽然实际的路由系统还包含嵌套路由、路由守卫等高级功能，但在面试中能够准确、逻辑清晰地描述上述核心基础流程，已经能够充分证明个人的设计能力与底层理解力。
