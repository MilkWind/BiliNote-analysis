## 1. 使用 Axios 库进行请求与响应拦截 *Content-[00:20]

拦截 Web 页面请求是前端开发中的一个常见需求。使用 Axios 库进行拦截是最常规、最基本的一个思路，也是同学们在实际项目中最为常见的一种方式。

- **请求拦截 (Request Interceptor)**
  - **实现方式**：通过 `axios.interceptors.request.use` 配置请求拦截器。
  - **核心逻辑**：在每次请求发起之前，都会先进入当前的拦截器逻辑。
  - **常见应用场景**：在请求发送前统一设置 `headers`（例如添加 Token 等身份认证信息），这是非常高频的业务需求。
  - **异常处理**：如果在拦截过程中出现异常，可以直接抛出对应的 `Promise` 进行错误传递。

- **响应拦截 (Response Interceptor)**
  - **实现方式**：通过 `axios.interceptors.response.use` 配置响应拦截器。
  - **核心逻辑**：如果不需要对数据做特殊处理，可以直接返回对应的 `response`。
  - **常见应用场景**：在拦截器中对返回的响应数据进行统一的结构化处理或提取。
  - **异常处理**：统一处理响应异常，例如拦截 HTTP 状态码，处理未登录、未授权（如 401 状态码）等全局错误情况。

## 2. 使用 Fetch API 重写全局方法实现拦截 *Content-[04:05]

除了使用第三方库，面试官通常希望候选人能够发散思维，思考其他底层实现思路。这也是提升个人能力、体现你与 P5、P6 甚至 P7 级别开发者区别的核心考点。我们可以通过重写全局的 `fetch` 方法来实现拦截。

- **核心思路**
  - 通过“猴子补丁（Monkey Patching）”的思想，存储原始的 `fetch` 方法，然后重写 `window.fetch`，在重写的方法中注入自定义逻辑，最后再调用原始方法。

- **具体实现步骤**
  1. **存储原始 fetch**：首先将原生的 fetch 方法保存下来，例如 `const originFetch = window.fetch`。
  2. **重写 window.fetch**：定义一个新的 `fetch` 函数，接收 `resource`（请求 URL 或 Request 对象）和 `config`（请求配置对象）作为参数。
  3. **请求前处理**：
     - 提取并处理传入的 `resource` 和 `config`。
     - 使用 `new Headers(config.headers)` 创建新的请求头对象。
     - 在请求头中添加自定义字段，例如 `Authorization` (Token)。
  4. **发起真实请求**：使用 `try...catch` 语句包裹，通过 `originFetch(resource, newConfig)` 发起真实的网络请求。
  5. **响应状态处理**：
     - 检查返回的 `response.ok` 属性。如果不为 `true`（即请求失败），则进行统一的错误处理逻辑。
     - 如果请求成功，则直接 `return` 当前的 `response`。
  6. **异常捕获**：在 `catch` 块中打印相关的异常信息，并 `throw` 抛出当前异常，确保错误能够被上层正确捕获。

## 3. 使用 Service Worker (SW) 拦截所有网络请求 *Content-[08:08]

如果需要更深层次的拦截，我们可以使用 Service Worker (SW)。SW 能够拦截页面中所有的网络请求，无论是 Ajax 资源还是 Fetch 资源，都可以通过 SW 执行对应的拦截操作。

- **核心思路**
  - 利用 Service Worker 的生命周期和事件监听机制，拦截网络层的请求，并结合 Cache API 实现缓存优先或网络优先等策略。

- **具体实现步骤**
  1. **监听 fetch 事件**：在 SW 的全局作用域中，通过 `self.addEventListener('fetch', event => { ... })` 监听所有的网络请求事件。
  2. **接管响应**：在事件回调中，使用 `event.respondWith(...)` 来拦截并自定义响应的返回逻辑。
  3. **缓存匹配逻辑**：
     - 打开缓存组（Cache Storage），检查是否存在与 `event.request` 匹配的缓存响应。
     - 如果在缓存中匹配到了响应，则直接返回该缓存响应。
  4. **发起网络请求**：
     - 如果缓存中没有匹配项，则使用 `fetch(event.request)` 向网络发起真实的请求。
  5. **网络响应处理与缓存更新**：
     - 在 fetch 的回调中，检查 `response` 的状态是否为成功态（如 `response.ok`）。
     - 如果不成功，直接返回该异常的 `response`。
     - 如果成功，**必须克隆响应**（使用 `response.clone()`）。因为 Fetch 的响应流（Response Stream）是只能被读取/使用一次的。
     - 将克隆后的响应添加到缓存组中（`cache.put(event.request, clonedResponse)`），以便后续请求使用。
     - 最终返回原始的 `response` 给页面。

## AI 总结

在前端面试中，回答“如何拦截 Web 页面请求”时，建议采用**由浅入深、层层递进**的策略来展现技术深度：
1. **基础方案 (Axios)**：这是最常规的业务实现，通过 Axios 提供的拦截器（Interceptors）统一处理请求头（如 Token）和响应异常（如未授权跳转）。适用于绝大多数基于 Axios 封装的日常项目。
2. **进阶方案 (重写 Fetch API)**：通过重写全局 `window.fetch` 方法，体现了开发者对 JavaScript 原型链、全局对象以及“猴子补丁”思想的理解。适用于原生使用 Fetch 或需要更灵活控制请求生命周期的场景。
3. **高阶方案 (Service Worker)**：这是最底层的网络拦截方式。SW 不仅能拦截所有类型的网络请求，还能结合 Cache API 实现离线缓存、PWA（渐进式 Web 应用）等高级特性。掌握 SW 能够充分证明候选人具备处理复杂网络环境和性能优化的架构能力。
