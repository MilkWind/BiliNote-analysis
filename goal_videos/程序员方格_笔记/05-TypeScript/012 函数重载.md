## 为什么需要函数重载 *Content-[00:43]

在日常开发中，我们致力于编写清晰且易于维护的代码。函数作为代码的基本单元，经常会遇到一种情况：**函数功能统一，但需要处理不同类型或不同数量的参数，并根据输入执行有差异的逻辑**。

### 联合类型的局限性
一个自然的想法是使用联合类型（如 `number | string`），但这存在明显的痛点：
- **无法精确描述对应关系**：联合类型无法精确表达“输入是 `number` 时输出也是 `number`，输入是 `string` 时输出也是 `string`”这种严格的类型约束。
- **降低 API 可读性**：函数签名不够具体，无法体现不同输入方式的内在区别。
- **IDE 提示模糊**：调用者在编辑器中输入函数名时，IDE 只能给出模糊的提示（如“可输入字符串或数字”），无法清晰指导用户。
- **影响类型判断**：在复杂场景下，模糊的归类会影响 TypeScript (TS) 进行精确的类型推断。

### 实际案例：`parseDate` 函数
假设有一个函数，目标是将时间戳（`number`）或日期字符串（`string`）转换为 `Date` 对象。
如果使用联合类型，虽然功能上可以通过 `typeof` 判断并正常工作，但从类型设计角度来看，它把“处理时间戳”和“处理日期字符串”这两种不同的行为模糊地归类成了一种，对调用者极不友好。

## 函数重载的标准结构与使用示例 *Content-[04:20]

为了解决上述问题，TS 提供了**函数重载（Function Overloads）** 机制，允许为同一个函数定义多个不同的、明确的调用签名。

### 标准结构
函数重载主要分为两部分：
1\. **重载签名（Overload Signatures）**：一系列没有函数体的函数声明。每条签名定义了一种合法的调用方式（包含函数名、参数列表和返回类型）。它相当于函数的公开 API 文档，专门给调用者和 IDE 看。
2\. **实现签名（Implementation Signature）**：紧跟在所有重载签名下方，带有完整函数体的强类型声明。包含处理所有情况的实际逻辑。它对外不可见，不能直接调用，且**必须兼容上面所有的重载签名**。

简单来说：**多个签名对外暴露用法，一个实现统一处理逻辑**。

### 代码示例与改造
使用函数重载改造 `parseDate` 函数：

```typescript
// 1. 重载签名（对外暴露）
function parseDate(timestamp: number): Date;
function parseDate(dateString: string): Date;

// 2. 实现签名（内部逻辑，对外不可见）
function parseDate(input: number | string): Date {
    if (typeof input === 'number') {
        return new Date(input); // 处理时间戳
    } else {
        return new Date(input); // 处理日期字符串
    }
}
```

### 调用效果
- 传入 `number`：TS 匹配第一个重载签名，允许调用。
- 传入 `string`：TS 匹配第二个重载签名，允许调用。
- 传入 `boolean`：不匹配任何重载签名，TS 在编译时直接报错。
- **IDE 提示**：智能编辑器会清晰提示该函数有两种不同的签名，建立了明确的输入输出关系。

## 函数重载的核心优势 *Content-[07:27]

1\. **提升 API 可读性**：函数签名像文档一样定义在头部，为开发者提供清晰、多样的调用形式提示。
2\. **精准的类型推断**：在返回类型与输入类型相关的函数中，TS 能够根据传入的参数类型，匹配到对应的重载签名，从而推断出最准确的返回类型。
3\. **提前发现错误**：通过定义严格的调用签名，任何不符合规范的函数调用都会在编译阶段被 TS 捕获，而不是等到运行时才暴露。

## 函数重载的关键规则与最佳实践 *Content-[08:36]

为了正确使用函数重载，必须掌握以下关键规则：

1\. **实现签名对外不可见**：TS 检查函数调用时，只会匹配提供的重载签名。实现签名纯粹用于函数内部的逻辑实现，不能绕过重载签名直接调用真正的实现。
2\. **实现签名必须兼容所有重载签名**：实现签名的参数类型和返回类型必须能够覆盖所有重载签名定义的情况。例如，如果重载分别接收 `number` 和 `string`，实现签名的参数必须是 `number | string`。
3\. **重载签名的顺序非常重要**：TS 在匹配时会**从上到下**依次检查每一个重载签名，并找到**第一个**匹配的签名。

### 最佳实践
**始终将最具体、最精确的签名放在最前面，将比较通用的签名放在最后面。**
- **错误示例**：如果将 `value: string` 放在 `value: 'hello'` 前面，那么传入 `'hello'` 时永远会匹配到 `string` 类型，导致更精确的字面量类型定义永远不会被优先使用。
- **正确做法**：`value: 'hello'` 必须放在 `value: string` 的前面。

## 函数重载与联合类型的适用场景对比 *Content-[10:36]

什么时候使用函数重载？什么时候只用联合类型即可？

- **使用联合类型**：当函数的**返回类型与输入类型之间没有任何关联**时。
  - *示例*：函数接收 `string | number` 类型的 `id`，但永远只返回固定的 `string` 类型。此时简单的联合类型就足够了。
- **使用函数重载**：当函数的**返回类型或核心行为依赖于输入参数的具体类型**时。
  - *示例*：`process` 函数，输入 `number` 返回 `number`，输入 `string` 返回 `string`。此时使用函数重载能更精确地描述它们之间的对应关系。

## 课程总结 *Content-[11:30]

- **概念**：函数重载是为同一个函数名称提供多个不同调用签名的机制，让一个函数有多种调用方法。
- **核心价值**：提升类型安全，特别是能够清晰地定义不同输入类型和不同返回类型之间的对应关系。
- **结构**：对外是多个重载签名，对内是单个实现签名。实现签名必须兼容所有重载，并包含函数的全部逻辑。
- **适用场景**：当函数的返回类型或核心行为依赖于输入参数的具体类型时，应优先考虑使用函数重载。
