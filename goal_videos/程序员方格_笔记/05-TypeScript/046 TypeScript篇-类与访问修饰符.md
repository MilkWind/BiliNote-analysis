## 1. 什么是类 *Content-[00:47]
- **类的概念**：类是创建对象的模板或蓝图，它描述了一类对象共同拥有的状态和行为。在传统的 JavaScript 中，主要通过原型链来模拟面向对象行为，而 TypeScript 的出现为 JavaScript 带来了真正基于类的面向对象编程体系。
- **类的三个主要组成部分**（以 `Player` 类为例）：
  - **Properties（属性）**：定义每个对象所拥有的数据或状态。例如 `user`、`health`、`isOnline` 等变量。
  - **Constructor（构造函数）**：一个特殊的方法，当新对象被创建时会自动调用，主要用于完成对象的初始化工作。例如接收 `userName` 参数，并设置 `health` 和 `isOnline` 的初始值。
  - **Methods（方法）**：定义对象能够执行的操作或行为。例如 `attack`（攻击）和 `disconnect`（断开连接）等方法。

## 2. 类的实例化与核心要点 *Content-[02:10]
- **实例化过程**：定义好类的蓝图后，使用 `new` 关键字加上类名和构造函数所需的参数，即可创建类的具体实例（如 `new Player('Alice')` 和 `new Player('Bob')`）。创建实例后，可通过点语法（`.`）访问对象属性或调用方法。
- **核心要点**：
  - **`new` 关键字**：是创建类实例的唯一方式，这个过程称为实例化。
  - **`constructor` 构造函数**：在 `new` 一个对象时被自动调用，负责接收并处理传入的参数（如 `Alice` 和 `Bob`）。
  - **`this` 关键字**：在类的内部使用 `this` 来引用当前的实例（如 `this.name` 或 `this.isOnline`）。`this` 始终指向正在操作的那个具体对象。

## 3. 访问修饰符简介 *Content-[03:29]
- **封装思想**：有时我们希望类的某些属性或方法不直接被外界访问，仅在类内部使用，这就需要用到封装的思想。
- **三种访问修饰符**：为了实现封装，TypeScript 提供了三种访问修饰符来控制类成员的可见性：
  - **`public`**：完全公开（默认修饰符）。
  - **`private`**：私有。
  - **`protected`**：受保护。

## 4. public 修饰符详解 *Content-[04:40]
- **基本概念**：`public` 代表完全公开，它是默认的修饰符。如果不写任何修饰符，成员默认就是 `public`。
- **可访问范围**：访问范围最广。无论是在类的内部、类的实例外，还是在子类中，都可以自由访问。
- **使用场景**：通常用来定义类对外提供的 API 或者公共数据。
- **代码示例**：在 `Greeter` 类中，使用 `public` 修饰 `message` 属性。创建实例后，可以在类的外部直接使用 `g.message` 进行访问，这是完全允许的。

## 5. private 修饰符详解 *Content-[05:49]
- **基本概念**：`private` 是实现封装的关键，定义非常严格。
- **可访问范围**：只能在声明它的那个类的内部被访问。不管是通过类的实例还是在子类里面，都无法访问到父类的 `private` 成员。
- **使用场景**：非常适合用来隐藏那些不希望外部依赖的实现细节或者内部状态。任何对私有属性的修改，都必须通过类提供的 `public` 方法来进行。
- **代码示例**：在账户类中，将 `balance`（余额）属性声明为 `private`。在类的外部直接调用 `balance` 时，TypeScript 编译器会立刻报错提示其为私有属性；而调用 `public` 的 `deposit`（存款）方法则是允许的。

## 6. protected 修饰符详解 *Content-[07:18]
- **基本概念**：`protected` 的行为介于 `public` 和 `private` 之间，与继承概念紧密相关。
- **可访问范围**：可以在声明它的类以及该类的所有子类中被访问。但是，在类的外部实例中是不可访问的（这一点与 `private` 类似）。
- **使用场景**：当设计一个可被继承的基类时，希望某些成员既不完全公开，又能被子类访问以扩展功能，此时使用 `protected` 是最佳实践。
- **代码示例**：基类 `Animal` 的 `name` 属性被声明为 `protected`。子类 `Dog` 通过 `extends` 继承 `Animal`，在 `Dog` 内部的 `bark` 方法中可以直接访问 `this.name`。但如果创建 `Dog` 的实例 `d`，在外部尝试访问 `d.name` 则是不被允许的。

## 7. 参数属性（语法糖） *Content-[09:08]
- **基本概念**：TypeScript 提供的一种非常有用的语法糖，叫做参数属性（Parameter Properties）。
- **用法与效果**：直接在 `constructor` 的参数前面加上访问修饰符（如 `public`、`private` 等）。这种简写形式可以将属性声明和赋值合二为一，让代码变得非常简洁。
- **代码示例**：在 `Person` 类中，直接写 `constructor(public name: string, public age: number)`。这完全等价于在类里面分别声明 `name` 和 `age` 为 `public`，然后在构造函数里接收同名参数并进行赋值。

## 8. 访问修饰符总结与使用场景 *Content-[10:02]
- **可见性维度总结**：
  - **`public`**：类内部（可见）、子类（可见）、外部实例（可见）。完全可见。
  - **`protected`**：类内部（可见）、子类（可见）、外部实例（不可见）。
  - **`private`**：类内部（可见）、子类（不可见）、外部实例（不可见）。最为严格。
- **最佳实践建议**：
  - 当一个成员需要作为对外的 API 接口，或者需要和外部环境交互时，使用 **`public`**。
  - 当一个成员是类内部的实现细节，不希望任何外部的代码依赖它时，使用 **`private`**。
  - 当正在设计一个基类，并且希望子类能够访问并扩展某些功能，但又不希望这些功能对外部完全开放时，使用 **`protected`**。
