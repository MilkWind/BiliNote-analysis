## TypeScript 的核心转变：从动态到静态 *Content-[00:25]*
- **JS 的动态类型特性**：JavaScript 是一门动态类型语言，这意味着变量在程序运行时的类型是可以随时改变的。例如，一个变量初始为数字，后续可以被赋值成字符串。
- **动态类型的局限性**：这种特性在小型项目中算是一个非常灵活的优势，但在大型项目中，容易引入一些意想不到的运行时错误。
- **TS 的解决方案**：TypeScript 引入了**类型注解（Type Annotation）**，让我们能够明确地告诉编译器这个变量应该是什么类型。
- **核心优势**：将类型的确定从“运行时”提前到了“编译时”。这样一来，编译器可以在我们运行代码之前，就检测出潜在的类型不匹配问题。

## 类型注解的语法与价值 *Content-[01:28]*
- **具体语法**：在变量名（identifier）后面加上一个冒号 `:`，然后跟上我们期望的类型（type）。
- **类型约束**：一旦类型被确定，这个变量就只能被赋予相应类型的值。如果我们试图将一个不兼容类型的值赋给它，TS 的编译器会发现并且发出警告。
- **核心价值**：这种机制的价值在于，它能将大量原本可能在用户浏览器中才会暴露出来的运行时 Bug，提前拦截在开发阶段，从而大幅提升代码质量。

## 基础类型之 string *Content-[03:10]*
- **定义与用途**：`string` 用来表示一切的文本内容，例如文章的标题、用户的姓名等，都可以用 `string` 来表示。
- **语法特性**：在 TS 中，不管使用双引号 `""` 还是单引号 `''`，都能被正确识别为 `string` 类型。
- **实际应用场景**：在项目中应用非常广泛，不管是界面上显示的文本、需要打印的日志，还是 API 返回的文本数据，都离不开 `string` 类型。

## 基础类型之 number *Content-[03:45]*
- **统一定义**：和一些后端语言不同，TS **不区分整数和浮点数**。所有的数字，不管是整数还是小数，都统一使用 `number` 进行类型注解。这让类型定义变得更加简单直接。
- **代码示例**：
  - `version`（浮点数）和 `articleCount`（整数）都正确使用了 `number` 类型。
- **类型检查能力**：如果一个变量被定义为 `number` 并赋值为 `100`，此时若尝试将 `"100k"` 这样的字符串赋值给它，TS 就会报错。
- **核心价值**：有效避免了 JS 中常见的由于隐式类型转换导致的计算问题。

## 基础类型之 boolean *Content-[04:48]*
- **纯粹的值**：`boolean` 类型非常纯粹，逻辑上仅代表“真”和“假”，只有 `true` 和 `false` 两个可能的值。
- **核心用途 1（状态定义）**：用于定义如 `isLoading` 这样的布尔变量，来表示组件的加载状态等。
- **核心用途 2（控制流程）**：是程序控制流程的核心。例如 `if` 语句就是通过 `boolean` 来判断程序走哪一个分支。
- **总结**：布尔值是所有逻辑判断和控制流程的最小单元。

## 课程总结与后续展望 *Content-[05:27]*
- **基础的重要性**：`string`、`number`、`boolean` 这三种原始类型构成了 TS 最基础的单元。无论未来接触多么复杂的数据结构（如 Array、Object、Tuple 等），最终都是由这些基本类型构成的。
- **类型推断的基石**：正是有了这些明确的基本类型定义，TS 才能发挥其强大的类型推断能力和错误检测能力。
- **后续课程预告**：接下来的课程将探讨如何使用这些基础类型来构建更加复杂的数据结构，例如数组和对象，以及如何让它们组合起来创建更强大的自定义对象。
