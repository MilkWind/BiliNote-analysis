## 1. 为什么需要为对象定义类型 *Content-[00:00]

- **原生 JavaScript 的隐患**：
  - 在原生 JS 中，对象非常灵活，可以随时添加或删除属性。
  - 这种动态和松散的结构会带来潜在问题：例如因拼写错误访问不存在的属性导致返回 `undefined`，或者接受了数据结构与预期不符的对象，从而导致程序在运行时崩溃。
- **TypeScript 的解决方案**：
  - TS 允许在对象上加上类型约束，明确定义对象的“形状”（即规定对象应包含哪些属性，以及每个属性的具体类型）。
  - 通过这种方式，TS 能够在代码编译阶段检查出不符合形状定义的操作，提前发现错误。
  - 这确保了传递和使用的每个对象都具备预期的属性和类型，从而大幅提升代码的健壮性和可维护性。

## 2. 基本类型注解（内联类型） *Content-[01:36]

- **类型注解的使用**：
  - 给对象添加类型约束的最基本方式是类型注解。通过冒号 `:` 后紧跟花括号 `{}` 来详细列出对象必须拥有的所有属性及其类型。
  - 示例代码：
    ```typescript
    let user: {
      id: number;
      userName: string;
      email: string;
    };
    ```
- **赋值时的严格约束规则**：
  - **不能缺少属性**：如果类型声明中定义了某个属性（如 `email`），在赋值时缺少该属性，TS 会报错。
  - **不能多出属性**：如果提供了类型定义中没有的额外属性（如 `age`），TS 同样会报错。
  - **类型必须匹配**：任何属性的类型不匹配（例如将 `id` 赋值为字符串），编译均无法通过。
- 以上三点共同确保了 `user` 对象在任何时候都严格符合预期的形状。

## 3. 类型复用：类型别名与接口 *Content-[03:08]

- 内联类型注解虽然直接，但在多处需要相同对象结构时，复制代码不利于复用。TS 提供了两种核心工具来解决此问题：
- **类型别名 (`type`)**：
  - 使用 `type` 关键字创建（如 `type User = { ... }`），之后可直接使用 `User` 来注解对象变量。
  - **特点**：轻量和灵活。除了对象，还可以给任何类型创建别名，例如联合类型 `type ID = string | number`。
- **接口 (`interface`)**：
  - 使用 `interface` 关键字创建。
  - **特点**：可扩展性强。可以通过 `extends` 关键字继承其他接口以实现组合。
  - 同名接口会自动合并，这在编写可扩展的库或模块时非常有用。
- **对比与选择**：
  - 就“定义对象形状”这一任务而言，`type` 和 `interface` 在绝大多数情况下是可以互换的，两者都能很好地完成工作。

## 4. 可选属性 *Content-[04:53]

- **应用场景**：
  - 实际开发中，对象的某些属性可能是非必需的（例如 `id` 是必须的，但 `nickname` 和 `bio` 可能是后来才填写的）。
- **语法与实现**：
  - 在属性名后添加问号 `?` 作为可选属性的标志。
  - 示例代码：
    ```typescript
    type User = {
      id: number;
      nickname?: string;
      bio?: string;
    };
    ```
- **关键技术细节**：
  - 一旦属性被标记为可选，TS 在内部会自动将其类型处理为 `T | undefined`（例如 `nickname` 的实际类型是 `string | undefined`）。
  - **注意事项**：由于该属性的值可能是 `undefined`，在使用它之前必须进行空值检查，以避免运行时错误。

## 5. 只读属性 *Content-[06:11]

- **应用场景**：
  - 某些属性在对象创建和初始化后就不应被修改，最典型的例子是对象的唯一标识符 `id`。
- **语法与实现**：
  - 在属性名前添加 `readonly` 修饰符。
  - 示例代码：
    ```typescript
    type User = {
      readonly id: number;
      userName: string;
    };
    ```
- **效果**：
  - 如果试图重新给 `id` 赋予新值，TS 会抛出错误并阻止该操作。
  - 对于没有 `readonly` 修饰的普通属性，依然可以随时修改其值，这是完全合法的。

## 6. 课程总结 *Content-[07:01]

- **对象类型定义**：TS 的基础功能，通过精确描述对象的形状和属性类型，为代码提供结构化约束，帮助在编译阶段发现潜在问题。
- **可选属性**：允许属性存在或不存在，为数据结构带来必要的灵活性。
- **只读属性**：强化数据的不变性，通过编译阶段禁止对属性的修改，保护那些一旦设置就不能更改的关键数据。
- 掌握以上对象类型定义、可选属性和只读属性，即掌握了 TS 中处理对象数据的核心技巧。
