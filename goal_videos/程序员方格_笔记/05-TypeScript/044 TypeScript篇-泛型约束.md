## 引言：泛型约束的核心概念 *Content-[00:00]
泛型是 TypeScript 的精髓之一，它允许开发者编写处理多种数据类型的组件或函数，同时保证类型检查能力，从而实现代码的可复用性和类型安全性。

然而，不受控制的泛型有时也会带来问题。本次分享的重点是如何使用 `extends` 和 `keyof` 这两个关键字给泛型增加必要的约束，从而编写出灵活、通用且类型安全的代码。

## 泛型的局限性与类型约束的原因 *Content-[00:36]
- **泛型的固有局限性**：当定义一个泛型 `T` 时，实际上是在告诉编译器 `T` 可以是任意类型。正是因为这种“万能性”，编译器在编译阶段无法对 `T` 做出任何具体的假设（例如它可能具有哪些必要的属性或方法）。
- **具体示例分析**：
  - 定义一个函数 `logLength`，接受一个泛型参数 `arg`，并希望打印出 `arg` 的 `length` 属性。
  - 此时编译器会立刻报错，因为编译器不知道传入的 `arg` 是否一定拥有 `length` 属性。
  - 如果传入一个数字 `123`，或者一个没有 `length` 属性的对象，那么 `arg.length` 在运行时就会是 `undefined`。
- **约束的原因**：为了防止这类潜在的运行时错误，TypeScript 在编译阶段就禁止了对未知类型属性的访问。这就是我们需要引入“泛型约束”的原因。

## 使用 `extends` 关键字实现泛型约束 *Content-[02:15]
`extends` 是实现泛型约束最核心的工具。

- **定义约束接口**：首先定义一个名为 `Lengthwise` 的接口，其结构非常简单，只描述了一个契约：任何实现该接口的类型，都必须拥有一个名为 `length` 的属性，且该属性的类型必须是 `number`。
  ```typescript
  interface Lengthwise {
      length: number;
  }
  ```

- **修改函数签名**：修改 `logLength` 函数的签名，将泛型参数改为 `T extends Lengthwise`。
  ```typescript
  function logLength<T extends Lengthwise>(arg: T): void {
      console.log(arg.length);
  }
  ```

- **约束的含义**：
  - 代码 `T extends Lengthwise` 的含义是对泛型做出声明：`T` 不再是任意类型，它必须是符合 `Lengthwise` 接口结构的一种类型。
  - 任何传给 `arg` 的参数，都必须至少包含一个 `length` 属性。
  - 这种方式并没有把 `T` 写死成一个具体的类型，它依然可以是泛型，可以接收字符串、数组等多种类型，但设定了一个明确的、最小化的结构边界。

- **结果**：通过设定结构边界，函数内部就可以安全地访问 `arg.length`，因为 TypeScript 编译器已经确保该属性是存在的。

## 使用 `keyof` 操作符实现高级约束 *Content-[03:56]
在更高级的约束场景中，需要用到 `keyof` 操作符。

- **场景描述**：假设要编写一个函数 `getProperty`，功能是接收一个对象和一个键的名字，然后返回对象上该键名对应的值。如果不使用泛型约束，就无法保证传入的键名是否真的存在于对象上。

- **函数签名实现**：
  ```typescript
  function getProperty<T, K extends keyof T>(obj: T, key: K) {
      return obj[key];
  }
  ```
  - 该签名包含两个泛型参数：`T` 代表传入的对象，`K` 代表传入的键名。

- **`keyof` 的作用**：
  - `keyof T` 会获取 `T` 类型的所有公共属性名，并组成一个字符串字面量的联合类型。
  - 例如，对于 `person` 对象（包含 `name`、`age`、`location` 属性），`keyof typeof person` 的结果就是 `"name" | "age" | "location"`。

- **约束的精确性**：
  - `K extends keyof T` 这个约束要求 `K` 的类型必须是 `keyof T` 这个联合类型中的一员。
  - 换句话说，它强制要求传入的 `key` 参数必须是 `obj` 对象上实际存在的属性名之一。

- **调用示例**：
  - 调用 `getProperty(person, 'name')` 是完全正确的，因为 `'name'` 是 `person` 中的一个键。
  - 当试图传入 `'email'` 时，因为 `'email'` 不存在于 `person` 对象上，调用将不合理并报错。

- **核心价值**：`keyof` 的约束将对象属性的访问从一种可能出现运行时错误的隐患，变成了一种在编译期就能保证类型安全的操作，有效避免了因属性名拼写错误或访问不存在属性而导致的问题。

## 总结：泛型与约束的关系 *Content-[06:36]
- **泛型与约束的关系**：泛型赋予了我们编写通用代码的能力，而约束则为这份通用代码提供了可靠的保障性。
- **`extends` 的核心作用**：定义结构边界。当需要确保一个泛型类型至少拥有某些属性或方法时，就应该使用 `extends`。
- **`keyof` 的核心作用**：专注于实现属性的安全访问。当需要编写函数来动态操作对象属性时，`keyof` 是保证类型安全的关键。
- **更高层次的意义**：泛型约束是 TypeScript 中非常重要的工具，它连接了代码中抽象的部分（泛型）和具体的数据结构，使得开发者能够编写出更加健壮的 TypeScript 代码。
