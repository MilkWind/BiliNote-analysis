## 1. 课程介绍 *Content-[00:01]
- **主题**：TypeScript 中的类与访问控制。
- **背景**：对于类语言的开发者来说，类是一个非常基础且核心的概念。在传统的 JavaScript 中，主要通过原型链去模拟面向对象的行为。而 TypeScript 的出现，为 JavaScript 带来了真正基于类的面向对象编程体系，极大提升了编程体验。
- **目标**：深入了解 TypeScript 是如何定义和使用类的，以及如何通过访问控制修饰符来实现良好的封装。

## 2. 什么是类 (Class) *Content-[00:47]
- **定义**：类是创建对象的模板或蓝图，它描述了一类对象共同拥有的状态和行为。
- **类的组成部分**（以 `Player` 类为例）：
  - **Properties（属性）**：定义每个对象所拥有的数据或状态。例如 `username`、`health`、`isOnline`。
  - **Constructor（构造函数）**：一个特殊的方法，当新对象被创建时会自动调用，主要用于完成对象的初始化工作。它接收参数（如 `username`）并设置其他属性的初始值。
  - **Methods（方法）**：定义对象能够执行的操作（即行为）。例如 `attack` 和 `disconnect`。
- **作用**：通过这种方式，将一个抽象的概念（如 Player）用代码封装起来。

## 3. 类的实例化与核心要点 *Content-[02:08]
- **实例化过程**：定义好类的蓝图后，使用 `new` 关键字加上类名和构造函数所需的参数，即可创建类的具体实例（如 `new Player('Alice')`）。创建后，可通过 `.` 操作符访问属性或调用方法。
- **核心要点**：
  1. **`new` 关键字**：是创建类实例的唯一方式，这个过程称为实例化。
  2. **`constructor` 构造函数**：在 `new` 一个对象时被自动调用，负责接收并处理传入的参数。
  3. **`this` 关键字**：在类的内部，使用 `this` 来引用当前的实例（如 `this.health`、`this.isOnline`）。`this` 始终指向正在操作的那个具体对象。

## 4. 封装与访问修饰符概述 *Content-[03:28]
- **封装思想**：有时我们希望类的某些属性或方法不直接被外界访问，仅在内部使用，这就需要用到封装。
- **访问修饰符**：为了实现封装，TypeScript 提供了三种访问修饰符来控制类成员的可见性：
  - `public`：完全公开。
  - `private`：私有。
  - `protected`：受保护的。

## 5. public 访问修饰符 *Content-[04:40]
- **示例**：在 `Greeter` 类中使用 `public` 修饰 `message` 属性，创建实例后，可以在类的外部通过 `g.message` 自由访问。
- **核心特点**：
  - **默认修饰符**：如果不写任何修饰符，成员默认就是 `public`。
  - **访问范围最广**：在类内部、子类内部以及外部实例中都可以自由访问。
- **使用场景**：通常用来定义一个类对外提供的 API 接口或者公共数据。

## 6. private 访问修饰符 *Content-[05:49]
- **示例**：在账户类中将 `balance`（余额）属性声明为 `private`。外部直接访问 `balance` 时，TypeScript 编译器会立刻报错。对余额的修改必须通过提供的 `public` 方法（如 `deposit`）来进行。
- **核心特点**：
  - **定义严格**：只能在声明它的那个类的内部被访问。
  - **子类不可见**：子类无法访问父类的 `private` 成员。
- **使用场景**：`private` 是实现封装的关键，非常适合用来隐藏那些不希望外部依赖的实现细节或内部状态。

## 7. protected 访问修饰符 *Content-[07:19]
- **示例**：基类 `Animal` 的 `name` 属性被声明为 `protected`。子类 `Dog` 通过 `extends` 继承 `Animal`，在 `Dog` 内部的方法中可以直接通过 `this.name` 访问该属性。但是，如果在类的外部创建 `Dog` 的实例并尝试访问 `name`，则是不被允许的。
- **核心特点**：
  - 行为介于 `public` 和 `private` 之间，与继承概念紧密相关。
  - 可以在声明它的类以及该类的所有子类中被访问。
  - 从外部实例的角度来看，`protected` 成员和 `private` 成员一样，都是不可访问的。
- **使用场景**：当设计一个可被继承的基类时，希望某些成员既不完全公开，又能被子类访问以扩展功能，此时使用 `protected` 是最佳实践。

## 8. 参数属性 (Parameter Properties) 语法糖 *Content-[09:03]
- **语法说明**：TypeScript 提供了一种简写形式，允许直接在 `constructor` 构造函数的参数前面加上访问修饰符（如 `public`）。
- **示例**：
  ```typescript
  class Person {
      constructor(public name: string, public age: number) {}
  }
  ```
- **作用**：这种写法将属性的声明和构造函数中的赋值合二为一，完全等价于在类中分别声明 `name` 和 `age` 为 `public`，然后在构造函数中接收同名参数并赋值。它能让代码变得非常简洁。

## 9. 访问修饰符总结与最佳实践 *Content-[10:02]
- **可见性对比总结**：

| 修饰符 | 类内部访问 | 子类访问 | 外部实例访问 |
| :--- | :---: | :---: | :---: |
| **`public`** | 可见 | 可见 | 可见 |
| **`protected`**| 可见 | 可见 | 不可见 |
| **`private`** | 可见 | 不可见 | 不可见 |

- **最佳实践建议**：
  - **`public`**：当成员需要作为对外的 API 接口，或者需要与外部环境交互时使用。
  - **`private`**：当成员是类内部的实现细节，不希望任何外部代码依赖它时使用。
  - **`protected`**：当正在设计一个基类，并且希望子类能够访问并扩展某些功能，但又不希望这些功能对外部完全开放时使用。
- 合理使用这些修饰符，能够高效地编写出结构清晰、易于维护的前端代码。
