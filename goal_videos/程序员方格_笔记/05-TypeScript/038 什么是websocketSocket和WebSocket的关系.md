## 什么是 WebSocket 及与 HTTP 的对比 *Content-[00:00]

WebSocket 是 HTML5 规范中推出的一种新协议，它是 HTTP 协议的一种补充。虽然两者在某些场景下有交集，但 WebSocket 本质上是一个全新的协议，与 HTTP 基本上没有直接关系。

### HTTP 协议的工作机制
1\. **版本差异与长连接**：HTTP 1.0 和 1.1 的重要区别在于 HTTP 1.1 引入了 `keep-alive` 长连接机制，允许在一条连接上发送多个 HTTP 请求，提高了连接复用率。
2\. **生命周期与一一对应**：HTTP 的生命周期通过 `Request` 来界定。客户端发起一个 `Request`，服务端返回一个 `Response`，两者严格一一对应。即使在 HTTP 1.1 的长连接模式下，发送多个 `Request` 依然是每个 `Request` 对应一个 `Response`。
3\. **被动响应**：HTTP 协议中的 `Response` 是被动的，服务端不能主动向客户端推送信息，必须由客户端发起请求。

## WebSocket 的核心特点与工作原理 *Content-[01:19]

WebSocket 于 2008 年诞生，并在 2011 年成为国际标准，目前所有主流浏览器均已支持。它属于服务端推送技术的一种，最大的突破在于实现了真正的双向通信。

### 全双工通信机制
1\. **双向平等对话**：WebSocket 允许服务端与客户端进行全双工（Full-duplex）通信。服务器可以主动向客户端推送信息，客户端也可以主动向服务端发送信息，打破了 HTTP 只能由客户端发起请求的限制。
2\. **生动比喻**：
   - **HTTP 协议像“发邮件”**：遵循“有发必回”的原则，客户端发送请求（邮件），服务端必须返回响应（回信）。
   - **WebSocket 像“打电话”**：双方可以实时、双向地交流。服务端可以一直说话（推送数据），客户端可以只听不回复，也可以随时插话，沟通更加灵活高效。

## WebSocket 的具体技术特性 *Content-[02:02]

WebSocket 在底层设计和实际应用中具备多项优异的技术特性，使其非常适合需要高频、实时数据交互的场景。

1\. **底层协议与兼容性**：
   - 建立在 TCP 协议之上，与 HTTP 协议有良好的兼容性。
   - 默认端口与 HTTP 相同，为 `80`（非加密）和 `443`（加密）。
2\. **握手阶段**：
   - 握手阶段采用 HTTP 协议，这使得它在建立连接时不容易被防火墙或代理服务器屏蔽，能够顺利穿过各种 HTTP 服务器代理。
3\. **数据与性能**：
   - 数据格式比较轻量，性能开销小，通信效率极高。
   - 支持发送文本数据，也支持发送二进制数据。
4\. **安全与跨域策略**：
   - **无同源策略限制**：这是非常重要的一个特点，WebSocket 客户端可以和任意的服务器进行通信，不受浏览器同源策略的约束。
   - **支持加密**：与 HTTP 和 HTTPS 的关系类似，WebSocket 也有加密版本。以 `ws://` 开头为非加密连接，以 `wss://` 开头则为加密连接。

## 面试考点：Socket 与 WebSocket 的关系 *Content-[03:08]

在面试中（如阿里等大厂的面试），面试官经常会询问 Socket 和 WebSocket 的关系，这通常是一个**面试陷阱**，旨在考察候选人对底层概念的理解是否清晰。

### 概念解析
1\. **Socket 的本质**：
   - Socket 并不是一个具体的协议，而是对 TCP/IP 协议栈的封装和应用（API 接口）。
   - 在软件开发领域（例如在 Node.js 中），Socket 通常表现为一个内置模块（如 `net` 模块），开发者可以通过它来直接操作底层的 TCP 连接。
2\. **两者的关系**：
   - **结论：两者没有任何关系。**
   - **形象比喻**：Socket 和 WebSocket 的关系，就像 **Java** 和 **JavaScript** 的关系一样。虽然名字里都有“Java/Socket”，但本质上是完全不同的东西。
   - **避坑指南**：面试时切勿因为名称相似就认为 WebSocket 是 Socket 的 Web 版本或存在继承关系，必须明确指出它们在概念和层级上是没有直接关联的。
