## 为什么需要为对象定义类型 *Content-[00:00]

- **原生 JS 对象的灵活性与隐患**
  - 在原生 JavaScript (JS) 中，对象非常灵活，允许随时添加或删除属性。
  - 这种动态和松散的结构在某些场景下很方便，但会留下隐患：
    - 拼写错误可能导致访问不存在的属性，从而得到 `undefined`。
    - 接收到数据结构与预期不符的对象，会导致程序在运行时崩溃。
- **TypeScript (TS) 的解决方案**
  - TS 允许在对象上添加**类型约束**，明确定义对象的“形状”（Shape）。
  - 规定对象必须包含哪些属性，以及每个属性的具体类型。
  - **核心优势**：在代码**编译阶段**就能检查出不符合形状定义的操作，提前发现错误，确保传递和使用的每个对象都具备预期的属性和类型，从而提升代码的健壮性和可维护性。

## 对象类型的基本定义：类型注解 *Content-[01:36]

- **内联类型注解**
  - 最基本的方式是在变量声明时直接使用类型注解。
  - **语法**：在变量名后使用冒号 `:`，紧跟花括号 `{}`，在花括号内详细列出对象必须拥有的所有属性及其类型。
  - **示例**：
    ```typescript
    let user: { id: number, username: string, email: string };
    ```
- **严格匹配规则**
  赋值时的对象必须严格遵循定义的结构，TS 会进行以下三点检查：
  1. **不能缺少属性**：如果类型声明中定义了 `email`，赋值时缺少该属性，TS 会报错。
  2. **不能多出属性**：如果提供了类型定义中没有的额外属性（如 `age`），TS 同样会报错。
  3. **类型必须匹配**：如果属性类型不匹配（例如将 `number` 类型的 `id` 赋值为字符串），编译将无法通过。
  - 这三点共同确保了对象在任何时候都严格符合预期的形状。

## 提升复用性：类型别名与接口 *Content-[03:08]

内联类型注解虽然直接，但在多处需要相同对象结构时，复制代码会导致复用性差。为此，TS 提供了两种核心工具：

- **类型别名 (`type`)**
  - **特点**：轻量且灵活。
  - **能力**：不仅可以为对象创建别名，还可以为**任何类型**创建别名。
  - **示例**：可以创建联合类型别名，如 `type ID = string | number;`。
- **接口 (`interface`)**
  - **特点**：具有极强的可扩展性。
  - **能力**：
    - 可以通过 `extends` 关键字继承其他接口，实现结构组合。
    - **同名接口会自动合并**（Declaration Merging），这在编写可扩展的库或模块时非常有用。
- **对比与选择**
  - 在“定义对象形状”这一特定任务上，`type` 和 `interface` 在绝大多数场景下是可以互换的，两者都能出色地完成工作。

## 可选属性 (Optional Properties) *Content-[04:53]

- **应用场景**
  - 实际开发中，对象的某些属性可能是非必需的（例如 `id` 是必填的，但 `nickname` 和 `bio` 可能是后续才填写的）。
- **语法与标志**
  - 在属性名后面添加问号 `?` 作为可选属性的标志。
  - **示例**：`nickname?: string`。
- **底层技术细节**
  - 一旦属性被标记为可选，TS 在内部会自动将其类型处理为 `T | undefined`。
  - 例如，`nickname?: string` 的实际类型是 `string | undefined`。
- **使用注意事项**
  - 由于该属性的值可能是 `undefined`，在代码中实际使用它之前，**必须进行存在性检查**，以避免引发运行时错误。

## 只读属性 (Readonly Properties) *Content-[06:11]

- **应用场景**
  - 对象的某些属性在创建和初始化之后，不希望被修改。最典型的例子是对象的唯一标识符 `id`。
- **语法与标志**
  - 在属性名前添加 `readonly` 前缀修饰符。
  - **示例**：`readonly id: number`。
- **约束效果**
  - 如果试图在初始化后重新给 `readonly` 属性赋新值，TS 会抛出错误并阻止该操作。
  - 没有 `readonly` 修饰的普通属性，依然可以随时合法地修改其值。
- **核心意义**：通过编译阶段的限制，强化数据的不变性，保护关键数据不被意外篡改。

## 课程回顾与总结 *Content-[07:01]

- **对象类型定义**：TS 的基础功能，通过精确描述对象的形状和属性类型，提供强大的结构化约束，帮助在编译阶段发现潜在问题。
- **可选属性**：通过 `?` 允许属性存在或不存在，为数据结构带来必要的灵活性。
- **只读属性**：通过 `readonly` 关键字强化数据不变性，在编译阶段禁止修改，保护核心关键数据。
- 掌握以上三点，即掌握了 TS 中处理对象数据的核心技巧。
