## 1. TS 基础类型概述 *Content-[00:07]
- TypeScript (TS) 的基础用法与 JavaScript (JS) 的基础用法是相互对应的。
- TS 中的数据类型主要分为三大类：
  - **基本数据类型**：如 boolean、number、string、null、undefined 等。
  - **引用类型（对象类型）**：如数组 (Array)、对象等。
  - **特殊类型**：如 any、unknown、void、never 等（这些是 JS 中不存在的 TS 专属类型）。

## 2. 基本数据类型与类型注解 *Content-[01:55]
- **基本类型定义**：
  - `boolean`：用于判断 true 或 false。
  - `number`：用于处理数字类型。
  - `string`：用于处理字符串类型。
- **类型注解语法**：
  - 格式：`let 变量名: 类型 = 初始值;`
  - 示例：`let name: string = "hello";`
- **类型约束与实时检查**：
  - 如果使用 `let` 声明了一个 `number` 类型的变量，后续重新赋值时如果赋为 `string` 类型，编辑器会直接标红报错。
  - 这种严格的类型约束能够在开发阶段（编译器/编辑器中）提供实时的错误提示，并且代码也无法通过编译，从而有效避免运行时错误。

## 3. 数组与元组类型 *Content-[03:28]
- **数组类型 (Array)**：
  - 定义数组有两种常见写法：
    - 普通写法：`let list: number[] = [1, 2, 3];`
    - 泛型写法：`let list: Array<number> = [1, 2, 3];`（`Array` 为 TS 内置泛型类型）。
  - **类型约束**：如果向 `number[]` 类型的数组中 `push` 一个 `string` 类型的数据，编译器会报错。
  - **类型断言**：如果遇到类型识别问题（如将对象识别错误），可以使用类型断言（如 `as Array` 或 `as number`）来强制指定类型。
- **元组类型 (Tuple)**：
  - 这是 TS 中新增的类型，表示**固定数量**和**固定类型**的数组。
  - 普通数组的长度通常是不固定的，而元组要求长度和每个位置的类型都必须严格匹配。
  - 示例：`let x: [string, number] = ["hello", 10];`，第一个元素必须是 string，第二个必须是 number，且长度固定为 2。

## 4. 枚举类型 (Enum) *Content-[06:21]
- **使用场景**：
  - 枚举在实际开发中使用频次很高，常用于处理一个 key 对应多种状态的场景（如 Map 映射、服务端状态码等）。
- **基本用法**：
  - 定义一个枚举后，其成员默认会从 `0` 开始自动递增（例如：Red=0, Green=1, Blue=2）。
  - 可以将枚举成员赋值给变量，如果赋值为非枚举成员的值，编译器会报错，从而保证状态的合法性。

## 5. 特殊类型 (any, void, never 等) *Content-[07:06]
- **`any` (任意类型)**：
  - 可以赋值为任何类型（string、number、boolean 等）。
  - **本质**：相当于关闭了 TS 的类型检查，写起来和 JS 几乎没有区别。
  - **建议**：尽量少用 `any`，否则会导致变量失去静态类型约束，失去使用 TS 的意义。
- **`void` (无返回值)**：
  - 一般用于函数，表示该函数没有任何返回值。
  - 示例：`function warnUser(): void { console.log("..."); }`。如果函数内部 `return 1`，则需要将返回类型改为 `number`。
- **`null` 和 `undefined`**：
  - 作为基本类型进行约束，变量的值只能是对应的 null 或 undefined。
- **`never` (永远没有返回值)**：
  - 用于那些永远不会有返回值的函数。
  - 典型场景：函数内部只有 `throw new Error()` 抛出错误，或者是一个死循环。

## 6. 接口 (Interface) 定义对象形状 *Content-[09:49]
- **核心作用**：用于定义对象的“形状”，即对象所包含的属性和方法。
- **基本用法**：
  - 示例：定义 `Person` 接口，包含 `firstName` (string)、`lastName` (string)、`age` (number) 等属性。
- **属性修饰符**：
  - `readonly`：只读属性。一旦初始化后就不能再被修改（如 `readonly id: number`）。
  - `?`：可选属性。表示该属性在对象中可以不存在（如 `age?: number`）。
- **方法定义**：
  - 可以在接口中定义方法，并约束其参数和返回值类型（如 `greet(): string`）。

## 7. 类型别名 (Type) 与复杂类型组合 *Content-[11:47]
- **核心作用**：类型别名相当于一个“变量”，用于存储一个类型，后续可以直接引用，使代码更简洁。
- **定义方式**：使用 `type` 关键字。
- **常见应用场景**：
  - **复杂类型组合**：如定义坐标 `type Point = { x: number, y: number }`。
  - **联合类型**：表示一个值可以是多种类型之一。例如 `type ID = string | number;`，表示 ID 既可以是 string 也可以是 number。
  - **函数类型**：定义函数的入参和出参。例如 `type Callback = (data: string) => void;`，表示接收一个 string 参数，无返回值。

## 8. Interface 与 Type 的区别及使用场景 *Content-[14:01]
- **Interface (接口)**：
  - **优先场景**：用于定义对象的形式。
  - **面向对象特性**：支持被类实现 (`implements`) 和扩展 (`extends`)。
  - **示例**：定义 `Animal` 基类，`Dog` 类可以通过 `extends` 继承 `Animal` 的属性和方法。
- **Type (类型别名)**：
  - **限制**：不能直接用于类的 `extends` 或 `implements`。
  - **优先场景**：用于联合类型、元组、交叉类型等复杂的类型组合。
  - **交叉类型示例**：使用 `&` 符号。例如 `type Square = Shape & { penWidth: number }`，此时 `Square` 必须同时具备 `Shape` 的所有属性和 `penWidth` 属性，缺一不可，否则编译器会报错提示缺少属性。
