## TypeScript 环境搭建与安装 *Content-[00:00]

在理解了 TypeScript (TS) 的必要性之后，我们需要上手进行 TS 环境的搭建。

- **安装 TypeScript 依赖**：
  - 可以通过**全局安装**（Global）或**局部安装**（Local）的方式来安装 TypeScript 相关的依赖包。
- **验证安装**：
  - 安装完成后，使用命令 `tsc -v` 来验证当前 TypeScript 的安装情况及版本信息。
- **生成配置文件**：
  - TypeScript 具有众多特性，需要配置编译目标、输入输出目录、需要编译的文件范围等。
  - 使用命令 `tsc --init` 可以生成 TypeScript 的核心配置文件 `tsconfig.json`。

## tsconfig.json 配置文件详解 *Content-[01:46]

`tsconfig.json` 是 TypeScript 的核心配置文件。它主要包含 `compilerOptions` 等关键部分，同时我们也可以添加 `include`（指定包含哪些文件）和 `exclude`（指定排除哪些文件）等额外的配置项。

**compilerOptions 重点配置项解析**：

- **target**：指定编译目标的 JavaScript 版本（例如配置为 `ES2016`）。
- **lib**：指定需要引入的内置类型包。例如在操作 `document` 时，需要引入 `DOM` 相关的依赖包，这样 TypeScript 才能正确识别 `document` 中的相关静态类型和 API。
- **jsx**：指定如何处理 JSX 语言（在 React 开发中经常使用）。可配置为 `preserve`、`react` 等方式来进行针对性处理。
- **outDir**：配置编译后的输出目录（例如配置为 `dist`）。
- **rootDir**：配置源文件（输入）的根目录。
- **module**：配置当前项目的模块规范类型。支持 `commonjs`、`esmodule`、`UMD` 等，用于控制模块的导入与导出规范。
- **paths**：用于类型路径映射，简化路径引入方式。例如，配置 `@/*` 匹配 `src/*` 下的路径，后续在引入 `src` 目录下的文件时，直接使用 `@/` 别名即可，无需编写复杂的相对路径。

## package.json 脚本配置与 Node 环境 *Content-[05:41]

完成 `tsconfig.json` 的配置后，我们需要在 `package.json` 中配置相应的脚本命令，以便于日常开发和生产构建。

- **dev 脚本**：
  - 配置为 `tsc --watch`。该命令用于实时监听 TypeScript 文件的变化，当源文件发生修改时，会自动编译并实时更新到 `dist` 输出目录下。
- **build 脚本**：
  - 主要用于生产环境的构建，执行完整的编译过程，生成最终的产物。

**Node 环境下的额外配置**：
- 如果在 Node.js 环境下进行开发，需要安装并引入 `@types/node` 依赖包。
- 引入该依赖后，即可使用其提供的 Node.js 相关静态类型，从而能够顺畅地编写 Node 环境下的 TypeScript 代码。
