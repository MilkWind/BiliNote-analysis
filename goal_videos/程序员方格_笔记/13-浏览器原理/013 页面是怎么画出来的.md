## 页面渲染流水线概述 *Content-[00:00]

浏览器渲染页面并不是写完 HTML 和 CSS 后就“一步到位”画出来的，而是像流水线一样，分阶段将信息加工成最终画面。

- **渲染流水线关键阶段**：
  1\. **Parse（解析）**：生成 DOM 和 CSSOM。
  2\. **Render Tree（渲染树）**：合并 DOM 和 CSSOM。
  3\. **Layout（布局/重排）**：计算盒子的几何信息。
  4\. **Paint（绘制/重绘）**：将边框、背景、文字等画成像素。
  *(注：本节课重点聚焦前三个阶段，即 DOM、CSSOM 和 Render Tree)*

- **形象比喻（做菜模型）**：
  - **HTML** = 食材清单
  - **CSS** = 调味规则
  - **DOM** = 把食材摆到案板上
  - **CSSOM** = 把调味规则整理成一本可以查询的配方书
  - **Render Tree** = 决定最终端上桌的菜是什么（只有能上桌的才会出现在 Render Tree 里）

## 第一棵树：DOM Tree *Content-[01:52]

DOM（Document Object Model）只解决一件事情：**页面里有哪些节点，以及它们是什么关系**。它不关心颜色、大小，也不关心元素是否可见。

- **构建过程**：DOM 的构建来自 HTML 的解析过程。HTML 是边解析边构建树的，因此浏览器往往很早就能够拿到其中的一部分节点。
- **示例解析**：
  - 假设 HTML 代码为：`<body>` -> `<div id="box">` -> `<span>` -> 文本节点 `hello`。
  - 对应的 DOM 树结构为：`document` -> `html` -> `body` -> `div#box` -> `span` -> `hello`（文本节点）。
- **面试强调要点**：
  1\. DOM 是节点关系，不是渲染结果。
  2\. 即使一个元素最终不可见，它也依然会出现在 DOM 树中。
  3\. DOM 的构建来自 HTML 的解析过程。

## 第二棵树：CSSOM *Content-[03:33]

CSSOM（CSS Object Model）不是样式的结果，而是一个**规则系统**。这是很多同学最大的误区，误以为 CSSOM 就是给每个元素算出样式。

- **构建过程**：
  - 浏览器解析 CSS 文件（如 `style.css`）时，不会将其当作纯字符串。
  - 浏览器会将每条 CSS 规则拆分为“选择器 + 声明块”，整理成一套结构化数据，方便后续查询。
- **工作机制**：
  - 当浏览器看到一个元素（如 `div#box`），会去 CSSOM 中查询它命中了哪些规则、哪些声明需要参与计算、哪些会被覆盖。
- **CSS 阻塞渲染的本质**：
  - 没有 CSSOM -> 无法计算元素的最终样式 -> 无法生成 Render Tree -> 无法进入 Layout 和 Paint。
  - 因此，CSS 阻塞渲染是结构性问题，而非单纯的网速问题。
- **形象比喻**：DOM 决定哪些演员在舞台上，而 CSSOM 决定舞台调度和服装的规则。拿不到规则，就无法知道演员要穿什么、站在哪里、灯光怎么打。

## 第三棵树：Render Tree *Content-[05:18]

当浏览器手里有了 DOM（结构）和 CSSOM（规则系统）后，会将 DOM 中需要渲染的节点挑出来，并附上计算后的样式，生成 Render Tree。这是面试的高频考点。

- **核心特征 1：只包含可渲染的节点**
  - `display: none`：该元素在 DOM 中，但**不在** Render Tree 中。因为其语义是“盒子不参与排版与绘制”。
  - `visibility: hidden` 和 `opacity: 0`：这两个元素**在** Render Tree 中。因为它们仍然占位，只是视觉上不可见。
  - **总结口诀**：`display` 决定有没有这个盒子；`visibility` 或 `opacity` 决定盒子能不能画得出来。
- **核心特征 2：每个节点都带着最终的计算样式**
  - 最终样式 = 默认值 + 继承 + 层叠 + 优先级 + 冲突解决。
  - 例如：若 `box` 设置 `font-size: 20`，`div` 设置 `font-size: 16`，最终 `box` 的字体大小是 20（层叠结果）；若未写 `color`，则直接继承父元素；此外还有浏览器的 User Agent Style 默认样式。
  - Render Tree 节点携带的是已经能够直接拿来布局和绘制的样式。
- **核心特征 3：是布局与绘制的输入，但不是最终画面**
  - Render Tree 告诉浏览器要画哪些对象以及它们的样式。
  - 接下来才会发生 Layout（计算几何信息）和 Paint（绘制像素），以及后续的合成和分层。
- **面试总结**：Render Tree 是“可见对象 + 样式计算的集合”，为 Paint 提供绘制参数。

## 综合示例与流程总结 *Content-[08:22]

- **综合示例代码结构**：
  - 包含 `<header>`、`<main>`，在 `main` 中实现一个卡片 `<div id="card">`。
  - `card` 内部包含一个标题（应使用 `<div>` 而非 `<title>`，因为 `<title>` 会作为浏览器 tab 的名字，不是可渲染元素）和一个 `<button>`。
  - 为按钮设置颜色，为 `card` 设置背景、padding 和 border。
  - 额外添加一个 `display: none` 的隐藏元素。
- **渲染流程串联**：
  1. HTML 解析生成 **DOM**（所有节点都在，包括隐藏元素）。
  2. CSS 解析生成 **CSSOM**（规则被组织起来等待匹配）。
  3. 浏览器遍历整个 DOM，将每个节点拿去匹配 CSSOM 进行最终计算，生成 **Render Tree**。
- **全课核心总结**：
  - HTML 解析生成 DOM，CSS 解析生成 CSSOM。
  - DOM 和 CSSOM 合并生成 Render Tree。
  - Render Tree 决定画哪些东西以及以什么样式画，随后才进入 Layout 和 Paint。
  - `display: none` 对性能影响更大，因为它直接从 Render Tree 中移除了节点，减少了布局和绘制的计算量。

## AI 总结

本视频详细解析了前端面试高频问题“页面是怎么画出来的”。核心在于理解浏览器的渲染流水线：HTML 解析生成 DOM（节点关系），CSS 解析生成 CSSOM（样式规则系统），两者结合剔除不可见节点（如 `display: none`）并计算最终样式，生成 Render Tree。Render Tree 作为布局（Layout）和绘制（Paint）的输入，决定了最终页面的呈现。掌握这三棵树的本质区别与联系，尤其是 `display`、`visibility` 和 `opacity` 在渲染树中的不同表现，是应对大厂前端面试的关键。
