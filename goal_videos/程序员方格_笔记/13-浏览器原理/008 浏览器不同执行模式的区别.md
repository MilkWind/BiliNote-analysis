## 面试题引入与核心概念 *Content-[00:00]

在前端面试中，关于浏览器渲染模式的面试题非常高频。浏览器在渲染页面时主要有两种执行模式：**标准模式（Standards Mode）** 和 **怪异模式（Quirks Mode）**。

1\. **核心区别概述**
这两种模式的核心区别在于对 HTML 和 CSS 规范的遵循程度，以及对默认样式和盒模型（Box Model）处理方式的不同。
- **标准模式**：严格遵循 W3C 标准规范。讲师比喻为“穿中山装”，即大家都提倡和遵循的标准规范。
- **怪异模式**：不遵循或打折遵循规范。讲师比喻为“穿牛仔服”，即没有遵循大众标准。

2\. **面试考察重点**
面试官不仅要求知道两种模式的名字，更要求深入理解：
- 浏览器之前是什么模式，现在是什么模式。
- 如何触发这两种模式。
- 两种模式在具体渲染细节（如盒模型、默认样式、布局行为）上的具体差异。

## 触发条件：DOCTYPE 声明 *Content-[04:07]

浏览器决定使用哪种渲染模式，主要取决于 HTML 文档第一行的 `DOCTYPE` 声明。

1\. **触发标准模式**
- 如果在页面第一行正确声明了 HTML5 的文档类型，即 `<!DOCTYPE html>`。
- 浏览器会识别该声明，并严格按照最新的 HTML5 和 W3C 标准来渲染页面。

2\. **触发怪异模式**
- 如果页面缺失 `DOCTYPE` 声明。
- 或者声明了旧版本的文档类型（例如 HTML 4.01 的某些过渡型或怪异型声明）。
- 此时，浏览器会模拟旧版本浏览器（如 IE5）的非标准行为来执行和渲染页面代码。

## 核心区别一：盒模型 (Box Model) 差异 *Content-[05:38]

盒模型用于计算元素的宽度和高度，这是标准模式和怪异模式最显著的差异之一。

1\. **标准模式（W3C 标准盒模型）**
- 指定的 `width` 和 `height` **仅仅代表内容区域（Content）** 的尺寸。
- **不包含**内边距（padding）和边框（border）。
- **总宽度计算公式**：元素总宽度 = `width` + `padding-left` + `padding-right` + `border-left` + `border-right`。

2\. **怪异模式（IE5 传统盒模型）**
- 由于没有遵循 W3C 标准，怪异模式使用的是 IE5 的传统盒模型。
- 指定的 `width` 和 `height` **包含了内容、内边距和边框**。
- 这意味着在怪异模式下，设置的宽度就是元素最终占据的实际总宽度，内容区域会被压缩以容纳 padding 和 border。

## 核心区别二：默认样式差异 *Content-[07:48]

浏览器对 HTML 元素有一套默认的 CSS 样式（如 `margin` 和 `padding`），两种模式下的默认值存在差异。

1\. **标准模式**
- 遵循现代浏览器的标准默认样式。
- 例如，`body` 元素默认的 `margin` 值是 **8px**。这使得页面内容在左上角会有一定的默认留白距离。

2\. **怪异模式**
- 模拟旧版浏览器的默认样式，表现不一致且混乱。
- `body` 的默认 `margin` 可能不是 8px，可能是 **0、3px 或 5px** 等，具体取决于模拟的旧版 IE 浏览器的具体版本。

## 核心区别三：布局和渲染行为差异 *Content-[09:38]

在页面布局、渲染机制以及一些特定元素的表现上，两种模式也有明显不同。

1\. **标准模式**
- **严格遵循 CSS3 规范**：完美支持现代布局特性，如 Flexbox（弹性盒子）和 Grid（网格布局）。
- **垂直边距合并**：相邻的块级元素，其垂直方向的外边距（margin）会发生合并，最终取两者中的最大值。
- **渲染行为成熟**：定位和浮动计算准确。

2\. **怪异模式**
- **垂直边距不合并**：相邻元素的垂直 margin 不会合并，而是直接相加。
- **Table 布局宽松**：对 `<table>` 标签的布局处理限制更少，行为更宽松。
- **定位差异**：对于浮动元素的定位计算可能存在偏差，导致元素看起来不在预期的位置。
- **其他渲染差异**：
  - **字体渲染**：可能使用不同的抗锯齿算法或字体大小计算方式。
  - **表单控件样式**：`input`、`select` 等表单元素的外观会呈现旧版浏览器的复古样式。

## 为什么存在怪异模式 (历史原因) *Content-[12:14]

很多开发者会疑惑，为什么浏览器不直接统一使用标准模式，还要保留怪异模式？

1\. **向后兼容性**
- 在 Web 早期，并没有统一的 W3C 标准，早期的网页代码严重依赖浏览器的非标准行为（即怪异行为）。
- 随着标准的建立，现代浏览器为了能够正常显示这些古老的旧页面，必须引入怪异模式来模拟旧版浏览器的渲染逻辑。

2\. **避免页面完全错乱**
- 怪异模式的存在为开发者提供了便利。如果一个旧页面没有写 `DOCTYPE` 声明，浏览器默认使用怪异模式渲染，可以最大程度保证页面“能看”，而不至于因为强制使用标准模式导致页面布局完全崩溃错乱。

## 总结与使用场景建议 *Content-[13:49]

1\. **触发条件对比**
- **标准模式**：正确编写 `<!DOCTYPE html>`。
- **怪异模式**：缺失 `DOCTYPE` 或编写错误的旧版 `DOCTYPE`。

2\. **核心区别对比**
- **盒模型**：标准模式宽高仅指内容；怪异模式宽高包含 padding 和 border。
- **默认样式**：标准模式 body margin 为 8px；怪异模式不统一（可能为 0 等）。
- **布局兼容性**：标准模式支持 Flexbox/Grid，垂直 margin 合并；怪异模式不支持现代布局，垂直 margin 不合并，table 布局宽松。

3\. **使用场景建议**
- **现代开发**：强烈建议且默认使用**标准模式**，以确保页面符合 W3C 规范，表现一致。
- **怪异模式**：**极不推荐**在现代项目中使用。仅在面对需要维护极旧版本遗留项目，且必须兼容旧版浏览器非标准行为时才会涉及。
