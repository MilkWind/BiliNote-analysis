## 课程引入与核心问题 *Content-[00:23]

本节课围绕 HTML 与 CSS 的高频面试题，探讨一个非常根本的问题：**页面到底是怎么被画出来的？** 这是面试官观察候选人对前端底层理解深度的典型问题。

*   **常见误区**：很多同学只会背诵口诀“DOM + CSSOM = Render Tree”，但面对面试官的追问（如：为什么要分 DOM 和 CSSOM？Render Tree 到底是什么树？`display: none` 为什么不在 Render Tree 而 `visibility: hidden` 还在？）很容易露馅。
*   **渲染流水线比喻（做菜）**：浏览器并不是写完 HTML/CSS 就一步到位画出页面，而是像流水线一样分阶段加工。
    *   **HTML** = 食材清单
    *   **CSS** = 调味规则
    *   **DOM** = 把食材摆到案板上
    *   **CSSOM** = 把调味规则整理成一本可以查询的配方书
    *   **Render Tree** = 决定最终端上桌的菜是什么（只有能上桌的才会出现）
*   **核心流水线词汇**：Parse（解析） -> DOM & CSSOM -> Render Tree -> Layout（布局/重排） -> Paint（绘制/重绘）。本节课重点讲解前三棵树。

## 第一棵树：DOM Tree (文档对象模型) *Content-[01:52]

DOM Tree 的核心定位非常明确：**只解决“页面里有哪些节点，它们是什么关系”**。它不关心颜色、大小，也不关心元素是否可见。

*   **代码示例解析**：
    在 `body` 中写一个 `div#box`，内部包含一个 `span`，文本为 "hello"。浏览器解析 HTML 时，会将其解析为树状结构：`document` -> `html` -> `body` -> `div` -> `span` -> 文本节点 "hello"。
*   **面试强调要点**：
    1\. **DOM 是节点关系，不是渲染结果**。
    2\. 即使一个元素最终不可见，它**依然会出现在 DOM 中**。
    3\. DOM 的构建来自 HTML 的解析过程，HTML 是**边解析边建树**的，因此我们往往很早就能拿到其中的一部分 DOM。

## 第二棵树：CSSOM (CSS对象模型) *Content-[03:33]

CSSOM 的核心定位是：**它不是样式的结果，而是一个规则系统**。这是很多同学最大的误区，误以为 CSSOM 就是给每个元素算好的最终样式。

*   **解析与匹配机制**：
    浏览器不会把 CSS 当作字符串，而是将每条规则拆分为“选择器 + 声明块”，整理成一套结构方便查询。当浏览器看到一个元素（如 `div#box`）时，会去查询它命中了哪些规则、哪些声明需要参与计算、哪些会被覆盖。
*   **CSS 阻塞渲染的本质**：
    没有 CSSOM -> 无法计算元素的最终样式 -> 无法生成 Render Tree -> 无法进入布局和绘制。因此，CSS 阻塞渲染是**结构性问题**，而不是单纯的网速慢问题。
*   **生动比喻**：
    DOM 决定哪些演员在舞台上，而 CSSOM 决定舞台的调度、服装规则和灯光。拿不到规则，就没法知道演员要穿什么、在哪里、灯光怎么打。

## 第三棵树：Render Tree (渲染树) *Content-[05:23]

Render Tree 是面试的高频考点。浏览器手里有了 DOM（结构）和 CSSOM（规则系统）后，会将 DOM 中需要渲染的节点挑出来，并附上计算后的样式，生成 Render Tree。

*   **核心特征 1：只包含可渲染的节点**
    *   `display: none`：语义为该盒子不参与排版与绘制，因此它**在 DOM 中，但不在 Render Tree 中**。
    *   `visibility: hidden`：元素占位还在，只是不可见，因此**依然在 Render Tree 中**。
    *   `opacity: 0`：透明度为 0，仍然占位，**也在 Render Tree 中**。
    *   *总结口诀*：`display` 决定有没有这个盒子，而 `visibility` 或 `opacity` 决定盒子能不能画得出来。
*   **核心特征 2：每个节点都带着最终的计算样式**
    *   这里的“最终”是指：默认值（User Agent Style） + 继承 + 层叠 + 优先级 + 冲突解决 之后的计算结果。
    *   Render Tree 节点携带的是**已经能够直接拿来布局和绘制的样式**。
*   **核心特征 3：是布局与绘制的输入，但不是最终画面**
    *   Render Tree 生成后并没有画好，它只是告诉浏览器要画哪些对象以及它们的样式。
    *   接下来才会发生 **Layout**（计算盒子的几何信息）和 **Paint**（把边框、背景、文字、阴影等画成像素），之后还有合成和分层阶段。
    *   *总结*：Render Tree 是“可见对象 + 样式计算”的集合，为 Paint 提供绘制参数。

## 综合示例与全流程串联 *Content-[08:25]

通过一个具体的页面结构示例，将三棵树串联起来：
*   **结构**：`header` -> `main` -> `div#card`（包含标题 `div.title` 和 `button`，并额外添加一个 `display: none` 的隐藏元素）。
*   *注意*：`title` 标签会作为浏览器 tab 的名字，不是可渲染元素，实际开发中应使用 `div` 等标签代替。
*   **全流程梳理**：
    1.  HTML 被解析生成 **DOM**（所有节点都在，包括隐藏元素）。
    2.  CSS 被解析生成 **CSSOM**（规则被组织起来等待匹配）。
    3.  浏览器进行合并：遍历整个 DOM，把每个节点拿去匹配 CSSOM 进行最终计算。
    4.  生成 **Render Tree**（剔除 `display: none` 的节点，附上计算好的最终样式）。

## 课程总结 *Content-[09:40]

*   HTML 解析生成 DOM。
*   CSS 解析生成 CSSOM。
*   DOM 和 CSSOM 合并生成 Render Tree。
*   Render Tree 决定画哪些东西以及以什么样式画，随后才进入 Layout 和 Paint。
*   `display: none` 对性能影响更大，因为它直接将节点从 Render Tree 中移除了，不参与后续的布局与绘制。

## AI 总结

本节课程深入剖析了浏览器渲染页面的核心前置流程，详细讲解了 DOM、CSSOM 和 Render Tree 这三棵关键“树”的生成机制与区别。DOM 负责构建页面的节点结构关系，CSSOM 负责整理样式规则系统，两者结合并经过计算后生成仅包含可见节点及最终样式的 Render Tree。课程通过生动的比喻和具体的代码示例，厘清了 `display: none`、`visibility: hidden` 和 `opacity: 0` 在渲染树中的不同表现，帮助前端开发者从底层原理上理解页面渲染机制，从而在面试中从容应对关于浏览器渲染原理及性能优化的高频追问。
