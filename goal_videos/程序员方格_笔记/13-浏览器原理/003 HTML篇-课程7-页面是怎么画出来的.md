## 1. 页面渲染流程概述 *Content-[00:23]*

在面试中，“页面到底是怎么被画出来的”是一道观察候选人对前端底层理解深度的典型问题。很多同学会背诵“DOM + CSSOM = Render Tree”的口诀，但面对追问（如为什么要分 DOM 和 CSSOM、`display: none` 与 `visibility: hidden` 的区别）时容易露馅。

浏览器渲染页面并非写完代码后一步到位，而是像**流水线**一样分阶段加工信息。这条流水线的核心阶段包括：
1\. **Parse**：解析 HTML 和 CSS，生成 DOM 和 CSSOM。
2\. **Render Tree**：将 DOM 和 CSSOM 合并生成渲染树。
3\. **Layout (重排)**：计算盒子的几何信息。
4\. **Paint (重绘)**：将盒子绘制成像素。
*(注：本节课重点讲解前三个阶段，重排和重绘将在后续课程展开。)*

**生动比喻（做菜模型）**：
* **HTML** 是食材清单。
* **CSS** 是调味规则。
* **DOM** 是把食材摆到案板上。
* **CSSOM** 是把调味规则整理成一本可查询的配方书。
* **Render Tree** 决定最终端上桌的菜是什么（只有能上桌的才会出现）。

## 2. 第一棵树：DOM Tree *Content-[01:52]*

**核心定位**：DOM Tree 只解决一件事情——**页面里有哪些节点，它们是什么关系**。它不关心颜色、大小，也不关心元素是否可见。

**代码示例**：
```html
<body>
  <div id="box">
    <span>hello</span>
  </div>
</body>
```
浏览器在解析上述 HTML 时，会将其解析为树状结构：`Document` -> `HTML` -> `Body` -> `Div(#box)` -> `Span` -> `Text(hello)`。

**面试强调要点**：
1\. **DOM 是节点关系，不是渲染结果**。
2\. **即使元素最终不可见，它也会出现在 DOM 中**。
3\. **DOM 的构建来自 HTML 的解析过程**，且 HTML 是边解析边建树的（流式处理），因此我们往往很早就能够拿到其中的一部分节点。

## 3. 第二棵树：CSSOM *Content-[03:30]*

**核心定位**：CSSOM 不是样式的最终结果，而是一个**规则系统**。这是很多同学最大的误区，误以为 CSSOM 就是给每个元素算好样式的结果。

**构建与作用机制**：
浏览器不会把 CSS 当作普通字符串，而是将每条规则拆分为“**选择器 + 声明块**”，整理成一套结构体方便后续查询。当浏览器看到一个元素（如 `id="box"` 的 div）时，会去查询它命中了哪些规则、哪些声明参与计算、哪些被覆盖。

**关键结论：CSS 会阻塞渲染**
* 没有 CSSOM -> 无法计算元素的最终样式。
* 没有最终样式 -> 无法生成 Render Tree。
* 没有 Render Tree -> 无法进入 Layout 和 Paint。
因此，CSS 阻塞渲染是**结构性问题**，而非单纯的网速问题。

**生动比喻（舞台模型）**：
DOM 决定哪些演员在舞台上，而 CSSOM 决定舞台的调度、服装和灯光规则。拿不到规则，就不知道演员穿什么、在哪、灯光怎么打。

## 4. 第三棵树：Render Tree (核心高频) *Content-[05:18]*

当浏览器拥有了 DOM（结构）和 CSSOM（规则）后，会将 DOM 中需要渲染的节点挑出来，并附上计算后的样式，生成 **Render Tree**。

**Render Tree 的三个核心特征**：

1\. **只包含可渲染的节点**
* **`display: none`**：语义为盒子不参与排版与绘制。该节点**在 DOM 中，但不在 Render Tree 中**。
* **`visibility: hidden`**：元素占位但不可见。该节点**在 Render Tree 中**。
* **`opacity: 0`**：透明度为 0，依然占位。该节点**在 Render Tree 中**。
* **面试金句**：`display` 决定有没有这个盒子，而 `visibility` 或 `opacity` 决定盒子能不能画得出来。

2\. **每个节点都带着“最终的计算样式”**
* 这里的“最终”是指：**默认值 (User Agent Style) + 继承 + 层叠 + 优先级 + 冲突解决** 之后的计算结果。
* Render Tree 节点携带的是已经能够直接拿来布局和绘制的样式。

3\. **是布局 (Layout) 与绘制 (Paint) 的输入，但不是最终画面**
* Render Tree 生成后并没有画好，它只是告诉浏览器“要画哪些对象以及它们的样式”。
* 随后才会发生 Layout（计算几何信息）和 Paint（将边框、背景、文字等画成像素），以及更靠后的合成与分层。
* **总结**：Render Tree 是“可见对象 + 样式计算”的集合，为 Paint 提供绘制参数。

## 5. 综合示例：三棵树的协同工作 *Content-[08:20]*

通过一个具体的页面结构来串联三棵树的工作流程：
```html
<header>...</header>
<main>
  <div id="card">
    <div class="title">Title</div> <!-- 注意：不要用 <title> 标签，它会作为 tab 名字，不可渲染 -->
    <button>Button</button>
  </div>
  <div class="hidden-element">不想显示的元素</div>
</main>
```
**CSS 设置**：给 button 颜色，给 card 背景、padding、border，给 `.hidden-element` 设置 `display: none`。

**渲染流程**：
1\. **解析 HTML**：生成 DOM Tree，所有节点（包括 header, main, card, hidden-element）都在 DOM 中。
2\. **解析 CSS**：生成 CSSOM，规则被组织起来等待匹配。
3\. **合并生成 Render Tree**：浏览器遍历整个 DOM，将每个节点拿去匹配 CSSOM 进行最终样式计算。在此过程中，`.hidden-element` 因为 `display: none` 被剔除，最终生成 Render Tree，只包含 header, main, card, title, button。

## 6. 课程总结 *Content-[09:40]*

* **HTML** 解析生成 **DOM**。
* **CSS** 解析生成 **CSSOM**。
* **DOM** 和 **CSSOM** 合并生成 **Render Tree**。
* **Render Tree** 决定画哪些东西以及以什么样式画，随后才进入 Layout 和 Paint。
* **`display: none` 影响更大**，正是因为它直接将元素从 Render Tree 中移除了，不仅不渲染，也不占据布局空间。

## AI 总结

本节课深度剖析了浏览器页面渲染的核心原理，重点讲解了 DOM、CSSOM 和 Render Tree 三棵树的生成机制与区别。核心考点在于理解 DOM 仅关注节点结构，CSSOM 作为规则系统会阻塞渲染，而 Render Tree 则是两者结合后剔除不可见元素（如 `display: none`）并计算最终样式的产物。掌握 `display`、`visibility` 和 `opacity` 在 Render Tree 中的不同表现，以及渲染流水线的各个阶段，是应对前端高频面试题和进行前端性能优化的关键基础。
