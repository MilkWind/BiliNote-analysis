## 浏览器的多进程架构 *Content-[00:30]
- **Tab 与进程的映射**：以 Chrome 浏览器为例，每打开一个 Tab 标签页，就会产生一个对应的独立进程。
- **架构演变的原因**：早期的浏览器采用的是单进程架构，但存在明显的弊端——一个页面的崩溃或卡顿会直接导致整个浏览器或其他页面受到影响。为了解决这个问题，浏览器逐渐演进为现在的多进程架构，实现了页面之间的隔离，提升了整体的稳定性和安全性。

## 浏览器的核心进程详解 *Content-[01:23]
浏览器包含多个进程，每个进程各司其职。主进程（Browser 进程）会通过通信方式与其他进程进行连接和调度。主要进程包括：

- **Browser 进程（浏览器主进程）**：全局只有一个。负责浏览器的整体调度、各个页面（Tab）的管理（创建与销毁）、将 Render 进程得到的内存数据绘制到用户界面（UI），以及网络资源的下载与管理。
- **第三方插件进程**：每种类型的插件对应一个独立的进程。仅在使用该插件时才会创建，实现了插件的隔离管理，防止插件崩溃影响浏览器主体。
- **GPU 进程**：全局只有一个。主要负责 3D 绘制等图形加速相关的任务。
- **Render 进程（渲染进程）**：即浏览器的内核。内部包含多个线程，运行着排版引擎（如 Blink）和 JS 引擎（如 V8）。负责将 HTML、CSS、JS 转化为用户可交互的页面，处理页面渲染排版、脚本执行及事件处理。V8 引擎通过 JIT（即时编译）等方式解释脚本，转化为机器码交由 CPU 调度执行。
- **网络进程**：负责页面网络资源的加载与请求处理。

## 渲染进程与页面渲染流程 *Content-[04:52]
渲染进程是浏览器中最核心的进程，主要负责浏览器界面的渲染。其核心工作流程如下：

- **渲染流程**：
  1. 解析 HTML，转化为浏览器认识的节点，生成 DOM Tree（DOM 树）。
  2. 解析 CSS，生成 CSSOM Tree（CSS 规则树）。
  3. 将 DOM Tree 与 CSSOM Tree 结合，生成 Render Tree（渲染树）。
  4. 进行布局（Layout）和绘制（Paint），最终呈现页面。
- **重绘（Repaint）与回流（Reflow）**：
  - **重绘**：当修改元素的颜色、背景色等外观属性，但不影响布局时触发。
  - **回流（重排）**：当修改元素的尺寸、大小等几何属性，导致布局发生变化时触发。
  - **性能优化**：回流和重绘的执行成本较高（尤其是回流），在实际开发中应尽量优化和避免频繁触发。

## 渲染进程中的核心线程机制 *Content-[06:32]
渲染进程内部包含多个线程，其中最核心的是 GUI 渲染线程和 JS 引擎线程。

- **GUI 渲染线程**：负责页面渲染。当需要执行 Repaint 或 Reflow 时，该线程会进行页面绘制操作。
- **JS 引擎线程**：负责 JS 脚本的解析与执行（如 V8 引擎）。处理核心运行机制、事件和任务。
- **互斥机制**：GUI 渲染线程与 JS 引擎线程是互斥的。当 JS 引擎执行时，GUI 渲染线程会被挂起（冻结），UI 更新操作会被保存在一个队列中；等到 JS 引擎空闲时，才会立即执行队列中的 UI 更新。
- **JS 单线程特性**：浏览器同时只有一个 JS 引擎在运行当前的 JS 程序。因此，对于每一个 Tab 页面，无论何时都只有一个 JS 线程在运行 JS 代码，这就是 JS 单线程的本质体现。

## 事件循环（Event Loop）基础 *Content-[08:36]
- **环境差异**：事件循环分为浏览器环境的事件循环和 Node 环境的事件循环，两者存在较大的底层区别，在学习和面试中需要分别理解和看待。
- **同步与异步机制**：JS 任务分为同步任务和异步任务。同步任务会在主线程（即 JS 引擎线程）中执行，并形成执行栈（Execution Stack）。异步任务则由主线程之外的其他模块（如 Web API）进行处理，完成后将回调推入任务队列。
