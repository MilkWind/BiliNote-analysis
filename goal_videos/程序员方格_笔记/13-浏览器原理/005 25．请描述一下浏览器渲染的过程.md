## 浏览器渲染流程概述 *Content-[00:00]
在 Web 前端面试中，浏览器渲染过程是一道极高频的面试题。
- **常见误区**：许多候选人仅回答生成 DOM Tree、CSSOM Tree 和 Render Tree，这种回答缺乏亮点，通常只能拿到基础分数（如 10K 水平）。
- **高分回答策略**：需要系统性、结构化地回答，将渲染过程拆解为 **8 个核心流程**。这 8 个阶段环环相扣，上一阶段的输出即为下一阶段的输入，形成一套组织严密的“生产流水线”。
- **八大流程概览**：HTML 解析、样式计算、布局、分层、绘制、分块、光栅化、合成。

## 1. 解析 HTML 与 CSS 生成 DOM 树和 CSSOM 树 *Content-[01:45]
渲染的第一步是解析文档，生成两棵核心的树结构：
- **DOM 树 (DOM Tree)**：解析 HTML 文档时，遇到 HTML 元素即生成 DOM 节点，最终构成 DOM 树。
- **CSSOM 树 (CSSOM Tree)**：解析 `<style>` 标签、`<link>` 元素、行内样式等 CSS 样式时，生成 CSSOM 树。浏览器的默认样式、内部样式、外部样式和行内样式均包含其中。

**关键阻塞机制：**
- **CSS 不阻塞 HTML 解析**：加载和解析 CSS 的工作是在**预解析线程**中进行的。当主线程解析到 `<link>` 标签时，即使外部 CSS 文件未下载完成，主线程也不会等待，而是继续解析后续 HTML。
- **JS 会阻塞 HTML 解析**：当主线程解析到 `<script>` 标签时，会暂停 HTML 解析，等待 JS 文件下载并执行完毕。根本原因是 JS 代码在执行过程中可能会修改当前的 DOM 结构，因此 DOM 树的生成必须暂停。

## 2. 样式计算 (Style Calculation) *Content-[03:51]
生成 DOM 树和 CSSOM 树后，进入样式计算阶段：
- **计算过程**：主线程遍历 DOM 树，依次为树中的每个节点计算出最终样式，称为 **Computed Style**。
- **单位与值转换**：在此过程中，许多预设值或相对值会被转换为绝对值。例如，颜色关键字 `red` 会转换为 RGB 格式或 16 进制表示；相对单位（如 `em`、`rem`）会转换为绝对单位（如 `px`）。
- **阶段输出**：完成样式计算后，得到一棵带有完整样式的 DOM 树。

## 3. 布局 (Layout) *Content-[04:52]
样式计算完成后，进入布局阶段：
- **计算过程**：布局线程依次遍历 DOM 树的每一个节点，计算每个节点的几何信息。
- **几何信息包含**：节点的宽度、高度以及在页面中的具体位置（坐标）。
- **阶段输出**：布局计算完成后，生成**布局树 (Layout Tree)**。

## 4. 分层 (Layer) *Content-[05:28]
得到布局树后，主线程会对页面进行分层处理：
- **分层策略**：主线程使用一套复杂的策略对整个布局树进行分层，生成多个图层 (Layer)。CSS 本质上是“层叠样式表”，浏览器渲染画面实际上是一层层堆叠上去的。
- **分层目的**：提升渲染效率。当某一个图层发生改变时，仅需对该层进行后续处理，而不需要重新渲染整个页面。
- **影响分层的因素**：滚动条、堆叠上下文、`transform`、`opacity` 等样式，以及 `will-change` 属性，都会不同程度地影响分层结果。

## 5. 绘制 (Paint) *Content-[06:00]
分层完成后，进入绘制阶段：
- **生成指令**：主线程会为每一个图层单独产生**绘制指令集**，用于详细描述这一层的内容该如何画出来。
- **线程交接（核心重点）**：完成绘制后，主线程会将每个图层的绘制信息提交给**合成线程 (Compositor Thread)**。
- **阶段意义**：到此为止，浏览器**渲染主线程**的工作基本完成，剩下的工作将全部交由合成线程处理。这也是浏览器采用多线程模型优化性能的关键设计。

## 6. 分块 (Tiling) 与光栅化 (Rasterize) *Content-[07:00]
合成线程接手后，主要进行分块和光栅化两项工作：

**分块 (Tiling)：**
- 合成线程首先会对每个图层进行分块，将其划分为更小的区域（类似于切蛋糕）。
- **目的**：将大块任务拆解，以便后续交给多个线程并行处理，提高处理速度。

**光栅化 (Rasterize)：**
- 合成线程将分块后的信息交给 **GPU 进程**，由 GPU 开启多个线程以极高的速度完成光栅化。GPU 专门用于图像处理，速度远超 CPU。
- **光栅化原理**：将画面划分为无数个微小格子（像素）。在 GPU 中，图形由顶点 (Vertex) 构成，但仅有顶点无法显示。光栅化的核心任务是：
  1. 确定图形的顶点信息。
  2. 确定构成该图形的所有**像素信息**（如具体的颜色填充）。
  3. 结合顶点与像素信息，将矢量图形转化为屏幕可显示的位图图像。

## 7. 合成与显示 (Composite & Draw) *Content-[10:45]
光栅化完成后，进入最终的合成与显示阶段：
- **合成显示**：GPU 将光栅化后的所有图层像素信息进行合成，最终渲染到屏幕上，呈现给用户看到的完整页面。
- **性能优化启示 (Transform 的优势)**：
  - 为什么在 CSS3 动画中强烈推荐性能使用 `transform`？
  - **本质原因**：`transform` 引起的变形和动画直接发生在**合成线程**，与**渲染主线程**完全无关。它不需要重新触发主线程的布局、绘制等耗时操作，因此执行效率极高，能显著提升页面动画性能。

## AI 总结
浏览器渲染过程是一个高度协同的多线程流水线作业。从主线程解析 HTML/CSS 生成 DOM 和 CSSOM 树，到计算样式、布局、分层和绘制，再到合成线程接管进行分块、光栅化和最终合成显示。理解这 8 个核心步骤，不仅能帮助在面试中脱颖而出，更能深刻理解前端性能优化的底层逻辑（如利用 `transform` 和 `will-change` 触发 GPU 加速，避免主线程阻塞），从而在实际开发中写出更高效、更流畅的 Web 应用。
