## 1. 早期前端 JS 引入方式的痛点 *Content-[00:01]
- **传统引入方式的局限性**：
  - 早期前端页面依赖的 JS 不像 Node.js 拥有 `require`（CommonJS 模块）来进行模块化引入。
  - 所有的 JS 文件必须依赖 HTML 文件的 `<script>` 标签引入才能执行，且对引入顺序有严格要求。
- **工具方法管理的痛点**：
  - 当项目中存在大量工具方法（如手机号正则验证、密码验证、随机数生成、获取定位等）时，通常会将它们统一放在一个文件（如 `tools.js`）中。
  - 如果多个页面或多个 JS 文件都需要使用这些工具方法，就必须依赖 HTML 进行全局引入。
  - 涉及多个页面时，相互引入会变得非常繁琐，极易导致引入顺序混乱或重复引入。
- **核心诉求**：
  - 迫切需要实现 JS 引入 JS，做到按需引入，不再强依赖 HTML 的全局 `<script>` 标签。

## 2. ES6 模块化概念与严格模式 *Content-[06:41]
- **ES6 模块化推出**：
  - 为解决上述痛点，ES6 正式推出了模块化概念，核心语法为 `export`、`export default`、`import` 和 `import from`。
- **自动开启严格模式**：
  - ES6 的模块自动采用严格模式（Strict Mode），无论是否在模块头部加上 `"use strict"`。
  - 一旦当前 JS 使用了 `export` 或 `export default` 作为模块对外暴露，即自动开启严格模式。
  - **严格模式的主要限制**：
    - 变量必须声明后再使用。
    - 函数的参数不能有同名属性，否则报错。
    - 不能对外暴露只读属性名，否则报错。
    - 不能使用带前缀 `0` 的八进制，否则报错。
    - 不能删除不可删除的属性。

## 3. export 与 import 的基本使用 *Content-[08:45]
- **export 的使用规则**：
  - 用于对外暴露指定内容供其他模块使用。
  - 可以暴露的内容包括：函数、类（`class`）、以及由 `var`、`let`、`const` 声明的变量。
  - **重要细节**：`export` 后面必须是一个**声明语句**（即包含创建变量或对象的语句），而不能仅仅是一个变量名。
    - 错误示例：`let str = 'hello'; export str;`
    - 正确示例：`export let str = 'hello';`
- **import 的使用规则**：
  - 用于引入其他模块暴露的数据。
  - **最佳实践**：引入模块数据的语句应尽量写在代码的第一行，类似于书籍的目录，方便阅读和了解当前文件依赖了哪些模块。
  - 基本语法：`import { str1 } from './1.js'`。
  - 注意：引入时必须加上大括号 `{}` 进行解构赋值，因为这是按需引入（非默认导出）。

## 4. 模块化运行的环境要求与路径配置 *Content-[14:06]
- **环境要求**：
  - **报错提示**：`cannot use import statement outside a module`，表示不能在非模块化环境下使用模块化语句。
  - **HTML 配置**：在 HTML 引入 JS 的 `<script>` 标签上，必须添加 `type="module"` 属性，表明其处于模块化环境。
  - **服务器环境**：ES6 模块化涉及路径查找，不能直接通过本地文件路径（`file://`）打开，必须处于服务器环境下运行（类似于 Cookie 的测试）。
  - **本地测试方案**：在 VS Code 插件中心安装 `Live Server` 插件，右键选择 "Open with Live Server"，通过 `http://127.0.0.1:5500` 等本地服务器地址访问。
- **路径配置**：
  - 引入模块时，路径必须以 `/`（根目录）、`./`（当前目录）或 `../`（上一级目录）开头。
  - 示例：`import { str1 } from './1.js'`。如果不写 `./` 会报错找不到模块。

## 5. 按需引入的细节与多变量引入 *Content-[16:47]
- **按需引入原则**：
  - 使用 `import { 变量名 } from '路径'` 时，大括号内的变量名必须与模块对外暴露的名字完全一致。
  - 一个模块可以对外暴露多个变量，引入时必须明确指定需要的变量名。
  - **形象比喻**：就像去肯德基或麦当劳点餐，不能只说“给我来份肯德基”，必须明确点具体的菜品（如原味鸡、香辣鸡腿堡）。引入模块前，必须先阅读 API 了解其暴露了哪些内容。
- **引入多个变量**：
  - 如果模块暴露了多个方法（如 `checkMobile` 和 `random`），可以在大括号内同时引入，用逗号隔开。
  - 示例：`import { checkMobile, random } from './tools.js'`。

## 6. 多文件引入同一模块与实战纠错 *Content-[19:44]
- **实战代码纠错**：
  - 在调用引入的 `checkMobile` 和 `random` 方法时，发现运行报错，需进行以下修复：
  - **正则表达式修复**：手机号验证正则缺少边界符，正确写法应为 `/^1[3-9]\d{9}$/`（`^` 表示开头，`$` 表示结尾）。
  - **随机数公式修复**：生成 $N$ 到 $M$ 的随机数公式为 $Math.floor(Math.random() \times (M - N + 1)) + N$，注意 `Math` 对象的方法调用及括号匹配。
- **多文件引入与执行**：
  - 如果 `2.js` 也需要使用 `tools.js` 中的方法，并且 `2.js` 内部包含具体的执行代码（如 `console.log`），那么 `2.js` 就不再是一个单纯的“仅暴露数据”的模块。
  - 此时，`2.js` 也需要在 HTML 中通过 `<script type="module" src="./2.js"></script>` 进行引入和执行。
  - **结论**：无论是作为纯模块暴露数据，还是包含执行逻辑，只要使用了 ES6 模块化语法，都需要在 HTML 中配置 `type="module"` 并确保在服务器环境下运行。
