## 1. Vue 2 中在组件内使用环境变量 *Content-[00:00]

在配置好环境变量后，最核心且面试最常考的操作就是**在组件中使用环境变量**。面试官通常会要求手写或在项目中演示这部分代码。

- **在 data 中定义变量**：
  在 Vue 2 组件的 `data` 函数中，定义需要使用的变量，例如 `baseAPI`（接口前缀）、`projectName`（项目名称）和 `env`（环境标识）。
- **读取环境变量**：
  通过 `process.env.VUE_APP_XXX` 的方式读取 `.env` 文件中配置的环境变量，并赋值给 `data` 中定义的变量。
- **在模板中渲染**：
  在 `<template>` 中，使用双大括号 `{{ }}` 将 `projectName`、`env` 和 `baseAPI` 渲染到页面上（如 `H1` 和 `P` 标签中）。
  *注意：在模板中绑定变量时，务必确保语法正确，使用大括号包裹变量名。*

## 2. Vue 2 中在方法中使用环境变量及 Axios 配置 *Content-[03:05]

除了数据渲染，更常见的场景是在业务方法（如请求接口）中使用环境变量。

- **在 methods 中拼接接口地址**：
  定义一个方法（如 `getUserData`），在方法内部通过 `this.baseAPI` 获取接口前缀，并拼接具体的接口路径（如 `/user`），从而完成请求地址的组装。
- **Axios 全局配置优化**：
  在实际项目中，不需要在每个请求里都手动拼接前缀。
  **最佳实践**：直接将 Axios 配置对象中的 `baseURL` 属性替换为环境变量（如 `process.env.VUE_APP_BASE_API`）。这样在切换不同环境时，接口前缀会自动切换，大大简化了代码逻辑。

## 3. 环境变量切换与热更新测试 *Content-[05:25]

为了验证环境变量是否生效，可以通过执行不同的 npm 脚本来切换环境。

- **切换环境**：
  将启动命令从开发环境的 `npm run dev` 切换为测试环境的 `npm run test`。
- **验证结果**：
  刷新页面后，可以看到接口前缀自动从 `localhost:8080` 变为了 `test` 开头的测试环境地址。这证明了环境变量在组件和 Axios 配置中已经成功生效并实现了动态切换。

## 4. Vue 3 中在组件与方法中使用环境变量 *Content-[06:05]

Vue 3（通常结合 Vite 构建工具）在组件中使用环境变量的核心逻辑与 Vue 2 相同，但由于 Composition API 的引入，语法上存在一定差异。

- **语法差异**：
  在 Vue 3 的 `<script setup>` 或 `setup` 函数中，**不再使用 `this`** 来访问组件实例。
- **读取与使用**：
  - 读取环境变量通常使用 `import.meta.env.VITE_XXX`（Vite 默认前缀）。
  - 定义方法时直接使用箭头函数或普通函数，在函数内部直接引用定义好的环境变量常量，无需通过 `this` 中转。
- **环境切换测试**：
  同样执行 `npm run test` 切换到测试环境，验证 Vue 3 项目中的接口前缀也能正确自动更新为测试环境地址。

## 5. 环境变量使用注意事项与总结 *Content-[07:56]

在组件中使用环境变量时，必须牢记以下核心规范和注意事项，这也是面试中的高频考点：

- **命名前缀规范**：
  环境变量**必须**以特定前缀开头，否则无法在组件中获取。
  - Vue 2 (Vue CLI)：必须以 `VUE_APP_` 开头（如 `VUE_APP_BASE_API`）。
  - Vue 3 (Vite)：必须以 `VITE_` 开头。
  *注意：大小写和下划线必须严格匹配，写错或漏掉前缀将导致读取失败。*
- **重启项目生效**：
  环境变量修改后，**必须重启项目**才能使修改生效。
  - Vue CLI 环境下必须重启。
  - Vite 环境下部分版本支持热更新，但为了保证配置的安全性和一致性，**建议统一执行重启操作**。
- **安全性与敏感信息**：
  生产环境中，前端的环境变量会被直接打包到静态代码中，任何人都可以在浏览器中查看。
  - **严禁**将敏感信息（如数据库密码、第三方 API 密钥等）直接写在环境变量中。
  - 敏感信息应通过后端接口进行获取和管理。
- **保持配置简洁**：
  不要在环境变量中存储过多的内容。只存储必要的配置项，如**接口地址**、**环境标识**等，以保持项目配置的清晰和简洁。
