## 2. 缓存机制的核心意义与思路 *Content-[01:07]
### 核心目标
- **避免重复计算**，提高函数的执行性能。
- 在复杂应用中，很多函数会被相同的参数反复调用。如果没有缓存，每次调用都会消耗计算资源；有了缓存，除第一次外，后续调用均可省略计算过程。

### 核心思路
- 将**输入的参数作为键（Key）**，**计算结果作为值（Value）** 存储起来。
- 当函数再次被调用时，先检查当前输入参数是否已有之前计算过的结果：
  - 如果**有**，则直接返回存储的结果。
  - 如果**没有**，则执行计算，并将新结果存入缓存，供下次使用。

### 广泛应用
- 该机制在 Lodash 中应用非常广泛，不仅限于 `memoize` 函数。
- 许多处理集合、数组的函数为了优化性能，内部都内置了类似的缓存逻辑。

## 3. memoize 函数解析与斐波那契案例 *Content-[03:11]
### memoize 函数核心步骤
`memoize` 是一个高阶函数，用于将普通函数转换成带缓存能力的记忆化函数。其代码实现分为三个核心步骤：
1. **创建缓存（cache）**：执行时创建一个 `memoized` 函数，并在其上附加一个 `cache` 属性，初始值为空对象，用于独立存储每个被记忆化函数的缓存结果。
2. **生成 Key**：调用时生成唯一的 key。默认情况下，直接使用函数的**第一个参数**作为 key。Lodash 也提供可选的 `hasher` 函数来自定义生成键的逻辑。
3. **存取结果**：检查 `cache` 对象中是否存在该 key。
   - 若**不存在**，执行原始函数 `func`，并将计算结果缓存到 `cache` 中。
   - 若**已存在**，直接跳过计算，返回 `cache` 中存储的值。

### 经典案例：斐波那契数列
- **原始递归实现的问题**：包含大量重复计算（如计算 5 需要计算 4 和 3，计算 4 又需要计算 3 和 2，导致 3 被重复计算）。数列长度增大时，计算量呈指数级增长。
- **使用 memoize 优化**：
  - 用 `memoize` 封装原始斐波那契函数，生成带缓存功能的函数。
  - 第一次调用（如 `fib(10)`）时，从 10 开始递归，将 2、3 到 10 的结果全部存入缓存。
  - 第二次调用时，`memoize` 机制生效，发现参数 10 的结果已在缓存中，直接返回结果（55），完全跳过递归计算。
  - 第二次及之后的调用均为毫秒级，性能提升巨大。

## 4. Lodash 内部的四种缓存数据结构 *Content-[07:44]
为了在各种场景下达到最优性能，Lodash 设计了多种不同的缓存数据结构，远比普通的 JS 对象复杂：

1. **ListCache**
   - **实现**：内部是一个数组，每个元素是包含 `key` 和 `value` 的键值对。
   - **优点**：结构简单，内存开销极小。
   - **缺点**：查找时需要线性遍历。
   - **适用场景**：仅适用于存储少量数据的场景。

2. **HashCache (HashMap)**
   - **实现**：对原生 JavaScript 对象的封装。
   - **特点**：当 key 是字符串时，对象的哈希读写性能非常高。
   - **适用场景**：当 Lodash 确定 key 的类型为字符串时，优先使用此结构。

3. **MapCache**
   - **实现**：一种混合结构。
   - **特点**：会根据存入的数据规模，动态在 `ListCache`、`HashCache` 或 ES6 的 `Map` 中进行切换，以达到性能平衡（下文详细解析）。

4. **StackCache**
   - **用途**：比较特殊，主要用于**深度比较**或**深度克隆**时。
   - **作用**：存储已经访问过的对象引用，防止因循环引用而导致无限递归的问题。

## 5. MapCache 的工作原理与动态切换机制 *Content-[10:03]
`MapCache` 本身不直接存储数据，而是作为一个**调度中心**，根据数据规模将数据委托给三种底层结构（`ListCache`、`HashCache`、原生 `Map`）。

### 决策流程与阈值
- Lodash 内部定义了一个常量 `LARGE_ARRAY_SIZE`（假定阈值为 200）。
- **数据量 < 200**：
  - 使用 `ListCache`。因为数据量小，线性查找开销不大，且 `ListCache` 实现更轻量，不会有不必要的开销。
- **数据量 >= 200**：
  - `MapCache` 执行一次**升级**，将 `ListCache` 中的所有数据迁移到更高效的结构中。
  - **环境支持 ES6 Map**：优先使用原生 `Map`，因为它支持任何类型的键。
  - **老环境不支持 Map**：回退到 `HashCache`（哈希结构）。

### 工程智慧
- 这种动态匹配机制使得函数在处理小规模数据时保持轻量，在处理大规模数据时自动切换到高性能模式，是极佳的工程实践。

## 6. 自定义缓存 Key：解决对象引用问题 *Content-[12:09]
### 默认行为的局限性
- `memoize` 默认使用函数的第一个参数作为缓存 key。
- 如果参数是**对象**，由于对象是按引用传递的，两个内容相同但引用不同的对象会被视为不同的 key，导致缓存失效。

### 使用 hasher 函数自定义 Key
- `memoize` 提供第二个可选参数 `hasher`（一个函数）。
- 它接收原始函数的所有参数，返回一个用于缓存的唯一 key。

### 示例解析
- 定义一个 `getObject` 函数，返回传入的对象。
- 使用 `memoize` 包装，并提供 `hasher` 函数：`obj => obj.id`。
- 定义两个结构相同、`id` 均为 `'A'` 但引用不同的对象 `obj1` 和 `obj2`。
- 第一次调用 `getObject(obj1)` 时，`hasher` 返回 `'A'` 作为 key，将结果存入缓存。
- 第二次调用 `getObject(obj2)` 时，`hasher` 同样返回 `'A'`，发现 key 已存在，直接返回缓存中的值。
- 从而实现了通过 `hasher` 控制基于对象内容的缓存行为。

## 7. 高级特性：直接操作缓存与缓存预热 *Content-[14:18]
### 访问与修改缓存
- 每个由 `memoize` 创建的函数，都会带有一个 `cache` 属性，该属性是一个 `MapCache` 实例。
- 可以像操作原生 `Map` 对象一样，直接调用 `.set()`、`.get()`、`.has()` 等方法来修改缓存。
- **示例**：创建一个将字符串转大写的记忆化函数 `upper`。调用 `upper('foo')` 后，缓存中存入 `'foo' -> 'FOO'`。此时可通过 `upper.cache.set('foo', 'BAR')` 强制修改缓存值。后续调用 `upper('foo')` 将直接返回 `'BAR'` 而不是重新计算。

### 应用场景
- **调试性能问题**：检查缓存的状态和内容。
- **缓存预热**：在应用启动时，提前计算一些高频函数的结果，并手动填充到缓存中，以优化后续的运行性能。
