## 1. 全局 Function 模式 *Content-[00:00]

在没有模块化规范的早期阶段，前端开发主要采用**全局 Function 模式**。这种模式将不同的功能封装成不同的全局函数，但由于缺乏严谨性，存在较多问题。

### 主要问题
- **污染全局命名空间**：所有的全局函数最终都会挂载到 `window` 对象上，导致全局变量泛滥。
- **命名冲突**：由于都在全局作用域，极易发生函数名冲突。例如定义了 `function m1` 和 `function m2`，如果后续代码中再次定义同名的 `m1`，会直接覆盖之前的逻辑，且不会报错。
- **数据不安全**：全局变量可以被任意访问和修改。
- **模块成员关系不明显**：各个函数之间缺乏内在的逻辑联系，看不出模块成员的对应关系。

## 2. Namespace (命名空间) 模式 *Content-[02:11]

为了解决全局 Function 模式带来的命名冲突问题，演进出了 **Namespace（命名空间）模式**。

### 核心思想
通过对简单对象进行封装来减少全局变量。例如，定义一个 `myModel` 对象，将原本全局的 `data` 和方法（如 `buy`）都挂载到 `myModel` 这个命名空间（作用域）下。

### 优点
- 减少了全局变量的数量。
- 有效解决了命名冲突问题。

### 遗留问题
- **数据依然不安全**：虽然减少了全局变量，但模块内部的数据完全暴露。外部可以直接通过 `myModel.data` 等方式修改内部私有数据，导致内部状态可以被外部随意改写，缺乏私有化保护。

## 3. IIFE (立即调用函数表达式) 模式 *Content-[05:04]

为了解决数据不安全的问题，引入了 **IIFE（Immediately Invoked Function Expression，立即调用匿名函数自调用）** 模式。虽然日常手写较少，但在 Webpack 等构建工具编译后的代码中仍被广泛使用。

### 核心思想
利用函数作用域实现私有化。将相关的数据和行为封装在一个匿名函数内部，然后通过 `window` 对象向外暴露必要的接口或方法。

### 优点
- **数据私有化**：内部数据和逻辑被封装在函数作用域内，外部无法直接访问。
- **高内聚**：外部只能通过模块暴露出来的特定方法进行操作，保证了数据的安全性和逻辑的严谨性。

## 4. IIFE 增强模式 (引入依赖) *Content-[08:41]

当一个模块需要依赖其他模块（如 `jQuery`）时，可以对 IIFE 模式进行增强。

### 实现方式
通过立即执行函数的参数传递机制，将依赖的模块传入。例如，传入 `window` 和 `jQuery`（通常用 `$` 表示），在函数内部即可直接使用这些依赖。

### 关键注意事项
- **依赖加载顺序**：在 HTML 入口文件（如 `index.html`）中，必须通过 `<script>` 标签手动引入依赖。
- **严格的前后顺序**：被依赖的第三方模块（如 `jQuery`）必须放在依赖它的模块（如 `main.js`）之前加载。如果顺序颠倒，会导致后续模块在执行时因找不到依赖而报错。

## 5. 模块化的优势与早期模式的局限性 *Content-[11:31]

### 模块化的核心优势
通过上述演进，模块化展现出了巨大的价值：
- 避免命名冲突。
- 更好地进行代码分离。
- 支持按需加载。
- 提高代码的复用性。
- 提升项目的可维护性。

### 早期模式（基于 `<script>` 标签）的局限性
尽管 IIFE 增强模式解决了一定问题，但依赖 HTML 中多个 `<script>` 标签引入的方式仍存在严重缺陷：
- **请求过多**：每个 `<script>` 标签都会发起一次 HTTP 请求，模块过多时会导致性能下降。
- **依赖关系模糊**：无法直观感知模块（如 jQuery、A模块、B模块、C模块）之间的复杂依赖关系。
- **难以维护**：由于依赖关系不透明，极易出现加载顺序错误，导致“牵一发而动全身”的严重问题。

### 演进方向
正是由于上述局限性，促使了后续标准化模块规范的诞生，如 **CommonJS** 和 **ES6 Module**，从而彻底解决了依赖管理和按需加载的问题。

## AI 总结

本视频详细梳理了 JS 模块化的早期进化过程：从最初容易导致命名冲突和全局污染的**全局 Function 模式**，到通过对象封装减少冲突的 **Namespace 模式**，再到利用函数作用域实现数据私有的 **IIFE 模式**及其**增强模式**。这些演进逐步解决了命名冲突和数据安全问题，但基于 `<script>` 标签的引入方式最终暴露出请求过多和依赖关系模糊的瓶颈，从而推动了 CommonJS 和 ES6 Module 等现代模块化规范的诞生。掌握这一进化史，有助于深入理解现代前端工程化的核心设计思想。
