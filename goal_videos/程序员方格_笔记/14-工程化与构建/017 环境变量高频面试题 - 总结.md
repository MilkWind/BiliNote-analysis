## 1. 环境变量概念 *Content-[00:00]

环境变量是前端工程化中用于管理不同运行环境配置的核心机制。

- **核心概念**：用于区分和管理不同的项目运行环境，通常包括**开发环境**、**测试环境**和**生产环境**。
- **主要目的**：提取不同环境下的可复用配置值（如 API 接口地址、数据库连接等），从而避免在切换环境时手动去修改代码，提高开发效率和代码的可维护性。

## 2. 环境变量命名规范 *Content-[00:37]

在配置环境变量时，必须严格遵守文件和变量的命名规范，以确保构建工具能够正确识别。

- **文件命名规范**：
  - 格式：`.env.环境标识`
  - 示例：开发环境可以简写为 `.env.dev`，但**强烈建议写完整**，例如 `.env.development`。
- **变量命名规范**：
  - 在 Vue CLI 项目中，自定义环境变量**必须以 `VUE_APP_` 开头**（例如 `VUE_APP_BASE_API`）。
  - 变量名是**大小写敏感**的。
- **值的规范**：
  - 字符串类型的值必须使用引号包裹（如 `VUE_APP_TITLE="My App"`）。
  - 数字或布尔类型的值直接书写即可，无需引号。

## 3. 环境变量配置步骤 *Content-[01:55]

在项目中使用环境变量，需要按照以下标准步骤进行配置：

1\. **创建环境变量文件**：在项目根目录下，根据实际需要的环境数量创建对应的 `.env` 文件（如开发、测试、生产各一个）。
2\. **定义环境变量**：在创建的文件中，按照命名规范定义具体的键值对。
3\. **配置启动命令**：在 `package.json` 文件的 `scripts` 中配置终端启动命令，通过 `--mode` 参数指定当前启动所使用的环境变量文件。
4\. **重启项目**：配置或修改环境变量后，**必须重启项目**（小黑窗/终端），否则新配置不会生效。

## 4. 组件中使用环境变量 *Content-[02:47]

在不同的前端脚手架中，读取环境变量的语法有所不同：

- **Webpack / Vite 脚手架**：
  - 使用 `import.meta.env.VUE_APP_XXX` 语法。
  - 将 `XXX` 替换为你实际定义的变量名后缀。
- **Vue CLI 脚手架**：
  - 使用 `process.env.VUE_APP_XXX` 语法。
  - 同样将 `XXX` 替换为实际的变量名后缀。

## 5. 三大环境的区别 *Content-[03:42]

理解三大环境的业务区别是面试中的高频考点：

- **开发环境 (Development)**：
  - **定义**：程序员日常编写代码的环境。
  - **特点**：其接口和数据库通常是测试用的，数据可能不够规范或完整。
- **测试环境 (Test / Staging)**：
  - **定义**：开发完毕后，提交给测试人员进行功能测试和部署的环境。
  - **特点**：接口和数据库是否更换视具体项目情况而定（实际开发中不一定更换）。
  - **💡 面试回答技巧**：在面试时，为了回答更严谨且符合标准流程，可以统一表述为：“切换到测试环境时，我们需要更换接口和数据库”。
- **生产环境 (Production)**：
  - **定义**：最终面向真实用户访问和使用的线上环境。
  - **特点**：接口和数据库都是正式的。所有功能（如商品浏览、购买、支付等）均正常运行，数据真实有效。

## 6. 环境变量的作用 *Content-[05:30]

环境变量在前端工程化中发挥着至关重要的作用，主要体现在以下四个方面：

1\. **避免手动修改代码，提高效率**：提前配置好各环境的参数，切换环境时只需更改启动命令，无需在代码中反复修改配置。
2\. **区分环境差异**：可以根据当前环境执行不同的逻辑。例如，在开发环境打印 `console.log` 进行调试，而在生产环境自动清除这些日志。
3\. **保护敏感信息**：将 API 密钥、数据库密码等敏感信息放入环境变量中，避免硬编码在代码里并被提交到 Git 仓库，提升安全性。
4\. **统一配置，便于协作**：团队成员使用同一套环境变量配置（例如统一的本地接口地址 `localhost:8080/api`），减少沟通成本，保证开发环境的一致性。
