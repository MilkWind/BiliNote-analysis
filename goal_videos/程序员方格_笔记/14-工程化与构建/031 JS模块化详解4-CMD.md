## 1. CMD 规范概述 *Content-[00:04]

- **基本概念**：CMD（Common Module Definition）专门用于浏览器端，其模块的加载机制是异步的。
- **核心特性**：与传统的提前加载不同，CMD 规范下的模块在**真正使用时**才会去进行加载和执行，体现了懒加载的思想。
- **规范融合**：CMD 规范巧妙地整合了 CommonJS 和 AMD 规范的特点，吸取了两者在模块化管理上的优势。
- **实现工具**：在实际开发中，我们主要使用 **SeaJS** 来处理符合 CMD 规范的模块加载、依赖管理等操作，所有基于 CMD 的 JS 模块都会遵循该规范。

## 2. CMD 与 AMD (RequireJS) 的核心区别 *Content-[01:25]

- **底层加载机制**：
  - CMD (SeaJS) 与 AMD (RequireJS) 在底层模块加载方式上原理是一致的。它们都是通过动态创建 `<script>` 标签，并监听 `load` 事件来实现模块的异步加载。
- **核心差异（依赖声明与加载时机）**：
  - **AMD (RequireJS)**：采用“加载在前，使用在后”的策略。在声明模块依赖时，会优先提前加载所有依赖模块。
  - **CMD (SeaJS)**：采用“使用在前，加载在后”的策略。它实行懒加载和按需加载，只有当代码执行到 `require` 引入模块的地方时，才会真正去加载对应的模块。

## 3. CMD 的基本用法详解 *Content-[02:42]

### 3.1 定义无依赖的模块
- 使用 `define` 方法进行模块定义。
- 通过 `exports.xxx = value` 的方式将内部数据或方法暴露出去，这种写法体现了 CMD 与 CommonJS 规范的结合。

### 3.2 定义有依赖的模块
- 在 `define` 的回调函数中，通常会接收 `require`、`exports`、`module` 等标准参数。
- **同步加载**：在函数内部，当业务逻辑需要用到某个外部模块时，直接通过 `require('模块路径')` 的方式同步加载并使用该模块。
- **异步加载**：除了同步加载，CMD 也支持异步加载模块。加载完成后，可以在回调函数中获取到模块暴露的资源，最后再通过特定方式将当前模块的内容暴露出去。

### 3.3 引入和使用模块
- 在模块内部或入口文件中，通过 `require` 同步加载所需的相关模块，随后即可进行具体的业务逻辑调用和使用。

## 4. SeaJS 的实现与使用 *Content-[06:05]

- **环境准备**：首先需要下载 **SeaJS** 库，并在 HTML 文件中通过 `<script>` 标签引入 SeaJS 的资源文件。
- **模块定义**：在 JS 文件中使用 `define` 定义模块。在工厂函数内部可以访问内部数据以及通过 `require` 引入的外部数据，最后向外暴露相关的方法或属性。
- **入口加载**：与 RequireJS 的使用流程类似，引入 SeaJS 资源后，需要通过调用 `seajs.use('模块入口路径')` 的方式来加载当前的模块入口，从而启动整个前端应用。

## 5. AMD 与 CMD 的核心差异总结 *Content-[08:24]

### 5.1 依赖处理方式
- **AMD**：推崇**依赖前置**。要求在定义模块时，通过依赖数组的方式提前声明当前模块的所有依赖项。
- **CMD**：推崇**依赖就近**。不要求提前声明，而是在编程时，只有在真正需要用到某个模块的地方，才通过 `require` 方式动态引入和加载，代码可读性和逻辑内聚性更强。

### 5.2 模块对外输出方式
- **AMD**：推崇通过 **`return` 返回值**的方式，将模块内部的接口或数据对外输出。
- **CMD**：推崇通过 **`module.exports` 赋值**的方式，将模块内部的接口或数据对外输出，这与 Node.js 中 CommonJS 的输出方式高度一致。
