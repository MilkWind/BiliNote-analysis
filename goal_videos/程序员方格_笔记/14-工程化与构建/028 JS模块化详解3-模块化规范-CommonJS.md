## 1. CommonJS 概念与核心特点 *Content-[00:00]

- **Node.js 与 CommonJS**：Node.js 应用由模块组成，主要采用 CommonJS 模块规范。
- **模块作用域**：每个文件都是一个独立的模块，拥有自己的作用域。在文件内定义的变量（如 `let`、`const` 等）或函数都是私有的，对外部文件不可见，从而避免污染全局作用域。
- **同步与异步加载机制**：
  - **服务端（Node.js）**：模块在运行时采用**同步加载**。因为加载的是本地文件，读取速度较快，所以同步加载是可行的。
  - **浏览器端**：需要提前编译打包，采用**异步方式**加载（如 AMD、CMD、UMD 等规范）。如果在浏览器端使用同步加载，会导致严重的渲染阻塞和长时间白屏。
- **核心特点总结**：
  - 主要运行在服务器端。
  - 所有代码运行在模块作用域内，不会污染全局作用域。
  - 运行时同步加载模块。
  - **缓存机制**：模块可以被多次加载，但只在第一次加载时运行一次。运行结果会被缓存，后续加载直接从缓存中读取。若要模块再次运行，必须手动清除缓存。
  - **加载顺序**：严格按照代码中出现的顺序进行处理。

## 2. CommonJS 基本用法 *Content-[04:26]

- **暴露模块**：
  - 通过 `module.exports` 方式暴露整个模块。例如：`module.exports = value`。
  - 通过 `exports` 对象暴露特定属性或方法。例如：`exports.xxx = value`。
- **引入模块**：
  - 通过 `require` 方式引入当前模块。
  - 引入**第三方模块**时，传入对应的模块名（如 `require('lodash')`）。
  - 引入**自定义模块**时，传入对应的文件路径（如 `require('./myModule')`）。

## 3. 模块暴露的本质与值的拷贝 *Content-[05:26]

- **暴露模块的本质**：
  - CommonJS 规范规定，每个模块内部都有一个 `module` 变量，代表当前模块。
  - `module` 是一个对象，其 `exports` 属性（即 `module.exports`）是对外的接口。
  - 加载某个模块，实际上是加载该模块的 `module.exports` 属性。所有向外暴露的内容都会封装在这个对象中。
- **代码示例解析**：
  - 在模块中定义变量 `x = 5` 和修改 `x` 的 `add` 方法。
  - 通过 `module.exports` 暴露 `x` 属性和 `add` 方法。
  - 在外部文件中 `require` 该模块，可以获取到暴露的内容，读取 `x` 的值并执行 `add` 方法。
- **require 的执行逻辑**：
  - 读入并执行当前的 JS 文件。
  - 返回该模块的 `module.exports` 对象。
  - 如果未找到对应的模块，则会抛出报错。

## 4. 模块加载机制与 ES6 模块的差异 *Content-[09:50]

- **CommonJS vs ES6 模块**：
  - **CommonJS**：运行时加载，输出的是**值的拷贝**。
  - **ES6 模块**：编译时输出接口。
- **值的拷贝特性（快照机制）**：
  - CommonJS 在第一次加载模块时运行一次并缓存对象。
  - 输出的是值的拷贝。一旦输出，模块内部的变化**不会**影响到外部。外部获取的只是当前时刻的数据快照。
  - **示例说明**：
    - 定义一个 `counter` 变量初始值为 3，并暴露一个 `incCounter` 方法使其加 1。
    - 外部引入后，先打印 `counter`，结果为 3。
    - 执行 `incCounter` 方法后，再次打印外部引入的 `counter`，发现**依然是 3**。
    - **原因**：引入时只是获取了值的拷贝，模块内部对 `counter` 的修改不会影响外部已拷贝的内存地址。
- **获取最新值的解决方案**：
  - 可以通过暴露一个 **getter 函数**（如 `getCounter`）来返回最新的 `counter` 值。
  - 外部调用该函数时，会实时获取模块内部最新的值，从而绕过值拷贝的限制。

## 5. require 的底层运行机制 *Content-[16:12]

- **Module 构造函数**：
  - Node.js 内部定义了 `Module` 构造函数，用于描述模块的相关信息。
  - 包含核心属性：`id`、`exports`（暴露的对象）、`parent`、`filename`、`loaded`（是否加载完成，初始为 `false`）、`children`（当前文件依赖的子模块）等。
- **加载流程**：
  - 调用 `require` 时，实际上会调用 `Module` 的 `load` 方法。
  - 根据 `filename` 创建当前模块实例。
  - 调用 `Module.prototype.load` 方法，通过文件系统（`fs`）读取磁盘上的文件。
  - 完成模块的编译工作。
  - 将 `module.loaded` 设置为 `true`。
  - 最终 `require` 获取到的是 `module.exports` 上的内容。

## 6. CommonJS 的局限性 *Content-[18:12]

- **缺少模块封装能力**：每个文件只能是一个模块（一个文件对应一个模块）。这在服务端是可行的，但在浏览器端不够友好，无法在一个文件中封装多个模块。
- **同步加载导致阻塞**：在浏览器中使用同步方式加载依赖，会阻塞 JS 渲染，导致长时间白屏，严重影响用户体验。
- **导出方式相对繁琐**：使用 `exports` 对象暴露模块时，需要将导出的变量和方法都手动挂载到 `exports` 或 `module.exports` 对象上。

## AI 总结

CommonJS 是 Node.js 默认采用的模块化规范，其核心特点是**运行时同步加载**和**模块作用域隔离**。它通过 `module.exports` 暴露接口，通过 `require` 引入模块，并且具有**首次加载后缓存**的机制。与 ES6 模块最大的区别在于，CommonJS 输出的是**值的拷贝**（快照），模块内部的后续修改不会影响外部已引入的值，若需获取最新值需借助 getter 函数。尽管 CommonJS 在服务端表现优异，但其同步加载特性和单文件单模块的限制，使其在浏览器端容易引发渲染阻塞，这也是后来 ES6 模块（ESM）在浏览器端成为主流的重要原因。理解 CommonJS 的底层加载机制（如 `Module` 构造函数和 `fs` 读取编译）对于深入掌握 Node.js 和前端工程化至关重要。
