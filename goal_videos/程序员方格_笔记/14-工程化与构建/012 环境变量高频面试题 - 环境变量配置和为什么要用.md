## 环境变量的概念与作用 *Content-[00:01]

- **核心定义**：Vue 项目中的环境变量是为不同环境（开发、测试、生产）提前写好的配置，用于区分不同环境的差异。
- **主要作用**：避免在代码中手动修改配置，从而大幅提高开发效率和代码的稳定性。
- **工作原理**：提前将接口地址、密钥、域名等配置写入环境变量文件。在代码中直接调用这些配置，Vue 会根据当前运行的环境自动匹配对应的环境变量。

## 环境变量的配置步骤 *Content-[00:38]

以 Vue3 + Vite 项目为例（Vue2 项目用法基本一致，后续会补充区别）。

### 1\. **确认项目根目录**
- 根目录是指与 `package.json` 同级的目录，也就是 Vue3 项目的第一级目录（通常包含 `node_modules` 文件夹）。

### 2\. **创建环境变量文件**
在根目录下创建三个固定命名的环境变量文件（**注意：文件名以 `.env` 开头，固定命名不能乱改，不能多写也不能少写**）：
- `.env.development`：开发环境（供开发者在自己电脑上开发使用）。
- `.env.test`：测试环境（供测试人员进行测试使用）。
- `.env.production`：生产环境（项目上线后供真实用户使用）。

### 3\. **定义环境变量内容**
在三个文件中分别定义对应的环境变量。
- **命名规范**：
  - 在 Vue3 + Vite 脚手架中，环境变量通常必须以 `VITE_` 开头（注：Vue2 + Vue CLI 中以 `VUE_APP_` 开头）。
  - 变量名必须全部大写，单词之间使用下划线 `_` 分隔。
- **配置示例**：
  - **开发环境 (`.env.development`)**：
    ```env
    VITE_APP_BASE_API="http://localhost:8080/api"  # 开发环境的接口前缀
    VITE_APP_ENV="development"                     # 开发环境的环境标识
    ```
  - **测试环境 (`.env.test`)**：
    ```env
    VITE_APP_BASE_API="http://test.xxx.com/api"    # 测试环境的接口前缀
    VITE_APP_ENV="test"                            # 测试环境的环境标识
    ```
  - **生产环境 (`.env.production`)**：
    ```env
    VITE_APP_BASE_API="http://production.xxx.com/api" # 生产环境的接口前缀
    VITE_APP_ENV="production"                         # 生产环境的环境标识
    ```

## 为什么要使用环境变量 *Content-[08:38]

面试时被问到“为什么要用环境变量”，千万不要只回答“方便”，应围绕以下四个核心原则并结合实际案例进行专业回答：

1\. **避免手动修改代码，提高开发效率**
- **案例**：如果不使用环境变量，每次切换环境（如修改 axios 实例中的 `baseURL`）都需要手动去改代码。
- **优势**：使用环境变量提前定义好配置后，切换环境时无需修改任何代码，只需执行 `npm run dev` 或 `npm run test` 等命令即可一键自动切换，既方便又避免了手动修改带来的错误。

2\. **区分环境差异，保证代码稳定性**
- **案例**：开发、测试、生产环境的接口地址和密钥各不相同。
- **优势**：环境变量能清晰区分这些配置，避免将开发环境的配置误用到生产环境（否则会导致线上用户看不到数据，这是开发大忌）。此外，还可以通过环境变量做条件判断，例如在开发环境保留 `console.log`，而在生产环境自动移除。

3\. **保护敏感信息，提高项目安全性**
- **案例**：电商项目中的支付密钥、对接第三方接口的通行证（密钥）等。
- **优势**：如果将敏感密钥直接写在代码中并推送到 GitHub，极易泄露造成损失。将敏感信息放在环境变量文件中，并通过 `.gitignore` 配置不将 `.env` 文件提交到 Git 仓库，可以确保密钥仅在开发团队内部可见，完美保护项目安全。

4\. **统一配置，便于团队协作**
- **案例**：团队中每个开发人员都使用相同的环境变量配置。
- **优势**：避免因为个人手动修改配置不一致而导致的代码错误（如“你那边能运行，我这边运行不了”的情况），确保大家使用相同的开发和测试接口，大幅提升团队协作效率。

**补充说明：单环境项目的必要性**
- 即使项目目前只有一个开发环境，也强烈建议使用环境变量。
- 这样做可以将接口地址、域名等集中管理，增强项目的可扩展性。后续如果需要增加测试或生产环境，直接新增对应的环境变量文件即可，无需重构代码。

## AI 总结

环境变量是前端工程化中不可或缺的配置管理工具。它通过将接口地址、密钥等配置与代码解耦，实现了多环境的无缝切换。在面试中，应从**提升开发效率、保证代码稳定性、保护敏感信息安全、促进团队协作**这四个维度进行系统性回答。此外，即使项目初期只有一个环境，提前引入环境变量配置也能为项目的后期扩展打下良好基础，体现了开发者规范的工程化思维。
