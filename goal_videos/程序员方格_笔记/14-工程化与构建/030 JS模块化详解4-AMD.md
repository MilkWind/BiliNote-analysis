## 1. AMD 规范概念与使用场景 *Content-[00:01]

- **与 CommonJS 规范的对比**：
  - **CommonJS**：采用**同步**方式加载模块。必须等待模块加载完成后，才能执行后续的相关操作。
  - **AMD**：采用**非同步（异步）** 方式加载模块，是一种异步模块加载机制。
- **使用场景分析**：
  - **CommonJS 适用场景（服务端）**：主要服务于 Node.js 服务端编程。由于模块文件通常存储在本地硬盘中，读取速度极快，因此无需考虑非同步加载，使用同步方式非常合适。
  - **AMD 适用场景（浏览器端）**：主要用于浏览器环境。在浏览器中，并非所有资源都在本地，经常需要从服务端获取数据和资源。如果使用同步方式加载，会导致页面阻塞，用户体验极差。因此，浏览器端必须使用异步方式加载模块，AMD 规范由此成为浏览器端的主流选择。

## 2. AMD 模块定义 (define) 详解 *Content-[02:06]

- **核心方法**：使用全局方法 `define` 来定义和加载模块。
- **基本语法结构**：`define(moduleId, dependencies, factory)`
  - **moduleId**：模块的唯一标识 ID。
  - **dependencies**：依赖的模块数据（数组格式），例如需要依赖的第三方模块。依赖关系是**前置**的。
  - **factory**：模块的具体实现逻辑，或者返回一个对象。
- **定义无依赖模块**：
  - 如果模块不依赖任何其他模块，可以直接省略 `dependencies` 参数，通过 `define` 直接定义模块逻辑（例如定义一个 `sayHello` 模块）。
- **定义有依赖模块**：
  - **依赖前置**：在 `dependencies` 数组中声明依赖，如 `jQuery` 和 `Underscore`。
  - **回调函数传参**：模块异步加载完成后，依赖的模块会作为参数传入 `factory` 回调函数中（例如 `$` 对应 jQuery，`_` 对应 Underscore）。
  - **模块实现**：在回调函数内部实现当前模块的逻辑（如修改 DOM 节点、进行模板替换等），此时可以安全访问并使用依赖模块提供的方法。
- **其他定义方式**：也支持定义带有依赖及具名的模块（但不常用），或者后续定义的模块。

## 3. AMD 模块加载 (require) 详解 *Content-[06:21]

- **加载方式**：通过 `require` 方法加载对应的模块。
- **多模块加载**：
  - 当需要加载多个模块时，通过**数组**的方式传入依赖列表，并配合一个回调函数。
  - 模块异步加载完成后，会将各个模块的导出结果（如 `mathAdd`、`utils`）作为参数传入回调函数中供后续使用。
- **支持 Promise 异步加载**：
  - AMD 支持异步加载并返回 Promise 对象。
  - **底层原理**：通过动态创建 `script` 标签加载模块，并监听 `load` 事件。当所有模块加载并执行完毕后，触发对应的回调。
  - **链式调用示例**：可以通过 `require` 加载模块 A，在 `.then()` 中获取 A 的内容；接着继续 `require` 模块 B，在 `.then()` 中获取 B 的内容，实现异步链式处理。
- **与 CommonJS 的核心区别**：
  - AMD 的 `require` 采用**前置依赖**（dependencies）机制，只有当所有前置依赖加载完成后，才会触发相关的回调函数。
  - 底层通过动态创建 `script` 标签和事件监听的方式实现异步加载，彻底解决了 CommonJS 同步加载在浏览器端造成的阻塞问题。

## 4. RequireJS 工具库的实际使用 *Content-[10:16]

- **工具库引入**：
  - AMD 规范的实际落地通常依赖 **RequireJS** 工具库，它主要用于客户端的模块管理，完全遵循 AMD 规范。
  - 基本思路：通过 `define` 定义模块，通过 `require` 加载模块。
- **具体使用步骤**：
  1. **引入资源**：在 HTML 文件中引入 RequireJS 资源文件，这是首要需要加载的资源。
  2. **主文件配置**：在主文件中使用 `require.config` 进行系统配置。
     - **baseUrl**：设置 JS 目录的基本路径（例如设定所有 JS 文件都在 `js/` 路径下）。
     - **paths**：定义模块标识名与实际文件路径的映射关系。例如，将本地模块 `alert` 映射到 `models/alert`，将第三方模块 `jQuery` 映射到 `libs/jquery` 的特定版本。
  3. **加载与使用**：配置完成后，通过 `require` 方法加载所需模块（如 `alert`），在回调函数中获取模块资源内容并进行业务逻辑处理。

## 5. AMD 规范核心总结 *Content-[14:03]

- **环境隔离**：AMD 模块定义方法清晰，不会污染全局环境。
- **依赖管理**：能够清晰地显示和声明模块之间的依赖关系。
- **适用场景**：主要用于浏览器环境。
- **加载机制**：允许非同步（异步）加载模块，支持通过动态方式加载对应的模块内容，极大提升了浏览器端的性能和用户体验。
