## ES6 模块化设计思想与优势 *Content-[00:01]

ES6 模块化是目前前端开发中使用频次最高的模块化规范。其核心设计思想与优势主要体现在以下几个方面：

- **设计思想：尽量静态化**
  - ES6 模块使得在**编译时**就能确定模块之间的依赖关系。
  - 对比 CommonJS：CommonJS 是运行时加载，必须在使用时才会去加载对应的模块，在运行之前无法确定当前的依赖关系。
- **静态化的核心优势：支持 Tree Shaking**
  - **Tree Shaking**（摇树优化）是性能优化的重要手段之一。
  - **原理**：在编译阶段分析模块之间的依赖关系并对代码进行打标。如果发现某些代码未被使用（冗余代码），则不会将其打包到最终的产物中，从而有效减小输出资源的体积。
- **语法特点**
  - CommonJS 将模块视为对象，输入时必须查找对象的相关属性。
  - ES6 模块实现了专属的模块功能，语法更加简洁、人性化。

## ES6 模块的导出与导入 *Content-[02:44]

ES6 模块主要通过 `export` 和 `import` 两个命令来实现模块的对外接口与输入。

- **模块导出 (export)**
  - 用于定义模块的对外接口。
  - **基本导出**：可以直接导出对应的变量或函数。
  - **批量导出**：可以通过大括号 `{}` 的方式直接导出一组变量。
  - **默认导出**：使用 `default` 关键字直接导出默认值。
- **模块导入 (import)**
  - 用于输入其他模块提供的接口以供当前模块使用。
  - 通过 `import` 命令引入其他模块导出的内容，支持按需导入或整体导入。

## ES6 模块与 CommonJS 的核心差异 *Content-[05:37]

ES6 模块与 CommonJS 在运行机制和底层逻辑上存在两个非常重要的差异：

- **差异一：输出值的类型**
  - **CommonJS**：输出的是**值的拷贝**。
  - **ES6 模块**：输出的是**值的引用**。
- **差异二：加载与生成时机**
  - **CommonJS**：**运行时**加载。模块（`module.exports`）是一个对象，只有在脚本运行完成后才会生成该对象。
  - **ES6 模块**：**编译时**输出接口。它不是对象，对外接口只是一种静态定义，在代码静态解析阶段就会生成。

**代码示例解析（值的引用 vs 拷贝）：**
1. 在 `live.js` 中定义变量 `counter = 3`，并导出 `incCounter` 方法（该方法对 `counter` 执行 `++` 操作）。
2. 在 `main.js` 中引入 `counter` 和 `incCounter`。
3. 初始打印 `counter`，结果为 3。
4. 执行 `incCounter()` 后，`live.js` 内部的 `counter` 变为 4。
5. 此时在 `main.js` 中再次打印 `counter`：
   - 如果是 **CommonJS**（值的拷贝），`main.js` 中获取的依然是初始拷贝的值 3。
   - 如果是 **ES6 模块**（值的引用），`main.js` 中打印的值会变为 4。因为 ES6 模块是动态引用，不会缓存值，而是直接寻址到模块内部绑定的变量。

## UMD 通用模块定义规范 *Content-[10:01]

- **概念**：UMD (Universal Module Definition)，即通用模块定义规范。
- **核心作用**：让模块能够在所有的 JS 运行环境中发挥作用。它能够同时满足 CommonJS、AMD、CMD 等多种标准。
- **解决的问题**：解决了 CommonJS 或 AMD 模式的代码不能在服务端和 Web 端通用的问题，实现“一份代码，多端执行”。
- **UMD 的实现逻辑**：
  1. **判断 CommonJS 环境**：检查全局变量 `module` 是否为 `object`，且 `typeof module.exports` 是否为 `object`。如果是，说明是 Node.js 环境，使用 CommonJS 规范执行代码。
  2. **判断 AMD 环境**：检查 `define` 是否为 `function`，且 `define.amd` 是否存在。如果存在，说明是 AMD 环境，使用 `require.js` 等工具加载代码。
  3. **判断 CMD 环境**：检查 `define` 是否为 `function`，且 `define.cmd` 是否存在。如果存在，说明是 CMD 环境（如 Sea.js），使用对应规范管理代码。
  4. **降级处理**：如果以上模块系统均不存在，则直接将代码挂载到对应的全局对象（如 `window`）上。

## JS 模块化规范总结与对比 *Content-[12:18]

- **CommonJS**：主要服务于服务端编程，采用同步加载模块的方式。由于会阻塞加载，因此不适合浏览器端编程。
- **AMD**：浏览器中的异步加载解决方案，支持并行加载多个模块。缺点是开发成本较高，代码阅读和书写困难，语义不够顺畅。
- **CMD**：与 AMD 相似，同样用于浏览器端的异步编程。其核心特点是“依赖就近、延迟执行”，这种设计使其很容易在 Node.js 中运行。
- **ES6 模块**：在语言标准层面上实现了模块功能。语法简单且强大，完全可以取代 CommonJS 和 AMD 等规范，成为浏览器和服务端通用的终极解决方案。
- **UMD**：作为一种兼容方案，同时满足了上述多种规范（CommonJS、AMD、CMD 等）的实现。
