## 微前端 JS 隔离的必要性 *Content-[00:00]

在微前端架构中，JavaScript 隔离是核心考察点之一，主要涉及对微前端整体方案的理解以及沙箱（Sandbox）特性的处理。

- **全局对象与事件冲突**：每个子应用在运行时，都会涉及对全局对象（Global Object）或全局事件监听的操作。如果不进行隔离，不同应用之间修改同一个全局变量（例如应用 A 和应用 B 同时修改 `document.title`）会导致严重的冲突和互相覆盖。
- **沙箱环境的必要性**：为了防止全局变量污染和样式互相影响，必须在对应的沙箱环境（Sandbox）中执行当前子应用的 JS 代码，确保各个应用之间的运行环境相互独立。

## Proxy 代理沙箱（Proxy Sandbox） *Content-[01:40]

在支持 `Proxy` 的浏览器环境下，微前端通常采用代理沙箱来实现 JS 隔离。其核心优势在于**支持多实例**运行。

- **核心实现原理**：
  - 在类的 `constructor` 中创建状态和 `fakeWindow`（伪造的 window 对象）。
  - 利用 `Proxy` 将 `fakeWindow` 代理到真实的 `window` 对象上。
  - 子应用对全局对象的修改，实际上都会被拦截并修改到 `fakeWindow` 上，从而避免污染真实的 `window`。

- **拦截机制（Trap）**：
  - **`set` 拦截**：劫持所有的 `set` 操作，确保对全局变量的修改都映射到 `fakeWindow`（即 Proxy 的 target）上，不会作用于真实的 `window`。
  - **`get` 拦截**：在获取数据时，优先从 `fakeWindow` 中读取；如果 `fakeWindow` 中不存在该属性，则回退到真实的 `window` 对象上获取。

- **生命周期状态管理**：
  - **激活状态（Active/Running）**：将全局代理对象绑定，子应用代码在沙箱环境中执行。此时所有对全局对象的处理，最终都会映射到 Proxy Sandbox 层面。
  - **非激活状态（Inactive）**：沙箱失效，解除代理绑定，恢复真实的全局环境。

## Snapshot 快照沙箱（Snapshot Sandbox） *Content-[06:57]

在不支持 `Proxy` 的老旧浏览器环境（如 IE11）下，微前端会降级使用快照沙箱来实现 JS 隔离。其核心逻辑是通过记录应用对 `window` 对象的修改来实现隔离。

- **核心数据结构**：
  - `proxy`：在不支持 Proxy 的场景下，直接指向真实的 `window`。
  - `modifiedProps`（Map 格式）：用于存储当前应用对 `window` 修改过的属性及值。
  - `windowSnapshot`：用于存储激活时 `window` 对象的初始快照。

- **激活状态（Active）处理逻辑**：
  1. **保存快照**：遍历当前的 `window` 对象，将其所有属性及值存储到 `windowSnapshot` 中，记录环境的初始状态。
  2. **恢复修改**：遍历之前记录的修改集合（Map），将之前修改过的属性值重新覆盖到当前的 `window` 上，使环境恢复到该应用上次运行时的状态。

- **销毁/非激活状态（Inactive）处理逻辑**：
  1. **记录修改**：遍历当前的 `window` 对象，对比当前属性值与 `windowSnapshot` 中存储的初始值。
  2. **存储差异**：如果当前值与快照中的值不相等，说明在运行期间发生了修改，将修改后的新值存储到 `modifiedProps`（Map）中。
  3. **恢复环境**：将 `window` 对象恢复到激活前的状态（即 `windowSnapshot` 的状态），确保子应用销毁后不会污染全局环境。

## AI 总结

微前端架构中的 JavaScript 隔离是确保多个子应用能够安全、独立运行的关键。主要通过沙箱（Sandbox）机制来实现，具体分为两种方案：
1. **Proxy 代理沙箱**：适用于现代浏览器，通过 `Proxy` 拦截对 `window` 的 `get` 和 `set` 操作，将修改重定向到 `fakeWindow`，性能更好且支持多实例。
2. **Snapshot 快照沙箱**：适用于不支持 `Proxy` 的老旧浏览器，通过在应用激活时保存 `window` 快照、销毁时对比差异并记录修改，利用“快照-恢复”的机制实现隔离。
两者均有效解决了子应用间全局变量和事件监听冲突的问题，是微前端面试中的高频核心场景题。
