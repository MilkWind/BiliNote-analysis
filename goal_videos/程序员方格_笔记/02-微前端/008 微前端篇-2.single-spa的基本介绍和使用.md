## single-spa 的核心能力 *Content-[00:00]
- **核心定位**：single-spa 本身是一个前端微应用整合的调度中心，不关心应用的具体业务逻辑。其核心职责是在浏览器运行时，负责指挥和调度各个微应用。
- **统一生命周期管理**：为所有接入的微应用提供标准化的生命周期（如 `bootstrap`、`mount`、`unmount` 以及 `update` 等）。无论使用 React 还是 Vue，都必须遵循这套约定，以便 single-spa 进行统一处理。
- **多应用共存能力**：确保在同一个页面上可以同时运行多个来自不同技术栈、独立开发的单页应用，且它们之间不会产生任何冲突。
- **基于路由的微应用切换**：监听浏览器 URL 变化。当 URL 匹配到某个微应用的规则时，自动加载并挂载该应用；当 URL 不再匹配时，自动卸载并释放资源。实现按需发生、自动加载和卸载。
- **技术栈无关**：得益于统一的生命周期，single-spa 不关心微应用内部使用的技术栈，React、Vue 等应用都能被完美集成到统一系统中。
- **总结**：single-spa 是一个纯粹的运行时框架，全部工作发生在用户的浏览器中，核心任务是通过统一的生命周期实现对不同技术栈应用的路由调度。

## single-spa 的三个关键组件 *Content-[03:13]
要上手 single-spa 框架，需要掌握其三个关键组件：
- **Root Config**：整个 single-spa 的入口，所有微应用的信息都会在此登记，负责定义调度规则。
- **Application**：通常的微应用，对应一个完整的业务单页面应用。由路由激活，当 URL 匹配时，single-spa 会加载对应的 application。
- **Parcels**：比 application 粒度更小的组件级微模块。不直接与路由绑定，可被任何应用动态、自由地挂载。
- **single-spa runtime**：底层调度引擎。根据 root config 中注册的信息及当前 URL 状态，决定加载、挂载或卸载哪个 application，同时提供 API 让 application 能够挂载 parcels。

## Root Config 的配置与代码示例 *Content-[05:36]
Root config 是微前端应用的入口文件，职责纯粹，主要做两件事：
1\. **注册所有微应用**：为每个微应用提供三个关键信息：
   - 唯一的名称（`name`）。
   - 异步加载函数（用于动态下载代码）。
   - 激活规则（`activeWhen`）：决定何时被挂载。
2\. **启动 single-spa 应用**：完成注册和配置后，调用 `start()` 函数。该函数告诉 single-spa 一切准备就绪，开始接管路由并根据 URL 变化调度微应用。

**代码示例解析**：
- 从 `single-spa` 包导入核心函数 `registerApplication` 和 `start`。
- **注册第一个应用（如 `app-react`）**：
  - `name`: `'app-react'`。
  - 加载函数：使用动态 `import()` 语法，实现代码按需异步下载。
  - `activeWhen`: 传入一个函数，接收 `location` 对象并返回布尔值。例如判断路径是否以 `/react` 开头，返回 `true` 则激活，`false` 则卸载。
- **注册第二个应用（如 `app-vue`）**：
  - `activeWhen` 支持传入字符串数组（语法糖），效果等同于判断 `location.pathname` 是否以 `/vue` 开头，提升了配置的灵活性。
- **启动应用**：调用 `start()` 后，路由监听机制正式启动。访问对应路径时，single-spa 会自动加载并挂载应用到指定的 container 上。

## 微应用的核心约定与生命周期 *Content-[10:28]
被注册的微应用必须向外导出一个符合规范的对象，包含三个异步的生命周期函数：
1\. **`bootstrap`**：
   - 在应用生命周期中只会被调用一次（首次激活、即将挂载前）。
   - 用于初始化阶段的一次性设置，如定义全局变量、初始化服务、创建挂载容器等。
2\. **`mount`**：
   - 当激活规则从 `false` 变为 `true` 时调用。
   - 核心职责：将微应用的 UI 渲染到主应用的 DOM 中（如 React 调用 `render`，Vue 调用 `app.mount`）。
3\. **`unmount`**：
   - 当激活规则从 `true` 变为 `false` 时调用。
   - 核心职责：将应用从 DOM 中完全移除，并清理相关资源（如解绑事件监听、清除定时器等）。

**注意事项**：`bootstrap` 只执行一次，而 `mount` 和 `unmount` 会随着路由切换被反复调用。
**框架辅助**：官方提供了 `single-spa-react` 和 `single-spa-vue` 等辅助库，会自动包裹应用并生成符合规范的生命周期函数，开发者通常无需手动编写模板代码。

## Parcels：组件级微模块 *Content-[14:35]
- **应用场景**：当复用需求的粒度更小（如全局消息通知组件、Header 组件），且不与路由直接绑定，而是由应用内部逻辑决定显示或隐藏时，`application` 就不再适用。
- **核心定义**：Parcels 是没有激活规则、可以被手动控制挂载和卸载的微应用（微模块）。
- **主要特点**：
  - **挂载灵活**：可以被挂载到任何微应用中、root config 的主 HTML 中，具体挂载位置由调用方决定。
  - **独立生命周期**：与 application 一样，必须导出 `bootstrap`、`mount`、`unmount` 等生命周期。
  - **技术栈无关**：可以用 Vue 编写一个微模块，然后在 React 应用中加载、挂载和卸载它。
- **价值**：提供了比 application 更灵活、细粒度更小的跨应用代码复用能力，非常适合在多个微应用中共享功能统一的 UI 组件。

## Parcels 的具体使用方法 *Content-[17:10]
Parcels 的使用是完全程序化、手动的，与自动化的 application 不同：
1\. **导入函数**：从 `single-spa` 包中导入 `mountRootParcel` 函数，这是手动挂载 parcel 的入口。
2\. **调用挂载**：调用 `mountRootParcel` 函数，接收两个主要参数：
   - **加载函数**：通常通过动态 `import()` 导入目标组件。
   - **配置对象**：包含重要属性 `domElement`，用于指定 parcel 具体挂载到的 DOM 节点（如 `id="user-card"` 的元素）。
   - 该函数会返回一个 parcel 对象。
3\. **手动卸载**：当不再需要该 parcel 时（如用户关闭弹窗），调用返回的 parcel 对象上的 `unmount()` 方法。这会触发 parcel 实例的 unmount 生命周期，将其从 DOM 中安全移除并释放资源。

通过 `mountRootParcel` 和 `unmount` 方法，开发者可以在任何地方、任何时机动态地挂载和卸载微前端组件。

## single-spa 整体工作机制总结 *Content-[19:25]
- **核心定位**：single-spa 是一个微前端的调度中心，其价值不在于编写业务逻辑，而在于组织和协调多个独立开发的应用。
- **调度手段**：通过一套统一的生命周期方法（`bootstrap`、`mount`、`unmount`）抹平不同技术栈之间的差异，从而标准化管理所有接入的微应用。
- **核心架构**：
  - **Root Config**：扮演注册中心和系统入口的角色。
  - **Application**：与路由绑定的页面级主要业务模块。
  - **Parcels**：提供细粒度、可被程序化控制的组件级能力。
