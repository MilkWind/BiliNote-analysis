## Module Federation 核心概念与角色 *Content-[00:00]
- **课程目标**：深入理解模块联邦（Module Federation, MF）中的两种核心角色：Remote（远程应用）和 Host（宿主应用），并学习最基础的配置以启动和运行一个模块联邦应用。
- **核心角色解析**：
  - **Host（宿主应用）**：相当于服务消费者，主要职责是消费或加载来自于其他应用的模块。
  - **Remote（远程应用）**：相当于服务提供者，作用是暴露或提供自己的模块，让其他应用来消费。
  - **双向数组（双向模式）**：一个应用既可以扮演 Host，也可以扮演 Remote。既能消费其他应用的模块，也能把自己的模块暴露给别人。这种设计打破了传统的单向依赖模式，使应用间的协作更加灵活，是 Module Federation 的核心优势。
- **两种协作模式图解**：
  - **基础 Host 和 Remote 关系**：app1 作为 Host 消费 app2（Remote）暴露的模块。
    - **关键特性**：
      1. **动态加载**：模块在运行时按需加载，而非在构建时打包。
      2. **独立部署**：每个应用可独立开发、独立发布，互不影响。
      3. **版本隔离**：有效避免不同应用间的依赖冲突。
  - **双向数组模式**：app1、app2、app3 之间互相消费模块，形成网状的协作结构。在大型组织多团队协作场景中非常有用，能极大提升代码复用率和开发效率。

## Webpack 中 Remote 应用的基础配置 *Content-[02:20]
- **核心工具**：启用模块联邦的核心是使用 Webpack 内置插件 `ModuleFederationPlugin`。
- **示例场景**：两个独立的 React 项目 app1（Host/消费者）和 app2（Remote/提供者）。目标是让 app2 暴露内部的 Button 组件，供 app1 加载使用。
- **Remote (app2) 的 Webpack 配置**：
  - 引入 `ModuleFederationPlugin` 并创建实例。
  - **核心配置项**：
    - `name`：定义远程应用的唯一名称，此处配置为 `app2`。
    - `filename`：指定打包后生成的入口文件名，通常命名为 `remoteEntry.js`。
    - `exposes`（视频中口述为 export）：Remote 配置中最核心的部分，定义要暴露给外部的模块。将内部路径 `./src/Button` 的组件通过别名 `./Button` 暴露出去。
    - `shared`：定义与宿主应用共享的依赖库（如 React），避免重复加载（详细讲解在下一节课）。

## Webpack 中 Host 应用的基础配置 *Content-[04:27]
- **Host (app1) 的 Webpack 配置**：
  - 同样需要引入 `ModuleFederationPlugin`。
  - `name`：需要一个唯一标识。
  - `shared`：与 Remote 中的配置保持一致。
  - **核心配置项 `remotes`**：告诉 Host 应用应该从哪里去寻找 Remote 模块。
    - 定义一个名为 `app2` 的远程应用。
    - 指明其入口文件的具体地址，即指向 `remoteEntry.js` 的完整 URL 路径。

## 在 Host 应用中加载与使用远程组件 *Content-[05:13]
- 配置完成后，即可在 Host 应用（app1）的代码中实际使用 Remote 应用（app2）暴露的组件。
- **代码实现细节**：
  - 使用 `React.lazy` 结合动态 `import` 来动态加载 Button 组件。
  - **路径组合规则**：路径由 Remote 应用的 `name`（即 `app2`）和 `exposes` 字段定义的别名（即 `./Button`）组合而成，例如 `import('app2/Button')`。
  - 在 JSX 中，使用 `<Suspense>` 组件将远程 Button 包裹起来，并提供 `fallback` 属性处理加载状态。
- **关键点总结**：
  - 通过 `React.lazy` 实现组件的动态导入，这是 React 官方推荐的方式。
  - `import('app2/Button')` 看似普通的动态导入语法，实际会触发 Module Federation 的运行时加载逻辑。
  - 由于加载是异步的，必须使用 `<Suspense>` 处理加载过程中的 UI 状态。
- **开发体验**：引入远程组件与引入本地动态组件几乎没有任何区别，仅在 Webpack 配置层面做了改动，充分体现了 Module Federation 的魅力。

## 模块联邦从构建到运行的完整流程 *Content-[06:54]
- **构建阶段（完全解耦）**：
  1. **Remote 打包**：app2 独立进行打包，Webpack 会生成 `remoteEntry.js` 以及暴露 Button 组件的 chunk。这些静态资源被部署在 Remote 服务器上。
  2. **Host 打包**：app1 独立进行打包，Webpack 读取 `remotes` 配置，将加载远程模块的逻辑注入到打包产物中。app1 被部署到自己的服务器上。
- **运行阶段**：
  3. **加载主应用**：用户访问 app1，浏览器加载 app1 的主应用代码。
  4. **动态加载远程模块**：当代码执行到渲染远程组件的地方时，app1 会根据配置向 Remote 发起请求，获取 `remoteEntry.js` 文件。解析完成后，得知 Button 组件具体的 chunk 地址，然后去下载该组件的代码并最终渲染到页面上。
  5. **依赖共享**：在此过程中，如果 Host（app1）发现 Remote（app2）也依赖 React 且版本兼容，它就会复用已经加载的 React，从而避免重复加载。
- 整个流程清晰地分为构建和运行阶段，这是实现应用独立部署和更新的基础。
