## 1. 路由拦截阶段 *Content-[00:26]

在 `single-spa` 的工作流程中，所有变化的起点都是 **URL 发生变化**。当 URL 变化时，`single-spa` 内部会经历路由拦截阶段。

- **核心拦截文件**：源码中的 `navigation-events` 文件负责拦截并捕获路由变化事件。
- **拦截机制**：
  - **重写 History 方法**：重写了浏览器的 `pushState` 和 `replaceState` 方法。
  - **监听原生事件**：监听了 `hashchange` 和 `popstate` 两个原生事件。
- **收集变更途径**：通过劫持上述两个 History 方法和两个原生事件，`single-spa` 将所有可能导致 URL 发生变化的途径全部收集起来。无论通过哪种方式触发路由变化，最终都会被该文件统一捕获。
- **统一入口**：收集完事件后，会统一调用 `reroute` 函数（*注：视频转录中识别为 `reload`，实际 single-spa 源码中为 `reroute`*），该函数是所有路由变更的统一入口。

## 2. 计算应用变更列表 *Content-[02:43]

在 `reroute` 函数中，首先需要调用 `getAppChanges` 方法（*转录中称为 `get app change`*）来计算哪些应用需要更新。

- **遍历注册应用**：遍历所有当前已经在 `rootConfig` 中注册的微前端应用。
- **激活判断**：根据每个应用注册时提供的**激活函数**（activity function），判断在当前 URL 下该应用是否应该被激活。
- **生成变更列表**：根据判断结果，生成并返回一个包含四个关键数组的变更列表，明确接下来需要执行的具体操作：
  - `appsToLoad`：需要被加载的新应用。
  - `appsToMount`：需要被挂载（重新加载）的应用。
  - `appsToUnmount`：需要被卸载的旧应用（*转录中口误为 `to amount`*）。
  - `appsToUnload`：需要被彻底移除的应用。

## 3. 生命周期编排与执行 *Content-[04:06]

拿到变更列表后，进入最关键的生命周期编排阶段。`single-spa` 会按照严格的顺序来调用各个应用的生命周期：

1. **执行卸载（Unmount）**：
   - 首先调用所有需要卸载的应用的 `unmount` 生命周期。
   - 目的：清空旧应用占用的 DOM 位置和状态。
2. **并行加载与初始化（Bootstrap）**：
   - 在卸载旧应用的同时，并行开始加载和初始化新应用。
   - `single-spa` 会下载新应用的代码，并执行 `bootstrap` 生命周期。
   - `bootstrap` 通常在应用第一次加载时仅执行一次，用于完成初始化工作。
3. **等待卸载完成**：
   - 系统会进行等待，确保所有旧应用的 `unmount` 生命周期都调用完毕后，才进行下一步操作。
4. **重新挂载（Mount）**：
   - 旧应用全部卸载完成后，开始执行新应用的 `mount` 生命周期。
   - 将新应用正式渲染到页面上。
5. **通知路由变化**：
   - 等到所有 DOM 操作完成且状态稳定后，回到 `navigation-events` 文件中。
   - 执行最初被拦截和暂存起来的 `popstate` 和 `hashchange` 事件监听器，正式通知各个应用路由已经发生变化。

## 4. 流程总结与 qiankun 延伸 *Content-[06:14]

- **核心流程总结**：
  1. `single-spa` 监听到 URL 变化。
  2. 通过激活函数计算出哪些应用需要更新（生成变更列表）。
  3. 遵循“**先卸载，后挂载**”的固定顺序去调用生命周期。
  4. 在所有操作完成后，才通知应用路由发生了变化。
- **机制优势**：正是这套非常清晰且可预测的调度机制，使得 `single-spa` 能够有序、稳定地管理多个微前端应用。
- **qiankun (乾坤) 延伸**：
  - 国内常用的微前端框架 `qiankun` 正是基于 `single-spa` 的这套调度机制来进行应用调度的。
  - 在此基础上，`qiankun` 增加了 **JS 隔离** 和 **CSS 隔离** 的能力，并提供了一系列工程化的处理方案，使其更易于在实际项目中落地。

## AI 总结

本视频深入解析了 `single-spa` 微前端框架的底层调度工作原理。当 URL 发生变化时，`single-spa` 通过劫持 `history` 方法和监听原生事件来拦截路由变化，并统一交由 `reroute` 函数处理。随后，通过 `getAppChanges` 计算出需要加载、挂载、卸载和移除的应用列表。在生命周期编排上，严格遵循“先卸载旧应用，并行初始化新应用，等待卸载完成后挂载新应用”的顺序，最后再触发暂存的路由事件通知。这套清晰可预测的机制保证了多应用调度的稳定性，而 `qiankun` 等框架正是基于此原理，进一步扩展了 JS/CSS 隔离等工程化能力。
