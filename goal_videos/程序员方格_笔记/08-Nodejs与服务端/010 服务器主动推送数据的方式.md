## 面试题背景与考察点 *Content-[00:00]

### 面试题目
**Web应用从服务器主动推送 data 到客户端，有哪些方式？**

### 考察背景与目的
- **全站开发视野**：大厂在招聘前端开发人员时，期望候选人不仅精通页面开发，还需具备一定的服务端知识，具备全站开发的视野。
- **业务场景需求**：在股票、金融等需要实时向页面或客户端推送数据的业务场景中，前端人员必须了解服务端数据的来源与推送方式。
- **核心考察点**：区分“客户端主动请求”与“服务器主动推送”。
  - **主动请求**：如发送 AJAX 请求，客户端不请求，服务端就不给数据。
  - **主动推送**：服务端主动将数据“推”给客户端，客户端只需做好接收工作。

## 方式一：WebSocket *Content-[03:11]

### 核心定义
WebSocket 是 HTML5 提供的一种**全双工通讯**协议。它基于 TCP 建立持久连接，允许服务器主动向客户端推送数据。

### 主要特点
- **双向通讯**：客户端和服务端均可主动发送消息，实现双向数据交互。
- **持久连接**：建立 TCP 连接后，数据以“帧”的形式进行传输，无需重复进行 HTTP 握手。
- **性能开销小**：协议头较小，相比传统的 HTTP 请求，性能开销更低。

### 代码实现逻辑（以 Node.js 为例）
- **服务端**：
  1. 导入 WebSocket 库并实例化，监听指定端口。
  2. 监听连接请求，连接成功后，通过 `send` 方法主动向客户端推送数据。
- **客户端**：
  1. 建立 WebSocket 连接。
  2. 绑定 `onmessage` 事件，当服务端推送数据时触发该事件以接收数据，并渲染到页面。
  3. 同样可通过 `send` 方法向服务端发送数据。

### 适用场景
适用于**高频更新**且需要**双向交互**的场景，如：
- 实时聊天系统
- 股票行情实时推送
- 多人协作编辑
- 实时游戏

## 方式二：SSE (Server-Sent Events) *Content-[06:20]

### 核心定义
SSE 是 HTML5 提供的专门用于服务器推送的技术。它基于 HTTP 协议，通过**单向长连接**向客户端发送事件流。

### 主要特点
- **单向通讯**：仅支持服务器向客户端推送数据。如果客户端需要向服务器发送数据，需借助其他方式（如 AJAX）。
- **自动重连**：当连接断开时，浏览器会自动尝试重新建立连接，无需开发者手动处理重连逻辑。
- **简单易用**：支持原生的 `EventSource` API，无需引入额外的第三方库。

### 代码实现逻辑（以 Node.js 为例）
- **服务端**：
  1. 创建 HTTP 服务并监听特定路由地址。
  2. 在该路由下，通过定时器（如每秒一次）不断向客户端发送数据流。
- **客户端**：
  1. 使用 `new EventSource(url)` 建立连接。
  2. 监听 `onmessage` 事件，通过 `event.data` 获取服务端推送的数据。
  3. 监听 `onerror` 事件处理断开提示（浏览器底层会自动执行重连）。

### 适用场景
适用于**不需要客户端回复**的单向数据更新场景，如：
- 实时通知（如系统消息推送）
- 新闻流推送
- 日志实时更新
- 低频的单向数据同步

## 方式三：长轮询 (Long Polling) *Content-[10:52]

### 核心定义
长轮询是指客户端发起一个 HTTP 请求，服务端**挂起该请求**，直到有数据可以发送时才进行响应并立即关闭连接。客户端收到响应后，立即发送新的请求，如此不断循环。

### 主要特点
- **兼容性好**：完全基于标准 HTTP 协议，无需特殊的协议支持或浏览器适配。
- **延迟较高**：每次更新数据都需要重新建立连接，相比 WebSocket 和 SSE，实时性稍差。
- **资源消耗大**：服务端需要维持大量挂起的连接，且频繁建立/关闭连接会带来较大的性能开销。

### 代码实现逻辑
- **客户端**：
  1. 发起 HTTP 请求。
  2. 接收到数据后，立即再次发起新的请求；若发生错误，可设置定时器（如每隔一秒）重试。
- **服务端**：
  1. 接收并挂起客户端的请求。
  2. 等待数据就绪（可设置超时时间，如等待 5 秒）。
  3. 数据到达后返回响应并关闭连接，等待客户端的下一次请求。

### 适用场景
作为 WebSocket 和 SSE 的**补充方案**，适用于：
- 需要兼容老旧浏览器的环境。
- 受限的网络环境（如某些代理或防火墙拦截了 WebSocket 和 SSE）。

## 总结与面试建议 *Content-[14:42]

### 方案选型建议
- **首选方案**：在条件允许的情况下，优先使用 **WebSocket**（双向、高频）或 **SSE**（单向、自动重连）。
- **降级/兼容方案**：当遇到浏览器兼容性限制或网络环境不支持时，使用 **长轮询** 作为兜底方案。

### 面试答题技巧
在面试中回答此题时，建议从以下四个维度进行结构化阐述：
1. **列举方案**：明确说出 WebSocket、SSE、长轮询三种主要方式。
2. **原理解析**：说明每种方式的底层协议（TCP/HTTP）及通讯模式（全双工/单向/请求-响应）。
3. **对比优缺点**：强调 WebSocket 的双向与低开销、SSE 的单向与自动重连、长轮询的兼容性。
4. **结合场景**：给出具体的业务应用场景，展现对技术的实际落地能力。
