## 2. 使用 fs.readFile 读取文件 *Content-[01:30]
- **读取文件方法**：在 `fs` 模块中，读取文件最快的方法是使用 `fs.readFile`。
- **基本语法**：`fs.readFile(path, [options], callback)`
  - `path`：文件路径（例如 `index4.html`）。
  - `options`：文件编码（可选参数，如 `'utf8'`，暂时可不写）。
  - `callback`：回调函数，接收两个参数 `(err, data)`。
    - `err`：文件读取错误信息（作为第一个参数，不能省略）。
    - `data`：读取成功后返回的数据。注意，如果不指定编码，`data` 默认返回的是 **Buffer**（字节/二进制）格式数据。
- **实操演示**：读取 `index4.html` 并在控制台打印 `data`，可以看到输出的是包含多个字节的 Buffer 数据。

## 3. 异步操作与响应结束时机 *Content-[04:13]
- **返回 Buffer 数据**：Buffer 数据可以直接通过 `response.write(data)` 写入响应体，传递给前端页面。
- **常见问题**：直接写入后刷新页面，发现前端没有数据显示。
- **原因分析**：`fs.readFile` 是**异步代码**。如果 `response.end()` 写在 `fs.readFile` 的外部，程序不会等待文件读取完成，而是直接向后执行 `end()` 结束本次响应。等文件读完时，请求已经结束了，导致数据无法返回。
- **解决方案**：将 `response.end()` 移动到 `fs.readFile` 的回调函数内部。确保“不读完数据，就不结束响应”。
- **结果**：重启服务后，刷新页面，HTML 内容正常渲染显示。

## 4. 结合路由返回不同页面 *Content-[06:03]
- **路由分发**：目前未做路由配置，访问任何路径都会返回同一个页面。需要结合 `if...else if...else` 进行路由判断：
  - `if (url === '/')`：读取并返回首页（`index4.html`）。
  - `else if (url === '/404')`：读取并返回 404 页面（`404.html`，内容可自定义，如“页面走丢啦”）。
  - `else`：兜底处理，默认读取并返回 404 页面。
- **注意事项**：每一个路径分支的后面，都需要单独调用 `response.end()` 来结束响应。

## 5. 处理 favicon.ico 与 MIME 类型 *Content-[07:33]
- **处理图标请求**：浏览器在访问页面时，会自动请求 `/favicon.ico` 获取网站小图标。
- **添加图标路由**：增加判断 `else if (url === '/favicon.ico')`，使用 `fs.readFile` 读取本地的 `.ico` 图标文件，并通过 `response.write(data)` 将 Buffer 数据写给页面，最后 `response.end()`。
- **发现问题**：重启后发现图标请求成功，但在浏览器中显示异常。
- **原因分析**：代码上方统一设置了响应头 `Content-Type: text/html; charset=utf-8`。这告诉浏览器返回的数据是 HTML 文本格式。当返回图标数据时，浏览器依然将其作为 HTML 解析，导致显示错误。
- **解决思路**：需要查阅 **MIME 类型表**，为图标设置正确的数据格式（如 `image/x-icon`）。

## 6. 响应头设置问题与最终解决 *Content-[09:31]
- **尝试覆盖失败**：在返回图标前，尝试重新设置 `Content-Type: image/x-icon`，但发现无效，浏览器依然无法正确识别。
- **原因分析**：在 Node.js 中，一旦响应头被设置并准备发送，后续不能简单地通过再次赋值来覆盖。
- **最终解决方案**：放弃在全局统一设置 `Content-Type`。将 `response.setHeader`（或 `writeHead`）移动到每一个 `if/else` 分支内部，针对不同资源单独设置对应的响应头格式：
  - 返回 HTML 页面时：设置 `text/html; charset=utf-8`。
  - 返回 ICO 图标时：设置 `image/x-icon`。
- **结果**：重启服务后，浏览器正确识别图标格式，页面图标完美显示，查看源码也能确认是真正的 ICO 二进制数据。
- **核心结论**：后端给前端返回数据时格式必须严谨，针对不同文件类型必须设置正确的 MIME 响应头。
