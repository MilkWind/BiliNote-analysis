## 1. JSON 的起源与基本概念 *Content-[00:01]

- **字面量对象演化**：JSON 格式是由 JavaScript 的字面量对象（Literal Object）演化而来的。平时我们在 JS 中创建对象时，通常使用字面量方式，例如 `let p = { name: "小强", age: 18 };`。
- **全称与定义**：JSON 的全称为 **JavaScript Object Notation**（JavaScript 对象简谱）。
- **核心优势**：在前后端交互的历史演变中，人们发现 JSON 这种字面量对象的格式最为简洁、通用，且信息存储非常方便。因此，它被确立为前后端交互、跨服务器或跨平台之间数据交互的通用标准格式。

## 2. JSON 的格式与前后端交互流程 *Content-[02:02]

### JSON 的两种格式
JSON 主要分为对象格式和字符串格式，两者在语法严格程度上有所不同：
- **JSON 对象**：可以直接理解为 JavaScript 中的普通对象，语法相对宽松（如属性名可以不加引号）。
- **JSON 字符串**：格式要求非常严格。
  - 属性名（键）必须使用双引号 `""` 包裹。
  - 属性值（值）如果是数字类型，不需要加双引号；如果是字符串类型，则必须加双引号。

### 前后端完整交互流程
在前后端数据交互的过程中，完整的流转步骤如下：
1. **前端数据处理**：前端进行操作获取用户数据，并将其封装成 JS 对象。
2. **前端发送数据**：由于后端只认识 JSON 字符串，前端需要将 JS 对象转换为 **JSON 字符串**，然后发送给后端。
3. **后端数据处理**：后端接收到 JSON 字符串后，将其转换为后端语言（如 Java、Python 等）所对应的对象，进行业务逻辑处理。
4. **后端返回数据**：后端处理完成后，将结果数据对象再次转换为 **JSON 字符串**，返回给前端。
5. **前端渲染数据**：前端接收到 JSON 字符串后，将其转换回自己能够使用的 JS 对象，最终进行页面渲染和显示。

> **核心要点**：
> - 在整个网络传输过程中，传输的数据载体始终是 **JSON 字符串**。
> - 在传输数据时，JS 对象中的 `function`（函数）是不需要也不能传给后端的，因为后端无法使用，我们只需要保留用于存储数据的各种属性即可。

## 3. JSON 对象与字符串的相互转换 *Content-[03:31]

在实际开发中，必须清晰掌握 JSON 对象与 JSON 字符串之间的相互转换，这直接关系到与后端交互数据的解析与处理。

### JSON 对象转 JSON 字符串
- **使用方法**：`JSON.stringify()`
- **作用**：将 JS 对象序列化为 JSON 格式的字符串，以便发送给后端。
- **代码示例**：
  ```javascript
  let p = {
      name: "小强",
      age: 18
  };
  
  // 将 JSON 对象转换为 JSON 字符串
  let jsonString = JSON.stringify(p);
  console.log(jsonString); 
  // 输出结果: {"name":"小强","age":18}
  // 可以看到，属性名和字符串类型的值都加上了双引号，数字类型不加
  ```

### JSON 字符串转 JSON 对象
- **使用方法**：`JSON.parse()`
- **作用**：将后端返回的 JSON 字符串反序列化为 JS 对象，以便前端进行数据处理和页面渲染。
- **代码示例**：
  ```javascript
  let jsonString = '{"name":"小强","age":18}';
  
  // 将 JSON 字符串转换回 JSON 对象
  let obj = JSON.parse(jsonString);
  console.log(obj); 
  // 输出结果: { name: '小强', age: 18 }
  // 恢复为原本的 JS 对象格式，方便前端操作
  ```
