## 1. 课程引入与面试核心问题 *Content-[00:21]
- **面试三大核心追问**：
  1. 语义化到底是什么？
  2. 为什么不用语义标签页面也能显示，却还要用？
  3. `div` + `class` 这种方式能不能代替语义标签？
- **核心认知**：语义化不是规范的洁癖，也不是单纯为了“写得好看”，它真正解决的是**浏览器、搜索引擎、辅助工具如何理解页面结构**。
- **常见误区**：很多开发者认为“别乱用 `div`，应该用 `header`、`nav`、`main`、`footer`”。如果只背这句话，面对“全用 `div` 页面照样显示”的追问时，仅回答“为了 SEO 或规范”会被面试官认定为只会背概念。
- **核心理念**：**HTML 标签不仅是给人看的，更是给机器读结构的**。

## 2. 实例解析：机器视角下的页面结构 *Content-[01:35]
- **常见页面结构示例**：使用 `div` 配合 `class`（如 `header`, `nav`, `content`, `article`, `aside`, `footer`）构建页面。
- **视觉与语义的差异**：
  - **对人类开发者**：通过 `class` 名称（如 `nav` 或 `header`）能看懂结构。
  - **对机器（浏览器/搜索引擎/读屏器）**：`div` 标签本身没有意义，`class` 对机器来说也不等于结构的语义。
- **结论**：全用 `div` 的结构在视觉层面是完整的，但在**语义层面其实是平级的**。机器无法直接识别哪块是导航、哪块是正文、哪块是主内容。

## 3. HTML语义化的标准定义与四大受益系统 *Content-[03:40]
- **标准定义**：HTML 语义化就是用合适的标签表达内容在页面结构中的角色，让非视觉系统也能正确理解页面。
- **四大非视觉系统（受益者）**：
  1. **浏览器内部的结构理解**：基于 DOM 和可访问性树（Accessibility Tree）做的语义推断。
  2. **搜索引擎**：抓取与摘要生成（即 SEO）。
  3. **屏幕阅读器和无障碍工具**：让用户通过结构导航使用页面（即 Accessibility / a11y）。
  4. **团队协作**：团队成员读 HTML 时，不用先看 CSS 就能理解模块作用。
- **HTML 的两层结构**：
  - **内容层**：表示有哪些文字、图片。
  - **结构层**：表示这些内容分别属于哪里（如导航、正文、文章、侧边栏）。
- **职责划分**：CSS 负责“怎么显示”（视觉），HTML 负责“这是什么”（语义）。写 HTML 时不要只想着 CSS（如要不要包一层、做 flex），要把 HTML 当作**结构声明语言**。

## 4. 代码重构：非语义化与语义化版本对比 *Content-[05:24]
- **重构操作**：
  - `div.header` -> `<header>`
  - `div.nav` -> `<nav>`
  - `div.content` -> `<main>`
  - `div.article` -> `<article>`（内部增加 `<h1>` 和 `<p>` 标签）
  - `div.aside` -> `<aside>`
  - `div.footer` -> `<footer>`
  - 删除所有对应的 `class` 名称。
- **样式变化**：语义化版本在样式上没有本质优化，视觉上的微小改变是因为浏览器的 **User Agent Style Sheet**（浏览器自带的默认样式）。
- **结构信息变化**：
  - 浏览器看到 `<nav>` 知道是导航区域。
  - 看到 `<main>` 知道是页面主内容。
  - 看到 `<article>` 当作可独立分发的内容单元。
  - 看到 `<aside>` 理解为附属/补充信息。
- 语义化的目的是让结构**更可被机器利用**，而不是让页面更像规范。

## 5. 面试高频追问：div+class 与 SEO 的误区 *Content-[07:49]
- **问题 1：`div` + `class` 可以等价/替代语义标签吗？**
  - **答案**：不可以。原因有三层：
    1. `class` 是自定义词汇，没有统一标准。
    2. 工具链、解析器、读屏器能直接识别标准语义标签，但不能保证识别自定义 `class`。
    3. 语义标签和 Accessibility 之间有天然映射，`div` 没有默认语义，需要额外补充。
  - **工程重点**：不是能不能用 `div`，而是能否把结构语义表达清楚。
- **问题 2：语义化主要是为了 SEO 吗？**
  - **答案**：答对一半。语义化不等于 SEO，SEO 只是受益者之一。
  - **核心收益**：可访问性（Accessibility）、可维护性、可组合性。面试时应强调**结构理解**。

## 6. 面试加分考点：article 与 section 的区别 *Content-[08:53]
- **`<article>`**：强调**独立性**，可以被单独分发、复用（如一篇文章、一条帖子、一条评论）。
- **`<section>`**：强调**分区**，是页面结构中的一个主题区域，通常内部会有标题。
- **判断口诀**：这块内容拿出去单独放在别的地方还成立吗？如果成立，偏 `<article>`；否则偏 `<section>`。
- **总结**：`<article>` 更像内容实体，`<section>` 更像内容分组。

## 7. 课程总结 *Content-[09:32]
- **本质**：HTML 语义化是用标准标签向机器传递结构信息，而不是为了让代码看起来更规范。
- **认知**：HTML 是结构声明语言，不是样式容器的堆叠。
- **思考方式**：写 HTML 时，不要只想“这个 `div` 要不要包一层”，而要想“这块内容在页面里究竟是什么角色”。
