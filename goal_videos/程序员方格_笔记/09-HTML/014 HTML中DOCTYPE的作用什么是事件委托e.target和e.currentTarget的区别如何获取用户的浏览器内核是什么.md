## HTML 中 DOCTYPE 的作用 *Content-[00:00]

- **基本定义**：`DOCTYPE`（Document Type）声明是 HTML 文档中的第一行代码，通常写为 `<!DOCTYPE html>`。
- **核心作用**：用于告诉浏览器当前页面所遵循的 HTML 版本规范。在现代 Web 开发中，它主要用于声明当前文档为 **HTML5** 标准。
- **版本与规范**：HTML 存在多个历史版本，但在目前的常规项目中，只需在文档顶部编写 `<!DOCTYPE html>` 这一行声明即可满足需求。
- **缺失的后果**：如果不写 `DOCTYPE` 声明，浏览器会默认使用老旧的**怪异模式**（Quirks Mode）来渲染页面。这会导致不同浏览器下的页面显示效果不一致，从而引发严重的跨浏览器兼容性问题。

## 什么是事件委托 *Content-[00:55]

- **应用场景**：假设有一个 `ul` 元素，其内部包含多个 `li` 子元素，业务需求是为每一个 `li` 绑定点击事件。
- **性能痛点**：如果为每一个 `li` 单独调用 `addEventListener` 去绑定事件，会产生大量的 DOM 事件监听器，对页面性能造成显著的负面影响。
- **解决方案（事件委托）**：
  - 利用 DOM 的**事件冒泡机制**，将子元素的事件统一委托给其父元素来处理。
  - 具体操作：只需在父元素 `ul` 上绑定一次事件监听器。当用户点击内部的 `li` 时，事件会向上冒泡到 `ul` 并被触发。
  - **精准定位**：在事件处理函数中，通过事件对象（Event Object）的 `event.target` 属性，即可准确判断出用户具体点击的是哪一个 `li` 元素，从而执行相应的逻辑。

## event.target 和 event.currentTarget 的区别 *Content-[01:40]

这两个属性在事件委托和事件处理中非常关键，它们的区别如下：

- **event.currentTarget**：
  - **定义**：指**事件绑定（监听）的元素节点**。
  - **特性**：无论事件是从哪里触发的，`currentTarget` 始终指向你绑定事件监听器的那个元素。
  - **示例**：如果将点击事件绑定在 `ul` 上，即使用户实际点击的是内部的 `li`，事件冒泡到 `ul` 触发时，`event.currentTarget` 依然指向 `ul`。简而言之，“事件绑在谁身上，它就是谁”。

- **event.target**：
  - **定义**：指**实际触发事件的元素节点**。
  - **特性**：它指向用户鼠标实际点击或交互的那个最具体的 DOM 元素。
  - **示例**：在上述场景中，如果用户点击了某个 `li`，那么 `event.target` 指向的就是该 `li` 元素。简而言之，“鼠标点的是谁，它就是谁”。

## 如何获取用户的浏览器内核 *Content-[02:27]

- **核心对象**：在浏览器环境中，可以通过全局对象 **`navigator`** 来获取用户浏览器的相关信息。
- **具体实现**：
  - 通过调用 `navigator.appCodeName` 属性，可以获取到浏览器的内核名称。
  - `navigator` 对象包含了大量与浏览器环境相关的属性，全面打印该对象（如在控制台执行 `console.log(navigator)`）可以查看到浏览器的详细配置和内核信息。
- **面试回答技巧**：在实际面试中，如果一时想不起具体的属性名（如 `appCodeName` 或常用的 `userAgent`），可以重点强调“通过浏览器全局的 `navigator` 对象来获取”，并说明可以通过打印该对象来查阅包含浏览器内核在内的各项详细信息。这种回答方式既展现了扎实的基础，又体现了灵活解决问题的能力。
