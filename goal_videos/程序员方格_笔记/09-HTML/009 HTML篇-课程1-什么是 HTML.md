## 课程介绍与底层认知 *Content-[00:00]

欢迎大家来到前端高频面试题系列课程。本节课我们将围绕 HTML 与 CSS 面试的底层认知开始讲起。

在正式开始前，相信大家已经不是不会写页面的新手，能够写出各种布局并使用组件库解决业务问题。但在面试时，经常会被一些看似简单却很难说清楚的问题问住，例如：
- 浏览器到底怎么解析你写的 HTML？
- 为什么 div 标签默认会换行？
- DOM 和 HTML 是不是一回事？

如果这些问题答得模糊，很容易给面试官留下“你会用，但没有理解”的印象。因此，这门课程不是教怎么背标签或过一遍 CSS 属性，而是带大家**站在浏览器的视角**，把 HTML 和 CSS 的底层规则讲清楚。我们会发现所有面试都在过同一条主线：**浏览器如何把文本变成页面**。

今天第一节，从最基础的一句问法开始：**HTML 到底是什么？**

## 拆解直觉：浏览器默认样式 *Content-[01:14]

初学 HTML 时，我们对它的定义通常是：“HTML 就是用标签写页面结构，然后浏览器把它渲染出来”。例如写一个 `h1` 标签展示大标题，写一个 `p` 标签显示文字，写一个 `button` 显示按钮。

在没有写 CSS 的情况下刷新浏览器，能看到很大的标题、段落间距以及带有边框和背景的按钮。于是我们自然得出结论：**HTML 负责页面结构，CSS 负责美化页面**。

这个结论在日常写业务时没问题，但会在面试中让人掉坑，因为它把两件本质不同的东西混在一起了：
1. **文档的结构与语义**
2. **显示效果**

我们在屏幕左边看到的最终显示效果，通常会误以为是 HTML 自己决定的。但为什么只写 HTML 没写 CSS，页面也能“像模像样”（按钮像按钮，标题像标题）？

这里埋下了第一个核心点：**浏览器自己就带着一套默认的样式**。我们看到的“像样”，并不是因为 HTML 规定了样式，而是浏览器在帮助我们兜底。

因此，我们需要建立一个新习惯：**不要从我们看到的页面出发去理解 HTML，而是要从浏览器如何理解 HTML 出发**。

## HTML的本质：标记与语义 *Content-[03:11]

HTML 的全称是 **Hypertext Markup Language**。这里最关键的词不是 Hypertext，而是 **Markup**（标记）。

所谓标记语言，意思是你写的不是“怎么画”，而是“这是啥”。更直观地说，HTML 的工作方式更像**给文档做标注**。就像拿到一份 Word 文档，用“标题一、标题二、正文、引用、代码块”去标注内容。标注的目的不是为了好看，而是为了告诉工具这段内容的**角色、结构和层级**是什么。

当我们写 `h1` 标签和 `p` 标签时，真正要表达的是：
- `h1`：这是一段一级标题，在结构上是一个重要的标题层级。
- `p`：这是一段正文的段落。

这两个标签代表了两个不同**语义**的内容块。在 HTML 的世界里（或浏览器理解 HTML 时），**语义优先于外观**。
- 同样的内容，用 `h1` 写就是标题语义，用 `div` 写就是没有语义的分组容器。
- 虽然用 CSS 可以把 `div` 和 `h1` 变得一样大（外观看起来一样），但在语义层面它们完全不一样。
- 语义会影响搜索引擎、无障碍工具（阅读器）以及浏览器内部的很多规则。

**核心结论**：
**HTML 的本质是文档结构的描述语言，而不是界面的描述语言。**

之所以会被误解为界面描述语言，是因为浏览器把结构渲染成了可视化的界面，让我们以为“结构 = 界面”。但要记住：**结构只是信息，界面是呈现方式**，呈现方式是由浏览器和 CSS 共同决定的，而不是 HTML 单独决定。

**面试回答话术**：
> “HTML 的职责是提供语义和结构，让浏览器能够构建 DOM；渲染效果主要来自于 CSS 及浏览器的默认样式。”

## 浏览器渲染主干流程 *Content-[06:08]

站在浏览器视角，从 HTML 加载到页面渲染发生的主干流程如下（后续课程会详细展开渲染链路）：

1. **读取文本**：浏览器拿到 HTML 文本（即 response body）。
2. **HTML 解析**：启动 **HTML Parser**（解析器），从上到下边读边解析字符流。
3. **构建 DOM Tree**：解析的结果不是页面，而是一棵结构树，称为 **DOM Tree**。它由节点（如 document, element, text, comment 等）组成，每个标签变成一个节点对象，节点间有父子关系。此时有了结构，还没有样式。
4. **构建 CSSOM**：CSS 也会被解析成一棵树，叫做 **CSSOM**（CSS 对象模型）。
5. **生成 Render Tree**：DOM 和 CSSOM 在后续阶段结合，构建出一棵只包含可见节点的树，称为 **Render Tree**。
6. **Layout（布局）**：计算每个盒子在页面上的几何信息（如位置和大小）。
7. **Paint（绘制）**：生成颜色、文字、边框等绘制指令。
8. **Composite（分层合成）**：把图层合成到屏幕上。

**核心链路记忆**：
HTML 构建出 DOM Tree -> CSS 构建出 CSSOM -> 二者结合生成 Render Tree -> Layout -> Paint -> Composite。

## 经典面试题：为什么 div 会换行？ *Content-[08:15]

这是一个特别经典的反直觉实验：
在 HTML 中写一个 `div` 和一个 `span`，刷新后 `div` 后面自动换行，而 `span` 后面不换行。

- **常见错误回答**：“因为 div 是块级元素。”
- **面试官追问**：“为什么 div 是块级元素？”
- **正确答案**：div 默认换行，是因为浏览器的 **User Agent Style**（浏览器默认样式表）给 div 设置了 `display: block` 的默认规则，而 span 没有这样的规则。

**核心结论**：
**HTML 并没有写 div 要换行，这个换行来自于浏览器的默认样式（User Agent Style Sheet）。**

## 核心概念辨析：HTML 与 DOM 的区别 *Content-[09:27]

HTML 和 DOM 不是同一种东西：
- **HTML**：是一段文本，属于源代码。
- **DOM**：是浏览器解析 HTML 之后，从内存里构建出来的一棵**对象树**。

在 JavaScript 中，我们通常操作的是 DOM 节点对象，而不是 HTML 本身。例如使用 `document.querySelector` 或 `getElementById` 拿到的是一个 element 对象，它上面有属性（如 `parentNode`, `children`）和方法。
- 修改 `textContent` 或 `className`，实际上是在修改 DOM 状态。
- 如果使用 `innerHTML`，它会把字符串重新交给解析器，再生成新的 DOM 节点。这个过程是有性能成本的，所以 `innerHTML` 是一个更重的操作。

**面试回答话术**：
> “DOM 是浏览器解析 HTML 后生成的内存数据结构，JS 操作的是 DOM，而 HTML 是原文本。”

## 课程核心总结 *Content-[10:52]

本节课的核心内容可以归纳为以下三句话：

1\. **HTML 是文档结构与语义的描述**，它不是界面样式的描述。
2\. **我们看到的默认的显示效果**，很大一部分来自于浏览器的默认样式表（User Agent Style），而不是 HTML 自己决定的。
3\. **HTML 是文本**，DOM 是浏览器解析后的内存结构，JS 操作的是 DOM。

## AI 总结

本节课从“浏览器视角”重新定义了 HTML，打破了初学者“HTML 负责画页面”的直觉误区。核心要点在于明确 HTML 的本质是**标记语言**，其职责是描述**文档的结构与语义**，而非控制外观。页面默认的视觉效果实际上是由浏览器的 User Agent Style 兜底提供的。

此外，课程梳理了浏览器的核心渲染链路（HTML -> DOM -> Render Tree -> Layout -> Paint -> Composite），并通过“div 换行”和“HTML 与 DOM 的区别”两个高频面试题，深入剖析了默认样式的作用机制以及源代码与内存对象树的本质差异。掌握这些底层认知，能帮助开发者在面试中展现出对前端基础原理的深刻理解，而不仅仅停留在 API 的使用层面。
