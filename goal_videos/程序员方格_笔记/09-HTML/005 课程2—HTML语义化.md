## 什么是HTML语义化 *Content-[00:21]
- 面试中常被问到的三个核心问题：
  1\. 语义化到底是什么？
  2\. 为什么不用语义标签页面也能显示，却还要用？
  3\. `div` 加 `class` 的方式能不能代替语义标签？
- **常见误区**：认为语义化只是“规范的洁癖”或“写得好看一点”，或者仅仅停留在“别乱用 `div`，应该用 `header`、`nav`、`main`、`footer`”的表层记忆。
- **核心认知**：HTML 标签不仅是给人看的，更是给机器读结构的。语义化真正解决的是浏览器、搜索引擎、辅助工具如何理解页面结构。如果面试时只回答“为了 SEO”或“为了规范”，会被认定为只会背概念，缺乏深度理解。

## 语义化的核心定义与受益者 *Content-[03:36]
- **核心定义**：HTML 语义化就是用合适的标签表达内容在页面结构中的角色，让非视觉系统也能正确理解页面。
- **非视觉系统（四大受益者）**：
  1\. **浏览器内部的结构理解**：基于 DOM 和可访问性树（Accessibility Tree）做的语义推断。
  2\. **搜索引擎**：搜索引擎的抓取与摘要生成（即 SEO）。
  3\. **屏幕阅读器和无障碍工具**：让用户通过结构导航使用页面（即 Accessibility / a11y）。
  4\. **团队协作**：团队其他成员在阅读 HTML 时，不用先看 CSS 就能理解模块的作用。
- 语义化并不是简单地把 `div` 换成新标签，而是在声明结构的角色。

## HTML的两层结构：内容层与结构层 *Content-[04:41]
- **内容层**：表示页面有哪些文字、图片等具体内容。
- **结构层**：表示这些内容分别属于哪里（如导航、正文、文章、侧边栏）。
- **职责划分**：
  - CSS 负责“怎么显示”（视觉）。
  - HTML 负责“这是什么”（语义）。
- 写 HTML 时，不要只想着 CSS（如要不要包一层、要不要做 flex），而要把 HTML 当作一门结构声明的语言。

## 代码重构：非语义化 vs 语义化 *Content-[05:24]
- **非语义化版本**：
  - 使用大量 `div` 标签，通过 `class` 名（如 `header`、`nav`、`content`、`article`、`aside`、`footer`）来区分角色。
  - 对人类开发者来说能看懂，但对机器来说，`div` 本身没有意义，`class` 也不等于结构的语义。视觉层面完整，但语义层面是平级的。
- **语义化版本重构**：
  - 将 `div` 替换为对应的语义标签：`<header>`、`<nav>`、`<main>`、`<article>`、`<aside>`、`<footer>`。
  - 删除多余的 `class` 名（如 `class="header"`）。
  - 在 `<article>` 内部添加 `<h1>` 表示标题，`<p>` 表示段落。
- **重构后的变化**：
  - 样式上变化不大（主要受浏览器的 User Agent Style Sheet 默认样式影响）。
  - 结构信息发生本质变化：浏览器看到 `<nav>` 就知道是导航，看到 `<main>` 知道是主内容，看到 `<article>` 当作可独立分发的内容单元，看到 `<aside>` 理解为附属/补充信息。
  - 结构图对比：非语义化结构充斥 `div`，靠 `class` 区分；语义化结构每个节点都在声明角色，结构更清晰。

## div+class 能否替代语义标签 *Content-[07:49]
- 面试回答：**不可以**。原因有三层：
  1\. `class` 是开发者自己定义的词汇，没有统一标准。
  2\. 很多工具链、解析器、读屏器能直接识别标准的语义标签，但不能保证识别自定义的 `class` 名称。
  3\. 语义标签和 Accessibility（无障碍）之间有天然的映射关系，`div` 没有默认语义，需要额外补充（如 ARIA 属性）。
- 工程上的重点不是“能不能用 `div`”，而是能否把结构语义表达清楚。

## 语义化与 SEO 的关系 *Content-[08:31]
- 语义化**不等于** SEO，SEO 只是语义化的受益者之一。
- 语义化更核心的收益是：**可访问性（Accessibility）**、**可维护性**和**可组合性**。
- 面试时不能只说“为了 SEO”，要强调是为了“结构理解”。

## 面试加分项：article 与 section 的区别 *Content-[08:53]
- `<article>`：强调**独立性**，可以被单独分发、单独复用。例如：一篇文章、一条帖子、一条评论。
- `<section>`：强调**分区**，是页面结构中的一个主题区域，通常内部会有标题。
- **简单判断法则**：这块内容拿出去单独放在别的地方还成立吗？如果成立，就偏向使用 `<article>`；`<article>` 更像内容实体，`<section>` 更像内容分组。

## 课程总结 *Content-[09:28]
- HTML 语义化的本质：用标准标签向机器传递结构信息，而不是为了让代码看起来更规范。
- HTML 是结构声明语言，不是样式容器的堆叠。
- 写 HTML 时的核心思考：不要想“这个 `div` 要不要包一层”，而要想“这块内容在页面里究竟是什么角色”。

## AI 总结
本节课深入剖析了 HTML 语义化的本质，指出其核心并非单纯的代码规范或为了 SEO，而是通过标准标签向机器（浏览器、搜索引擎、辅助工具）传递清晰的结构信息。通过对比非语义化（`div`+`class`）与语义化标签的差异，强调了 HTML 作为结构声明语言的重要性。掌握语义化不仅能提升页面的可访问性与可维护性，还能在面试中展现出对前端底层逻辑的深刻理解。
