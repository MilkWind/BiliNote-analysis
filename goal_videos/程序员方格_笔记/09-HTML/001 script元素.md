## 1. script 标签的核心职责与用途 *Content-[00:00]
- **核心职责**：`<script>` 标签是连接 HTML 和 JavaScript 的桥梁，是在任何 Web 开发项目中都绕不开的核心标签，用于将 JS 嵌入到 HTML 页面中。
- **两个主要用途**：
  1. **内部嵌入代码**：直接在 HTML 页面内部的 `<script>` 标签中包裹可以直接在浏览器执行的 JS 脚本代码。
  2. **引入外部文件（更常用）**：通过 `src` 属性引入外部的 JS 文件。这种方式能够让代码结构更加清晰，也更易于后期维护。
- **解析机制**：浏览器在解析 HTML 文档时，一旦遇到 `<script>` 标签，就会暂停解析，开始下载并执行其中的脚本，这一行为对页面的加载性能有极大的影响。

## 2. script 标签的核心属性：src 与 type *Content-[01:45]
- **`src` 属性**：用于指定外部脚本的地址（路径）。当需要引入外部 JS 文件时，必须通过该属性指定正确的路径。
- **`type` 属性**：
  - 过去该属性是必须指定的（如 `type="text/javascript"`），但现在浏览器默认会将 `<script>` 标签内的内容当作 JavaScript 来处理，因此在常规情况下通常可以省略。
  - **例外情况**：如果需要加载 ES6 模块，则必须显式设置 `type="module"`，此时该属性不可省略。

## 3. 性能优化关键属性：async 与 defer *Content-[02:52]
- **默认行为（阻塞问题）**：默认情况下，浏览器遇到 `<script>` 标签会暂停解析 HTML，立即下载并执行脚本，执行完毕后才继续解析后续的 HTML。如果脚本文件较大或网络较慢，会导致页面出现长时间的白屏。
- **`async`（异步模式）**：
  - **机制**：告诉浏览器继续解析 HTML，脚本的下载与 HTML 解析并行进行，解决了下载阻塞问题。
  - **执行时机**：脚本一旦下载完成，浏览器会立即暂停 HTML 解析并执行该脚本。
  - **特点与局限**：无法保证多个脚本的执行顺序（取决于哪个脚本先下载完成）。
  - **适用场景**：脚本之间没有依赖关系，需要尽快执行的场景。
- **`defer`（延迟模式）**：
  - **机制**：同样是并行下载，不阻塞 HTML 解析。
  - **执行时机**：将脚本的执行延迟到**整个 HTML 文档解析完成之后**。
  - **特点**：**严格按照脚本在代码中出现的顺序执行**。
  - **适用场景**：脚本之间存在依赖关系，或者需要操作 DOM（文档对象模型）的场景，是更安全、更可靠的选择。

## 4. 安全与模块化相关属性 *Content-[04:49]
- **`crossorigin` 与 `integrity`（安全增强）**：
  - 这两个属性通常配合使用，用于从公共 CDN 加载第三方库时增加安全性。
  - `integrity`：提供一个文件的哈希值。浏览器下载文件后会计算其哈希值并与提供的值进行比对，如果不匹配（说明文件可能已被篡改），浏览器将拒绝执行该脚本。
  - `crossorigin`：用于配置跨域请求的相关策略。
- **`nomodule`（渐进增强策略）**：
  - 用于处理老旧浏览器不支持 ES 模块（`type="module"`）的兼容性问题。
  - 现代浏览器支持 ES 模块，会直接忽略带有 `nomodule` 属性的普通脚本。
  - 老旧浏览器不支持 ES 模块，会忽略 `type="module"` 的脚本，转而执行带有 `nomodule` 属性的备用普通脚本。
- **`referrerpolicy`（隐私保护）**：
  - 用于控制 HTTP `Referer` 头的发送策略，从而增强用户的隐私保护。

## 5. 脚本在 HTML 中的放置位置与最佳实践 *Content-[07:17]
- **传统做法：放在 `<head>` 标签中**
  - **优点**：脚本逻辑可以先于页面内容执行。
  - **缺点**：严重阻塞浏览器解析 HTML。浏览器从上到下解析，遇到 `<head>` 中的脚本必须等待其下载和执行完毕，如果脚本多或网络慢，会导致用户面对空白页面等待过久。
- **现代最佳实践：放在 `<body>` 元素末尾（`</body>` 前）**
  - **优点**：浏览器可以先完整渲染页面的结构和样式，让用户第一时间看到内容。随后再加载和执行脚本进行事件绑定、数据获取等交互逻辑，能极大改善加载性能和用户体验。
- **折中策略：配合 `defer` 放在 `<head>` 中**
  - 如果页面某些内容必须依赖 JS 才能显示，可以将带有 `defer` 属性的脚本放在 `<head>` 中。这样既不阻塞页面渲染，又能让脚本尽早开始下载。

## 6. 课程总结 *Content-[09:15]
- `<script>` 标签是连接 HTML 和 JavaScript 的桥梁，用于嵌入代码或引用外部文件。
- `async` 和 `defer` 是必须掌握的性能优化属性，能让脚本下载不阻塞页面解析。其中 `defer` 因能保证执行顺序且在 DOM 渲染后执行，适用性更广，是大多数情况下的首选方案。
- 从实践角度看，将脚本放到 `<body>` 标签底部是保证用户尽快看到页面内容最简单、最有效的方法。
