## 课程介绍与底层认知 *Content-[00:00]
- **课程定位**：本课程不是教开发者死记硬背标签，也不是简单过一遍 CSS 属性，而是带大家站在浏览器的视角，把 HTML 和 CSS 的底层规则讲清楚。
- **核心主线**：所有的面试考点本质上都在围绕同一条主线——**浏览器如何把文本变成页面**。
- **面试痛点**：很多开发者能熟练写出各种布局、使用组件库解决业务问题，但在面试中遇到“浏览器如何解析 HTML”、“为什么 div 默认换行”、“DOM 和 HTML 的区别”等看似简单的问题时，往往回答模糊。这会给面试官留下“只会用，但没有深入理解”的印象。

## 常见误区：HTML 负责结构，CSS 负责样式？ *Content-[01:14]
- **初学者的直觉**：写 `<h1>` 显示大标题，写 `<p>` 显示段落，写 `<button>` 显示按钮。由此得出结论：HTML 负责页面结构，CSS 负责美化页面。
- **拆解误区**：这种直觉在日常写业务时没问题，但在面试中会掉坑，因为它把两件本质不同的事情混为一谈了：
  1. **文档的结构与语义**
  2. **显示效果**
- **核心真相**：我们在页面上看到的“像样”的显示效果（如按钮有边框、标题有大小），并不是 HTML 自己规定的样式，而是**浏览器自带了一套默认样式（User Agent Style）** 在帮忙兜底。
- **认知转变**：不要从“看到的页面效果”出发去理解 HTML，而是要从“浏览器如何理解 HTML”出发。

## HTML 的本质：文档结构与语义的描述语言 *Content-[03:11]
- **全称解析**：HTML 全称为 HyperText Markup Language，最核心的词是 **Markup（标记）**。
- **标记语言的含义**：标记语言的工作方式更像给文档做标注。写的不是“怎么画”，而是“这是啥”。就像给 Word 文档标注“标题一”、“正文”、“引用”，目的是告诉工具这段内容的角色、结构和层级是什么。
- **语义优先于外观**：
  - `<h1>` 表达的是“一级标题”的语义和重要的层级结构。
  - `<p>` 表达的是“正文段落”的语义。
  - 如果使用 `<div>`，它只是一个没有语义的分组容器。即使通过 CSS 把 `<div>` 和 `<h1>` 的字体大小改得一模一样，它们在语义层面也完全不同。
- **语义的影响**：语义会直接影响搜索引擎的抓取、无障碍工具（如屏幕阅读器）的解析，以及浏览器内部的很多默认规则。
- **核心结论**：HTML 的本质是**文档结构与语义的描述语言**，而不是界面的描述语言。界面呈现是由浏览器和 CSS 共同决定的。
- **面试回答技巧**：“HTML 的职责是提供语义和结构，让浏览器能够构建 DOM；渲染效果主要来自于 CSS 及浏览器的默认样式。”

## 浏览器解析流程：从 HTML 到页面渲染 *Content-[06:08]
浏览器拿到 HTML 后，将其转化为可视化页面的主干流程如下：
1. **读取文本**：浏览器首先读取到一段文本，即 HTTP 响应中的 response body。
2. **HTML 解析**：启动 HTML Parser（解析器），从上到下边读边解析字符流。解析的结果不是页面，而是一棵由节点（Document、Element、Text、Comment 等）组成的结构树，称为 **DOM Tree**。
3. **CSS 解析**：CSS 也会被解析成一棵树，称为 **CSSOM**（CSS 对象模型）。
4. **生成渲染树**：DOM Tree 和 CSSOM 结合，构建出一棵只包含可见节点的树，称为 **Render Tree**。
5. **布局 (Layout)**：计算每个盒子在页面上的几何信息（如位置和大小）。
6. **绘制 (Paint)**：生成颜色、文字、边框等具体的绘制指令。
7. **分层合成 (Composite)**：将各个图层合成并最终渲染到屏幕上。
- **核心记忆点**：HTML 构建 DOM Tree，CSS 构建 CSSOM，二者结合生成 Render Tree，之后才进入 Layout、Paint 和 Composite。

## 经典实验：为什么 div 默认会换行？ *Content-[08:15]
- **现象**：在 HTML 中，`<div>` 标签后面的内容会自动换行，而 `<span>` 标签后面不换行。
- **常见错误回答**：“因为 div 是块级元素。”（如果这样回答，面试官通常会追问：为什么 div 是块级元素？）
- **正确答案**：`<div>` 默认换行，是因为浏览器的 **User Agent Style（默认样式表）** 给 `div` 设置了 `display: block` 的默认规则。而 `span` 没有这样的默认规则。
- **核心结论**：HTML 标签本身并没有写“div 要换行”，换行效果完全来自于浏览器的默认样式表。

## 核心辨析：HTML 与 DOM 的区别 *Content-[09:29]
- **HTML**：是一段纯文本，属于源代码。
- **DOM**：是浏览器解析 HTML 之后，在内存中构建出来的一棵**对象树**（内存数据结构）。
- **JS 的操作对象**：JavaScript 操作的是 DOM 节点对象（如通过 `document.querySelector` 或 `getElementById` 获取），而不是 HTML 文本本身。
- **DOM 节点的特性**：DOM 节点对象包含属性和方法（如 `parentNode`、`children`、`textContent`、`className`）。修改这些属性，实际上是在修改 DOM 的内存状态。
- **`innerHTML` 的性能代价**：使用 `innerHTML` 修改内容时，浏览器会把传入的字符串重新交给 HTML 解析器，重新生成新的 DOM 节点。这是一个有性能成本的重操作。
- **面试回答技巧**：“DOM 是浏览器解析 HTML 后生成的内存数据结构，JS 操作的是 DOM，而 HTML 是原文本。”

## 本节课程总结 *Content-[11:27]
1\. **HTML 是文档结构与语义的描述，它不是界面样式的描述。**
2\. **我们看到的默认显示效果，很大一部分来自于浏览器的默认样式表（User Agent Style），而不是 HTML 自己决定的。**
3\. **HTML 是文本，DOM 是浏览器解析后的内存结构，JS 操作的是 DOM。**

## AI 总结
本节课程从浏览器底层视角重新定义了 HTML。核心要点在于打破“HTML 负责画页面”的直觉误区，明确 HTML 的本质是**描述文档结构与语义的标记语言**，而非界面描述语言。页面默认的视觉效果源于浏览器的 User Agent Style。此外，课程详细梳理了浏览器从解析 HTML 生成 DOM Tree，到结合 CSSOM 生成 Render Tree，最终完成 Layout、Paint 和 Composite 的完整渲染链路。最后，清晰界定了 HTML（源代码文本）与 DOM（内存中的对象树）的本质区别，为后续深入理解前端渲染机制与性能优化打下了坚实的认知基础。
