## JavaScript 预解析实战场景 17 *Content-[00:00]

本示例主要探讨在函数内部未使用关键字声明变量时，预解析机制及作用域查找导致的报错问题。

### 1\. 代码结构还原
根据视频讲解，示例 17 的核心代码如下：
```javascript
function fn() {
    console.log(a);
    a = 13;
}
fn();
```

### 2\. 预解析阶段分析
- 当代码执行到 `fn` 函数内部时，会开启一个新的局部作用域并进行预解析。
- 在函数体内，变量 `a` 的赋值（`a = 13`）前面**没有**使用 `var`、`let` 或 `const` 等关键字进行声明。
- 因此，在预解析阶段，局部作用域（仓库）中**不会**提升变量 `a`。预解析完毕后，局部仓库中没有任何关于 `a` 的记录。

### 3\. 逐行执行阶段分析
- 执行到第一行 `console.log(a);` 时，引擎会尝试查找变量 `a`。
- 由于局部作用域中没有 `a`，且全局作用域中也没有定义过 `a`，此时访问未定义的变量会直接触发报错。
- **报错信息**：`a is not defined`（注：视频语音识别为 `defend`，实际应为 `defined`）。
- **执行结果**：代码在此处报错并中断，后续代码不再执行。

## JavaScript 预解析实战场景 18 *Content-[02:49]

本示例基于示例 17 进行改进，重点考察全局隐式变量与函数局部作用域之间的交互及预解析机制。

### 1\. 代码结构还原
```javascript
a = 12; // 第1行
function fn() { // 第2行
    console.log(a); // 第3行
    a = 13; // 第4行
}
fn(); // 第6行
console.log(a); // 第7行
```

### 2\. 全局预解析阶段
- 引擎在全局作用域进行预解析，找到函数声明 `function fn`，并将其提升。
- 第1行的 `a = 12` 没有使用 `var` 关键字，因此在预解析阶段**不会**提升变量 `a`。
- 全局预解析完毕后，全局作用域仓库中只有：`fn = function() {...}`。

### 3\. 全局逐行执行阶段
- **第1行**：`a = 12;`。由于没有使用 `var` 等关键字，`a` 会被隐式声明为**全局变量**，并赋值为 12。此时全局 `a = 12`。
- **第2行**：函数声明，不改变值，直接跳过。
- **第6行**：`fn();` 发生函数调用，程序进入 `fn` 的局部作用域。

### 4\. fn 函数内部执行阶段
- **局部预解析**：开启新的局部作用域，函数内部没有 `var` 声明，因此局部预解析仓库为空。
- **局部逐行执行**：
  - **第3行**：`console.log(a);`。局部作用域中没有 `a`，引擎向上层（全局作用域）查找，找到全局变量 `a`，此时其值为 12。因此，控制台输出 **12**。
  - **第4行**：`a = 13;`。没有使用关键字，直接修改全局变量 `a` 的值。全局 `a` 由 12 变为 13。
- 函数执行完毕，返回全局作用域。

### 5\. 全局继续执行阶段
- **第7行**：`console.log(a);`。此时访问的是全局变量 `a`。由于在 `fn` 函数内部 `a` 的值已被修改为 13，因此控制台输出 **13**。

### 6\. 最终结果验证
- 控制台依次输出：
  ```text
  12
  13
  ```
- 在浏览器执行环境中验证，结果与分析完全一致。

## AI 总结 *Content-[09:41]

本视频深入解析了 JavaScript 中的预解析（变量与函数提升）机制及其在实际代码中的执行表现。通过两个实战示例，核心要点如下：
1\. **隐式全局变量不提升**：未使用 `var`/`let`/`const` 声明直接赋值的变量，在预解析阶段不会被提升。如果在赋值前访问该变量，且全局也未定义，则会报 `is not defined` 错误（示例 17）。
2\. **作用域链查找**：函数内部访问变量时，若局部作用域未找到，会沿作用域链向上查找全局变量（示例 18 中输出 12）。
3\. **全局变量的修改**：在函数内部对未加关键字的变量进行赋值，若全局已存在该变量，则会直接修改全局变量的值，影响后续的全局执行（示例 18 中全局 `a` 被修改为 13）。
掌握这些底层机制，有助于在面试中准确分析复杂的变量作用域和预解析问题。
