## 面试题解析：变量到底存在哪 *Content-[00:00]
- **面试题背景**：在全局作用域中，使用 `const` 和 `let` 声明的变量，不像使用 `var` 定义的变量那样放在 `window` 对象上。
- **核心疑问**：`let` 和 `const` 定义的变量到底存储在哪里？如何获取并访问到它们？
- **考察目的**：考察应聘者对变量存储环境的理解，即不同变量定义方式在底层存储位置的差异，以及是否在日常开发中关注到了这一底层细节。

## var 与 let/const 的存储位置区别 *Content-[01:42]
- **var 的存储机制**：
  - 使用 `var` 定义的全局变量会自动成为 `window` 对象的一个属性。
  - **代码示例**：定义 `var a = 10;`，可以通过 `window.a` 进行访问，变量会自动绑定为 `window` 的属性。
- **let/const 的存储机制**：
  - 使用 `let` 和 `const` 声明的全局变量**不会**绑定到 `window` 对象上，无法通过 `window.变量名` 访问。
  - 它们存储在**词法环境（Lexical Environment）** 中（在宏观上表现为脚本作用域或模块作用域）。
  - **词法环境（Lexical Environment）**：是 JavaScript 引擎内部用于跟踪变量或函数声明的一种数据结构，它与执行上下文（Execution Context）绑定。
  - 例如，在函数内定义的变量保存在函数的词法环境中；在函数外定义的全局变量保存在词法环境的全局上下文中。
  - 全局的 `let` 和 `const` 存储在全局词法环境中，但该环境不会暴露到 `window` 对象上，即不会作为 `window` 的属性来保存变量值。

## 为什么不将 let/const 绑定到 window 对象 *Content-[05:47]
- **设计决策与历史遗留问题**：
  - `var` 绑定到 `window` 实际上是一种历史遗留的妥协方案。早期 JavaScript 只有全局作用域和函数作用域，为了标识和访问全局变量，只能将其放入 `window` 中。
  - `let` 和 `const` 的引入是为了解决变量提升和全局变量污染问题。在设计这两个新关键字时，官方明确区分了绑定行为，决定不再沿用 `var` 的历史遗留问题，从而避免全局污染。
- **支持块级作用域（Block Scope）**：
  - `let` 和 `const` 支持块级作用域（即大括号 `{}` 内的作用域）。
  - 如果将块级作用域内的 `let` 和 `const` 变量绑定到 `window` 对象上，块级作用域的隔离性就会被彻底破坏。因为开发者依然可以通过 `window.变量名` 在外部访问到这些本应被隔离的变量，导致块级作用域失去意义。

## 如何显式访问 let/const 定义的全局变量 *Content-[09:12]
- 在现代 ES6 及模块化时代，不再推荐通过 `window` 来访问全局变量。
- **推荐方式：使用 ES6 模块化（Modules）**：
  - 在定义变量的文件（如 `a.js`）中，使用 `export` 将变量（如 `data`）导出。
  - 在需要访问该变量的文件（如 `b.js`）中，使用 `import` 将变量从 `a.js` 中导入。
  - 导入后即可直接使用该变量。这种方式科学、优雅，且符合现代浏览器的执行规范。
- **现代浏览器的执行变化**：
  - 在现代浏览器的模块化执行环境下，即使是使用 `var` 定义的变量，默认也不再挂载到 `window` 对象上。因此，不能再依赖 `window` 来访问全局变量，拥抱模块化是必然趋势。

## 核心知识点总结 *Content-[11:30]
- **存储位置**：`let` 和 `const` 声明的全局变量存储在**词法环境**中，而不是 `window` 对象中（这与 `var` 有本质区别）。
- **访问方式**：在变量所属的作用域内，直接通过**变量名**进行访问即可，无需通过 `window` 对象。
- **模块化隔离**：在模块化环境中，全局变量默认是隔离和独立的。若需跨文件访问，必须通过 `export` 导出和 `import` 导入的方式来实现，这也是目前最推荐的变量共享方式。

## AI 总结 *Content-[12:56]
本次面试核心探讨了 `let`/`const` 与 `var` 在全局变量存储位置上的本质差异。`var` 由于历史原因将全局变量挂载于 `window` 对象，而 `let`/`const` 则将其存储于引擎内部的**词法环境（Lexical Environment）** 中，以支持块级作用域并避免全局污染。在现代前端开发中，应摒弃通过 `window` 访问全局变量的旧习惯，全面采用 ES6 模块化（`export`/`import`）来进行科学、优雅的变量管理与跨文件共享。
