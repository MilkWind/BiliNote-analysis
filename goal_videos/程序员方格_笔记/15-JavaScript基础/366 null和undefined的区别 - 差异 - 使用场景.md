## 核心原则 *Content-[00:00]
在开发中，最忌讳把 `null` 和 `undefined` 混用。
**核心原则**：让 `undefined` 自动出现，手动赋值时只使用 `null`。

## null 的语义化使用场景 *Content-[00:49]

### 1\. 场景一：声明将来要存储对象的变量初始化
- **规范说明**：这是开发中的规范（不遵守不会报错，但会显得不专业）。明确表示该变量的用途是存储对象，目前还未赋值，语义清晰。
- **正确做法**：假如定义了一个将来要存储对象的变量，初始化为 `null`（如 `let user = null;`），同事一看就知道 `user` 里面未来放的是对象。如果赋值为 `undefined`，则语义不明确。
- **补充延伸**：声明将来要存储数组的变量，初始值也应该是 `null`，因为数组属于引用数据类型。

### 2\. 场景二：解除对象引用，让垃圾回收机制（GC）回收内存
- **原理**：GC（Garbage Collection，垃圾回收器）负责回收内存。当一个对象不再需要使用时，手动将其赋值为 `null`，可以切断变量和对象的引用关系。
- **效果**：使对象变成游离状态，GC 会在合适的时机回收该对象的内存，从而避免内存泄漏。

### 3\. 场景三：作为原型链的终点
- **原理**：JS 中所有对象的原型链最终都会指向 `Object.prototype`。
- **终点**：`Object.prototype.__proto__` 的值是 `null`，这就表示到了原型链的尽头，没有上层原型了。
- **完整链路**：实例对象 -> `__proto__` -> 构造函数原型 -> `__proto__` -> `Object.prototype` -> `__proto__` -> `null`。

### 4\. 场景四：访问不存在的 DOM 元素返回 null
- **原理**：DOM 是独立于 JS 的外部 API，遵循自身的规范。
- **表现**：访问页面中不存在的 DOM 元素时（例如使用 `document.getElementById('no-exist')`），返回的是 `null` 而不是 `undefined`。

### 5\. 场景五：正则匹配失败时返回 null
- **原理**：使用字符串的 `match` 方法匹配正则时，遵循特定的返回规范。
- **表现**：如果匹配失败，返回 `null`；如果匹配成功，则返回包含匹配结果的数组。

## undefined 的语义化使用场景（返回 undefined 的情况） *Content-[07:43]
面试官常问：“哪些情况下会返回 undefined？” 以下是 7 种典型情况：

### 1\. 情况一：声明变量未赋值
- 变量只声明不赋值，JS 引擎会自动给其赋值为 `undefined`。

### 2\. 情况二：函数调用时形参未传值
- 函数定义时要求多个参数，但在调用时如果没有给某个形参传值（实参缺失），该形参的默认值就是 `undefined`。

### 3\. 情况三：访问对象不存在的属性
- 访问对象上没有定义的属性时，JS 引擎不会报错，而是自动返回 `undefined`。

### 4\. 情况四：访问数组不存在的索引
- 数组的索引是连续的，当访问超出数组长度的索引（即不存在的索引）时，会自动返回 `undefined`。

### 5\. 情况五：函数没有 return 语句
- JS 中所有的函数都有返回值。如果没有手动写 `return` 语句，函数执行完后会自动返回 `undefined`。

### 6\. 情况六：使用 void 操作符
- `void` 是 JS 的一元操作符，作用是执行表达式，但返回纯粹的 `undefined`。
- **开发技巧**：开发中常用 `void 0` 来获取不受全局变量污染的、最原始的 `undefined`。

### 7\. 情况七：全局作用域中的 window.undefined
- `undefined` 是全局对象 `window` 的一个属性，其值就是原始的 `undefined`。
- **对比 null**：`null` 是 JS 的关键字，不能被赋值，也不是任何对象的属性。通过 `'undefined' in window` 返回 `true`，而 `'null' in window` 返回 `false` 可以验证。
- **不可修改性**：在最新版本的浏览器中，禁止手动修改 `window.undefined`（例如 `window.undefined = 123` 是无效的），它始终保持为原始的 `undefined`。

## AI 总结
本视频详细讲解了前端面试中高频考点 `null` 和 `undefined` 的区别与使用场景。核心原则是“`undefined` 自动出现，手动赋值只用 `null`”。
- **`null`** 主要用于手动干预的场景，如：对象/引用类型变量的初始化、解除对象引用以协助 GC 回收内存、作为原型链的终点、以及 DOM 查询和正则匹配失败时的系统返回值。
- **`undefined`** 则代表“缺失”或“未定义”的默认状态，主要用于：变量声明未赋值、函数形参未传值、访问不存在的对象属性或数组索引、函数无返回值、`void` 操作符求值，以及作为 `window` 对象的固有属性。
