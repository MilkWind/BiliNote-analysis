## 事件流与三个阶段回顾 *Content-[01:55]

- **什么是事件流**：
  - 当点击页面上的一个元素（如 `button`）时，事件并不是只在该元素上触发，而是会按照特定的顺序在 DOM 树中进行传播。

- **事件流的三个阶段**：
  1\. **捕获阶段（Capture Phase）**：
     - 事件从最顶层开始，自上而下传播。
     - 传播顺序：`window` 对象 -> `document` 对象 -> `html` 标签 -> `body` 标签 -> ... -> 目标元素。
  2\. **目标阶段（Target Phase）**：
     - 事件到达真正触发的元素（例如上述例子中的 `button` 元素），此时处于目标阶段。
  3\. **冒泡阶段（Bubble Phase）**：
     - 事件从目标元素自下而上回传到顶层。
     - 传播顺序与捕获阶段相反：`button` -> `body` -> `html` -> `document` -> `window`。

## 阻止事件冒泡的实际应用场景 *Content-[04:24]

- **为什么要阻止事件冒泡**：
  - 事件源本身可能没有处理事件的能力，或者处理事件的函数并未绑定在该元素上。
  - 实际开发中常利用事件冒泡机制实现**事件委托**（Event Delegation）。
  - 但在某些特定场景下，事件冒泡会干扰正常的事件处理机制，此时就需要主动阻止事件冒泡。

- **实际项目场景举例**：
  - **业务需求**：在一个移动端少儿比赛项目中，点击“参赛规则”按钮打开一个弹窗。弹窗没有传统的“×”关闭按钮，而是通过**点击弹窗外部的空白区域**来关闭弹窗。
  - **冲突点**：点击按钮打开弹窗时，点击事件会冒泡到外层容器或 `document`，从而触发关闭弹窗的逻辑，导致弹窗刚打开就立刻被关闭。

## 弹窗关闭功能的代码实现与问题复现 *Content-[05:48]

- **代码实现步骤**：
  1\. **获取 DOM 元素**：
     - 获取“参赛规则”按钮：`const openBtn = document.getElementById('open');`
     - 获取弹窗容器：`const layout = document.getElementById('layout');`（初始状态为 `display: none`）。
  2\. **实现打开弹窗功能**：
     - 给按钮添加点击事件监听：`openBtn.addEventListener('click', () => { layout.style.display = 'block'; });`
  3\. **实现点击空白关闭弹窗功能**：
     - 给 `document` 添加点击事件监听：`document.addEventListener('click', () => { layout.style.display = 'none'; });`

- **问题复现与原因分析**：
  - **现象**：点击“参赛规则”按钮后，弹窗并没有成功显示（或者闪现后立刻消失）。
  - **原因**：当点击按钮时，按钮的点击事件触发，弹窗被设置为 `display: block`。紧接着，该点击事件**冒泡**到了 `document`，触发了 `document` 上的点击事件回调，又将弹窗设置为了 `display: none`。
  - **解决方案引出**：为了解决这个问题，需要在按钮的点击事件回调中调用 `event.stopPropagation()` **阻止事件冒泡**，防止事件传递到 `document` 触发关闭逻辑。
