## 1. 面试题引入与核心考点 *Content-[00:01]
- **面试题目**：`['1', '2', '3'].map(parseInt)`
- **核心考点**：本题主要考察对 JavaScript 中数组的 `map` 遍历方法以及 `parseInt` 解析函数的深入理解。
- **常见误区**：许多初学者看到题目会感到困惑，不清楚为什么可以直接将 `parseInt` 函数名作为参数传递给 `map` 方法，而不是使用括号进行函数调用。

## 2. map 方法基础回顾 *Content-[00:40]
- **基本用法**：`map` 是数组的一个实例方法，用于遍历数组并返回一个新数组。
- **回调函数参数**：`map` 方法需要传入一个回调函数，该回调函数默认接收两个主要参数：
  - **第一个参数**：数组的当前元素（`item`）。
  - **第二个参数**：当前元素对应的索引值（`index`）。
- **示例说明**：遍历数组 `[1, 2, 3]` 时，回调函数接收到的 `item` 依次为 `1, 2, 3`，对应的 `index` 依次为 `0, 1, 2`。

## 3. parseInt 方法基础回顾 *Content-[01:30]
- **基本功能**：`parseInt` 是一个全局函数，主要目的是从字符串中解析并提取出一个整数。
- **基础示例**：对于字符串 `'123'`，使用 `parseInt('123')` 解析后，返回的是数字类型的 `123`。

## 4. 面试题代码拆解与执行原理 *Content-[02:11]
- **函数名作为参数**：在 JavaScript 中，函数名本身就代表整个函数实体。因此，将 `parseInt` 直接传给 `map`，相当于把整个函数交给了 `map` 来处理。
- **参数传递机制**：当 `map` 遍历数组时，会将当前元素（`item`）和索引（`index`）作为参数传递给 `parseInt`。
- **等价代码拆解**：
  ```javascript
  ['1', '2', '3'].map(parseInt) 
  // 等价于以下执行过程：
  parseInt('1', 0)
  parseInt('2', 1)
  parseInt('3', 2)
  ```

## 5. 深入解析 parseInt 的第二个参数（进制） *Content-[03:26]
- **查阅 MDN 文档**：`parseInt` 实际上可以接收两个参数。
  - **第一个参数**：需要解析的字符串。如果传入的不是字符串，系统会自动将其转换为字符串。
  - **第二个参数**：基数（进制），表示要解析的进制数，范围是 `2 ~ 36` 之间的整数（如 2 进制、8 进制、10 进制、16 进制等）。
- **基数为 0 或未指定的规则**：
  - 如果第二个参数为 `0`、`undefined` 或未传递，`parseInt` 会根据字符串的值自动推算进制。
  - 如果字符串以 `0x` 或 `0X` 开头，按 **16 进制** 解析。
  - 如果字符串以 `0` 开头，按 **8 进制** 解析（注：ES5 之后严格模式下不再支持前导 0 的 8 进制，默认按 10 进制处理，但视频主要讲解传统推算逻辑）。
  - 其他情况默认按 **10 进制** 解析。
- **非法返回值**：如果解析失败或数字超出了指定进制的表示范围，则返回 `NaN`（Not a Number）。

## 6. 逐次迭代过程详细推导 *Content-[04:35]
结合 `map` 传入的 `item` 和 `index`，对 `['1', '2', '3'].map(parseInt)` 进行逐次拆解：

- **第一次迭代**：
  - **参数**：`item` = `'1'`，`index` = `0`。
  - **执行**：`parseInt('1', 0)`。
  - **解析**：第二个参数为 `0`，触发自动推算规则。字符串 `'1'` 没有特殊前缀，被推算为 10 进制。数字 `1` 在 10 进制中合法。
  - **结果**：`1`。

- **第二次迭代**：
  - **参数**：`item` = `'2'`，`index` = `1`。
  - **执行**：`parseInt('2', 1)`。
  - **解析**：第二个参数为 `1`，即尝试按 1 进制解析。1 进制本身不合法（类似于 2 进制逢 2 进 1，1 进制逢 1 进 1，不存在数字 `2`）。且传入的字符串 `'2'` 超出了 1 进制所能表示的范围。
  - **结果**：`NaN`。

- **第三次迭代**：
  - **参数**：`item` = `'3'`，`index` = `2`。
  - **执行**：`parseInt('3', 2)`。
  - **解析**：第二个参数为 `2`，即按 2 进制（二进制）解析。2 进制只能包含数字 `0` 和 `1`，而传入的字符串 `'3'` 超出了 2 进制的合法范围。
  - **结果**：`NaN`。

## 7. 面试题最终结论与总结 *Content-[08:07]
- **最终输出结果**：`[1, NaN, NaN]`。
- **错误原因剖析**：
  - 开发者误将 `map` 的第二个参数（索引 `index`）当作了 `parseInt` 的第二个参数（进制 `radix`）传入。
  - 由于索引值（`0, 1, 2`）作为进制时，要么触发特殊的 0 进制推算，要么传入了非标准的进制数（如 1 进制），导致后续解析失败并返回 `NaN`。
- **避坑指南**：在使用 `map` 结合其他自带多参数的函数（如 `parseInt`、`Number` 等）时，务必注意回调函数隐式传递的参数数量，避免因参数错位导致逻辑错误。正确做法通常是使用箭头函数显式控制参数：
  ```javascript
  ['1', '2', '3'].map(item => parseInt(item))
  // 或者
  ['1', '2', '3'].map(Number)
  ```
