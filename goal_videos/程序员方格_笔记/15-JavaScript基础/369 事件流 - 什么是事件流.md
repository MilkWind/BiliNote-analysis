## 什么是事件流与生活案例解析 *Content-[01:34]
在深入理解事件流之前，先思考一个小问题：*点击按钮时，除了按钮本身，还有哪些元素会收到事件？*

为了更好理解，可以通过一个生活案例来类比：
- 假设你在公司前台签收快递。
- 这个“签收”动作不仅是你和快递员之间的互动。
- 公司的前台、部门主管、甚至行政人员可能都会知道这件事。
- 这种信息从具体事件点向周围扩散的过程，就是**事件传播**。

在 JavaScript 中，**事件流**就是事件发生后，在元素节点和根节点之间的传播顺序。点击按钮时，事件不仅在该按钮上触发，还会沿着 DOM 树向上或向下传播，所有经过的节点都会感知到这个事件。

## 点击按钮时的事件传播范围 *Content-[04:29]
回到开头的小问题，如果页面上只有一个按钮，点击它之后，事件会向上传播。因此，除了按钮本身，以下元素都会收到该事件：
- `body`
- `document`
- `window`
- `html`

这意味着，在页面上点击按钮，不仅仅是按钮接收到了事件，它的父级及更上层的祖先节点都能接收到。

## 同心圆比喻与 DOM 节点传播 *Content-[05:05]
可以通过“同心圆”的视觉比喻来加深理解：
- 想象画在纸上的一组同心圆。
- 如果把手指放在最中心的圆心，手指指向的不仅仅是圆心本身，而是纸上的**所有圆**。
- 同理，在 DOM 结构中，触发最内层的按钮（圆心），也相当于触发了它的父元素（如 `div`）、爷爷元素（如 `body`）以及更外层的元素。

**DOM 结构传播示例**：
假设页面结构为：`window` -> `document` -> `html` -> `body` -> `div` -> `button`。
当点击 `button` 时：
- 不仅点击了 `button`。
- 同时也点击了包含它的 `div`。
- 进而也点击了 `body`、`html`、`document` 和 `window`。
这就是整个事件在 DOM 树中的传播过程。

## DOM 事件流的标准定义 *Content-[07:25]
综合以上内容，可以得出 DOM 事件流的标准概念：
- **事件流**描述的是从页面中接收事件的顺序。
- 事件发生时，会在元素节点与根节点之间按照特定的顺序进行传播。
- 所有经过的节点都会收到该事件。
- 这个完整的传播过程就是 **DOM 事件流**。

## 事件流的历史由来与 W3C 标准 *Content-[08:17]
事件流的概念在早期浏览器发展中经历过分歧与统一：

- **早期分歧**：
  - **IE 浏览器**：提出了**事件冒泡**（Event Bubbling）。事件从目标元素向上传递到根元素（从具体元素到不具体元素，如 `button` -> `div` -> `body` -> `window`）。
  - **Netscape（网景）浏览器**：提出了**事件捕获**（Event Capturing）。事件从根元素向下传递到目标元素（从不具体元素到具体元素）。
  - 这两种机制的传播方向是完全相反的。

- **W3C 统一标准**：
  - 后来 W3C（万维网联盟）制定了统一标准。
  - 规定完整的 **DOM 事件流包含三个阶段**：
    1. **事件捕获阶段**（Capture Phase）
    2. **目标阶段**（Target Phase）
    3. **事件冒泡阶段**（Bubbling Phase）
  - 现代浏览器（除早期 IE 外）均支持并遵循这一 W3C 标准。
