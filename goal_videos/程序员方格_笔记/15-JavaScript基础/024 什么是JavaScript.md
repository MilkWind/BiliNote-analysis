## JavaScript 的诞生与早期发展 *Content-[00:42]
- **早期背景**：在 Web 发展的早期，浏览器只能展示静态内容。为了解决客户端输入验证的问题，避免每次数据校验都要往返服务器，产生了对客户端脚本语言的需求。
- **诞生（1995年）**：网景公司（Netscape）的工程师 Brendan Eich 在极短的时间内开发出了这门语言，内部代号“Mocha”。为了蹭当时 Java 语言的热度，最终定名为 JavaScript。这也导致至今仍有许多人混淆 Java 和 JavaScript，但实际上两者在技术实现上差异巨大。
- **浏览器竞争（1996年）**：随着网景浏览器的成功，微软在 IE3 中推出了类似的实现，命名为 JScript。这导致浏览器之间存在两套不同的脚本语言标准，给开发者带来极大的困扰。
- **ECMAScript 的诞生（1997年）**：
  - 为了解决标准不一的问题，网景公司将 JavaScript 交给 ECMA 组织，希望制定统一的标准。
  - 1997年，ECMA-262 第一版发布，正式确立了 ECMAScript（简称 ES）作为这门语言的标准规范。
  - **核心目标**：统一语言的语法和语义，消除不同浏览器厂商实现上的差异。自此，JS 摆脱了野蛮生长，成为一门公认的标准化的主流编程语言。

## 现代 JavaScript 的三大组成部分 *Content-[03:03]
通常我们所说的 JavaScript，实际上是由三个截然不同的部分构成的：
- **ECMAScript（核心）**：语言的基础，定义了变量声明、循环、函数定义等语法和逻辑处理规则。
- **DOM（文档对象模型）**：负责连接 HTML 文档，让 JS 能够识别并修改页面上的元素（如改变文字颜色、插入新图片）。
- **BOM（浏览器对象模型）**：负责连接浏览器环境，让 JS 能够控制浏览器窗口本身的行为（如弹出新窗口、获取屏幕分辨率、读取历史记录）。
- **总结**：ECMAScript 提供基础语法能力，DOM 提供操作页面内容的能力，BOM 提供操作浏览器窗口的能力。三者缺一不可。

## 深入理解 ECMAScript 核心规范 *Content-[04:53]
- **定位**：ECMAScript 是语言的核心规范，不仅适用于浏览器环境，也适用于 Node.js 等服务器环境。只要掌握了 ECMAScript，就掌握了在不同环境中编写逻辑的核心能力。
- **底层机制**：规定了编程语言最底层的机制，包括：
  - 语法和流程控制语句（如 `if` 判断、`for` 循环）。
  - 数据类型（如数字、字符串、布尔值等）。
  - 对象和函数的定义方式。
- **作用**：提供编写 JS 代码的语言规范，是所有 JavaScript 代码的底层基础。

## ECMAScript 版本演进与关键标准 *Content-[06:06]
ES 标准由专门的委员会负责制定和维护，以下是几个关键的时间节点：
- **ES5（2009年）**：
  - 在很长一段时间内是浏览器的通用标准。
  - 引入严格模式（Strict Mode）以规范代码编写。
  - 增加原生 JSON 支持以及 `forEach`、`map` 等数组方法，大幅提升开发效率。
- **ES6 / ES2015（2015年）**：
  - 里程碑式的革命性更新。
  - 引入 `let`、`const`（块级作用域）、`Promise` 等关键特性。
  - 使 JavaScript 真正具备了编写大型复杂应用的能力。
- **后续小版本迭代（2015年之后）**：
  - 官方调整策略，改为每年发布一个小版本，保持语言的持续迭代。
  - **ES2017**：带来 `async/await` 特性，让异步代码读起来像同步代码一样清晰，极大改善了异步编程的体验。
  - 随后的版本中陆续加入各种新特性，不断完善开发者的编码体验。

## DOM 文档对象模型详解 *Content-[07:57]
- **本质与作用**：DOM 是一套 API，充当 JS 和 HTML 页面之间的桥梁。如果没有 DOM，JS 就无法感知页面的存在，也无法对页面进行任何修改。
- **核心思想**：将整个页面文档看作一个由节点构成的层级结构。HTML 页面中的每一个标签、每一段文本、每一个属性在 DOM 中都被抽象成一个节点对象。
- **功能**：通过 DOM 提供的接口，开发者可以使用脚本动态地访问和更新文档的内容、结构甚至 CSS 样式（如动态添加按钮、修改标题文字）。
- **DOM 树结构**：
  - 浏览器解析 HTML 代码后，会生成一个倒置的树状结构（DOM 树）。
  - `<html>` 标签是根节点，分叉出 `<head>` 和 `<body>` 子节点，`<body>` 下又包含 `<p>` 节点及文本节点。
  - 这种树状结构定义了节点之间的层级关系，JS 正是沿着这条路径精确定位并操作具体的节点。
- **DOM 标准演进**：
  - **DOM Level 1**：主要专注于核心文档结构和 HTML 元素的映射，支持基本的节点操作。
  - **DOM Level 2**：功能得到极大扩展，最重要的是引入了标准化的事件模型（如 `addEventListener`）以及 CSS 样式操作接口，使处理用户交互和动态变更样式更加优雅。
  - **DOM Level 3**：功能进一步扩展，增加了内容加载和保存的能力，以及对 XML 的验证支持。

## BOM 浏览器对象模型详解 *Content-[11:06]
- **关注点**：与 DOM 关注页面内容不同，BOM 关注的是承载页面的容器——浏览器本身。
- **标准化情况**：在很长一段时间内，BOM 并没有像 DOM 那样有非常严格的标准，不同浏览器厂商各自制定规范，导致实现上存在较多差异。
- **核心对象 `window`**：
  - **双重身份**：
    1. JS 访问浏览器窗口的接口（如控制窗口大小/位置、设置 `setTimeout` 定时器等）。
    2. ECMAScript 规范规定的全局对象（Global Object）。在全局作用域中定义的各种变量和函数，本质上都变成了 `window` 对象上的属性。
- **其他实用对象**：
  - **`navigator`**：常用于判断当前用户使用的是什么浏览器，或区分 PC 端与手机端。
  - **`location`**：负责管理地址栏，可用于获取当前 URL 或跳转新页面。
  - **`history`**：现代单页应用（SPA）的前端路由实现，很大程度上依赖其提供的 API。
  - **`performance`**：提供非常精确的性能监测数据，对于性能优化来说至关重要。

## 课程总结与回顾 *Content-[13:29]
- 当我们谈论 JavaScript 时，讨论的不只是一门语言，而是一个由三部分组成的完整体系：
  - **ECMAScript (ES)**：JS 的基石，定义了变量、逻辑、语法的编写规则，是所有 JS 实现的通用基础。
  - **DOM**：页面元素接口，能够用代码去读取、修改、删除页面上的 HTML 元素和样式。
  - **BOM**：浏览器应用接口，能够控制浏览器窗口的行为，处理导航和历史记录等环境相关的任务。
- 只有深入理解了这三个部分的职责和边界，才能在开发中写出更加清晰、更加健壮的代码。
