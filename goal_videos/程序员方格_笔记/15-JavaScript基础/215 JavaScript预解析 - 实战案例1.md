## 1. 示例一：变量预解析 *Content-[00:05]

本案例主要考察变量提升（预解析）的基本机制。

**代码逻辑：**
```javascript
console.log(a);
var a = 1;
```

**执行过程分析：**
1. **预解析阶段**：
   - 预解析器会寻找代码中的 `var`、`function` 以及函数参数。
   - 发现 `var a`，将其放入“预解析仓库”中，并赋予初始值 `undefined`。
   - 此时预解析仓库中的状态为：`a = undefined`。
2. **执行代码阶段**：
   - 逐行执行代码。
   - 第一行执行 `console.log(a)`，此时引擎从预解析仓库中获取 `a` 的值。
   - 因为 `a` 在预解析阶段只声明未赋值，值为 `undefined`，所以最终输出结果为 `undefined`。

## 2. 示例二：变量未定义报错 *Content-[02:45]

本案例考察当变量完全未被声明时的执行结果。

**代码逻辑：**
```javascript
console.log(a);
```

**执行过程分析：**
1. **预解析阶段**：
   - 预解析器寻找 `var`、`function` 和参数。
   - 代码中均不存在这些关键字，因此预解析仓库为空（空空如也）。
2. **执行代码阶段**：
   - 逐行执行代码，第一行执行 `console.log(a)`。
   - 由于预解析仓库中没有变量 `a`，引擎在全局和当前作用域中均无法找到该变量。
   - 最终抛出错误：`a is not defined`（变量未定义）。

## 3. 示例三：变量与函数预解析 *Content-[04:12]

本案例考察变量与函数同时存在时的预解析及执行顺序。

**代码逻辑：**
```javascript
alert(a);
var a = 1;
function fn() {
    alert(2);
}
alert(a);
```

**执行过程分析：**
1. **预解析阶段**：
   - 寻找 `var` 和 `function`。
   - 发现 `var a`，仓库中记录 `a = undefined`。
   - 发现 `function fn`，仓库中记录 `fn = function() { alert(2); }`。
2. **执行代码阶段**：
   - 第一行执行 `alert(a)`，此时从仓库中取值，`a` 的值为 `undefined`，输出 `undefined`。
   - 第二行执行 `var a = 1`，变量 `a` 被重新赋值为 `1`。
   - 第三行为函数声明 `function fn() { alert(2); }`。**注意**：函数声明本身如果没有被调用，不会改变任何变量的值，也不会执行函数体内的代码。
   - 因此，第一个 `alert(a)` 的结果确认为 `undefined`。

## 4. 示例四：变量与函数同名预解析（PK机制） *Content-[07:25]

本案例是预解析中的高频难点，考察变量与函数同名时的“PK（覆盖）机制”。

**代码逻辑：**
```javascript
var a = 1;
function a() {
    alert(2);
}
var a = 3;
function a() {
    alert(4);
}
alert(a);
```

**预解析阶段（核心 PK 机制）：**
1. **遇到 `var a`**：
   - 预解析仓库中记录 `a = undefined`。
2. **遇到 `function a() { alert(2) }`**：
   - 仓库准备存入 `a = function() { alert(2); }`。
   - 此时与之前的 `undefined` 发生 PK。
   - **PK 规则 1**：`undefined` 代表没有值，函数代表有值。**有值的胜出**，且与上下文顺序无关。
   - 结果：`a = function() { alert(2); }` 胜出。
3. **遇到 `var a = 3`**：
   - 预解析阶段只提升声明，即准备存入 `a = undefined`。
   - 与现有的 `function` 再次 PK。
   - 同样适用“有值胜出”规则，`function` 保留。
   - 结果：`a` 依然是 `function() { alert(2); }`。
4. **遇到 `function a() { alert(4) }`**：
   - 仓库准备存入 `a = function() { alert(4); }`。
   - 与现有的 `function() { alert(2); }` 发生 PK。
   - **PK 规则 2**：当两个都有值（都是函数）时，**遵循上下文顺序，后面的声明会覆盖前面的声明**。
   - 结果：`function() { alert(4); }` 胜出。

**最终预解析结果：**
- 预解析仓库中最终保留的值为 `a = function() { alert(4); }`。
- 后续执行代码时，若调用 `a()` 或打印 `a`，均以此最终函数为准。

## AI 总结

JavaScript 的预解析（变量提升与函数提升）是理解代码执行顺序的核心。在预解析阶段，引擎会提前将 `var` 声明的变量提升并赋值为 `undefined`，将 `function` 声明的函数整体提升。当变量与函数同名时，函数提升的优先级高于变量提升（有值覆盖无值）；当存在多个同名函数提升时，则遵循代码的上下文顺序，后声明的函数会覆盖先声明的函数。掌握这一“PK机制”，能够准确推断复杂代码的执行结果。
