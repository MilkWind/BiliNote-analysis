## 1. 清空数组的六种方法及特点 *Content-[00:02]

在面试中，当被问及“你知道哪几种清空数组的方法”时，可以回答以下六种方法及其核心特点：

1. **`splice` 方法**：不会断开数组引用，能够同步清空关联数组，但写法稍显复杂。
2. **`length` 属性赋值为零 (`arr.length = 0`)**：性能最优，可清空 `const` 声明的数组，不会断开引用，是大厂开发者和面试的最优解与首选。
3. **直接赋值空数组 (`arr = []`)**：写法简单，但会断开原数组的引用关系，且不能用于 `const` 声明的数组，仅适合简单场景。
4. **`delete` 运算符配合循环**：属于伪清空，会留下空位且数组长度不变，性能差，绝对不推荐。
5. **`pop` 配合循环**：循环删除最后一个元素，性能较差，仅作为知识点了解。
6. **`shift` 配合循环**：循环删除首元素，且后续元素会前移，性能最差，无实用价值。

## 2. const声明的数组清空与报错原因 *Content-[01:17]

**问题**：`const` 声明的数组可以清空吗？如果可以怎么清空？为什么赋值空数组会报错？

**解答**：
- `const` 声明的数组**可以清空**，推荐使用 `arr.length = 0` 的方法。
- **原理**：`const` 声明数组时，仅保证数组在内存中的**引用地址不变**，不保证数据的内部内容不变。
- **`arr.length = 0`**：只是修改了数据的内部内容，并未更改引用地址，符合 `const` 的约束，因此不会报错。
- **`arr = []`**：是让变量重新指向了一个新的空数组，相当于修改了数据的引用地址，违反了 `const` 的语法约束，因此会报赋值错误（TypeError）。

## 3. 断开数组引用使另一变量不受影响 *Content-[02:04]

**问题**：如何让两个指向同一数组的变量，其中一个清空后，另一个不受影响？

**解答**：
- **方法**：使用 `arr = []`（直接赋值为空数组）的方法清空其中一个变量。
- **原理**：该方法会让变量断开对原数组的引用，重新指向内存当中的一个新空数组。原数组不会被任何修改，因此另一个指向原数组的变量也不会受到任何影响，两者互不相干。

## 4. delete运算符不能真正清空数组的原因 *Content-[02:41]

**问题**：为什么 `delete` 运算符不能真正清空数组？它的核心问题是什么？

**解答**：
`delete` 运算符属于“伪清空”，其核心问题有两个：
1. **仅删除值，不删除下标**：`delete` 仅删除数组元素的值，不会删除数组的下标位置，删除后会留下空位元素（空属性）。
2. **不改变 length 属性**：`delete` 不会改变数组的 `length` 属性，数组长度始终和原数组一致，只是里面的元素是空的。

**结论**：最终得到的不是真正的空数组，且性能较差，实际开发中绝对不推荐使用。

## 5. 开发中清空数组的最优解及大厂推荐原因 *Content-[03:31]

**问题**：开发中清空数组的最优解是什么？为什么大厂都推荐这个方法？

**解答**：
- **最优解**：`arr.length = 0`。
- **大厂推荐的三大原因**：
  1. **性能最优**：直接修改数组的 `length` 属性，无任何额外计算和循环操作。
  2. **兼容性最好**：能适配 `let`、`var`、`const` 所有声明方式的数组。
  3. **引用友好且简单**：不会断开数组的引用关系，适配所有需要保留数组引用的开发场景，且写法简单易记。

## 6. 数组引用与同步清空代码解析 *Content-[04:04]

**问题**：以下代码中 `newArr` 的结果是什么？并解释原因。
```javascript
let arr = [1, 2, 3];
let newArr = arr;
arr.length = 0;
console.log(newArr);
```

**解答**：
- **结果**：`newArr` 的结果为空数组 `[]`。
- **原因**：`arr.length = 0` 这种清空方式**不会断开数组的引用关系**。`newArr` 和 `arr` 在内存当中指向的是同一块堆数据。当 `arr` 被清空后，这块共享的数据被清空，因此 `newArr` 同步受到影响，输出为空。

## 7. const数组使用splice清空的代码解析 *Content-[04:46]

**问题**：以下代码执行会报错吗？为什么？执行后 `console.log(arr)` 的结果是什么？
```javascript
const arr = [1, 2, 3];
arr.splice(0);
console.log(arr);
```

**解答**：
- **结果**：**不会报错**，`console.log(arr)` 的结果是空数组 `[]`。
- **原因**：`splice` 方法只是修改数组的内部内容，并未改变 `const` 声明数组在内存当中的引用地址。它完全符合 `const` 的语法约束，因此不会报错，且能成功清空数组。

## 8. 清空数组方法是否断开引用关系总结 *Content-[05:23]

**问题**：清空数组中哪些会断开数组引用关系？哪些不会？

**解答**：
- **会断开数组引用关系的方法**：
  - 直接赋值为空数组 (`arr = []`)
- **不会断开数组引用关系的方法**（原数组和指向它的其他变量会同步变化）：
  - `splice` 方法
  - `length` 属性赋值为零 (`arr.length = 0`)
  - `delete` 运算符配合循环
  - `shift` 配合循环
  - `pop` 配合循环

## 9. pop与shift循环清空数组的性能问题 *Content-[05:51]

**问题**：`pop`、`shift` 循环清空数组的性能问题是什么？为什么不推荐使用？

**解答**：
两者的核心性能问题在于**循环次数太多**：
- **`pop` 循环**：每次仅删除数组最后一个元素。数组元素越多，循环次数越多，且每次执行 `pop` 都会重新计算数组长度。
- **`shift` 循环**：每次删除数组的第一个元素。除了循环次数多的问题外，删除后数组的所有**后续元素都会向前移动一位**。元素越多，移动次数越多，耗时越长，性能比 `pop` 更差。

**结论**：两者均无实际开发价值，仅作为 JS 的基础知识了解。面试时如果提到这两种方法以及 `delete`，一定要准确说明它们的性能缺点。

## 10. 判断真正的空数组与delete伪数组 *Content-[06:39]

**问题**：如何判断一个数组是真正的空数组，而不是 `delete` 后的伪数组？

**解答**：
- **判断方法**：通过判断数组的 `length` 属性是否为 `0` 来区分。
- **真正的空数组**：`length` 属性为 `0`。
- **`delete` 后的伪数组**：虽然数组内的元素都是空位，但 `length` 属性和原数组保持一致（始终大于 0）。例如原数组长度为 5，`delete` 清空后 `length` 依旧是 5，因此它不是真正的空数组。

## 11. 面试模拟与总结 *Content-[07:15]

**模拟面试场景**：
假设你现在面试大厂（如字节跳动）的前端实习生，面试官提问：
> “为什么 `const` 声明的数组能用 `arr.length = 0` 清空，却不能用 `arr = []` 清空？”

**答题核心思路**：
这道题考察的是对 JavaScript 内存管理和 `const` 底层原理的理解。回答时需点明：`const` 锁定的是内存中的**引用地址**而非**内部数据**。`arr.length = 0` 修改的是内部数据，地址未变，故合法；而 `arr = []` 改变了引用地址，指向了新的内存空间，故触发 `const` 的赋值报错。
