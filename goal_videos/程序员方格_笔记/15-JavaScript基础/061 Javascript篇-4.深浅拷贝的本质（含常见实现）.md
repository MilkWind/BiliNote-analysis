## 1. 核心概念：深浅拷贝的本质 *Content-[00:49]

- **讨论范围**：所有拷贝问题均围绕 JavaScript 中的**引用类型**（如对象、数组、函数等）展开，这也是让拷贝变得复杂的原因。
- **内存存储差异**：
  - **值类型**（数字、字符串等）：变量直接存储值本身。
  - **引用类型**：变量存储的是指向内存中某个位置的**地址（引用）**。
- **直接赋值（`=`）的陷阱**：
  - 使用 `const copy = origin` 并非真正的拷贝，而是创建了一个新指针，两者指向内存中的同一个对象。
  - 修改 `copy` 的嵌套属性会直接污染原始对象 `origin`。
  - **结论**：在处理引用类型时，直接赋值绝对不可行，我们需要一个在物理上全新且独立的对象。

## 2. 浅拷贝与深拷贝的原理 *Content-[03:11]

- **浅拷贝（Shallow Copy）**：
  - 创建一个新对象，并复制原始对象的**第一层属性**。
  - 如果第一层属性是值类型，直接复制值；如果是引用类型（如嵌套对象），则只复制其**内存地址**。
  - 新旧对象的第一层是独立的，但深层嵌套的引用类型是**共享**的。
- **深拷贝（Deep Copy）**：
  - 创建一个新对象，并**递归复制所有层级**的属性。
  - 所有遇到的引用类型都会被一次又一次地重新创建。
  - 最终得到的新旧两个对象在内存中**完全独立**，互不影响（“井水不犯河水”）。

## 3. 浅拷贝的常见实现 *Content-[05:05]

- **`Object.assign()`**：
  - 经典实现方法，第一个参数为目标对象（如空对象 `{}`），后续参数为原对象。
  - 效果：第一层属性被复制，嵌套对象仍共享引用。
- **扩展运算符（`...`）**：
  - ES6 引入的语法糖，如 `{ ...origin }`。
  - 效果与 `Object.assign()` 完全相同。
  - **建议**：在日常开发中，如果需要浅拷贝，通常更推荐使用扩展运算符，语法更加简洁。

## 4. 深拷贝的“一行代码”实现及缺陷 *Content-[06:34]

- **实现方式**：`JSON.parse(JSON.stringify(origin))`
- **优点**：代码实现非常简单。
- **缺点（常见的坑）**：
  - 会直接忽略值为 `undefined` 或 `Symbol` 的属性。
  - 无法处理**函数**。
  - 会将 `Date` 日期对象静默转换为**字符串**，导致严重的数据类型丢失。
  - 如果对象中存在**循环引用**，会直接报错崩溃。

## 5. 现代 JavaScript 深拷贝最佳实践 *Content-[08:23]

- **官方推荐方案**：`structuredClone()`
  - 浏览器和 Node.js 内置的全局函数，无需引入任何第三方库即可直接使用。
  - 专为深拷贝设计，性能更优。
  - **支持**：循环引用、`Date`、正则表达式、`Map`、`Set` 等多种复杂数据类型。
  - **局限性**：无法拷贝函数和 `Error` 对象。
  - **结论**：在绝大多数现代开发场景中，它都应该是深拷贝的**首选方案**。

## 6. 面试实战：手写深拷贝 *Content-[10:30]

- **考察目的**：面试官并非要求在实际项目中手写该代码，而是考察候选人对**递归**、**引用类型判断**以及**边界情况处理**的综合理解能力。
- **实现思路**：
  1. **边界处理**：如果输入是 `null` 或原始类型，直接返回。
  2. **处理循环引用**：使用 `Map` 或 `WeakMap` 存储已经拷贝过的对象，防止递归调用陷入死循环。
  3. **创建新容器**：根据原始值是数组还是对象，创建对应的新空容器，并立即将其存入 `WeakMap` 中。
  4. **递归遍历**：遍历原始对象的所有属性，递归调用 `deepClone` 函数，将返回值赋给新容器的对应属性。

## 7. 实际工作中的使用原则与决策指南 *Content-[13:07]

- **核心目的**：
  1. **避免意外的副作用**：确保修改副本时不会污染原数据。
  2. **实现状态的不可变性**：这是 React 或 Vue 等现代前端框架构建高效更新 UI 的基础思想。
  3. **隔离数据**：创建一份完全独立的数据快照。
- **性能对比**：
  - 浅拷贝只复制一层，速度非常快，开销极小。
  - 深拷贝需要遍历对象的所有节点，相对较慢，开销更大。
  - **原则**：按需使用，切勿滥用深拷贝。
- **决策指南**：
  - **数据只有一层**：明确只需复制第一层时，使用扩展运算符（`...`）做浅拷贝即可。
  - **常规深拷贝需求**：首选 `structuredClone()`。
  - **老旧浏览器/极简数据**：在确保没有 `Date`、`undefined` 等特殊值的情况下，可考虑使用 `JSON.parse(JSON.stringify())` 作为备选。
  - **复杂场景/需拷贝函数**：直接使用成熟的第三方库，如 `lodash.cloneDeep`。

## 8. 课程最终总结 *Content-[15:27]

1. 浅拷贝只复制一层，深层的引用类型是共享的；而深拷贝会递归复制所有层级，得到完全独立的对象。
2. 在现代 JavaScript 开发中，进行深拷贝的首选方法是 `structuredClone()`。
3. 当面试被要求手写深拷贝时，一定要记住处理好**递归**和**循环引用**这两个核心问题。
