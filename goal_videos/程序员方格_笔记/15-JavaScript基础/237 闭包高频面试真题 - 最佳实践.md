## 闭包的最佳实践 *Content-[00:00]

1\. **避免滥用闭包，仅在必要时使用**
   - **适用场景**：
     - **封装私有变量**：有效避免全局变量污染。
     - **状态持久化**：当希望某个变量长期驻留在内存中时（例如：记录按钮的点击次数），使用闭包是非常合适的。
   - **核心原则**：千万不要为了使用闭包而使用闭包，必须基于实际业务需求。

2\. **及时解除引用**
   - 对于大型对象，在使用完毕后应及时将其引用设为 `null`，以解除引用，帮助垃圾回收机制释放内存。

3\. **优先使用块级作用域**
   - 在日常开发中，优先使用 `let` 或 `const` 来替代 `var`，这可以从根本上减少闭包带来的各种陷阱。

## 闭包的注意事项 *Content-[01:38]

1\. **内存管理**
   - **潜在问题**：闭包会导致外部函数的变量常驻内存当中。如果过度使用闭包，极易导致内存泄漏。
   - **解决方案**：在不再使用闭包时，及时将变量置空（重置引用，直接设置为 `null`），从而切断引用链，释放内存。

2\. **性能考量**
   - **潜在问题**：由于作用域链的存在，访问外部变量（父级作用域）的速度必然比访问局部变量（自身作用域）慢。
   - **优化建议**：在性能要求较高或关键的代码逻辑中，应当谨慎使用闭包。

## 循环中的闭包与代码示例 *Content-[03:05]

1\. **循环中的闭包问题**
   - 在循环结构中使用闭包时，强烈推荐使用 `let` 替代 `var`，这样可以有效避免额外的闭包问题和变量作用域陷阱。

2\. **代码示例：按钮点击事件绑定**
   - **业务场景**：获取页面中的多个按钮元素，并为每个按钮添加点击事件，要求点击时能正确输出对应的索引值。
   - **错误做法（使用 `var`）**：
     ```javascript
     var btns = document.querySelectorAll('button');
     for (var i = 0; i < btns.length; i++) {
         btns[i].addEventListener('click', function() {
             console.log(i); // 错误：输出结果都是循环结束后的最终值（如 2 或 3）
         });
     }
     ```
   - **正确做法 1（使用 `let`）**：
     ```javascript
     var btns = document.querySelectorAll('button');
     for (let i = 0; i < btns.length; i++) {
         btns[i].addEventListener('click', function() {
             console.log(i); // 正确：输出对应的索引（0, 1, 2...）
         });
     }
     ```
   - **正确做法 2（使用自执行函数 IIFE）**：
     - 如果不使用 `let`，也可以通过自执行函数（立即调用函数表达式）传参的方式，为每次循环创建独立的作用域，从而正确捕获当前的索引值。
