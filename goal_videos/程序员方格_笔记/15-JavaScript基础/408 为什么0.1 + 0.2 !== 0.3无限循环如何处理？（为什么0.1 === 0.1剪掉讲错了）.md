## 1. 0.1 + 0.2 !== 0.3 的根本原因 *Content-[00:00]

在 JavaScript 中，`0.1` 和 `0.2` 在计算机底层存储时已经不再是精确的值，而是**近似值**。
- 两个不精确的值相加，不可能得到一个绝对精准的值。
- `0.1`（近似值） + `0.2`（近似值） 得到的实际结果是 `0.30000000000000004`，而不是正好的 `0.3`。
- 这就是 `0.1 + 0.2 !== 0.3` 的最直观表现和根本原因。

## 2. 浮点数精度丢失与内存取舍 *Content-[00:25]

计算机的存储空间是有限的，无法存储一个无限循环的数，因此在精度和内存之间必须做出取舍：**在某个精度点直接舍弃**。不舍弃就无法存储，这也意味着必然会产生精度丢失。大整数的精度丢失和浮点数的精度丢失在本质上是一致的。

### IEEE 754 双精度浮点数标准
- **尾数位限制**：计算机存储浮点数时，尾数（Mantissa）的固定长度是 52 位（实际存储为 53 位，因为隐藏了科学计数法中默认的 `1`）。
- **JS 精度上限**：JavaScript 最多能表示的十进制精度长度是 **16 位**。

### 使用 `toPrecision()` 验证精度丢失
可以通过 `toPrecision()` 方法来测试和观察精度丢失的现象：
- **精度为 16 位时**：`0.1` 去掉末尾的零后，显示正好为 `0.1`。这是因为 JS 在 16 位精度内自动做了凑整处理。
- **精度为 20 位时**：如果将精度调高到 20 位，结果会出现问题，末尾会多出多余的数字（例如 `...555`）。这证明了底层存储的 `0.1` 并不是精确的 `0.1`，而是发生了舍入误差的近似值。

## 3. 十进制转二进制的精度丢失原理 *Content-[04:16]

为什么使用 `toPrecision(20)` 时，末尾会出现 `5`？这与十进制转换为二进制的数学规律有关。

- **有限二进制的特征**：能被转化为有限二进制小数的十进制小数，其最后一位必然以 `5` 结尾。因为只有 $0.5 \times 2 = 1$ 才能在乘 2 取整的过程中变为整数。
- **精度丢失的必然性**：在十进制的一位小数 `0.1` 到 `0.9` 当中，**除了 `0.5` 之外的值**，在转换成二进制的过程中都会产生无限循环，从而丢失精度。

## 4. 0.1 和 0.2 转换为二进制的详细过程 *Content-[05:18]

### 0.1 和 0.2 的二进制转换
- **0.1 转二进制**：通过 `(0.1).toString(2)` 可以看到，`0.1` 转换为二进制是一个无限循环的值，循环节为 `0011`。
- **0.2 转二进制**：同理，`0.2` 转换为二进制的无限循环值也是 `0011`。

### 舍入误差的产生
- 二进制计算是“逢二进一”。当无限循环的二进制小数被截断并向前进位时，会导致转换后的二进制值**比原始的十进制值稍微大一些**。
- 因此，`0.1` 和 `0.2` 在转换为二进制后，实际存储的都是比原始值略大的近似值。计算还没开始，在十进制转二进制时就已经产生了第一次舍入误差。

### 两次精度丢失导致最终结果偏大
1. **第一次丢失**：十进制转为二进制时，由于无限循环截断产生舍入误差（值变大）。
2. **第二次丢失**：两个浮点数进行相加计算时，需要对齐指数（阶码对齐），这个对齐过程也会产生精度的损失。

由于两次精度丢失，且转换后的值本身都略大于原始值，最终导致 `0.1 + 0.2` 的运算结果为 `0.30000000000000004`，大于 `0.3`。

## 5. 为什么 0.1 === 0.1 结果为 true？ *Content-[11:33]

既然 `0.1` 在底层存储的是近似值，为什么 `0.1 === 0.1` 的比较结果依然是 `true`？

- **底层存储一致**：`0.1` 的二进制无限循环值在存储时，JS 会自动做精度凑整处理。两次写入的 `0.1`，其底层存储的二进制近似值是**完全相同**的。
- **16 位精度截断**：JS 的精度上限是 16 位十进制数。在小于等于 16 位的精度范围内，JS 能够保证精度不丢失。两个 `0.1` 在 16 位截断后的表现完全一致，看起来都是精确的 `0.1`。
- **对比验证**：如果使用 `toPrecision()` 将精度调高到 20 位（大于 16 位），就能看到底层真实的近似值（包含多余的位数）。但在常规的 `===` 比较中，由于底层存储的近似值相同，且在 JS 默认的安全精度（16位）内表现一致，因此判定为相等。

## 6. AI 总结

本视频深入解析了前端经典面试题 `0.1 + 0.2 !== 0.3` 以及 `0.1 === 0.1` 的底层原理。核心要点如下：
1. **浮点数存储限制**：受限于 IEEE 754 双精度浮点数标准（尾数 52 位），计算机无法精确存储无限循环的二进制小数，必须在特定精度点截断，导致精度丢失。JS 的安全十进制精度上限为 16 位。
2. **转换与计算的双重误差**：`0.1` 和 `0.2` 转为二进制时均为无限循环（`0011`），截断进位导致值略微偏大（第一次丢失）；相加时指数对齐再次导致精度损失（第二次丢失），最终结果 `0.30000000000000004` 大于 `0.3`。
3. **相等性判断原理**：`0.1 === 0.1` 为 `true` 是因为 JS 在底层对字面量进行了相同的精度凑整处理，两者存储的二进制近似值完全一致，且在 16 位安全精度内表现相同。
