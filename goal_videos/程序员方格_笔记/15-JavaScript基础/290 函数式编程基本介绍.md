## 2. 函数式编程的历史与现代应用 *Content-[01:12]
- **历史渊源**：函数式编程并非新概念，早在 1950 年代随着 Lisp 语言的创建就已经进入大众视野，拥有非常悠久的历史。
- **现代复兴**：近年来，函数式编程凭借其优雅和简单的特点，重新风靡整个编程界，被视为继命令式编程（Imperative Programming）和面向对象编程（OOP）之后的“第三次编程范式革命”。
- **主流语言的支持**：现代主流编程语言在设计时都大量参考了函数式编程的特性。例如：
  - 支持 Lambda 表达式。
  - 内置 `map`、`reduce` 等高阶函数。
  - Java 8 等语言也全面引入了对函数式编程的支持。

## 3. 前端领域的函数式编程场景 *Content-[02:15]

- **Redux**：引入了函数式编程思想，其核心概念 Reducer 要求必须返回纯函数。

## 4. 案例对比：命令式编程的实现与痛点 *Content-[03:39]
为了直观理解函数式编程的优势，视频通过一个具体需求对比了两种编程范式。

- **需求描述**：
  - 输入：一个字符串数组，如 `['john', 'hello-world', 'JAMES']`。
  - 处理：将中划线（`-`）替换为空格，并将每个单词的首字母大写。
  - 输出：一个对象数组，如 `[{name: 'John'}, {name: 'Hello World'}, {name: 'James'}]`。

- **命令式编程（Imperative Programming）实现思路**：
  - 创建临时变量 `newArr` 用于存储最终结果。
  - 使用 `for` 循环遍历原数组，获取每一个 `item`。
  - 使用 `split('-')` 将字符串按中划线拆分为单词数组。
  - 再次使用 `for` 循环遍历拆分后的单词数组，提取首字母转为大写，并拼接剩余部分。
  - 使用 `join(' ')` 将处理后的单词用空格连接成新字符串。
  - 将新字符串赋值给对象的 `name` 属性，并 `push` 到 `newArr` 中，最后 `return newArr`。

- **命令式编程的痛点**：
  - **临时变量泛滥**：需要定义大量如 `newArr`、`newItem`、`names` 等临时变量。
  - **逻辑耦合度高**：嵌套循环和复杂的字符串处理逻辑交织在一起，代码可读性极差。
  - **维护困难**：命名困难，必须从头到尾阅读整个函数才能理解其具体功能，后期定位和修复 Bug 非常痛苦。
  - **复用性差**：这段代码只能解决当前这一个特定需求，无法复用到其他场景。

## 5. 案例对比：函数式编程的实现思路与优势 *Content-[10:38]
- **函数式编程（Functional Programming）实现思路**：
  - **核心思想**：不关注“怎么做”（过程性语句），而是关注“做什么”。将复杂需求拆分为多个单一职责的小函数，通过函数组合来解决问题。
  - **函数拆分与伪代码示例**：
    - `capitalize`：专门负责将字符串首字母大写。
    - `convertToObject`：将字符串转换为 `{name: string}` 格式的对象。
    - `splitByHyphen`：按中划线分割字符串。
    - `joinBySpace`：用空格连接数组元素。
    - 结合 `map` 等高阶函数对数组进行遍历和转换。
  - **执行流程**：通过 `map` 接收处理函数，内部调用 `split` 分割，再通过 `map` 调用 `capitalize` 处理首字母，接着用 `join` 拼接，最后调用 `convertToObject` 生成对象。

- **函数式编程的优势**：
  - **关注点分离**：开发者只需专注于实现每一个基础函数，确保其逻辑正确且纯粹。
  - **极高的复用性**：拆分出的基础函数（如首字母大写、对象转换）是通用的，可以在项目的其他场景中直接复用。
  - **灵活的组合能力**：通过不同的函数组合和变换（如使用 `compose` 或 `pipe`），可以像搭积木一样应对和实现各种不同的需求，产生出非常强大的代码力量。
  - **对比总结**：命令式编程只能解决当前的特定需求，而函数式编程通过基础函数的灵活组合，能够以更优雅、更具扩展性的方式解决更广泛的问题。
