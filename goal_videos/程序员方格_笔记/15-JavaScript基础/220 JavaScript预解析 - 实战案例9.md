## 1. 案例代码还原与全局预解析 *Content-[00:00]

在分析 JavaScript 预解析实战案例 9 之前，首先根据视频讲解还原出完整的示例代码结构：

```javascript
var a = 1;
function fn(a) {
    alert(a);
    a = 2;
}
fn(a);
alert(a);
```

**全局预解析阶段（Hoisting）：**
JavaScript 引擎在执行代码前，会先进行全局预解析，将变量声明和函数声明提升到当前作用域的顶部。
- **第一行 `var a = 1`**：遇到 `var` 关键字，变量 `a` 被提升。此时预解析仓库中 `a` 的值为 `undefined`。
- **第二行 `function fn(a)`**：遇到 `function` 关键字，函数 `fn` 整体被提升。预解析仓库中 `fn` 的值为完整的函数体代码。
- **预解析结果**：全局作用域中，`a = undefined`，`fn = function(a) { ... }`。后续没有其他 `var` 或 `function` 声明，预解析阶段结束。

## 2. 全局代码逐行执行与函数调用 *Content-[01:46]

预解析完成后，进入全局代码的逐行执行阶段：

- **第一行 `var a = 1`**：执行赋值操作，全局变量 `a` 的值由 `undefined` 变为 `1`。
- **第二行 `function fn(a)`**：函数声明在预解析阶段已经处理完毕，逐行执行时不会改变其值，因此直接跳过，不做任何修改操作。
- **第六行（代码逻辑上的第三行） `fn(a)`**：执行函数调用。此时将全局变量 `a` 当前的值（即 `1`）作为实参传递给函数 `fn`，程序进入函数内部执行。

## 3. 函数内部局部预解析与执行 *Content-[03:33]

函数被调用时，会开启一个新的局部作用域。在函数内部，需要重新进行预解析和逐行解读代码。

**局部预解析阶段：**
- 函数 `fn` 定义中包含一个形参 `a`。在 JavaScript 中，**函数的形参相当于局部作用域中的变量声明**。
- 因此，在函数内部的预解析仓库中，局部变量 `a` 被初始化为 `undefined`。

**局部逐行执行阶段：**
- **接收实参**：函数调用时传入了实参 `1`，该实参会赋值给局部形参 `a`。此时，函数内部的局部变量 `a = 1`。
- **执行 `alert(a)`**：弹出局部变量 `a` 的值，因此第一个弹窗结果为 `1`。
- **执行 `a = 2`**：将变量 `a` 重新赋值为 `2`。
  - **核心考点**：虽然这里的 `a = 2` 前面没有 `var` 关键字，但由于函数的形参 `a` 已经相当于在局部作用域中声明了变量，因此这个赋值操作**覆盖的是局部作用域中的 `a`**，而**绝对不会影响**全局作用域中的 `a`。
  - 此时，函数内部的局部变量 `a` 变为 `2`。

## 4. 作用域深度分析与结果验证 *Content-[06:15]

为了彻底理清逻辑，我们需要对代码中出现的多个 `a` 进行作用域划分：

- **全局作用域的 `a`**：包括第一行的 `var a = 1`、函数调用时传入的实参 `fn(a)`、以及最后的 `alert(a)`。这三个 `a` 属于同一阵营，它们的值始终为 `1`。
- **局部作用域的 `a`**：包括函数的形参 `function fn(a)`、函数内部的 `alert(a)` 以及 `a = 2`。这三个 `a` 属于局部阵营，它们在函数执行期间参与了变化（1 -> 2）。

**回到全局执行：**
- 函数 `fn` 执行完毕，程序回到全局作用域。
- **执行最后的 `alert(a)`**：此时访问的是全局变量 `a`。由于函数内部的修改仅作用于局部作用域，全局变量 `a` 的值未被改变，依然为 `1`。因此第二个弹窗结果也是 `1`。

**最终结果验证：**
两次 `alert` 弹出的结果均为 `1`。在浏览器控制台（执行环境）中保存并刷新运行，弹出的结果与按照预解析规则推导出的结果完全一致，证明分析逻辑正确。

## AI 总结 *Content-[09:40]

本视频通过实战案例 9 深入剖析了 JavaScript 中的**预解析机制**与**作用域隔离**特性。核心知识点如下：
1. **预解析顺序**：全局作用域先进行变量和函数的提升（`var` 提升为 `undefined`，`function` 整体提升），然后再逐行执行代码。
2. **形参的局部变量特性**：函数的形参在局部作用域中等同于使用 `var` 声明的局部变量。
3. **作用域隔离**：在函数内部对形参或同名变量进行赋值时，如果该变量已在局部作用域中声明（包括形参声明），则修改的仅是局部变量，不会向上查找或污染全局作用域中的同名变量。理解这一机制是避免 JavaScript 中变量覆盖和状态污染bug的关键。
