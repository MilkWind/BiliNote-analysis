## 解释型语言与编译型语言的区别 *Content-[00:49]
- **JS 的运行机制**：JS 属于解释型语言，但并非完全在运行时简单地逐句解释执行。
- **编译型语言（如 Java）**：
  - 代码在执行前必须先进行编译。
  - 编译的目的是将代码翻译成当前操作系统支持的环境格式（如在 Mac 上编译成苹果格式，在 Windows 上编译成 Windows 格式），从而实现**跨平台**。
  - 在编译过程中，引擎会提前处理好变量和函数的提升等操作。
- **解释型语言（如 JS）**：
  - 特点是“逐行执行”，类似于“车到山前必有路”，执行时再处理。
  - **优点**：执行速度快，省去了前期的编译步骤。
  - **缺点**：安全性相对编译型语言较低，因为运行时可能会遇到未预料的错误。

## JS 的预解析与函数提升 *Content-[02:47]
- **预解析阶段**：JS 引擎在真正解释执行代码之前，会先对代码进行“预解析”（大致扫一眼）。
- **提升规则**：
  - 会将使用 `var` 和 `function` 关键字声明的变量和函数进行提前处理。
  - **注意**：ES6 引入的 `let` 和 `const` **不存在**变量提升。
- **函数提升机制**：
  - 当函数声明处于代码较靠后的位置时，会被提升到**当前作用域**的开头。
  - **示例**：在代码上方调用 `func()`，下方才定义 `function func() {}`，程序不会报错，因为函数已被提升。
  - **关于“第一行”的理解**：所谓提升到“第一行”，是指它一定会在你实际执行的第一行代码之前，无需纠结具体的物理行号或绝对位置。

## 变量提升与函数提升的核心区别 *Content-[04:08]
- **变量提升**：
  - **只提升变量名（声明）**，**不会提升变量值（赋值）**。
  - 如果在赋值前提前打印该变量，结果为 `undefined`。
- **函数提升**：
  - 会将**整个函数体**（包括函数名和函数内部的代码逻辑）提升到当前作用域的第一行。

## 前端学习方法论：广度与深度的平衡 *Content-[05:09]

  - **进阶阶段（重深度）**：在掌握整体框架和基础语法后，再逐层深挖底层原理。
- **生动的比喻**：
  - **森林与松树**：进入森林学习，不要在一棵松树（某个细节）上死磕而放弃了整片森林（整体知识体系）。
  - **金字塔与压强**：知识积累像建金字塔，地基必须铺得广且稳。如果只在一个点上深挖，根基不稳；就像在冰面上行走，如果只踩一个点（受力面积小）压强很大，容易踩碎冰面；如果踩在宽大的木板上（知识面广），压强分散，就能安全通过。
- **核心原则**：“会学”比“死学”更重要，先广度后深度，才能事半功倍。

## 深度解析：为什么变量只提升声明不提升赋值？ *Content-[08:06]
- **函数提升的安全性**：
  - 函数即使被整体提升，只要不被调用就不会执行，因此不会打乱程序的正常执行顺序。
- **变量赋值的复杂性**：
  - 变量的值不一定是一个简单的字面量，它极有可能是一个**函数的调用结果**。
  - **示例**：`var a = show()`，而 `show` 函数内部可能调用了 `qq`，`qq` 调用了 `ww`，层层嵌套（就像扯毛衣线头一样）。
- **如果提升赋值的后果**：
  - 如果将变量的赋值也一起提升，就相当于把整个复杂的函数调用链和执行逻辑都提前了。这会彻底破坏程序的执行顺序，导致预解析失去意义。
- **设计者的考量**：
  - 为了保证程序执行顺序的安全性，JS 设计者规定变量提升**只提升声明，不提升赋值**。
  - 提升变量名的唯一目的，是为了防止在提前调用变量时报“变量未定义”的致命错误。虽然赋值为 `undefined`，但大幅提高了程序运行的安全性。

## 变量声明的三个阶段与提升本质 *Content-[11:18]
- JS 变量处理在底层经历以下三个阶段：
  1. **声明阶段**：告诉编译器该变量存在，但**不分配内存空间**。
  2. **定义阶段（分配内存）**：为变量分配具体的内存空间，准备接收数据。
  3. **初始化/赋值阶段**：将具体的值放入已分配并初始化好的内存空间中。
- **变量提升的本质**：
  - 变量提升**仅仅提升了“声明阶段”**。
  - 这意味着在预解析时，JS 只是声明了变量，并没有为其分配内存空间，也没有进行赋值操作。
