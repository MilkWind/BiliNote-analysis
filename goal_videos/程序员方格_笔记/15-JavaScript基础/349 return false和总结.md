## 字节跳动面试真题引入 *Content-[00:00]

本部分通过一道字节跳动的高频面试真题引入，该题的答错率高达 83%。

**核心问题**：
当我们使用 `addEventListener` 方法绑定事件时，在回调函数中 `return false` 能否阻止事件冒泡？

**答案公布**：
使用 `addEventListener` 方法绑定的事件，`return false` **既不能阻止事件冒泡，也不能阻止默认行为**。
它唯一的作用是**结束当前回调函数的执行**（即阻止该函数内后续代码的执行），这是 `return` 语句本身具备的基础能力，与事件机制无关。

## addEventListener 绑定事件下的 return false 测试 *Content-[01:05]

为了验证上述结论，视频中进行了两项具体的代码测试。

### 1\. **测试一：能否阻止默认行为**
- **测试场景**：在 `<a>` 标签上使用 `addEventListener` 绑定 `click` 事件，并在回调函数中执行 `return false`。
- **预期效果**：如果 `return false` 能阻止默认行为，点击链接后不应发生跳转。
- **实际结果**：点击链接后，页面依然正常跳转到了目标地址（如百度）。
- **结论**：`addEventListener` 绑定的事件，`return false` **不能阻止默认行为**。

### 2\. **测试二：能否阻止事件冒泡**
- **测试场景**：
  1. 在 `<a>` 标签上使用 `addEventListener` 绑定 `click` 事件，并 `return false`。
  2. 在其父元素 `document.body` 上同样使用 `addEventListener` 绑定 `click` 事件，并在回调中打印日志（如 `console.log('触发了body')`）。
- **预期效果**：如果 `return false` 能阻止事件冒泡，点击 `<a>` 标签时，事件不会冒泡到 `body`，`body` 的回调不会被触发。
- **实际结果**：点击 `<a>` 标签后，控制台依然打印出了 `body` 的日志，说明事件成功冒泡到了父元素。
- **结论**：`addEventListener` 绑定的事件，`return false` **不能阻止事件冒泡**。

**阶段总结**：
使用 `addEventListener` 绑定的事件，`return false` 既不会阻止默认行为，也不会阻止事件冒泡。

## onclick 绑定事件下的 return false 测试 *Content-[03:27]

接下来，将事件绑定方式更换为传统的 `onclick`（如 HTML 属性 `onclick="return false"` 或 DOM 0 级事件绑定），再次进行相同的测试。

### 1\. **测试一：能否阻止默认行为**
- **测试场景**：在 `<a>` 标签上使用 `onclick` 绑定事件，并 `return false`。
- **实际结果**：点击链接后，页面**没有发生跳转**。
- **结论**：使用 `onclick` 绑定的事件，`return false` **可以阻止默认行为**。

### 2\. **测试二：能否阻止事件冒泡**
- **测试场景**：同样在 `<a>` 标签使用 `onclick` 并 `return false`，在父元素 `document.body` 使用 `addEventListener` 监听 `click` 事件并打印日志。
- **实际结果**：点击 `<a>` 标签后，虽然页面没有跳转，但控制台**依然打印出了 `body` 的日志**。
- **结论**：使用 `onclick` 绑定的事件，`return false` **不能阻止事件冒泡**。

**阶段总结**：
使用 `onclick` 绑定的事件，`return false` 可以阻止默认行为，但不会阻止事件冒泡。

## 事件冒泡与默认行为核心知识点总结 *Content-[05:48]

视频最后对前端事件中阻止冒泡和默认行为的核心 API 进行了系统性总结。

### 1\. **阻止事件冒泡的方法**
共有两种标准方法，它们的共同点是都能阻止事件向父元素冒泡，但存在关键区别：
- **`stopPropagation()`**：
  - 阻止事件继续向上传播。
  - **不会**阻止当前元素上绑定的其他同类事件监听器执行。
- **`stopImmediatePropagation()`**：
  - 阻止事件继续向上传播。
  - **会**阻止当前元素上绑定的其他同类事件监听器执行（即立即终止当前元素上所有后续同类事件的回调）。

### 2\. **阻止默认行为的方法**
- **`preventDefault()`**：
  - 标准且唯一用于阻止元素默认行为的方法（如阻止 `<a>` 标签跳转、阻止表单提交等）。

### 3\. **`return false` 的行为差异总结**
`return false` 的效果完全取决于**事件绑定的方式**：
- **使用 `addEventListener` 绑定**：
  - 既**不会**阻止事件冒泡。
  - 也**不会**阻止默认行为。
  - 仅起到 `return` 的作用，结束当前函数执行。
- **使用 `onclick`（DOM 0 级 / HTML 属性）绑定**：
  - **会**阻止默认行为。
  - **不会**阻止事件冒泡。

## AI 总结 *Content-[08:26]

本视频深入解析了前端面试中极易踩坑的 `return false` 知识点。核心结论是：`return false` 并非万能的事件控制手段。在标准的 `addEventListener` 中，它仅能终止当前回调函数的执行，无法阻止事件冒泡和默认行为；而在传统的 `onclick` 绑定中，它仅能阻止默认行为，依然无法阻止事件冒泡。在实际开发中，应明确使用 `e.stopPropagation()`（或 `stopImmediatePropagation()`）来阻止冒泡，使用 `e.preventDefault()` 来阻止默认行为，以避免因事件绑定方式不同而引发的逻辑 Bug。
