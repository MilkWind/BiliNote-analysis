## 1. ES6 为什么要引入 Symbol 数据类型 *Content-[00:02]
- **引入原因**：在 ES5 中，对象的属性名只能是字符串。如果存在重名的属性，后定义的属性会覆盖先定义的属性，极易出现属性名冲突的问题。因为字符串作为属性名不具备共存性。
- **核心作用**：为了解决属性名冲突问题，ES6 引入了 `Symbol` 数据类型。其核心是能够生成独一无二的值，从而从根本上避免属性名的冲突。
- **附加作用**：利用 `Symbol` 的隐藏特性，可以实现对象的真正私有属性。在没有 `Symbol` 之前，实现 ES6 class 类的私有属性通常使用约定俗成的加下划线（如 `_name`），但这仅仅是团队之间的规范。如果新人不遵守规范，属性依然能被外部修改，而 `Symbol` 则能实现真正的私有化。

## 2. Symbol 的核心特性及数据类型验证 *Content-[01:21]
- **数据类型**：`Symbol` 是第六种基本数据类型（第七种基本数据类型是 `BigInt`）。
- **核心特性**：
  - **唯一性**：所有 `Symbol` 的值都是唯一的，即使描述相同，两个值也不相等。
  - **不可实例化**：不能作为构造函数，不能使用 `new` 关键字创建。
  - **不可添加属性**：因为它是基本数据类型，所以本身不能添加属性。
  - **不可运算**：不能与其他类型进行运算。
  - **类型转换**：可显式转为字符串，可隐式转为布尔值（值为 `true`），但不能转为数值。
  - **遍历隐藏**：作为对象属性名时，不会被常规遍历方法获取。
  - **序列化忽略**：在 `JSON.stringify` 中会被直接忽略。
  - **特定获取**：能被 `Object.getOwnPropertySymbols` 和 `Reflect.ownKeys` 方法获取。
- **验证方式**：
  - 使用 `typeof` 检测，会返回 `'symbol'`（引用数据类型除 `function` 外均返回 `'object'`）。
  - 不能用 `new` 创建。
  - 值直接存在栈中，无引用地址。
  - **面试建议**：面试时直接回答使用 `typeof` 验证即可，这是最直接简单的方法。

## 3. Symbol 与 Symbol.for 的核心区别及 Symbol.keyFor 的作用 *Content-[03:21]
- **核心区别**：
  - **`Symbol()`**：始终新建，即使描述相同，两个值也不相等。创建的值不会注册到全局注册表，仅在局部（当前页面）有效。
  - **`Symbol.for()`**：在全局注册表中唯一，相同描述返回同一个值。创建的值会注册到全局注册表，可跨文件、跨作用域访问。
- **`Symbol.keyFor` 的作用**：
  - 用于从全局 `Symbol` 注册表中获取指定 `Symbol` 值对应的描述字符串。
  - **注意**：仅对 `Symbol.for` 创建的值有效。如果对 `Symbol()` 创建的值调用此方法，会返回 `undefined`。

## 4. Symbol 类型的运算与类型转换 *Content-[04:24]
- **运算**：`Symbol` 值不能和任何类型进行运算，否则会直接报错。
- **类型转换**：
  - **不可转为数值**：尝试转为数值会直接报错。
  - **可显式转为字符串**：可以通过 `toString()` 或 `String()` 方法进行转换。
  - **可隐式转为布尔值**：且所有 `Symbol` 值的布尔值都为 `true`，不存在假值。

## 5. 为什么 JSON.stringify 会忽略 Symbol 类型的属性 *Content-[04:57]
- **原因**：根据 JSON 数据格式的规范，它仅支持字符串、数字、布尔、数组和普通对象等类型，并不支持 `Symbol` 类型。
- **结果**：因此 `JSON.stringify` 在序列化对象时，会直接忽略 `Symbol` 类型的属性，仅保留其支持的数据类型属性。

## 6. 如何获取对象中 Symbol 类型的属性 *Content-[05:22]
- **常规方法的限制**：常规遍历、`for...in`、`Object.keys` 以及 `Object.getOwnPropertyNames` 均不能获取 `Symbol` 类型的属性，它们只能获取字符串类型的属性。
- **正确的获取方法**：
  - **`Object.getOwnPropertySymbols()`**：仅能获取对象的 `Symbol` 类型属性，返回的是 `Symbol` 值的数组。
  - **`Reflect.ownKeys()`**：获取对象的所有属性，包括字符串和 `Symbol` 类型，返回属性名的数组。

## 7. 利用 Symbol 实现对象的真正私有属性 *Content-[06:19]
- **实现方法**：定义 `Symbol` 变量作为属性名，将对象或类的属性名设为 `Symbol` 的值。由于 `Symbol` 属性不会被常规方法遍历获取，外部无法直接访问和修改，仅能通过对象或类的公共方法进行操作，从而实现真正的私有。
- **下划线伪私有不严谨的原因**：下划线（如 `_name`）伪私有仅为开发约定，JS 引擎并未对其做出任何限制。外部依然可以直接访问或修改该属性（例如 `obj._name = '李四'`），无法保证数据的安全性。

## 8. Symbol 作为对象属性名的语法要求 *Content-[07:29]
- **语法要求**：`Symbol` 作为对象属性名时，必须使用中括号 `[]`，不能使用点语法 `.`。
- **核心原因**：JS 引擎会将点语法后面的标识符解析为字符串（例如 `obj.s` 会被解析为 `obj['s']`，此时 `s` 变成了字符串）。而中括号会保留变量的原始类型（例如 `obj[s]` 会保留 `s` 的 `Symbol` 类型）。因此，必须使用中括号才能正确识别 `Symbol` 属性名。

## 9. 利用 Symbol 消除魔术字符串 *Content-[08:11]
- **魔术字符串定义**：指的是代码中多次出现且与业务逻辑无关的字符串或数字，非常不利于代码维护。
- **消除方法**：用 `Symbol` 常量替代魔术字符串。将魔术字符串定义为 `Symbol` 的常量，在代码中使用常量而非直接使用硬编码的字符串或数字。
- **优势**：修改时仅需维护常量，无需修改所有代码。且常量的值是 `Symbol`，具有唯一性，避免了硬编码带来的耦合问题。

## 10. Symbol description 属性的作用及与 Symbol.keyFor 的区别 *Content-[09:12]
- **`description` 属性的作用**：用于获取任意 `Symbol` 值的描述字符串，包括 `Symbol()` 和 `Symbol.for()` 创建的。有描述则返回描述字符串，无描述则返回 `undefined`。
- **与 `Symbol.keyFor` 的区别**：
  - **使用范围**：`description` 适用于所有的 `Symbol` 值；`Symbol.keyFor` 仅适用于用 `Symbol.for` 创建并注册在全局注册表中的 `Symbol` 值。
  - **查找位置**：`description` 直接查找 `Symbol` 值自身的描述；`Symbol.keyFor` 是从全局 `Symbol` 注册表中查找描述。
  - **本质区别**：`description` 是 `Symbol` 值的实例属性；`Symbol.keyFor` 是全局方法，依赖全局注册表。
