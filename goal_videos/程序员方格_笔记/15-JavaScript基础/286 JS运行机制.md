## 进程的概念与特性 *Content-[00:40]
- **基本定义**：进程是 CPU 资源分配的最小单位。
- **核心组成**：进程包括运行中的程序以及程序运行所需的相关资源（如内存资源、系统资源等）。可以将其理解为一个可以单独运行或拥有自己独立资源空间的任务程序。
- **运行机制与资源分配**：
  - 电脑每打开一个软件，就会产生一个或多个进程。
  - 电脑运行软件过多时会导致卡顿，这是因为 CPU 的总资源是有限的，分配给各个进程的资源空间越多，越容易导致系统资源紧张。
  - 各个进程之间是相互独立的。CPU 在运行一个进程时，其他进程处于非运行状态。
  - CPU 使用**时间片轮转调度算法**来实现同时运行多个进程。

## 线程的概念与分类 *Content-[02:25]
- **基本定义**：线程是 CPU 调度的最小单位，建立在进程的基础之上。
- **通俗理解**：线程是程序中的一个执行流。执行一个程序时，首先由 CPU 调度进程，进程内部再通过一个或多个线程来执行具体的任务。
- **线程分类**：
  - **单线程**：一个进程中只有一个执行流。程序执行时，所有的程序路径按照连续的顺序排列，前面的任务必须处理完毕后，后面的任务才能执行。
  - **多线程**：一个进程中有多个执行流。允许单个程序创建多个并行执行的线程，来同时完成各自不同的任务。

## JS 为什么是单线程 *Content-[04:25]
- **核心原因**：JS 作为浏览器的脚本语言，主要用途是与用户进行交互以及操作 DOM。这种特定的用途决定了它只能是单线程。
- **多线程的冲突问题**：
  - 假设 JS 是多线程的，当两个线程同时操作同一个 DOM 时会产生严重的同步问题。例如，一个线程在某个 DOM 中添加内容，而另一个线程同时将该 DOM 移除。
  - 在这种情况下，CPU 将无法判断究竟应该执行增加还是删除操作，从而产生逻辑矛盾和冲突。为了避免这种不可控的冲突，JS 被设计为单线程。

## Web Worker 多线程能力与限制 *Content-[05:45]
- **Web Worker 的引入**：HTML5 提出了 Web Worker 标准，允许 JS 脚本创建多个线程，从而利用多核 CPU 的计算能力，使 JS 具备了多线程的处理能力。
- **Worker 线程的严格限制**：
  - **受主线程控制**：子线程完全受主线程控制，不能脱离主线程独立运行。
  - **禁止操作 DOM**：Worker 线程中无法访问 `document` 对象，不能进行任何 DOM 操作。这是为了避免对主线程的渲染和用户交互造成干扰。
- **使用场景与通信机制**：
  - 主要用于处理复杂的计算逻辑。
  - 通过 `postMessage` 方式与主线程进行通信。主线程将计算量大的任务发送给 Worker，Worker 计算完成后，再将结果通过 `postMessage` 返回给主线程。
  - 这种机制可以避免繁重的计算任务阻塞主线程，保证页面渲染和用户交互的流畅性。
- **本质未变**：尽管有 Web Worker 标准赋予了 JS 多线程的能力，但这并没有改变 JS 本质上是单线程的事实。
