## JavaScript 预解析实战案例分析 *Content-[00:00]

本章节主要引入并分析一道关于 JavaScript 预解析（变量提升与函数提升）的高频实战面试题。通过剖析代码在全局作用域和函数局部作用域中的预解析与执行过程，帮助深入理解 JavaScript 的执行机制。

案例代码的核心结构包含以下部分：
- 全局变量声明与赋值（`var a = 10; var b = 11; var c = 12;`）。
- 函数声明（`function test(a) { ... }`）。
- 函数调用并传入实参（`test(10);`）。
- 控制台输出全局变量（`console.log(a); console.log(b); console.log(c);`）。

## 全局作用域预解析与执行 *Content-[00:05]

### 1\. 全局预解析阶段
在代码执行前，JavaScript 引擎会先进行预解析（提升），将变量声明和函数声明提升到当前作用域的顶部。
- **变量声明提升**：`var a`、`var b`、`var c` 被提升，初始值均被赋为 `undefined`。
- **函数声明提升**：`function test(a)` 函数体整体被提升。
- **预解析后的“仓库”（执行上下文）状态**：
  - `a = undefined`
  - `b = undefined`
  - `c = undefined`
  - `test = function(a) { ... }`

### 2\. 全局执行阶段
预解析完成后，开始逐行执行代码：
- **第一行**：执行 `var a = 10; var b = 11; var c = 12;`。此时对全局变量进行赋值，全局“仓库”中的值更新为 `a = 10`，`b = 11`，`c = 12`。
- **第二行**：遇到函数声明 `function test(a)`。由于函数声明在预解析阶段已经处理，此处不会改变已有变量的值，不做任何修改操作，直接跳过。
- **第七行**：执行 `test(10);`。这是一个函数调用，传入实参 `10`。此时会开启函数内部新的预解析和执行过程。

## 函数 test 内部预解析与执行 *Content-[03:20]

### 1\. 函数内部预解析阶段
进入 `test` 函数内部，首先进行局部的预解析：
- **形参处理**：函数的形参 `a` 相当于通过 `var` 定义了局部变量。
- **变量声明提升**：函数内部的 `var a` 和 `var b` 被提升。
- **预解析后的局部“仓库”状态**：
  - `a = undefined`
  - `b = undefined`

### 2\. 函数内部执行阶段
预解析完成后，开始逐行执行函数内部的代码：
- **传入实参**：调用时传递了实参 `10`，此时局部变量 `a` 接收实参，值变为 `10`。
- **第三行**：执行 `var a = 1;`。此时存在全局传入的 `a = 10` 和局部声明的 `a = 1`。由于两者都是变量，赋值以代码中最后出现的为准，因此局部 `a` 的最终结果被覆盖为 `1`。
- **第四行**：执行 `var b = 2;`。此时局部变量 `b` 被赋值为 `2`。
- **第五行**：执行 `c = 3;`。**核心考点**：定义变量 `c` 时**没有使用 `var` 关键字**。因此，`c` 不会作为局部变量，而是会沿着作用域链向上查找，被识别为全局变量 `c`。此时，全局变量 `c` 的原值 `12` 被直接覆盖，最终全局 `c` 的值变为 `3`。

至此，`test` 函数内部代码执行完毕。

## 全局作用域后续执行与结果验证 *Content-[08:30]

`test` 函数执行完毕后，程序回到全局作用域，继续执行后续的代码：

- **第八行**：执行 `console.log(a);`。此时全局中的 `a` 值依然是初始赋值的 `10`（函数内部修改的是局部 `a`），因此输出结果为 `10`。
- **第九行**：执行 `console.log(b);`。此时全局中的 `b` 值依然是初始赋值的 `11`（函数内部修改的是局部 `b`），因此输出结果为 `11`。
- **第十行**：执行 `console.log(c);`。此时全局中的 `c` 值为 `3`。因为在函数内部执行 `c = 3` 时未使用 `var` 声明，导致直接修改了全局变量 `c`，覆盖了原来的 `12`，因此输出结果为 `3`。

**最终控制台输出结果**：
```text
10
11
3
```

**避坑指南**：
在分析此类问题时，函数内部的局部变量操作往往是“障眼法”。需要特别警惕未使用 `var`、`let` 或 `const` 声明的变量，它们会意外地提升为全局变量并修改全局状态。通过在浏览器执行环境中实际运行验证，结果确为 `10`、`11`、`3`。

## AI 总结

本视频详细拆解了一道经典的 JavaScript 预解析面试题，核心考察了**变量提升**、**函数作用域**以及**隐式全局变量**的概念。
1. **预解析机制**：明确了 `var` 声明的变量和函数声明会被提升到作用域顶部，但赋值操作保留在原位。
2. **作用域隔离**：函数内部使用 `var` 声明的变量（如 `a` 和 `b`）属于局部变量，不会污染全局作用域。
3. **隐式全局变量**：未使用关键字声明直接赋值的变量（如 `c = 3`）会沿着作用域链查找，最终修改全局变量，这是导致全局 `c` 值被改变的根本原因。
掌握这些底层执行逻辑，能够有效避免在实际开发中遇到变量覆盖和作用域污染的问题。
