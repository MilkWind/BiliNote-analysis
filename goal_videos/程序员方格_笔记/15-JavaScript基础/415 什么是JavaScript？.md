## JavaScript 简介与核心组成 *Content-[00:31]
在现代 Web 开发中，JavaScript 几乎无处不在，涵盖了前端交互、后端服务以及移动端应用。然而，绝大多数开发者往往只关注使用 React、Vue 等框架以及各种构建工具来开发应用，从而忽略了 JavaScript 的本质。本节旨在从头到尾梳理 JavaScript 的本质，回顾其历史，并深入理解其核心组成部分。

## JavaScript 的诞生与早期历史 *Content-[01:19]
在 Web 发展的早期，浏览器只能展示静态内容。为了解决客户端输入验证问题，避免每次数据校验都要往返服务器，客户端脚本语言的需求应运而生。

- **1995年诞生**：网景公司的工程师 Brendan Eich 在极短的时间内开发出了这门语言。其内部代号最初为 Mocha，随后为了蹭当时 Java 语言的热度，最终定名为 JavaScript。这也导致至今许多人会混淆 Java 和 JavaScript，但实际上两者在技术实现上差异巨大。
- **浏览器大战与标准统一**：随着网景浏览器的成功，微软在 IE3 中推出了类似的实现 JScript。这导致浏览器之间存在两套不同的脚本语言标准，给开发者带来极大困扰。
- **1997年关键转折**：为了解决标准混乱的问题，网景公司将 JavaScript 交给了 ECMA 组织，希望制定统一的标准。同年，ECMA-262 第一版发布，正式确立了 ECMAScript（简称 ES）作为这门语言的标准规范。其核心目标是统一语言的语法和语义，消除不同浏览器厂商实现上的差异。自此，JavaScript 摆脱了野蛮生长，成为一门公认的主流标准化编程语言。

## 现代 JavaScript 的三大组成部分 *Content-[03:34]
通常所说的 JavaScript 实际上是由三个截然不同的部分构成的完整体系：

1\. **ECMAScript（核心基础）**：定义了这门语言的基础语法（如变量声明、循环、函数定义），负责所有的逻辑处理。
2\. **DOM（文档对象模型）**：负责连接 HTML 文档，让 JavaScript 能够识别并修改页面上的元素（如改变文字颜色、插入新图片）。
3\. **BOM（浏览器对象模型）**：负责连接浏览器环境，让 JavaScript 能够控制浏览器窗口本身的行为（如弹出新窗口、获取屏幕分辨率、读取浏览器历史记录）。

这三者缺一不可，ECMAScript 提供基础语法能力，DOM 提供操作页面内容的能力，BOM 提供操作浏览器窗口的能力。

## 深入 ECMAScript 核心规范 *Content-[05:20]
ECMAScript 是开发者每天打交道最多的部分，也是语言的核心。需要明确的是，ECMAScript 是一个规范，不仅适用于浏览器环境，也适用于 Node.js 等服务器环境。只要掌握了 ECMAScript，就掌握了在不同环境中编写逻辑的核心能力。

它规定了编程语言最底层的机制，包括：
- 语法和流程控制语句（如 if 判断、for 循环）。
- 数据类型（如数字、字符串、布尔值）。
- 对象和函数的定义方式。

简而言之，ECMAScript 提供了编写 JavaScript 代码的语言规范和语法规范，是所有 JavaScript 代码的底层基础。

## ECMAScript 版本演进史 *Content-[06:42]
ECMAScript 标准由专门的委员会负责制定和维护，以下是几个关键的时间节点和版本演进：

- **ES5（2009年）**：在很长一段时间内是浏览器的通用标准。引入了严格模式以规范代码编写，增加了原生的 JSON 支持以及 `forEach`、`map` 等数组方法，大幅提升了开发效率。
- **ES6 / ES2015（2015年）**：这是一次里程碑式的革命性更新。引入了 `let`、`const`、块级作用域、`Promise` 等关键特性，使 JavaScript 真正具备了编写大型复杂应用的能力。
- **ES2017 及后续版本**：ES6 之后，官方调整策略为每年发布一个小版本以保持持续迭代。其中 ES2017 带来了 `async`/`await` 特性，让异步代码读起来像同步代码一样清晰，极大改善了异步编程体验。后续版本不断加入新特性，持续完善开发者的编码体验。

## DOM 文档对象模型详解 *Content-[08:28]
DOM（Document Object Model）的本质是一套 API，充当了 JavaScript 和 HTML 页面之间的桥梁。如果没有 DOM，JavaScript 将无法感知页面存在，也无法进行任何修改。

- **核心思想**：将整个页面文档看作一个由节点构成的层级结构（树状结构）。HTML 页面中的每一个标签、每一段文本、每一个属性在 DOM 中都被抽象成一个节点对象。通过 DOM 提供的接口，开发者可以动态访问和更新文档的内容、结构甚至 CSS 样式。
- **树状结构示例**：浏览器解析 HTML 后会生成一个倒置的树状结构。`html` 是根节点，分叉出 `head` 和 `body` 子节点，`body` 下又有 `p` 标签，`p` 节点下包含文本 "hello world"。JavaScript 正是沿着这条路径精确定位并操作具体节点。
- **DOM 标准演进**：
  - **DOM Level 1**：专注于核心文档结构和 HTML 元素的映射，支持基本的节点操作。
  - **DOM Level 2**：功能大幅扩展，最重要的是引入了标准化的事件模型（如 `addEventListener`）以及 CSS 样式的操作接口，使处理用户交互和样式变更更加优雅。
  - **DOM Level 3**：进一步增加了内容加载和保存的能力，以及对 XML 的验证支持。

## BOM 浏览器对象模型详解 *Content-[11:36]
BOM（Browser Object Model）与 DOM 关注页面内容不同，它关注的是承载页面的容器——浏览器本身。需要注意的是，在很长一段时间内，BOM 并没有像 DOM 那样有非常严格的标准，不同浏览器厂商的实现存在较多差异。

BOM 允许 JavaScript 访问和操作浏览器自身的功能，其核心对象和常用组件包括：

- **window 对象**：BOM 的核心，具有双重身份。第一，它是 JavaScript 访问浏览器窗口的接口（如控制窗口大小位置、设置 `setTimeout` 定时器）；第二，它是 ECMAScript 规范中规定的全局对象（Global Object），在全局作用域中定义的变量和函数本质上都是 `window` 对象上的属性。
- **navigator 对象**：常用于判断当前用户使用的浏览器类型，或是区分 PC 端与手机端。
- **location 对象**：负责管理地址栏，可用于获取当前 URL 或进行页面跳转。
- **history 对象**：负责管理浏览器的历史记录。现代单页应用（SPA）的前端路由实现在很大程度上依赖于 `history` 对象提供的 API。
- **performance 对象**：提供非常精确的性能监测数据，对于前端性能优化至关重要。

## 课程总结与回顾 *Content-[14:00]
当我们谈论 JavaScript 时，讨论的不仅是一门语言，而是一个由三部分组成的完整体系：
- **ECMAScript (ES)**：JavaScript 的基石，定义了变量、逻辑、语法的编写规则，是所有 JS 实现的通用基础。
- **DOM**：页面元素接口，让我们能够用代码读取、修改、删除页面上的 HTML 元素和样式。
- **BOM**：浏览器应用接口，让我们能够控制浏览器窗口的行为，处理导航和历史记录等环境相关的任务。

只有深入理解这三个部分的职责和边界，开发者才能在日常开发中写出更加清晰、更加健壮的代码。
