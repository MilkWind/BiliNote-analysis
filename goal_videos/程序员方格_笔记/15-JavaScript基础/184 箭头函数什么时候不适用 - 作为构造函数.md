## 1\. 构造函数的创建过程 (new 的执行步骤) *Content-[00:00]
详细讲解 `new` 操作符实例化对象时的底层创建过程，这也是前端面试中的一道高频独立面试题。

1\. **创建一个空对象**
   首先，在内存中创建一个全新的空对象，作为将要返回的实例对象（例如变量 `p`）。

2\. **链接原型链**
   为空对象添加 `__proto__` 属性（隐式原型），并将其链接至构造函数的 `prototype`（原型对象）。
   - 这一步使得实例对象 `p` 能够继承构造函数原型上的方法。

3\. **绑定 this 并执行代码**
   将实参带入构造函数，并将构造函数内部的 `this` 指向修改为刚刚创建的空对象 `p`。
   - 随后执行构造函数内部的代码，为实例添加属性。

4\. **返回新对象**
   如果构造函数没有显式返回一个对象，则默认返回这个新创建的实例对象。

## 2\. 箭头函数不能作为构造函数的原因 *Content-[01:39]
由上述构造函数的创建过程可以看出，如果箭头函数作为构造函数并使用 `new` 操作符，会在以下两个核心步骤中失败：

1\. **没有自己的 this**
   - `new` 关键字的核心操作之一是将构造函数的 `this` 指向新创建的实例对象。
   - 箭头函数没有自己的 `this`，它的 `this` 是在定义时继承自外层词法环境的，且无法被改变（即使使用 `call`、`apply` 或 `bind` 也无法改变其指向）。
   - 因此，`new` 操作无法将 `this` 绑定到新创建的实例上。

2\. **没有 prototype 属性**
   - `new` 创建实例时，需要将新实例的 `__proto__` 指向构造函数的 `prototype`，以完成原型链的绑定。
   - 箭头函数没有 `prototype` 属性（即没有原型对象），因此无法完成原型链的绑定。

## 3\. 错误写法与报错分析 *Content-[03:18]
如果强行使用箭头函数作为构造函数并进行实例化，代码会直接抛出错误。

- **错误代码示例**：
  ```javascript
  const Person = (name, age) => {
      this.name = name;
      this.age = age;
  };
  const p = new Person('张三', 20); // 抛出错误
  ```
- **报错信息**：
  控制台会抛出 `TypeError: Person is not a constructor`（Person 不是一个构造函数）。
- **错误原因总结**：
  1. 箭头函数没有自己的 `this`，而 `new` 的核心是将 `this` 指向新创建的实例对象。
  2. 箭头函数的 `this` 继承自外层并且无法改变。
  3. 箭头函数没有 `prototype` 属性，`new` 创建实例时需要将实例的 `__proto__` 指向构造函数的 `prototype`，箭头函数无法完成原型链绑定。

## 4\. 正确写法 *Content-[08:06]
要解决上述问题，只需将箭头函数改为**普通函数**即可。普通函数拥有自己的 `this` 和 `prototype` 属性，能够完美支持 `new` 操作符的实例化过程。

- **正确代码示例**：
  ```javascript
  const Person = function(name, age) {
      this.name = name;
      this.age = age;
  };
  const p = new Person('张三', 20);
  console.log(p); // 正常输出实例对象 { name: '张三', age: 20 }
  ```

## 5\. 验证箭头函数的原型链与 prototype 属性 *Content-[09:20]
通过代码验证，进一步深入理解箭头函数的原型链特性及其与普通函数的区别。

1\. **验证箭头函数存在原型链（但不完整）**
   箭头函数本身是有原型链的，它也有自己的构造函数，但原型链到箭头函数这一环就断掉了，因为它没有 `prototype` 属性，无法连接它实例的原型链。
   ```javascript
   const fn = () => {};
   
   // 验证 Function 的构造函数是否在 fn 的原型链上
   console.log(Function.prototype.isPrototypeOf(fn)); // true
   
   // 验证隐式原型指向
   console.log(fn.__proto__ === Function.prototype); // true
   
   // 验证原型链的顶端
   console.log(fn.__proto__.__proto__ === Object.prototype); // true
   ```
   以上结果证明箭头函数是有原型链的，只是无法用于实例化。

2\. **验证箭头函数没有 prototype 属性**
   对比箭头函数和普通函数的 `prototype` 属性：
   ```javascript
   const fn1 = () => {}; // 箭头函数
   const fn2 = function() {}; // 普通函数
   
   // 箭头函数的 prototype
   console.log(fn1.prototype); // undefined
   
   // 普通函数的 prototype
   console.log(fn2.prototype); // { constructor: ƒ } (存在原型对象)
   ```
   这直接证明了箭头函数没有 `prototype` 属性，因此无法作为构造函数使用。

## AI 总结 *Content-[13:34]
箭头函数不能作为构造函数的核心原因有两点：一是**没有自己的 `this`**，导致 `new` 操作符无法将 `this` 绑定到新创建的实例对象上；二是**没有 `prototype` 属性**，导致无法将实例的 `__proto__` 链接到构造函数的原型对象上，从而无法完成原型链的绑定。在实际开发中，若需要使用 `new` 关键字实例化对象，必须使用普通函数（包括 ES6 的 `class` 语法，其底层也是基于普通函数）来定义构造函数。
