## 1. 案例背景与代码结构 *Content-[00:00]
- 本案例是基于示例 10 的改进，主要增加了第 3 行和第 5 行代码。
- 强调在解决 JavaScript 预解析问题时，必须稳扎稳打，一步一步分析，切忌急躁和凭直觉猜测。
- 核心代码结构如下：
  ```javascript
  var arr = [1, 2, 3]; // 第 1 行
  function test(arr) { // 第 2 行
      console.log(arr); // 第 3 行
      arr = []; // 第 4 行
      console.log(arr); // 第 5 行
  } // 第 6 行
  test(arr); // 第 7 行
  console.log(arr); // 第 9 行
  ```

## 2. 全局预解析阶段 *Content-[00:24]
- **第一步：全局预解析**
  - 遇到 `var arr`：在全局预解析仓库中，变量 `arr` 被声明并赋值为 `undefined`。
  - 遇到 `function test(arr)`：函数声明整体提升，在预解析仓库中，`test` 被赋值为该函数的代码块。
- **预解析仓库最终状态**：
  - `arr = undefined`
  - `test = function(arr) { ... }`

## 3. 全局代码执行与函数调用 *Content-[01:46]
- **第二步：逐行执行全局代码**
  - **第 1 行**：`var arr = [1, 2, 3];`。将数组 `[1, 2, 3]` 赋值给 `arr`，此时全局 `arr` 的值由 `undefined` 变为 `[1, 2, 3]`。
  - **第 2 行**：函数声明。函数声明本身不会改变变量的值，因此不做任何修改操作，直接跳过。
  - **第 7 行**：`test(arr);`。发生函数调用，将全局变量 `arr`（当前值为 `[1, 2, 3]`）作为实参传递给函数 `test`。进入函数内部，开启新的局部作用域。

## 4. 函数局部预解析与执行 *Content-[03:41]
- **第三步：函数内部预解析**
  - 函数内部开启新的预解析和执行规则，与全局规则一致。
  - 函数 `test` 有一个形参 `arr`。在函数内部的预解析仓库中，局部变量 `arr` 被声明，初始值为 `undefined`。
  - **注意**：函数内部的预解析与外部全局作用域无关，是独立的局部作用域。
- **第四步：逐行执行函数内部代码**
  - **第 3 行**：`console.log(arr);`。
    - 函数调用时传递了实参 `arr`（全局中的 `[1, 2, 3]`）。
    - 形参 `arr` 接收实参，此时局部 `arr` 的值变为 `[1, 2, 3]`。
    - 因此，第一次打印的结果为 `[1, 2, 3]`。
  - **第 4 行**：`arr = [];`。
    - 将空数组 `[]` 赋值给 `arr`。
    - **作用域核心考点**：由于函数内部预解析时已经声明了局部变量 `arr`，根据作用域链“就近原则”，修改的是局部作用域中的 `arr`，而**不是**全局的 `arr`。
    - 此时局部 `arr` 的值由 `[1, 2, 3]` 变为 `[]`。
  - **第 5 行**：`console.log(arr);`。
    - 打印局部变量 `arr` 的当前值。
    - 因此，第二次打印的结果为 `[]`（空数组）。

## 5. 函数执行完毕与全局后续执行 *Content-[08:58]
- **第五步：函数执行完毕，回到全局**
  - `test` 函数执行完毕，局部作用域销毁。
  - 继续执行全局代码，来到 **第 9 行**。
- **第六步：执行全局第 9 行代码**
  - **第 9 行**：`console.log(arr);`。
  - 此时在全局作用域中查找变量 `arr`。全局作用域不能访问局部作用域的变量，因此找到的是全局的 `arr`。
  - 全局的 `arr` 在函数执行期间并未被修改，其值依然是 `[1, 2, 3]`。
  - 因此，第三次打印的结果为 `[1, 2, 3]`。

## 6. 最终结果验证 *Content-[10:22]
- 将代码放入执行环境中运行验证。
- 控制台输出结果依次为：
  1. `[1, 2, 3]`
  2. `[]`
  3. `[1, 2, 3]`
- 分析与实际运行结果完全一致，证明了预解析和作用域分析的正确性。

## AI 总结
- 本视频详细讲解了 JavaScript 预解析机制中的经典实战案例，重点剖析了**全局作用域**与**局部作用域**的交互关系。
- 核心知识点包括：
  1. **预解析机制**：`var` 声明的变量提升为 `undefined`，`function` 声明的函数整体提升。
  2. **作用域链与就近原则**：函数内部如果存在与外部同名的变量（或形参），在赋值和访问时会优先使用局部变量，不会污染全局变量。
  3. **参数传递**：函数调用时，实参的值会传递给形参，形参在局部作用域中表现为一个已赋值的局部变量。
- 解决此类面试题时，必须严格按照“全局预解析 -> 全局执行 -> 局部预解析 -> 局部执行 -> 回到全局”的步骤进行推演，切忌凭直觉跳跃思考。
