## Map 的定义与核心特性 *Content-[00:00]

Map 是 ES6 引入的一个核心数据结构，专门用于存储键值对的集合。你可以将其理解为一个功能更加纯粹、更加强大的字典结构，它解决了传统意义上使用 Object 作为键值存储时面临的一些限制。

Map 具有以下几个显著的核心特性：

1\. **任意类型键**：键（key）可以是任意数据类型，不再局限于字符串或 `Symbol`。对象、函数甚至是基本数据类型都可以作为 key 值。
2\. **保持插入顺序**：Map 严格保持元素的插入顺序。这意味着以什么顺序添加数据，在遍历时就会以相同的顺序取出。而在 Object 中，尤其是处理数字类型的 key 时，顺序是无法完全得到保证的。
3\. **性能优势**：相较于 Object，在频繁进行增删操作的场景下，Map 的内部实现通常会提供更好的性能表现。

**代码示例要点**：
通过 `new Map()` 创建实例，使用 `set` 方法添加数据。在 Map 中，可以分别使用字符串、数字、对象和函数作为 key，这在普通 Object 中是无法直接实现的。此外，通过 `size` 属性可以直接获取 Map 中键值对的数量，无需像 Object 那样手动计算。

## Map 与 Object 的关键区别 *Content-[02:58]

为了直观理解“任意类型键”这一特性解决了什么问题，我们需要对比 Map 和 Object 在处理键值时的差异。

**Object 的局限性**：
- **数字键隐式转换**：当尝试使用数字 `1` 作为 key 时，JavaScript 引擎会将其隐式转换为字符串 `"1"`。因此，先后使用数字 `1` 和字符串 `"1"` 赋值时，实际上是在操作同一个属性，后面的赋值会覆盖前面的。
- **对象键转换冲突**：当把对象（如 `k1` 和 `k2`）作为 key 时，Object 会强制调用其 `toString()` 方法，结果都会变成字符串 `"[object Object]"`。这会导致同名键冲突，`k2` 的值会覆盖 `k1` 的值，最终只存储了一个值。

**Map 的优势**：
- **精确区分类型**：Map 能够精确区分数字 `1` 和字符串 `"1"`，将它们视为两个完全不同的 key，因此它们可以共存。
- **基于内存引用**：对于对象类型的 key，Map 比较的是对象的内存引用地址。`k1` 和 `k2` 是两个不同的对象实例，在 Map 中它们就是两个独立的 key，互不干扰。这在需要将元数据关联到特定对象实例的场景中非常有用。

## Map 的 API 设计与操作 *Content-[05:05]

Map 的 API 设计非常直观，语义明确，遵循常见的增删改查模式。

**主要操作方法**：
1\. `set(key, value)`：添加一个新的键值对，或者更新一个已经存在的 key。该方法执行后会返回 Map 实例本身，因此支持**链式调用**，可以方便地在一行代码中添加多个数据。
2\. `get(key)`：根据 key 获取对应的值。
3\. `has(key)`：检查一个 key 是否存在于 Map 中，返回布尔值。
4\. `delete(key)`：删除指定的键值对。
5\. `clear()`：一次性清空整个 Map。

**重要属性**：
- `size`：直接返回 Map 中键值对的数量。这是一个 $O(1)$ 复杂度的操作，意味着无论 Map 中有多少数据，获取其大小都非常快。相比之下，获取 Object 的属性数量需要调用 `Object.keys().length`，性能优势更加明显。

## Map 的迭代机制 *Content-[07:31]

Map 是一个内置的可迭代对象，并且严格遵守插入顺序。可以通过包含键值对数组的数组（如 `[['apple', 1], ['banana', 2]]`）来快捷初始化 Map。

**常见的遍历方式**：

1\. **`entries()` 方法**：返回一个迭代器，每个元素都是 `[key, value]` 形式的数组。可以方便地在 `for...of` 循环中通过解构赋值获取 key 和 value，输出顺序与插入顺序完全一致。
2\. **`keys()` 与 `values()` 方法**：分别返回只包含 key 或 value 的迭代器。可以配合展开运算符 `...` 直接将它们转换成数组。
3\. **`forEach()` 方法**：与数组的 `forEach` 非常相似，接收一个回调函数。需要特别注意的是，回调函数的参数顺序是 **value 在前，key 在后**，这是为了与 `Array.prototype.forEach` 及其他集合类型的 `forEach` 保持一致。
4\. **直接使用 `for...of`**：这是最常用、最简洁的方法。因为 Map 默认的迭代器就是 `entries` 迭代器，所以可以直接在 `for...of` 循环中使用 Map 实例本身并进行解构赋值，代码非常优雅。

## 实际项目中的选型指南 *Content-[09:49]

在实际项目中，选择 Map 还是 Object 需要根据具体的业务场景来决定。

**优先选择 Map 的场景**：
1\. **非字符串类型键**：需要将 DOM 节点或对象实例作为 key 来关联数据时，必须使用 Map。
2\. **频繁增删操作**：数据集合会频繁添加或删除，Map 的内部实现针对此类操作有性能优化。
3\. **需要保证顺序**：要求数据的迭代顺序与插入顺序严格一致。
4\. **频繁获取集合大小**：需要快速、频繁地获取集合大小，Map 的 `size` 属性是 $O(1)$ 复杂度，比 Object 更高效。
5\. **动态 key**：key 是动态生成的，使用 Map 的 `get`/`set` 方法比操作 Object 的动态属性更加清晰、安全。

**优先选择 Object 的场景**：
1\. **固定的字符串键**：在编码时已知的固定字符串 key（如简单的配置对象），Object 的字面量语法更加简洁。
2\. **JSON 数据交换**：需要与 JSON 格式进行频繁的数据交换时，`JSON.stringify` 和 `JSON.parse` 对 Object 是原生支持的，而 Map 需要进行额外的转换步骤。
3\. **解构赋值**：Object 支持解构赋值，而 Map 目前还不支持。
4\. **结构化数据记录**：当目的只是为了存取一个结构化的数据记录（纯数据对象）时，Object 更符合语义。

**选型原则总结**：
当你需要一个**字典或者哈希表**数据结构时，选择 Map；当你只是需要一个简单的 **Record 或者是纯数据对象**时，选择 Object。

## AI 总结 *Content-[12:42]

Map 作为 ES6 引入的核心数据结构，弥补了传统 Object 在键值存储上的诸多不足。它最大的亮点在于支持任意数据类型作为键、严格保持插入顺序以及在频繁增删场景下的性能优势。在与 Object 的对比中，Map 能够精确区分不同类型的键并基于内存引用处理对象键，避免了隐式类型转换带来的冲突。在实际开发中，开发者应遵循“字典/哈希表用 Map，结构化纯数据对象用 Object”的选型原则，结合 JSON 交互、解构赋值等具体需求，做出最合适的技术选择。
