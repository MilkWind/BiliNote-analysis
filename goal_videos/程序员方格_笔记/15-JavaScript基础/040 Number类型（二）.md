## Number 对象的静态方法与类型检查 *Content-[00:38]

本节课深入探讨 JavaScript 中的数值系统及其特殊的边界情况，重点介绍 `Number` 对象挂载的静态方法及其使用场景。

### `Number.isInteger()`
- **功能**：用于判断一个值是否为整数。
- **底层机制**：在 JavaScript 中，`1` 和 `1.0` 在底层是同一个值，因此都会返回 `true`。
- **严格类型检查**：该方法非常严格，**不会进行隐式类型转换**。例如，字符串 `"1"` 虽然看起来像整数，但由于其数据类型是字符串，因此会直接返回 `false`。

### `Number.isNaN()` (面试高频考点)
- **功能**：用于判断一个值是否为 `NaN` (Not a Number)。
- **对比旧版全局 `isNaN()`**：
  - **全局 `isNaN()` 的缺陷**：会先尝试将参数转换成数字。例如，传入字符串 `"hello"`，转换数字失败后变成 `NaN`，从而导致误报返回 `true`。
  - **`Number.isNaN()` 的优势**：挂载在 `Number` 对象上，**不会进行类型转换**。只有当参数真的是 `NaN` 这个特殊值时，才会返回 `true`。
- **最佳实践**：在当前版本的开发中，建议全面使用 `Number.isNaN()` 替代旧版的全局 `isNaN()` 函数。

## 安全整数与精度丢失问题 *Content-[02:36]

在处理后端返回的大 ID 或进行高精度计算时，理解“安全整数”的概念至关重要。

### 双精度浮点数与范围限制
- JavaScript 使用**双精度浮点数**（IEEE 754 标准）存储所有的数字。
- 这导致其能够精确表示的整数范围是有限的。
- 安全整数的上限为 `Number.MAX_SAFE_INTEGER`，其值为 $2^{53} - 1$（大约是 9000 万亿，即 $9,007,199,254,740,991$）。在这个范围内，整数是安全的。

### 精度丢失的致命影响
- 一旦超过安全整数范围，就会发生严重的**精度丢失**。
- **相等性判断错误**：例如 $9,007,199,254,740,992$ 和 $9,007,199,254,740,993$ 这两个完全不同的数字，在 JavaScript 中会被判定为相等。
- **运算异常**：在超大数值下进行加法运算时，`+1` 可能没有任何反应，`+2` 会直接跳过中间值。这是因为尾数位的位数不够用了。
- **业务风险**：如果业务涉及高精度的金融计算，或者处理数据库大整数 ID（主键），这种精度丢失错误是致命的。

## 应对大数值与精度丢失的方案 *Content-[04:04]

既然存在精度丢失的风险，可以通过以下两种主要方式来应对：

### 1\. 使用 `Number.isSafeInteger()` 进行检测
- **功能**：在进行关键运算或接收外部数据时，使用该方法检测数值是否在安全范围内。
- **返回值**：只要返回 `false`，就意味着该数值可能已经失去了精度，或者它根本就不是一个整数。

### 2\. 使用 `BigInt` 类型处理超大整数
- **适用场景**：当业务需求确实需要处理超出安全范围的整数时。
- **使用方法**：放弃 `Number` 类型，改用 `BigInt`。在数字字面量后面加上 `n`（例如 `123n`）。
- **优势**：`BigInt` 能够进行任意精度的整数运算，彻底解决大整数精度丢失的问题。

## 其他 Number 静态方法 *Content-[05:08]

除了上述方法，`Number` 对象还挂载了其他几个常用的静态方法：

### `Number.isFinite()`
- **功能**：检测一个值是否是有限的（即不是无穷大，也不是 `NaN`）。
- **特性**：与前面的方法一样，它也是一个**严格的类型检查**，不会接收字符串进行隐式转换。如果传入非数字类型或无穷大、`NaN`，均返回 `false`。

### `Number.parseInt()` 与 `Number.parseFloat()`
- **背景**：在 ES6 中，为了语言的规范性，将全局的 `parseInt` 和 `parseFloat` 方法搬到了 `Number` 对象上。
- **功能**：它们的功能与全局版本完全一样。
- **优势**：使用 `Number.parseInt()` 这种写法，使得代码的命名空间更加清晰，也更加符合 JavaScript 模块化的设计规范。

## AI 总结

本视频深入讲解了 JavaScript 中 `Number` 类型的进阶知识，重点剖析了数值系统的边界情况与精度问题。核心要点包括：
1. **严格类型检查**：推荐使用 `Number.isInteger()`、`Number.isNaN()` 和 `Number.isFinite()`，它们不进行隐式类型转换，比旧版全局函数更安全可靠。
2. **安全整数与精度丢失**：JS 使用双精度浮点数，最大安全整数为 $2^{53}-1$。超出此范围会导致精度丢失，对金融计算和数据库大 ID 处理是致命的。
3. **解决方案**：使用 `Number.isSafeInteger()` 校验数值安全性；对于超大整数需求，应使用 `BigInt` 类型（数字后加 `n`）以保证任意精度运算。
4. **模块化规范**：ES6 将 `parseInt` 和 `parseFloat` 移至 `Number` 对象下，使命名空间更清晰，符合现代 JS 模块化设计。
