## 1. 传统 var 声明与全局污染 *Content-[00:01]

### 传统变量声明方式
- 在传统的 JavaScript 开发中，我们通常使用 `var` 关键字来声明变量，或者使用 `function` 关键字声明函数。
- 当这些声明写在全局作用域（例如直接写在 `<script>` 标签中或独立的全局 JS 文件里）时，它们会被创建为**全局变量**或**全局函数**。

### 全局变量与 window 对象的绑定
- 全局变量和全局函数会自动绑定到全局的 `window` 对象上。
- 这意味着我们不仅可以直接通过变量名（如 `a` 或 `demo`）来访问它们，还可以通过 `window.a` 和 `window.demo` 来获取。
- 如果在多个 JS 文件中，后加载的文件也可以直接访问前面文件中定义的全局变量。

### 全局污染的严重危害
- 全局变量的作用范围太广，极易导致**全局命名空间污染**。一旦变量名被占用，其他模块或文件再使用同名变量就会引发冲突和 Bug。
- **生动比喻**：
  - 假设一对小情侣逛街，女生生气上头时骂了一句：“全天下没有一个好男人，男人都是渣男！”
  - 这句话的“覆盖范围”太广，把全世界男人都骂了，导致旁边无辜的路人（其他变量/模块）受到牵连，甚至引发冲突（代码报错）。
  - 相反，如果是“指名道姓”地骂（相当于局部变量），则只会影响特定对象，不会波及无辜。
- 因此，尽量避免在全局作用域下随意创建变量，以防止全局污染。

## 2. ES6 let 和 const 的引入及特性 *Content-[03:44]

### 块级作用域变量的诞生
- 为了解决 `var` 带来的全局污染和变量提升等问题，ES6 推出了块级作用域变量声明关键字：`let` 和 `const`。
- 使用 `let` 和 `const` 声明变量时，**不允许在同一作用域内重复声明同名变量**。

### 脱离 window 对象绑定
- 当在全局作用域下使用 `let` 和 `const` 声明变量时（例如 `let aa = 99; const bb = 66;`），它们**不再属于传统意义上的全局变量**。
- **核心区别**：它们**不会**绑定到 `window` 对象上。
- 因此，尝试通过 `window.aa` 或 `window.bb` 进行打印或获取时，结果是 `undefined` 或报错，无法通过 `window` 对象访问。
- 虽然它们在全局作用域下声明，但只能通过**直接输入变量名**（如 `aa`、`bb`）来进行访问。

## 3. 块级作用域的具体表现 *Content-[05:47]

### 跨 script 标签的访问
- 如果将 `let` 和 `const` 声明的变量分别写在两个不同的 `<script>` 标签中，由于浏览器底层在解析时会将它们合并到同一个全局执行上下文中，因此在后面的 `<script>` 标签中依然可以通过变量名直接访问。

### 大括号 {} 的块级隔离
- `let` 和 `const` 真正的“块级作用域”特性体现在**大括号 `{}`** 中。
- 一旦将 `let` 或 `const` 声明的变量放入 `{}` 内部，它们的作用域就被严格限制在该代码块内。
- **对比测试**：
  - 将 `var` 或 `function` 放入 `{}` 中，在块外部依然可以访问（非严格模式下）。
  - 将 `let` 或 `const` 放入 `{}` 中，在块外部访问会直接报错（`ReferenceError`）。
  - 甚至在另一个完全独立的 `<script>` 标签中尝试访问 `{}` 内部的 `let`/`const` 变量，同样会报错，因为作用域已经被彻底隔离。

## 4. 底层原理与 globalThis *Content-[07:10]

### globalThis 与 window 的关系
- 有些开发者可能会想到使用 `globalThis` 对象来获取全局变量。
- 在浏览器环境中，`globalThis` 和 `window` 是**全等（`===`）** 的关系，它们指向同一个对象。
- 因此，既然 `let`/`const` 不绑定 `window`，自然也无法通过 `globalThis.aa` 来获取。

### 底层存储环境的区别
- **对象环境（Object Environment）**：`var` 声明的全局变量会直接绑定到 `window` 对象的属性上。
- **词法环境（Lexical Environment）**：`let` 和 `const` 声明的变量存储在词法环境的记录中。它们存在于当前所处的块级作用域位置，独立存储，不对外曝光。
- **ES6 的设计初衷**：特意将全局变量与全局对象（`window`）进行**解耦**。这样做的目的是避免全局命名空间污染，使得代码更加模块化、更加安全。

## 5. 最佳实践与开发建议 *Content-[08:23]

### 变量声明的优先级
1. **优先使用 `const`**：`const` 用于声明常量，一旦赋值后其引用地址不可更改。优先使用 `const` 可以最大程度保证数据的安全性，防止意外修改。
2. **其次使用 `let`**：当明确知道某个变量的值在后续逻辑中需要被更改时，使用 `let`。它同样具备块级作用域特性，能有效避免变量污染。
3. **避免使用 `var`**：由于 `var` 存在变量提升、全局污染、函数作用域而非块级作用域等缺陷，在现代前端开发中应尽量避免使用。

### 模块化开发中的全局变量处理
- 在模块化（如 ES6 Modules）开发中，不应再依赖全局变量来共享数据。
- 如果确实需要让某个变量在多个模块中生效，应该通过模块的**对外暴露机制**（如 `export` / `import`）来进行共享，而不是将其挂载到全局对象上。

## AI 总结

本视频详细讲解了前端面试中高频考点：`let` 和 `const` 变量声明的核心特性及其与 `var` 的本质区别。核心要点包括：
1. `var` 声明的全局变量会绑定到 `window` 对象，容易引发全局命名空间污染；而 `let` 和 `const` 实现了全局变量与全局对象的解耦，不绑定 `window`（也不绑定 `globalThis`）。
2. `let` 和 `const` 具备严格的**块级作用域**，在 `{}` 内部声明的变量无法在外部被访问，底层存储在词法环境（Lexical Environment）中。
3. 在实际开发中，应遵循“优先使用 `const`，必要时使用 `let`，杜绝使用 `var`”的最佳实践，并通过模块化的 `export` 机制来管理跨文件的数据共享，从而提升代码的安全性和可维护性。
