## 引言与核心问题 *Content-[00:01]
在前端面试中，`call`、`apply` 和 `bind` 是几乎必考的知识点。它们不仅考察对 JavaScript 中 `this` 机制的理解，更能反映对函数调用和上下文控制的掌握程度。

本期视频重点解答三个核心问题：
1\. **控制 `this` 指向**：函数运行时的 `this` 指向容易让人头疼，如何精确控制？
2\. **区别与联系**：这三个方法看起来很相似，到底有什么区别和联系？
3\. **底层原理**：抛开 V8 引擎复杂的 C++ 代码，如何用 JavaScript 模拟实现这三个方法，从而理解核心原理？

## 基本概念与核心作用 *Content-[01:10]
`call`、`apply` 和 `bind` 是 JavaScript 中 `Function.prototype` 对象上的三个方法，这意味着任何一个普通的 JavaScript 函数实例都可以直接调用它们。

- **核心作用**：帮助我们显式指定函数执行时的上下文，也就是内部的 `this` 关键字的值。
- **主要使用目的**：
  - **解决 `this` 指向不确定的问题**：JavaScript 中的 `this` 非常灵活但也容易混淆，尤其在回调函数和异步操作中。通过这三个方法，可以强制函数在指定对象的上下文中执行。
  - **借用其他对象的方法**：非常常见的用法，例如将数组的某些方法借用到类数组对象上。
  - **提供灵活的参数处理方式**：`apply` 和 `call` 在参数处理上有所不同，提供了不同的便利性。

## call 方法详解 *Content-[02:46]
- **语法**：`call(thisArg, arg1, arg2, ...)`
- **主要特点**：
  - **立即执行**：会立即执行调用它的函数，而不会返回一个新函数。
  - **指定 `this`**：第一个参数 `thisArg` 是希望函数执行时 `this` 所指向的对象。
  - **参数逐个传入**：从第二个参数开始，需要逐个列出传递给目标函数的参数。
- **`thisArg` 的小细节**：
  - 如果传入 `null` 或 `undefined`：在非严格模式下，函数内部的 `this` 会自动指向全局对象（浏览器环境的 `window` 或 Node.js 的 `globalThis`）。
  - 如果传入基本类型值（如字符串、数字、布尔值）：它们会被自动包装成对应的包装对象（例如字符串 `'abc'` 会被包装成 `String` 对象）。
- **返回值**：直接返回原始函数的执行结果。
- **示例说明**：
  - 假设有一个 `greet` 函数打印问候语，内部使用了 `this.name`。如果直接调用 `greet('Hello', '!')`，在非严格模式下 `this` 默认指向 `window`，导致输出不符合预期。
  - 使用 `greet.call(person, 'Hello', '!')`，明确指定 `this` 为 `person` 对象，控制台就能正确输出预期的问候语。

## apply 方法详解 *Content-[06:22]
- **语法**：`apply(thisArg, [argsArray])`
- **与 `call` 的区别**：
  - 功能上非常相似，同样会立即执行函数，且第一个参数 `thisArg` 的处理规则与 `call` 完全一致。
  - **核心区别在于参数传递方式**：`apply` 只接收两个参数，第二个参数要求将所有传递给函数的参数放在一个**数组或类数组对象**里。数组中的元素会被展开，作为函数的各个参数传入。
- **示例说明**：
  - 假设有一个 `sum` 函数计算三个数的和，并打印 `this.name`。如果有一个包含数字的 `numbers` 数组，普通调用需要手动展开参数，较为繁琐。
  - 使用 `sum.apply(object, numbers)`，第一个参数指定 `this` 为 `object`，第二个参数直接传入数组。这样不仅正确指向了 `this.name`，还自动将数组元素作为参数传递，展示了 `apply` 在参数已组织成数组时的极大便利性。

## bind 方法详解与高级特性 *Content-[09:20]
- **语法**：`bind(thisArg, arg1, arg2, ...)`
- **核心特点**：
  - **不会立即执行**：与 `call` 和 `apply` 不同，`bind` 不会立即调用函数。
  - **返回新函数**：它会返回一个全新的函数。
  - **永久固定 `this`**：当这个新函数被调用时，其内部的 `this` 会被永久固定为 `bind` 时传入的 `thisArg`。
  - **预设参数（偏函数）**：`bind` 时传入的参数会作为新函数的预设参数，放在参数列表的最前面。
- **示例说明**：
  - 调用 `sayHello.bind(user, 'Hi')` 会返回一个新函数 `boundSayHello`，此时原函数尚未执行。
  - 当调用 `boundSayHello()` 时，`this` 被固定为 `user` 对象，且 `'Hi'` 作为第一个参数传入，最终输出 "Hi Bob"。这特别适用于事件监听器等需要固定上下文的回调场景。
- **高级特性（作为构造函数）**：
  - 当 `bind` 创建的新函数被 `new` 操作符调用（即作为构造函数）时，`bind` 时指定的 `thisArg` 会被**完全忽略**（失效）。
  - 此时，函数内部的 `this` 会指向 `new` 操作符创建的新实例。
  - 但是，`bind` 时预设的参数依然有效，会作为构造函数参数的一部分传递进去。

## 底层原理与模拟实现 *Content-[14:51]
JavaScript 引擎的底层实现是复杂的 C++ 代码，但我们可以通过模拟实现来抓住其核心思想。

- **核心思想**：利用 JavaScript 中的一个特性——**函数作为对象的方法调用时，其内部的 `this` 会指向调用该方法的对象**。
- **模拟 `call` / `apply` 的步骤**：
  1\. **获取原函数**：获取调用 `call` 或 `apply` 的原始函数本身。
  2\. **获取目标对象**：拿到第一个参数 `thisArg`，即希望 `this` 指向的目标对象。
  3\. **临时挂载方法**：将原始函数临时作为目标对象的一个方法存储。为了防止属性覆盖，可以使用 `Symbol` 创建一个独一无二的属性名。
  4\. **调用临时方法**：通过目标对象调用刚才添加的临时方法（如 `targetObj[symbol](...args)`）。此时由于是对象调用，`this` 自然指向目标对象，同时传入相应的参数。
  5\. **清理临时方法**：函数执行完毕后，必须删除目标对象上的临时方法，避免污染原对象。
- **模拟 `bind` 的额外处理**：
  - **延迟执行**：不能立即执行上述步骤，而是将挂载、调用、删除的过程包裹在一个**新返回的函数**中。
  - **合并参数**：需要处理好两次传入的参数，将 `bind` 时的预设参数与调用新函数时传入的参数合并在一起传递给原始函数。
  - **处理 `new` 调用**：需要额外判断新函数是否被 `new` 调用，如果是，则忽略绑定的 `this`，使其指向新创建的实例。

## 总结回顾 *Content-[18:15]
- **`call` 和 `apply`**：作用是立即改变函数执行时的 `this` 指向并执行函数。两者的区别仅仅在于参数传递方式，`call` 接收参数列表，`apply` 接收参数数组。
- **`bind`**：更加灵活，不立即执行函数，而是返回一个固定了 `this` 和部分参数的新函数，非常适合延迟执行和作为回调使用。
- **底层原理**：无论是哪种方法，其模拟实现都巧妙地利用了“函数作为对象方法调用时 `this` 指向调用者”的特性。理解了这些用法和原理，在应对前端面试中的相关场景题时会更加从容自信。
