## 面试题背景与考察重点 *Content-[00:00]

在前端面试中，经常会遇到关于 JavaScript 继承的面试题。核心问题通常是：**ES5 和 ES6 的继承除了写法以外，还有什么本质区别？**

- **考察核心**：这道题主要考察应聘者对 ES5 中面向对象编程（模拟继承）的底层理解。虽然 ES6 的 `class` 继承写法更简单，但面试官更看重候选人是否理解 ES5 是如何“模仿”面向对象来实现继承的。
- **为什么现在还要考 ES5**：
  - 很多现代前端框架的底层代码和编译后的语法依然依赖 ES5 逻辑。
  - ES6 的许多语法糖（如 `class`）在底层编译后，本质上也是 ES5 的模拟实现逻辑。因此，理解 ES5 的继承机制对于排查底层问题和深入理解 JS 引擎至关重要。

## ES5 中的继承实现（寄生组合式继承） *Content-[02:26]

在 ES5 中，JavaScript 并没有真正的“类”概念，继承是通过函数（`function`）和原型链（`prototype`）模拟出来的。最标准的实现方式是**寄生组合式继承**。

### 1\. 定义父类
- 使用 `function` 定义父类构造函数，接收参数并绑定到 `this`（如 `name`）。
- 在构造函数内部定义实例属性（如 `colors`）。
- 通过 `prototype`（原型链）在父类上挂载公共方法（如 `sayName`），这样所有实例化对象都可以直接调用该方法。

### 2\. 定义子类并继承属性
- 同样使用 `function` 定义子类构造函数，接收子类特有的参数（如 `name`, `age`）。
- **关键步骤 1：借用构造函数继承属性**。在子类构造函数内部，使用 `Parent.call(this, name)`。
  - `call` 方法的作用是“借用执行”：让子类的实例（`this`）去执行父类的构造函数。
  - 这样可以将父类的所有属性继承到子类中，并且可以传入子类自己的参数，保证属性的独立性。

### 3\. 继承方法并修复构造函数指向
- **关键步骤 2：继承原型方法**。将子类的原型链指向父类的原型对象。
  - 代码实现：`Child.prototype = Object.create(Parent.prototype)`（注：视频转录中识别为“object的CLID”，实为 `Object.create` 方法）。
  - 这样子类就可以直接调用父类原型链上的方法。
- **关键步骤 3：修复 `constructor` 指向**。
  - 由于重写了子类的 `prototype`，其 `constructor` 属性会默认指向父类。
  - 必须手动修复：`Child.prototype.constructor = Child`。
  - 如果不修复，后续在子类原型上添加的方法可能会出现访问异常或指向错误。

## ES6 中的继承实现（Class 与 Extends） *Content-[09:00]

ES6 引入了 `class` 和 `extends` 关键字，使继承的写法更加简洁、直观，更接近传统的面向对象语言。

### 1\. 定义父类
- 使用 `class` 关键字定义父类。
- 在 `constructor` 中初始化属性（如 `name`, `colors`）。
- 直接在类中定义公共方法，无需手动挂载到 `prototype` 上。

### 2\. 定义子类并继承
- 使用 `class Child extends Parent` 语法，明确指定继承父类。
- **关键步骤 1：调用 `super()`**。
  - 在子类的 `constructor` 中，**第一行**必须调用 `super(...args)`。
  - `super` 的作用：调用父类的构造函数，继承父类的属性。必须传入与父类 `constructor` 对应的参数。
  - **重要限制**：`super()` 必须写在子类构造函数的第一行。只有在调用 `super()` 之后，才能使用 `this` 关键字或定义子类自有的属性（如 `this.age = age`）。

## ES5 与 ES6 继承的核心区别总结 *Content-[12:12]

通过代码实现可以看出，两者在底层机制和语法表现上有显著差异：

### ES5 继承特点
- **本质**：属于“寄生组合式继承”，是模拟的面向对象。
- **属性继承**：通过 `call` 或 `apply` 借用构造函数，手动继承父类属性。
- **方法继承**：通过 `Object.create()` 手动将子类原型指向父类原型，继承父类方法。
- **构造函数修复**：必须手动修复子类 `prototype.constructor` 的指向，否则会导致原型链混乱。

### ES6 继承特点
- **本质**：原生支持类与继承，语法更科学、合理。
- **自动处理**：使用 `extends` 关键字，引擎会自动处理原型链和静态方法的继承，无需手动操作。
- **super 调用**：`super` 必须在子类 `constructor` 最前面调用，用于初始化父类构造函数的内容。
- **安全性**：默认返回 `this`，构造函数的返回更加安全，彻底告别了手动修复原型链指向的繁琐步骤。

## AI 总结 *Content-[14:15]

ES5 和 ES6 的继承在本质上是从“手动模拟”到“原生支持”的进化。ES5 通过 `call` 借用构造函数继承属性，通过 `Object.create` 继承方法，并需要手动修复 `constructor` 指向，过程繁琐且容易出错；而 ES6 通过 `class`、`extends` 和 `super` 关键字，将复杂的原型链操作封装在底层，实现了属性和方法的自动继承。理解 ES5 的底层模拟逻辑，有助于开发者更深刻地掌握 JavaScript 的原型链机制，从而在面试和实际开发中游刃有余。
