## 真题一：函数声明和函数表达式的区别 *Content-[00:02]

在 JavaScript 中，函数声明和函数表达式的核心区别主要体现在以下四个维度：

### 1. 定义方式不同
- **函数声明**：以 `function` 关键字开头，直接写函数名、形参和函数体，无需赋值给变量。这是我们平时最常写的标准格式。
- **函数表达式**：把函数作为值赋值给一个变量。通常是一个匿名函数，格式如 `const sayHello = function() {}`，即一个正常的变量，其值为函数。

### 2. 变量提升不同
- **函数声明**：会**整体提升**，包括函数名和函数体。因此可以先调用后定义，不会报错。
- **函数表达式**：只**提升变量声明**，不提升函数赋值。变量提升后的值为 `undefined`，因此必须先定义后调用，否则调用时会报错。

### 3. 函数名使用不同
- **函数声明**：有明确的函数名，可以通过函数名直接调用，也能在函数内部通过函数名实现递归。
- **函数表达式**：通常是匿名函数，只能通过赋值的变量去调用。若为**具名函数表达式**（如 `const sayHello = function fn() {}`），其函数名 `fn` **只能在函数内部使用**，外部无法调用。
  - *验证示例*：在外部调用具名函数表达式的函数名 `fn()` 会报错 `Fn is not defined`；但在函数内部调用 `fn()` 是可以执行的（常用于递归），但需注意避免无限递归导致栈溢出（Stack overflow）。

### 4. 使用场景不同
- **函数声明**：适合定义通用的、可多次复用的工具函数，函数复用性高。
- **函数表达式**：更加灵活，适合定义临时使用的函数，如回调函数、事件处理函数、立即执行函数（IIFE），能有效避免全局变量污染。

## 真题二：变量提升上的不同及案例说明 *Content-[03:16]

- **核心区别**：函数声明会整体提升（函数名+函数体），函数表达式只提升变量声明，不提升赋值操作。
- **案例说明**：
  - 对于函数声明，在代码执行前，函数已经被提升到作用域顶部，因此在定义之前调用可以正常执行。
  - 对于函数表达式，由于只提升了变量声明，在赋值操作执行前，变量的值为 `undefined`。如果此时尝试调用，会因为 `undefined` 不是函数而报错。必须等待赋值完成后，才能正常调用执行。

## 真题三：调用与定义顺序的核心原因 *Content-[03:39]

为什么函数声明可以先调用后定义，而函数表达式必须先定义后调用？核心原因在于 **JS 的变量提升机制**，具体分为两种情况：

- **函数声明**：JS 在执行代码前，会将函数声明**整体提升**到当前作用域的最顶部（包括函数名和函数体）。相当于提前把整个函数准备好了，所以可以在声明之前直接调用，不会报错。
- **函数表达式**：本质是**变量的赋值**。JS 只会提升变量的声明，不会提升赋值操作。也就是说，变量会被提升到作用域顶部，但变量值（函数体）没有被提升，此时变量的值为 `undefined`（不是函数）。因此先调用会报错，必须等待赋值完成后才能正常执行。

> **形象比喻**：
> - 函数声明：提前准备好了**整个工具**，随时可用。
> - 函数表达式：提前准备好了**工具盒**，但还没有把工具放进去，需要等赋值后才能使用。

## 真题四：实际开发中的选择策略 *Content-[04:55]

在实际开发中，应根据函数的**复用性**和**使用场景**来选择，核心原则如下：

### 1. 选择函数声明的场景
- **适用情况**：函数需要多次复用，是通用的工具函数，全局可用。
- **典型案例**：计算两个数的和、验证手机号格式（如 `checkPhone`）、格式化时间等。
- **优势**：这些函数会在很多地方调用，使用函数声明定义可以直接调用，可读性高，复用性强。

### 2. 选择函数表达式的场景
- **适用情况**：函数是临时的，只在特定地方应用，无需全局复用。
- **典型案例**：
  - **案例一（回调函数）**：数组遍历（如 `forEach`）中的回调函数，只在遍历内部使用，无需复用，使用函数表达式更合适。
  - **案例二（事件处理）**：按钮点击事件（如 `document.getElementById('btn').onclick = function() {}`），直接赋值一个匿名函数表达式。
  - **案例三（立即执行函数）**：执行一次即结束，无需复用。使用函数表达式（IIFE）可以创建独立作用域，避免全局污染。

> **总结**：通用复用选**函数声明**，临时使用选**函数表达式**。核心目的是提高代码可读性，避免全局污染。

## 真题五：箭头函数的归属及验证 *Content-[07:18]

**结论**：箭头函数属于**函数表达式**。

**核心原因**：
1. **没有函数声明的格式**：函数声明必须以 `function` 关键字开头，且有明确的函数名。而箭头函数没有 `function` 关键字，也没有独立的函数名，本质就是一个匿名函数。
2. **必须赋值给变量或作为回调**：箭头函数必须赋值给变量才能调用，或者作为回调函数使用，这完全符合函数表达式的核心特征。

**验证与补充**：
- 将箭头函数赋值给变量（如 `const add = (a, b) => a + b`），属于函数表达式的特征，可正常执行。
- 箭头函数作为回调函数（如数组遍历中），也是函数表达式的特点。
- **补充说明**：箭头函数**不能**作为函数声明使用。如果不赋值给变量直接写箭头函数语法，虽然可能不报错，但无法执行调用。必须赋值给变量（如 `const res = ...`）后才能传入参数并得出结果，这进一步说明了箭头函数本质上是函数表达式。

## 真题六：具名函数表达式与函数声明的区别 *Content-[09:32]

具名函数表达式是函数表达式的一种，指的是有函数名的函数表达式（如 `const fn = function myFn() {}`）。它与函数声明的核心区别有两点：

### 1. 函数名的作用域不同
- **具名函数表达式**：函数名**只能在函数内部使用**，外部无法通过该函数名调用（外部调用会报错 `not defined`）。
- **函数声明**：函数名在**整个当前作用域**都能使用，外部可直接调用。

### 2. 变量提升不同
- **具名函数表达式**：依然是函数表达式，只能提升变量声明，**不提升函数体**。必须先定义后调用。
- **函数声明**：会**整体提升**（包括函数名和函数体），可先调用后定义。
