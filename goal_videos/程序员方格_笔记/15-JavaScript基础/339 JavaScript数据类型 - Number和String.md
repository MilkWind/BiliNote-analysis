## Number 数据类型基础与安全范围 *Content-[00:00]

在 JavaScript 中，`Number` 类型只有一种数据格式，它既可以表示整数，也可以表示浮点数（小数）。

- **安全范围**：
  - `Number` 类型存在一个安全整数范围，具体是从 $-(2^{53} - 1)$ 到 $2^{53} - 1$。
  - 换算成具体数值，即 $-9007199254740991$ 到 $9007199254740991$ 之间的整数。
- **精度丢失问题**：
  - 如果数值超出了上述安全范围，JS 引擎会采用四舍五入的方式进行处理。
  - 这意味着任何超出此范围的整数值都可能会**丢失精度**。
  - 在实际开发中（尤其是涉及金额等精确计算时），必须特别注意精度丢失带来的严重后果。
- **代码验证**：
  - 定义整数 `num1 = 10` 和浮点数 `num2 = 3.14`，使用 `typeof` 检测，两者返回的结果均为 `number`。
  - **安全范围内**：赋值 `9007199254740991`，打印结果与赋值完全一致，不会丢失精度。
  - **超出安全范围**：将尾数改为 `999`（即 `9007199254740999`），打印结果会变成 `9007199254741000`，发生了明显的精度丢失。

## NaN 的特殊性质与产生场景 *Content-[04:11]

`NaN`（Not a Number）是 `Number` 类型中的一个特殊值，具有非常独特的性质。

- **基本属性**：
  - `NaN` 本质上仍然是一个 `Number` 类型。使用 `typeof NaN` 进行检测，返回结果是 `number`。
  - 它用来表示“非数值”的情况。
- **比较特性**：
  - `NaN` 不等于任何值，**甚至不等于它自己**。
  - 验证：无论是 `NaN == NaN` 还是 `NaN === NaN`，返回值均为 `false`。
- **产生场景**：
  - 当运算结果无法用一个合理的数字来表示时，就会返回 `NaN`。
  - 典型场景：将一个数字除以一个无法转换为数字的字符串（如 `1 / 'a'`），结果未知且不是数字，此时就会返回 `NaN`。

## String 数据类型基础与引号使用 *Content-[06:17]

`String` 类型用于表示文本数据。在 JavaScript 中，可以使用三种引号来包裹字符串，且这三者在表示字符串时是**完全等价**的。

- **三种引号**：
  - 单引号 `' '`
  - 双引号 `" "`
  - 反引号 `` ` ``（位于键盘左上角 `ESC` 键下方，与波浪线 `~` 同一个按键）。
- **注意事项**：
  - 必须使用**英文状态**下的引号，中文引号会导致语法错误。
  - 使用 `typeof` 检测这三种引号包裹的文本，返回的数据类型均为 `string`。

## 模板字符串与变量拼接 *Content-[08:35]

反引号是 ES6 引入的语法，相比于传统的单引号和双引号，它提供了更高级的特性，主要体现在**模板字符串**和**多行字符串**的支持上。

- **传统字符串拼接**：
  - 使用单/双引号时，需要通过 `+` 号来连接变量和字符串。
  - 示例：`'我是' + name + '，我的年龄是' + age`
  - 缺点：当变量较多或描述性语句较长时，代码会显得非常杂乱，可读性较差。
- **模板字符串（反引号）**：
  - 使用反引号包裹，并通过 `${变量名}` 的语法直接嵌入变量。
  - 示例：`` `我是${name}，我的年龄是${age}` ``
  - 优点：语法简洁，开发体验更好，代码可读性显著增强。

## 多行字符串的处理方案 *Content-[11:00]

在 JavaScript 中，如果使用普通的单引号或双引号直接换行书写多行文本，会导致**语法报错**（在 VS Code 等现代编辑器中会有明显的红色错误提示）。

处理多行字符串通常有以下三种解决方案：

1. **使用转义字符**：
   - 在每一行文本的末尾添加反斜杠 `\` 进行转义，告诉编译器忽略换行符。
2. **单行书写**：
   - 不使用换行，将所有文本内容强制写在同一行代码中（不推荐，严重影响代码可读性）。
3. **使用反引号（最佳方案）**：
   - 反引号原生支持多行字符串。
   - 直接使用反引号包裹文本并正常换行即可，且最终打印输出的格式与代码书写时的排版格式完全一致。
