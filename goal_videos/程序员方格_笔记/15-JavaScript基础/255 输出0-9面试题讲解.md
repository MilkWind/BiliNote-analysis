## 面试题背景与问题分析 *Content-[00:00]

- **题目要求**：修改给定的 `for` 循环与 `setTimeout` 结合的代码，使其能够按顺序输出 0 到 9。
- **初始现象**：直接运行原始代码，控制台会输出 10 个 10，而不是预期的 0 到 9。
- **解题思路**：在面试中，不要急于写出解法。首先需要深入分析为什么代码会输出 10 个 10，彻底理解其背后的运行机制后，解题思路自然会打开。写法本身并不重要，核心在于对原理的掌握。

## 核心原理剖析：为什么输出十个 10？ *Content-[01:07]

要解决问题，必须先理解 JavaScript 的事件循环（Event Loop）机制以及变量作用域。

- **代码结构分析**：
  - 外层是一个 `for` 循环，属于**同步代码**。
  - 内层是 `setTimeout` 定时器，属于**异步代码**（具体为宏任务）。

- **事件循环执行顺序**：
  - 当同步代码和异步代码同时存在时，JavaScript 引擎会**先执行完所有的同步代码**。
  - 同步代码执行完毕后，再去执行异步代码。
  - 在异步代码中，会先检查并执行所有的**微任务**（如 `Promise`、`nextTick` 等），然后再执行下一个**宏任务**（如 `setTimeout`）。本例中没有微任务，因此直接执行宏任务。

- **执行过程推演**：
  - 当 `i = 0` 时，循环同步执行，`setTimeout` 被作为异步任务“扔到一边”等待，内部代码不执行。
  - 接着 `i = 1`、`i = 2` ... 直到 `i = 9`，每次循环都将定时器任务挂起。
  - 当 `i = 10` 时，循环条件不满足，跳出循环，**同步代码全部执行完毕**。
  - 此时，引擎开始处理之前挂起的 10 个 `setTimeout` 宏任务。

- **变量作用域问题（根本原因）**：
  - 原始代码中使用 `var` 声明变量 `i`，`var` 没有块级作用域，`i` 是一个**全局变量**。
  - 当 10 个定时器开始执行时，回调函数内部并没有定义 `i`，因此会向外部（全局环境）查找。
  - 此时，全局环境中的 `i` 经过循环已经变成了 10。
  - 因此，10 个定时器读取到的都是同一个全局变量 `i`，最终输出 10 次 10。

## 解决方案一：使用 ES6 的 let 声明 *Content-[05:38]

- **修改方法**：将 `var i = 0` 修改为 `let i = 0`。
- **原理解析**：
  - `let` 声明的变量具有**块级作用域**。
  - `for` 循环的每一次迭代，都会形成一个新的块级作用域（大括号 `{}` 就是一个块）。
  - 相当于在内存中为每次循环创建了一个独立的块，并锁定了当前 `i` 的值（例如第一次循环锁定 `i = 0` 的块，第二次锁定 `i = 1` 的块）。
  - 当定时器延迟结束后执行时，它们会去各自对应的块级作用域中查找 `i`，从而正确输出 0 到 9。
- **注意事项**：
  - 使用 `let` 后，确实输出了 0 到 9，但由于 10 个定时器的延迟时间都是 1000ms，它们会在 1 秒后**同时（唰一下）** 输出。
  - 题目仅要求“输出 0~9”，并未要求“每隔一秒输出一个”，因此该解法完全符合题意。

## 解决方案二：利用闭包与函数作用域 *Content-[08:36]

在 ES6 普及之前，通常利用闭包来解决此类问题。

- **修改方法**：在 `for` 循环内部定义一个普通函数（例如 `function show(j)`），将循环变量 `i` 作为参数传递给该函数，并在 `setTimeout` 中调用该函数打印形参 `j`。
- **原理解析**：
  - 函数的形参属于**局部变量**。
  - 每次循环时，将当前的 `i` 值（0, 1, 2...）作为实参传递给函数的形参 `j`。
  - 利用函数作用域，成功将 `i` 的瞬时值“闭包”保存了下来。
- **缺点与局限性**：
  - JavaScript 中的 `for` 循环本身并没有块级作用域（`let` 只是让变量本身表现为块级）。
  - 在循环内部使用 `function` 声明函数，实际上创建的是全局函数。循环 10 次就创建了 10 个同名的全局函数，虽然同名会覆盖，但这种写法依然会造成**内存空间的浪费**，在实际开发中不推荐。

## 解决方案三：使用立即执行函数 (IIFE) *Content-[10:52]

为了解决普通函数造成的内存浪费问题，引入了立即执行函数（Immediately Invoked Function Expression, IIFE）。

- **修改方法**：在循环内部使用 IIFE，例如 `(function(j) { setTimeout(function() { console.log(j); }, 1000); })(i)`。
- **原理解析**：
  - IIFE 同样利用了函数作用域来保存变量 `i` 的值。
  - 关键优势在于：函数在定义后**立即执行**，执行完毕后就会被垃圾回收机制当作垃圾回收掉。
  - 这样既实现了闭包保存变量的目的，又避免了在内存中驻留多个无用的函数引用，优化了内存使用。

## 解决方案四：利用 setTimeout 的第三个参数 *Content-[12:43]

这是一种非常巧妙且代码简洁的解法，在老版本浏览器中兼容性也很好。

- **修改方法**：`setTimeout(function(j) { console.log(j); }, 1000, i)`。
- **原理解析**：
  - `setTimeout` 函数的第一个参数是回调函数，第二个参数是延迟的毫秒数。
  - 从**第三个参数开始**，所有的参数都会作为实参，传递给第一个参数（回调函数）的形参。
  - 因此，直接将循环中的 `i` 作为第三个参数传入，回调函数接收为形参 `j` 并打印，完美避开了全局变量 `i` 最终变为 10 的问题。

## 课后思考与延伸 *Content-[14:38]

- **进阶思考题**：目前的解法虽然输出了 0 到 9，但都是 1 秒后同时输出的。如果题目要求**第一秒输出 0，第二秒输出 1，第三秒输出 2……每隔一秒输出一次**，直到输出 9，应该如何修改代码？
- **提示**：需要结合定时器的延迟时间机制，对延迟毫秒数进行动态累加计算（例如将延迟时间设置为 `1000 * i`），建议大家课后自行尝试实现。

## AI 总结

本节视频深入剖析了前端经典面试题“`for` 循环与 `setTimeout` 结合输出 0-9”的底层原理。核心考点在于 **JavaScript 的事件循环机制（Event Loop）** 以及 **变量作用域**。
1. **问题根源**：`var` 声明的全局变量在同步循环结束后值变为 10，导致异步执行的定时器读取到错误的全局值。
2. **解决方案**：
   - **ES6 `let`**：利用块级作用域，每次循环锁定独立的变量值（最推荐、最现代的做法）。
   - **闭包/IIFE**：利用函数作用域保存变量，IIFE 进一步解决了内存浪费问题（ES6 前的经典做法）。
   - **`setTimeout` 传参**：利用定时器的第三参数直接传递循环变量（代码最简洁）。
掌握这些解法及其背后的内存与执行机制，能够极大提升对 JavaScript 异步编程和作用域链的理解深度。
