## 1. 面试题解析与背景 *Content-[00:00]
- **面试题目**：说一下 JavaScript 当中垃圾回收的机制。
- **考察核心**：
  - **原理**：浏览器是如何实现垃圾回收的？什么样的标准会被回收？
  - **策略**：什么样的对象、变量或内容会被回收？
- **背景意义**：垃圾回收是浏览器性能优化的重要环节。前端开发人员不仅需要实现功能，还需要了解浏览器的底层执行机制，尤其是垃圾回收功能，这在互联网大厂的前端面试中是高频考点。

## 2. 垃圾回收的具体定义 *Content-[02:33]
- **基本定义**：垃圾回收是一种**自动的内存管理机制**。
  - **自动性**：不需要开发者手动参与或编写代码释放内存，只要达到标准，浏览器就会自动回收。
- **核心目的**：
  - **释放内存**：回收不再使用的内存空间，将其释放给其他应用使用，优化整体系统资源分配。
  - **防止内存泄漏**：确保浏览器占用的内存足够精简，避免无用对象持续占用内存导致泄漏问题。
- **核心思想**：识别并清除掉**不再被引用的对象**，从而释放内存空间。

## 3. 垃圾回收的基本原理：可达性 *Content-[05:47]
- **核心概念**：**可达性（Reachability）**。
- **树状结构**：浏览器在执行页面代码时，内存中的对象呈现树状结构（根节点 -> 子节点 -> 孙子节点等）。
- **可达对象**：
  - 从“根”出发，通过**引用链**可以访问到的对象。
  - 包括：全局变量、当前执行栈中的变量、`document` 的元素等。
  - **处理机制**：只要是可达对象，其内部使用的所有对象和变量都不能被清除，必须保留。
- **不可达对象**：
  - 通过引用链无法从根节点访问到的对象。
  - **处理机制**：被视为“垃圾”，直接进行回收。
- **总结**：可达的对象就保存，不可达的对象就回收。

## 4. 回收策略一：标记-清除 *Content-[08:54]
- **工作机制**：基于可达性原理，给可达对象做标记，没有做标记的不可达对象就会被清除掉。
- **地位**：最主流的浏览器性能优化方法，也是 **V8 引擎**默认使用的垃圾回收方法。
- **优点**：
  - 完美避免了**循环引用**的问题。如果两个对象相互引用，但不被外部引用访问，它们依然是不可达的，会被正确回收。
- **缺点**：
  - 回收释放出来的内存是断断续续的（产生**内存碎片**）。在后续分配大对象时，可能需要进行额外的**内存整理**。
- **代码示例**：
  - `object1` 和 `object2` 相互引用（`object1` 引用 `object2`，`object2` 引用 `object1`）。
  - 当外部将它们的引用置为 `null`（视频中口误为 none）时，它们不再被外部引用链访问，变为不可达对象，从而被垃圾回收。

## 5. 回收策略二：引用计数 *Content-[11:47]
- **工作机制**：跟踪每个对象的引用次数，当对象的引用次数等于 0 时，就将其回收。
- **背景**：比较早期的浏览器垃圾回收机制原理，逻辑简单易懂。
- **优点**：实现简单，容易理解。
- **缺点**：
  - **无法处理循环引用**。如果对象之间相互引用，它们的引用计数永远不会降为 0，最终导致**内存泄漏**。
- **代码示例**：
  - `object1` 被引用（计数为 1），`object2` 被引用（计数为 1）。
  - 两者相互引用后，即使外部引用被置为 `null`，它们内部的相互引用依然会让计数大于 0，导致无法被回收。

## 6. 回收策略三：分代回收 *Content-[13:03]
- **工作机制**：现代引擎（如 **V8**）的优化策略，将内存划分为**新生代**和**老生代**，针对不同生命周期的对象采用不同的回收算法。
  - **新生代**：存放新创建的对象，存活时间短，回收频率高，使用相应的算法（如复制算法）。
  - **老生代**：存放存活时间较长的对象，回收频率低，使用“标记-清除”结合“标记-整理”算法。
- **优点**：大幅提高了垃圾回收的效率，减少了主线程停顿的时间。
- **缺点**：底层实现逻辑比较复杂。

## 7. 回收策略四：增量回收与总结 *Content-[13:59]
- **增量回收（Incremental GC）**：
  - **工作机制**：将垃圾回收任务拆分为多个小任务，分步执行，而不是一次性完成。
  - **应用**：新生代和老生代均可使用。
  - **优点**：避免了垃圾回收导致的长时间主线程停顿，提升了页面的响应性能。
  - **缺点**：增加了一些额外的执行开销。
- **四大策略总结**：
  1. **标记-清除**：V8 默认，解决循环引用，但有内存碎片。
  2. **引用计数**：早期机制，简单但存在循环引用导致的内存泄漏缺陷。
  3. **分代回收**：现代 V8 优化策略，分新老生代，提高效率。
  4. **增量回收**：拆分任务，减少停顿，但有额外开销。

## AI 总结
JavaScript 的垃圾回收是一种自动内存管理机制，其核心原理是基于**可达性**（从根节点通过引用链访问对象）。在回收策略上，现代浏览器（如 V8 引擎）主要采用**标记-清除**作为基础，并结合**分代回收**（区分新生代与老生代）和**增量回收**（拆分任务减少停顿）来进行深度优化。早期的**引用计数**因无法解决循环引用导致的内存泄漏问题已被淘汰。掌握这些底层原理与策略，是前端开发者进行性能优化及应对大厂面试的关键。
