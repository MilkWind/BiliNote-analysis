## 1. 函数同名时的提升规则 *Content-[00:08]

当代码中存在多个同名函数时，变量提升和预解析阶段会触发覆盖机制。

- **场景示例**：定义了两个同名的函数 `func1`，第一个打印 `this is func1`，第二个打印 `this is last func1`。在代码的不同位置分别调用这两个函数。
- **执行结果**：两次调用均输出 `this is last func1`。
- **原因分析**：
  - 在预解析阶段，函数声明会被整体提升到当前作用域的第一行。
  - 当遇到同名函数时，后面的函数声明会覆盖前面的函数声明（类似于变量赋值覆盖，如 `a = 10` 后 `a = 20`，最终 `a` 为 20）。
  - 预解析阶段在代码执行前就已经完成了函数的覆盖，因此无论后续代码如何调用，最终生效的只有最后一个同名函数。
- **核心结论**：同名函数相互覆盖，**后面的函数会覆盖之前的函数**。

## 2. 变量和函数同名时的提升规则 *Content-[02:49]

当变量声明与函数声明同名时，提升规则会有所不同。

- **场景示例**：先声明函数 `function foo()`，再声明变量 `var foo = 66`。在变量赋值前（提前）打印 `foo`。
- **执行结果**：提前打印输出的是**函数本身**。
- **原因分析**：
  - 函数和变量同名时，**函数会被提升，而变量的声明提升会被忽略**。
  - 因此，在预解析阶段，只有函数被提升到了第一行，变量 `foo` 的声明被忽略，最终保留下来的是函数。
- **延后打印的情况**：
  - 如果在 `var foo = 66` 之后（延后）打印 `foo`，输出结果为 `66`。
  - 虽然变量的“声明提升”被忽略，但变量的“赋值操作”依然保留在代码执行阶段。当代码执行到赋值语句时，`foo` 被重新赋值为 `66`。

## 3. 先声明变量后声明函数的报错情况 *Content-[05:45]

如果改变变量和函数同名时的声明顺序，会导致不同的结果。

- **场景示例**：先声明变量 `var nm`，再声明同名函数 `function nm()`，随后调用 `nm()`。
- **执行结果**：调用时报错（提示 `nm` 不是函数）。
- **原因分析**：
  - 变量 `var nm` 首先被提升，此时 `nm` 的值为 `undefined`。
  - 随后遇到同名函数 `function nm()`，由于前面已经存在变量 `nm` 的声明，**函数的提升会被忽略**。
  - 在代码执行阶段，`nm` 保持为 `undefined`（或后续被赋值为其他非函数类型的值，如数字）。
  - 当尝试调用 `nm()` 时，由于 `nm` 不是一个函数，因此触发报错。

## 4. 预解析是分作用域的 *Content-[07:21]

变量和函数的提升具有严格的作用域限制。

- **场景示例**：在全局作用域打印变量 `nm`；在局部函数 `show` 内部声明并打印 `nm`；函数执行完毕后，再次在全局打印 `nm`。
- **执行结果**：
  - 局部函数内提前打印 `nm` 输出 `undefined`。
  - 全局第二次打印 `nm` 报错（`nm is not defined`）。
- **原因分析**：
  - 变量和函数的提升**只会提升到当前作用域的第一行**，绝不会跳出或穿透当前作用域。
  - 局部变量 `nm` 只在 `show` 函数内部提升，全局作用域中根本不存在 `nm`。因此，局部提升后是局部变量，全局依然没有该变量，导致全局调用时报错。

## 5. JS 预解析是分段的 *Content-[09:57]

JS 的预解析和变量提升不会跨越独立的代码块。

- **场景示例**：在第一个 `<script>` 标签中提前打印变量 `nm`，在第二个 `<script>` 标签中声明并赋值 `var nm = 10`。
- **执行结果**：第一个 `<script>` 标签中打印报错。
- **原因分析**：
  - **变量提升不会跨 `<script>` 标签**，同样也不会跨独立的 JS 文件。
  - 每个 `<script>` 标签或 JS 文件都是一个独立的预解析和执行单元。
  - 这也解释了为什么在引入第三方 JS 文件时，引入顺序非常重要：后面引入的文件中创建的全局变量，无法被前面引入的文件在预解析阶段调用。

## 6. 函数表达式不会被提升 *Content-[11:19]

使用函数表达式创建函数时，不享有函数声明的提升特权。

- **场景示例**：使用 `var foo = function() { console.log('我是foo'); }` 创建函数，并提前打印 `foo`。
- **执行结果**：提前打印输出 `undefined`。
- **原因分析**：
  - 函数表达式本质上是**变量赋值**，因此它完全遵循**变量提升规则**。
  - 预解析阶段只会提升变量名 `foo`，而不会提升变量值（即函数体）。
  - 因此，提前打印时，`foo` 只是一个值为 `undefined` 的变量。

## 7. 条件式函数声明的提升规则 *Content-[12:28]

当函数声明位于条件语句（如 `if`）内部时，提升规则会发生改变。

- **场景示例**：定义 `var boo = true`，在 `if (boo)` 语句块内声明函数 `function show() {}`，并在外部提前打印 `show`。
- **执行结果**：提前打印输出 `undefined`。
- **原因分析**：
  - 预解析阶段**不会去执行或计算条件语句的真假**（因为条件结果可能在运行时才确定，预解析引擎不会“替开发者做决定”）。
  - 因此，引擎无法确定该函数是否应该被完整提升。为了安全起见，只要函数声明出现在 `if` 等条件语句中，**一律按照变量提升规则处理**。
  - 即：只提升函数名 `show`，不提升函数体。提前打印时值为 `undefined`。
  - 条件语句的真假（`true` 或 `false`）只影响后续代码执行时该函数是否被真正赋值和调用，不影响预解析阶段的降级处理。

## AI 总结

本视频详细剖析了 JavaScript 中变量提升与函数预解析的多种复杂及特殊情况，核心要点如下：
1. **同名覆盖**：同名函数提升时，后者覆盖前者；函数与变量同名时，函数提升优先，变量声明提升被忽略（但赋值保留）。
2. **作用域与分段限制**：提升操作严格限制在当前作用域内，且不会跨越 `<script>` 标签或独立的 JS 文件。
3. **非标准函数声明降级**：函数表达式和条件语句（如 `if`）中的函数声明，均不享受整体提升的特权，而是降级遵循变量提升规则（仅提升标识符，值为 `undefined`）。
掌握这些底层预解析机制，能够有效避免前端开发中的变量未定义报错及逻辑覆盖问题，是应对大厂前端面试的必备基础。
