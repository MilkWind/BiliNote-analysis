## 1. 上节课知识回顾 *Content-[00:00]

- **基本数据类型与引用数据类型的区别**：
  - **内存分配**：基本数据类型声明在栈（Stack）中，内容也在栈中；引用数据类型声明在栈中，但内容存储在堆（Heap）中。
  - **赋值操作**：基本数据类型相互赋值时，是值的复制；引用数据类型相互赋值时，是地址的复制（地址一样，内容一样，一改全改）。
- **匿名对象与内存垃圾**：
  - 当一个引用数据类型不再有任何地址引用时，会被内存标记为垃圾对象，等待垃圾回收器回收。
  - 匿名对象通常只使用一次，使用完毕后会立即被标记为垃圾对象，从而节省内存空间。

## 2. 构造函数内部绑定方法的问题 *Content-[01:54]

- **问题引入**：
  - 创建一个构造函数 `Person`，包含属性 `name`、`age` 和方法 `sayHi`。
  - 通过 `new Person()` 创建对象 `p1` 和 `p2`，它们都可以调用 `sayHi` 方法。
- **`new` 关键字的四个作用回顾**：
  1. 开辟内存空间，存储新创建的对象。
  2. 将 `this` 指向当前新创建的对象。
  3. 执行内部代码，为当前对象绑定属性和方法。
  4. 返回当前新创建的对象（相当于内部默认 `return this`）。
- **核心痛点：内存资源浪费**：
  - 比较 `p1.sayHi === p2.sayHi`，结果为 `false`，说明它们不是同一个方法。
  - 每次使用 `new` 关键字创建对象时，都会执行一次构造函数内部代码，相当于以表达式的方式重新创建了一次 `sayHi` 函数。
  - 如果大量 `new` 对象（例如 1 万次），就会在内存中创建 1 万个功能完全相同的 `sayHi` 方法。
  - 属性（如 `name`、`age`）每个对象不同，需要独立创建；但方法（如 `sayHi`）功能相同，在内存中创建多份完全没有必要，会造成严重的资源浪费。
  - **通俗比喻**：就像 40 个学生每人单独办一条宽带，而实际上大家共享一条或几条宽带就足够了，没必要每人单独办，造成资金和资源浪费。

## 3. 临时解决方案与全局污染痛点 *Content-[08:35]

- **临时解决方案**：
  - 将 `sayHi` 函数提取到构造函数外部定义为全局函数（例如 `function sayHi(name) { ... }`）。
  - 在构造函数内部，通过 `this.sayHi = sayHi` 的方式引用该全局函数。
  - **效果**：解决了方法重复创建的问题，此时 `p1.sayHi === p2.sayHi` 结果为 `true`，实现了方法的共享。
- **新痛点：全局污染**：
  - 将函数定义在全局作用域下，会增加全局变量的数量。
  - **全局污染的定义**：在 JS 的全局环境下，创建过多的全局变量，导致全局命名冲突的风险增加。
  - **通俗比喻**：就像全球人口越来越多，起名字重名的概率就越来越大。如果只有 10 个人，重名风险很低；但变量名在全局作用域中是唯一的，过多全局变量极易引发命名冲突。

## 4. 引出原型（Prototype）概念 *Content-[12:21]

- **总结当前困境**：
  - 既要解决构造函数内部创建对象方法导致的**浪费资源问题**。
  - 又要解决将方法提取到外部导致的**全局污染问题**。
- **原型（Prototype）的引入**：
  - 原型正是为了解决上述两个痛点而存在的。
  - 解决痛点的能力就是原型的核心特点。通过原型，可以让所有实例对象共享方法，同时避免污染全局作用域。

## AI 总结

本节视频主要探讨了在 JavaScript 构造函数内部直接绑定方法所引发的内存资源浪费问题。由于每次 `new` 对象都会重新创建方法，导致大量功能相同的函数在内存中冗余。虽然将方法提取到全局作用域可以解决共享问题，但会引入全局命名冲突的“全局污染”风险。为同时解决“资源浪费”与“全局污染”这两大痛点，视频自然引出了 JavaScript 中的核心概念——原型（Prototype），为后续深入学习原型链机制奠定了基础。
