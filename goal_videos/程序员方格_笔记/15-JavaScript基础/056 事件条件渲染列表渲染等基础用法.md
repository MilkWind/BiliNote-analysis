## 1. 条件渲染与列表渲染 *Content-[00:15]

### 条件渲染
在 JSX 中，条件渲染通常通过**三元表达式**来实现，这种方式非常便捷。
- **场景示例**：通过 `isLogin` 状态判断用户是否登录。
  - 如果已登录（`isLogin` 为 true），则显示 "Welcome back"（欢迎回来）。
  - 如果未登录，则提示用户去登录。
- **实现方式**：直接在 JSX 模板中使用三元运算符 `condition ? trueComponent : falseComponent` 进行条件判断和渲染。

### 列表渲染
列表渲染主要通过数组的 `map` 方法来实现，遍历数组并生成对应的元素列表。
- **场景示例**：提供一个 `numbers` 数组 `[1, 2, 3, 4, 5]`，通过 `map` 方法将其渲染为 `<li>` 标签组成的列表。
- **`key` 属性的重要性**：
  - 在渲染列表时，必须为每个元素指定唯一的 `key`（例如使用 `item.toString()` 将数字转为字符串作为 key）。
  - **核心作用**：`key` 在 React 的 **diff** 算法过程中具有极高的权重和优先级。
  - **Diff 机制**：
    - 如果 `key` 相同：React 会进一步判断内部的标签（tag）或内容是否相同，从而决定是复用还是更新。
    - 如果 `key` 不同：React 会直接销毁旧节点并重建新节点。
  - 因此，合理且唯一的 `key` 能够大幅提升列表渲染和更新的效率。

## 2. 事件绑定与样式绑定 *Content-[02:04]

### 事件绑定
在 JSX 中绑定事件时，需要特别注意事件名称的命名规范（通常采用驼峰命名法）。
- **定义方法**：首先在组件中定义事件处理函数，例如 `handleClick`。
- **绑定方式**：在 JSX 语法中，通过花括号 `{}` 将函数绑定到对应的事件属性上。
  - 示例：`<button onClick={handleClick}>点击我</button>`。
- **特点**：通过这种显式定义的方式，可以清晰地注册和管理当前组件关注的交互事件。

### 样式绑定
- **实现方式**：首先定义一个样式对象（JavaScript Object），然后在 DOM 元素中通过 `style` 属性绑定该对象。
- **示例**：`<div style={styleObject}>内容</div>`，从而完成动态或内联样式的绑定。

## 3. JSX 底层转换原理 *Content-[03:21]

### 为什么需要转换？
- 浏览器原生无法理解 JSX 语法。
- 必须将 JSX 转换为标准的 JavaScript 代码，以便浏览器能够解析和执行。
- 这种转换不仅是为了运行，还能显著提高代码的可读性和可维护性。

### 转换工具与核心思想
- **Webpack**：作为核心的工程化打包工具，负责处理模块依赖和构建流程。
- **Babel**：作为语言转换工具，负责将 JSX 等现代语法转换为浏览器兼容的 JS 代码。
- **AST（抽象语法树）**：Babel 在背后利用 AST 思想，将源代码解析为树状结构，进行转换后再重新生成目标代码。

### 转换方式一：Classic Runtime（经典模式）
在这种模式下，JSX 会被转换为 `React.createElement` 函数的调用。
- **函数参数解析**：
  1. **第一个参数**：元素类型（如 `'h1'`、`'div'` 等标签名或组件）。
  2. **第二个参数**：属性对象（`props`），包含 className、onClick 等属性。
  3. **第三个参数**：子元素（`children`），可以是文本、其他元素或数组。
- **示例**：`<h1 className="title">Hello</h1>` 会被转换为 `React.createElement('h1', { className: 'title' }, 'Hello')`。

## 4. 转换模式对比与工程配置 *Content-[05:42]

### 转换方式二：Automatic Runtime（自动模式）
这是 React 17 引入的经典转换模式的升级版，将 JSX 转换为来自 `react/jsx-runtime` 的 `jsx` 函数调用。

#### Automatic Runtime 的核心优势
1. **减少显式引用**：在 Classic 模式下，即使组件内部没有直接使用 `React` 对象，也必须在文件顶部显式 `import React from 'react'`，因为 JSX 转换后依赖 `React.createElement`。而在 Automatic 模式下，无需手动引入 `React`。
2. **自动注入**：编译过程中，Babel 会自动注入对 `react/jsx-runtime` 的依赖，解除了组件对 `React` 顶层对象的强耦合。
3. **提升编译效率**：减少了不必要的模块引入和对象引用，优化了整体的编译和打包体积。

#### 版本差异与推荐
- **React 17 及之后**：强烈推荐并默认使用 **Automatic Runtime**。
- **React 17 之前**：默认使用 **Classic Runtime**。

### 工程层面的配置（Webpack + Babel）
在工程化项目中，通常通过配置 Webpack 和 Babel 预设来控制转换模式。
- **核心插件**：使用 `@babel/preset-react`，这是一组用于转换 React JSX 代码的插件集合。
- **配置方式**：在 Webpack 的 Babel loader 配置中，通过 `runtime` 参数指定转换模式：
  - 使用 Automatic 模式：配置 `runtime: 'automatic'`（无需手动 import React）。
  - 使用 Classic 模式：配置 `runtime: 'classic'`（需要手动 import React）。
- **实操建议**：在实际开发中，务必理解这两种模式的区别，并根据项目的 React 版本正确配置 `@babel/preset-react`。
