## 1. 课程回顾与引入 *Content-[00:00]
- **原型核心概念回顾**：
  - **原型是什么**：为所有对象提供的公共空间。
  - **为什么需要原型**：解决传统构造函数中方法创建过多、内存占用过大的问题。
  - **原型的作用**：通过构造函数相互绑定，实现方法和属性的共享。
  - 前序课程还讲解了原型替换的使用场景。
- **本节课核心主题**：在理解原型概念的基础上，深入讲解访问原型的**第二种方式**。

## 2. 访问原型的第一种方式：通过构造函数 *Content-[00:38]
- **语法格式**：`构造函数.prototype`
- **形象比喻**：
  - 将“构造函数”比作**丈夫**，将“原型（prototype）”比作**妻子**。
  - 通过构造函数（丈夫）可以直接访问其对应的原型（妻子）。

## 3. 访问原型的第二种方式：通过实例对象 *Content-[01:32]
- **语法格式**：`对象.__proto__`
- **属性深度解析**：
  - `__proto__` 是一个**属性**，而不是方法。
  - 它是**非 W3C 标准属性**，并非官方推出的标准，而是浏览器厂商（最早由 Firefox 火狐浏览器引入）为了开发者访问方便而“众望所归”集资推出的。
- **为什么需要第二种方式**：
  - 第一种方式需要明确知道对象的“构造函数”是谁。但在实际开发中，有时手里**只有一个对象实例**，并不清楚它的构造函数是什么。
  - 例如：使用字面量创建对象 `let o = {}`，基础不扎实的人可能不知道它的构造函数是 `Object`（字面量创建与 `new Object()` 原理相同）。
  - 此时，通过实例对象自身的 `__proto__` 属性，就可以直接向上追溯并访问其原型，无需关心构造函数是谁。
- **形象比喻（双重身份）**：
  - 原型（妻子）具有两重身份：既是“丈夫（构造函数）的妻子”，也是“孩子（实例对象）的母亲”。
  - `prototype` 对应“丈夫的妻子”，`__proto__` 对应“孩子的母亲”。两者指向的是同一个人（同一个原型对象）。

## 4. 两种访问方式的等价性验证 *Content-[02:50]
- **代码演示**：
  ```javascript
  function Person() {}
  let p = new Person(); // 实例对象 p
  
  // 通过实例对象访问原型
  console.log(p.__proto__); 
  ```
- **等价性证明**：
  - 验证 `p.__proto__ === Person.prototype`，结果为 `true`。
  - 这再次印证了“父亲的妻子”和“孩子的母亲”指的是同一个对象。
  - 无论通过 `构造函数.prototype` 还是 `实例对象.__proto__`，获取到的都是同一个原型公共空间。

## 5. `__proto__` 属性的使用注意事项 *Content-[04:40]
- **核心原则**：可以使用 `__proto__` 来**访问**原型，但**强烈建议不要通过它去修改原型的成员**。
- **原因分析**：
  - **维护成本极高**：通过实例对象访问并修改原型是不可控的。因为原型是所有实例的“公共空间”，一旦通过某个实例的 `__proto__` 修改了原型内容，会导致所有引用该原型的其他实例对象的行为都发生改变（一改全改）。
  - **排查困难**：当代码出现问题时，由于修改源头分散在各个实例的隐式操作中，极难追踪和维护。
- **最佳实践**：除非在实际开发中有极特殊的需求，否则**永远不要**通过实例对象的 `__proto__` 属性去修改原型成员。修改原型应统一通过 `构造函数.prototype` 进行规范操作。

## AI 总结
本节课深入讲解了 JavaScript 中访问原型的两种主要方式。第一种是通过构造函数的 `prototype` 属性，第二种是通过实例对象的 `__proto__` 属性。讲师通过“丈夫与妻子”、“母亲”的生动比喻，清晰地解释了 `prototype` 和 `__proto__` 指向同一个原型对象的本质。同时，课程重点强调了 `__proto__` 作为非标准属性的使用规范：仅建议用于读取和访问，严禁用于修改原型成员，以避免引发公共空间污染和极高的代码维护成本。掌握这两种访问方式及其使用边界，是应对前端大厂面试中原型链相关问题的重要基础。
