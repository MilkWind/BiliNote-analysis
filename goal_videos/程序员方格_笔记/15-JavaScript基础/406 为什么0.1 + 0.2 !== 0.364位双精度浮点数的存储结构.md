3\. **考察重点与常见误区**
- **考察目的**：考察候选人对 JS 数据存储底层原理的理解，以及在实际开发（如电商支付统计功能）中处理金额、数值计算时避免精度 Bug 的能力。

## JS 数据存储规则与底层原理 *Content-[01:17]

1\. **精度问题的本质**
- **浮点数精度问题**：$0.1 + 0.2 \neq 0.3$ 的判断结果为 `true`，即确实不等于 0.3。
- **大数精度问题**：在 JS 中，两个肉眼看起来不相等的大数（例如 `9007199254740992` 和 `9007199254740993`），使用 `==` 或 `===` 进行比较时，结果均为 `true`。
- **核心结论**：这不是 JS 语言的 Bug，而是数学运算中浮点数运算和大数运算的固有特性。

2\. **JS 的 Number 类型特性**
- **不区分整数和小数**：JS 中只有 `Number` 这一种数字数据类型，底层根本不区分整数和浮点数。
- **底层存储形式**：所有数字在底层都遵循 **IEEE 754** 规范，使用 **64 位双精度浮点数** 进行存储。
- **统一为小数存储**：不管数字是 `1` 还是 `0.1`，底层都是以小数（浮点数）形式存储的。即便是整数，也是以浮点数形式表示，只是小数部分为零。
  - **示例验证**：在 JS 中，`1 === 1.0` 的结果为 `true`。因为底层存储的都是小数，`1` 后面的 `.0` 在显示时被省略了。

3\. **这种设计的优点**
- 可以归一化处理整数和小数。
- 有效节省存储空间。

## IEEE 754 浮点数标准详解 *Content-[05:58]

1\. **IEEE 754 标准的背景**
- IEEE 754 是目前最广泛使用的浮点数运算标准。
- 在该标准出现之前，各家计算机公司的各型号计算机有着千差万别的浮点数表示方式。
- 这种标准不一导致数据交换和计算机协同工作造成了极大的不便，接口对接非常麻烦。IEEE 754 标准的出现解决了这一乱象，成为业界通用的浮点数运算标准。

2\. **常用的浮点数表示方式**
- **单精度（Single Precision）**：使用 32 位存储。例如 C 语言中的 `float` 通常是指 IEEE 754 单精度。
- **双精度（Double Precision）**：使用 64 位存储。例如 C 语言中的 `double` 是指 IEEE 754 双精度。JS 中的 `Number` 类型采用的就是 64 位双精度浮点数存储。
