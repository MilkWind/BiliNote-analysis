## var 的特性与历史痛点 *Content-[01:14]

在 ES6 (2015年) 之前的很长一段时间里，`var` 是声明变量的唯一选择。理解它的特性是理解后续演进的关键前提。

### var 的核心特性
1\. **作用域**：仅有函数作用域或全局作用域，缺少块级作用域。
2\. **变量提升**：变量的声明会提前到所在作用域的顶部。
3\. **重复声明**：允许在同一个作用域内重复声明同一个变量，容易无意中覆盖重要值。
4\. **可变性**：声明的变量可以随时被重新赋值。

### var 的两大痛点
**痛点一：变量提升违背直觉**
由于变量提升，可以在变量正式声明并赋值前访问它。此时不会报错，而是得到 `undefined`。这种行为违背编码直觉，是产生 Bug 的温床（你以为变量还没出现，其实它已经在那了，只是值不对）。

**痛点二：缺乏块级作用域（变量泄露）**
在很多语言中，花括号代表独立作用域，但 `var` 并非如此。在 `if` 语句或 `for` 循环内部用 `var` 声明的变量，其作用范围会泄露到外部。

**代码示例分析**：
```javascript
function test() {
    console.log(a); // 打印 undefined (因为变量提升，声明已提前，但未赋值)
    var a = 10;
    console.log(a); // 打印 10

    if (true) {
        var a = 20; // 没有块级作用域，这里的 var a 就是外部的 a
        console.log(a); // 打印 20
    }
    
    console.log(a); // 打印 20 (if 块内的修改泄露到了外部，覆盖了原来的 10)
}
```

## let 的引入与块级作用域 *Content-[05:17]

为了解决 `var` 的遗留问题，ES6 引入了 `let` 和 `const`。`let` 可以理解为 `var` 更完善、更符合现代编程思想的替代品。

### let 的核心特性
1\. **块级作用域**：任何一个花括号 `{}` 内声明的 `let` 变量，都只在这个括号内有效。
2\. **暂时性死区 (TDZ)**：没有变量提升。在变量声明语句出现之前，无法访问它，任何尝试都会直接抛出错误。
3\. **不允许重复声明**：在同一个作用域内，不允许重复声明同一个变量，使代码更健壮。
4\. **可变性**：与 `var` 一样，`let` 声明的变量可以被重新赋值。

**代码示例分析**：
```javascript
function test() {
    // console.log(b); // 如果取消注释，由于 TDZ，程序会直接抛出 ReferenceError
    let b = 10;
    console.log(b); // 打印 10

    if (true) {
        let b = 20; // 块级作用域，这是一个全新的、只存在于 if 块内部的局部变量
        console.log(b); // 打印 20
    }
    
    console.log(b); // 打印 10 (if 块执行结束后内部变量销毁，外部 b 的值从未改变)
}
```
通过引入块级作用域，`let` 完美解决了变量泄露问题，代码行为变得清晰且可预测。

## const 的核心特性与引用类型陷阱 *Content-[08:30]

`const` (constant 的缩写) 的作用域、暂时性死区 (TDZ) 以及不允许重复声明的特性与 `let` 完全一样。它唯一且核心的区别在于**可变性**。

### const 的基本规则
1\. **不可重新赋值**：声明的变量不能被重新赋值。
2\. **必须初始化**：声明时必须进行初始化，否则容易报错。
3\. 直接尝试给 `const` 变量重新赋值（如 `c = 40`），JavaScript 引擎会立即抛出 `TypeError`。

### 核心细节：引用不变性 vs 值不变性
这是 `const` 最让人混淆的地方，特别是在与引用类型（对象、数组）交互时。
`const` 保证的是**变量引用的不变性**（即指向内存地址的指针不变），而不是**变量值的不变性**。

**代码示例分析**：
```javascript
const obj = { a: 'react' };

// 允许的操作：修改对象内部属性
obj.a = 'vue'; 
// 完全允许，因为没有改变 obj 的指向，只是修改了它指向的那块内存里的数据。

// 不允许的操作：重新赋值整个对象
obj = {}; 
// 立即触发 TypeError。因为这试图让 obj 指向一个全新的空对象，改变了引用指向，这是 const 绝对禁止的。
```
**总结**：用 `const` 声明对象或数组时，不能把变量指向另一个对象/数组，但可以随心所欲地修改其内部的属性或元素。`const` 锁住的是引用，而不是值。

## 关键概念深化：TDZ 与全局作用域 *Content-[12:29]

### 1. 暂时性死区 (TDZ - Temporal Dead Zone)
对于 `let` 和 `const`，从它们所在作用域的左花括号 `{` 开始，一直到该变量的声明语句出现之前，这整个区域就是变量的“死区”。
在此区域内，任何对该变量的读写操作都会导致 `ReferenceError`。这是一种更安全的设计，强制开发者必须先声明后使用。

### 2. 全局作用域下的表现差异
在浏览器环境中，顶层对象是 `window`。
1\. **使用 `var`**：在全局作用域下声明的变量，会自动成为 `window` 对象的一个属性（例如可以通过 `window.globalVar` 访问）。
2\. **使用 `let` / `const`**：在全局声明的变量虽然是全局变量，但**不会**被挂载到 `window` 对象上。
这是 ES6 的重要变更，有效减少了对全局对象的污染。

## 日常开发最佳实践 *Content-[14:25]

在日常开发中，应遵循以下三条明确的最佳实践：

1\. **优先使用 `const`**：这是最核心的原则。默认使用 `const` 可以保证变量不会被意外重新赋值，增加代码的健壮性和可预测性。
2\. **必要时使用 `let`**：只有当你明确知道一个变量需要被重新赋值时，才使用 `let`。典型场景包括 `for` 循环的计数器，或需要改变值的状态变量。
3\. **彻底告别 `var`**：在任何现代的使用 ES6 或更高版本的 JavaScript 项目中，已经没有任何理由再去使用 `var`。

## 面试实战：如何回答 var, let, const 的区别 *Content-[15:25]

当面试官问及此问题时，建议按照以下逻辑清晰、全面地组织答案：

1\. **第一点：作用域规则（最核心区别）**
   - `var` 声明的变量是函数作用域或全局作用域。
   - `let` 和 `const` 是块级作用域。
   - *补充说明*：块级作用域的引入解决了 `var` 在 `if` 语句或 `for` 循环中容易造成变量泄露的问题，让代码更健壮。

2\. **第二点：提升行为与 TDZ**
   - `var` 存在变量提升，声明会提到作用域顶部并初始化为 `undefined`。声明前访问不报错，但得到 `undefined`。
   - `let` 和 `const` 不存在变量提升，具有暂时性死区 (TDZ) 特性。声明前访问会直接抛出 `ReferenceError`，行为更安全、更符合预期。

3\. **第三点：赋值与声明规则**
   - `var`：既可以重复声明，也可以重新赋值。
   - `let`：不能在同一作用域中重复声明，但可以重新赋值。
   - `const`：最严格，既不能重复声明，也不能重新赋值。

4\. **加分点（针对 `const` 的深入理解）**
   - 特别强调：当 `const` 用于声明对象或数组等引用类型时，它保证的是**变量引用的不变**，而对象内部的属性是可变的。

## 课程总结 *Content-[18:02]

`let` 和 `const` 的出现为 JavaScript 带来了两个至关重要的特性：
1\. **块级作用域**：像一道防火墙，有效隔离变量，防止了 `var` 时代的变量泄露问题。
2\. **暂时性死区 (TDZ)**：终结了变量提升带来的非直觉行为，让代码执行顺序更清晰、更安全。

**最终开发准则**：优先使用 `const`，只在必要时使用 `let`，彻底告别 `var`。
