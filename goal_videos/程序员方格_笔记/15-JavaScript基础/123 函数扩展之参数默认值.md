## ES6 函数扩展概述 *Content-[00:01]
- ES6 对函数进行了多方面的扩展，主要知识点包括：
  - 函数参数默认值
  - rest 参数（可变参数）
  - 函数的严格模式
  - `name` 属性
  - 箭头函数
- 本节重点讲解**函数参数默认值**。

## ES5 与 ES6 参数默认值写法对比 *Content-[00:25]
- **ES5 中的写法**：
  - 在 ES6 之前，函数参数没有默认值的语法。
  - 需要在函数体内手动判断参数是否为 `undefined`，然后再进行赋值。
  - 示例代码：
    ```javascript
    function show(a, b) {
      if (typeof b === 'undefined') {
        b = 66;
      }
      console.log(a, b);
    }
    show(128, 87); // 输出 128 87
    show(128);     // 输出 128 66 (b 生效默认值)
    ```
- **ES6 中的写法**：
  - ES6 允许直接在函数的参数列表中为参数指定默认值。
  - 示例代码：
    ```javascript
    function show(a, b = 66) {
      console.log(a, b);
    }
    ```
  - 这种写法大幅简化了代码，提高了可读性。

## 参数默认值的惰性求值特性 *Content-[02:15]
- **惰性求值（Lazy Evaluation）**：
  - 函数的参数默认值不是简单的传值，而是**每次重新计算默认值表达式的值**。
  - 这意味着默认值表达式只有在真正需要用到时才会执行（即“懒惰性求值”：不需要时不动，需要时才生效）。
- **代码示例**：
  ```javascript
  function fn() {
    console.log('我是默认值函数');
    return 326;
  }

  function show(a, b = fn()) {
    console.log(a, b);
  }

  show(1, 2); // 传入了 b 的值，fn() 不会被调用，不会输出 '我是默认值函数'
  show(1);    // 未传入 b，触发默认值，fn() 被调用，输出 '我是默认值函数' 和 326
  ```
- **结论**：如果调用函数时已经为参数赋值，默认值的函数或表达式是**不会**被执行的。

## 多个参数默认值与同名参数限制 *Content-[03:16]
- **多个参数默认值**：
  - 函数可以有多个参数同时设置默认值。
  - 示例：`function show(x = 128, y = 36) { console.log(x, y); }`
  - 调用时，如果只传入第一个参数，第二个参数将生效其默认值。
- **同名参数限制**：
  - 使用参数默认值时，函数**不能**有同名参数。
  - 如果在没有默认值的情况下写同名参数，可能不会报错（非严格模式下）；但**一旦其中某个参数设置了默认值，再出现同名参数就会直接报错**。

## 默认值参数的位置要求 *Content-[05:52]
- **必须放在参数列表末尾**：
  - 有默认值的参数必须放在函数参数列表的最后面（即尾参数）。
  - 示例正确写法：`function show(a, b, c = 9, d = 128)`
- **跳过传参的问题**：
  - 如果默认值参数不在末尾（例如 `function show(a = 999, b, c, d)`），在调用时想要跳过 `a` 直接给 `b` 赋值，必须显式传入 `undefined`。
  - 示例：`show(undefined, 2, 3, 4)`。如果不传 `undefined` 而是直接传值，会被当作赋给 `a`。
  - 由于不能像解构赋值那样“跳着传参”，这种写法在实际中毫无意义。
- **最佳实践**：尽量将带有默认值的参数写在参数列表的末尾，避免使用 `undefined` 进行跳过传参。

## 解构赋值与函数参数默认值的结合 *Content-[08:15]
- **结合使用的复杂性**：
  - 解构赋值本身支持默认值，函数参数也支持默认值。
  - 将两者结合使用时（例如：`function show({a = 1, b = 2} = {})`），逻辑会变得非常绕。
- **建议**：
  - 在实际开发中，如果觉得这种结合写法过于复杂，建议直接跳过或避免使用。
  - 作为面试扩展知识了解即可，不必深究。
