## 条件语句：if 与 switch *Content-[00:07]

- **if 语句**
  - 用于评估并判断一个条件表达式。
  - 如果表达式的结果为 `true`，则执行紧跟的 `if` 代码块。
  - 可以通过 `else if` 添加多个判断条件分支。
  - 使用 `else` 来处理所有不满足前面条件的情况。

- **switch 语句**
  - **适用场景**：当判断逻辑基于同一个变量的多个不同离散值时，使用 `switch` 比一长串的 `if...else` 结构更加清晰，可读性更高。
  - **比较机制**：将传入的表达式与每一个 `case` 的值进行**全等比较**（`===`）。
  - **执行逻辑**：如果匹配成功，则从该 `case` 开始执行代码。
  - **关键细节（break）**：每个 `case` 代码块的末尾通常都需要一个 `break` 语句。如果没有 `break`，代码会发生**穿透（fall-through）**，继续执行下一个 `case` 的代码，直到遇到 `break` 或 `switch` 结束。
  - **default 关键字**：可选，用于处理表达式的值与所有 `case` 都不相匹配的情况。

## 迭代语句：循环结构 *Content-[02:04]

- **while 与 do...while 循环**
  - 两者都适用于循环次数不确定的场景。
  - **核心区别在于测试条件的时机**：
    - `while`：先判断条件，后执行循环体。如果条件一开始就不满足，循环体一次都不会执行。
    - `do...while`：先执行循环体，然后再进行条件判断。这保证了循环体**至少会执行一次**。

- **for 循环**
  - 最常用的循环语句，结构非常清晰。
  - 将变量的初始化、循环条件以及循环后要做的操作（通常是递增或递减）集中在一个括号内。

- **for...in 循环**
  - **设计初衷**：用于遍历对象的属性。
  - **迭代内容**：迭代的是对象的每一个**可枚举的 Key**（键）。
  - **注意事项**：`for...in` 的遍历顺序是不确定的，并且会遍历到**原型链**上的属性。因此，**不推荐**使用它来遍历数组。

- **for...of 循环**
  - ES6 引入的特性，是遍历可迭代数据的**首选**方案。
  - **适用对象**：字符串、数组、`Map`、`Set` 等内置的可迭代对象。
  - **迭代内容**：迭代的是集合中每一个元素的**值**（Value），而不是 Key。
  - **示例对比**：用 `for...in` 遍历对象得到的是键（如 `a`, `b`）；用 `for...of` 遍历数组得到的是数组里的具体值（如 `x`, `y`）。

## 流程控制语句：break、continue 与 label *Content-[05:07]

- **break 与 continue**
  - 两者都用在循环内部，用于更精细地控制代码执行流程。
  - **break**：非常决绝，一旦执行就会立刻终止并**跳出整个循环**。
  - **continue**：相对温和，只会结束**当前这一次迭代**，然后立刻开始下一次迭代。

- **标签语句（label）**
  - 在简单的循环中，`break` 和 `continue` 只能影响它们所在的最内层循环。
  - 在嵌套循环中，如果想从内层循环直接跳出外层循环，就需要用到 `label` 标签。
  - **用法**：给外层循环起一个标签名，然后在内存循环里使用 `break` 并带上该标签名，即可直接终止外层循环。
  - **评价**：这是一个不常用的进阶高级技巧。

## with 语句 *Content-[06:36]

- **作用**：临时改变作用域链。在 `with` 代码块的内部，可以直接访问指定对象的属性，不需要写对象名本身。
- **严重缺陷**：
  - 会使得代码的**词法作用域**变得非常模糊不清。
  - 开发者很难判断一个变量到底是来自 `with` 对象，还是来自外部作用域。
  - 给代码的理解、维护和调试带来了极大的困难。
- **结论与建议**：
  - 这是一种非常不好的实践，通常**不推荐**使用。
  - 在**严格模式**（Strict Mode）下，`with` 语句被完全禁止使用。
  - 在日常开发中，应该彻底避免使用 `with` 语句。
