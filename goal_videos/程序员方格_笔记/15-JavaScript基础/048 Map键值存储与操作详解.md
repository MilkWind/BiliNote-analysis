## Map 简介与核心特性 *Content-[00:00]

Map 是 ES6 引入的一个核心数据结构，提供了一种更加现代、专业的方式来存储键值对，解决了传统意义上使用 Object 作为键值存储时面临的限制。你可以将 Map 理解成一个功能更加纯粹、更加强大的字典结构。

相较于 Object，Map 具有以下三个显著的核心特性：

1\. **键（Key）可以是任意数据类型**：不再局限于只能使用字符串或 Symbol 作为键。对象、函数甚至是基本数据类型都可以作为 Key。
2\. **严格保持元素的插入顺序**：以什么顺序添加数据，遍历时就会以相同的顺序取出。而在 Object 中，尤其是处理数字类型的 Key 时，顺序是无法完全得到保证的。
3\. **更优的性能表现**：相较于频繁的增删操作，Map 的内部实现通常会提供比 Object 更好的性能。

**基础代码示例**：
通过 `new Map()` 创建实例，使用 `set` 方法添加数据（支持字符串、数字、对象、函数等作为 Key），并通过 `size` 属性直接获取键值对的数量，无需像 Object 那样手动计算。

## Map 与 Object 的对比 *Content-[02:58]

为了直观理解“任意类型键”这一特性解决的问题，我们需要对比 Map 和 Object 在处理特殊 Key 时的差异。

**Object 的局限性**：
- **数字 Key 隐式转换**：当尝试使用数字 `1` 作为 Key 时，JavaScript 引擎会将其隐式转换为字符串 `"1"`。如果先后用数字 `1` 和字符串 `"1"` 赋值，实际上是在操作同一个属性，后者会覆盖前者。
- **对象作为 Key 时的冲突**：当把对象（如 `k1` 和 `k2`）作为 Key 时，它们会被强制调用 `toString()` 方法，结果均变成字符串 `"[object Object]"`。这会导致同名键冲突，`k2` 的值会覆盖 `k1` 的值，最终只存储了一个值。

**Map 的解决方案**：
- **精确区分类型**：Map 能精确区分数字 `1` 和字符串 `"1"`，将它们视为两个完全不同的 Key，允许它们共存。
- **比较对象的内存引用**：对于对象类型的 Key，Map 比较的是对象的内存引用地址。因此，`k1` 和 `k2` 作为两个不同的对象实例，在 Map 中就是两个独立的 Key，互不干扰。这在需要将元数据关联到特定对象实例的场景中非常有用。

## Map 的核心 API 与操作 *Content-[05:05]

Map 的 API 设计直观且语义明确，遵循常见的增删改查模式：

- **`set(key, value)`**：添加一个新的键值对，或者更新一个已经存在的 Key。**注意**：该方法执行后会返回 Map 实例本身，因此支持链式调用，可以方便地在一行代码中添加多个数据。
- **`get(key)`**：根据 Key 获取对应的值。
- **`has(key)`**：检查一个 Key 是否存在于 Map 中，返回布尔值。
- **`delete(key)`**：删除指定的键值对。
- **`clear()`**：一次性清空整个 Map。

**重要属性 `size`**：
`size` 属性可以直接返回 Map 中键值对的数量。这是一个时间复杂度为 $O(1)$ 的操作，意味着无论 Map 中有多少数据，获取其大小都非常快。相比之下，Object 需要调用 `Object.keys().length` 来计算属性数量，Map 的性能优势更加明显。

## Map 的迭代机制 *Content-[07:31]

Map 是一个内置的可迭代对象，并且会严格遵守插入的顺序。可以通过包含键值对数组的数组来快捷初始化 Map，例如：`new Map([['apple', 1], ['banana', 2], ['orange', 3]])`。

Map 提供了多种遍历方式：

1\. **`entries()`**：返回一个迭代器，每个元素都是 `[key, value]` 形式的数组。可以在 `for...of` 循环中通过解构赋值获取 Key 和 Value，输出顺序与插入顺序完全一致。
2\. **`keys()` 与 `values()`**：分别返回只包含 Key 或 Value 的迭代器。可以配合展开运算符 `...` 直接将它们转换成数组。
3\. **`forEach(callback)`**：与数组的 `forEach` 非常相似，接收一个回调函数。**特别注意**：回调函数的参数顺序是 **`value` 在前，`key` 在后**，这是为了与数组及其他集合类型的 `forEach` 方法保持一致。
4\. **`for...of` 直接遍历**：最常用且最简洁的方法。Map 默认的迭代器就是 `entries` 迭代器，因此可以直接在 `for...of` 循环中使用 Map 实例本身，并直接进行解构赋值，代码非常优雅。

## Map 与 Object 的选型指南 *Content-[09:47]

在实际项目中，选择 Map 还是 Object 取决于具体的业务场景。

**优先选择 Map 的场景**：
1\. **非字符串类型 Key**：需要将 DOM 节点或对象实例作为 Key 来关联数据时，Object 无法胜任，必须使用 Map。
2\. **频繁的增删操作**：Map 的内部实现针对此类操作有性能优化，表现更好。
3\. **需要保证迭代顺序**：要求数据的迭代顺序与插入顺序严格一致时。
4\. **频繁快速获取集合大小**：利用 Map 的 `size` 属性（$O(1)$ 复杂度），比 Object 获取 Key 长度更高效。
5\. **动态 Key**：使用 Map 的 `get`/`set` 方法比操作 Object 的动态属性更加清晰、安全。

**优先选择 Object 的场景**：
1\. **固定的字符串 Key**：编码时已知的字符串（如简单的配置对象），Object 的字面量语法更加简洁。
2\. **JSON 数据交换**：`JSON.stringify` 和 `JSON.parse` 原生支持 Object，而 Map 需要进行额外的转换步骤。
3\. **需要解构赋值**：Object 支持解构赋值，而 Map 目前不支持。
4\. **结构化数据记录**：当目的只是为了存取一个结构化的数据记录（Record）或纯数据对象时，Object 更符合语义。

**选型原则总结**：
当你需要一个**字典或者哈希表**数据结构时，选择 `Map`；当你只是需要一个简单的 **Record 或者是纯数据对象**时，选择 `Object`。

## AI 总结

本视频详细讲解了 JavaScript ES6 中 Map 数据结构的核心特性、API 用法以及与 Object 的对比选型。Map 突破了传统 Object 作为键值存储的限制，支持任意数据类型作为 Key、严格保持插入顺序，并在频繁增删和获取集合大小（$O(1)$ 复杂度）时具备更优的性能。在 API 层面，Map 提供了语义明确的增删改查方法及丰富的迭代机制。在实际开发中，若需处理复杂键类型、保证遍历顺序或构建哈希表，应优先选用 Map；若涉及 JSON 交互、固定字符串键的配置对象或纯数据结构记录，Object 仍是最佳选择。掌握两者的核心差异与适用场景，是前端开发中数据结构选型的关键。
