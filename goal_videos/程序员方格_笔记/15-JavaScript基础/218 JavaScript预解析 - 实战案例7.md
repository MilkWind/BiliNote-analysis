## 案例七：JavaScript预解析与作用域链综合实战 *Content-[00:00]

本案例是 JavaScript 预解析（变量提升与函数提升）结合**作用域链**的经典实战题目。通过剖析代码在内存中的预解析阶段和代码执行阶段，深入理解局部作用域与全局作用域的交互机制。

### 核心代码还原
根据视频讲解，本题的核心代码如下：
```javascript
var a = 1;
function fn() {
    alert(a);
    a = 2;
}
fn();
alert(a);
```

### 第一阶段：全局预解析（变量与函数提升）
在代码执行前，JavaScript 引擎会进行预解析（提升），将 `var` 声明的变量和 `function` 声明的函数提升到当前作用域的最前面。

- **寻找 `var` 变量**：发现 `var a`，在预解析“仓库”（内存空间）中将 `a` 赋值为 `undefined`。
- **寻找 `function` 函数**：发现 `function fn()`，在预解析“仓库”中将 `fn` 赋值为整个函数体 `function() { alert(a); a = 2; }`。

**预解析完毕后的内存状态**：
- `a = undefined`
- `fn = function() { alert(a); a = 2; }`

### 第二阶段：全局代码执行
预解析完成后，代码从上到下逐行执行。

1. **第一行 `var a = 1;`**：
   - 将数字 `1` 赋值给变量 `a`。
   - 此时全局作用域中 `a` 的值变为 `1`。
2. **第二行 `function fn() {...}`**：
   - 函数声明本身不会改变变量的值，因此不做任何修改操作，直接跳过。
3. **函数调用 `fn();`**：
   - 遇到函数调用，进入 `fn` 的局部作用域，开启新的预解析和执行流程。

### 第三阶段：函数 `fn` 内部执行与作用域链
函数内部是一个独立的**局部作用域**，遵循与全局相同的“先预解析，后执行”规则。

#### 1. 局部预解析
- 检查函数内部是否有 `var`、`function` 关键字以及参数。
- 经检查，函数内部均没有，因此局部预解析“仓库”为空。

#### 2. 局部代码执行
- **执行 `alert(a);`**：
  - 在局部作用域中查找变量 `a`，发现局部预解析仓库为空，没有 `a`。
  - 根据**作用域链**规则（“自己身上没有，就找父级”），向上级（全局作用域）查找。
  - 在全局作用域中找到 `a`，且当前全局 `a` 的值为 `1`。
  - **结果**：第一个弹窗输出 **`1`**。
- **执行 `a = 2;`**：
  - 将 `2` 赋值给 `a`。
  - **关键细节**：这里的 `a` 前面**没有** `var` 关键字。在 JavaScript 中，如果在函数内部给一个未用 `var` 声明的变量赋值，它会默认成为**全局变量**。
  - 因此，这一步操作直接**覆盖**了全局作用域中的 `a`。
  - 执行完毕后，全局变量 `a` 的值被修改为 `2`。
- 函数 `fn` 内部代码执行完毕，退出局部作用域，返回全局。

### 第四阶段：全局后续代码执行与验证
回到全局作用域，继续执行剩余代码。

- **执行 `alert(a);`**：
  - 此时需要打印全局变量 `a` 的值。
  - 由于在 `fn` 函数内部执行时，全局 `a` 已经被覆盖修改为 `2`。
  - **结果**：第二个弹窗输出 **`2`**。

### 最终结果验证
在浏览器控制台或执行环境中运行该代码，弹窗依次输出 `1` 和 `2`，与通过预解析和作用域链规则推断的结果完全一致。

## AI 总结 *Content-[08:49]

本视频详细拆解了 JavaScript 预解析与作用域链的综合实战案例。核心考点包括：
1. **预解析机制**：`var` 声明的变量提升为 `undefined`，`function` 声明的函数整体提升。
2. **作用域链查找**：函数内部访问变量时，若局部不存在，会沿着作用域链向上层（全局）查找。
3. **隐式全局变量**：在函数内部直接对未使用 `var` 声明的变量赋值，会意外修改或覆盖全局变量，这是前端开发中常见的陷阱。
通过分阶段（预解析 -> 全局执行 -> 局部执行 -> 全局后续执行）剖析，能够清晰、准确地推断出代码的最终执行结果。
