## 原型中 this 的指向与作用 *Content-[00:00]

### 1\. 原型方法中 this 的指向
在原型对象的方法中使用 `this`，完全可以实现“谁调用就指向谁”的功能。
- **核心原则**：不要被函数定义的环境所迷惑。函数内的 `this` 指向取决于**最终是谁调用了该函数**。
- **示例说明**：如果实例对象 `p1` 调用了原型上的 `sayHi` 方法（即 `p1.sayHi()`），那么方法内部的 `this` 就指向 `p1`，从而能够正确获取 `p1` 自身的 `name` 属性并输出“张三你好”或“李老五你好”。
- **结论**：在原型中调用方法本身没有实际意义，将方法绑定到原型上的唯一目的就是为了**让实例对象去访问和调用**。

### 2\. 原型绑定方法与属性的区别
在改造传统构造函数时，需要严格区分方法和属性的放置位置：
- **方法（公有）**：适合绑定在原型对象上，供所有实例共享（比喻为“大家共用同一个教室的灯”）。
- **属性（独享）**：**绝对不能**放在原型对象中作为公有属性。因为属性的目的是为每个对象独有一份（比喻为“个人的手机”或“女朋友”），如果写在原型里，所有实例将共享同一个属性值，修改一个实例的属性会影响所有实例，导致严重错误。
- **最佳实践**：原型中一般只绑定方法，不绑定属性；属性应写在构造函数内部（通过 `this.xxx = xxx`）。

### 3\. 原型三角关系
理解原型的核心在于掌握以下三角关系：
1\. **构造函数** 通过 `prototype` 属性访问 **原型对象**。
2\. **构造函数** 实例化出一个或多个 **实例对象**。
3\. **实例对象** 通过隐式原型（`__proto__`）链接到 **原型对象**，从而能够访问原型里面的属性和方法。

## 直接替换原型对象 *Content-[03:13]

### 1\. 替换原型的背景
每次创建一个构造函数时，系统都会自动为其分配一个默认的空原型对象。但有时开发者看不上这个默认的空对象，而是希望使用一个已经定义好多个方法的自定义对象（视频中比喻为“心中的白月光”）来作为原型。

### 2\. 代码实现示例
通过直接将构造函数的 `prototype` 指向自定义对象，即可实现原型替换。

```javascript
// 1. 定义一个自定义对象（白月光），包含多个方法
const o = {
    sayHi: function() {
        console.log(this.name + " 您好");
    },
    eat: function() {
        console.log(this.name + " 吃吃吃");
    },
    run: function() {
        console.log(this.name + " 跑跑跑"); // 东北话“撩”的意思即 run
    }
};

// 2. 创建构造函数，内部只保留实例独有属性
function Person(name, age) {
    this.name = name;
    this.age = age;
}

// 3. 直接替换原型对象
Person.prototype = o;

// 4. 实例化对象并调用方法
const p = new Person("小李", 18);
p.sayHi(); // 正常输出：小李 您好
p.eat();   // 正常输出：小李 吃吃吃
p.run();   // 正常输出：小李 跑跑跑
```
**效果**：通过原型替换，实例对象 `p` 可以完美调用自定义对象 `o` 中的所有方法，省去了逐个绑定方法的繁琐操作。

## 原型替换带来的问题（同父异母） *Content-[08:39]

### 1\. 核心问题：前后对象原型不一致
原型替换虽然方便，但会引发一个严重问题：**在替换前创建的对象**和**替换后创建的对象**，它们的原型对象是不一致的。
- **生动比喻**：这就像“同父异母”的亲兄弟。构造函数（父亲）是同一个，但在替换原型（离婚再娶）前后生下的孩子，他们的原型（母亲）不是同一个。

### 2\. 代码验证与测试
为了验证这个问题，我们在替换前后分别绑定方法并创建对象：

```javascript
// 1. 替换前：给“原配”原型绑定一个 walk 方法
Person.prototype.walk = function() {
    console.log(this.name + " 正在走路");
};

// 2. 创建替换前的对象（原配生的孩子）
const p = new Person("小李", 18);

// 3. 执行原型替换（迎娶白月光）
Person.prototype = o; // 新原型包含 sayHi, eat, run

// 4. 创建替换后的对象（白月光生的孩子）
const o1 = new Person("小张", 19);
```

### 3\. 方法调用测试结果
- **旧对象调用旧方法**：`p.walk()` -> **可以调用**（`p` 指向旧原型，旧原型有 `walk`）。
- **旧对象调用新方法**：`p.eat()` -> **报错 `p.eat is not a function`**（`p` 无法访问新原型 `o` 中的方法）。
- **新对象调用旧方法**：`o1.walk()` -> **报错 `o1.walk is not a function`**（`o1` 指向新原型，新原型没有 `walk`）。
- **新对象调用新方法**：`o1.eat()` -> **可以调用**（`o1` 指向新原型，新原型有 `eat`）。

### 4\. 最终结论
- 替换前创建出来的对象，**只能访问旧原型**里面的数据和方法。
- 原型替换后创建出来的对象，**只能访问新原型**里面的数据和方法。
- 两者互不干扰，但也无法跨越原型链去调用对方原型上的方法。在实际开发中，应尽量避免在实例化过程中途替换原型，以免引发难以排查的 Bug。

## AI 总结 *Content-[15:22]

本节视频深入讲解了 JavaScript 原型（Prototype）的高级使用技巧及注意事项。核心要点如下：
1\. **this 指向**：原型方法中的 `this` 依然遵循“谁调用指向谁”的原则，指向调用该方法的实例对象。
2\. **属性与方法分离**：原型只适合存放供所有实例共享的**公有方法**；**属性**必须放在构造函数内部以保证每个实例独享，绝不能放入原型中。
3\. **原型替换**：可以通过 `Constructor.prototype = customObj` 直接替换默认原型，以复用已定义好的方法集合。
4\. **替换的副作用**：原型替换会导致替换前后创建的实例对象指向不同的原型（“同父异母”现象），旧实例无法访问新原型的方法，新实例也无法访问旧原型的方法。因此，原型替换操作应在创建任何实例之前完成。
