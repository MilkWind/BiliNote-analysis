## 1. JS的作用域分类 *Content-[00:23]

在 JS 中，作用域主要分为以下两种：

- **全局作用域**：不在任何一个函数内的作用域。在全局作用域中声明的变量，可以在代码的任何地方被访问。
- **局部作用域**：在函数内部创建的作用域。在函数内部声明的变量即为局部作用域变量，只能在函数内部访问。

**关于块级作用域的补充**：
- ES6 引入的 `let` 和 `const` 关键字具有块级作用域的特点。
- 但 JS 语言本身并没有真正的块级作用域，仅仅是 `let` 和 `const` 创建的变量具备该特性。
- 抛开这两个关键字，使用 `var` 声明的变量或普通的代码块（如 `{}`）无法形成真正的块级作用域。

## 2. 词法作用域的概念 *Content-[01:48]

词法作用域（Lexical Scope）也可以理解为“变量作用域”，是前端面试中常考的核心概念。

- **核心定义**：在代码编写过程中体现出来的作用域范围。
- **关键特性**：
  - 代码一旦写好，**不用执行**，作用域范围就已经确定好了。
  - 作用域确定后就不会再发生改变。
  - 通过阅读代码阶段就能看出其作用域。
- **代码块与全局变量**：
  - 因为 JS 没有真正的块级作用域，所以一个大括号 `{}` 并不能形成真正的作用域。
  - 在大括号内（如 `if` 语句中）使用 `var` 声明的变量依然是全局变量，在全局任何地方都可以使用，不会报错（这与 C++、C#、Java 等语言不同）。

## 3. JS作用域规则与面试核心心法 *Content-[03:14]

在分析作用域面试题时，必须掌握以下核心规则（面试心法）：

1. **函数允许访问外部数据**：下级作用域可以访问上级作用域的数据。
2. **只有函数可以限定作用域**：整个代码结构中，除了函数内部是局部作用域，其余皆为全局作用域。
3. **优先使用变量提升规则分析**：在分析作用域题目时，第一步必须先分析变量和函数的提升规则。
4. **就近原则**：如果当前作用域内已经有同名变量，则不再向外层查找（内部有就不去外部找）。

## 4. 经典面试题解析 *Content-[04:10]

### 4.1 基础作用域查找
- **场景**：全局定义 `var num = 123`，父函数内部没有 `num`，直接打印 `num`。
- **分析**：父函数内部找不到 `num`，向上级（全局）查找，找到 `num = 123`。
- **结果**：输出 `123`。

### 4.2 变量提升与 `if` 语句
- **场景**：全局定义 `var num`，在 `if (false) { var num = 456; }` 中赋值，然后打印 `num`。
- **分析**：
  - JS 中只有函数能限定局部作用域，`if` 语句的大括号不能限定作用域，因此 `num` 是全局变量。
  - **变量提升**：`var num` 声明会被提升到顶部，但赋值操作不会提升。
  - 提升后，`num` 声明但未赋值，初始值为 `undefined`。
  - `if (false)` 条件不成立，内部代码不执行，赋值操作未发生。
- **结果**：输出 `undefined`。

### 4.3 嵌套函数中的作用域查找
- **场景**：全局 `num = 123`，父函数内部 `num = 456`，子函数内部打印 `num`。
- **分析**：子函数执行时，先在当前作用域查找 `num`，未找到；继续向上级（父函数）查找，找到 `num = 456`。
- **结果**：输出 `456`。

### 4.4 函数内部修改上级作用域变量
- **场景**：
  - 全局 `var num1 = 123`。
  - 函数一内部 `var num1 = 456`，并调用函数二。
  - 函数二内部直接赋值 `num1 = 789`（无 `var` 声明），并调用函数三。
  - 函数三内部打印 `num1`。
  - 最后在全局打印 `num1`。
- **分析**：
  - 函数二中的 `num1 = 789` 是赋值操作。由于函数二内部没有声明 `num1`，它会向上级查找到函数一中的局部变量 `num1`，并将其修改为 `789`。
  - 函数三打印时，沿着作用域链找到函数一的 `num1`，此时已被修改为 `789`。
  - 全局的 `num1` 和函数一的 `num1` 不是同一个变量，全局变量未被修改，依然为 `123`。
- **结果**：函数三输出 `789`，全局输出 `123`。

## 5. 词法作用域的核心本质（调用位置 vs 定义位置） *Content-[10:23]

### 5.1 核心面试题解析
- **场景**：
  - 全局 `var num = 123`。
  - `func1` 内部打印 `num`。
  - `func2` 内部定义 `var num = 456`，并调用 `func1`。
  - 全局调用 `func2`。
- **易错点**：很多人认为 `func1` 是在 `func2` 内部被调用的，所以会去 `func2` 的作用域找 `num`，误以为输出 `456`。
- **正确结果**：输出 `123`。

### 5.2 词法作用域的本质
- **定义决定作用域**：词法作用域意味着作用域在**代码编写（定义）时**就已经确定，与函数**在哪里被调用**完全无关。
- **`func1` 的作用域**：`func1` 定义在全局，它的作用域链就是 `func1` 内部 -> 全局。无论它在哪里被调用，它都只能访问自己定义时的作用域（即全局的 `num = 123`）。
- **调用位置的作用**：函数在哪里被调用，只能决定该函数**何时执行**，绝不会改变其作用域。

### 5.3 生动案例理解（南极打电话）
- **比喻**：
  - 假设你在南极（调用位置），通过卫星电话给在家里（定义位置）的朋友小张（被调用的函数）打电话。
  - 你在南极挨冻，但小张在家里吹暖气，他并不会因为你在南极打电话给他而感到冷。
  - **结论**：调用位置（南极）的环境，无法影响被调用者（小张）所在的环境（家里）。同理，`func1` 在 `func2` 中被调用，`func2` 的环境（局部作用域）无法影响 `func1` 自身定义时的环境（全局作用域）。
- **除非传参**：除非通过参数传递（比喻为发明一种“电话穿梭机”把人传过来），否则调用位置无法改变被调用函数的作用域。

## AI 总结 *Content-[14:29]

本视频详细讲解了 JS 中的**词法作用域**（变量作用域）这一核心前端面试考点。主要内容包括：
1. **作用域分类**：JS 仅有全局作用域和局部作用域（函数作用域），`let`/`const` 提供了块级作用域特性，但 `var` 和普通代码块不具备。
2. **词法作用域本质**：作用域在代码编写（定义）时就已经确定，与函数的调用位置无关。
3. **解题心法**：分析作用域题目时，需牢记“只有函数能限定作用域”、“变量提升规则”以及“就近查找原则”。
4. **易错点规避**：在嵌套函数调用中，内部函数始终沿着其**定义时**的作用域链查找变量，而不是沿着**调用时**的执行上下文查找。掌握这一本质，即可轻松应对绝大多数 JS 作用域面试题。
