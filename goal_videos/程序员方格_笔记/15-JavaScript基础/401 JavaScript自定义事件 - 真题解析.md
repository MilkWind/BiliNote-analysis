## 1. 什么是JS自定义事件及其与内置事件的区别 *Content-[00:03]
- **自定义事件**：由开发者手动创建、手动绑定、手动触发的非浏览器内置事件。
- **浏览器内置事件**：例如 `click`、`touchstart` 等，由浏览器的特定行为自动触发。
- **核心区别**：两者的触发主体不同。
  - **内置事件**：由浏览器控制触发。
  - **自定义事件**：由开发者通过 `dispatchEvent` 方法手动触发，可以在任意时机完成执行。

## 2. 创建自定义事件的两种方法及区别 *Content-[00:37]
- **两种创建方法**：`Event` 构造函数 和 `CustomEvent` 构造函数。
- **核心区别**：是否支持自定义参数。
  - **`Event` 构造函数**：仅能创建无参的简单自定义事件，语法相对简单。
  - **`CustomEvent` 构造函数**：支持通过 `detail` 属性传递任意类型的参数，并且还能配置事件冒泡（`bubbles`）。它可以覆盖 99% 的实际开发场景。
- **开发建议**：在实际开发中应优先使用 `CustomEvent` 构造函数。这种方法同时也是 Vue 或 React 等框架中自定义事件的底层实现原理。

## 3. 如何给自定义事件传递参数 *Content-[01:21]
- **实现方式**：通过 `CustomEvent` 构造函数的 `detail` 属性来传递参数。
- **具体实现步骤**：
  1. **传递参数**：在创建 `CustomEvent` 时，在配置项中通过 `detail` 属性设置需要传递的参数。
  2. **获取参数**：在绑定的自定义事件处理函数中，通过事件对象 `e.detail` 来获取传递的参数。

## 4. 如何让自定义事件支持事件冒泡 *Content-[01:55]
- **配置方法**：在创建自定义事件时，在配置项中显式设置 `bubbles: true`，即可开启事件冒泡。
- **实际用途**：主要用于实现子组件或子元素向父组件或父元素的通信传值。父组件或父元素无需直接给子组件绑定事件，只需监听冒泡上来的自定义事件即可。这是前端框架中实现“子向父传值”的核心底层原理。

## 5. 如何手动触发自定义事件 *Content-[02:28]
- **使用方法**：通过 DOM 元素的 `dispatchEvent` 方法手动触发。
- **语法格式**：`元素.dispatchEvent(event)`。
- **触发时机**：该方法非常灵活，可在浏览器内置事件完成、异步请求结束、定时器结束等任意时机调用。

## 6. 如何移除自定义事件及原因 *Content-[02:54]
- **移除方法**：使用 `removeEventListener` 方法移除自定义事件。
- **移除原因**：如果自定义事件不再使用但未被移除，会造成内存泄漏，从而严重影响页面性能。
- **移除的关键点**：事件的处理函数**不能是匿名函数**，必须定义具名函数。并且在移除时，传入的事件名和具名函数必须与绑定时完全一致，否则无法成功移除。

## 7. 自定义事件在实际开发中的常见应用场景 *Content-[03:23]
1. **组件通信**：在原生或框架开发中，实现子组件向父组件的通信传值。
2. **异步处理**：异步请求完成后触发自定义事件，以处理后续的业务逻辑。
3. **组件/插件封装**：在封装公共组件或插件时，提供自定义事件供使用者监听（例如：轮播图的切换完成事件）。
4. **模块解耦**：实现多个独立模块之间的通信，达到代码解耦的目的（例如：将业务逻辑放在 A 模块，将触发事件的逻辑放在 B 模块）。
5. **逻辑复用**：当多个操作需要触发同一业务逻辑时，通过自定义事件避免代码重复，实现封装与复用。

## 8. Vue 和 React 自定义事件的底层原理 *Content-[04:12]
- **底层基础**：Vue 的 `$emit` 和 React 的自定义事件，底层都是基于 JavaScript 原生的 `CustomEvent` 实现的。
- **实现流程**：
  1. 通过 `CustomEvent` 创建带有参数的自定义事件。
  2. 开启 `bubbles` 属性实现事件冒泡。
  3. 子组件通过 `$emit`（Vue）触发事件。
  4. 父元素通过 `v-on`（Vue）或 `addEventListener`（本质）监听事件，从而实现子向父的传值与通信。
