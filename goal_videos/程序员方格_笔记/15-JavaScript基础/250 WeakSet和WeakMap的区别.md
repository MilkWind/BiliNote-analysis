## Map 集合的核心概念与特性 *Content-[00:00]
- **Set 集合回顾**：Set 集合的核心特点是元素的**唯一性**和**不重复性**，添加重复元素时会自动查重。
- **Map 集合的本质**：Map 集合同样具备不重复的特性，但其最大区别在于它是一个**键值对（Key-Value）集合**。
- **成双成对的结构**：Map 中的每一个元素都由“键（Key）”和“值（Value）”组成。
- **生活中的键值对映射**：
  - 电脑文件属性：类型、大小、占用空间、创建时间等。
  - 零食包装袋信息：生产日期、保质期、配料表、开口处等。
  - 这些生活中的“属性-属性值”关系，本质上都是键值对。因此，Map 集合非常契合日常开发中存储关联数据的场景。

## Map 集合的创建与常用方法 *Content-[01:27]
- **创建方式**：由于 Map 存储的是键值对，因此不能像 Set 那样直接传入一维数组，而是需要传入**二维数组**。
  - 示例：`[['name', '张三'], ['age', 20]]`，其中第一个元素是键，第二个元素是值。
- **数据类型支持**：Map 的**键**和**值**都可以是**任意类型**，包括字符串、数字、对象，甚至是函数（如箭头函数）。
- **核心操作逻辑**：根据“键”来操作“值”。键就像保险柜的钥匙，通过钥匙来存取对应的物品（值）。
- **常用 API 方法**：
  - 根据键获取值 / 设置值
  - 判断键是否存在（`has`）
  - 根据键删除对应的值（`delete`）
  - 获取集合的大小（`size`）
  - 遍历集合：支持 `forEach` 和 `for...of` 循环。

## Set 与 Map 的核心区别 *Content-[05:48]
- **Set 集合**：强调元素本身的**唯一不重复**，元素是独立存在的个体。
- **Map 集合**：强调**键值对**结构，核心在于通过“键”来管理和操作对应的“值”。

## 强引用与垃圾回收机制（GC） *Content-[06:51]
- **对象的存储机制**：当 Set 和 Map 中存储**对象**时，实际存储的是该**对象的内存地址**。
- **强引用导致的内存问题**：
  - 这种存储方式构成了**强引用**。
  - 如果一个对象在业务逻辑中已经不再使用（被社会抛弃），但只要它的地址还保留在 Set 或 Map 集合中（名字还在组织里），垃圾回收器（GC）就**不会**回收该对象。
  - 这会导致对象一直占用内存，容易引发内存泄漏。

## WeakSet 与 WeakMap 的特性与应用场景 *Content-[08:09]
- **Weak（弱引用）的含义**：`WeakSet` 和 `WeakMap` 中的“Weak”代表弱引用。
- **不阻止垃圾回收**：
  - 弱引用**不会阻止**垃圾回收器回收对象。
  - 如果一个对象只被 `WeakSet` / `WeakMap` 引用，而在程序的其他地方没有被引用，GC 会将其视为“眼中钉”，**随时可能将其回收**。
  - 只有当对象在其他地方也被引用时，它才会被保留。
- **核心应用场景**：非常适合用来存储**缓存式**的、非核心的临时对象，能够有效避免内存泄漏。

## Set/Map 与 WeakSet/WeakMap 的全面对比 *Content-[09:22]
- **迭代能力对比**：
  - `Set` 和 `Map` 是**可迭代**的，可以使用 `for...of` 等方法遍历。
  - `WeakSet` 和 `WeakMap` 是**不可迭代**的。因为其中的对象随时可能被 GC 回收，无法保证迭代过程中数据的稳定性和一致性。
- **支持的数据类型对比**：
  - `Set` 和 `Map` 可以存储**任意类型**的数据（包括原始类型和引用类型）。
  - `WeakSet` 和 `WeakMap` **只能存储对象和 `Symbol` 类型**，不能存储普通的数字、字符串等原始类型。

## AI 总结 *Content-[10:25]
本次面试讲解深入剖析了前端 ES6 中集合数据结构的差异与内存管理机制。`Set` 和 `Map` 提供了强大的数据去重和键值对存储能力，但由于其对对象采用**强引用**，在特定场景下可能导致内存泄漏。为此，ES6 引入了 `WeakSet` 和 `WeakMap`，它们采用**弱引用**机制，不阻止垃圾回收器（GC）回收不再使用的对象，且仅支持对象和 `Symbol` 类型、不可迭代。在实际开发中，应根据是否需要长期持有对象引用以及是否需要遍历，合理选择使用标准集合还是弱引用集合，以优化内存性能。
