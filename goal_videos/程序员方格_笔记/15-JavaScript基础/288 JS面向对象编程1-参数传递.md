## 参数传递基础概念 *Content-[03:19]

在日常开发中，参数传递是极其频繁的操作，涉及基本类型和引用类型的传递。

**核心结论：**
在 ECMAScript 中，**所有函数的参数都是按值传递的**。

**按值传递的定义：**
按值传递顾名思义，就是把函数外部的值复制给函数内部的参数。这类似于将一个变量的值赋值给另一个变量。

## 基本数据类型的参数传递 *Content-[05:52]

对于基本数据类型（如 Number、String、Boolean 等），按值传递的机制非常直观。

**代码示例：**
```javascript
let val1 = 1;

function foo(val) {
    val = 2; // 在函数内部重新赋值
    console.log(val); // 输出: 2
}

foo(val1);
console.log(val1); // 输出: 1
```

**机制解析：**
1. 调用 `foo(val1)` 时，将 `val1` 的值（`1`）拷贝一份传递给函数内部的参数 `val`。
2. 在函数内部对 `val` 进行重新赋值（`val = 2`），只是修改了局部副本的值。
3. 这个操作完全不会影响外部的原始变量 `val1`，因此外部打印的结果依然是 `1`。

## 引用数据类型的参数传递 *Content-[08:02]

当传递复杂数据类型（如 Object、Array 等引用类型）时，情况会有所不同，这通常被称为**按共享传递**（或按引用传递）。

**代码示例与场景对比：**
```javascript
let obj = { val: 1 };

function foo(o) {
    // 场景一：修改对象内部的属性
    o.val = 2; 
    console.log(o.val); // 输出: 2
    
    // 场景二：直接对参数重新赋值（取消注释以测试）
    // o = 2; 
    // console.log(o); // 输出: 2
}

foo(obj);
console.log(obj.val); 
// 场景一下输出: 2 （原对象被影响）
// 场景二下输出: 1 （原对象未被影响）
```

**机制解析：**
- **场景一（修改属性）**：函数内部通过参数修改了对象的属性，外部原始对象 `obj.val` 也变成了 `2`。这说明两者引用的是同一个对象。
- **场景二（重新赋值）**：如果在函数内部直接将参数 `o` 重新赋值为基本类型 `2`（或一个新对象），此时只是改变了局部参数 `o` 的指向，外部原始对象 `obj` 依然保持不变（`obj.val` 仍为 `1`）。

## 底层机制与内存图解 *Content-[12:10]

要彻底理解上述现象，需要深入 JS 的内存管理机制，即**栈内存（Stack）** 与**堆内存（Heap）** 的协作。

**1. 基本数据类型的存储：**
- 存储在**栈内存**中。
- 占用空间大小确定，由系统自动分配和释放（涉及 GC 垃圾回收机制）。
- 传递时，直接拷贝具体的**值**。

**2. 引用数据类型的存储：**
- 实际的数据内容存储在**堆内存**中。
- 在**栈内存**中存储的是指向堆内存中实际数据的**内存地址**（指针）。

**3. 参数传递的内存流转过程：**
- 当传递引用类型参数时，实际上是将栈内存中的**内存地址**拷贝了一份给函数内部的参数。
- **修改属性时**：函数内部的参数通过拷贝的内存地址，找到堆内存中的实际对象并修改其属性。因为内外指向同一个堆内存地址，所以外部对象也会随之改变。
- **重新赋值时**：在函数内部执行 `o = 2` 时，只是将栈内存中局部参数 `o` 的指针指向了一个新的值（切断了与原堆内存地址的联系）。原有的内存地址和堆内存中的对象并未受到任何影响，因此外部对象保持不变。

## 参数传递机制总结 *Content-[16:15]

综上所述，JS 中函数传递的参数，本质上**传递的都是参数的拷贝**，但拷贝的内容因数据类型而异：

1\. **常规数据类型（基本类型）**：
- 拷贝的是**具体的值**。
- 存储在栈内存中。
- 在函数内部修改参数，**不会**影响外部原有的变量。

2\. **引用数据类型**：
- 拷贝的是**内存地址（指针/索引）**。
- 实际值存储在堆内存中，栈中仅保存地址。
- 在函数内部修改对象的**属性**，**会**影响外部原有的对象（因为操作的是同一块堆内存）。
- 在函数内部对参数进行**重新赋值**，**不会**影响外部原有的对象（因为只是改变了局部栈内存中的指针指向）。
