## 1. 面试题背景与核心问题 *Content-[00:00]

- **核心功能**：`call` 和 `apply` 的主要功能是改变函数内部 `this` 的指向，并且立即执行该函数。
- **面试题重点**：虽然两者功能相同，但面试中主要考察它们之间的区别。回答此题需要从以下三个维度进行深度剖析：
  1. 参数传递方式的区别。
  2. 性能上的区别。
  3. 底层逻辑的区别。

## 2. 核心区别：参数传递方式 *Content-[01:29]

两者的根本区别在于**参数传递的方式不同**。

### `call` 方法
- **传参方式**：参数逐个传递。
- **参数规则**：
  - 第一个参数用于指定 `this` 的指向（即替代函数内部的 `this`）。
  - 后续参数按顺序依次传递给函数的形参。
- **代码示例**：
  ```javascript
  function add(n, m) {
      return this.z + n + m;
  }
  const obj = { z: 10 };
  
  // 第一个参数 obj 替代 this，后续参数 5, 3 依次传递
  const result = add.call(obj, 5, 3); 
  // 计算过程：$10 + 5 + 3 = 18$
  ```

### `apply` 方法
- **传参方式**：参数打包传递。
- **参数规则**：
  - 第一个参数同样用于指定 `this` 的指向。
  - 第二个参数**必须为数组**或类似于数组的对象。数组中的元素会按顺序依次传递给函数的形参。
- **代码示例**：
  ```javascript
  function multiply(n, m) {
      return this.z * n * m;
  }
  const obj = { z: 5 };
  const args = [2, 3];
  
  // 第一个参数 obj 替代 this，第二个参数为数组
  const result = multiply.apply(obj, args); 
  // 计算过程：$5 \times 2 \times 3 = 30$
  ```

## 3. 性能差异与底层逻辑 *Content-[07:30]

由于传参方式的不同，两者的性能也存在差异。在大多数情况下，**`call` 的性能优于 `apply`**。

- **底层机制差异**：
  - **`apply`**：因为第二个参数是数组，底层引擎需要将数组**解构**为独立的参数，然后再分别传入函数的形参。多出的这一步解构动作会导致性能下降。
  - **`call`**：参数在调用时已经明确列出，直接传递给形参，无需额外的解构处理。
- **性能测试数据**：
  - 在现代浏览器（如 Chrome）中进行测试，当函数调用次数极多（例如 1000 万次）且**参数超过 3 个**时，`call` 的性能比 `apply` 快 **5% 到 10%**。
  - 如果参数较少或调用次数少，两者性能差异不明显；但在亿万级访问量的高频调用场景下，这种性能差异会被显著放大。

## 4. ES6 优化方案：展开运算符 *Content-[10:46]

虽然 `call` 性能更好，但在参数较多时，逐个书写参数会导致代码冗长。在 ES6 时代，可以通过**展开运算符（`...`）** 结合 `call` 来完美解决这个问题。

- **实现方式**：使用 `...` 将数组展开，然后传递给 `call`。
- **代码示例**：
  ```javascript
  const args = [2, 3];
  // 使用展开运算符将数组元素展开，传递给 call
  const result = multiply.call(obj, ...args); 
  ```
- **优势**：这种写法等效于 `apply` 直接传递数组，但底层依然保持了 `call` 的高性能优势，同时大幅简化了代码的书写。

## 5. 使用场景建议 *Content-[12:19]

根据两者的特性，在实际开发中应选择合适的场景：

### 优先使用 `call` 的场景
1. **参数数量固定且较少**：当参数在 1~3 个时，直接传递代码可读性最高。
2. **对性能敏感的场景**：如高频调用的函数、亿万级访问量的网站，使用 `call`（或结合展开运算符）能带来更好的性能表现。

### 优先使用 `apply` 的场景
1. **参数已存在于数组或类数组结构中**：无需额外拆散，直接作为第二个参数传入即可，代码更简洁。
2. **需要动态生成参数列表**：当参数是以列表、对象或数组形式动态生成时，`apply` 是最合适的选择。

## AI 总结 *Content-[14:47]

本次视频详细解析了前端高频面试题中 `call` 与 `apply` 的区别。两者的核心功能均是改变 `this` 指向并立即执行函数，但核心区别在于**参数传递方式**：`call` 逐个传递参数，而 `apply` 将参数打包为数组传递。在**底层逻辑与性能**方面，由于 `apply` 需要额外的数组解构操作，`call` 在参数较多或高频调用时性能更优。在实际开发中，建议参数少且固定时使用 `call`，参数已存在于数组中时使用 `apply`；同时，可以利用 ES6 的展开运算符 `...` 配合 `call`，兼顾代码简洁性与执行高性能。
