## 1. IIFE 立即执行函数简介 *Content-[00:00]
IIFE（立即执行函数）是前端实际开发和面试中非常常见的一个核心概念。它有着独特的特点和过人之处，理解并掌握它对于编写高质量的前端代码以及应对大厂面试都至关重要。

## 2. 为什么需要 IIFE（全局污染与内存占用） *Content-[00:35]
在探讨 IIFE 之前，我们先来看看常规函数和变量在全局环境下的局限性：
- **全局污染问题**：如果直接在全局位置创建变量（例如 `let i = 0; console.log(i);`），虽然代码能正常运行，但会污染全局作用域。在实际项目中，全局变量过多极易引发命名冲突和难以排查的 Bug。
- **普通函数的内存浪费**：为了解决全局污染，我们可以将代码放入普通函数中（例如 `function show() { let i = 0; console.log(i); }`）。这样变量就被限制在了函数作用域内。但是，如果这个 `show` 函数在全局只被调用一次，而后续有十万行代码都不再使用它，这个函数对象依然会驻留在内存中，造成不必要的内存浪费。

## 3. 生动比喻：外卖与一次性筷子 *Content-[02:40]
为了更直观地理解上述“内存浪费”的问题，视频中使用了一个非常生动的“点外卖”比喻：
- **场景设定**：点外卖时通常需要餐具，商家一般会提供一次性筷子或环保包装盒。
- **为什么不用“金筷子”**：假设商家给每份外卖都配一双纯金或银制的非一次性筷子。首先，造价极其高昂，不符合商业逻辑；其次，对于消费者而言，非一次性筷子用完后如果不扔，积累十次就会在家里堆满金筷子，极其占用空间（内存）。
- **映射到代码开发**：在代码执行环境中，我们很多时候只需要一个“一次性”的执行空间。IIFE 就像外卖中的一次性筷子，它的核心需求就是：**只需要执行一次，执行完毕后立即变成垃圾，被垃圾回收器（GC）回收，绝不空占内存空间**，同时还能提供一个独立的函数作用域来避免全局污染。

## 4. IIFE 的语法格式与原理 *Content-[06:30]
IIFE 的标准语法格式如下：
```javascript
(function() {
    let i = 0;
    console.log(i);
})();
```
**原理解析**：
- **匿名函数**：内部的 `function() { ... }` 是一个没有名字的匿名函数。匿名意味着它没有外部引用，只能在当前声明的地方使用，无法在第二行被再次调用。
- **创建即调用**：
  - 外层的第一个小括号 `()` 将函数声明包裹起来，使其转换为**函数表达式**（Function Expression）。
  - 紧跟其后的第二个小括号 `()` 则是**调用操作符**，用于立即执行这个刚刚创建的函数表达式。
- 代码执行到此处时，会立即创建函数、执行内部代码，然后函数及其内部变量就会被销毁。

## 5. IIFE 的全称与其他写法 *Content-[08:50]
- **英文全称**：**I**mmediately **I**nvoked **F**unction **E**xpression（立即执行的函数表达式）。
- **其他写法探讨**：
  - **写法二（可用但不推荐）**：`(function() { ... }())`。将调用括号放在内部小括号里面。这种写法在语法上是完全正确的，也能正常执行，但视觉上看起来比较别扭，不符合大多数开发者的阅读习惯。
  - **写法三（不推荐）**：`+function() { ... }()`。利用一元加号 `+` 强制将函数声明转换为表达式。这种写法属于非标准的“奇技淫巧”，显得不伦不类，还会增加额外的记忆负担，在实际开发中应尽量避免。

## 6. IIFE 核心特点总结 *Content-[10:35]
综合以上内容，IIFE（立即执行函数）的核心特点与用法可以总结为以下三点：
1. **创建并立即调用**：函数在声明的同时就会被立即执行，无需额外的调用语句。
2. **用完即焚，不占内存**：函数只执行一次，执行完毕后，其函数体及内部声明的变量就会立刻被垃圾回收器（GC）当作垃圾回收，不会造成内存泄漏或浪费。
3. **隔离作用域，避免污染**：它形成了一个独立的函数包裹空间（块级/函数作用域），内部的变量不会泄漏到全局，完美解决了全局变量污染的问题。
