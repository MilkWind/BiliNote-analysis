## 1. match 与 search 方法 *Content-[00:00]

### match 方法
`match` 是最常用的正则匹配方法，其行为取决于正则表达式是否带有全局标志 `g`（global flag）：
- **不带 `g` 标志**：行为类似于 `RegExp.prototype.exec()` 方法。返回一个包含详细信息的数组，包括匹配到的文本、索引位置以及捕获组的信息。
- **带有 `g` 标志**：返回一个包含所有匹配字符串的简单数组，不再包含索引等详细信息。这在提取所有符合特定模式的文本时非常高效。

### search 方法
`search` 方法专注于寻找位置，接受一个正则表达式，返回第一个匹配项的索引。
- **对比 `indexOf`**：虽然 `indexOf` 也能查找位置，但 `search` 的优势在于它**支持正则表达式**。例如，查找第一个数字出现的位置，`indexOf` 无法直接做到，而 `search` 可以轻松实现。
- **性能建议**：如果只需要查找固定子串，出于性能考虑，推荐使用 `indexOf`；但凡涉及到模式查找，`search` 一定是首选。

## 2. replace 方法详解 *Content-[01:50]

`replace` 是字符串处理中最灵活、最强大的方法。

### 参数与常见坑
- **第一个参数**：可以是字符串或正则表达式。
  - **常见坑**：如果第一个参数是字符串，`replace` 默认**只会替换第一个匹配项**。在 ES2021 之前，若想替换所有匹配项，必须使用带有 `g` 标志的正则表达式。
- **第二个参数**：支持特殊的变量符号和回调函数。

### 特殊变量符号
- `$&`：表示匹配到的子串本身。例如，可以利用它给匹配内容加上括号。
- `$1`、`$2` 等：对应正则表达式中的捕获组。例如，通过正则捕获“姓”和“名”，然后在替换字符串中使用 `$2` 和 `$1` 调换它们的顺序，轻松实现格式调换。

### 回调函数机制
如果替换逻辑非常复杂，简单的字符串无法满足需求，可以向第二个参数传递一个**回调函数**。
- 对于每一个匹配项，该函数都会被调用。
- 函数的返回值会作为最终的替换内容。
- **示例**：匹配所有的数字，在回调函数中将它们乘以 2 再替换回去。这种机制赋予了在字符串替换过程中执行任意逻辑代码的能力。

## 3. replaceAll 方法 (ES2021) *Content-[03:58]

为了解决 `replace` 方法默认只替换第一个匹配项带来的不便，ES2021 标准引入了 `replaceAll` 方法。

### 核心优势
- 在以前，即使是替换简单的固定字符串，为了实现全部替换也不得不写一个正则并加上 `g` 标志。
- 现在只需使用 `replaceAll` 并直接传入字符串，它会自动替换所有出现的位置。代码意图更加直白，同时减少了正则转义带来的麻烦。

### 对比与注意事项
- **对比 `replace`**：`replace` 默认只处理首个匹配，而 `replaceAll` 处理所有的匹配。
- **正则强制要求**：`replaceAll` 虽然也支持正则表达式，但**强制要求正则必须包含 `g` 标志**。如果传入一个不带 `g` 的正则，它会抛出错误。这是为了确保方法名中 "all" 的语义一致性（既然替换所有，就不应允许只替换一个的正则存在）。

## 4. split 方法：字符串与数组的桥梁 *Content-[05:22]

`split` 是数据解析的核心方法，用于将字符串拆分为数组。

### 基础用法与性能优化
- **基本用法**：传入一个分隔符字符串（如逗号），将 CSV 格式的字符串拆分为数组。
- **限制长度**：接收可选的第二个参数，用来限制返回数组的长度。如果只关心前几项数据，该参数可以避免解析整个字符串带来的不必要性能开销。

### 正则表达式的威力
`split` 的真正威力在于支持**正则表达式作为分隔符**：
- **按数字分割**：例如使用 `/\d/` 以数字为界进行分割。
- **处理不规范输入**：当一段文本混合使用了逗号、分号和空格作为分隔符时，可以通过正则一次性识别所有符号，并将它们作为统一的分隔符，清洗出干净的数据列表。

### 互逆操作
`split` 和 `join` 方法是一对互逆的操作：`join` 把数组组合成字符串，`split` 把字符串还原成数组。

## 5. 其他特定场景下的字符串方法 *Content-[07:12]

### localeCompare
用于比较两个字符串的排序顺序，返回一个数字表示原字符串是在参数字符串之前、之后还是相同。
- **最大用处**：配合 `sort` 方法使用。特别是在处理中文字符串排序时，`localeCompare` 能够按照**拼音顺序**正确排序，这是普通比较运算符（如 `<`、`>`）无法做到的。

### normalize
涉及 Unicode 的标准化问题。
- **背景**：在 Unicode 中，同一个字符串可能含有多种编码的表现形式。例如 `café` 中的 `é`，既可以是一个独立的字符，也可以是 `e` 加上重音符号组合而成的。
- **问题**：虽然它们显示相同，但二进制编码不同，会导致全等比较（`===`）失败。
- **解决**：`normalize` 可以将它们转换为标准的形式，确保比较逻辑的正确性。

### valueOf 和 toString
- 通常用来获取 `String` 对象对应的原始值。
- 在日常开发中，我们主要使用字符串字面量。这两种方法在底层类型转换时会被自动调用，手动调用的场景相对较少。
