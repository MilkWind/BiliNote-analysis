## 面试题引入与现象分析 *Content-[00:00]
- **题目描述**：给出一段关于函数重新赋值的代码，要求判断打印内容并解释原因。
- **现象展示**：在特定的函数表达式（如立即执行函数 IIFE）中，尝试在函数内部对函数名进行重新赋值（例如 `show = 99` 或 `show = 20`），但打印结果依然是**函数本身**，而不是赋值后的数字。
- **常见误区**：很多初学者会感到困惑，认为赋值操作理应生效，不明白为什么赋值会“失效”，甚至怀疑是不是代码写错了。

## 声明式函数与变量赋值 *Content-[01:11]
- **声明式创建函数**：使用 `function show() {}` 语法直接声明函数。
- **核心原理**：声明式函数在创建时，内部会同步创建一个与函数同名的**变量**。因此，函数本身就可以被视为一个变量。
- **赋值结果**：既然是变量，就可以被正常重新赋值。例如执行 `show = 99` 后，`show` 的值被修改为 99，再次打印 `show` 就会输出 `99`。

## 函数表达式与常量特性 *Content-[04:06]
- **函数表达式创建函数**：包括将函数赋值给变量（如 `var show = function() {}`）以及立即执行函数（IIFE，如 `(function show() {})()`）。
- **核心特性**：在函数表达式创建的函数**内部**，函数名本身会被视为一个**常量**（Constant），无法被重新赋值。
- **代码验证（IIFE）**：
  - 给立即执行函数加上名字，例如：
    ```javascript
    (function show() {
        show = 99; 
        console.log(show); 
    })();
    ```
  - 在函数内部执行 `show = 99` 时，由于 `show` 在内部作用域是常量，赋值操作会**失败**。
  - 打印结果依然是函数本身。
- **对比外部赋值**：如果是 `var show = function show() {}`，在函数**外部**对 `show` 赋值（`show = 99`）是修改外部的变量，会正常生效。但本题考查的是在**函数内部**对函数名本身赋值，此时函数名表现为常量。

## 严格模式下的赋值报错 *Content-[08:27]
- **非严格模式下的表现**：
  - 在 ES6 中，使用 `const` 声明的常量如果重新赋值会直接报错。
  - 但在本题的默认非严格模式下，函数表达式内部的函数名虽然表现为常量，对其重新赋值只会导致**静默失败**（赋值失败），并不会抛出错误。
- **严格模式下的表现**：
  - 如果在代码顶部加上 `"use strict";` 开启严格模式。
  - 此时再尝试对函数表达式内部的函数名进行重新赋值，代码会直接**报错**（TypeError: Assignment to constant variable）。

## 面试题总结与延伸 *Content-[09:19]
- **原题解析**：题目中的代码使用的是函数表达式（如 IIFE），在函数内部对函数名赋值。由于函数名在内部是常量，赋值失败，因此打印出来的依然是函数本身。
- **举一反三（面试延伸）**：
  - 如果代码**不加**严格模式：赋值失败，打印函数本身。
  - 如果代码**加上**严格模式（`"use strict"`）：常量重新赋值会直接报错。在面试中遇到此类变体题时，需准确回答“报错”而非“赋值失败”。

## AI 总结
本视频详细解析了一道经典的 Web 前端面试题，核心考点在于**声明式函数**与**函数表达式**在内部作用域中对函数名处理的区别。声明式函数的函数名是变量，可被重新赋值；而函数表达式（如 IIFE）的函数名在内部是常量，重新赋值会失败。此外，视频还延伸讲解了非严格模式与严格模式（`"use strict"`）下常量赋值失败的不同表现（静默失败 vs 直接报错），帮助求职者在大厂面试中做到举一反三，避免踩坑。
