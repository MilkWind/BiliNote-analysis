## 2. 什么是 JS 自定义事件 *Content-[01:31]
- **定义**：自定义事件是开发者**手动创建、手动绑定、手动触发**的非浏览器内置事件。简单来说，就是自己定规则、自己触发执行的事件。
- **与内置事件的区别**：
  - **内置事件**（如 `click`、`resize`、`load` 等）：由浏览器行为自动触发，**浏览器控制触发**。
  - **自定义事件**：由开发者控制触发。
- **重要性**：无论是原生开发还是框架开发，企业都会考察自定义事件的用法。如果不了解，会暴露出不懂代码解耦和组件通信的硬伤。

## 3. 为什么要使用自定义事件 *Content-[03:00]
自定义事件的核心价值是**代码解耦**和**灵活通信**，这体现了企业面试官最看重的工程化思维（封装能力）。使用自定义事件主要有以下 4 个核心原因：
1. **逻辑解耦**：将事件触发逻辑和事件处理（业务执行）逻辑分离开来。例如，触发逻辑在组件 A，而业务逻辑在组件 B；或者触发逻辑在一个函数，业务逻辑在另一个函数，这样代码更容易维护。
2. **组件或模块通信**：在原生或框架开发中，用于实现子组件向父组件传值，或者多个独立模块之间的通信。
3. **灵活触发**：可在任意时机手动触发，不受浏览器行为的限制。例如在异步请求完成时，或者定时器结束时触发。
4. **避免代码重复**：当多个操作需要触发同一业务逻辑时，只需绑定一个自定义事件即可，无需重复编写代码，实现代码复用。

## 4. 自定义事件的核心三部曲 *Content-[06:24]
无论使用哪种方式创建自定义事件，都必须遵循“**创建 -> 绑定 -> 触发**”的固定流程，这是面试第一问必考的内容：
1. **创建**：使用 `new Event()` 或 `new CustomEvent()` 方法创建自定义事件对象，并定义事件名称。
2. **绑定**：使用 `addEventListener()` 方法给 DOM 元素绑定自定义事件，指定触发后的处理逻辑。
3. **触发**：使用 `dispatchEvent()` 方法手动触发自定义事件，从而执行绑定的事件处理函数。

## 5. Event 与 CustomEvent 的核心区别 *Content-[08:35]
两者都是用来创建自定义事件的构造函数，核心区别在于**能否传递自定义参数**。在实际开发中，优先使用 `CustomEvent`，因为它能传递参数，可覆盖 99% 的场景。具体对比如下：
- **参数传递**：
  - `new Event()`：不支持直接传递自定义参数。
  - `new CustomEvent()`：支持通过 `detail` 属性传递任意类型的参数（如对象、数组、字符串等）。
- **语法复杂度**：
  - `new Event()`：相对简单，仅需传入事件名。
  - `new CustomEvent()`：稍复杂，支持配置项（如传参、冒泡等）。
- **使用场景**：
  - `new Event()`：适用于无需传递参数的简单自定义事件。
  - `new CustomEvent()`：适用于需要传参的实际开发场景；Vue 和 React 框架自定义事件的底层实现均使用的是 `CustomEvent`。
- **浏览器兼容性**：两者均全浏览器支持（`CustomEvent` 除外 IE，但现代企业开发已无需考虑 IE 兼容性）。

## 6. 自定义事件的事件冒泡 *Content-[10:53]
- **默认行为**：自定义事件默认**不支持**冒泡。
- **配置方法**：需要在创建事件时显式配置 `bubbles: true`（布尔值设为 `true`）。
- **实际用途**：开启冒泡后，才能实现子元素触发自定义事件，父元素监听并执行。这是**子组件向父组件传值**的核心实现方式。

## 7. 自定义事件的移除 *Content-[11:52]
- **为什么要移除**：与浏览器内置事件一样，自定义事件绑定后如果不再使用，必须移除。否则会占用不必要的内存空间，甚至可能造成**内存泄漏**。
- **移除方法**：必须使用 `removeEventListener()` 方法进行移除。
- **移除的关键与注意事项**：
  - 处理函数**不能是匿名函数**，必须定义**具名函数**。
  - 移除时，传入的**事件名**和**具名函数**必须与绑定时**完全一致**。
