## 1. null 和 undefined 的核心区别 *Content-[00:00]
两者都是表示“无”的特殊值，但核心差异体现在数据类型、数值转换和语义场景三个方面：
- **数据类型**：
  - `undefined` 属于 undefined 类型，`typeof` 返回 `"undefined"`。
  - `null` 属于 null 类型，`typeof` 返回 `"object"`。
  - 两者的真实类型可通过 `Object.prototype.toString.call()` 来获取。
- **数值转换**：
  - `null` 转为数值是 `0`，可以参与算术运算。
  - `undefined` 转为数值是 `NaN`，无法参与算术运算。
- **语义场景**：
  - `undefined` 是**被动的“原始空”**，表示原来就是空的，由 JS 引擎自动声明（如声明变量未赋值、函数参数未传等，共 7 种情况）。
  - `null` 是**主动的“人为空”**，由开发者手动赋值，专门用来表示空（如初始化未来存储对象的变量、解除对象引用等，共 5 种场景）。

## 2. null 和 undefined 的相等判断（== 与 ===） *Content-[01:16]
- **`==`（松散相等）**：会进行隐式类型转换。`null` 和 `undefined` 都表示“无”，隐式转换后值相等，因此返回 `true`。
- **`===`（严格相等）**：不会进行任何类型转换，要求类型和值都完全相等。由于 `null` 是 null 类型，`undefined` 是 undefined 类型，两者类型完全不同，因此直接返回 `false`。

## 3. null 和 undefined 的使用场景与自动出现场景 *Content-[01:53]
- **手动赋值 `null` 的常见场景**：
  1. **初始化引用类型变量**：声明一个将来需要存储对象或数组（引用类型）的变量时，初始化为 `null` 语义非常合适。
  2. **解除对象引用**：在让垃圾回收机制（GC）回收内存时，将变量赋值为 `null`。
- **自动出现 `undefined` 的常见场景**（共 7 种，此处列举 4 种）：
  1. 声明变量但未赋值。
  2. 函数形参未传（默认值为 `undefined`）。
  3. 访问对象或数组中不存在的属性或索引。
  4. 函数没有 `return` 语句，默认返回 `undefined`。

## 4. 在 if 判断中均为 false，为何仍需区分 *Content-[02:45]
虽然二者在条件判断中都会转为假值（false），但区分它们的核心目的如下：
- **代码语义化**：明确区分开发者手动设置的空（`null`）与 JS 引擎自动生成的未定义（`undefined`），让代码更易读、易维护。
- **避免算术 Bug**：`null` 转数值是 `0` 可参与运算，而 `undefined` 转数值是 `NaN`，会导致算术运算结果异常。
- **开发规范**：让 `undefined` 只在自动场景出现，手动赋值统一使用 `null`，形成统一的编码规范，减少团队协作沟通成本。

## 5. JSON 数据格式中为何只支持 null 不支持 undefined *Content-[03:32]
- JSON 是一种轻量级的数据交换格式，其设计原则是简洁、通用、可解析。
- `undefined` 表示“未定义”，没有实际的数值意义，因此 JSON 规则只支持 `null` 来表示空值。
- 如果对象属性值为 `undefined`，在使用 `JSON.stringify()` 时会直接忽略该属性，从而避免传输无意义的空值，减少数据传输量。

## 6. 如何手动获取 undefined 值 *Content-[03:57]
- **方法一**：直接使用全局的 `undefined`（例如 `window.undefined`）。
- **方法二**：使用 `void` 操作符，它对任意表达式求值都会返回 `undefined`（例如 `void 0`）。

## 7. 存储对象的变量初始化：null 还是 undefined *Content-[04:14]
- **应该初始化为 `null`**。
- **原因**：`null` 的语义是人为设置的空对象，明确表示该变量的用途是用来存放对象的，只是目前还未赋值，语义非常清晰。如果初始化为 `undefined`，会让变量的用途变得不明确，不符合开发的语义化规范。

## 8. 解除对象引用时为何赋值为 null *Content-[04:42]
- **语义层面**：解除对象引用是开发者的手动操作，`null` 表示主动的人为置空，语义完全匹配；而 `undefined` 是被动的原始空，混用会导致语义混乱。
- **内存方面**：赋值为 `null` 能切断变量与对象的引用关系，让对象成为游离状态，从而让垃圾回收机制（GC）顺利回收内存。虽然赋值为 `undefined` 也能切断引用，但不符合语义化规范，属于不推荐的写法。

## 9. 访问不存在的 DOM 元素与对象属性的返回值 *Content-[05:21]
- **访问 DOM 不存在的元素返回 `null`**：因为 DOM 是独立于 JS 的外部 API，其规范明确规定不存在的元素返回 `null`。
- **访问对象不存在的属性返回 `undefined`**：因为 JS 引擎的规范规定，访问对象未定义的属性时不会报错，而是自动返回 `undefined`。

## AI 总结 *Content-[05:52]
`null` 和 `undefined` 虽然都表示“无”，但在前端开发中有着严格的语义分工。`undefined` 代表 JS 引擎自动分配的“被动缺失”（如未赋值的变量、缺失的参数），而 `null` 代表开发者主动设置的“人为空值”（如初始化对象引用、解除 DOM 引用）。在类型判断、数值转换、JSON 序列化以及相等性比较（`==` 与 `===`）中，两者的行为差异显著。遵循“`undefined` 自动出现，`null` 手动赋值”的编码规范，不仅能保证代码语义清晰、提升可读性，还能有效避免潜在的算术 Bug 和内存泄漏问题。
