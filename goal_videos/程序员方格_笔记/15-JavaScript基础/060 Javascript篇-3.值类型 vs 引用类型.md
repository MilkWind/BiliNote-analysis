## 1. 引言与核心问题 *Content-[00:01]
- 日常开发中的常见困惑：
  - 为什么将一个变量 `B` 赋值给 `A` 后，改变 `A` 会导致 `B` 跟着变，而有时它们又各自独立、互不影响？
  - 将对象作为参数传递给函数时，函数内部到底对这个对象做了什么？
  - 为什么用 `const` 声明了一个对象，依然可以修改它的属性？
- 这些问题的答案都指向了 JavaScript 内存管理的核心基石：**值类型与引用类型**。

## 2. 内存存储分类：值类型与引用类型 *Content-[00:57]
从内存的角度来看，JavaScript 中所有的数据都会被归为两大类：

### 2.1 值类型（原始类型）
- **核心特点**：
  - 变量直接存储数据的值本身。
  - 赋值给另一个变量时，发生的是**值的拷贝**。
  - 数据通常存放在内存的**栈（Stack）** 中。
- **包含的类型**（共 7 种）：
  - `String`
  - `Number`
  - `Boolean`
  - `Null`
  - `Undefined`
  - `Symbol`
  - `BigInt`

### 2.2 引用类型
- **核心特点**：
  - 变量存储的不是数据本身，而是一个**内存地址**（称为引用）。
  - 赋值操作时，拷贝的仅仅是这个**引用（地址）**。
  - 数据本身被存放在内存的**堆（Heap）** 中。
- **包含的类型**：
  - `Object`
  - `Array`
  - `Function`
  - 所有其他的对象实例。

## 3. 值类型的赋值行为与内存解析 *Content-[03:08]
通过代码和内存图拆解值类型的赋值过程：

```javascript
let a = 100;
let b = a;
a = 200;
```

- **执行 `let a = 100`**：JavaScript 在栈内存中为 `a` 开辟一个空间，并将 `100` 存入。
- **执行 `let b = a`**：由于 `a` 是值类型，发生值的拷贝。系统在栈中为 `b` 开辟全新空间，并将 `a` 的值 `100` 复制进去。此时 `a` 和 `b` 是两个完全独立的变量。
- **执行 `a = 200`**：直接修改变量 `a` 所在内存空间的值，将其从 `100` 更新为 `200`。此过程与 `b` 无关，`b` 的值依然是 `100`。
- **结论**：值类型的赋值行为是**赋值即拷贝，之后互不干扰**。

## 4. 引用类型的赋值行为与内存解析 *Content-[05:19]
通过代码和内存图拆解引用类型的赋值过程：

```javascript
let obj1 = { name: 'Alice' };
let obj2 = obj1;
obj1.name = 'Bob';
```

- **执行 `let obj1 = { name: 'Alice' }`**：
  - 对象实体 `{ name: 'Alice' }` 被创建在**堆内存**中（假设地址为 `0x101`）。
  - 变量 `obj1` 被创建在**栈内存**中，它不存储对象本身，而是存储堆内存中的地址 `0x101`。
- **执行 `let obj2 = obj1`**：
  - 发生**引用的拷贝**。系统在栈中为 `obj2` 开辟新空间，并将 `obj1` 存储的地址 `0x101` 复制给 `obj2`。
  - 此时 `obj1` 和 `obj2` 就像两把钥匙，指向堆内存中的**同一个对象**。
- **执行 `obj1.name = 'Bob'`**：
  - 通过 `obj1` 存储的地址找到堆内存中的对象，并修改其 `name` 属性。
  - 因为 `obj2` 指向同一个对象，所以通过 `obj2.name` 访问时，结果也是被修改后的 `'Bob'`。
- **结论**：引用类型的赋值会导致多个变量指向同一内存地址，修改对象内部属性会相互影响。

## 5. 核心考点一：函数参数的传递机制 *Content-[08:32]
- **核心结论**：JavaScript **永远是按值传递**的。
  - 对于值类型：传递的是**值的副本**。
  - 对于引用类型：传递的是**引用的副本**（内存地址的副本）。

**代码示例分析**：
```javascript
function modify(obj) {
  obj.name = 'modify';
  obj = { name: 'new object' };
}

let myObj = { name: 'original' };
modify(myObj);
```

- **传参过程**：`myObj` 传入函数时，发生引用的拷贝。函数内的参数 `obj` 和外部的 `myObj` 指向堆内存中的同一地址。
- **修改属性**：执行 `obj.name = 'modify'` 时，通过函数内的引用修改了公共对象，因此会影响外部的 `myObj`。
- **重新赋值**：执行 `obj = { name: 'new object' }` 时，让函数内的 `obj` 指向一个全新的对象（在堆中创建新对象并赋新地址）。这一步**彻底切断**了函数内 `obj` 与外部 `myObj` 的联系。
- **最终结果**：`myObj.name` 的值变为 `'modify'`，而函数内部后续的重新赋值对外部变量无任何影响。

## 6. 核心考点二：const 声明对象的修改原理 *Content-[11:38]
- **核心原理**：`const` 保证的是**变量所存储的内容不可变**。
  - 对于引用类型，变量存储的是一个**内存地址**。
  - 因此，`const` 只能保证该变量**永远指向同一个地址**，不能保证地址指向的对象内部内容不可修改。
- **代码示例**：
  ```javascript
  const user = { name: 'Alice' };
  user.name = 'Bob'; // 合法：没有改变 user 变量里存的地址，只是修改了对象内容
  user = { name: 'Charlie' }; // 报错 (TypeError)：试图改变 user 变量本身存储的地址
  ```

## 7. 核心考点三：全等运算符的比较机制 *Content-[12:48]
全等运算符（`===`）在比较不同类型时，行为有所不同：
- **值类型**：比较的是**值**是否相等。
  - 例如：`100 === 100` 结果为 `true`。
- **引用类型**：比较的是**内存地址（引用）** 是否相等。
  - 例如：`{} === {}` 结果为 `false`。因为这两个空对象在堆内存中是独立创建的，拥有不同的地址。
  - 例如：
    ```javascript
    let objA = {};
    let objB = objA;
    objA === objB; // 结果为 true，因为它们存储了完全相同的地址，指向同一个对象。
    ```

## 8. 课程总结 *Content-[14:01]
1. **数据类型分类**：JavaScript 数据分为值类型和引用类型。值类型存值本身，引用类型存内存地址。
2. **赋值行为差异**：值类型赋值会完整拷贝一份值；引用类型赋值只拷贝地址，导致后续行为差异巨大。
3. **函数传参机制**：JavaScript 永远按值传递。对于引用类型，传递的是引用的副本。这意味着在函数内部可以修改对象属性，但不能通过重新赋值来影响外部变量本身。
