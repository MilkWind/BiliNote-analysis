## 1. 面试题背景与需求分析 *Content-[00:00]
- **手写代码考察**：在前端面试中，手写代码是常见的考察方式，主要用于检验候选人的实际编码能力、逻辑思维以及对基础 API 的掌握程度。
- **题目核心需求**：将浏览器 URL 中 `search` 部分（即 `?` 后面的查询参数）的字符串转换为 JSON 对象（Object）。
- **URL 参数结构示例**：
  - 格式：`?a=1&b=2&c=3`
  - `?` 标志着 search 部分的开始。
  - 参数由 `key=value` 组成，多个参数之间使用 `&`（and 链接符）连接。
- **目标**：将上述字符串解析为对象，以便通过属性名直接获取对应的值（例如通过 `obj.a` 获取 `1`），从而方便后续的数据处理。

## 2. 常规思路及其局限性 *Content-[02:21]
- **题目要求**：在 JavaScript 中，请将一个 URL 的 search 部分的参数与值转成一个 JSON 对象。
- **常规思路（字符串分割法）**：
  1. 截取 `?` 后面的所有内容，获取 search 字符串。
  2. 使用 `&` 对字符串进行 `split` 分割，得到包含各个 `key=value` 的数组。
  3. 遍历数组，再使用 `=` 对每个元素进行二次分割，提取 key 和 value 并赋值给目标对象。
- **局限性分析**：
  - **未考虑 Key 重复**：在实际 URL 中，参数名（key）可能会重复（例如 `?language=zh&language=en`）。简单的分割赋值会导致后面的值覆盖前面的值，丢失数据。
  - **代码繁琐**：需要进行多次字符串分割和条件判断，代码量较大，逻辑不够优雅。
  - **边界情况处理不足**：缺乏对 URL 编码、特殊字符等复杂情况的全面校验，容易引发 Bug。

## 3. 标准解法：使用 URLSearchParams *Content-[05:22]
为了追求代码量少、功能全且考虑周全，推荐使用浏览器原生 API `URLSearchParams`。

### 3.1 提取 search 部分
- 使用 `new URL(urlString)` 来解析完整的 URL。
- **注意**：传入的 URL 字符串必须包含协议名（如 `http://` 或 `https://`），否则会抛出错误。
- 通过 `url.search` 属性提取包含 `?` 在内的完整 search 字符串。

### 3.2 解析 search 字符串
- 使用 `new URLSearchParams(searchString)` 对提取出的 search 部分进行解析。
- 该 API 会自动处理 URL 编码（如将 `%20` 或 `+` 解码为空格），并生成一个类似 Map 的 `URLSearchParams` 对象。

### 3.3 处理重复参数名并转换为普通对象
由于 `URLSearchParams` 在遇到重复 key 时，默认行为可能不符合直接转为 JSON 对象的需求（需要将重复的值放入数组），因此需要手动遍历处理：
1. 定义一个空对象 `result = {}` 用于存储最终结果。
2. 使用 `entries()` 方法遍历 `URLSearchParams` 对象的所有键值对。
3. 在遍历过程中进行判断：
   - **如果 key 已存在于 `result` 中**：说明参数重复。将 `result[key]` 转换为数组（如果原本不是数组的话），并将当前的 `value` `push` 到该数组中。
   - **如果 key 不存在**：直接将 `result[key] = value` 赋值。
4. 遍历结束后，返回 `result` 对象。

### 3.4 核心代码实现
```javascript
function parseSearch(urlString) {
  // 1. 提取 search 部分
  const url = new URL(urlString);
  const searchString = url.search;
  
  // 2. 解析 search 字符串
  const params = new URLSearchParams(searchString);
  const result = {};
  
  // 3. 遍历处理重复参数
  for (const [key, value] of params.entries()) {
    if (result[key] !== undefined) {
      // 如果已存在，转为数组或 push 进数组
      if (Array.isArray(result[key])) {
        result[key].push(value);
      } else {
        result[key] = [result[key], value];
      }
    } else {
      result[key] = value;
    }
  }
  
  return result;
}
```

## 4. 代码特性与测试验证 *Content-[11:06]
- **自动解码功能**：`URLSearchParams` 会自动对 URL 中的编码字符（如空格、中文等）进行解码，无需手动调用 `decodeURIComponent`。
- **重复参数处理**：通过上述的 `entries()` 遍历逻辑，完美解决了同名参数覆盖的问题，将其合理转换为数组。
- **数据类型**：解析后的所有值均保持为 **字符串 (String)** 类型。
- **兼容性**：支持所有现代浏览器以及 Node.js 环境。
- **测试验证**：传入包含重复参数（如 `?language=zh&language=en`）的 URL，输出结果中 `language` 的值为 `['zh', 'en']`，符合预期业务逻辑。

## 5. 简化替代方案：Object.fromEntries *Content-[12:46]
如果确定 URL 中**绝对不会出现重复的 key**，可以使用更简短的一行代码方案。

- **实现方式**：
  结合 `URLSearchParams` 和 `Object.fromEntries()`。
  ```javascript
  const result = Object.fromEntries(new URLSearchParams(new URL(urlString).search));
  ```
- **优点**：代码极其简洁，只需一行即可完成转换。
- **缺点/局限性**：
  - 没有对重复参数名进行特殊处理。
  - 当存在重复的 key 时，`Object.fromEntries()` 会直接覆盖，**只保留最后一个值**。
- **适用场景**：适用于业务场景明确、可保证 URL 参数名唯一的情况。

## 6. 面试总结与建议 *Content-[14:46]
- **展现全面思考**：在面试中，不仅要给出能跑通的代码，还要主动提及边界情况（如参数重复、URL 编码等），这能体现思维的严谨性和对实际业务的考量。
- **优先使用原生 API**：尽量使用浏览器提供的标准 API（如 `URL` 和 `URLSearchParams`），它们的健壮性、安全性和兼容性远优于纯手工的字符串分割。
- **权衡代码简洁与功能完整**：
  - 如果追求功能完美，使用 `entries()` 遍历处理重复值的方案。
  - 如果追求极致简洁且业务允许，使用 `Object.fromEntries()` 方案。
  - 面试时可以先写出基础版，再根据面试官的追问补充完善版，展现良好的沟通能力。
