## 1. 垃圾回收 (Garbage Collection) 概念与内存泄漏 *Content-[00:00]

- **程序卡顿的原因**：电脑或程序卡顿通常是因为没有足够的运行空间（CPU 或内存不足）。每个程序运行都需要向系统申请对应的 CPU 和内存空间。
- **内存泄漏 (Memory Leak)**：指申请的空间没有被及时销毁和释放。这会导致系统频繁申请更多有效空间，占用原本就有限的内存资源。
- **内存泄漏的后果**：其他程序无法申请使用内存，当前程序后续操作也会因空间不足而无法执行，最终导致系统卡顿。

## 2. 垃圾的产生与系统内存管理 *Content-[01:24]

- **垃圾的定义**：在程序运行过程中产生的、不再被使用的内存空间。如果内存还在被使用，则不是垃圾；一旦使用完毕且后续不再使用，即成为“垃圾”。
- **系统层面的内存管理**：操作系统或运行时环境会在系统层面上帮助管理内存操作，包括垃圾回收 (Garbage Collection, GC)、垃圾清除以及内存空间的申请等。
- **不同语言的内存管理差异**：
  - **前端 / JS 开发**：对 GC 过程相对无感，JS 引擎会自动执行垃圾回收，开发者无需手动干预。
  - **C/C++ 开发**：需要开发者手动管理内存的分配与释放。

## 3. 垃圾产生原因与 JS 引擎自动分配 *Content-[03:21]

- **内存占用**：在编写代码时，创建基本类型、对象或函数都需要占用相应的内存空间来存储数据。
- **自动分配机制**：JS 引擎会自动为创建的对象和变量分配内存资源，开发者无需手动进行内存分配。

## 4. 内存引用变化与垃圾形成示例 *Content-[04:09]

- **示例代码过程**：
  1. **初始化对象**：`let test = { name: '张三' }`。此时在栈 (Stack) 中的变量 `test` 指向堆 (Heap) 内存中的对象 `{ name: '张三' }`。
  2. **重新赋值**：`test = [1, 2, 3, 4, 5]`。变量 `test` 的引用被修改，重新指向堆内存中的新数组。
- **垃圾形成**：在重新赋值后，原本的对象 `{ name: '张三' }` 失去了引用关系，不会再被程序使用，因此变成了“垃圾”。
- **复杂场景**：如果应用程序频繁创建和修改对象，或者在函数内部创建对象（在没有闭包的情况下），函数执行完毕后这些对象将不再被使用，从而产生大量垃圾，需要及时清理。

## 5. 持续运行进程的内存释放与栈/堆管理 *Content-[06:37]

- **内存释放的重要性**：对于持续运行的服务进程，必须及时释放不再使用的内存。否则内存占用会越来越多，最终导致系统性能下降甚至崩溃。
- **栈 (Stack) 与堆 (Heap) 的管理区别**：
  - **栈**：存储基本数据类型，其内存管理由操作系统直接进行处理和垃圾回收。
  - **堆**：存储引用类型，由于其大小不确定，需要依赖 JS 引擎的垃圾回收机制来进行专门处理。

## 6. 垃圾回收策略与 V8 引擎 *Content-[07:50]

- **垃圾判断标准**：JS 引擎通过“引用关系”来判断对象是否为垃圾。如果一个对象没有任何引用指向它，即没有被使用，引擎就会将其识别为垃圾并进行释放。
- **V8 引擎策略**：V8 引擎提供了一套完整的垃圾回收策略，用于高效地识别和清理内存中的垃圾，保障程序的稳定运行。
