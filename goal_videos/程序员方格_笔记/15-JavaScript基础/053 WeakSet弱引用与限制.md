## WeakSet 简介与应用场景 *Content-[00:00]
- 在日常前端开发中，开发者通常习惯使用 `Set` 来处理集合数据。
- 当涉及复杂的对象引用关系和内存管理时，使用标准的 `Set` 可能会导致内存泄漏问题。
- 此时应使用 `WeakSet` 来编写更高效、更安全的 JavaScript 代码。

## WeakSet 的核心特点与对比 *Content-[00:47]
- **严格定义**：`WeakSet` 是一个专门用来存储对象引用的集合。
- **核心特点**：
  - 内部只能存储对象，不能存储数字、字符串等原始值。
  - 持有的是对象的弱引用（Weak reference）。
  - 因为是弱引用，`WeakSet` 内部的存在不会干扰垃圾回收（GC）机制。如果一个对象只被 `WeakSet` 引用，垃圾回收器依然可以回收它。
- **与普通 `Set` 的本质区别对比**：
  - **存储类型**：普通 `Set` 可存任意类型；`WeakSet` 仅限对象。
  - **引用方式**：普通 `Set` 是强引用；`WeakSet` 是弱引用。
  - **内存回收**：普通 `Set` 只要存在，元素就不会被回收；`WeakSet` 不影响 GC 回收。
  - **遍历与属性**：普通 `Set` 可遍历，有 `size` 属性；`WeakSet` 不可迭代，没有 `size` 属性。

## 深入理解弱引用机制 *Content-[02:18]
- **强引用 vs 弱引用**：
  - **强引用**：JavaScript 中通常创建的引用都是强引用。将对象赋值给变量，只要变量在作用域内或被其他对象持有，GC 就不会回收该对象。
  - **弱引用**：建立一种非常松散的联系，不足以维持对象的生命周期。弱引用不会阻止 GC 回收对象。
- **内存回收过程示例**：
  - 创建一个 `obj` 对象（强引用），并将其加入 `WeakSet`。
  - 将 `obj` 设置为 `null`，断开对该对象的唯一强引用。
  - 虽然 `WeakSet` 中似乎还存在该对象，但由于是弱引用，GC 会忽略这种关系，直接回收对象占用的内存，其在 `WeakSet` 中的条目也会被自动移除。
  - 这就是 `WeakSet` 能够防止内存泄漏的根本原因。

## WeakSet 的类型限制 *Content-[04:04]
- **为什么只能存储对象**：
  - 基本数据类型（如数字、字符串）通常按值传递，或在引擎内部有特殊的存储池。
  - 它们没有像对象那样明确的生命周期和垃圾回收机制供 `WeakSet` 追踪。
- **允许添加的类型**：
  - 普通对象、字面量、数组、函数、DOM 节点或任何类的实例。
- **禁止添加的类型**（添加会报错）：
  - 基础值：数字、字符串、布尔值。
  - 特殊值：`null`、`undefined`、`Symbol`。

## WeakSet 的 API 限制与设计原因 *Content-[05:08]
- **可用的 API**：
  - `add()`：添加元素。
  - `has()`：检测元素是否存在。
  - `delete()`：删除元素。
- **被屏蔽的功能**：
  - 没有 `size` 属性。
  - 没有 `clear()` 方法。
  - 没有 `forEach` 或任何迭代器接口，彻底屏蔽了所有与集合遍历相关的功能。
- **设计为“黑盒”的原因**：
  - **不确定性**：`WeakSet` 中对象的存活完全取决于是否有其他强引用指向它。如果没有强引用，对象进入待回收状态。由于 JavaScript 的 GC 运行时机不可预测（可能现在运行，也可能等几秒），在任何给定瞬间，都无法确切知道 `WeakSet` 内部到底包含哪些元素（有些可能刚被标记回收但尚未从内存抹去）。
  - **安全性**：假设在遍历 `WeakSet` 时，GC 突然触发回收了一部分对象，迭代器的行为会变得不可预测。
  - **规范决定**：基于上述原因，ES 规范明确决定让 `WeakSet` 成为一个黑盒。开发者只能查询关注的对象是否在里面（通过 `has`），但不能要求列出所有内容。

## AI 总结
`WeakSet` 是 JavaScript 中用于存储对象弱引用的特殊集合。与标准 `Set` 的强引用不同，`WeakSet` 不会阻止垃圾回收器（GC）回收其引用的对象，从而有效避免了复杂对象引用场景下的内存泄漏问题。由于弱引用的特性以及 GC 执行的不可预测性，`WeakSet` 在类型上被严格限制为只能存储对象，在 API 上被精简为仅支持 `add`、`has` 和 `delete`，且被设计为不可遍历、无 `size` 属性的“黑盒”结构。理解 `WeakSet` 的底层机制，有助于在前端开发中编写出内存管理更安全、更高效的代码。
