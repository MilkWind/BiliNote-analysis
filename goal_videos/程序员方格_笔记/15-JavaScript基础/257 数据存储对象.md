## 面试题解析与考察重点 *Content-[00:00]
- **面试题目**：如何使用 JavaScript 实现一个轻量级的本地存储方案，用于保存和读取用户的偏好设置。
- **考察核心**：
  - 对浏览器存储对象（如 `localStorage`）的深入了解。
  - 是否掌握对象的核心用法及其适用场景。
  - 方案封装能力：不仅是调用单个方法，而是将其封装为一个完整的“方案”或“对象”。
- **方案目的**：将用户偏好设置保存在本地，使得读取速度极快，响应迅速。

## 存储（Set）方法的封装与注意事项 *Content-[02:09]
- **封装手法**：使用一个对象来封装存储方案，对外提供 `set` 方法。
- **参数设计**：`set(key, value)`，包含两个参数：`key`（键）和 `value`（保存的值）。
- **Key 的唯一性**：
  - 必须确保 `key` 不会冲突或重复。
  - **解决方案**：为 `key` 添加特定的前缀，组合成唯一的标识。
- **存储对象的选择**：
  - 选用 `localStorage`，调用其 `setItem` API 进行保存。
  - **对比 `sessionStorage`**：基于浏览器的打开状态（关闭即消失），适合保存临时数据，不符合本题“本地持久化存储”的需求。
  - **对比 `cookie`**：大部分由服务端实现和读取，不适合纯前端的本地存储方案。
- **Value 的数据类型限制**：
  - `localStorage` 要求保存的值**必须是字符串**。
  - **解决方案**：如果保存的是对象或数组，必须使用 `JSON.stringify()` 将其转换为字符串后再存储。
- **容量限制**：
  - `localStorage` 的存储容量通常限制为 **5MB**。
  - **建议**：由于容量较小，应只保存有用且重要的数据，避免存储大量无用数据。

## 读取（Get）方法的封装 *Content-[06:57]
- **封装手法**：在对象中提供 `get` 方法用于读取数据。
- **默认值处理**：可以设置默认值，如果未找到对应的 `key`，则返回空值（如 `null`）。
- **读取与转换**：
  - 调用 `localStorage.getItem(key)` 获取数据。
  - 由于存储时使用了 `JSON.stringify()`，读取后需要使用 `JSON.parse()` 将字符串**转换回对象**。
  - **目的**：转换为对象后，可以更方便地使用点语法（`.`）来读取其内部属性，提升开发体验。

## 删除（Remove）方法的封装与API调用 *Content-[08:28]
- **删除单个数据**：
  - 封装 `remove` 方法，调用 `localStorage.removeItem(key)` 删除指定的单条数据。
- **清空所有数据**：
  - 提供批量清空功能，调用 `localStorage.clear()` 清空所有存储的数据。
- **API 调用示例**：
  - 设置数据：`StorageAPI.set('font', '...')`，`StorageAPI.set('style', {...})`。
  - 读取数据：`StorageAPI.get('font')`。
  - 删除数据：`StorageAPI.remove('font')` 或 `StorageAPI.clear()`。
- **回答要点总结**：
  - 彻底了解和掌握 `localStorage` 的 API。
  - 清楚 API 使用的注意事项：`key` 必须唯一（加前缀）、`value` 必须是字符串、明确整体容量大小（5MB）。

## 扩展问题：超出存储容量限制的解决方案 *Content-[09:56]
- **问题场景**：当 `localStorage` 的 5MB 空间被存满，且需要继续写入新数据时该如何处理？
- **自我清除机制（缓存淘汰策略）**：
  - 需要设计一种机制，自动删除旧数据以腾出空间。
  - **淘汰条件 1（时间维度）**：按时间排序，优先删除**保存时间最久**（最早存入）的数据。
  - **淘汰条件 2（频率维度）**：优先删除**不经常使用**（访问频率低）的数据。
  - **综合策略**：结合数据的“保存时间”和“使用频率”，自动清理最不重要、最陈旧的数据，从而释放存储空间，保证系统的持续可用性。
