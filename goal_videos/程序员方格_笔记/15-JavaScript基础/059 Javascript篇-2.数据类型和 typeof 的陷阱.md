## JavaScript 数据类型回顾 *Content-[01:06]
在 JavaScript 中，所有的数据都归属于两大阵营：**原始类型**（Primitive types）和**对象类型**（Object types）。

- **原始类型（共 7 种）**：
  - `String`（字符串）
  - `Number`（数字）
  - `Boolean`（布尔值）
  - `Null`（空值）
  - `Undefined`（未定义）
  - `Symbol`（ES6 加入的符号类型）
  - `BigInt`（后来加入的大整数类型）
- **对象类型**：
  - 除了上述 7 种原始类型之外，其他所有的数据（如数组、函数、日期等）都属于 `Object`。

## typeof 操作符基础与用法 *Content-[01:52]
`typeof` 是一个一元操作符，用法很简单：放在一个变量或值的前面，它会返回一个字符串，告诉你该操作数的类型。

- **对原始类型的返回值**（符合直觉）：
  - `"hello"` 返回 `"string"`
  - `123` 返回 `"number"`
  - `true` 返回 `"boolean"`
  - `Symbol()` 返回 `"symbol"`
  - `BigInt(123)` 返回 `"bigint"`
  - `undefined` 返回 `"undefined"`

- **对对象类型的返回值**：
  - 普通对象 `{a: 1}` 返回 `"object"`
  - 数组 `[1, 2]` 返回 `"object"`（注意：`typeof` 并不区分普通对象和数组，这是一个小陷阱）
  - 日期对象 `new Date()` 返回 `"object"`
  - **例外**：函数 `function() {}` 返回 `"function"`。虽然函数在 JS 中本质也是一种特殊的对象，但 `typeof` 为其提供了一个专门的返回值，这在实际开发中非常方便。

## typeof 的两大核心陷阱 *Content-[04:06]
### 陷阱一：`typeof null` 返回 `"object"`
在控制台打印 `typeof null`，会发现它返回的不是 `"null"` 而是 `"object"`。这是一个在 JS 最初版本就存在，且因历史原因被保留至今的 Bug。
- **历史原因**：在早期的 JS 实现中，内部使用一个“类型标签”来标识数据的类型，对象的标签是 `0`。而 `null` 值在底层的表示恰好是空指针（即全零 `0x00`）。结果 `typeof` 的实现就把这个全零的 `null` 错误地判断成了对象。
- **保留原因**：由于涉及范围太广，如果当时修复可能会破坏大量现有的网站，因此这个 Bug 一直被保留到了今天。

### 陷阱二：无法区分具体的对象类型
无论是数组的字面量还是对象的字面量，`typeof` 都一视同仁，通通返回 `"object"`。这意味着如果你想检查一个变量是不是数组，只用 `typeof` 是绝对不够的。

## 准确的类型判断最佳实践 *Content-[06:03]
既然 `typeof` 存在这些陷阱，社区总结了一些最佳实践来编写更健壮、更准确的类型判断代码：

- **如何正确判断 `null`**：
  - 放弃 `typeof`，直接使用严格相等运算符 `===`。
  - 示例：`myVar === null`。这是最直接也是最可靠的方法。

- **如何正确判断数组**：
  - 使用 ES6 提供的专门工具：`Array.isArray()`。
  - 示例：`Array.isArray(arr)` 会返回布尔值 `true`，而 `typeof arr` 依然返回 `"object"`。判断数组请认准此方法。

- **终极武器：精确判断所有数据类型**：
  - 如果需要区分普通对象、日期对象、正则表达式等更复杂的类型，可以使用 `Object.prototype.toString.call()`。
  - 通过该方法调用，可以获得一个格式非常统一的字符串，精确覆盖所有数据类型：
    - `null` -> `"[object Null]"`
    - 数组 -> `"[object Array]"`
    - 普通对象 -> `"[object Object]"`
    - 字符串 -> `"[object String]"`
    - 数字 -> `"[object Number]"`
  - 这是目前最可靠的通用类型检测方案。

## typeof 的独特优势 *Content-[08:56]
在给 `typeof` 下定论时，它其实还有一个值得一提的优点：**对未声明的变量不会报错**。

- 如果你直接访问一个根本没有声明过的变量（例如 `su`），JavaScript 会立即抛出一个 `ReferenceError`，导致程序中断。
- 但是，如果你对它使用 `typeof su`，你会得到一个安全的字符串 `"undefined"`，而不会导致程序崩溃。
- **应用场景**：在某些场景下，可以用 `typeof` 来安全地检查某个全局变量是否存在，而不必担心引发报错。

## 知识点总结 *Content-[09:58]
- `typeof null` 返回 `"object"` 是一个公认的历史 Bug，判断 `null` 请直接使用 `===`。
- `typeof` 无法区分数组和普通对象，判断数组需要使用 `Array.isArray()` 方法。
- 如果需要精确判断所有数据类型的终极方案，请使用 `Object.prototype.toString.call()`。
