## 1. instanceof 无法判断 null 和 undefined *Content-[00:00]

在使用 `instanceof` 运算符时，它无法用于判断 `null` 和 `undefined`，甚至会直接导致程序报错。

1\. **报错现象**：
当执行 `null instanceof Object` 时，控制台会直接抛出类型错误（TypeError），提示“右侧的 instanceof 不是对象”（Right-hand side of 'instanceof' is not an object）。对 `undefined` 进行同样的操作也会抛出完全相同的错误。

2\. **核心原因**：
`null` 和 `undefined` 在 JavaScript 中都属于**基本数据类型**。而 `instanceof` 运算符的核心机制是**基于原型链进行查找**。因为 `null` 和 `undefined` 是基本类型，它们不是对象，没有原型链，所以 `instanceof` 无法对它们进行判断，从而引发错误。

## 2. instanceof 对基本数据类型的判断陷阱：字面量 vs new 创建 *Content-[00:54]

`instanceof` 在处理基本数据类型时存在一个重要的坑点：**通过字面量创建的基本类型**与**通过 `new` 关键字创建的基本类型包装对象**，在使用 `instanceof` 判断时结果截然不同。

1\. **代码示例与结果**：
- 字面量方式：`7 instanceof Number`，返回结果为 **`false`**。
- `new` 创建方式：`new Number(7) instanceof Number`，返回结果为 **`true`**。

2\. **字面量的概念**：
字面量就是指代码中直接写出来的、一看就知道其具体值的量（例如直接写 `7`），它是 JS 中最基础的数据表示方式。

## 3. instanceof 运算符的两个核心限制 *Content-[01:36]

要理解上述陷阱，首先需要明确 `instanceof` 的核心作用与限制。它的核心作用是检测构造函数的 `prototype` 属性是否出现在实例对象的原型链上。

基于此，它有两个关键的限制条件：

1\. **限制一：仅能判断对象（引用数据类型）**
`instanceof` 无法判断基本类型。因为基本类型不是对象，没有 `__proto__`（原型属性），自然也不存在原型链。既然 `instanceof` 是基于原型链做判断的，遇到没有原型链的基本类型自然无法使用。

2\. **限制二：操作数为基本类型时直接返回 false**
如果 `instanceof` 左侧的操作数是基本数据类型，引擎会直接返回 `false`，根本不会去进行任何原型链的检测。

## 4. 深度解析：为什么 7 instanceof Number 返回 false？ *Content-[04:19]

针对 `7 instanceof Number` 返回 `false` 的现象，需要从以下三个核心维度进行深度剖析（这也是面试时的标准答题逻辑）：

1\. **本质是基本类型且无原型链**：
`7` 是通过字面量创建的基本数据类型，本质上是简单值，直接存储在栈（Stack）中。它不是任何构造函数的实例，没有 `__proto__` 属性，因此根本不存在原型链。

2\. **JS 装箱机制的误区**：
在日常开发中，我们确实可以让 `7` 调用 `toString()`、`toFixed()`（保留小数位）等方法。但这并非因为 `7` 本身变成了对象，而是触发了 JS 的**基本类型装箱行为**。在调用方法的瞬间，JS 引擎会将其临时包装为引用类型（`Number` 对象），方法调用完毕后，这个临时包装对象会**立即被销毁**。因此，`7` 本身依然是基本类型，不会变成 `Number` 的实例。

3\. **instanceof 的检测目标**：
`instanceof` 检测的是 `7` 这个基本类型**本身**，而不是方法调用时产生的临时包装类型。因为 `7` 本身没有原型链，所以直接返回 `false`。

> **💡 面试回答技巧**：
> 回答此问题时，建议分条理阐述：第一点指出它是字面量/基本类型；第二点解释它没有 `__proto__` 和原型链；第三点补充说明虽然能调用方法是因为“临时装箱行为”，但 `instanceof` 检测的是其本身而非临时包装对象。这样回答会显得逻辑非常严密。

## 5. 深度解析：为什么 new Number(7) instanceof Number 返回 true？ *Content-[07:47]

针对 `new Number(7) instanceof Number` 返回 `true` 的现象，核心原因在于**创建方式的不同导致了数据类型的本质差异**。

1\. **显式创建与引用类型**：
`new Number(7)` 是通过 `Number` 构造函数显式创建的。这种方式返回的结果不再是基本类型，而是 `Number` 的包装类型的**实例对象**，它属于**引用数据类型**。

2\. **具备完整的原型链**：
既然是引用类型的实例对象，它就拥有完整的原型链结构：
- 该实例对象自身的 `__proto__` 指向 `Number.prototype`。
- `Number.prototype` 的 `__proto__` 继续向上指向 `Object.prototype`。

3\. **符合 instanceof 检测规则**：
因为 `new Number(7)` 拥有完整的原型链，且 `Number.prototype` 确实存在于它的原型链上，所以它完全符合 `instanceof` 的检测规则，最终返回 `true`。

## AI 总结

本视频深入剖析了 JavaScript 中 `instanceof` 运算符的底层原理及其在特定场景下的局限性。核心知识点包括：
1. **局限性**：`instanceof` 依赖原型链查找，因此无法判断没有原型链的 `null` 和 `undefined`，直接操作会引发 TypeError。
2. **基本类型陷阱**：`instanceof` 只能判断引用类型。对于基本类型，字面量创建（如 `7`）存储在栈中，无原型链，返回 `false`；而通过 `new` 创建（如 `new Number(7)`）会生成引用类型的包装对象，拥有完整原型链，返回 `true`。
