## 案例六：JavaScript 预解析与局部作用域嵌套 *Content-[00:00]

本案例在前五个案例的基础上，引入了**局部作用域**的概念，并详细展示了 JavaScript 引擎如何开启嵌套的预解析和执行代码过程。

### 1\. 代码结构还原
根据视频讲解的逻辑，本案例的 JavaScript 代码结构如下：
```javascript
var a = 1;                  // 第1行
function fn() {             // 第2行
    alert(a);               // 第3行
    var a = 2;              // 第4行
}
fn();                       // 第6行
alert(a);                   // 第7行
```

### 2\. 全局预解析阶段
在全局作用域中，JavaScript 引擎首先进行预解析，寻找 `var` 声明和 `function` 声明。
- 找到 `var a`：在“仓库”（即变量对象/执行上下文）中，`a` 的初始值被提升并赋为 `undefined`。
- 找到 `function fn`：在“仓库”中，`fn` 被赋值为整个函数体代码。
- **全局预解析结果**：此时仓库中的值为 `a = undefined`，`fn = function() { ... }`。

### 3\. 全局执行代码阶段
预解析完成后，开始逐行执行全局代码：
- **第1行**：`var a = 1;`。执行赋值操作，全局变量 `a` 的值由 `undefined` 变为 `1`。
- **第2行**：`function fn() { ... }`。这是一个函数声明，在预解析阶段已经处理过，此处不会改变任何值，直接跳过。
- **第6行**：`fn();`。执行函数调用，代码进入 `fn` 函数内部。由于函数内部是一个**局部作用域**，因此会在此局部作用域内开启新一轮的预解析和执行代码（即嵌套解析）。

### 4\. 局部作用域（fn 函数内部）解析与执行
进入 `fn` 函数后，首先进行局部预解析：
- **局部预解析**：在函数内部寻找 `var` 和 `function`。找到第4行的 `var a`，因此在局部“仓库”中，`a` 的初始值为 `undefined`。（注意：局部变量 `a` 会遮蔽全局变量 `a`）。
- **局部执行代码**：
  - **第3行**：`alert(a);`。此时访问的是局部作用域中的 `a`，由于其刚完成预解析还未执行赋值操作，因此输出结果为 `undefined`。
  - **第4行**：`var a = 2;`。执行赋值操作，局部变量 `a` 的值由 `undefined` 变为 `2`。
- 函数内部代码执行完毕，跳出局部作用域，回到全局作用域继续执行。

### 5\. 回到全局作用域继续执行
- **第7行**：`alert(a);`。此时需要明确当前访问的是哪个作用域的 `a`。由于第7行处于全局作用域，它只能访问全局变量 `a`，无法访问已经销毁的局部变量 `a`。
- 全局变量 `a` 的值在第1行已被赋为 `1`，因此最终输出结果为 `1`。

### 6\. 代码运行验证
将上述代码放入浏览器控制台或编辑器中运行进行验证：
- 第一个弹窗（第3行）：显示 `undefined`。
- 第二个弹窗（第7行）：显示 `1`。
运行结果与通过 JavaScript 引擎执行机制推导出的结果完全一致，证明了上述预解析与作用域嵌套分析的正确性。

## AI 总结

本视频详细讲解了 JavaScript 预解析（Hoisting）机制中的**局部作用域嵌套**核心问题。关键要点在于：当函数被调用时，会在局部作用域内重新进行独立的预解析和执行。局部作用域中的 `var` 声明会产生变量提升，导致在赋值前访问该变量会得到 `undefined`。同时，局部变量会遮蔽（Shadow）同名的全局变量，且局部作用域销毁后不会影响全局作用域。深刻理解全局与局部作用域的隔离性以及预解析的嵌套过程，是掌握 JavaScript 执行上下文、应对复杂变量提升面试题以及大厂前端面试的必备基础。
