## 原型与对象的三角关系 *Content-[00:00]

在 JavaScript 中，构造函数、原型对象和实例对象构成了一个稳定的“三角关系”（可以形象地理解为一家三口），这三者是不可或缺的：
- 只要存在一个构造函数，就会分配一个对应的原型对象。
- 原型（Prototype）的本质就是一个对象。
- 只要是 JS 中的对象，就会有对应的构造函数。

## 函数的本质与构造函数 *Content-[01:14]

要理解大写的 `Function`，首先需要明确函数在 JS 中的本质：
- **函数的功能**：将一段代码过程封装起来，以便反复调用。
- **函数是变量**：函数本身是一个变量。虽然它与基础类型的变量（如 `let a = 10` 用于存储数字）不同，但它依然是一个变量。
- **函数是引用类型**：函数变量不属于基本类型，而是属于引用类型，也就是我们所说的**对象**。因此，**函数本身也是一个对象**。
- **函数的构造函数**：既然函数是一个对象，根据“对象必有构造函数”的原则，函数对象也有自己对应的构造函数，这个构造函数就是大写的 `Function`。

## new Function 的使用与语法 *Content-[03:30]

既然 `Function` 是一个构造函数，那么它就可以像其他构造函数一样，使用 `new` 关键字来创建对象（即创建函数）。

**语法格式**：
`let 函数名 = new Function(参数1, 参数2, ..., "函数体代码字符串")`

**具体示例**：
1\. **无参数创建**：
```javascript
let show = new Function("console.log('我是show函数')");
show(); // 正常调用并输出
```

2\. **带参数创建**：
```javascript
let show = new Function("a", "b", "console.log(a, b)");
show(1, 2); // 正常调用并输出 1, 2
```
通过事实证明，使用 `new Function` 完全可以成功创建并调用函数。

## new Function 的实际意义与局限性 *Content-[05:59]

虽然 `new Function` 可以创建函数，但在实际开发中有着明显的局限性和特定的理论意义。

**局限性（为什么实际开发中几乎不用）**：
- **书写极不方便**：函数体代码必须写成字符串形式。如果代码逻辑简单还好，但如果需要封装一个复杂的业务逻辑（例如 100 行代码的无缝轮播图），将 100 行代码写成字符串会非常繁琐，且完全无法维护。
- 因此，日常开发中我们使用的函数声明方式（如 `function show() {}`）实际上是 `new Function` 的简便写法（字面量语法）。

**实际意义**：
- 其核心意义在于**完善 JS 的底层理论逻辑**。它证明了“函数作为一个对象，拥有自己对应的构造函数”，让 JS 的对象模型在理论上形成闭环。了解其用法即可，无需在业务中强行使用。

**扩展补充**：
- 视频中提到了 ES6 的**模板字符串**（使用反引号 `` ` ``）。模板字符串支持多行换行，可以在一定程度上缓解 `new Function` 中函数体字符串拼接的痛苦，写起来相对方便，但依然不推荐用于实际复杂逻辑的编写。
