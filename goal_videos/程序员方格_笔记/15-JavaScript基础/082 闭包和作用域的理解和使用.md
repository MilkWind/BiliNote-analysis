## CSS 基础面试题解析 *Content-[00:04]

1\. **`display: none` 与 `visibility: hidden` 的区别**
- `display: none`：元素直接不占据任何空间，在视觉上完全丢失。
- `visibility: hidden`：元素依然占据原有的物理空间，只是在视觉上看不见。

2\. **CSS 中 `<link>` 和 `@import` 的区别**
- **引入方式**：`<link>` 属于静态引入，`@import` 属于动态引入。
- **加载时机**：`<link>` 一般写在 `<head>` 标签里，页面加载时就会同步加载，适合用于基础架构样式；`@import` 建议写在 CSS 文件内部，用于加载动态样式。
- **兼容性**：`@import` 只有 IE5 以上版本才能识别（目前基本无兼容问题），而 `<link>` 不存在任何兼容性问题。
- **权重**：`<link>` 的样式权重肯定大于 `@import`。

## CSS 进阶概念与 HTML 基础 *Content-[01:22]

1\. **CSS 盒子模型**
- **组成**：内容（content）、内边距（padding）、外边距（margin）、边框（border）。
- **IE 盒子模型**：设置的宽高即为最终宽高。`padding` 和 `border` 会向内挤压，不会撑大盒子。
- **标准（谷歌）盒子模型**：盒子最终的宽高 = 边框 + 内外边距 + 内容宽高。`padding` 和 `border` 会向外撑大盒子。

2\. **样式初始化**
- **原因**：不同浏览器的默认基础样式存在差异。
- **目的**：如果不进行样式初始化，用户切换浏览器时可能会因默认样式不同导致页面布局混乱。

3\. **BFC（块级格式化上下文）**
- **概念**：一个独立的布局区域。
- **作用**：防止内部样式与外部样式相互冲突（例如通过 `display: none` 等属性触发 BFC）。

4\. **HTML 语义化**
- **原则**：尽量使用语义化标签（如 `<header>`、`<footer>`、`<main>`、`<strong>` 代替 `<b>`、`<dl>` 代替 `<s>` 等），减少使用 `<div>`、`<span>` 等非语义化标签。
- **优点**：有利于 SEO 搜索引擎优化，同时提高 HTML 代码的可读性和结构清晰度。

5\. **其他前端基础知识点**
- **HTML 与 XML 的区别**：纯理论概念，HTML 用于展示数据，XML 用于传输和存储数据。
- **常见兼容问题**：需在实际开发中积累和测试。
- **行内元素与块级元素的区别**：块级元素独占一行，行内元素不独占一行。
- **对 W3C 的理解**：万维网联盟，负责制定 Web 标准。
- **前端三层结构**：HTML（结构层）、CSS（表现层）、JavaScript（行为层）。
- **DOCTYPE 文档声明**：用于告诉浏览器使用哪种 HTML 规范来解析页面。
- **CSS 选择器与 `display` 的常见值**：基础属性，需熟练掌握。

## JavaScript 中的 this 指向 *Content-[04:27]

- `this` 是函数内部默认的一个上下文对象，其指向并非固定不变，而是取决于**函数的调用模式**：
  - **函数模式**：指向全局 `window` 对象。
  - **对象方法模式**：指向调用该方法的对象。
  - **构造函数模式**：指向新创建的实例对象。
  - **上下文模式**（如 `call`、`apply`、`bind`）：想指向谁就指向谁，由传入的参数决定。

## 作用域与闭包的核心概念 *Content-[05:10]

1\. **作用域基础规则**
- JavaScript 传统上只有全局作用域和局部（函数）作用域，没有块级作用域。
- ES6 中 `let` 和 `const` 创建的变量具有块级作用域的特点，但并非创建了全新的作用域。
- **访问规则**：
  - **下级可以访问上级**：如同在屋内可以看到屋外的情况。
  - **上级无法访问下级**：如同走在大街上无法看到别人家里的东西。每一个函数本身就是一个闭合的独立空间（作用域）。

2\. **闭包的意义**
- **核心痛点**：上级作用域无法直接访问下级作用域的数据。
- **解决方案**：通过在下级作用域中再定义一个函数（下下级作用域），并将其作为返回值返回给上级作用域。这样，上级作用域就可以通过调用这个返回的函数，**间接访问**到下级作用域中的数据。

## 闭包的实际应用与代码实现 *Content-[09:35]

1\. **错误示例分析（每次返回新对象）**
```javascript
function show() {
    let obj = { name: '张三', age: 16 };
    return obj;
}

let p1 = show();
let p2 = show();

p1.name = '大黄';
console.log(p2.name); // 依然是 '张三'
```
- **问题所在**：每次调用 `show()` 函数，都会在内存中创建一个新的 `obj` 对象并返回。`p1` 和 `p2` 指向的是两个地址不同的新对象。这就好比去银行取黄金，每次去都给你重新打造一批新黄金，而不是从保险柜里拿同一批。修改 `p1` 自然不会影响 `p2`，这不符合“多次访问同一个内部数据”的需求。

2\. **正确实现（利用闭包返回同一个引用）**
```javascript
function demo() {
    let obj = { name: '张三', age: 16 };
    
    // 返回一个内部函数
    return function() {
        return obj;
    }
}

let d = demo(); // 执行一次 demo，返回内部函数
let p1 = d();   // 执行内部函数，获取 obj
let p2 = d();   // 再次执行内部函数，获取同一个 obj

console.log(p1 === p2); // true，证明是同一个对象引用

p1.name = '大黄';
console.log(p2.name); // '大黄'，因为指向同一对象，一改全改
```
- **实现原理**：`demo` 函数只执行一次，内部的 `obj` 被下下级作用域（返回的匿名函数）引用。外部通过多次调用返回的匿名函数，获取到的始终是同一个 `obj` 的内存引用。

## 闭包的缺点与内存泄漏 *Content-[15:37]

- **内存泄漏/内存溢出风险**：
  - 正常情况下，函数调用完毕后，其内部变量会被销毁，并被垃圾回收器回收。
  - 但在闭包中，内部函数对外暴露，且始终持有对外部函数局部变量（如 `obj`）的**强引用**。
  - 只要外部变量（如 `p1`, `p2` 等）还存在，垃圾回收器就无法回收这些被强引用的对象。
  - 如果闭包使用过多，会导致大量对象常驻内存无法被回收，最终引发内存泄漏或内存溢出问题。因此在使用闭包时需要谨慎，必要时手动解除引用。
