## 1. 面试题解析：ES5与ES6继承的区别概述 *Content-[00:01]
- **核心考点**：对 JavaScript 继承机制的深入理解。
- **涉及知识点**：
  - ES5 中的 `prototype` 原型机制。
  - ES6（及后续如 ES2020 等，通常统称为 ES6 范畴）中的 `extends` 关键字及 `class` 语法。
  - 两者在写法、底层实现及特性上的核心差异。

## 2. ES5 的继承实现方式 *Content-[00:34]
### 2.1 构造函数与原型链 *Content-[00:44]
- **类的模拟**：ES5 没有 `class` 关键字，通过**构造函数（Constructor）** 来模拟类的创建，这与 Java 等强类型语言直接声明类不同。
- **方法复用**：将方法绑定到构造函数的 `prototype` 原型上，使得通过 `new` 关键字创建的所有实例都能共享和调用这些方法。
- **静态方法**：直接绑定在构造函数本身上的方法，属于静态方法。

### 2.2 借用构造函数继承（属性继承） *Content-[02:04]
- **实现方式**：在子类构造函数内部，使用 `call` 或 `apply` 方法调用父类构造函数。
- **原理**：通过 `call` 方法将父类构造函数中的 `this` 指向修改为子类当前的实例对象，从而实现属性的继承。
- **扩展**：`call`、`apply` 和 `bind` 的区别及应用也是前端面试中的高频考点。

### 2.3 原型链继承（方法继承） *Content-[02:40]
- **实现方式**：使用 `Object.create()` 方法拷贝父类的原型对象，并将其赋值给子类的原型。
- **核心细节**：**必须进行对象拷贝，绝对不能直接赋值**（如 `Sub.prototype = Super.prototype`）。
  - 直接赋值会导致两者指向同一个内存地址（引用传递）。
  - 一旦修改子类的原型，会直接污染父类的原型，导致“一改全改”的严重问题。

### 2.4 ES5 继承的局限性与思考 *Content-[03:46]
- **缺点**：写法繁琐、臃肿，需要手动处理属性和方法的继承。
- **思考题**：如果在执行完继承代码之后，再给父类的原型新增方法，子类能否继承到这些新方法？
  - **答案**：**不能**。因为 `Object.create()` 是在继承时拷贝了当时的原型状态，后续父类原型的新增方法不会自动同步到子类。
- **静态方法**：ES5 中父类的静态方法不会自动被子类继承。

## 3. ES6 的继承实现方式 *Content-[04:42]
### 3.1 class 与 extends 关键字 *Content-[04:42]
- **语法升级**：ES6 引入了 `class` 和 `extends` 关键字。
- **写法优势**：语法结构非常类似 Java 等强类型语言，代码更加简洁直观，无需手动操作 `prototype`。

### 3.2 自动继承的优势 *Content-[05:35]
- **动态继承**：ES6 实现了**自动继承**。即使在继承代码执行后，父类在原型上后续增加的新方法，子类也会自动拥有。
- **静态方法继承**：与 ES5 不同，ES6 中父类的静态方法也会自动被子类继承。
- **总结**：ES5 是“手动挨个拿”，ES6 是“你有什么我就自动有什么”，极大提升了开发效率。

## 4. ES6 继承的底层原理与注意事项 *Content-[06:15]
### 4.1 实际开发中的应用 *Content-[06:32]
- **兼容性考虑**：在需要兼容极老旧浏览器的场景下，可能仍需使用 ES5 的写法（或通过 Babel 等工具转译）。
- **项目过渡**：对于旧项目，建议逐步过渡到使用 ES6 的继承方式，因为 ES6 继承更加好用且易于维护。

### 4.2 暂时性死区与 super 关键字 *Content-[06:55]
- **类不能提升**：ES6 的 `class` 不存在变量提升（Hoisting），必须先定义后使用。
- **暂时性死区（TDZ）**：在 `class` 内部存在暂时性死区，局部变量和函数内部变量只能在作用域内使用，无法被提升。
- **super 的使用限制**：在子类的构造函数中，**必须在使用 `this` 之前调用 `super()`**，且 `super()` 必须放在构造函数的**第一行**。

### 4.3 语法糖本质 *Content-[07:48]
- **底层机制**：ES6 的 `class` 和 `extends` 本质上是一个巨大的**语法糖**。
- **未脱离本质**：JavaScript 依然是弱类型语言，`class` 的底层实现依然依赖于 `prototype` 原型链机制。
- **意义**：虽然底层没变，但语法糖封装了繁琐的原型操作代码，让开发者无需手动编写复杂的原型继承逻辑，提升了代码的可读性和开发体验。

## 5. 面试答题要点总结 *Content-[08:29]
在面试中回答“ES5和ES6继承的区别”时，建议从以下三个层次展开：
1. **写法区别**：ES5 基于构造函数和 `prototype`，写法繁琐；ES6 基于 `class` 和 `extends`，写法简洁，类似强类型语言。
2. **底层实现区别**：ES5 需要手动处理属性（`call`）和方法（`Object.create`）的继承；ES6 底层封装了自动继承逻辑，支持父类后续新增方法的动态继承，且静态方法也会自动继承。
3. **本质认知**：向面试官点明，ES6 的 `class` 本质上是**语法糖**，并没有改变 JavaScript 基于原型继承的核心本质，但极大地优化了开发体验。
