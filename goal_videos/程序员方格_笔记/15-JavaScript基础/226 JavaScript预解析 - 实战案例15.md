## JavaScript 预解析实战案例 15 概述 *Content-[00:00]

本视频主要讲解了 JavaScript 预解析机制在定时器（`setTimeout`）场景下的实战应用。通过剖析一段包含全局变量与定时器回调函数的代码，详细演示了全局预解析与局部预解析的执行顺序及变量状态的变化。

### 1\. 核心代码结构还原
根据视频讲解，实战案例的代码逻辑大致如下：
- **第一行**：`var a = 6;` （全局变量声明与赋值）
- **第二行**：`setTimeout(function() { ... })` （定时器及匿名回调函数）
- **定时器内部（第三行）**：`alert(a);` （弹窗输出变量 `a`）
- **定时器内部（第四行）**：`var a = 36;` （局部变量声明与赋值，口述为“三个六”）

## 全局作用域的预解析与执行 *Content-[00:06]

在代码刚开始加载时，JavaScript 引擎会首先对全局作用域进行预解析，然后逐行执行代码。

### 1\. 全局预解析阶段
- **变量提升**：按照预解析规则，全局的 `var a` 会被提前声明，并放入预解析仓库中。此时仓库中的值为 `a = undefined`。
- **匿名函数不预解析**：需要特别注意的是，定时器内部的函数是**匿名函数**，它不会在全局阶段进行预解析。
- **函数内部延迟解析**：函数内部的代码（如 `var a = 36`）在函数未被调用执行时，不会开启预解析。只有当函数真正被调用时，才会开启函数内部的预解析（即局部预解析）。
- **预解析结果**：全局预解析完毕后，全局仓库中仅存在 `a = undefined`。

### 2\. 全局逐行执行阶段
- **执行第一行**：`var a = 6;`。此时全局变量 `a` 被正式赋值为 `6`。
- **执行第二行**：遇到 `setTimeout` 定时器。定时器会将内部的匿名回调函数放入任务队列中，等待主线程空闲及时间到达后再执行，此时并不会立即执行函数内部的代码。

## 定时器回调函数的局部预解析与执行 *Content-[02:43]

当定时器的时间到达后，回调函数被推入执行栈，此时会开启该函数内部的局部预解析与执行机制。

### 1\. 局部预解析阶段
- **开启新仓库**：定时器回调函数执行时，会开启**新的局部预解析**（也可称为局部预解析）。
- **局部变量提升**：在函数内部遇到 `var a`，引擎会将其提前声明并放入局部预解析仓库中。此时，局部仓库中的值为 `a = undefined`。
- **预解析结果**：局部预解析完毕后，函数内部的局部变量 `a` 初始值为 `undefined`，它遮蔽（Shadow）了外部的全局变量 `a`。

### 2\. 局部逐行执行阶段
- **执行第三行**：`alert(a);`。由于局部变量 `a` 刚刚经过预解析，值为 `undefined`，且尚未执行到下一行的赋值操作，因此此时 `a` 的值就是 `undefined`。弹窗输出的结果即为 `undefined`。
- **执行第四行**：`var a = 36;`。将数值 `36` 赋值给局部变量 `a`。此时局部 `a` 的值变为 `36`（但这发生在 `alert` 之后，因此不会影响前面的弹窗结果）。

## AI 总结

本视频通过实战案例深入剖析了 JavaScript 中的预解析（变量提升）机制，特别是其在定时器回调函数中的表现。核心结论是：
1. **全局与局部隔离**：全局预解析只处理全局的 `var` 声明，定时器内的匿名函数在未被调用前不会进行预解析。
2. **局部预解析机制**：当定时器回调函数执行时，会开启独立的局部预解析。函数内部的 `var a` 会被提升并初始化为 `undefined`。
3. **变量遮蔽效应**：由于局部预解析的存在，回调函数内部的 `a` 在赋值前（即 `alert(a)` 时）为 `undefined`，而不会读取到外部全局变量 `a` 的值（`6`）。这强调了在开发中理解作用域和预解析机制对排查变量状态问题的重要性。
