## 1. 场景题解析：如何拦截 JS 函数的执行 *Content-[00:00]

在前端面试的场景题中，经常会遇到这样一个问题：**如何对每个 JS 函数的执行实现拦截？** 
这个问题主要考察的是我们如何感知并拦截 JavaScript 函数的执行过程。针对这个问题，常用的手段主要有两种：
1. **高阶函数（手动包裹）**：通过高阶函数的形式，在原始函数外包裹一层逻辑。
2. **Proxy 代理对象**：利用 ES6 的 `Proxy` 特性，通过代理对象的方式来拦截函数的调用。

## 2. 方式一：使用高阶函数实现拦截 *Content-[01:37]

### 核心原理
高阶函数（Higher-Order Function）的方式，顾名思义，就是通过一个函数来接收并返回另一个函数。我们可以在执行原始函数之前和之后，插入一些拦截相关的逻辑（例如提供拦截前和拦截后的钩子函数）。

### 代码实现思路
1. 定义一个名为 `intercept` 的高阶函数，接收原始函数 `fn` 作为参数。
2. 该高阶函数返回一个新的函数，新函数接收任意参数（如 `...args`）。
3. 在新函数的内部逻辑中：
   - **拦截前**：在调用原函数之前，先执行相应的打印或拦截逻辑。
   - **执行原函数**：通过 `fn.apply(this, args)` 的方式调用原始函数，并传入当前的上下文和参数，同时保存返回的结果。
   - **拦截后**：在函数调用之后，继续执行相关的打印或拦截逻辑。
   - **返回结果**：最终将原函数的执行结果 `result` 返回。

### 使用示例
假设我们有一个简单的 `add` 方法：
- 直接调用 `add(1, 2)` 只会输出计算结果。
- 如果使用高阶函数包裹，即调用 `intercept(add)(1, 2)`：
  - 首先会打印“拦截前”的相关参数。
  - 然后执行 `add` 方法并打印计算结果。
  - 最后打印“拦截后”的相关结果。
通过这种形式，我们成功实现了对函数执行前后的拦截与监听。

## 3. 方式二：使用 Proxy 代理对象实现拦截 *Content-[04:27]

### 核心原理
第二种方式是通过 `Proxy` 代理对象来实现。大家对 `Proxy` 应该比较熟悉，例如在 Vue3 中，我们广泛使用 `Proxy` 来拦截对象属性的获取和设置。实际上，**函数在 JavaScript 中也是对象**，因此同样可以通过 `Proxy` 代理对象的方式来进行拦截。

### 代码实现思路
1. 定义一个 `handler` 对象，在其中实现 `apply` 拦截器。
2. `apply` 方法会接收三个参数：
   - `target`：被拦截的原始函数。
   - `thisArg`：调用时的 `this` 上下文。
   - `argumentsList`：调用时传入的参数列表。
3. 在 `apply` 拦截器内部：
   - **拦截前**：执行相应的打印或拦截逻辑。
   - **执行原函数**：必须使用 `Reflect.apply(target, thisArg, argumentsList)` 的方式来执行原始函数，并保存返回结果。
   - **拦截后**：执行拦截后的打印或相关逻辑。
   - **返回结果**：将原函数的执行结果返回。
4. 创建代理函数：使用 `new Proxy(add, handler)`，将原始函数 `add` 和定义好的 `handler` 结合，生成一个新的代理函数。

### 使用示例
通过 `new Proxy` 创建代理函数后，直接调用该代理函数（例如传入参数 `1, 2`），即可自动触发 `handler` 中定义的 `apply` 拦截逻辑，从而完美实现对函数调用的拦截。

## AI 总结

本视频详细讲解了前端面试中的经典场景题——**如何拦截 JS 函数的执行**。核心解答分为两种主流方案：
1. **高阶函数方案**：通过闭包和函数包裹（如 `intercept`），在调用原函数（`fn.apply`）前后手动插入拦截逻辑，实现简单且兼容性好。
2. **Proxy 方案**：利用 ES6 的 `Proxy` 和 `Reflect` 特性，通过配置 `handler.apply` 拦截器来代理函数调用。这种方式更加优雅，也是 Vue3 等现代框架底层实现响应式的核心思想。

掌握这两种方式，不仅能应对面试中的场景题，还能加深对 JavaScript 函数本质、高阶函数以及 ES6 代理机制的理解。
