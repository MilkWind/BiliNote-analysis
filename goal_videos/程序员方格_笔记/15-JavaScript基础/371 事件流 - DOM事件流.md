## DOM事件流的三个阶段 *Content-[00:00]

DOM2 级事件规定的事件流包含三个明确的阶段，事件在这三个阶段中按照特定的顺序进行传播：

1\. **事件捕获阶段**：事件首先发生，从不具体的外层元素开始，向下传播到具体的目标元素（从 `window` 向下传播到目标元素）。
2\. **处于目标阶段**：事件到达目标元素，此时执行目标元素上绑定的事件处理函数。
3\. **事件冒泡阶段**：事件从具体的目标元素开始，向上传播回到不具体的外层元素（从目标元素向上传播到 `window`）。

## 代码演示与事件流顺序验证 *Content-[01:33]

为了直观理解事件流的传播顺序，可以通过代码为 DOM 树中的各个层级节点绑定事件来进行验证。

- **节点层级与获取方式**：
  - `window` 对象
  - `document` 对象
  - `<html>` 元素（通过 `document.documentElement` 获取）
  - `<body>` 元素（通过 `document.body` 获取）
  - `<div>` 目标元素

- **事件绑定规则**：
  - 为上述每个节点分别绑定捕获阶段和冒泡阶段的事件。
  - 使用 `addEventListener` 方法时，第三个参数设置为 `true` 表示在**捕获阶段**触发，设置为 `false` 表示在**冒泡阶段**触发。

- **打印结果与顺序验证**：
  当点击 `<div>` 元素时，控制台的打印顺序完美印证了事件流的三个阶段：
  - **捕获阶段（自上而下）**：`window` -> `document` -> `<html>` -> `<body>` -> `<div>`
  - **处于目标阶段**：到达 `<div>`。
  - **冒泡阶段（自下而上）**：`<div>` -> `<body>` -> `<html>` -> `document` -> `window`

## 目标元素的特殊触发机制 *Content-[05:39]

在观察代码打印结果时，会发现目标元素（如 `<div>`）的事件处理函数被触发了两次。这涉及到 W3C 标准与现代浏览器实现之间的差异：

- **W3C 标准规定**：事件捕获阶段不涉及目标元素，目标元素的事件只在“处于目标阶段”触发一次。
- **现代浏览器实际行为**：现代浏览器为了兼容性，会在捕获阶段和冒泡阶段都触发目标元素的事件。
- **最终结论**：如果目标元素同时绑定了捕获和冒泡事件，它会在捕获阶段触发一次，在冒泡阶段再触发一次，共计触发两次。

## 不冒泡的事件及替代方案 *Content-[07:34]

虽然所有事件都会经历捕获阶段和处于目标阶段，但并非所有事件都会经历冒泡阶段。

- **常见的不冒泡事件**：
  - `focus`：获取焦点事件。
  - `blur`：失去焦点事件。
  - `load`：资源加载完成事件。

- **支持冒泡的替代方案**：
  如果需要在事件委托等场景中使用冒泡机制，可以使用以下支持冒泡的替代事件：
  - 使用 `focusin` 替代 `focus`。
  - 使用 `focusout` 替代 `blur`。
