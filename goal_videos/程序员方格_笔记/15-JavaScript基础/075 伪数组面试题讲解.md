## 面试题代码执行现象 *Content-[00:00]

- **题目背景**：考察一个伪数组（类数组）对象在调用 `push` 方法后的执行结果。
- **初始状态**：
  - 对象具有 `length` 属性，初始值为 `2`。
  - 对象在索引 `2` 的位置值为 `3`，在索引 `3` 的位置值为 `4`。
  - 对象通过某种方式（如借用原型方法）拥有了 `push` 方法。
- **执行操作**：对该伪数组调用 `push(1, 2)`。
- **执行结果**：
  - `length` 属性的值变为 `4`。
  - 索引 `2` 的值由 `3` 变为了 `1`。
  - 索引 `3` 的值由 `4` 变为了 `2`。
- **核心疑问**：为什么 `push` 操作没有将 `1` 和 `2` 追加到对象后面，而是直接替换了索引 `2` 和 `3` 位置原有的值？

## 伪数组 push 方法的底层原理 *Content-[01:05]

- **方法来源**：伪数组本身并不是真正的 `Array` 实例，题目中是通过重写或借用 `Array.prototype.push` 使其具备 `push` 能力。
- **`push` 方法的底层执行逻辑**：
  1.  **读取长度**：调用 `push` 时，引擎会优先读取对象的 `length` 属性。
  2.  **添加元素**：在当前 `length` 值所对应的索引位置添加传入的元素。
  3.  **更新长度**：元素添加完毕后，`length` 属性自动加 `1`。
- **本题执行过程推演**：
  - 初始 `length` 为 `2`。
  - **添加第一个元素 `1`**：引擎在索引 `2` 的位置添加 `1`，即执行 `obj[2] = 1`。由于对象属性名会自动转为字符串，`obj["2"]` 被覆盖为 `1`（原值 `3` 被替换）。
  - **更新长度**：`length` 自动加 `1`，变为 `3`。
  - **添加第二个元素 `2`**：引擎在索引 `3` 的位置添加 `2`，即执行 `obj[3] = 2`。原值 `4` 被覆盖。
  - **再次更新长度**：`length` 再次自动加 `1`，最终变为 `4`。
- **结论**：正是因为 `push` 严格依赖 `length` 属性来决定插入位置，所以导致了原有属性值被覆盖，而不是在末尾追加。

## 伪数组的局限性与报错场景 *Content-[03:31]

- **本质区别**：伪数组（类数组）仅仅是在结构上模仿了数组（拥有 `length` 和数字索引），但它并不是真正的数组实例。
- **方法缺失**：伪数组没有继承 `Array.prototype` 上的方法。
- **报错示例**：
  - 如果尝试在伪数组上调用 `obj.shift()` 方法，由于对象本身不存在该方法。
  - JavaScript 会沿着原型链向上查找至 `Object.prototype`，依然找不到 `shift` 方法。
  - 最终引擎会抛出 `TypeError` 报错。
- **使用建议**：不能将伪数组直接当作真数组来使用，在调用数组特有方法前必须确保其具备该方法或已转换为真数组。

## 伪数组转换为真数组的陷阱 *Content-[04:10]

- **转换方法**：可以使用 `Array.from(obj)` 或扩展运算符 `[...obj]` 将伪数组转换为真数组。
- **意外结果**：
  - 使用 `Array.from(obj)` 转换后，打印出的数组结果为 `[undefined, undefined, 1, 2]`。
  - 前两个元素是 `undefined`，后两个元素才是 `push` 进去的 `1` 和 `2`。
- **原因深度解析**：
  - `Array.from` 在转换时，会首先读取对象的 `length` 属性。
  - 初始 `length` 为 `2`，`Array.from` 会认为该对象包含 `2` 个元素（即索引 `0` 和索引 `1`）。
  - 但是，该伪数组对象在索引 `0` 和 `1` 的位置并没有定义具体的值（存在空位 / empty）。
  - 因此，转换后的真数组前两个位置被填充为 `undefined`。
  - 接着，`Array.from` 继续读取索引 `2` 和 `3` 的值，获取到 `1` 和 `2`，并将其放置在数组的第 `3` 和第 `4` 个位置。
- **核心考点**：此现象深刻考察了开发者对伪数组 `length` 属性与索引映射关系的理解，`length` 的值并不一定代表实际拥有的元素个数，它只代表数组的“长度”预期。

## AI 总结

本视频详细解析了一道经典的前端伪数组面试题。核心知识点包括：
1. **`push` 原理**：数组的 `push` 方法底层是依赖 `length` 属性来决定元素插入位置的，因此伪数组调用 `push` 时，会直接在 `length` 对应的索引处覆盖原有值，并自动递增 `length`。
2. **伪数组局限**：伪数组不具备数组原型链上的方法（如 `shift`），强行调用会导致原型链查找失败并报错。
3. **转换陷阱**：使用 `Array.from` 转换伪数组时，会严格依据 `length` 属性来初始化数组长度。若 `length` 大于实际定义的索引属性，多出来的空位会被填充为 `undefined`。掌握这些底层逻辑有助于在面试中展现出对 JavaScript 对象与数组本质的深刻理解。
