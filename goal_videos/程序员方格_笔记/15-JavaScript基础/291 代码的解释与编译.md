- **垃圾回收与运行机制的重要性**
  - 对于前端开发而言，垃圾回收（Garbage Collection）和运行机制是极其重要的核心基础。

## 计算机组成与内存管理基础 *Content-[02:22]

- **计算机系统组成**
  - 理解垃圾回收前，需先了解计算机系统的两大组成部分：
    - **硬件系统**：包括主机、CPU、内存、外部设备（I/O）等。
    - **软件系统**：包括操作系统、程序语言处理系统、数据库管理系统以及各类应用程序。

- **内存的申请与释放机制**
  - 软件运行时需要加载到内存中，系统会自动为声明的变量分配相应的内存空间。
  - **低级语言（如 C/C++）**：开发者需要手动动态申请内存空间（根据 `int`、`string` 等不同数据类型分配不同大小的空间），使用完毕后还必须手动释放内存。
  - **高级语言（如 JS、Java）**：开发者无需手动管理内存空间的申请与释放。系统会自动处理，例如基本数据类型（`string`、`number` 等）会在栈（Stack）中自动申请一块连续的内存空间。

## JavaScript 的解释与编译 *Content-[05:04]

- **解释型语言的特性**
  - JavaScript 属于解释型语言（Interpreted Language），其核心运行特点是“边解释边执行”。
  
- **解释与编译的区别**
  - **编译型语言（如 Java）**：相当于提前准备好了一桌子菜，客人来了可以直接开吃。代码在执行前需要经历完整的编译过程。
  - **解释型语言（如 JS）**：相当于吃火锅，需要一边煮一边吃。代码在运行时才动态编译并执行。
  
- **机器语言的转换**
  - JS 作为高级语言，CPU 等硬件无法直接识别。
  - 必须在代码执行时，通过 JS 引擎将其转换为 CPU 能够理解和执行的机器语言（Machine Code）。

## JS 引擎的工作流程与 AST *Content-[07:01]

- **JS 引擎（JS Engine）的核心作用**
  - JS 引擎负责接收 JS 源码，并将其解释、转换为机器语言。
  - 核心过程涉及 **AST（Abstract Syntax Tree，抽象语法树）**，即将一种编程语言转换为另一种语言（或中间表示）的过程。

- **代码解析流程**
  - **词法分析（Lexical Analysis）与语法分析（Syntax Analysis）**：Parser（解析器）对源码进行分析，最终生成 AST 树。
  - 生成 AST 后，引擎可基于该树结构对代码进行后续的转换与处理。

- **执行与优化阶段**
  - **Interpreter（解释器）**：逐行读取代码并立即执行，生成 **Bytecode（字节码）**。字节码是一种中间码，计算机仍需进一步翻译才能执行。
  - **Compiler（编译器）**：读取完整的代码，进行深度优化处理，最终生成优化后的机器码（Optimized Code）。
  - **总结**：Interpreter 和 Compiler 协同工作，将源码转换为机器语言，两者的主要区别在于转换与优化的处理过程不同。

## 主流 JavaScript 引擎介绍 *Content-[11:32]

- **V8 引擎**
  - 由 Google 开发，使用 C++ 编写，完全开源。
  - 广泛应用于 Chrome 浏览器以及 Node.js 运行环境。
  
- **JavaScriptCore (JSC)**
  - 由 Apple 开源。
  - 主要用于 WebKit 内核的浏览器（如 Safari）。

- **SpiderMonkey**
  - 世界上第一款 JavaScript 引擎。
  - 早期用于 Netscape Navigator 浏览器，现主要用于 Mozilla Firefox。

- **V8 引擎的详细执行流程**
  - 获取 JS 源码。
  - 解析源码并抽象为 AST。
  - 通过解释器生成 Bytecode（字节码）。
  - 引入 **TurboFan**（优化编译器）对代码进行优化编译（Optimizing Compiler）。
  - 最终转化为高效的机器码交由 CPU 执行。
