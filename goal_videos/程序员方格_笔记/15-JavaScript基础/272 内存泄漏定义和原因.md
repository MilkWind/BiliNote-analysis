## 面试题介绍 *Content-[00:00]
在前端开发面试中，一道高频面试题是：“在前端开发时，哪些操作会造成内存泄漏？”
回答此题的核心在于彻底了解内存泄漏的情况，明确什么是内存泄漏，并找出导致内存泄漏的具体原因和代码操作。

## 内存泄漏的定义与影响 *Content-[01:27]
**定义**：
内存泄漏（Memory Leak）是指由于代码的错误或编写不当，导致某些不再使用的内存无法被垃圾回收（GC）机制回收，从而持续无效地占用内存资源。这里的“泄漏”并非指内存丢失，而是指无效的占用。

**影响**：
如果本应被回收的对象或不适当的代码导致内存占用过高且得不到回收，会使得可用内存越来越不足。这会严重影响程序效率和用户体验，导致用户遇到页面打不开、加载缓慢、卡顿等问题。

## 导致内存泄漏的常见原因及解决方案 *Content-[04:07]
内存泄漏的根本原因在于编写代码时的错误习惯。以下是导致内存泄漏的具体操作及修复方法：

### 1. 意外的全局变量 *Content-[04:19]
**原因**：
在声明变量时，未使用 `var`、`let` 或 `const` 等指定关键字，导致变量被隐式挂载到全局对象（如浏览器的 `window` 对象）中。由于全局对象的生命周期贯穿整个页面，这些变量会一直存在，无法被回收。此外，在非严格模式下直接使用 `this`（如 `this.arr = [...]`），`this` 会指向 `window`，同样会导致意外的全局变量。

**解决方案**：
- 始终显式使用 `var`、`let` 或 `const` 声明变量。
- 开启严格模式（`"use strict";`），防止 `this` 在非严格模式下意外指向全局对象。

### 2. 被遗忘的定时器和回调 *Content-[07:03]
**原因**：
使用 `setInterval`、`setTimeout` 或添加事件监听器后，在组件卸载或页面跳转时未正确清除。这会导致回调函数及其关联的数据无法释放，持续占用内存。

**解决方案**：
养成良好习惯，在组件卸载、页面跳转或销毁时，必须手动清除所有定时器和事件回调。

### 3. DOM 引用与事件监听未释放 *Content-[09:12]
**原因**：
- **DOM 引用残留**：在移除 DOM 节点后，仍然通过闭包、全局变量或缓存保留了对该 DOM 节点的引用。虽然 DOM 节点已从页面移除，但由于引用依然存在，垃圾回收器无法回收其占用的内存。
- **事件监听未移除**：DOM 节点上的事件监听器（如 `onclick`）未移除，导致 DOM 节点及关联数据无法释放。

**解决方案**：
- 移除 DOM 节点后，手动解除对其的引用（例如将变量置为 `null`）。
- 在组件卸载时，务必移除对应的事件监听器，做好“善后”工作。

### 4. 闭包 (Closure) 引用未释放 *Content-[12:33]
**原因**：
闭包会长期持有其外部函数的变量引用。如果闭包本身未被释放，或者在闭包中引用了不必要的大型数据（如大数组），会导致这些大型数据无法被垃圾回收，从而引发内存泄漏。

**解决方案**：
- 避免在闭包中引用不必要的大型数据。
- 在不需要时，手动解除引用（将变量赋值为 `null`）。

### 5. 未清理的 Map/Set 或缓存 *Content-[13:44]
**原因**：
使用 `Map`、`Set` 或自定义缓存对象时，如果没有设置过期机制或大小限制，会导致键值对（key）无限增长，数据无限积累，最终耗尽内存。

**解决方案**：
- 使用弱引用数据结构，如 `WeakMap` 或 `WeakSet`。
- 为缓存设置大小限制或数据过期时间（TTL）。

### 6. Iframe 未被释放 *Content-[14:17]
**原因**：
未释放的 `iframe` 可能不会被浏览器自动回收，尤其是在跨域场景下，内存泄漏的风险更高。

**解决方案**：
在移除 `iframe` 之前，先清空其内容（例如将 `src` 设置为 `'about:blank'`），然后再将其从 DOM 中移除。

### 7. 其他第三方库与订阅问题 *Content-[14:37]
**原因**：
- 引入的第三方库（如地图库）在页面跳转或组件卸载时未正确销毁和释放实例。
- 废弃的事件订阅（如发布-订阅模式中的订阅）未取消。

**解决方案**：
对于大型对象或第三方库实例，在不使用时必须调用其提供的销毁方法，或手动将其置空（`null`），确保不会发生内存泄漏。

## AI 总结
内存泄漏是前端开发中常见的性能隐患，其本质是代码编写不当导致不再使用的内存无法被垃圾回收机制释放。常见的引发原因包括：意外的全局变量、未清除的定时器与事件监听、残留的 DOM 与闭包引用、无限增长的缓存以及未销毁的 Iframe 和第三方库实例。在面试和实际开发中，开发者应养成良好的编码习惯，注重组件生命周期中的“善后”清理工作，合理使用弱引用和严格模式，从而有效避免内存泄漏，提升页面性能与用户体验。
