## 字符串提取方法对比 *Content-[00:00]

从字符串中提取特定片段是字符串操作中最高频的场景之一。JavaScript 历史上提供了三个类似的方法，了解它们的差异对编写严谨的代码至关重要。

- `slice(start, end)`
  - **参数规则**：接收开始和结束索引，是一个**左闭右开**区间（包含开始索引，不包含结束索引）。
  - **负数支持**：强大之处在于支持负数索引，负数表示从字符串末尾倒数计算。
  - **应用场景**：处理去除最后一位、获取后缀名等场景非常方便。
- `substring(start, end)`
  - **正数处理**：与 `slice` 基本一致。
  - **负数处理**：会将所有的负数参数强制转换成 `0`。
  - **容错机制**：如果第一个参数大于第二个参数，会自动交换这两个参数的位置。
  - **缺点**：这种看似智能的机制有时会掩盖代码中的逻辑错误，因此不如 `slice` 严谨。
- `substr(start, length)`
  - **参数差异**：第二个参数表示的是**截取长度**，而不是结束索引。
  - **状态**：已被标记为废弃（Legacy）。虽然浏览器为了兼容仍然支持，但在新代码中应绝对避免使用。

**核心建议**：在项目中统一使用 `slice` 方法。它的参数定义最符合直觉，对负数的支持最完善，能够满足绝大多数子串提取的需求。

## 数据清洗与格式化操作 *Content-[02:53]

在数据清洗和格式化场景中，经常需要用到清理、重复和填充的方法。

### 1\. 空白字符清理
- `trim()`：移除字符串两端的所有空白字符（包括空格、制表符和换行符）。这是表单数据处理的标准步骤，可防止用户误输入空格影响后端逻辑。
- `trimStart()` / `trimEnd()`：ES2019 进一步标准化的方法，允许单独移除左侧或右侧的空白。它们有 `trimLeft` 和 `trimRight` 这样的别名，但推荐使用标准名称以保持语义的准确性。

### 2\. 字符串重复
- `repeat(count)`：接受一个整数参数，返回将原字符串重复指定次数的新字符串。
  - **细节**：如果传入小数，该方法会向下取整。
  - **应用场景**：文本格式化，如生成固定长度的分割线，或生成特定深度的代码缩进。

### 3\. 字符串填充
ES2017 引入了两个处理字符填充场景的方法，极大简化了格式化输出的逻辑，消除了过去手动计算长度并循环拼接的繁琐代码。
- `padStart(targetLength, padString)`：在字符串开头填充，直到达到指定的目标长度。
  - 第一个参数是目标长度，第二个参数是用来填充的字符。
  - 如果原字符串长度已等于或超过目标长度，则不进行任何处理。
  - 如果未指定填充字符，默认使用空格。
  - **应用场景**：编号补零、时间格式化（如将 `9:5` 格式化为标准的 `09:05`，确保无论数字是几位都能输出两位数格式）。
- `padEnd(targetLength, padString)`：在字符串末尾进行填充，参数逻辑与 `padStart` 完全一致。
  - **应用场景**：命令行工具或日志输出中的文本对齐，确保名称占据固定宽度，让后续列（如价格）能够整齐排列。

## 字符串大小写转换 *Content-[06:47]

字符串大小写转换是数据标准化的基础操作。

- 基本方法：`toLowerCase()` 和 `toUpperCase()`
  - 将字符串转换成全小写或全大写。
  - **注意**：返回的是**新字符串**，原字符串保持原样（字符串的不可变性）。
- 国际化方法：`toLocaleLowerCase()` 和 `toLocaleUpperCase()`
  - 区别在于对特定语言环境的支持。在绝大多数西方语言中结果一样，但对于土耳其语等有特定大小写映射规则的语言（如带点的 `I` 和不带点的 `i` 是不同的），需要使用此方法。
  - **建议**：除非应用涉及特定语言的国际化处理，否则通常使用基本方法即可。

**核心应用场景**：
1. **忽略大小写比较**：在输入验证码或搜索关键词时，将输入值和目标值统一转换成小写或大写，然后再进行全等比较。
2. **首字母大写**：通过组合使用 `charAt()`（或 `at()`）、`toUpperCase()` 和 `slice()` 等 API 轻松实现。

## 字符串搜索方法 *Content-[08:38]

String 提供了两类搜索方法：一类返回位置索引，另一类返回布尔值。

### 1\. 返回位置索引的方法
- `indexOf(searchValue, fromIndex)`
  - 从字符串头部开始查找，返回子串**第一次**出现的索引位置。如果没找到，返回 `-1`。
  - 第二个参数表示从哪个索引开始向后查找，利用此特性可跳过前面的匹配项。
  - **进阶用法**：利用第二个参数构建循环，每次找到匹配项后将下一次搜索起始位置设为当前匹配位置加一，可遍历出所有匹配坐标（适用于文本高亮或关键词统计）。
- `lastIndexOf(searchValue, fromIndex)`
  - 从字符串尾部开始向前查找。
  - **注意**：虽然查找方向是反的，但返回的索引值依然是**基于 0 的正向索引**。
  - 第二个参数表示从哪个索引开始向前查找，即限制查找范围的右边界。

### 2\. 返回布尔值的方法（ES6 引入）
ES6 引入的新方法不再返回索引，而是返回布尔值，让语义判断更加清晰。

- `includes(searchString, position)`
  - 判断字符串是否包含子串。
  - 替代了 ES6 之前 `indexOf(searchString) !== -1` 这种可读性较差的写法，代码意图一目了然。
  - 支持第二个参数，表示从指定的搜索起始位置开始搜索。
- `startsWith(searchString, position)`
  - 检查字符串是否以特定的子串开头。
  - **应用场景**：判断 URL 协议（如 `https`）或路径前缀。
  - 第二个参数可指定起始位置，实际上相当于检查任意位置是否是某个子串的开头。
- `endsWith(searchString, length)`
  - 检查字符串是否以特定的子串结尾。
  - **应用场景**：判断文件的扩展名（如是否以 `.jpg` 结尾）。
  - **注意**：第二个参数含义略有不同，它表示作为**结束位置的索引**（或者理解为在检查前将字符串截断成多长）。
