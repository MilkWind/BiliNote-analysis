## typeof null 现象解析 *Content-[00:00]
- 在 JavaScript 中，当我们使用 `typeof` 操作符检测 `null` 值时，理所当然地认为应该返回 `null` 类型。
- 因为 `null` 属于基本数据类型，且它的值就是它本身。
- 但事实是，`typeof null` 返回的结果是 `object`。
- 这个现象让人理解起来有些费解，因为 `null` 本来是基本数据类型，但 `typeof` 却返回了 `object`，容易让人误以为它是引用类型。

## 逻辑角度解释 *Content-[01:18]
- 从逻辑角度来看，`null` 本身表示的是一个**空对象指针**。
- 它代表的其实就是一个空对象。
- 因此，当我们使用 `typeof` 操作符进行检测时，由于空对象也是对象，返回 `object` 在逻辑上是可以理解的。

## 底层存储角度解释（根本原因） *Content-[02:15]
- 从 JS 底层存储变量的角度来看，这是返回 `object` 的根本原因。
- JS 在底层存储变量时，可以分为两部分：
  - 一部分是**数据类型的标签**。
  - 另一部分是**实际的数据**在内存当中的存储。
- 在 JS 中，二进制的**前三位**存储的就是类型标签，一共有五个基本标识：
  - `000`：代表对象（object）
  - `010`：代表浮点数（float）
  - `100`：代表字符串（string）
  - `110`：代表布尔值（boolean）
  - `001`：代表整数（integer）
- 在 JS 中，如果二进制的**前三位都为零**，它会被判断为 `object` 类型。
- 而 `null` 的二进制表示**全为零**（即它的标签和实际数据都是 0）。
- 既然全为零，那么它的前三位必然也是 `000`。
- 因此，在进行 `typeof` 检测时，系统将其识别为 `object` 类型。

## ES6 修复提案及被拒原因 *Content-[04:57]
- 在 ES6 时期，曾经有一些提案想要为这个历史遗留问题“平反”，试图将 `typeof null` 的结果纠正为 `null`。
- 但最终该提案被拒绝了，保持了现在 `typeof null` 返回 `object` 的现状。
- **被拒原因**：
  - 担心修改后会引发其他无法预知的问题。
  - JS 从诞生至今已经存在了很多年，全世界使用 JS 的地方非常多。
  - 如果贸然将 `typeof null` 改为 `null`，可能会引发大量无法估算的兼容性或破坏性问题。
- 因此，可以将这个现象理解为 JS 设计当中的一个小小的历史 bug。
