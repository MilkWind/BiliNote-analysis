## class 的定义与引入目的 *Content-[01:04]
- **标准引入**：`class` 是 JavaScript 在 ES6（ES2015）标准中引入的一种新语法。
- **核心目的**：提供一种更清晰、更简洁的方式来定义类，使开发者能够像在传统面向对象语言中那样，方便地描述一类事物的“蓝图”。
- **主要优势**：
  - 使得基于蓝图创建新对象变得直观。
  - 让不同蓝图之间建立继承关系变得更加清晰。
  - 显著提升了代码的可读性和简洁性，使 JS 的面向对象编程更加友好。

## ES6 之前实现面向对象的痛点 *Content-[02:05]
在 ES6 之前，JS 主要通过构造函数结合原型链来实现对象的复用和继承。这种方式虽然强大，但存在以下显著痛点：
- **语法分散且学习曲线高**：需要定义构造函数，然后在构造函数的 `prototype` 属性上挂载方法。这种分散的语法对习惯了传统面向对象语言的开发者来说较为困惑。
- **模拟方式不直观**：旧语法模拟类和继承的方式不够直观易懂。
- **私有化实现困难**：在旧语法下实现真正意义上的私有属性和私有方法非常困难，通常需要借助闭包（Closure）等模式来模拟，增加了代码的复杂度。
- **代码可读性差**：由于需要大量的原型链操作和函数嵌套来模拟复杂结构，导致旧语法下的代码结构往往不够清晰，给后续维护带来不便。

## class 的基础用法详解 *Content-[03:34]
- **定义类**：使用 `class` 关键字后跟类名（如 `class MyClass`）。
- **构造函数**：类内部包含一个特殊的 `constructor` 方法。当使用 `new` 关键字创建类的实例时，该方法会被自动调用。在构造函数中，使用 `this` 关键字来定义实例的属性。
- **实例方法**：在构造函数外部定义的方法即为实例方法，它们最终会被挂载到类的原型（`prototype`）上。
- **静态方法**：使用 `static` 关键字定义的方法为静态方法，它们直接关联到类本身，而不是类的实例。

**代码示例与调用规则**：
```javascript
class MyClass {
  constructor(value) {
    this.property = value; // 实例属性
  }
  
  myMethod() {
    console.log(this.property); // 实例方法，可访问实例属性
  }
  
  static staticMethod() {
    console.log("Static method called"); // 静态方法
  }
}
```
- **实例化**：使用 `const instance = new MyClass('Hello')` 创建实例，`'Hello'` 会赋值给 `instance.property`。
- **调用实例方法**：通过实例调用 `instance.myMethod()`，输出 `Hello`。
- **调用静态方法**：**必须**通过类名本身调用，即 `MyClass.staticMethod()`。如果尝试使用实例调用（如 `instance.staticMethod()`），会导致运行时错误。

## class 的继承机制 *Content-[07:01]
`class` 语法极大地简化了继承的实现：
- **声明继承**：使用 `extends` 关键字声明子类继承自哪个父类。
- **调用父类构造函数**：在子类的 `constructor` 中，必须第一行调用 `super()` 来执行父类的构造函数，并传入父类所需的参数。**注意：在调用 `super()` 之前，不能使用 `this` 关键字。**
- **调用父类方法**：子类可以通过 `super.methodName()` 来调用被子类重写过的父类方法。
- **方法重写（Override）**：子类可以定义与父类同名的方法，从而覆盖父类的行为，实现定制化逻辑。

**继承代码示例**：
```javascript
class BaseClass {
  constructor(name) {
    this.name = name;
  }
  greet() {
    console.log(`Hello ${this.name}`);
  }
}

class DerivedClass extends BaseClass {
  constructor(name, age) {
    super(name); // 必须在第一行调用 super 初始化父类属性
    this.age = age; // 子类特有属性
  }
  
  greet() {
    super.greet(); // 调用父类的原始方法
    console.log(`I'm ${this.age} years old`); // 子类特有逻辑
  }
}

const derivedInstance = new DerivedClass('Alice', 30);
derivedInstance.greet(); 
// 输出: 
// Hello Alice
// I'm 30 years old
```

## class 的本质与核心细节 *Content-[10:36]
- **本质是语法糖**：`class` 并没有引入一套全新的、独立的面向对象机制。它本质上仍然是基于 JavaScript 原型链的实现，仅仅是提供了一种更高级、更友好的语法来封装和使用现有的原型链特性。因此，它是一个名副其实的“语法糖”。
- **与传统语言的区别**：不同于 Java 或 C++ 等语言中编译时期的 `class` 概念，JS 的 `class` 定义实际上就是一个构造函数。在 `class` 内部定义的所有实例方法，最终都会被挂载到这个构造函数的 `prototype` 属性上面。
- **核心细节注意**：
  - **声明不会提升**：与函数声明不同，`class` 的声明不会被提升到当前作用域的顶部。因此，在使用一个类之前，必须确保它已经被声明（行为类似于函数表达式）。
  - **默认严格模式**：`class` 主体内部的代码默认处于严格模式（`"use strict"`）下，无需显式添加。这意味着在类内部不能随意使用未声明的变量，且 `this` 的指向在实例方法和静态方法中有明确的规定，有助于编写更加健壮、规范的代码。

## 核心要点回顾 *Content-[12:41]
- `class` 是 ES6 基于现有的原型链机制提供的一个语法糖，没有引入全新的底层逻辑。
- 其主要价值在于提供了一种更符合传统面向对象习惯的语法形式，让 JS 的 OOP 变得更加清晰和简洁。
- 极大地简化了定义类、添加方法以及实现类之间继承的操作步骤。
- **核心认知**：无论语法表面多么华丽，其底层实现依旧是 JavaScript 强大而灵活的原型链机制。
