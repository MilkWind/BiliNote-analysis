## 引言与核心问题 *Content-[00:01]

在日常的前端开发中，开发者经常会遇到以下三个关于变量与内存的困惑：
1\. **变量赋值相互影响**：为什么有时候把变量 `b` 赋值给 `a` 后，改变 `a` 会导致 `b` 也跟着变，而有时候它们又各自独立、互不影响？
2\. **对象传参机制**：当把一个对象作为参数传递给函数时，函数内部到底对这个对象做了什么？
3\. **const 修改对象**：为什么用 `const` 声明了一个对象后，依然可以修改它的属性？

这些问题的答案都指向了 JavaScript 内存管理的一个核心基石：**值类型与引用类型**。

## 内存存储机制：值类型与引用类型 *Content-[00:57]

从内存的角度来看，JavaScript 中所有的数据都会被归为两大类：

### 值类型（原始类型）
值类型具有以下三个核心特点：
- **存储内容**：变量直接存储数据的值本身。
- **赋值行为**：将一个值类型变量赋值给另一个变量时，发生的是一次**值的拷贝**。
- **存储位置**：数据通常被存放在内存的**栈（Stack）** 中。
- **包含类型**：共 7 种，分别是 `String`、`Number`、`Boolean`、`Null`、`Undefined`、`Symbol` 以及 `BigInt`。

### 引用类型
引用类型与值类型相对，其特点如下：
- **存储内容**：变量里存储的不是数据本身，而是一个**内存地址**（称为引用）。
- **赋值行为**：进行赋值操作时，拷贝的仅仅是这个**引用（地址）**。
- **存储位置**：数据实体本身被存放在内存的**堆（Heap）** 区域。
- **包含类型**：范围更广，包括 `Object`、`Array`、`Function` 以及所有其他的对象实例。

## 值类型赋值行为与内存图拆解 *Content-[03:08]

通过具体代码和内存图来拆解值类型的赋值行为：

```javascript
let a = 100;
let b = a;
a = 200;
```

**内存图逐步拆解：**
1. 执行 `let a = 100`：JavaScript 在栈内存中为 `a` 开辟一个空间，并将 `100` 存入。
2. 执行 `let b = a`：由于 `a` 是值类型，此处发生**值的拷贝**。系统在栈中为 `b` 开辟一个全新的空间，并将 `a` 的值 `100` 复制一份放进去。此时 `a` 和 `b` 是两个完全独立的变量，只是值恰好相同。
3. 执行 `a = 200`：直接修改变量 `a` 所在的内存空间的值，将其从 `100` 更新为 `200`。这个过程与变量 `b` 没有任何关系，`b` 的值依然是 `100`。

**结论**：值类型的复制行为是“赋值即拷贝，拷贝后互不干扰”。最终 `a` 的值为 `200`，`b` 的值为 `100`。

## 引用类型赋值行为与内存图拆解 *Content-[05:19]

引用类型的赋值行为是理解变量相互影响的关键：

```javascript
let obj1 = { name: 'Alice' };
let obj2 = obj1;
obj1.name = 'Bob';
```

**内存图逐步拆解：**
1. 执行 `let obj1 = { name: 'Alice' }`：对象是引用类型，存储分为两部分。对象实体 `{ name: 'Alice' }` 被创建在**堆内存**中（假设地址为 `0x101`）；变量 `obj1` 被创建在**栈内存**中，不存对象本身，而是存储堆中的地址 `0x101`。
2. 执行 `let obj2 = obj1`：由于是引用类型，发生**引用的拷贝**。系统在栈中为 `obj2` 开辟新空间，并将 `obj1` 存储的地址 `0x101` 复制给 `obj2`。此时 `obj1` 和 `obj2` 就像两把钥匙，指向堆内存中的同一个对象。
3. 执行 `obj1.name = 'Bob'`：通过 `obj1` 存储的地址找到堆内存中的对象，并修改其 `name` 属性。因为 `obj1` 和 `obj2` 指向同一个对象，所以通过 `obj2.name` 访问时，看到的也是修改后的 `'Bob'`。

**结论**：引用类型赋值拷贝的是地址。最终 `obj1.name` 和 `obj2.name` 输出的都是 `'Bob'`。

## 核心考点一：函数参数传递机制 *Content-[08:32]

在面试和实际开发中，函数参数的传递机制是高频考点。

**核心结论**：JavaScript 永远是**按值传递**的。
- 对于值类型：传递的是**值的副本**。
- 对于引用类型：传递的是**引用的副本**。

**代码示例分析：**
```javascript
function modify(object) {
  object.name = 'modify'; // 操作 1
  object = { name: 'new object' }; // 操作 2
}

let myObject = { name: 'Alice' };
modify(myObject);
```

**执行过程解析：**
1. 当 `myObject` 传入函数时，发生了一次引用的拷贝。函数内的参数 `object` 和外部的 `myObject` 都指向堆内存中的同一地址。
2. **操作 1** (`object.name = 'modify'`)：通过函数内的引用修改了公共对象的属性，因此这个修改会同步影响外部的 `myObject`。
3. **操作 2** (`object = { name: 'new object' }`)：让函数内部的 `object` 变量指向一个全新的对象（在堆中创建新对象并赋新地址）。这一步**彻底切断**了函数内的 `object` 和外部 `myObject` 的联系。此后 `object` 指向新对象，`myObject` 仍指向旧对象。

**最终结果**：`myObject.name` 的值为 `'modify'`，函数内部后续的重新赋值与外部变量无关。

## 核心考点二：const 声明对象的修改原理 *Content-[11:38]

**核心原理**：`const` 保证的是变量所存储的**内容（即内存地址）** 不可变。
- 对于引用类型，变量存储的是一个地址。`const` 只能保证这个变量永远指向同一个地址，**不能保证**地址指向的对象内部属性不可修改。

**代码表现：**
```javascript
const user = { name: 'Alice' };
user.name = 'Bob'; // 合法：没有改变 user 变量里存的地址
user = { name: 'Charlie' }; // 报错：试图改变 user 变量本身存储的地址，抛出 TypeError
```

## 核心考点三：全等运算符的比较规则 *Content-[12:48]

全等运算符 `===` 在比较不同类型时，行为存在本质差异：

- **值类型**：比较的是**值**是否相等。
  - 示例：`100 === 100` 结果为 `true`。
- **引用类型**：比较的是**引用（内存地址）** 是否相等。
  - 示例 1：`{} === {}` 结果为 `false`。虽然两个空对象看起来一样，但它们在堆内存中是两个独立的对象，拥有不同的地址。
  - 示例 2：`let objA = {}; let objB = objA; objA === objB` 结果为 `true`。因为此时它们存储了完全相同的地址，指向同一个对象。

## 课程总结 *Content-[14:01]

1\. **数据类型分类**：JavaScript 的数据类型分为值类型和引用类型。值类型存的是值本身，而引用类型存的是一个内存地址。
2\. **赋值操作差异**：在进行赋值操作时，值类型会完整地拷贝一份值，而引用类型只会拷贝那个地址，这就导致了它们后续行为的巨大差异。
3\. **函数传参机制**：在函数传参时，JavaScript 永远是按值传递的。对于引用类型传递的是引用的副本，这意味着在函数内部可以修改对象属性，但不能通过重新赋值来影响外部变量本身。
