## 函数组合 *Content-[01:01]

函数组合（Function Composition）是前端面试中关于函数式编程的重要考点。它是一种将多个函数像乐高积木一样链式连接起来，从而创建一个新函数的通用技术。

### 核心思想与优势

函数组合的核心思想是：**前一个函数的输出会作为下一个函数的输入**，以此形成一个数据处理的链条。

使用函数组合主要有以下三个优势：
1\. **提高可读性**：将复杂的业务逻辑分解为单一职责、易于理解的小函数，并通过组合将它们连接，能够清晰地表达数据处理流程，让人一眼看出数据经过了哪些步骤。
2\. **增强可维护性**：参与组合的每个小函数都是独立的单元，职责明确且单一。修改或调试特定功能时只需关注对应的小函数，不会影响其他部分，测试也变得更加方便。
3\. **提高可复用性**：细粒度、独立的函数非常容易在不同的业务场景下被重复使用。通过组合这些基础函数，可以灵活构建出各种新的复杂功能，无需从头编写代码。

### 实际应用与经典实现

函数组合并非 JavaScript 内置的特定 API，而是一种函数式编程模式或实现技巧。经典的实现方式通常通过高阶函数来完成，最常见的是 `compose` 和 `pipe`（有时也叫 `flow`）：
- **`compose`**：从右向左依次执行组合函数。
- **`pipe` / `flow`**：从左向右执行函数，更符合人类的阅读习惯（例如 `lodash` 中的 `flow`）。

#### `compose` 的代码实现解析

`compose` 作为一个高阶函数，接收多个函数作为参数，并返回一个新的组合函数。

```javascript
function compose(...fns) {
  // 边缘情况处理：如果没有参数或只有一个函数，直接返回
  if (fns.length === 0) return arg => arg;
  if (fns.length === 1) return fns[0];
  
  // 核心逻辑：使用 reduce 从右向左遍历
  return fns.reduce((a, b) => {
    // 返回一个新的函数，接收任意参数
    return (...args) => a(b(...args));
  });
}
```
- **执行流程**：`reduce` 默认从右向左遍历数组。`a` 代表当前累积的组合函数，`b` 代表正在处理的函数。回调函数返回一个新函数，该函数接收 `...args`，先将其传递给 `b` 执行，再将 `b` 的执行结果传递给 `a` 继续执行。

#### 使用示例

假设有三个基础函数：`add1`（加1）、`multiply2`（乘2）、`subtract3`（减3）。

```javascript
// 按照 subtract3, multiply2, add1 的顺序传入
const processValue = compose(subtract3, multiply2, add1);

// 传入初始值 5
console.log(processValue(5)); // 输出 9
```
**执行步骤解析**（因为 `compose` 从右向左执行）：
1. 最先执行 `add1(5)`，结果为 `6`。
2. 将 `6` 传入 `multiply2(6)`，结果为 `12`。
3. 将 `12` 传入 `subtract3(12)`，最终结果为 `9`。

### 注意事项

1\. **函数签名匹配**：函数组合能顺利工作的前提是，前一个函数的输出类型必须与后一个函数的输入类型兼容。类型不匹配可能导致运行时错误。
2\. **错误处理**：在组合链条中，如果某个环节抛出错误，如何优雅地中断流程并上抛或捕获错误，需要提前设计。简单的 `compose` 实现不包含内置的错误处理机制。

## 函数记忆化 *Content-[09:35]

函数记忆化（Memoization）是另一种非常实用的优化技术，核心在于通过缓存来提升性能。

### 核心思想与优势

函数记忆化的核心是**缓存函数调用的结果**。当带有记忆化功能的函数被调用时，如果传入的参数与之前缓存过的某次调用完全相同，它就不会重新执行计算逻辑，而是直接返回缓存的结果。

- **显著提升性能**：对于计算量大、耗时长的函数，特别是存在大量重复子问题计算的场景（如递归计算），记忆化可以大幅减少重复计算的时间。
- **减少资源消耗**：避免重复计算，从而节省宝贵的 CPU 周期和其他系统资源。

### 实现原理与代码解析

记忆化通常通过高阶函数实现，经典命名为 `memoize`。它接收原始函数作为参数，返回一个具有记忆能力的新函数。

#### `memoize` 的基础实现

```javascript
function memoize(fn) {
  // 利用闭包特性，维护一个缓存对象
  const cache = {}; 
  
  return function(...args) {
    // 1. 生成缓存 key
    // 单参数直接用值，多参数使用 JSON.stringify 转换
    const key = args.length === 1 ? args[0] : JSON.stringify(args);
    
    // 2. 检查缓存
    if (cache.hasOwnProperty(key)) {
      console.log(`Fetching from cache for key: ${key}`);
      return cache[key]; // 缓存命中，直接返回
    }
    
    // 3. 缓存未命中，执行原始计算
    console.log(`Calculating for key: ${key}`);
    // 使用 apply 确保 this 指向和参数传递正确
    const result = fn.apply(this, args); 
    
    // 4. 存入缓存并返回
    cache[key] = result;
    return result;
  };
}
```

**关键点解析**：
- **闭包**：`cache` 对象通过闭包一直存在于返回的新函数的作用域链中。
- **Key 的生成**：这是最关键的一步。基础实现中使用 `JSON.stringify`，但对于复杂参数类型（如对象、数组顺序不同、函数等），这种方法存在局限性或效率不高。生产级别的库（如 `lodash` 或 `reselect`）会有更复杂的 key 生成策略。
- **`this` 指向**：使用 `fn.apply(this, args)` 调用原函数，以正确处理上下文和参数。

### 使用示例：优化斐波那契数列

朴素的递归实现斐波那契数列（$F(n) = F(n-1) + F(n-2)$）存在大量的重复计算。例如计算 `fib(5)` 时，`fib(3)` 会被重复计算多次，导致效率极低。

```javascript
// 原始递归函数
function fib(n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}

// 使用 memoize 包装
const memoFib = memoize(fib);

console.log(memoFib(10)); // 第一次调用，计算并缓存 0-10 的结果
console.log(memoFib(10)); // 第二次调用，瞬间从缓存返回 55，无重复计算
console.log(memoFib(15)); // 调用新参数，计算并缓存涉及的新子结果
console.log(memoFib(10)); // 再次调用 10，直接命中缓存
```

### 注意事项

1\. **缓存结构与策略**：需要考虑使用简单的 JS 对象还是 `Map`（`Map` 允许任意类型作为 key，包括对象引用）。如果函数被频繁调用且参数多样，缓存可能会消耗大量内存。需考虑何时清理内存（如使用 LRU 缓存淘汰策略），避免内存泄漏。
2\. **Key 生成的健壮性**：必须保证相同的输入总是生成相同的 key。对于原始类型参数，简单的 `JSON.stringify` 不够健壮。
3\. **仅限纯函数**：记忆化必须且只能对**纯函数**使用。纯函数要求相同输入总返回相同输出，且无副作用。如果函数有副作用（如修改全局变量、网络请求、DOM 操作），使用记忆化会导致这些副作用只在第一次调用时发生，后续调用被跳过，从而产生意外行为。

## 总结与面试建议 *Content-[21:02]

- **函数组合**：将多个函数链式连接，旨在提高代码的可读性、可维护性和可复用性。
- **函数记忆化**：通过缓存函数结果来提升计算性能并减少资源消耗。
- **面试考察点**：面试官通常会结合实际场景，考察你如何设计和实现 `compose` 或 `memoize`，或者询问在什么情况下需要使用它们以及相关的注意事项。深入理解它们的内部原理和适用范围是应对面试的关键。
