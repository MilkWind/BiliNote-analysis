## 背景与问题引入 *Content-[00:00]

- **JS 的 Number 类型限制**：
  - JavaScript 中的 `Number` 类型使用的是 IEEE 754 双精度浮点数。
  - 其最大安全整数为 $2^{53}-1$（即 9007199254740991，约 9007 万亿）。
- **常见业务痛点**：
  - **超过最大值**：当数字规模超过 $2^{53}-1$ 时，无法准确表示。
  - **精度丢失**：在服务端返回大数字，或前端进行数学计算时，容易出现精度丢失，导致计算结果与预期不符。
- **面试核心问题**：前端该如何更好地处理超过 `Number` 最大值的大数计算与精度问题？

## 解决方案一：使用 BigInt *Content-[01:29]

- **基本概念**：
  - 在 ES2020 标准中，JavaScript 引入了 `BigInt` 数据类型。
  - 它专门用于表达大于 $2^{53}-1$ 的任意精度的整数。
- **使用方法**：
  - **字面量方式**：在数字末尾添加后缀 `n`。
    ```javascript
    const biggerNumber = 12345678901234567890n;
    ```
  - **构造函数方式**：使用 `BigInt()` 函数并传入数字或字符串。
    ```javascript
    const biggerNumber = BigInt("12345678901234567890");
    ```
- **运算支持**：
  - `BigInt` 支持常规的数学运算（如加法、减法等），可以顺利完成大数之间的加和计算，不会像 `Number` 那样报错或丢失精度。
- **⚠️ 注意事项**：
  - `BigInt` **不能**与普通的 `Number` 类型进行混合计算。如果强行混合运算，JavaScript 会抛出类型错误（TypeError）。

## 解决方案二：使用第三方库 *Content-[03:45]

- **适用场景**：
  - 需要进行更复杂的数学计算（如包含小数/浮点数的运算）。
  - 需要兼容不支持 `BigInt` 的旧版浏览器。
- **推荐第三方库**：
  - **bignumber.js**：功能强大，支持任意精度的十进制运算（包含小数）。
  - **big.js**：一个轻量级的大数运算库，适合对包体积有要求的项目。
- **代码示例（以 bignumber.js 为例）**：
  ```javascript
  import BigNumber from 'bignumber.js';

  // 实例化大数对象
  const x = new BigNumber("12345678901234567890.123");
  const y = new BigNumber("98765432109876543210.456");
  
  // 调用 plus 方法进行高精度相加
  const result = x.plus(y);
  
  // 输出结果
  console.log(result.toString()); 
  ```

## AI 总结

在前端开发中，处理超过 JavaScript `Number` 最大安全整数（$2^{53}-1$）的大数问题时，主要有两种解决方案：
1. **原生方案**：使用 ES2020 引入的 `BigInt`。它适合处理超大整数，语法简洁，但需注意它不能与 `Number` 混合计算，且不支持小数运算。
2. **第三方库方案**：使用 `bignumber.js` 或 `big.js` 等库。它们不仅支持超大整数，还支持高精度的小数运算，并且具有良好的浏览器兼容性，是处理复杂金融计算或旧项目兼容时的首选。
