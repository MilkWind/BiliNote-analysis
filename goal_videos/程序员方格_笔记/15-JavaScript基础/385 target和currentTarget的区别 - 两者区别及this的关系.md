## this、target 与 currentTarget 的基本概念 *Content-[00:00]

在事件处理函数中，理解 `this`、`target` 和 `currentTarget` 的指向是前端开发的核心基础。

- **`this` 与 `currentTarget` 的关系**：
  - 事件处理函数中的 `this` 始终等于 `currentTarget`。
  - 基础规则：“谁调用指向谁，谁绑定的事件指向谁”。

- **核心概念定义**：
  - **`currentTarget`**：事件的监听者，即**绑定事件**的元素。
  - **`target`**：真正的事件触发者，即**触发事件**的元素。

- **代码示例分析**：
  - 假设给 `UL` 元素添加了点击事件，内部包含多个 `LI` 子元素。
  - 当用户点击 `LI` 时：
    - `e.target` 指向 `LI`（真正被点击触发的元素）。
    - `e.currentTarget` 指向 `UL`（事件监听者）。
    - `this` 指向 `UL`（因为 `this` 始终等于 `currentTarget`）。
  - 此时，`e.target` 和 `e.currentTarget` 不相等（返回 `false`），但 `this` 和 `e.currentTarget` 是完全相等的。`this` 并不会和事件的真正触发者（`target`）相等。

## target 与 this 相等的条件 *Content-[01:41]

- **核心疑问**：`e.target` 和事件处理函数中的 `this` 一定相等吗？
- **答案**：不一定。

- **相等的特定条件**：
  - 当**没有嵌套元素**，即事件流处于**目标阶段**时，两者才会相等。
  - **目标阶段**的定义：触发事件的元素正好就是绑定事件的元素。
  - 在这种情况下，`this`、`e.target` 以及 `e.currentTarget` 三者指向完全相同。

## target 与 currentTarget 的相同点 *Content-[02:53]

尽管两者在大多数情况下指向不同，但它们也存在以下相同点：

1. **事件流的目标阶段**：
   - 在事件流的目标阶段，两者的指向完全相同（即触发事件的元素就是绑定事件的元素）。
2. **获取方式与作用**：
   - 都能通过事件对象（Event Object）获取。
   - 都用于定位事件相关的 DOM 元素。

## target 与 currentTarget 的核心区别 *Content-[03:58]

为了更清晰地理解两者的差异，可以从以下四个维度进行对比：

1\. **核心角色**
- **`target`**：事件的真正触发者。谁被点击或者操作了，就是谁。
- **`currentTarget`**：事件的监听者。谁绑定了事件，就是谁。

2\. **指向稳定性**
- **`target`**：指向触发事件的具体元素，**可能会变化**。取决于用户实际点击了哪个元素（例如在事件委托中，点击不同的 `LI`，`target` 就会改变）。
- **`currentTarget`**：始终指向绑定事件的元素，**固定不变**。事件绑定在谁身上，它就永远指向谁。

3\. **与 `this` 的关系**
- **`target`**：**不一定**等于 `this`。取决于触发的具体元素，如果触发的是子元素，则与 `this` 不相等；如果触发的是绑定元素本身，则相等。
- **`currentTarget`**：**始终**等于 `this`。事件处理函数中的 `this` 就是绑定事件的元素，无论触发的是哪个子元素，它都保持不变。

4\. **应用场景**
- **`target`**：常用于**事件委托**中，用于判断具体触发事件的子元素，从而执行相应的逻辑。
- **`currentTarget`**：用于明确当前正在处理事件的监听元素，确保操作的是绑定事件的正确容器。

## 总结与面试建议 *Content-[05:45]

- **核心知识点回顾**：
  - `target` 是真正触发事件的元素。
  - `currentTarget` 是监听事件的元素。
  - 当触发的元素和绑定事件的元素是同一个时（目标阶段），`this`、`target` 和 `currentTarget` 都相等。

- **面试与开发建议**：
  - 这是一个**高品质的前端面试题**，同时也是日常开发中（尤其是处理事件委托时）经常遇到的实际问题。
