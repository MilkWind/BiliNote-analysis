## 1. 全局作用域预解析分析 *Content-[00:00]

本案例主要讲解带有形参的函数在 JavaScript 预解析（变量与函数提升）过程中的执行机制。

- **第一步：进入预解析阶段**
  - **第一行代码**：存在 `var a = 1`。在预解析阶段，变量声明会被提升，此时内存（仓库）中的值为 `a = undefined`。
  - **第二行代码**：是一个函数声明 `function fn(a) { ... }`。函数声明在预解析阶段会被整体提升，且不会对代码的执行产生任何影响和改变。
  - **核心细节（形参提升）**：函数 `fn` 包含形参 `a`。在预解析期间，除了寻找 `var` 和 `function` 关键字外，**形参**也是必须寻找和提取的标志。
  - **预解析完毕后的仓库状态**：全局内存中的值为 `a = undefined`，`fn = function(a) { alert(a); a = 2; }`。

## 2. 全局作用域代码执行 *Content-[02:13]

预解析完成后，进入逐行执行代码阶段。

- **第一行**：执行 `a = 1`。将数值 `1` 赋值给全局变量 `a`，此时全局作用域中 `a` 的值由 `undefined` 变为 `1`。
- **第二行**：代码为函数声明。在执行阶段，函数声明不会改变任何值，因此不做任何修改操作，直接跳过。
- **后续执行**：代码直接跳转到第六行，执行 `fn()` 函数调用。

## 3. 局部作用域（fn函数）预解析与执行 *Content-[03:14]

当执行 `fn()` 时，程序进入函数的局部作用域，并在函数内部重新开启**预解析**和**执行代码**阶段。

- **局部预解析阶段**：
  - 同样遵循寻找 `var`、参数、`function` 的规则。
  - 函数 `fn` 有一个形参 `a`，因此局部仓库（内存）中的值为 `a = undefined`。函数内部没有其他 `var` 或 `function` 声明。
- **局部执行代码阶段**：
  - **第三行**：执行 `alert(a)`。由于局部预解析仓库中 `a` 的值为 `undefined`，因此第一个弹窗输出结果为 `undefined`。
  - **第四行**：执行 `a = 2`。将 `2` 赋值给 `a`。
    - **关键考点**：虽然 `a = 2` 前面没有 `var` 关键字，但**函数的参数相当于在局部作用域中声明了变量**。因此，这个赋值操作会直接覆盖并修改局部作用域中的 `a` 变量。
    - 此时，fn 函数内部的局部变量 `a` 的值变为 `2`。
  - 至此，fn 函数内部代码全部执行完毕。

## 4. 全局作用域后续执行与结果验证 *Content-[07:09]

fn 函数执行完毕后，程序返回全局作用域，继续执行后续代码。

- **第七行**：执行 `alert(a)`。
  - 此时访问的是**全局作用域**中的 `a`。根据作用域链规则，全局代码不可能到函数内部去找变量，只能查找全局作用域中的 `a`。
  - 全局作用域中的 `a` 在之前被赋值为 `1`，且 fn 函数内部修改的仅仅是局部 `a`，并未影响全局 `a`。
  - 因此，第二个弹窗输出结果为 `1`。
- **结果验证**：
  - **理论推导结果**：第一个弹窗输出 `undefined`，第二个弹窗输出 `1`。
  - **实际运行结果**：保存代码并刷新浏览器，弹出的结果与理论推导完全一致。

## AI 总结

本视频详细剖析了 JavaScript 预解析机制中一个经典的高频面试题（实战案例 8）。核心考点在于**函数形参在局部作用域中的变量提升与覆盖特性**。当函数被调用时，其形参相当于在局部作用域中通过 `var` 声明了同名变量。因此，在函数内部对形参的赋值操作（即使没有 `var` 关键字）也只会修改局部变量，而不会意外创建或修改全局变量。理解这一机制对于掌握 JavaScript 作用域链和执行上下文至关重要，是前端面试中必考的“八股文”基础。
