## 基本概念：强引用与弱引用 *Content-[00:36]

在深入了解具体 API 之前，需要明确 JavaScript 内存管理中的两个核心概念：

- **强引用 (Strong Reference)**：日常编写 JS 代码中最常用的默认引用方式。当使用 `let` 或 `const` 声明变量并指向一个对象时，就创建了一个强引用。只要引用链是可达的，垃圾回收器 (GC) 就永远不会回收该对象占用的内存。
- **弱引用 (Weak Reference)**：如果一个对象只被一个或多个弱引用指向，而没有任何强引用指向它，GC 在执行扫描时会忽略这些弱引用的存在。这意味着该对象是可以被回收的（可能在下一次 GC 循环中，也可能更晚，时机不确定）。

**弱引用的核心价值**：允许我们持有对一个对象的引用，但不会成为该对象存活的负担。我们只是“观察”这个对象，而不干扰它的生命周期。这在实现缓存系统或监视对象状态的场景中非常有用。

## WeakRef API 详解与使用规范 *Content-[02:15]

`WeakRef` 是 ES2021 引入的 API，用于创建对象的弱引用。

**基本用法与核心规范**：
1\. **初始化**：通过 `new WeakRef(targetObj)` 创建弱引用实例。
2\. **访问对象**：不能像普通对象那样直接使用，必须调用其 `deref()` 方法（dereference 的缩写，意为解除引用）。
3\. **返回值判断**：
   - 如果目标对象仍存在于内存中，`deref()` 返回对象本身。
   - 如果目标对象已被 GC 回收，`deref()` 返回 `undefined`。
4\. **防御性编程（必须遵守）**：由于对象可能在任何时间点被回收，每次通过 `deref()` 获取对象后，**必须**进行严格的判空检查。绝不能在没有检查的情况下直接使用结果，否则会导致运行时错误。

**标准使用流程拆解**：
- **第一步（初始化）**：拥有目标对象，并用 `new WeakRef()` 将其包装。
- **第二步（访问）**：业务需要时，调用 `deref()` 方法获取对象或 `undefined`。
- **第三步（防御检查）**：判断返回值。如果不等于 `undefined`，说明对象存在，可安全使用；如果等于 `undefined`，则执行备用逻辑（如提示用户数据已过期）。

## FinalizationRegistry API 详解 *Content-[05:30]

`WeakRef` 可以让我们感知对象被回收后的消失，但如果我们希望在对象被回收的**那一刻**自动执行清理工作，就需要它的搭档 `FinalizationRegistry`。

**基本用法**：
```javascript
const registry = new FinalizationRegistry((heldValue) => {
    // 预设的清理任务
});
registry.register(targetObj, heldValue);
```

**`register` 方法参数解析**：
- **target**：要监视的目标对象。
- **heldValue**：注册时传入的可序列化值（如字符串、数字）。因为回调函数执行时 `target` 本身已经被销毁，无法再访问它，所以需要 `heldValue` 来帮助识别当初是哪个对象被回收，从而执行对应的清理操作。

**典型应用场景**：
- 释放 JS 引擎之外的内存或资源（如使用 WebGL 或 WebAssembly 时）。
- 辅助调试内存泄漏。
- 在对象销毁时自动关闭网络连接、移除全局事件监听器等。

## 实战案例：实现自动清理的智能缓存 *Content-[08:19]

将 `WeakRef` 和 `FinalizationRegistry` 结合，可以解决缓存系统中常见的内存泄漏问题。

**痛点分析**：
如果使用标准的 `Map` 作为缓存，当缓存的 value 对象在外部不再被强引用并被 GC 回收后，`Map` 中的 key 依然会残留。此时 value 变成了一个失效的 `WeakRef`（`deref()` 返回 `undefined`），这会导致内存泄漏。

**解决方案（智能缓存 `WeakCache` 实现逻辑）**：
1\. 使用标准 `Map` 作为存储，但 value 存储的不是数据对象本身，而是包裹着数据对象的 `WeakRef` 实例（使缓存对数据对象保持弱引用）。
2\. 在 `set` 方法中，除了将 `new WeakRef(value)` 存入 `Map`，还要调用 `registry.register(value, key)`，将缓存项的 `key` 作为 `heldValue` 传给注册表。
3\. **系统闭环**：当某个缓存的 value 对象被 GC 回收时，注册的回调函数被触发，接收到当初传入的 `key`。通过该 `key`，可以准确地将 `Map` 中已经失效的条目删除，从而实现自动清理。

## 使用注意事项与适用场景 *Content-[10:55]

虽然这两个 API 非常强大，但不推荐在项目中滥用，必须遵守以下规则：

**使用注意事项**：
1\. **不确定性**：JS 中无法通过代码精确控制 GC 的运行时机（取决于浏览器实现、内存压力、CPU 负载等）。`deref()` 的结果可能在任何两次调用之间发生变化，永远不要假设弱引用对象会在特定时间点消失或存在。
2\. **不过度依赖**：弱引用不应被用于实现程序的核心功能，它只是一种渐进式的优化手段。如果程序逻辑依赖某个对象是否被回收来决定下一步操作，通常意味着程序设计存在问题。
3\. **性能考量**：创建和管理大量的 `WeakRef` 和 `FinalizationRegistry` 实例会给垃圾回收器带来额外负担，使用前需合理评估场景。

**好的适用场景**：
- **缓存系统**：缓存那些可以被重新计算或重新获取的数据。
- **DOM 操作**：在不希望阻止 DOM 元素被移除的情况下，持有它的引用。
- **观察者模式**：希望观察者能够被自动清理，不需要手动注销。

## AI 总结

本视频深入讲解了 JavaScript 内存管理中的高阶概念——弱引用。核心介绍了 ES2021 引入的 `WeakRef` 和 `FinalizationRegistry` 两个 API。`WeakRef` 允许开发者持有对象的弱引用而不阻碍垃圾回收，配合 `deref()` 方法和严格的防御性编程，可安全访问可能已被回收的对象。`FinalizationRegistry` 则弥补了弱引用无法感知回收时机的缺陷，允许在对象被回收时异步执行清理回调。视频通过实现一个自动清理过期条目的智能缓存案例，展示了两者结合的强大能力。最后强调了使用这些 API 时的注意事项：GC 时机具有不确定性，弱引用仅应作为性能优化的辅助手段，而不应作为核心业务逻辑的依赖。适用场景主要集中在缓存、DOM 引用和观察者模式的自动清理中。
