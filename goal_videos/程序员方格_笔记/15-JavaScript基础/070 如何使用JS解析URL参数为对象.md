## 1. 题目背景与重要性 *Content-[00:05]
- **高频面试题**：使用 JS 解析 URL 参数为对象是前端面试中非常高频的场景题。
- **实际工作应用**：在实际开发中（无论是 C 端还是 B 端项目），解析当前 URL 内容（如 `search`、`hash`、`path` 等）的出现频次非常高。
- **核心要求**：掌握使用 JS 解析 URL 参数的方法是前端开发者必须具备的基本功，面试时一定要会手写实现。

## 2. 方法一：使用 URLSearchParams API *Content-[00:54]
- **核心原理**：利用现代浏览器提供的 `URLSearchParams` API 来获取当前浏览器 URL 中的查询参数对象。
- **实现步骤**：
  - 获取 `location.search` 作为参数传入 `URLSearchParams` 构造函数。
  - 通过 `entries()` 方法遍历，获取所有的 key-value 键值对。
  - 将获取到的键值对存储到一个对象（Object）中并返回。
- **优缺点分析**：
  - **优点**：代码简洁，现代 API 使用非常方便。
  - **缺点**：需要考虑兼容性问题，因为它是较新的浏览器 API，在老旧浏览器中可能不支持。

## 3. 方法二：传统字符串解析方法 *Content-[03:02]
- **背景**：由于 `URLSearchParams` 存在兼容性问题，面试官通常会追问：“有没有兼容性更好的传统实现方式？”
- **核心原理**：通过对 URL 的 `query string` 字符串进行手动拆分和解析，兼容性极好。
- **实现步骤**：
  - 获取 `location.search` 字符串。
  - 使用 `split('&')` 根据 `&` 符号对字符串进行裁剪拆分，得到包含多个 `key=value` 的数组。
  - 遍历拆分后的数组，对每个元素再次使用 `split('=')` 根据 `=` 符号进行分割，获取左侧的 key 和右侧的 value。
  - 对获取到的 value 进行解码处理（如使用 `decodeURIComponent` 防止中文或特殊字符乱码）。
  - 将解析后的 key-value 存储到最终的对象中并返回。
- **优缺点分析**：
  - **优点**：兼容性极佳，适用于所有浏览器。
  - **缺点**：代码相对繁琐，需要进行多次字符串拆分操作。

## 4. 方法三：正则表达式匹配方法 *Content-[06:52]
- **背景**：除了传统字符串拆分，还可以利用正则表达式来高效提取参数，避免多次 `split`。
- **核心原理**：URL 参数的格式非常规范（由 `&` 连接，由 `=` 分隔键值），非常适合使用正则表达式进行全局匹配。
- **实现步骤**：
  - 获取 `location.search` 字符串。
  - 编写正则表达式，匹配等号前后的内容，并处理多个参数（使用全局匹配修饰符）。
  - 使用正则的匹配方法（如 `replace` 或 `matchAll`），在回调函数中获取匹配到的 key 和 value。
  - 将匹配结果存储到对象中。
- **优缺点分析**：
  - **优点**：避免了传统方法中多次使用 `split` 拆分的繁琐操作，执行效率高。
  - **缺点**：需要开发者对正则表达式的规则有较好的理解和掌握。

## 5. 面试技巧与建议 *Content-[07:41]
- **多准备几种解法**：在面试中，当写出一种解法后，面试官通常会继续追问“还有别的解读方式吗？”。
- **技多不压身**：一定要学会使用多种方法（如 API、字符串操作、正则）来解题，以满足面试官不断深入考察的诉求。不要只局限于一种写法，展现出对底层原理和多种实现方案的掌握。

## AI 总结 *Content-[10:47]
本次视频详细讲解了前端面试中高频场景题“使用 JS 解析 URL 参数为对象”的三种主流实现方案：
1. **现代 API 方案**：使用 `URLSearchParams`，代码简洁但需考虑兼容性。
2. **传统字符串方案**：通过 `split` 多次拆分 `&` 和 `=`，兼容性最好但代码稍显繁琐。
3. **正则表达式方案**：利用正则全局匹配键值对，执行高效且代码优雅，但考验正则功底。
