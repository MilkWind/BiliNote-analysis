## new 关键字的作用与默认返回机制 *Content-[01:07]
- **回顾 `new` 关键字的四个核心作用**：
  - 开辟内存空间。
  - 存储新创建的对象。
  - 将 `this` 绑定为当前新创建的对象。
  - 执行内部代码，为当前对象绑定属性和方法，并最终返回当前新创建的对象。
- **默认返回机制**：
  - 构造函数内部通常不需要手动编写 `return`。
  - 因为 `new` 关键字的作用，默认会自动完成返回新创建对象（相当于默认 `return this`）的动作，无需开发者手动干预。

## 手动添加 return 的不同情况测试 *Content-[02:13]
如果开发者在构造函数中手动添加了 `return`，需要注意以下几种情况。**重要前提：必须是通过 `new` 关键字调用**，否则不作为构造函数处理，以下讨论均无意义。

- **手动写 `return this`**
  - 结果：没有实际意义。
  - 原因：`new` 调用时默认就是返回 `this`，手动写等同于没写。

- **手动添加 `return` 但不写任何内容（即 `return;`）**
  - 结果：相当于 `return this`。
  - 原因：依然返回当前新创建的对象，等同于没有写。

- **`return` 基本数据类型（如 `return 99;`）**
  - 结果：无效，没有任何反应。
  - 原因：依然会保留原有的默认行为，即返回 `this`。

- **`return` 特殊值（如 `return undefined;` 或 `return null;`）**
  - 结果：一样无效。
  - 原因：依然保留原来返回 `this` 的行为。

## return 对象类型与寄生式对象 *Content-[04:13]
- **`return` 对象类型（如数组、普通对象等）**
  - 结果：此时返回的将是该对象本身，破坏了原有的 `return this` 默认行为。
  - 示例：如果在构造函数中 `return [1, 2, 3]`，那么 `new Person()` 得到的将是一个数组，而不是 `Person` 实例对象。
- **寄生式对象的概念**
  - 本来期望通过 `new` 得到特定类型（如 `Person`）的对象，但由于返回了其他对象（如数组），导致返回结果被“替换”。
  - 这种现象就像寄生虫一样寄生到构造函数中，吸走原有环境的营养，最终返回的是寄生对象，从而破坏了原有的实例化环境。
- **开发建议**
  - 在实际开发中，要严格避免“寄生式对象”的诞生。
  - 构造函数中尽量不要手动 `return` 一个对象，以免破坏原有的实例化逻辑。

## AI 总结
本视频详细讲解了在 JavaScript 构造函数中使用 `return` 关键字的注意事项。核心结论是：通过 `new` 调用构造函数时，默认会自动返回新创建的实例对象（`this`）。如果手动 `return` 基本数据类型或 `undefined`、`null` 等，返回值会被忽略，依然返回实例对象；但如果手动 `return` 一个引用类型（对象、数组等），则会覆盖默认行为，返回该引用类型，从而产生“寄生式对象”，破坏原有的实例化逻辑。因此，在实际开发中应严格避免在构造函数中 `return` 对象类型。
