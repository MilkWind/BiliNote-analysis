## 核心问题与现象 *Content-[00:01]*
- **现象描述**：在 JavaScript 中，直接比较 `$0.1 === 0.1$`，结果为 `true`。
- **核心疑问**：既然 `$0.1$` 转换为二进制是无限循环小数，底层存储的是一个近似值，为什么两次写 `$0.1$` 进行比较还能完全相等？

## 原理解析：为什么 0.1 === 0.1 成立？ *Content-[00:19]*
- **固定截断规则**：虽然 `$0.1$` 的二进制表示是无限循环的，但 JS 引擎会按照**固定的规则**将其截断，转换成同一个近似值进行存储。
- **一致性保证**：每次在代码中声明 `$0.1$` 时，JS 都会应用完全相同的截断规则。因此，多次声明的 `$0.1$` 在底层内存中存储的近似值是**完全相同**的。
- **结论**：因为两次存储的近似值在底层是同一个数，所以使用全等比较（`===`）时自然返回 `true`。

## 生活案例类比 *Content-[00:39]*
为了更好地理解这个抽象概念，可以通过以下两个生活中的例子来类比：
- **超市买苹果**：就像你两次去超市买“一斤”苹果。虽然苹果的实际物理重量不可能做到绝对的一模一样，但超市的秤都是按“一斤”的标准刻度来计算的。因此，在超市的系统里，这两次称出来的“一斤”是相等的。
- **不准的体重秤**：假设有一个体重秤不准，每次称重都会固定多显示 10 斤。当你和另一个人分别站上去称重时，虽然得出的绝对重量是错的，但秤对于你们两人的相对重量判断（谁轻谁重）依然是有效的。同理，JS 使用固定的误差规则，保证了相同输入的近似值输出是一致的。

## 代码验证：高精度查看真实存储值 *Content-[01:39]*
- **默认显示限制**：JS 默认只显示 16 位以内的数字，这掩盖了底层的精度丢失问题。
- **调出高精度**：为了验证两次声明的 `$0.1$` 是否为同一个数，可以手动调用 `toPrecision()` 方法调出高精度。
- **验证代码**：
  ```javascript
  let a = 0.1;
  let b = 0.1;
  
  // 调高到 20 位精度查看真实存储值
  console.log(a.toPrecision(20)); // 输出类似：0.10000000000000000555
  console.log(b.toPrecision(20)); // 输出类似：0.10000000000000000555
  
  // 比较两者
  console.log(a === b); // 输出：true
  ```
- **结果分析**：调高精度后，可以直观地看到 `$0.1$` 真实的存储值（如 `$0.10000000000000000555$`）。无论声明多少次 `$0.1$`，其真实存储的值都是这个固定的近似值，比较结果依然为 `true`。

## 对比分析：为什么 0.1 + 0.2 !== 0.3？ *Content-[02:26]*
- **单个对比（0.1 === 0.1）**：相当于单个苹果按标准称重两次，由于规则一致，结果相同。
- **加法运算（0.1 + 0.2 !== 0.3）**：
  - `$0.1$` 从十进制转为二进制时会丢失精度，产生**误差 A**。
  - `$0.2$` 从十进制转为二进制时也会丢失精度，产生**误差 B**。
  - 当这两个带有各自误差的近似值进行相加时，**误差会发生累加**。
  - 累加后的总误差变得足够明显，导致最终计算结果（如 `$0.30000000000000004$`）与 `$0.3$` 的近似值不再相等，因此返回 `false`。

## 核心总结 *Content-[03:00]*
- `$0.1$` 的二进制真值虽然是无限循环的，但 JS 按照固定规则截断后，生成的**近似值是相等的**。
- 两次声明的 `$0.1$` 存储的都是这同一个近似值，因此全等比较返回 `true`。
- 可以通过 `toPrecision(20)` 调出高精度，直观看到 `$0.1$` 的真实存储值，验证多次声明的 `$0.1$` 本质上是同一个数。
- **一句话总结**：它虽然是无限循环，但每次存的近似值都是同一个，所以直接比较相等。

## AI 总结
本视频详细解答了前端面试中的经典浮点数问题：为什么在 JavaScript 中 `0.1 === 0.1` 为 `true`，而 `0.1 + 0.2 !== 0.3`。核心原因在于 JS 对浮点数的 IEEE 754 存储机制。虽然 `0.1` 无法用二进制精确表示，但 JS 每次都会使用**相同的固定规则**进行截断，生成**完全一致的近似值**，因此直接比较时相等。而在执行 `0.1 + 0.2` 时，两个数各自的截断误差在加法运算中发生了累加，导致最终结果偏离了 `0.3` 的近似值。理解这一底层机制，有助于开发者在实际项目中正确处理浮点数比较（例如引入 `Number.EPSILON` 或使用高精度计算库）。
