## 1. 执行上下文 (Execution Context) *Content-[00:12]*

执行上下文是 JavaScript 中非常底层且核心的概念，你可以将其想象成代码被执行时所处的“环境”。这个环境决定了代码在执行期间可以访问到哪些变量、函数以及其他数据。

执行上下文主要分为以下两种类型：

- **全局上下文 (Global Context)**：
  - 这是代码首先进入的环境，也是最外层的上下文。
  - 在浏览器环境中，全局上下文对应着我们熟悉的 `window` 对象。
  - 在全局作用域下，使用 `var` 声明的所有变量和函数，都会自动成为 `window` 对象的属性。
- **函数上下文 (Function Context)**：
  - 每当调用一个函数时，JavaScript 引擎就会为该函数创建一个全新的上下文环境。

## 2. 执行上下文栈 (Execution Context Stack) *Content-[01:03]*

当存在多个函数调用时，JavaScript 引擎使用“执行上下文栈”来管理这些上下文。其具体的执行和管理顺序如下：

1. 当代码开始运行时，**全局上下文**首先被推入栈底。
2. 如果此时调用了函数 A，引擎会创建函数 A 的上下文，并将其推入栈顶。
3. 如果函数 A 内部又调用了函数 B，函数 B 的上下文会被创建并继续入栈，位于函数 A 的上下文之上。
4. 当函数 B 执行完毕后，它的上下文会从栈顶弹出，控制权交还给函数 A。
5. 函数 A 执行完毕后，其上下文也会出栈。
6. 直到最后所有的代码都执行完毕，全局上下文才会出栈。

## 3. 作用域链 (Scope Chain) *Content-[02:16]*

在理解了执行上下文之后，作用域链是另一个关键概念。

- **本质与定义**：
  - 作用域链的本质是一个指向各级作用域的指针列表。
  - 它定义了在当前执行上下文中，代码能访问到哪些变量和函数，以及它们的访问顺序。
- **结构**：
  - 作用域链的最前端，永远是当前正在执行的那个上下文的变量对象。
  - 如果是在一个函数内部，其作用域链的顶端就是该函数的**活动对象 (Activation Object)**。
  - 下一环是外部函数的变量对象，再下一环是更外层的变量对象，以此类推，直到最终的全局上下文。
- **工作机制**：
  - 当代码需要访问一个变量时，JavaScript 引擎会沿着作用域链进行一次搜索。
  - 首先在当前作用域（链的最前端）查找，如果找到则直接使用该变量。
  - 如果没找到，引擎会移动到链的下一个环节（外部作用域）继续查找。
  - 这个过程会一直持续，直到找到变量或者抵达作用域链的末端（全局作用域）。
  - 如果在全局作用域中依然没有找到，通常会抛出一个引用错误 (`ReferenceError`)。
- **遮蔽效应 (Shadowing Effect)**：
  - 这种逐级搜索的机制带来了“遮蔽效应”。
  - 如果内部作用域定义了一个与外部作用域同名的变量，在内部作用域访问该变量时，搜索在第一站就会结束。
  - 引擎会直接使用内部的变量，不会再向上访问外部的同名变量，即内部变量“遮蔽”了外部变量。

## 4. 作用域边界与变量声明关键字 *Content-[04:24]*

作用域链的边界是由函数如何声明以及使用的变量声明关键字来决定的。回顾 `var`、`let` 和 `const` 这三个关键字与作用域的关系：

- **`var`**：
  - 声明的是**函数作用域 (Function Scope)**。
  - 这意味着不管 `var` 语句写在函数的哪个角落，它声明的变量在整个函数内部都是可见的。
  - 这与 JavaScript 中的**变量提升 (Hoisting)** 现象紧密相关。
- **`let` 和 `const` (ES6 引入)**：
  - 带来了全新的**块级作用域 (Block Scope)** 规则。
  - 用 `let` 或 `const` 声明的变量，其生命周期被严格限制在它被定义时所在的那个块级作用域内（即花括号 `{}` 内部）。
  - 这个块可以是一个 `if` 语句块、一个 `for` 循环块，甚至是一个独立的代码块。
  - 它们**没有任何的变量提升**，并且存在**暂时性死区 (Temporal Dead Zone, TDZ)**，这使得变量的行为更加可预测。

## 5. 代码示例解析：testScope *Content-[05:39]*

通过 `testScope` 函数的示例，可以清晰地看到不同关键字在作用域中的表现：

- 在函数内部，第一个 `console.log` 会输出 `undefined`，这是因为 `var` 声明的变量存在变量提升。
- 在 `if` 语句块内部，分别使用 `var` 声明了变量 `a`，使用 `let` 声明了变量 `b`。
- 当 `if` 块执行完毕之后：
  - 打印 `a` 可以正常访问到 `"var in block"`。这是因为 `var` 的作用域是整个函数，它从 `if` 块中“泄露”出来了。
  - 如果尝试访问 `b`（或 `const` 声明的变量），就会得到一个 `ReferenceError`。因为 `let` 和 `const` 的作用域被严格限制在了 `if` 块的内部，外部是无法访问的。
- **结论**：这就是块级作用域的威力，它能有效防止变量污染，使代码逻辑更加严谨。
