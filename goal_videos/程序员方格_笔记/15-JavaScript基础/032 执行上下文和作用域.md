## 执行上下文 *Content-[00:12]

执行上下文（Execution Context）是 JavaScript 中两个非常底层且重要的概念之一。你可以将其想象成代码被执行时所处的“环境”。这个环境决定了代码在执行期间可以访问到哪些变量、函数以及其他数据。

执行上下文主要分为两种类型：

1\. **全局上下文（Global Context）**
- 这是代码首先进入的环境，也是最外层的上下文。
- 在浏览器环境中，全局上下文对应着我们熟悉的 `window` 对象。
- 在全局作用域下，使用 `var` 声明的所有变量和函数，都会自动成为 `window` 对象的属性。

2\. **函数上下文（Function Context）**
- 每当调用一个函数时，JavaScript 引擎就会给这个函数创建一个全新的上下文环境。
- 这个环境包含了该函数内部定义的变量、参数以及内部函数等。

## 执行上下文栈 *Content-[01:03]

当有多个函数调用时，JavaScript 引擎通过**执行上下文栈（Call Stack）** 来管理这些上下文。其执行和管理顺序如下：

- **入栈**：当代码开始运行时，全局上下文首先被推入栈底。如果此时调用了函数 A，函数 A 的上下文就会被创建并推入栈顶。如果函数 A 内部又调用了函数 B，函数 B 的上下文会继续入栈，位于函数 A 之上。
- **出栈**：当函数 B 执行完毕后，它的上下文会从栈顶弹出，控制权交还给函数 A。接着函数 A 执行完毕，其上下文也会出栈。
- **结束**：直到最后所有的代码都执行完毕，全局上下文才会出栈，整个执行过程结束。

## 作用域链 *Content-[02:16]

作用域链（Scope Chain）的本质是一个指向各级作用域的指针列表。它定义了在当前执行上下文中，代码能访问到哪些变量和函数，以及它们的访问顺序。

### 作用域链的结构
- 作用域链的最前端，永远是当前正在执行的那个上下文的**变量对象**。
- 如果是在一个函数内部，作用域链的顶端就是该函数的**活动对象（Activation Object）**。
- 它的下一环是外部函数的变量对象，再下一环是更外层的变量对象，以此类推，直到最终的全局上下文。

### 作用域链的工作机制
- 当代码需要访问一个变量时，JavaScript 引擎会沿着作用域链进行一次搜索。
- 首先在当前作用域（链的最前端）查找，如果找到则直接使用该变量。
- 如果没找到，引擎会移动到链的下一个环节（即外部作用域）继续查找。
- 这个过程会一直持续，直到找到变量或者抵达作用域链的末端（全局作用域）。
- 如果在全局作用域中依然没有找到该变量，JavaScript 通常会抛出一个引用错误（`ReferenceError`）。

### 遮蔽效应（Shadowing）
这种逐级搜索的机制带来了一个重要特性——遮蔽效应。如果内部作用域定义了一个与外部作用域同名的变量，那么在内部作用域访问该变量时，搜索在第一站（内部作用域）就会结束。引擎会直接使用内部的变量，不会再继续向上访问外部的同名变量。

## 变量声明与作用域边界 *Content-[04:24]

作用域链的边界是由函数和变量的声明方式决定的。回顾 `var`、`let` 和 `const` 三个关键字，它们与作用域的关系有显著差异：

### 1. `var`：函数作用域
- `var` 声明的变量属于**函数作用域**。
- 这意味着不管 `var` 语句写在函数的哪个角落，它声明的变量在整个函数内部都是可见的。
- 这种现象与**变量提升（Hoisting）** 紧密相关。

### 2. `let` 和 `const`：块级作用域
- ES6 引入的 `let` 和 `const` 带来了全新的**块级作用域**规则。
- 用它们声明的变量，其生命周期被严格限制在定义时所在的那个块级作用域内（即花括号 `{}` 内部，如 `if` 语句块、`for` 循环块或独立的代码块）。
- 它们**没有变量提升**，并且存在**暂时性死区（TDZ, Temporal Dead Zone）**，这使得变量的行为更加安全和可预测。

### 示例分析：`testScope` 函数
在视频提供的 `testScope` 函数示例中：
- 首先打印变量 `a`，由于 `var` 的变量提升特性，此时输出 `undefined`。
- 在 `if` 语句块内部，使用 `var` 声明了 `a`，使用 `let` 声明了 `b`，使用 `const` 声明了 `c`。
- 当 `if` 块执行完毕后，在外部再次打印 `a`，可以正常访问到 `"var in block"`。这是因为 `var` 的作用域是整个函数，变量从 `if` 块中“泄露”了出来。
- 但是，如果尝试在 `if` 块外部访问 `b` 或 `c`，就会得到一个 `ReferenceError`。因为 `let` 和 `const` 的作用域被严格限制在了 `if` 块的内部，外部无法访问。
- **结论**：块级作用域能有效防止变量污染，是现代 JavaScript 开发中推荐使用的声明方式。
