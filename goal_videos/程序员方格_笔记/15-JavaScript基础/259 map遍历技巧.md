## 1. 经典面试题引入 *Content-[00:00]

在前端开发面试中，有一道非常经典的题目用于考察开发者对 JavaScript 基础函数的理解深度，而不仅仅是停留在表面的 API 调用。

**面试题目**：
在 JavaScript 中，执行以下代码的结果是什么？为什么？
```javascript
['1', '2', '3'].map(parseInt)
```

**考察核心**：
这道题主要考察应聘者对 `map` 函数的遍历机制以及 `parseInt` 函数参数的彻底理解。很多开发者存在思维误区，认为 `map` 只是简单的遍历，而 `parseInt` 只是将字符串转换为数字，因此想当然地认为结果会是 `[1, 2, 3]`。但实际上，由于参数传递的机制，结果会大相径庭。

## 2. 结果与原因深度剖析 *Content-[02:22]

**最终结果**：
上述代码的实际输出结果为：`[1, NaN, NaN]`。

**原因拆解**：
要理解为什么会产生这样的结果，需要深入分析 `map` 和 `parseInt` 这两个函数的参数定义。

1. **`map` 函数的回调参数**：
   `map` 方法在遍历数组时，其回调函数（callback）固定会接收三个参数：
   - 第一个参数：`currentValue`（当前遍历到的值）
   - 第二个参数：`index`（当前值的索引号）
   - 第三个参数：`array`（整个数组本身）

2. **`parseInt` 函数的参数**：
   `parseInt(string, radix)` 函数用于解析字符串并返回一个整数，它接收两个参数：
   - 第一个参数：`string`（需要被转换的具体字符串值）
   - 第二个参数：`radix`（基数/转换格式），有效范围是 **2 到 36**。如果该值为 0 或未指定，则默认按十进制进行解析。

**迭代过程分析**：
当把 `parseInt` 直接作为 `map` 的回调函数时，`map` 传递的三个参数会被 `parseInt` 接收，但 `parseInt` 只使用前两个参数（即 `currentValue` 和 `index`），第三个参数（整个数组）会被忽略。

- **第一次迭代**：
  传入参数为 `'1'`（当前值）和 `0`（索引）。
  执行：`parseInt('1', 0)`。
  解析：`radix` 为 0，默认以十进制解析，字符串 `'1'` 转换为数字 `1`。
  **结果：`1`**

- **第二次迭代**：
  传入参数为 `'2'`（当前值）和 `1`（索引）。
  执行：`parseInt('2', 1)`。
  解析：`radix` 为 1，但 `parseInt` 的基数有效范围是 2~36。1 不在有效范围内，无法进行转换。
  **结果：`NaN`**

- **第三次迭代**：
  传入参数为 `'3'`（当前值）和 `2`（索引）。
  执行：`parseInt('3', 2)`。
  解析：`radix` 为 2，表示要求以**二进制**格式解析字符串。但是，字符串 `'3'` 并不是一个有效的二进制数（二进制只能包含 0 和 1），因此转换失败。
  **结果：`NaN`**

综上所述，由于 `map` 传递的索引值意外地成为了 `parseInt` 的基数参数，导致了后两次转换失败，最终输出 `[1, NaN, NaN]`。

## 3. 正确的解决方案 *Content-[08:19]

为了避免这种因参数不匹配导致的隐蔽错误，在实际开发中，我们需要采用更严谨的写法。以下是两种推荐的解决方案：

**方法一：使用箭头函数（嵌套函数）包装**
通过箭头函数显式地只传递第一个参数给 `parseInt`，从而阻断 `map` 传递多余的 `index` 参数。这是最常见且最稳妥的做法。
```javascript
// 方式 A：不指定 radix，默认处理
['1', '2', '3'].map(item => parseInt(item))

// 方式 B：明确指定 radix 为 10（推荐，代码意图更清晰）
['1', '2', '3'].map(item => parseInt(item, 10))
```

**方法二：使用 `Number` 构造函数**
如果我们的最终目的仅仅是将字符串数组转换为数字数组，可以直接使用 `Number` 构造函数。
`Number` 函数在作为回调时，只会使用传入的第一个参数（当前值），会自动忽略后续的 `index` 和 `array` 参数，因此不会产生类似 `parseInt` 的副作用。
```javascript
['1', '2', '3'].map(Number)
```

## AI 总结

本题是一道极具代表性的前端“陷阱题”，核心在于揭示 JavaScript 中高阶函数参数传递的底层机制。`map` 会向回调函数传递 `value`、`index` 和 `array` 三个参数，而 `parseInt` 的第二个参数 `radix`（基数）恰好会接收到 `index` 的值。由于 `radix` 的有效范围是 2~36，当索引为 1 时超出范围返回 `NaN`，当索引为 2 时要求二进制解析但字符串 `'3'` 不合法也返回 `NaN`。

在面试中回答此题时，不仅要答出 `[1, NaN, NaN]` 的正确结果，更要清晰地阐述 `map` 与 `parseInt` 的参数映射关系。在实际开发中，应养成使用箭头函数包装或直接使用 `Number` 构造函数的良好编码习惯，以规避此类隐式参数带来的 Bug。
