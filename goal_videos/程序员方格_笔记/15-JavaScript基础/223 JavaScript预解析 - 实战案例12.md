## 4. 深入解析 `b in window` 与全局变量 *Content-[02:02]
- **`in` 操作符的作用**：
  - `b in window` 用于判断 `window` 对象中是否存在名为 `b` 的属性或方法。
- **常规对象属性访问验证**：
  - 如果直接访问一个对象上不存在的属性（如 `window.b`），结果会返回 `undefined`。
  - 在控制台打印 `console.log(window.b)` 进行初步验证，结果确为 `undefined`，这容易让人误以为 `window` 中没有 `b`。
- **结合预解析上下文分析**：
  - 在预解析阶段，`var b` 声明的全局变量实际上会挂载到 `window` 对象下，即 `window.b = undefined`。
- **控制台实操深度验证**：
  - 为了验证全局变量的挂载机制，可以在控制台执行 `var b = 1;` 或直接赋值 `window.b = 100;`。
  - 打印 `window` 对象并展开，先找方法，再找属性，找到 `b` 开头的属性，可以明确看到 `b: 100`。
  - 此时再访问 `window.b`，结果就是 `100`。
- **得出结论**：因为预解析时 `b` 已经挂载到 `window` 对象上，所以表达式 `b in window` 的结果为 `true`。

## 5. 条件分支执行与最终结果输出 *Content-[06:30]
- **逻辑取反与条件判断**：

  - 因此，`if` 条件不成立，`if` 代码块内的语句（`b = 2; a += 1;`）**不会执行**。
- **执行 `else` 分支**：

  - 执行 `console.log(b)`：由于 `b` 的值在 `if` 块中未被修改，依然保持预解析时的原始值，因此输出 `undefined`。
