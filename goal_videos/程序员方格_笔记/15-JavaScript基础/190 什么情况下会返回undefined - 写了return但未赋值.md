## 函数写了 return 但未赋值的情况 *Content-[00:00]
- **场景描述**：在函数中写了 `return` 关键字，但是 `return` 后面没有任何值，且单独成行。
- **执行结果**：JavaScript 会认为该函数没有返回值，默认返回 `undefined`。

## 核心原因：JS 自动分号插入规则 *Content-[00:39]
- **核心机制**：JavaScript 存在自动分号插入规则（Automatic Semicolon Insertion, ASI）。
- **触发条件**：当 `return` 关键字后面直接换行时，JS 引擎会自动在 `return` 后面添加一个分号。
- **实际效果**：代码中的 `return` 换行会被 JS 解析为 `return;`。由于 `return;` 已经表示函数结束且没有返回值，因此最终返回 `undefined`。

## 案例分析与代码演示 *Content-[01:46]

1\. **案例 1：`return` 单独成行**
- **代码逻辑**：定义一个函数 `fn`，内部只有 `return` 单独成行，下方定义了变量（如 `let a = 10;`）。
- **执行结果**：调用函数，返回结果为 `undefined`。
- **原理解析**：`return` 语句已经结束了函数的执行，因此 `return` 后面的代码永远不会被执行（属于死代码）。由于 `return` 后面没有具体的值，JS 会给予默认值 `undefined`。

2\. **案例 2：`return` 后换行写值（常见坑点）**
- **代码逻辑**：定义函数 `getNum`，写了 `return` 后直接换行，在下一行写上具体的值 `100`。
- **执行结果**：调用函数并保存结果，返回值依旧是 `undefined`。
- **原理解析**：这是一个非常容易踩坑的点。因为 `return` 后换行，JS 自动在 `return` 后添加了分号，代码实际被解析为 `return; 100;`。因此函数直接返回 `undefined`，而后面的 `100` 同样不会被返回。

## 开发避坑技巧与正确写法 *Content-[03:58]
- **避坑原则**：`return` 的值必须和 `return` 关键字写在同一行。
- **核心目的**：避免 JS 自动分号插入规则导致意外添加分号，从而造成无返回值的 Bug。
- **正确写法示例**：
  ```javascript
  function fn() {
      return 100; // 返回值与 return 关键字保持在同一行
  }
  ```
- **执行结果**：调用函数 `fn()`，能够正确保存并输出结果 `100`。
