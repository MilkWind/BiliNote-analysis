## 1. 可达性（Reachability）概念 *Content-[00:07]

在 JavaScript 的内存管理中，**可达性（Reachability）** 是一个核心概念。
- **定义**：指以某种方式可访问或可用的值。
- **示例说明**：假设有一个对象 `test`，如果可以通过某种方式访问到其中的值（如 `12345`），则该值具备可达性；如果 `name: '张三'` 无法通过任何方式被访问到，则它不具备可达性。
- **垃圾判定**：不可访问、不具备可达性的对象即被视为“垃圾”。
- **垃圾回收机制**：JS 引擎通过可达性来判断是否回收内存。由于实时回收的开销较大，JS 垃圾回收机制会**定时定期**找出那些不可达（不可用）的内存变量，并释放其占用的内存空间。

## 2. 标记清除算法（Mark and Sweep） *Content-[01:25]

**标记清除算法（Mark and Sweep）** 是目前 JavaScript 引擎中最常用的垃圾回收算法，各大浏览器厂商都在使用，并在此基础上进行了各自的优化（不同厂商的实现细节和回收频率存在差异）。

该算法主要分为两个阶段，并包含一个重置阶段：

- **标记阶段（Mark）**：
  - 垃圾回收器会从**根对象（Root objects）** 出发（如全局的 `window` 对象、文档的 DOM 对象等）。
  - 遍历内存中的所有对象。默认情况下，假设所有对象都是垃圾，将其二进制标识位标记为 `0`。
  - 在遍历过程中，如果从根对象出发能够访问到某个节点（即具备可达性，说明还在使用），则将该节点的二进制标识位设置为 `1`。
- **清除阶段（Sweep）**：
  - 遍历结束后，清理并销毁所有标记为 `0` 的对象，回收它们所占用的内存空间。
- **重置阶段**：
  - 将内存中所有存活对象的标记重新置为 `0`，等待下一轮垃圾回收（GC）的执行。

## 3. 标记清除算法的缺点与内存分配策略 *Content-[09:10]

### 内存碎片化问题
标记清除算法在清除垃圾后，会导致剩余的空闲内存空间变得**不连续**，从而引发**内存碎片化**。当需要分配一个较大的新对象（如 `new Object()`）时，可能会因为找不到足够大的连续空间而导致分配失败。

### 内存分配策略
针对碎片化的内存空间，系统需要决定将新对象存放到哪块空间，通常有以下三种策略：
- **First fit（首次适应）**：找到第一个大于等于当前所需 `size` 的内存块并立马返回。
  - *特点*：不需要遍历整个列表，分配速度快、效率高，是最明智的选择。
- **Best fit（最佳适应）**：遍历整个空闲内存列表，找到大于等于当前 `size` 的最小内存块。
  - *特点*：空间利用率看起来最合理，但需要遍历整个列表，分配速度较慢。
- **Worst fit（最坏适应）**：遍历整个空间，找到最大的内存块，将其切分为两部分，返回所需 `size` 大小的部分。
  - *特点*：切分后剩余的小块会加速内存碎片化，因此不推荐使用。

### 标记清除算法的三大明显缺点
1. **内存碎片化**：空闲内存空间不连续，容易导致分配所需内存过大的对象时找不到合适的连续空间。
2. **分配速度慢**：即使采用 First fit 策略，仍存在 $O(n)$ 的时间复杂度操作。在最坏情况下需要遍历到最后，且碎片化会导致大对象的分配效率更低。
3. **执行效率问题（Stop the world）**：在标记和清除阶段，必须**停止整个应用程序的执行**（即 Stop the world）。程序暂停后垃圾回收器才开始工作，清理完毕后再恢复程序状态。这会导致应用程序出现明显的卡顿。

## 4. 其他垃圾回收策略简介 *Content-[16:00]

除了主流的标记清除算法外，JavaScript 中还存在其他的垃圾回收策略，例如**引用计数（Reference counting）** 算法等，用于在不同场景下辅助或替代标记清除机制。
