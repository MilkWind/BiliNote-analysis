## 1. 条件语句 *Content-[00:11]

### 1.1 if 语句
- **基本逻辑**：`if` 语句用于评估并判断一个条件表达式。如果表达式的结果为 `true`，则执行紧跟的 `if` 代码块。
- **多条件分支**：可以通过 `else if` 添加多个判断条件，最后使用 `else` 来处理所有不满足条件的情况。

### 1.2 switch 语句
- **适用场景**：当判断逻辑基于同一个变量的多个不同离散值时，`switch` 语句通常比一长串的 `if...else` 结构更加清晰，可读性更高。
- **比较机制**：`switch` 会将传入的表达式与每一个 `case` 的值进行**全等比较**（`===`）。
- **执行逻辑**：如果匹配成功，代码会从匹配的 `case` 开始执行。
- **关键细节（穿透问题）**：每个 `case` 代码块的末尾通常都需要一个 `break` 语句。如果没有 `break`，代码会继续**穿透**到下一个 `case` 并继续执行，直到遇到 `break` 或 `switch` 结构结束。
- **default 关键字**：这是一个可选关键字，用于处理表达式的值与所有 `case` 都不相匹配的情况。

## 2. 迭代语句 *Content-[02:04]

### 2.1 while 与 do...while 循环
- **适用场景**：两者都适用于循环次数不确定的场景。
- **主要区别（测试条件的时机）**：
  - `while`：**先判断再执行**。如果条件一开始就不满足，循环体一次都不会执行。
  - `do...while`：**先执行再判断**。保证了循环体至少会执行一次。

### 2.2 for 循环
- **特点**：最常用的循环语句，结构非常清晰。
- **语法结构**：将变量的初始化、循环条件以及循环后要做的操作（通常是递增或递减）集中在一个括号内。

### 2.3 for...in 与 for...of 循环
这两个语句非常容易混淆，需明确区分：
- **for...in 循环**：
  - **设计初衷**：用于遍历对象的属性。
  - **迭代内容**：迭代对象的每一个**可枚举的 Key**。
  - **注意事项**：遍历顺序是**不确定**的，并且会遍历到**原型链**上的属性。因此，**不推荐**使用它来遍历数组。
- **for...of 循环**：
  - **引入版本**：ES6 引入的特性，彻底解决了 `for...in` 的问题。
  - **适用场景**：遍历**可迭代数据**的首选。适用于字符串、数组、`Map`、`Set` 等内置可迭代对象。
  - **迭代内容**：迭代集合中每一个元素的**值**，而不是 Key。
  - **对比示例**：使用 `for...in` 遍历对象得到的是 Key（如 `a`, `b`）；使用 `for...of` 遍历数组得到的是数组里面的值（如 `x`, `y`）。

## 3. 流程控制语句 *Content-[05:07]

### 3.1 break 与 continue
两者都用在循环内部，用于精细控制代码的执行流程：
- **break**：非常决绝，一旦执行就会立刻**终止并跳出整个循环**。
- **continue**：相对温和，只会**结束当前这一次迭代**，然后立刻开始下一次迭代。

### 3.2 标签语句 (Label)
- **使用场景**：在简单的循环中，`break` 和 `continue` 只能影响它们所在的最内层循环。但在**嵌套循环**中，如果想从内层循环直接跳出外层循环，就需要用到 `label` 标签。
- **使用方法**：给外层循环起一个标签名，然后在内层循环里使用 `break` 或 `continue` 并带上该标签名，即可直接终止或跳过外层循环。
- **注意**：这是一个不常用的高级技巧。

### 3.3 with 语句
- **作用**：临时改变作用域链。在 `with` 代码块内部，可以直接访问指定对象的属性，不需要写对象名本身。
- **严重缺陷**：该特性会使得代码的**词法作用域变得非常模糊不清**，开发者很难判断一个变量到底是来自 `with` 对象还是来自外部作用域，给代码的理解和调试带来极大困难。
- **结论**：这是一种**不良实践**。在严格模式（strict mode）下被**完全禁止使用**，日常开发中应彻底避免。
