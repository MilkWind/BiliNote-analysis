## 1. 值的可变性概念 *Content-[00:00]
- **核心定义**：值的可变性是指能否直接修改变量存储的原始值。
- **重要性**：基本类型和引用类型在值的可变性规则上完全相反。这是前端开发中非常容易踩坑的知识点，很多工作 5 年以上的开发者也可能对此存在认知盲区。

## 2. 基本数据类型的不可变性 *Content-[00:42]
- **核心概念**：基本类型的原始值是无法被直接修改的。
- **通俗比喻**：就像你买了一瓶可乐，你不能直接把它变成雪碧。如果你想要雪碧，只能把可乐扔掉，再重新买一瓶雪碧。
- **代码示例 1：尝试直接修改字符**
  - 定义变量 `let str2 = '最编程'`。
  - 尝试修改第二个字符：`str2[1] = 'm'`。
  - 打印结果：输出依然是 `'最编程'`。
  - **结论**：直接修改基本类型的内部值是无效的，原始值始终没有发生改变。
- **代码示例 2：变量重新赋值**
  - 重新赋值：`str2 = '创未来'`。
  - 打印结果：输出变为 `'创未来'`。
  - **原理解析**：
    - 看起来 `str2` 的值改变了，但实际上只是改变了**指针的指向**。
    - `str2` 原本是一个指向 `'最编程'` 的指针，重新赋值后，指针指向了新的值 `'创未来'`。
    - 在栈内存中，`'最编程'` 这个字符串依旧存在，并没有被修改或删除，只是变量 `str2` 不再指向它，而是指向了 `'创未来'`。
  - **关键区分**：必须严格区分“值的改变”和“指针的改变”。基本数据类型体现的是**指针指向的改变**，而非值本身的改变。

## 3. 引用数据类型的可变性 *Content-[06:36]
- **核心概念**：引用类型可以直接修改堆内存中的实际数据。
- **通俗比喻**：两个人各拿一把钥匙（指针），打开的是同一个房间（堆内存中的数据）。第一个人在房间里放了东西，第二个人进去后就能直接看到。
- **代码示例 3：对象属性修改**
  - 定义对象 `let o = { x: 1 }`。
  - 修改并增加属性：`o.x = 2; o.y = 3;`。
  - 打印结果：输出 `{ x: 2, y: 3 }`。
- **代码示例 4：数组元素修改**
  - 数组同样属于引用数据类型。
  - 修改数组元素或增加新元素（如修改下标 0 的值，或在末尾追加元素），都是直接修改了堆内存中的实际数据。
  - 打印结果：能够直接获取并显示修改后的数组值。

## 4. 核心底层逻辑总结 *Content-[09:00]
- **基本数据类型**：
  - **值不可变**：原始值无法被直接修改。
  - **指针可变**：变量重新赋值时，改变的是栈内存中变量的地址指针，使其指向新的值。
- **引用数据类型**：
  - **数据可变**：可以直接修改堆内存中的实际数据。
  - **指针不变**：栈中变量的地址指针始终不变。因为所有指向该地址的变量共享同一块数据，所以修改后，所有相关变量都能获取到修改后的值。

## AI 总结
本视频深入剖析了前端面试中高频考点“基本类型与引用类型的区别”，核心聚焦于**值的可变性**。基本数据类型的值是不可变的，所谓的“修改”实际上是改变了变量指针的指向，而原始值在内存中依然存在；相反，引用数据类型的值是可变的，修改变量时直接修改了堆内存中的实际数据，而栈内存中的地址指针保持不变。理解这一底层逻辑（指针改变 vs 数据改变）对于避免开发中的引用陷阱以及应对大厂面试至关重要。
