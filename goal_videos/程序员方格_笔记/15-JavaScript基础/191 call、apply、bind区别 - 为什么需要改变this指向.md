## call、apply、bind 的核心作用与 this 指向 *Content-[02:46]

抛开面试套路，从最基础的问题入手，`call`、`apply`、`bind` 这三个方法的核心作用只有一个：**改变函数内部 `this` 的指向**。

- **`this` 的基本概念**：
  通俗来说，`this` 就是函数“谁调用就指向谁”。这个常规概念可以应对 80% 以上的场景。例如，一个函数被 A 对象调用，`this` 就指向 A 对象；被 B 对象调用，`this` 就指向 B 对象。
- **三大方法的作用**：
  `call`、`apply`、`bind` 的作用就是打破这个常规，让函数明明被 A 对象调用，却可以强制指向 B 对象。这相当于“借别人的函数干自己的活儿”，这就是改变 `this` 指向的本质。

## 为什么要改变 this 指向 *Content-[04:31]

理解为什么要改变 `this` 指向，需要先了解 JS 的上下文机制。

- **JS 的上下文机制**：
  JS 的一大特点是函数存在**定义时的上下文**以及**运行时的上下文**，且上下文是可以改变的。
  - **箭头函数**：使用的是定义时的上下文。
  - **普通函数**：使用的是运行时的上下文。
  - `call`、`apply`、`bind` 这三个函数都是为了改变某个函数**运行时的上下文**而存在的，换句话说就是为了改变函数体内部 `this` 的指向。

- **生活案例**：
  周末临时决定带孩子去野餐，但没有帐篷且来不及买。此时可以借同事或邻居的帐篷用一次，既达到了野餐的目的，又节省了开支，一举两得。

- **代码应用逻辑**：
  在开发中，如果 A 对象有一个方法，而 B 对象因为某种原因也需要用到同样的方法。此时不需要为 B 对象单独扩展一个方法，而是直接借用 A 对象的方法。这样既完成了需求，又减少了内存的占用。

## 实际开发中的 this 指向案例分析 *Content-[05:57]

通过一个实际的代码案例，来直观感受 `this` 指向的变化以及为什么需要修改它。

**代码环境设置**：
```javascript
// 全局变量（注：视频中原本使用 name，但因 window 对象默认有 name 属性，故替换为 username）
let username = '金小子'; 

const obj = {
    username: '老金',
    c: function() {
        console.log(this.username);
    }
};
```

**情况一：正常调用**
```javascript
obj.c(); 
```
- **结果**：打印出 `老金`。
- **原因**：此时 `c` 方法是由 `obj` 对象调用的，根据“谁调用指向谁”的原则，`this` 指向 `obj` 对象。`obj` 对象中存在 `username` 属性，因此输出 `老金`。

**情况二：在定时器中异步调用**
```javascript
setTimeout(obj.c, 0); 
```
- **结果**：打印出 `undefined`。
- **原因**：在定时器 `setTimeout` 中，`c` 方法是作为回调函数执行的。当回到主线程执行时，是在全局执行上下文的环境中执行的，因此 `this` 指向了 `window` 对象。而 `window` 对象上并没有 `username` 这个属性，访问一个不存在的属性，返回值即为 `undefined`。

**案例总结**：
- 正常情况下，`c` 方法中的 `this` 指向调用它的 `obj` 对象。
- 在定时器 `setTimeout` 中，`c` 方法作为回调函数执行，`this` 丢失了原有的对象绑定，指向了 `window` 对象。
- **实际需求**：如果我们需要在定时器的回调函数中，让 `this` 依然指向 `obj` 对象（即找到 `老金` 而不是 `window`），就需要使用 `call`、`apply` 或 `bind` 来强行修改 `this` 的指向。这也是这些方法在实际开发中最典型的应用场景之一。
