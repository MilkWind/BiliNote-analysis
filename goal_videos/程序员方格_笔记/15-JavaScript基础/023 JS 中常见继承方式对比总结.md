## 引言与继承的基本概念 *Content-[00:00]

### 什么是继承
继承是一种机制，允许一个对象或构造函数去继承另一个对象或构造函数的属性和方法。这意味着子对象可以访问父对象上已经定义好的属性和方法。

### 为什么需要继承
- **代码复用**：将通用的属性和方法定义在父类型，子类型可以直接继承，避免重复造轮子，大大减少代码开发量。
- **构建层级结构**：允许建立对象之间的父子或祖孙关系，形成一种自然的分类和组织方式。这对于管理大型复杂的代码库至关重要，能让代码结构更加清晰、易于维护。
- **多态（Polymorphism）**：在传统的面向对象语言中，多态允许不同的对象对同一个方法调用做出不同的响应。JS 的原型链继承虽然不像传统继承那样严格，但也能实现类似的多态效果：不同的对象通过原型链找到相同的方法名，但根据各自的上下文执行时，可能会有不同的表现。

## JS 继承方式概览 *Content-[03:07]

JS 提供了多种实现继承的方式，随着语言的发展不断演进，主要包括：
- **原型链继承**：理解 JS 继承的基础。
- **构造函数继承**：为解决原型链的一些问题而提出。
- **组合继承**：基于前两者的优点结合而成。
- **原型式继承**：基于 `Object.create` 实现。
- **寄生式继承**：原型式继承的增强版。
- **寄生组合式继承**：被认为是 ES6 之前 JS 中最优的解决方案。
- **ES6 Class 及 `extends` 关键字**：现代 JS 中最常用的方式，语法简洁，底层依然基于前述思想构建。

## 原型链继承 *Content-[04:32]

### 核心机制
通过子类型的原型（`Child.prototype`）去指向父类型的实例（`new Parent()`），从而形成原型链。

### 代码逻辑解析
```javascript
function Parent() {
    this.name = 'parent';
    this.colors = ['red', 'blue'];
}
Parent.prototype.sayName = function() { console.log(this.name); };

function Child() {
    this.age = 18;
}
// 关键步骤：将子类型的原型指向父类型的实例
Child.prototype = new Parent(); 
// 修复 constructor 指向，否则会指向 Parent
Child.prototype.constructor = Child; 
Child.prototype.sayAge = function() { console.log(this.age); };
```

### 执行过程
当调用子实例的方法或属性时，首先在实例自身查找；找不到则沿着原型链向上查找：子实例 -> `Child.prototype` (即 Parent 实例) -> `Parent.prototype` -> `Object.prototype` -> `null`。

### 缺点
1. **引用类型属性被共享**：父类实例上的引用类型属性（如数组 `colors`）会被所有子类实例共享。修改一个实例的引用属性，会影响其他所有实例。
2. **无法传参**：在设置 `Child.prototype = new Parent()` 时，无法向 Parent 构造函数传递参数，导致父类需要初始化的属性无能为力。
3. **constructor 指向错误**：直接设置原型会导致 `constructor` 指向父类，需要手动修复。

## 构造函数继承 *Content-[09:28]

### 核心机制
在子类型的构造函数里，通过 `call` 或 `apply` 方法调用父类型的构造函数，并将子类型实例的 `this` 作为第一个参数传入。

### 代码逻辑解析
```javascript
function Parent(name) {
    this.name = name;
    this.colors = ['red', 'blue'];
    // 注意：方法定义在构造函数内部
    this.sayName = function() { console.log(this.name); }; 
}

function Child(name, age) {
    // 关键步骤：借用父类构造函数，并传入参数
    Parent.call(this, name); 
    this.age = age;
}
```

### 优点
- 解决了引用类型属性共享的问题，每个实例都有独立的属性副本。
- 支持在创建子实例时向父类构造函数传递参数。

### 缺点
1. **方法无法复用**：如果像示例中那样将方法定义在构造函数内部，每一个子实例都会拥有一个独立的方法副本，方法过多时会造成严重的资源浪费。
2. **父类原型方法不可见**：只继承了父类型的实例属性，父类型原型上定义的方法对子类型是不可见的，无法实现方法的继承和复用。

## 组合继承 *Content-[13:18]

### 核心机制
结合原型链继承和构造函数继承。通过构造函数继承实现独立的属性继承和传参，解决引用类型共享问题；通过原型链继承实现方法的继承和复用。

### 代码逻辑解析
```javascript
function Parent(name) {
    this.name = name;
    this.colors = ['red', 'blue'];
}
Parent.prototype.sayName = function() { console.log(this.name); };

function Child(name, age) {
    // 1. 构造函数继承：继承属性，每个实例独立
    Parent.call(this, name); 
    this.age = age;
}
// 2. 原型链继承：继承方法，实现复用
Child.prototype = new Parent(); 
Child.prototype.constructor = Child;
Child.prototype.sayAge = function() { console.log(this.age); };
```

### 缺点
- **隐藏的性能开销**：调用了两次父类构造函数。第一次在 `Child` 构造函数内部（`Parent.call(this)`），第二次在设置原型链时（`new Parent()`）。这导致 `Child.prototype` 上存在一份多余的父类实例属性，造成不必要的内存开销。

## 寄生组合式继承 *Content-[16:10]

### 核心机制
ES6 Class 出现之前 JS 实现继承的最优方案。目标是避免在继承原型方法时实例化父类型。核心是不直接将子类型的原型指向父类型的实例，而是创建一个空对象作为中介，该中介对象的原型指向父类型的原型。

### 辅助函数实现
通常定义一个辅助函数（如 `inheritPrototype`）来简化这一过程：
```javascript
function inheritPrototype(child, parent) {
    // 创建一个新对象，原型指向父类的 prototype
    let prototype = Object.create(parent.prototype); 
    // 修复 constructor 指向
    prototype.constructor = child; 
    // 将新对象赋值给子类的 prototype
    child.prototype = prototype; 
}
```

### 完整继承实现
```javascript
function Parent(name) {
    this.name = name;
    this.colors = ['red', 'blue'];
}
Parent.prototype.sayName = function() { console.log(this.name); };

function Child(name, age) {
    // 只调用一次父类构造函数，继承属性
    Parent.call(this, name); 
    this.age = age;
}
// 使用辅助函数继承原型方法，避免实例化父类
inheritPrototype(Child, Parent); 
Child.prototype.sayAge = function() { console.log(this.age); };
```

### 优点
- 只调用了一次父类型的构造函数，解决了组合继承的性能问题。
- 兼顾了属性的独立性（每个实例有独立副本）和方法的复用性。
- `instanceof` 和 `isPrototypeOf` 等类型检测 API 能正常工作，层级关系正确。

## ES6 Class 继承 *Content-[20:30]

### 核心机制
现代 JS 提供了更简洁的语法糖。使用 `class` 关键字定义类，使用 `extends` 关键字表明继承关系，在子类的 `constructor` 中使用 `super` 调用父类的构造函数。

### 代码逻辑解析
```javascript
class Parent {
    constructor(name) {
        this.name = name;
        this.colors = ['red', 'blue'];
    }
    // 方法直接写在类体中，自动添加到原型对象上
    sayName() { 
        console.log(this.name); 
    }
}

class Child extends Parent {
    constructor(name, age) {
        // super 相当于调用 Parent.call(this, name)
        super(name); 
        this.age = age;
    }
    sayAge() { 
        console.log(this.age); 
    }
}
```

### 本质与优势
- **本质**：`class` 仅仅是 JS 基于原型链和构造函数实现继承的一种语法糖。其底层机制（特别是 `extends` 和 `super` 的实现）与寄生组合式继承非常相似。
- **优势**：解决了传统原型继承写法的繁琐和陷阱，使得 JS 的面向对象编程更接近传统面向对象语言的习惯，更加易读、易于维护。是现代 JS 开发中实现继承的推荐和首选方式。
