## 1. 包装类型的概念与特性 *Content-[00:05]

- **基本概念**：
  在 JavaScript 中，有三个基本数据类型（`Number`、`Boolean`、`String`）可以调用方法。这是因为在调用方法的瞬间，基本数据类型会转换为引用类型，调用完毕后又会自动转回基本类型。这个转换的过程就是“装箱”的过程，也就是**包装类型**。
- **包含的类型**：
  只有 `Number`、`Boolean`、`String` 这三种基本数据类型拥有对应的包装类型。
- **无包装类型的类型**：
  其他四个基本数据类型（`undefined`、`null`、`Symbol`、`BigInt`）**没有**包装类型，也就没有自动转换的过程。
  - **注意**：如果尝试在 `undefined` 或 `null` 等没有包装类型的值上调用方法（例如 `undefined.toString()` 或 `undefined.substring()`），必然会直接报错。

## 2. 包装类型的作用与装箱操作分类 *Content-[02:12]

- **包装类型的目的与作用**：
  包装类型的核心作用是为了**简化基本类型的操作**，便于开发者直接对基本类型值进行各种方法调用，而无需手动进行繁琐的转换。

- **装箱操作的分类**：
  装箱操作分为**隐式装箱**和**显式装箱**两类，具体差异如下：

  **1. 隐式装箱**
  - **触发条件**：当 `Number`、`String`、`Boolean` 的值调用方法时，JS 引擎会自动触发装箱操作。
  - **特点**：创建的是**临时实例**，仅存在于代码执行的瞬间。执行完毕后，该临时实例会**立即销毁**。

  **2. 显式装箱**
  - **触发条件**：开发者手动通过包装类型的构造函数（如 `new String()`）创建实例。
  - **特点**：创建的实例是**普通引用类型**，**不会自动销毁**。它的生命周期会一直持续，直到执行流离开作用域被垃圾回收机制（GC）回收，或者开发者手动将其置为 `null`。

## 3. 包装类型高频真题解析 *Content-[04:48]

### 题1：什么是 JS 的包装类型？包含哪几种类型？
- **概念**：包装类型也叫基本包装类型，是 JS 为了让基本类型能调用方法，专门为三种基本类型设计的特殊引用类型。其本质是基本类型的引用类型包装器。
- **包含类型**：共有三种，分别是 `Boolean`、`Number`、`String`，对应三种基本类型（注意这里指的是构造函数）。
- **无包装类型**：`undefined`、`null`、`Symbol`、`BigInt` 无包装类型。其中 `undefined` 和 `null` 调用任何方法会直接报错。

### 题2：已经有了基本类型了，为什么 JS 还要设计包装类型？
- **原因**：基本数据类型是简单值，本身无法调用任何方法。如果没有包装类型，操作基本类型（如截取字符串）需要开发者自定义函数，过程非常繁琐。
- **核心目的**：便于操作基本类型的值。让 `Boolean`、`Number`、`String` 能像引用类型一样直接调用内置方法（如 `toString()`、`substring()`）。
- **优势**：JS 引擎在后台自动完成基本类型和引用类型的转换，开发者无需手动操作，极大简化了开发流程。

### 题3：什么是 JS 中的装箱操作？分别为哪两种？核心区别是什么？
- **装箱操作**：将基本类型转换为对应的包装类型实例（即引用类型）的操作。
- **分类与核心区别**：分为**隐式装箱**和**显式装箱**。核心区别在于**是否需要开发者手动触发**。
  - **隐式装箱**：引擎自动触发，临时创建，执行完毕立即销毁，无法自定义属性和方法。
  - **显式装箱**：开发者手动通过构造函数创建，是普通引用类型，不会自动销毁，可自定义属性和方法。

### 题4：为什么数字 `7.toString()` 会报错？至少写出两种修改后能正常执行的写法。
- **报错原因**：JS 引擎会将数字后的点优先解析为**小数点**，而非方法调用的点运算符。因为前面是数字，引擎将其简写为小数点，从而导致语法错误（SyntaxError）。
- **正确写法 1**：使用括号改变解析优先级，将数字单独括起来。
  ```javascript
  (7).toString(); 
  ```
- **正确写法 2**：将数字赋值给变量，再用变量调用对应方法。
  ```javascript
  let num = 7;
  num.toString();
  ```

### 题5：为什么字符串 `"7".toString()`、`true.toString()` 能正常调用，而 `undefined.toString()` 会报错？
- **正常调用的原因**：`"7"` 和 `true` 分别是 `String` 和 `Boolean` 基本类型，引擎能正确识别点运算符为方法调用，自动触发隐式装箱，创建临时实例调用方法后立即销毁。
- **报错原因**：`undefined` 没有对应的包装类型，JS 引擎无法创建临时实例。引擎只能将其视为单纯的基本类型，而基本类型本身没有 `toString()` 方法，因此调用时直接触发类型错误（TypeError）。

### 题6：包装类型和普通的引用类型有什么核心区别？
两者的核心区别在于**实例的生存期（生命周期）不同**，具体差异如下：
1. **生存期**：
   - 包装类型的隐式实例是临时的，一行代码执行完毕立即销毁。
   - 普通引用类型的实例长期存在，执行流离开作用域后会被垃圾回收机制（GC）回收。
2. **创建方式**：
   - 包装类型由引擎自动隐式创建，或开发者手动显式创建。
   - 普通引用类型只能由开发者手动通过 `new` 关键字调用构造函数来创建。
3. **自定义属性**：
   - 包装类型的隐式实例无法添加自定义属性（因为会立即销毁）。
   - 包装类型的显式实例和普通引用类型可以自由添加、修改、删除自定义属性。

### 题7：为什么不能直接给基本类型添加自定义属性和方法？举例说明。
- **原因分析**：当给基本类型添加属性或方法时，JS 引擎会触发隐式装箱，创建一个临时的包装类型实例，属性或方法被添加在这个临时实例上。然而，该行代码执行完毕后，临时实例会**立即销毁**。
- **后续访问**：当后续再次访问该属性或方法时，引擎会重新创建一个新的临时实例。由于新实例上并没有之前添加的属性和方法，因此会返回 `undefined`。

### 题8：如何给基本类型添加可复用的自定义方法呢？
- **解决方案**：需要在对应的包装类型的**原型对象（`prototype`）** 上添加方法。
- **原理**：隐式装箱创建的临时实例会继承包装类型原型上的所有方法。因此，所有该类型的基本值都能调用这个自定义方法。
- **代码示例**：给 `String` 基本类型添加一个返回字符串长度的 `myLength` 方法。
  ```javascript
  String.prototype.myLength = function() {
      return this.length;
  };
  
  let str = "abc";
  console.log(str.myLength()); // 输出: 3
  ```
