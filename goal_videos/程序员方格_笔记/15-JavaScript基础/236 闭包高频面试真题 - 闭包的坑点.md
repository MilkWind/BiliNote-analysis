## 1. 闭包应用场景：函数工厂 *Content-[00:00]

闭包的一个经典应用场景是**函数工厂**，它可以用来动态生成具有定制化行为的函数。

### 代码示例与原理
通过外层函数接收配置参数，内部函数接收执行参数，利用闭包特性保存外层函数的变量，从而实现函数的定制化。

```javascript
// 定义外层函数，接收参数 A
function outer(A) {
  // 返回内部函数，形成闭包
  return function(B) {
    return B * A;
  }
}

// 定制化生成 double 函数（乘数固定为 2）
const double = outer(2);
console.log(double(5)); // 结果：10 (2 * 5)

// 定制化生成 triple 函数（乘数固定为 3）
const triple = outer(3);
console.log(triple(5)); // 结果：15 (3 * 5)
```

### 技术分析
- `outer` 函数作为一个**函数工厂**，每次调用都会生成一个新的闭包环境。
- 每个闭包环境独立保存自己的变量值（如 `A` 的值）。
- 这种模式实现了**配置化函数生成**，能够非常优雅地动态生成具有定制化行为的函数。

## 2. 闭包的其他核心应用场景 *Content-[02:25]

除了函数工厂，闭包在前端开发中还有以下几种高频应用场景。在面试中，建议重点掌握前四种，足以让你在面试中脱颖而出：

1. **模块化**：利用闭包实现私有变量和模块封装，避免全局变量污染。
2. **防抖（Debounce）与节流（Throttle）**：在闭包中记录定时器或时间戳，控制函数执行频率。
3. **事件处理**：在事件回调中保留外部状态，避免循环中变量共享导致的问题。
4. **事件监听/点击次数统计**：利用闭包记录状态（如点击次数），实现数据的持久化记录。
5. **函数工厂**：动态生成定制化函数（相对前几种考察频率略低，但同样重要）。

## 3. 闭包坑点一：循环中的闭包陷阱 *Content-[03:30]

在循环中使用闭包时，极易出现变量共享导致的陷阱，这也是前端笔试和面试中的高频运行题。

### 陷阱现象
```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i); 
  }, 100);
}
// 预期输出：0, 1, 2
// 实际输出：3, 3, 3
```

### 原因分析
- `var` 声明的变量**没有块级作用域**，只有函数作用域或全局作用域。
- 循环中的所有 `setTimeout` 回调函数共享同一个全局/函数作用域下的变量 `i`。
- 当 `setTimeout` 的回调函数执行时，循环已经结束，此时 `i` 的值已经变成了 3，因此所有回调打印的都是 3。

### 解决方案
**方案一：使用自执行函数（IIFE）创建独立闭包**
通过立即执行函数为每次循环创建一个独立的作用域，将当前的 `i` 值作为参数传递进去。
```javascript
for (var i = 0; i < 3; i++) {
  (function(index) {
    setTimeout(() => {
      console.log(index); // 输出：0, 1, 2
    }, 100);
  })(i);
}
```

**方案二：使用 `let` 替代 `var`（最推荐）**
`let` 具有**块级作用域**，每次循环都会生成一个新的块级作用域，从而避免了变量共享问题。
```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i); // 输出：0, 1, 2
  }, 100);
}
```

## 4. 闭包坑点二：内存泄漏问题 *Content-[06:50]

闭包虽然强大，但如果使用不当，会导致严重的性能问题，面试中必问其弊端及解决方案。

### 内存泄漏原理
- 闭包会引用外层函数的作用域对象，导致该对象**无法被垃圾回收机制（GC）销毁**。
- 如果长期持有闭包引用，没用的变量会一直占用内存，就像家里的垃圾一直不扔，最终导致内存被占满，引起页面卡顿甚至崩溃。

### 代码示例
```javascript
function outer() {
  // 模拟占用大量内存的大数组（长度10万）
  let bigArray = new Array(100000).fill(0); 
  
  // 内部函数引用了 bigArray
  return function inner() {
    console.log(bigArray.length);
  }
}

// 获取闭包函数
let fn = outer();
fn(); // 输出 100000

/* 
 * 此时 bigArray 在业务逻辑上已经没有用了（仅读取了长度），
 * 但因为闭包 fn 依然引用着它，垃圾回收机制不会清理 bigArray，
 * 导致 10万长度的数组一直占用大量内存空间，造成内存泄漏。
 */
```

### 解决方案
**手动解除引用**：在使用完闭包后，手动将闭包变量赋值为 `null`，切断引用关系，让垃圾回收机制正常清理内存。

```javascript
// 手动解除闭包引用
fn = null; 
// 此时 bigArray 不再被引用，会被垃圾回收机制释放，内存泄漏问题解决。
```
*注：在声明闭包变量时，需使用 `let` 或 `var`，不能使用 `const`，否则后续无法重新赋值为 `null`（会报只读属性错误）。*
